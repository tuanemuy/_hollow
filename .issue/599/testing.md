回帰（正常系）確認のため、以下が必要:

## 確認項目

### 1. 存在しない公開ノート id で 410（gone）表示

- **対応する受け入れ基準:** AC-1
- **目的:** RSC 内 notFound が system/500 ではなくルート意図の `ErrorPage kind="gone"` に届く。
- **手順:**
  1. `http://localhost:3000/notes/public/01956000-0000-7000-8000-00000000ffff` を開く。
- **期待結果:** 「このノートは公開されていません」＋ `Error code: 410 Gone` 相当の 410 ページが表示される。
- **確認ポイント:** 「予期しないエラーが発生しました」/ `500 Internal Server Error`（system）になっていないこと。

### 2. 非公開ノート id で 410（gone）表示・列挙耐性

- **対応する受け入れ基準:** AC-1, AC-4
- **目的:** 非公開ノートでも存在の有無を露出せず一律 410 になる。
- **手順:**
  1. シードした非公開ノートの id で `http://localhost:3000/notes/public/<privateNoteId>` を開く。
- **期待結果:** 存在しない id（項目1）と**まったく同じ** 410 ページ。
- **確認ポイント:** 「存在するが非公開」と「そもそも存在しない」が画面・挙動から区別できないこと。

### 3. `/u/$username/$noteSlug` で存在しない slug は 410（gone）表示

- **対応する受け入れ基準:** AC-2
- **目的:** 同じ `PublicNoteDetail`（bySlug 入口）を使う波及先ルートも修正される。
- **手順:**
  1. 実在ユーザーで `http://localhost:3000/u/<username>/this-slug-does-not-exist` を開く。
- **期待結果:** `ErrorPage kind="gone"`（410）が表示される。
- **確認ポイント:** system/500 になっていないこと。

### 4. 存在しないユーザーで 404（notFound）表示

- **対応する受け入れ基準:** AC-3
- **目的:** `/u/$username`（`UserPublicTop`）も同根本原因が解消され、ルート意図の `ErrorPage kind="notFound"` が出る。
- **手順:**
  1. `http://localhost:3000/u/nonexistent-user-xyz` を開く。
- **期待結果:** 「ページが見つかりません」＋ `Error code: 404 Not Found` 相当の 404 ページ。
- **確認ポイント:** system/500 になっていないこと。

## 既存機能への影響確認

### 5. 正常系（公開ノート詳細）の回帰なし

- **対応する受け入れ基準:** AC-5
- **目的:** 修正で正常系の本文・メタ・関連表示が壊れていない。
- **手順:**
  1. `http://localhost:3000/notes/public/<noteId>`（実在の公開ノート）を開く。
  2. `http://localhost:3000/u/<username>/<slug>`（同ノートの bySlug 入口）を開く。
- **期待結果:** タイトル・本文・公開日/更新日・タグ・バックリンク・関連ノートが表示される。`<head>` の meta / JSON-LD（OGP・Article 構造化データ）も従来どおり出力される。
- **確認ポイント:** notFound 修正が正常系の描画・head 生成に副作用を与えていないこと。

### 6. 正常系（ユーザー公開トップ）の回帰なし

- **対応する受け入れ基準:** AC-5
- **目的:** `UserPublicTop` の修正で実在ユーザー（公開ノート0件含む）の表示が壊れていない。
- **手順:**
  1. `http://localhost:3000/u/<username>`（実在ユーザー）を開く。
  2. 可能なら公開ノートが 0 件のユーザーでも開く。
- **期待結果:** プロフィール・ノート一覧が表示される。公開ノート0件のユーザーでも **404 にならず**、空状態（ノートなし）として正常表示される。
- **確認ポイント:** Promise.all 全体 try/catch が、ユーザー実在・ノート0件のケースを誤って notFound に倒していないこと（AC-4 の論拠）。
