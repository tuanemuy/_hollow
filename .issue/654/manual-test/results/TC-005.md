## 判定理由

- **AC-5 の肝（cap 到達時の追加抑止）が ARIA レベルで実装されていることを確認**:
  8件選択時、＋chip listbox の未選択 option はすべて `[disabled]` になり、9件目を選択できない。
- disabled option はクリックしても URL に入らず（3b）、セマンティッククエリからも除外される（3c）。
  これは agent-browser の偽陽性ではなく、**実装が option を disabled にしている**ことが snapshot の `[disabled]` 属性で明示的に確認できた。
- 8件状態のリロードで tags が保持され、サイレント全消失（tags 空化）は起きなかった（4）。
- 補足検証で、9件を直接URLに入れると `tags.max(8).catch(undefined)` により tags 全消失が起きることを確認。
  ＋chip の8件到達時 disabled 抑止は、まさにこの全消失をユーザー操作経路で防ぐための実装であり、期待通り機能している。

## agent-browser クリックの扱い

- ＋chip option のクリックは TC-004 で偽陽性（React 合成イベントに届かない）と確認済みだが、
  本 TC では「disabled かどうか」「9件目が URL に入らないか」という**結果**を snapshot の属性と URL で検証したため、
  クリックの効/不効に依存せず判定が成立する。cap 抑止は実装側の `[disabled]` レンダリングで明確に確認できた。
