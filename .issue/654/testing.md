# 動作確認計画 — Issue #654: 公開ページ(P30)の「タグを追加(＋)」UI（公開面タグサジェスト）

**Issue:** #654
**作成日:** 2026-06-13

---

## 確認環境

このIssueの変更（`/u/$username` の `filter-row` に「＋ タグを追加」chip を追加し、公開タグ母集合を供給する読み取り経路）を確認するために必要な手順のみ記載。スキーマ変更はないため新規マイグレーションは不要。

### 検証環境の起動

```bash
pnpm db:migrate    # ローカル D1 にマイグレーション適用（初回・未適用時のみ）
pnpm dev           # vite dev (workerd) on http://localhost:3000
```

確認 URL: `http://localhost:3000/u/<username>`（公開ノートを持つユーザー名）

### デプロイ方法

なし（検証環境のみで確認できる）。

### シードデータ

確認には以下が揃ったユーザーが必要:

- 公開（public）ノートが複数件あり、**1ページに収まらない件数**のタグ分布を持つ。すなわち「現ページの一覧には出現しないが、別ページの公開ノートには付与されているタグ」が少なくとも1つ存在する（母集合が発見タグの上位集合であることを確認するため）。
- **非公開（private/trash）ノートにのみ付与されたタグ**が少なくとも1つ存在する（公開 gate が効いていることを確認するため）。
- タグの種類が **9種類以上**（transport cap `tags.max(8)` 到達時の抑止挙動を確認するため）。

シード整備は manual-test スキルに委ねる。「公開のみに付くタグ」「非公開のみに付くタグ」「現ページ外の公開タグ」の作り分けが確認の鍵。

## 確認項目

### 1. ＋chip の表示とモック一致

- **対応する受け入れ基準:** AC-1
- **目的:** `filter-row` に「＋ タグを追加」chip が表示され、モック（`P30-user-public-top.html` 570-573行＝Plus アイコン＋「タグを追加」）の構造・見た目に一致することを確認する。
- **手順:**
  1. `/u/<username>` を開く。
  2. ソート/期間 chips の並ぶ `filter-row` を確認する。
  3. 「＋ タグを追加」chip が表示されているか確認する。
  4. ブラウザの DevTools で chip のクラスを確認する。
- **期待結果:** Plus アイコン＋「タグを追加」ラベルの chip が表示される。トリガーの見た目は公開面 `CHIP` クラス（実線 pill）であり、auth 側の破線 `filterChipGhost` ではない。
- **確認ポイント:** モック `spec/design/pages/P30-user-public-top.html` の `filter-row` と並べて、装飾・配置に違和感がないか。

### 2. 母集合（全公開タグ）の列挙

- **対応する受け入れ基準:** AC-2
- **目的:** ＋chip を開くと、このユーザーの公開ノートに付与された全タグ名（母集合）が列挙される。現ページ一覧に出現していないタグも含む。
- **手順:**
  1. `/u/<username>` を開く（タグ未選択・1ページ目の状態）。
  2. 既存のタグ chips 行（サーバー発見タグ）にどのタグが出ているか控える。
  3. 「＋ タグを追加」chip を開く。
  4. 列挙されるタグ名と、手順2の発見タグを比較する。
- **期待結果:** ＋chip の選択肢に、現ページ一覧には出ていない公開タグも含めた母集合が並ぶ（発見タグの上位集合になっている）。
- **確認ポイント:** 「別ページの公開ノートにのみ付くタグ」が選択肢に現れること。

### 3. 公開可視性 gate

- **対応する受け入れ基準:** AC-3
- **目的:** 母集合が公開可視性で gate され、非公開のみに付いたタグは選択肢に出ない。
- **手順:**
  1. シードで「非公開（private/trash）ノートにのみ付与したタグ名」を控える。
  2. `/u/<username>` で ＋chip を開く。
  3. 選択肢に手順1のタグが含まれていないことを確認する。
- **期待結果:** 非公開のみに付くタグは母集合に現れない。別オーナーの公開タグも混入しない。
- **確認ポイント:** 公開ノートにも付いているタグは出てよいが、「非公開のみ」のタグは出ないこと。（gate の SQL レベル検証は step 3 の integration テストで担保）

### 4. ＋chip からのタグ追加と楽観更新／URL 反映

- **対応する受け入れ基準:** AC-5
- **目的:** ＋chip からタグを選択すると `tags` フィルターに追加され、既存タグ chips・期間フィルターと同じ楽観更新／URL 反映の作法で即時反映される。
- **手順:**
  1. `/u/<username>` を開く。
  2. ＋chip を開き、未選択のタグを1つ選ぶ。
  3. 一覧が即時に絞り込まれ、URL の `tags` パラメータに選択タグが追加されることを確認する。
  4. ブラウザバック／リロードで状態が URL から復元されることを確認する。
- **期待結果:** 選択と同時にリスト・URL が更新される。既存のタグ chips・期間 chips と同じ操作感。
- **確認ポイント:** 楽観更新のちらつき・URL 反映のタイミングが既存 chips と揃っているか。

### 5. transport cap（8件）到達時の追加抑止

- **対応する受け入れ基準:** AC-5
- **目的:** 選択タグ数が route schema の `tags.max(8)` に達したら ＋chip 側で以降の追加を抑止し、`.catch(undefined)` による全消失を起こさない。
- **手順:**
  1. ＋chip と既存 chips を使ってタグを 8 件まで選択する。
  2. 8 件に達した状態で ＋chip を開く。
  3. さらにタグを選ぼうとする。
- **期待結果:** 8 件到達後は ＋chip 側で未選択 option の追加が抑止される（選べない／無効表示）。9 件目を URL に押し込んで全タグがサイレント消失することはない。
- **確認ポイント:** 8 件選択状態でリロードしても `tags` が消えずに保持されること（cap 超過の `.catch(undefined)` 全消失が起きないこと）。

### 6. 既存タグ chips との整合

- **対応する受け入れ基準:** AC-6
- **目的:** 既存のタグ chips（サーバー発見タグ＋選択中タグのマージ）と整合し、chips 行内で選択中タグの欠落や二重表示が起きない。
- **手順:**
  1. ＋chip で「現ページ一覧には出ていない公開タグ」を選択する。
  2. chips 行に選択中タグが反映されるか確認する。
  3. 既存の発見タグ chip を選択／解除して、chips 行内の表示を確認する。
- **期待結果:** chips 行内で選択中タグが正しく表示され、欠落・二重表示が起きない。
- **確認ポイント:** chips 行と ＋chip 選択肢に同一タグが両方出る重複は ADR-003 で意図的に許容する（これは異常ではない）。chips 行**内**での重複・欠落のみを問題視する。

## エッジケース・異常系

### 1. 公開タグが0件のユーザー

- **目的:** 公開ノート（またはタグ付き公開ノート）が無いユーザーで ＋chip が破綻しないことを確認する。
- **手順:**
  1. 公開ノートにタグが1つも付いていないユーザーの `/u/<username>` を開く。
  2. ＋chip を開く。
- **期待結果:** 選択肢が空でもエラーにならず、空状態（または ＋chip 非表示）として穏当に振る舞う。

### 2. cap（件数上限）規模のタグ数

- **目的:** 母集合が件数上限に近い規模でも列挙・選択が破綻しないことを確認する（cap=1000 は手動再現困難なため、現実的な多数タグで代替確認）。
- **手順:**
  1. タグ種類の多い公開ノート群を持つユーザーで ＋chip を開く。
  2. スクロール・選択操作を行う。
- **期待結果:** 多数の選択肢でも listbox の表示・選択が破綻しない。

## 既存機能への影響確認

- **既存タグ chips の絞り込み:** ＋chip 追加後も、既存の発見タグ chip による絞り込み・解除がこれまで通り動くこと。
- **期間フィルター・ソート:** ＋chip 追加が期間フィルター・ソート chips の楽観更新／URL 反映に影響していないこと。
- **非公開ページ・認証面:** 公開面の母集合クエリ追加が、認証側（auth）のタグ機能や非公開ノート取得に影響していないこと。
