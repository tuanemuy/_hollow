# 動作確認計画 — Issue #824: P12 編集中のヘッダー簡略タイトル（モバイル orientation）

**Issue:** #824
**作成日:** 2026-07-10

---

## 確認環境

このIssueはプレゼンテーション層のみの変更（`app/components/layout/` の共有シェルと `app/components/note/editor/NoteEditor.tsx`）。新規のデータ取得・サーバ往復は無い。確認に必要な手順のみ記載する。

### 検証環境の起動

コンポーネント変更なので HMR が効く vite dev を使う。

```bash
pnpm db:migrate   # ローカル D1 にマイグレーション適用（未適用なら。初回のみ）
pnpm dev          # vite dev（workerd / @cloudflare/vite-plugin）
```

`pnpm dev` はポート **3000 固定**だが、使用中なら自動で番号が増える（3001…）。実ポートは起動ログ（`Local: http://localhost:XXXX`）で確認する。以下 URL の `3000` は実ポートに読み替える。

### シードデータ（必須）

editor 画面（`/notes/new` / `/notes/$noteId/edit`）は `_app` 配下の認証必須ルート。決定論的な管理者ユーザーとセッションを投入する。

```bash
pnpm seed:dev-admin
```

出力トークンを CDP 経由でセッション cookie に注入する（cookie 名 `__Host-session` は Secure 必須で `document.cookie` 注入不可）。

```bash
agent-browser cookies set "__Host-session" "<token>" \
  --url http://localhost:3000 --path / --secure --sameSite Lax
```

注入後 `/notes/new` を開くと editor が表示される。**既存タイトルを持つ編集画面**（AC-1 の edit モード初期表示に必須）を使うには、所有ノートを 1 件 SQL（`pnpm db:execute:local <SQLファイル>`）で投入し、その `noteId` で `/notes/$noteId/edit` を開く。タイトルは AC-2 の truncation 確認のため十分長いもの（例:「Q2 計画 — プロダクトレビューに向けて」）を含めておくとよい。

### 確認幅

DevTools のレスポンシブモードで **モバイルは `< sm`（640px 未満）**、代表として **iPhone 12 相当 390px / 375px** を基準にする。デスクトップ回帰は `sm`（640px）以上、代表として **768px / 1280px** を見る。境界（639px ⇔ 640px）での切り替わりも 1 度確認する。

### デプロイ方法

なし（検証環境のみで確認できる。ステージング/本番への反映は不要）。

## 確認項目

### 1. モバイル編集画面のヘッダー簡略タイトル表示

- **対応する受け入れ基準:** AC-1
- **目的:** モバイル幅で編集画面を開くとタイトルが共有ヘッダー中央に簡略表示されること（既存タイトルは即座に、新規は入力で）。
- **手順:**
  1. DevTools を 390px にする。
  2. **edit モード**: 既存タイトルを持つノートの `/notes/$noteId/edit` を開く。
  3. ヘッダー中央にそのタイトルが即座に（本文に触れる前に）表示されるか確認する。
  4. **new モード**: `/notes/new` を開く。ヘッダー中央にタイトルが無い（検索が出ている）ことを確認する。
  5. 本文冒頭のタイトル入力にテキストを打鍵し、打鍵に追従してヘッダー中央にそのタイトルが現れることを確認する。
- **期待結果:** edit は開いた瞬間、new は入力開始でヘッダー中央にタイトルが表示される。
- **確認ポイント:** タイトルを編集して変更するとヘッダー表示もリアルタイムに追従すること。表示位置は中央グリッド列（メニューボタンと右端アイコンの間）。

### 2. 長文タイトルの truncation（横押し広げ防止）

- **対応する受け入れ基準:** AC-2
- **目的:** 長文タイトルが末尾 ellipsis になり、ヘッダーを横に押し広げない／横スクロールを出さないこと。
- **手順:**
  1. 390px で編集画面を開く。
  2. タイトルに mock「Q2 計画 — プロダクトレビューに向けて」以上の長さを入力する。さらに念のため、空白を含まない長い連続文字列（例: `supercalifragilisticexpialidociousAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA`）も試す。
  3. ヘッダー全体が横スクロールしない／右端アイコンが押し出されないことを確認する。
  4. タイトルが末尾で `…`（ellipsis）に切れることを確認する。
- **期待結果:** 中央 `1fr` トラックが伸びず、タイトルは 1 行内に収まり末尾 ellipsis。ページ/ヘッダーに横スクロールが出ない。
- **確認ポイント:** truncation は「中央 grid アイテム（HeaderCenter root）の `min-w-0`」と「`.header-doc` 内側の `min-w-0` + `truncate`」の両方が効いて初めて成立する。どちらか欠けると nowrap タイトルの min-content でトラックが伸びるので、押し広げが起きたら両 `min-w-0` の有無を DevTools で確認する。

### 3. スクリーンリーダーの二重読み上げ防止

- **対応する受け入れ基準:** AC-3
- **目的:** ヘッダーの簡略タイトルは装飾要素であり、スクリーンリーダーはエディタ本文の `<input>`（label「タイトル」）のみ読み上げること。
- **手順:**
  1. 390px で編集画面を開く。
  2. DevTools の要素検査で、ヘッダー中央のタイトル要素（`.header-doc` 相当）に `aria-hidden="true"` が付いていることを確認する。
  3. DevTools の Accessibility ツリー（またはスクリーンリーダー）で、ヘッダーのタイトル要素がアクセシビリティツリーから除外され、タイトルはエディタ本文の入力欄（アクセシブルネーム「タイトル」）としてのみ現れることを確認する。
- **期待結果:** ヘッダーのタイトルは a11y ツリーに現れず、タイトルが二重に読まれない。読み上げ対象はエディタ本文の入力欄のみ。
- **確認ポイント:** `aria-hidden="true"` が動的に付け外しされず常時付いていること。

### 4. デスクトップは検索のみ（簡略タイトル非表示）

- **対応する受け入れ基準:** AC-4
- **目的:** `sm` 以上では編集画面を含む全ページでヘッダー中央が従来どおり検索ボックスのみで、簡略タイトルが表示されないこと。
- **手順:**
  1. DevTools を 768px（および 1280px）にする。
  2. 既存タイトルを持つ `/notes/$noteId/edit` を開く。
  3. ヘッダー中央が検索ボックスのみで、簡略タイトルが表示されていないことを確認する。
  4. `/notes/new`・一覧（P10）など他ページでも同様に検索のみであることを確認する。
- **期待結果:** desktop では全ページで検索ボックスのみ。簡略タイトルは（DOM 上に存在しても）`sm:hidden` で不可視。
- **確認ポイント:** 639px ⇔ 640px 境界で、モバイルのタイトル表示 ⇔ デスクトップの検索表示が切り替わること。

### 5. 検索置換（モバイル編集中は検索が同時表示されない）

- **対応する受け入れ基準:** AC-8
- **目的:** モバイル幅で title を持つ編集画面を開いている間、ヘッダー中央の検索ボックスが表示されず、タイトルが検索を置換する（同時表示にならない）こと。
- **手順:**
  1. 390px で既存タイトルを持つ `/notes/$noteId/edit` を開く。
  2. ヘッダー中央にタイトルが表示され、**同時に検索ボックスが表示されていない**ことを確認する（タイトルと検索が並存しない）。
  3. `/notes/new` を開き（title 空）、検索ボックスが表示されていることを確認する。
  4. タイトルを入力し、検索ボックスが消えてタイトルに置き換わることを確認する。
  5. タイトルを全消去して空にすると、検索ボックスが再表示されることを確認する。
- **期待結果:** モバイル編集で title があれば検索は非表示（タイトルのみ）。title が空/無ければ検索が表示。両者が同時に見えることはない。
- **確認ポイント:** 検索ラッパー要素自身に `data-doc` 属性が付き（title 非空時）、`data-[doc]:max-sm:hidden` で隠れていること。DevTools でこの属性とクラスの適用を確認する。

### 6. 編集画面離脱でタイトル消去・検索復帰

- **対応する受け入れ基準:** AC-6
- **目的:** 編集画面から他画面へ遷移（エディタ unmount）すると簡略タイトルが消え、検索ボックスに戻ること（title のリークが無い）。
- **手順:**
  1. 390px で既存タイトルを持つ編集画面を開き、ヘッダーにタイトルが出ている状態にする。
  2. サイドバー/リンクから他の `/_app` 画面（例: ノート一覧 P10、設定）へ遷移する。
  3. 遷移先ヘッダー中央が検索ボックスに戻り、簡略タイトルが残っていないことを確認する。
  4. ブラウザバックで編集画面に戻ると再びタイトルが表示されることを確認する。
- **期待結果:** 編集画面を離れるとタイトルが消え検索に復帰。永続ヘッダーに前ノートのタイトルが残らない。
- **確認ポイント:** ヘッダーはキャッシュされる永続要素のため、unmount cleanup（title=null）が効かないと前タイトルがリークする。他画面でタイトルが一瞬でも残らないことを見る。

### 7. タイポ・字揃えの mock 準拠

- **対応する受け入れ基準:** AC-7
- **目的:** 簡略タイトルが mock `.header-doc` のタイポ・字揃え（`text-sm` / `font-medium` / `text-ink`・左寄せ）に準拠すること。
- **手順:**
  1. 390px で編集画面を開き、ヘッダーのタイトル要素を DevTools で検査する。
  2. computed style で `font-size` が `--text-sm` 相当、`font-weight` が `--weight-medium` 相当、`color` が `--color-ink` 相当であることを確認する。
  3. `text-align` が指定されず**左寄せ**で流れている（中央寄せでない）ことを確認する。
- **期待結果:** タイトルは mock `.header-doc`（`P12-editor.html` L227-235）と一致するタイポ・左寄せ。
- **確認ポイント:** `text-center` が付いていないこと。中央寄せは mock からの逸脱かつ ellipsis と相性が悪いので、左寄せであること。

## エッジケース・異常系

### 1. 新規ノートの空タイトル fallback（progressive）

- **目的:** `/notes/new` で title が空の間は検索が出たまま、入力で切り替わる意図的挙動であることの確認。
- **手順:**
  1. 390px で `/notes/new` を開く（title 空）。
  2. ヘッダー中央が検索のままであることを確認する。
  3. タイトルを 1 文字入力 → 検索がタイトルに置換されることを確認する。
  4. 入力を全消去 → 検索に戻ることを確認する（空白のみの入力も `trim()` で空扱いされ検索に戻ることを確認）。
- **期待結果:** 空タイトル時は検索 fallback、非空で置換。空⇔非空の往復で正しくトグルする。

### 2. SSR→hydration の一瞬の検索フラッシュ

- **目的:** モバイル編集画面の初回ロードで、SSR は title=null で検索を描画 → hydration 後にタイトルへ切り替わる挙動が許容範囲であることの確認。
- **手順:**
  1. 390px で既存タイトルを持つ編集画面を**フルリロード**（キャッシュ無効化して読み込み直し）する。
  2. 初回描画時に一瞬検索が見えてからタイトルに切り替わる（またはちらつきが気にならない）ことを確認する。
- **期待結果:** ハイドレーション不整合エラー（コンソール警告）は出ない。装飾要素の一瞬の切り替わりは許容。
- **確認ポイント:** ブラウザコンソールに hydration mismatch 警告が出ないこと。

## 既存機能への影響確認

共有シェル（`AppShellDrawer` / `Header`）を触るため **全 `/_app` ページがレンダーパスを通る**。title=null（非編集画面）のとき従来と視覚・挙動が不変であることが回帰の要（AC-5）。

- **全 `/_app` 画面のヘッダー中央（AC-5）**: モバイル（390px）・デスクトップ（1280px）の両方で、編集画面**以外**の代表ページ（ノート一覧 P10、設定、admin など到達できる範囲）を開き、ヘッダー中央が従来どおり検索ボックスで、視覚（位置・寸法・検索アイコン位置）と挙動（フォーカス順・検索入力の動作）が現行と一致することを目視する。`HeaderCenter` のラッパー div が 1 段増えるが、padding/margin の無い inert wrapper のため入力左端・アイコン位置は不変であることを確認する。
- **打鍵中の全ツリー非再レンダー（ADR-006 / churn 封じ込め）**: モバイル編集画面でタイトルを連打入力する間、ヘッダー中央（HeaderCenter）のみが更新され、サイドバーや本文以外の共有シェルが打鍵ごとに再描画されないこと（React DevTools Profiler の highlight updates で、打鍵時に `EditorTitleProvider` 配下の巨大サブツリーが再レンダーしないこと）を確認する。全ツリーが光る場合は children 渡し（"children as prop"）が壊れている疑い。
- **既存ユニット/コンポーネントテスト**: 本 Issue で追加する `EditorTitleContext` / `HeaderCenter` / `useEditorTitleSync` の各テストが緑であること。既存の editor 系テスト（`app/components/note/editor/__tests__/`）にも回帰が無いこと。`pnpm test:unit` を実行する。
- **必須手順**: `pnpm typecheck && pnpm lint:fix && pnpm format` が通過すること。
