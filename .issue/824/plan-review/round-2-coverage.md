## 1周目指摘の解消確認

- **P-001（AC-6↔ステップ紐づけ誤り）→ 解消**: AC-6 の対応ステップが `1,6` → `1,3,4,6` に修正され、AC-6 文言にも「unmount クリア＝ステップ3／title=null 時の検索復帰＝ステップ4」が明記された。トレーサビリティ回復。
- **P-002（`text-center` による mock 乖離が無検証）→ 解消**: `HEADER_DOC` から `text-center` を削除（現: `"sm:hidden truncate text-sm font-medium text-ink min-w-0"`）。mock `.header-doc`（L227-235）は `text-align` を持たず左寄せであることを実ファイルで確認。加えて `SEARCH_BOX_WRAPPER`（`max-w-[460px] w-full mx-auto relative`）は flex/`justify-*`/`text-*` を持たないため、その内側にネストする `.header-doc` も左寄せのまま流れる（1周目 P-002 が懸念した「wrapper 由来の中央寄せ」は成立しない）ことを確認。mock 完全準拠が担保された。
- **S-001（AC-5 過剰主張）→ 解消**: AC-5 が「SSR いずれも不変」から「視覚・挙動が従来と不変（ラッパー div が 1 段増えるため SSR DOM は厳密には同一でないが無害な inert wrapper のみ）」へ緩和。検証可能性を満たす形になった。
- **S-002（タイポ mock 準拠の AC 欠如）→ 解消**: AC-7 を新設し `text-sm`/`font-medium`/`text-ink`・左寄せの mock 準拠を検証項目化。mock L228-230（`--text-sm`/`--weight-medium`/`--color-ink`）と一致。
- **S-003（AC-1 が edit モード初期表示を取りこぼし）→ 解消**: AC-1 が「既存タイトルを持つ編集画面を開くと即座に表示／新規はタイトル入力で表示」の両ケースへ拡張。`NoteEditor.tsx` L133（`title: mode==="edit" ? initialTitle : ""`）に照らし edit 時 mount 発火が根拠づけられている。
- **arch S-003（harness 切り出し）→ 反映**: ADR-005 新設 + ステップ3 + テスト方針に `useEditorTitleSync` harness を明記。「推奨・任意」と正しく位置づけられ、スコープ肥大化にならない。

いずれも見送り無しで全反映。反映品質は高い。

#### 問題点（要修正）

問題点ゼロ。

Issue 3 要件のカバレッジ・検証可能性・ステップ紐づけ・スコープ規律のいずれにも要修正の欠陥は見当たらない。AC↔ステップの紐づけも AC-6 修正後は全て整合しており（AC-2→4,5／AC-3→4／AC-4→4,5／AC-7→5 等、実装機構と対応）、スコープ外作業（ドメイン/ユースケース/アダプター、Icon API、保存バー複製）の混入も無い。

#### 改善提案（検討推奨）

- **[S-001]** ADR-002 の中核である「モバイル編集中はタイトルが**検索を置換**する（＝モバイル編集時、中央の検索ボックスは表示されない）」という観察可能挙動を、直接検証する AC が無い。
  - 理由: AC-1 は「タイトルが表示される」を、AC-4 は「デスクトップは検索のみ」を検証するが、「モバイル編集時に検索が消える」ことは AC で明示されていない。仮に実装が壊れて title と検索が**同時表示**になっても AC-1/AC-4 は真のまま通過しうる。置換挙動は `data-[doc]:max-sm:hidden` と HeaderCenter テストの `data-doc` 属性確認で間接的に担保されてはいるが、Issue mock（P12 モバイルは検索を持たない）が示す設計意図の要であり、受け入れ基準へ昇格すると忠実性の回帰網が締まる。
  - 提案: AC-1 に「…同時に、モバイル編集時はヘッダー中央の検索ボックスが表示されない（title が検索を置換）」の一節を足すか、独立 AC を 1 行追加。実装追加は不要（既存の `data-[doc]:max-sm:hidden` で成立済み）で、検証観点の明文化のみ。優先度は低い。

#### 良い点

- 1周目指摘を骨子を保ったまま全反映し、各修正が AC 文言・対応ステップ・ADR・テスト方針まで一貫して伝播している（P-001 の AC-6 紐づけ、P-002 の mock 準拠 style、S-002 の AC-7、S-003 の AC-1 両ケース）。修正の取りこぼしが無い。
- Issue 3 要件が AC-1〜AC-7 に過不足なく写像され、各 AC が検証可能（幅・ellipsis・aria-hidden・sm:hidden・data-doc・タイポ/左寄せ）。mock 実値（L227-235）・`NoteEditor` 実装（L133/L491）と突き合わせて根拠が実在することを確認できた。
- スコープ規律が引き続き優秀。「含まれないもの」を明示し、プレゼン層に閉じることをドメイン/UC/アダプター「なし」の根拠付きで宣言。harness（ADR-005）も「任意・推奨」と明記されスコープ膨張を招かない。
- ADR-004（`min-w-0` を中央 grid アイテム自身と `.header-doc` の 2 箇所に置く）が、mock の直接 grid 子（L234 `min-width:0`）を一段ネストして写す際の truncation 落とし穴を正確に捉え、AC-2 の検証手順（長文入力の目視）まで結線している。
- リスク節が SSR→hydration のちらつき・新規ノート空タイトルの progressive fallback・全 `/_app` 回帰を網羅し、受け入れ挙動と AC の整合を説明済み。

## 判定

要修正なし。カバレッジ・スコープ整合性ともに実装着手可能な水準。S-001（検索置換の AC 昇格）は忠実性回帰網の精度向上で、任意対応。
