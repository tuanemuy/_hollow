# 動作確認計画 — Issue #545: 領域6「管理（admin）」(P40〜P47) のモック実装追従

**Issue:** #545
**作成日:** 2026-06-08

---

## 確認環境

本 Issue はフロントエンドの admin 画面（P40 ダッシュボード / P45 ユーザー / P46 ジョブ / P47 利用状況ほか）をデザインモックへ追従させる変更。新規 backend は無い。実機確認はローカル開発サーバで行う。

### 検証環境の起動

```
pnpm db:migrate
pnpm seed:dev-admin
pnpm dev
```

- `pnpm db:migrate` — ローカル D1（`hollow-local-d1`）にマイグレーションを適用（初回または未適用時）。
- `pnpm seed:dev-admin` — `scripts/seed-dev-admin.mjs` が admin ロールのユーザーを投入する（admin 画面へアクセスするため。表示される認証情報でログインする）。
- `pnpm dev` — `vite dev`（Cloudflare ランタイム）でローカルサーバが起動。表示 URL をブラウザで開き、**admin ユーザー**でログインして `/admin` 配下を確認する。

### デプロイ方法

なし（検証環境のみで確認できる。ステージング反映が必要な場合は `pnpm deploy:staging`）。

## 確認項目

### 1. P47 利用状況 — 限度テーブルの狭幅行積層（本命）

- **目的:** `/admin/metrics` のインスタンス上限テーブルが、広幅では通常テーブル、狭幅（`md` 未満 = ビューポート幅 768px 未満）では行積層カードになる。
- **手順:**
  1. admin でログインし `/admin/metrics` を開く。
  2. デスクトップ幅（≥768px）で、上限テーブルが「項目 / 値」2 列の通常テーブル表示であることを確認。
  3. ブラウザ幅を 768px 未満に狭める（or DevTools のデバイスエミュレーション）。
  4. 各行がカード状に積層し、各値の上 or 左に「項目」「値」ラベル（実 DOM の `<span>`）が表示されることを確認。
- **期待結果:** 広幅＝テーブル、狭幅＝行積層カード。狭幅でセルが潰れない。値（バイト数・件数・秒・日数）は backend 実値（`InstanceSettingsDTO.limits`）で、モックのダミー値ではない。
- **確認ポイント:** ラベルが `md:hidden`（広幅で消える）こと。積層時のラベル色（ink-tertiary）・サイズ（text-xs）がモック P47 に近いか。スクリーンリーダーでラベル「項目」「値」が読み上げられること（実 DOM 要素のため）。

### 2. P45 ユーザー / P46 ジョブ — テーブルの min-width 横スクロール

- **目的:** `/admin/users` と `/admin/jobs` のテーブルが狭幅でセルを潰さず横スクロールする。
- **手順:**
  1. `/admin/users` を開く（→ リスク参照: #471 未修正だと描画不能の可能性）。
  2. ブラウザ幅を十分狭める。テーブルが `min-width`（P45=880px 相当）を保ち、横スクロールバーが出てセルが潰れないことを確認。
  3. `/admin/jobs` を開き、同様に `min-width`（P46=920px 相当）で横スクロールすることを確認。
- **期待結果:** 両画面とも狭幅で横スクロール。**行積層にはならない**（P47 と扱いが異なる）。
- **確認ポイント:** P45/P46 が積層していないこと（積層は P47 限度テーブルのみ）。

### 3. P40 ダッシュボード — 実値表示・虚偽数値が出ていないこと

- **目的:** `/admin` ダッシュボードが backend 実値（nullable / 取得失敗）を出し、データ源の無いチャート・最近のアクティビティを**追加していない**こと。
- **手順:**
  1. `/admin` を開く。
  2. status banner（アラート無し時「All systems operational」相当 / アラート有り時 `.alert`）と 4 つの metric-card を確認。
  3. metric-card が実値、もしくは取得失敗時に「取得失敗 / —」を出すことを確認。
  4. 24h チャート（sparkline）や「最近のアクティビティ」テーブルが**描画されていない**ことを確認（追加していれば虚偽数値表示になる）。「管理メニュー」案内セクションは存在してよい。
- **期待結果:** 実値 or 取得失敗のみ。ダミーのチャート・活動行は無い。
- **確認ポイント:** モックにあるチャート/アクティビティが未実装であること（Phase 4 で別 Issue 化済み）。

### 4. P40 / P47 / P41〜P44 — トークン・文言整合（軽微差分）

- **目的:** metric-card・section-desc・各フォームの寸法/色/文言がモックと整合し、視覚的な崩れが無い。
- **手順:**
  1. `/admin`・`/admin/metrics`・`/admin/llm`・`/admin/prompts`・`/admin/design`・`/admin/registration` を順に開く。
  2. section-title / section-desc の文言、カード・余白の見た目が対象モックと大きくずれていないか目視。
- **期待結果:** モックと整合。リテラル px 由来の崩れが無い。
- **確認ポイント:** 文言・トークン整合は実質 no-op に近い想定。明らかな崩れが無ければ OK。

## エッジケース・異常系

### 1. メトリクス取得失敗時の表示

- **目的:** `UsageMetricsProvider` が一部 null を返したとき、該当 metric-card が「取得失敗 / —」を出し、ページ全体が壊れない。
- **手順:** 既定の no-op provider（全 null）環境で `/admin` / `/admin/metrics` を開く。
- **期待結果:** 各カードが取得失敗プレースホルダを出し、レイアウトは崩れない。
