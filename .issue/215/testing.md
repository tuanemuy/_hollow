# 動作確認計画 — Issue #215: URL にデフォルトの page=1&limit=20 が常に付与されてしまう

**Issue:** #215
**作成日:** 2026-05-29

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm dev
```

`vite dev --config vite.config.cloudflare.ts` が走り、ローカル開発サーバーが立ち上がる。

### デプロイ方法

なし（検証環境のみで挙動を確認できる）。

## 確認項目

### 1. ホーム（`/`）への初期遷移で URL にクエリが付かない

- **目的:** ログイン直後・他ページからの戻り遷移で、URL に `?page=1&limit=20` が付かないことを確認する。
- **手順:**
  1. ログインして `/` を開く（既に `/` にいる場合は別ページに遷移してから戻る）。
  2. ブラウザのアドレスバーを確認する。
  3. ヘッダーのロゴ・ホームリンク（`<Link to="/" search={HOME_SEARCH}>`）をクリックする。
- **期待結果:** アドレスバーが `/`（クエリなし）であること。
- **確認ポイント:** `?page=1` `?limit=20` `?page=1&limit=20` のいずれも付かないこと。

### 2. ゴミ箱（`/trash`）への初期遷移で URL にクエリが付かない

- **目的:** `/trash` への初期遷移で URL に `?page=1&limit=20` が付かないことを確認する。
- **手順:**
  1. サイドバーの「ゴミ箱」リンクをクリックする（または `/trash` を直接開く）。
  2. アドレスバーを確認する。
- **期待結果:** アドレスバーが `/trash`（クエリなし）であること。

### 3. ノート履歴（`/notes/$noteId/history`）への初期遷移で URL にクエリが付かない

- **目的:** ノート履歴ページへの初期遷移で URL に `?page=1&limit=20` が付かないことを確認する。
- **手順:**
  1. 任意のノート詳細を開く。
  2. ノートアクションから「履歴」リンクをクリックする。
  3. アドレスバーを確認する。
- **期待結果:** `/notes/{noteId}/history`（クエリなし）であること。

### 4. ユーザー公開ページ（`/u/$username`）への初期遷移で URL にクエリが付かない

- **目的:** 公開ユーザーページへの初期遷移で URL に `?page=1&limit=20` が付かないことを確認する。
- **手順:**
  1. `/u/{username}` を直接開く（または公開ノートからユーザーリンクで遷移）。
  2. アドレスバーを確認する。
- **期待結果:** `/u/{username}`（クエリなし）であること。

### 5. ホームでの表示モード切替（list ↔ tile ↔ calendar）でデフォルトクエリが付かない

- **目的:** `DisplayModeSwitch` で表示モードを切り替えたとき、URL に `?page=1&limit=20` を残さないことを確認する。
- **手順:**
  1. `/` を開く（URL クエリなしの状態）。
  2. 「タイル」「カレンダー」「リスト」のボタンを順にクリックする。
  3. それぞれのクリック後にアドレスバーを確認する。
- **期待結果:** URL は `/?display=tile`, `/?display=calendar`, `/`（list はデフォルトなのでクエリなし）の形で、`page` / `limit` が混ざらないこと。

### 6. ホームでフィルター変更してもデフォルトクエリが付かない

- **目的:** `FilterBar` でタグ・期間・公開状態などのフィルターを操作したときに、URL に `page=1` / `limit=20` が付かないことを確認する。
- **手順:**
  1. `/` を開く（URL クエリなしの状態）。
  2. タグを 1 つ選択する → アドレスバーを確認。
  3. 期間（from/to）を入力する → アドレスバーを確認。
  4. 公開状態セレクトを変更する → アドレスバーを確認。
  5. 「クリア」ボタンを押す → アドレスバーを確認。
- **期待結果:** URL に `tagNames` / `from` / `to` / `visibility` が反映され、`page` / `limit` は付かないこと。「クリア」後はクエリなしの `/` に戻ること。

### 7. ページ送りした場合のみ `?page=N` が付き、戻ったら消える

- **目的:** ユーザーが明示的にページ送りした場合だけクエリが付与され、page=1 に戻ると消える挙動を確認する。
- **手順:**
  1. 履歴の多いノートで `/notes/{noteId}/history` を開く（履歴 21 件以上必要)。
  2. 「次へ」をクリックして 2 ページ目に遷移する → アドレスバーが `?page=2` を含むこと。
  3. 「前へ」をクリックして 1 ページ目に戻る → アドレスバーからクエリが消えること。
  4. `/u/{username}` でも同様（公開ノート 21 件以上のユーザーで確認可能なら）。
- **期待結果:** ページ送り時のみクエリが付き、1 ページ目に戻ると `?page=1` ではなくクエリ無しになる。

## エッジケース・異常系

### 1. 既に `?page=1&limit=20` 付きの URL から遷移しても壊れない

- **目的:** 既存のブックマーク等で `?page=1&limit=20` 付き URL を開いたときも、コンテンツが正しく表示されることを確認する。
- **手順:**
  1. アドレスバーに直接 `/?page=1&limit=20` を入力して開く。
  2. ページが正しく表示されることを確認する。
- **期待結果:** スキーマの `.catch().default()` で値が吸収され、ノート一覧が正しく表示される。

### 2. SavedView の選択でも page/limit が URL に出ない

- **目的:** `NoteListToolbar` で保存ビューを選択したときに、URL に `?page=1&limit=20` が出ないことを確認する。
- **手順:**
  1. 保存ビューを 1 つ以上持つ状態で `/` を開く。
  2. 「保存ビューを選択」セレクトから 1 つ選ぶ。
  3. アドレスバーを確認する。
- **期待結果:** URL に `viewId=...` は付くが、`page` / `limit` は付かないこと。

## 既存機能への影響確認

- **ホームのフィルター挙動** — フィルター変更時に勝手にページが進まないか（page=2 のときフィルター変更したら自動で page=1 に戻る挙動が崩れないか）。
- **ノート履歴のページ送り** — 「前へ」「次へ」の Link が動くこと。
- **ユーザー公開ページのページ送り** — 同上。
- **SavedView 復元時の URL 正規化（Issue #219 ADR-002）** — `viewId` が指定された状態で `display` 未指定の場合、`SavedView.displayMode` で正規化リダイレクトが走る挙動が壊れていないこと。
