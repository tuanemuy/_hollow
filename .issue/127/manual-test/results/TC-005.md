`kind=id` の本文直書き UUID が `resolved_note_id` に正しく解決されることを確認した。

ref_kind: id

resolved_note_id: 019e7219-5754-73a2-8a9a-7616cb26b817   <-- ref_target と一致、NOT NULL。PASS

直近の `ref_kind='id'` 行が解決済み。なお、その1つ前の行（前回 FAIL 時に作成）は
`resolved_note_id=null` のまま残っており、修正前後の差分が明確に確認できる。

## エッジ: 存在しない UUID は保存成功＆ resolved_note_id NULL のまま

| 操作 | 期待 | 実際 | 判定 |
| --- | --- | --- | --- |
| ノート `Id Linker Edge` 本文に `[[01999999-9999-7999-8999-999999999999]]`（存在しないUUIDv7）を入力・保存 | FK 違反で落ちず保存成功 | `createNote` POST 200、`Id Linker Edge` 詳細へ遷移、エラーなし | PASS |
| D1 確認 | `resolved_note_id IS NULL` | `ref_kind='id'`, `ref_target='01999999-...999'`, `resolved_note_id=null` | PASS |

存在しないノートを指す `kind=id` リンクでも保存は成功し、FK 制約違反で落ちることなく
`resolved_note_id` は NULL のまま保持された。
