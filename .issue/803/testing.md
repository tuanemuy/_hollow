## 確認環境

このIssueの変更を確認するために必要な手順のみ記載（プロジェクト全体のセットアップは省略）。

### 検証環境の起動

```bash
pnpm db:migrate    # ローカル D1 にマイグレーション適用（未適用時のみ）
pnpm dev           # vite dev (workerd) on http://localhost:3000
```

タグ入力（combobox）はログイン後のノート編集画面（P12）にある。`/notes/new`（新規）または `/notes/$noteId/edit`（編集）で到達し、フロントマター/メタ領域の「タグ」フィールドが対象。候補パネルは既存タグがある状態で入力欄にフォーカス／文字入力すると下に開く。

候補の出る既存タグが必要なので、確認前に少なくとも数件のタグを持つノートを1つ以上作成しておく（タグを付けて保存 → 別ノートの編集画面で同じ先頭文字を打つと候補に出る）。

### デプロイ方法

なし（検証環境のみで確認できる。ステージング/本番反映は本Issueの確認に不要）。

## 確認項目

### 1. 画面下部でフォーカスしても候補パネルが viewport 内に収まる（縦クランプ）

- **対応する受け入れ基準:** AC-1
- **目的:** パネル下端が画面下端をはみ出す位置でも、上方向に押し上げられて全体が見えること
- **手順:**
  1. 既存タグが複数候補に出る状態を用意する（事前に同じ先頭文字のタグを数件作っておく）
  2. ブラウザウィンドウの高さを小さめにする、またはタグフィールドが画面最下部に来るようスクロールする
  3. タグ入力欄にフォーカスし、候補が複数出る先頭文字を1文字入力する
- **期待結果:** 候補パネルが画面下端で切れず、全候補が viewport 内に見える（下にはみ出す場合は上方向に shift される）
- **確認ポイント:** パネルが viewport 下端 8px の余白を保って収まること。DevTools でパネル要素に `transform: translateY(...)`（負値）が当たっていること。

### 2. typing で候補件数が変わっても再クランプされる（動的高さ）

- **対応する受け入れ基準:** AC-3
- **目的:** 候補件数の増減でパネル高さが変わったときも、はみ出しが残らず再配置されること
- **手順:**
  1. 確認項目1と同じく画面下部でパネルを開く
  2. さらに文字を打って候補件数を絞り込む（パネルが低くなる）／消して候補件数を増やす（パネルが高くなる）
- **期待結果:** どの段階でもパネルが viewport 内に収まり続ける。候補が減って余裕ができたら shift 量も縮む（不要なはみ出し・過剰な押し上げが残らない）
- **確認ポイント:** 候補を減らした後にパネルが不自然に大きく浮いたまま（古い shift が残る）にならないこと。

### 3. 外側クリックで候補パネルが閉じる

- **対応する受け入れ基準:** AC-2
- **目的:** input の blur 依存ではなく、タグ入力コンテナの外側クリックで明示的に閉じること
- **手順:**
  1. タグ入力欄にフォーカスして候補パネルを開く
  2. パネル・タグ入力コンテナの外側（ページの空白部分や別の入力欄など）を1回クリックする
- **期待結果:** 候補パネルが閉じる
- **確認ポイント:** パネル内の候補をクリックした場合は閉じる前にそのタグが追加されること（外側クリックのクローズが候補選択を妨げない）。コンテナ内（チップや input 自体）のクリックでは不意に閉じないこと。

### 4. 既存のキーボード操作・コミット挙動が回帰しない（非回帰）

- **対応する受け入れ基準:** AC-4
- **目的:** combobox の a11y / IME / キーボード操作 / blur コミットがこれまで通り動くこと
- **手順:**
  1. 候補を開いた状態で ↑↓ で候補をハイライト移動し、Enter でハイライト中の既存タグが追加されることを確認
  2. ハイライトしていない状態で新規文字列を打ち Enter（または `,`）で新規タグが追加されることを確認
  3. 日本語入力（IME 変換確定）の Enter で誤ってコミットされないことを確認
  4. Escape で候補パネルが閉じ、draft（入力中文字列）は保持されることを確認
  5. 空 draft で Backspace すると直前のチップが削除されることを確認
  6. 有効な draft を入れたまま入力欄の外をクリック（blur）するとそのタグがコミットされることを確認
- **期待結果:** いずれも従来通りに動作する（今回の変更で挙動が変わらない）
- **確認ポイント:** Escape クローズと外側クリッククローズが二重に競合して draft を失わないこと。

## エッジケース・異常系

### 1. 候補ゼロ・新規作成のみのときのパネル

- **目的:** 既存候補が無く「＋『xxx』を新規作成」インジケータのみのときも、クランプ・外側クリッククローズが正しく働くこと
- **手順:**
  1. 既存タグにマッチしない文字列を画面下部で入力する（候補ゼロ＝新規作成行のみ表示）
  2. 外側をクリックする
- **期待結果:** 新規作成行のみの小さいパネルも viewport 内に収まり、外側クリックで閉じる

### 2. 画面上部でフォーカスしたとき

- **目的:** 下方向に余裕がある通常位置では shift が当たらず、これまで通り下向きに開くこと
- **手順:**
  1. タグフィールドが画面上部にある状態でフォーカスし候補を開く
- **期待結果:** パネルは input 直下にそのまま開き、不要な押し上げ（transform）が当たらない

## 既存機能への影響確認

- **ノート保存・タグ永続化:** タグを追加/削除して保存し、再読込後もタグが保持されること（クランプ・外側クリックの追加が保存経路に影響しないこと）
- **ディレクトリ選択（DirectoryTreeSelect）:** 同じ編集画面の別 combobox（Popover ベース）の開閉・外側クリックが従来通り動くこと（共有 `usePopover` ヘルパ流用による副作用がないこと）
