## 確認項目

### 1. フィールド順序の入れ替え（H-1）

- **目的:** editing view のフィールド並びが `タイトル → 本文プレビュー → ディレクトリ → タグ → FrontMatter（折りたたみ）` になっていることを確認する
- **手順:**
  1. アップロード画面でファイルを選び、LLM の推論完了まで待つ
  2. editing モーダルが開いたら、上から順にフィールドを目視する
- **期待結果:** 順序が「タイトル」「本文プレビュー」「ディレクトリ」「タグ」「FrontMatter（折りたたみ）」になっている
- **確認ポイント:** 本文プレビューがディレクトリ／タグ／FrontMatter よりも上に来ている

### 2. FrontMatter のデフォルト折りたたみ（H-1）

- **目的:** FrontMatter セクションが初期状態で閉じていて、クリックで展開できることを確認する
- **手順:**
  1. editing モーダルを開く
  2. FrontMatter セクション（最下段）の `<summary>` をクリック
  3. もう一度クリックして閉じる
- **期待結果:**
  - 初期状態では FrontMatter の textarea が表示されていない（`<details>` が `open` ではない）
  - クリックで textarea が現れる
  - 再クリックで再び閉じる
- **確認ポイント:** キーボード操作（Tab で summary にフォーカス → Space / Enter）でも開閉できる

### 3. AI 提案バッジの初期表示（H-2）

- **目的:** タイトル / ディレクトリ / タグ / FrontMatter のラベル付近に「✨ AI 提案」キャプションが表示されることを確認する
- **手順:**
  1. editing モーダルを開く
  2. 各フィールドのラベル（タイトル / ディレクトリ legend / タグ / FrontMatter summary）付近に「AI 提案」キャプションが表示されていることを目視
- **期待結果:** 4 フィールドすべての近傍に「✨ AI 提案」キャプションが見える
- **確認ポイント:** キャプションのフォントサイズが本文より小さく、`text-ink-tertiary` の薄い色で本体ラベルを邪魔していない

### 4. 編集による AI 提案バッジの消去（H-2）

- **目的:** ユーザーがフィールドを編集すると、当該フィールドの「AI 提案」キャプションが消えることを確認する
- **手順:**
  1. editing モーダルを開く
  2. タイトル input を編集（例: 末尾に「（編集済み）」を追記）
  3. 当該フィールドのキャプションが消えることを確認
  4. タイトルを元の LLM 提案値と完全に一致するように戻す
  5. キャプションが再表示されることを確認
  6. 同様にタグ、FrontMatter、ディレクトリでも試す
- **期待結果:**
  - 編集中はバッジが消える
  - 完全に元の値に戻すとバッジが再表示される
- **確認ポイント:** 4 フィールドそれぞれが独立して挙動する（タイトルだけ編集してもタグのバッジは残る）

### 5. 既存機能の維持（登録 / 破棄 / キャンセル）

- **目的:** UI 再構成によって既存の登録・破棄・キャンセル動作が壊れていないことを確認する
- **手順:**
  1. editing モーダルでタイトル・FrontMatter を編集
  2. 「登録」を押す
  3. ノート詳細に遷移することを確認
  4. 別のファイルで再度モーダルを開き「破棄」→ ConfirmDialog → 「破棄」確定
  5. キューから消えることを確認
  6. 別のファイルで再度開き「キャンセル」で何も起きずに閉じる
- **期待結果:** 登録 / 破棄 / キャンセルが従来通り動く
- **確認ポイント:** sticky アクションバーの位置、disabled 状態の見た目に regress がない

## エッジケース・異常系

### 1. FrontMatter が空（`"{}"`）のときの折りたたみ表示

- **目的:** LLM が空 FrontMatter を返したケースで、`<details>` が閉じていても問題ないことを確認する
- **手順:**
  1. LLM が `frontMatterJson: "{}"` を返すケースで editing モーダルを開く（既存 `emptyFrontMatterJob` ケース相当）
  2. FrontMatter を開かずそのまま登録
- **期待結果:** 登録が成功する（既存テスト `omits frontMatterJson from the payload when the textarea is empty` 相当の挙動）

### 2. FrontMatter JSON エラー時のスクロール / 可視性

- **目的:** 「FrontMatter が閉じている状態で submit → JSON 不正エラーが返る」シナリオで、ユーザーがエラーを見つけられることを確認する
- **手順:**
  1. FrontMatter を一度開いて不正 JSON を入力
  2. `<details>` を閉じてから登録ボタン
- **期待結果:** エラーが画面上のアラート領域に表示される（折りたたみ中でも `role="alert"` の文言が見える）
