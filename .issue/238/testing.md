このIssueの変更を確認するために必要な手順のみ記載（プロジェクト全体のセットアップは省略）。

ログイン後、ヘッダーの「アップロード」から `/upload` ページへ遷移する。

### 破棄済みジョブの準備（シード）

破棄済みカードを確認するには `discarded` ステータスのジョブが必要。UI 操作で作れる:

1. `/upload` でファイルをアップロードし、プレビュー（`previewing`）になるまで待つ
2. そのジョブの「破棄」ボタン → 確認ダイアログで破棄 → `discarded` になる（トグル OFF では一覧から消える）

## 確認項目

### 1. トグルの存在と既定状態

- **目的:** `/upload` に「破棄済みを表示」トグルがあり、既定 OFF であること
- **手順:**
  1. `/upload` を開く
  2. アップロードキューのセクション付近にトグルがあることを確認
- **期待結果:** トグルが表示され、既定で OFF。URL に `includeDiscarded` が付いていない
- **確認ポイント:** OFF のとき `discarded` ジョブが一覧に出ないこと

### 2. トグル ON で破棄済みが表示される

- **目的:** トグル ON で `discarded` を含む全ステータスが表示されること
- **手順:**
  1. 事前に破棄済みジョブを1件作る（上記シード手順）
  2. トグルを ON にする
- **期待結果:** 破棄済みジョブがカードとして一覧に現れる。他ステータス（待機中・処理中・プレビュー可能・保存済み・失敗）も従来どおり表示
- **確認ポイント:** ON↔OFF を切り替えると破棄済みカードが出たり消えたりする

### 3. URL クエリパラメータでの状態保持

- **目的:** トグル状態が URL に保持されリロードに耐えること
- **手順:**
  1. トグルを ON にする → URL を確認
  2. ブラウザをリロード（F5）
  3. トグルを OFF に戻す → URL を確認
- **期待結果:**
  - ON のとき URL に `?includeDiscarded=true` が付き、リロード後もトグル ON・破棄済み表示が維持される
  - OFF に戻すと `includeDiscarded` パラメータが URL から消える（クリーンURL）
- **確認ポイント:** トグル操作で履歴が積み上がらない（`replace` 動作）

### 4. 破棄済みカードの視覚的区別

- **目的:** 破棄済みカードが保持中ジョブと視覚的に区別できること
- **手順:**
  1. トグル ON にして破棄済みカードを表示
- **期待結果:** 破棄済みカードは「破棄済み」バッジ＋カード全体のトーンダウン（opacity 低下）で、保持中ジョブと一目で区別できる
- **確認ポイント:** バッジのラベルが「破棄済み」であること

### 5. ポーリング後も破棄済みが残る

- **目的:** トグル ON 中の自動ポーリング（4秒間隔）で破棄済みが消えないこと
- **手順:**
  1. トグル ON で破棄済みを表示した状態で十数秒待つ（ポーリングが複数回走る）
- **期待結果:** ポーリングが走っても破棄済みカードは表示され続ける
- **確認ポイント:** ネットワークタブで `getIngestionJobs` 系リクエストに `includeDiscarded` が含まれること

## エッジケース・異常系

### 1. hand-typed URL の正規化

- **目的:** 手入力 URL でルートが壊れず型安全に正規化されること
- **手順:**
  1. アドレスバーに `/upload?includeDiscarded=true` → Enter
  2. `/upload?includeDiscarded=1` → Enter
  3. `/upload?includeDiscarded=abc` → Enter
- **期待結果:**
  - `=true` / `=1` → トグル ON・破棄済み表示
  - `=abc`（不正値）→ エラーにならず OFF 扱い（`.catch(undefined)` → `?? false`）

## 既存機能への影響確認

- **トグル OFF 時の従来挙動:** OFF（既定）では `discarded` が非表示のまま（#229 の既定挙動を維持）
- **他ステータスの操作:** previewing の保存/再生成/破棄、failed の再試行/破棄、saved のノートを開く、が従来どおり動作すること
- **アップロード → プレビュー → 保存の動線:** トグル追加で既存のアップロードフローが壊れていないこと
