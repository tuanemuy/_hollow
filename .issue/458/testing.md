## 確認項目

### 1. プロンプト設定: 説明と placeholder の役割分離

- **目的:** カード説明と textarea の placeholder が同じ内容を繰り返さず、placeholder が具体的な記入例になっていること。
- **手順:**
  1. `/admin/prompts` を開く
  2. 各プロンプトカード（取り込み構造化 / タイトル生成 / ディレクトリ提案 / メタデータ抽出 / OCR 補助）の説明文と、未入力時の textarea プレースホルダを見比べる
- **期待結果:** 説明＝「何を入力する欄か」、placeholder＝「例: …」という具体的な記入例で、内容が重複していない。purpose ごとに異なる記入例が表示される。
- **確認ポイント:** placeholder が説明の単なる言い換えになっていないこと。

### 2. デザイントークン: フォーム行の整列

- **目的:** ラベル列（トークン名）と値列（入力欄）の先頭入力欄が縦に揃って表示されること。
- **手順:**
  1. `/admin/design` を開く
  2. 各トークン行のトークン名 input と値 input の上端を確認する
- **期待結果:** 左列の input と右列の input が同じ高さ（上端）で整列し、行ごとにガタつかない。
- **確認ポイント:** 「上書き中」バッジ付き行や「既定値: …」表示のある行でも整列が崩れないこと。

### 3. デザイントークン: 説明文からファイル名除去

- **目的:** 説明文にリポジトリ内ファイルパスが表示されないこと。
- **手順:**
  1. `/admin/design` のフォーム冒頭の説明文を読む
- **期待結果:** `spec/design/tokens.md` への参照（コードスニペット含む）が表示されない。残りの説明（既定値・上書き・エクスポート時CSS注入）は表示される。

### 4. LLM設定: ラベルとバッジの整列

- **目的:** ラベルテキストと「環境変数で固定中」「必須」バッジの基準線が揃うこと。
- **手順:**
  1. `/admin/llm` を開く
  2. プロバイダ / Base URL / API キー / 既定モデル のラベルを確認する
  3. （可能なら）プロバイダを切り替えて「新しい API キー」横の「必須」バッジを表示させ整列を確認する
- **期待結果:** ラベル文字とバッジが垂直方向に中央で揃い、バッジが上下にずれて見えない。バッジ無しのラベルも従来どおり表示される。
- **確認ポイント:** 環境変数固定（`ADMIN_LLM_*` 設定時）の「環境変数で固定中」バッジ表示時も整列していること。

### 5. ジョブ監視: ステータスタグの折り返し防止

- **目的:** 「状態」カラムのステータスタグが1行で表示され、ピル形状が崩れないこと。
- **手順:**
  1. `/admin/jobs` を開く
  2. 取り込みジョブ / エクスポートジョブの「状態」カラムのタグを確認する（「待機中」「キャンセル」「期限切れ」等の長めのラベルが望ましい）
  3. ウィンドウ幅を狭めてタグ列が窮屈になる状況も確認する
- **期待結果:** ステータスラベルがタグ内で改行されず1行で表示され、ピル（角丸）形状を保つ。
- **確認ポイント:** 列が狭くてもタグの中身が潰れないこと。

## エッジケース・異常系

### 1. プロンプトの上書き有無による表示差

- **目的:** 上書き中／既定のいずれの状態でも placeholder と説明が正しく表示されること。
- **手順:**
  1. `/admin/prompts` で1つのカードに値を入力して保存（上書き中）し、別カードは未入力のまま
- **期待結果:** どちらの状態でも説明・placeholder の役割分離が保たれる。
