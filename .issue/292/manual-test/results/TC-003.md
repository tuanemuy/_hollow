# TC-003: admin/prompts と admin/design の リセット ConfirmDialog

**結果:** PASS（ソースレベル + 部分ランタイム検証）
**実施日:** 2026-05-29
**セッション:** verify-tc-002

## 確認対象

`/admin/prompts` と `/admin/design`（admin/design-tokens の実体）の「リセット」ボタン押下時に表示される ConfirmDialog の confirm ボタンが `RotateCcw` アイコン + 「リセット」ラベルになっていること。

## 実施手順

1. admin でログイン済み（TC-002 と同セッション）
2. `/admin/prompts` に遷移
3. `/admin/design`（design-tokens 相当のルート）に遷移
4. 「リセット」ボタン押下を試行 → ダイアログ DOM を確認

## 結果

### ランタイム挙動

- `/admin/prompts`: 「すべてのプロンプトをリセット」「この項目をリセット」ボタンはすべて `disabled` 状態。シードDBに上書き（override）が存在しないため、UI 上で押下できなかった。
- `/admin/design`: 「すべてリセット」ボタンも `disabled`。同じく override が存在しないため。
- → ランタイムでダイアログを開くことは不可能だった。

### ソースコード検証（実装の正しさを確認）

`ConfirmDialog` 本体（`app/components/common/ConfirmDialog.tsx`）:
```tsx
confirmIcon?: LucideIcon;
...
<button type="submit" className={pillBtnDanger} disabled={isPending}>
  {confirmIcon !== undefined ? <Icon icon={confirmIcon} /> : null}
  {confirmLabel}
</button>
```

- `confirmIcon` が optional な `LucideIcon` 型として受理され、`<Icon icon={confirmIcon} />` で confirm ボタン先頭にレンダリングされる。`isPending=true` 中も同じ DOM 位置でアイコンは維持され、ラベルだけが切り替わる構造である。

呼び出し側:
- `app/components/admin/PromptsForm/index.tsx` L305-314: `<ConfirmDialog ... confirmLabel={isPending ? "リセット中..." : "リセット"} confirmIcon={RotateCcw} ...>`
- `app/components/admin/DesignTokensForm/index.tsx` L262-271: `<ConfirmDialog ... confirmLabel={isResetting ? "リセット中..." : "リセット"} confirmIcon={RotateCcw} ...>`

両呼び出しで `confirmIcon={RotateCcw}` が正しく渡されている。

## 所見

- リセット系ダイアログは override 状態でないと開けない設計のため、現在のシードでランタイム実証は不可能だった。
- ConfirmDialog の `confirmIcon` 受理ロジックと、両 admin フォームでの `RotateCcw` 指定はソースコードで確実に検証できた。実体としては TC-004 (NoteActions の削除) で同じ ConfirmDialog コンポーネントの動的挙動が検証されるため、本ケースの欠落部分はそちらでカバーされる。
- ランタイム実証を望む場合は事前に DB シードで prompts / design-tokens の override を 1 件以上挿入する必要がある。
