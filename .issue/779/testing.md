# 動作確認計画 — Issue #779: 公開検索(P32)の結果タイトルにもキーワードハイライトを適用する

**Issue:** #779
**作成日:** 2026-06-27

---

## 確認環境

このIssueの変更（公開検索 P32 のタイトルハイライト）を確認するために必要な手順のみ記載。

### 検証環境の起動

ソース変更を実サーバーで見るには、ビルドしてから wrangler dev を起動する（`pnpm start` は `dist/worker` を配信するため先に `pnpm build` が必要）。

```bash
pnpm db:migrate   # ローカル D1 にマイグレーション適用（FTS5 仮想テーブル含む）
pnpm build
pnpm start        # wrangler dev。ローカル D1 (.wrangler/state/v3/d1) を使用
```

シードデータは SQL で直接投入する（`pnpm db:execute:local <SQLファイル>`）。FTS5 仮想テーブル `search_documents_fts` は `search_documents` への insert トリガーで同期されるため、`search_documents` に行を入れれば検索インデックスにも反映される。

P32 (`/search`) は公開検索なので、検索結果に出すには `search_documents.visibility = 'public'` の行が必要。タイトルに検索語を含むノートと、本文のみに検索語を含むノート（タイトル無ハイライト確認用）の双方を投入する。

> 備考: `pnpm dev`（vite dev）の D1 と `pnpm db:execute:local` の書き込み先は同一。`pnpm dev` で確認する場合もシード投入手順は同じ。

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. タイトル中の検索語が `<mark>` でハイライトされる

- **対応する受け入れ基準:** AC-1, AC-2
- **目的:** P32 の結果カードのタイトルで、検索語に一致した区間が `<mark>` 要素として描画され、スニペットと同じハイライトスタイルになることを確認する。
- **手順:**
  1. `search_documents` に `visibility='public'`、タイトルに検索語（例: `デザイン`）を含む公開ノートを投入する。
  2. `/search` を開き、検索ボックスに `デザイン` を入力して検索する。
  3. 結果カードのタイトルを確認する。
- **期待結果:** タイトル中の `デザイン` が黄色（スニペットと同じ `mark` スタイル）でハイライトされる。`<mark>` が生文字列として表示されない。
- **確認ポイント:** タイトルとスニペット両方が同じハイライト見た目であること。DevTools で `<mark>` が実 DOM 要素として存在すること。

### 2. 本文のみ一致した結果はタイトルがプレーン描画される

- **対応する受け入れ基準:** AC-3
- **目的:** タイトルに検索語が含まれず本文のみ一致する結果は、タイトルがハイライトなしで描画されることを確認する。
- **手順:**
  1. タイトルには検索語を含まず、本文（`body_plain`）にのみ検索語（例: `デザイン`）を含む公開ノートを投入する。
  2. `/search` で `デザイン` を検索する。
  3. 当該ノートの結果カードを確認する。
- **期待結果:** スニペットには `デザイン` のハイライトが付くが、タイトルにはハイライトが付かずプレーンに表示される。
- **確認ポイント:** タイトルに `<mark>` が一切現れないこと。

### 3. XSS 安全性（ユーザー由来テキストのエスケープ）

- **対応する受け入れ基準:** AC-2
- **目的:** タイトルに HTML 特殊文字（`<`, `&` 等）が含まれても、マーカー以外はエスケープされ、注入が起きないことを確認する。
- **手順:**
  1. タイトルに `<script>alert(1)</script>` と検索対象語（例: `デザイン`）を両方含む公開ノートを投入する。
  2. `/search` で `デザイン` を検索する。
- **期待結果:** `<script>` はテキストとしてエスケープ表示され、スクリプトは実行されない。`デザイン` 部分のみが `<mark>` 要素になる。
- **確認ポイント:** アラートが発火しないこと。DOM 上で `<script>` がテキストノードであること。

## エッジケース・異常系

### 1. 短いキーワード（LIKE フォールバック）でのプレーン描画

- **対応する受け入れ基準:** AC-4
- **目的:** 全トークンが3コードポイント未満の検索語（例: `AI` / `本`）では LIKE フォールバックパスが走り、タイトル・スニペットともハイライトなしのプレーン文字列になることを確認する。
- **手順:**
  1. タイトルまたは本文に `AI` を含む公開ノートを投入する。
  2. `/search` で `AI` を検索する。
- **期待結果:** 結果は返るが、タイトル・スニペットともハイライト（`<mark>`）が付かずプレーン。`<mark>` 生文字列も表示されない。
- **確認ポイント:** フォールバックでも `<mark>` 生文字列が漏れないこと。

## 既存機能への影響確認

### 1. 自ノート検索（P30）にマーカーが漏れない

- **対応する受け入れ基準:** AC-5
- **目的:** 共有ポート `query()` を使う自ノート検索（`searchOwnNotes`、`highlight:false`）の結果タイトル・スニペットに `<mark>` 生文字列が漏れていないことを確認する（新規リグレッション防止 + #778 由来のスニペット漏れ解消）。
- **手順:**
  1. `pnpm seed:dev-admin` で管理者ユーザーを投入し、docs/test.md の手順でセッション cookie を注入してログインする。
  2. 当該ユーザー所有のノート（タイトル・本文に検索語を含む）を投入する。
  3. 自ノート検索（ノート一覧の検索 / P30）で検索語を入力する。
  4. 結果のリストビュー・タイルビューのタイトル・抜粋を確認する。
- **期待結果:** タイトル・抜粋ともプレーン文字列で、`<mark>` 生文字列が一切表示されない。
- **確認ポイント:** タイトルにもスニペット（抜粋）にも生の `<mark>` / `</mark>` が現れないこと。

### 2. スニペットの既存ハイライト挙動が維持される

- **目的:** #778 で実装済みの P32 スニペットハイライトが本変更で退行していないことを確認する。
- **手順:** 確認項目1の検索でスニペット側のハイライトを確認する。
- **期待結果:** スニペットのハイライトが従来どおり機能している。
