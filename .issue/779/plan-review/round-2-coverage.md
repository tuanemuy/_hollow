# Plan Review (Round 2) — Issue #779: 要件カバレッジ・スコープ整合性

（P-001 / S-001 / S-002）の反映妥当性、(b) 新たなカバレッジ漏れ・検証可能性・
ステップ紐づけ・スコープ逸脱、を確認した。

  （ステップ3を除外）、AC-5 が `1,2,3,4,7`（ステップ3を追加）に修正されている
  （plan.md L17, L21）。AC-5 の中核実装であるステップ3（`searchOwnNotes` の
  `highlight:false`）が正しく紐づき、トレーサビリティの反転が解消されている。

  `L928`（タイトル `<mark>` 例）、`L511`（`.result-title mark`）も実ファイルと一致しており、
  追加された行参照に事実誤りはない。

## 問題点（要修正）

問題点ゼロ。

AC-1〜AC-5 は Issue 本文の合意要件（P32 タイトルハイライト／モック整合／バックエンド
FTS 変更／`highlightSnippet` 再利用／他サーフェス非リグレッション）を漏れなく覆い、
各 AC は検証可能な形（`<mark>` 要素の有無、プレーン描画、フラグ伝播）で記述され、
対応ステップ・テスト方針に紐づいている。スコープ外（自ノートへの新規ハイライト追加、
`highlightSnippet` 共有モジュール移設）は明示除外され、逸脱はない。1周目で反転していた
クロスリファレンスが正され、計画全体の整合が取れている。

## 改善提案（検討推奨）

- **[S-001]** AC-4 の対応ステップが `2` のみで、テスト（ステップ6）が含まれていない。
  - 理由: テスト方針には「LIKE フォールバックで `hit.title`/`hit.snippet` ともプレーン」の
    アダプタ統合テストが明記されている（plan.md L151）。AC-3 は `2,6` とテストステップを
    含むのに対し、同じくアダプタ統合テストで検証される AC-4 がステップ6を欠くのは
    軽微なトレーサビリティの非対称。AC-4 を `2,6` にすると検証根拠が一意になる。
    実装スコープは増えない（テスト自体は既に方針に存在）。

## 良い点

- 1周目の3指摘がいずれも過不足なく反映され、かつ追加された行参照（L511/L928/L984）が
  実ファイルと完全一致している。指摘の機械的反映でなく、根拠の確定化まで踏み込めている。
- AC-5（横断リグレッション防止）が、共有ポート `query()` の3サーフェス利用と自ノート
  loader のプレーン描画という実態に基づいて中核ステップ3へ正しく紐づき、本Issue最大の
  落とし穴がトレーサビリティ上も明示された。
- `searchUserPublicNotes` の扱いが「未決→不在確認済み」へ確定し、実装者の判断負荷を
  残さない計画になっている。スコープ境界と副次効果（自ノートスニペット漏れの是正）の
  開示も維持されている。
