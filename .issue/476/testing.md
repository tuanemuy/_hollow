## 確認項目

### 1. 期間プリセット変換・ラベル整形のユニットテスト

- **目的:** 期間プリセット → `{from, to}` 変換と期間／公開状態チップのラベル整形が回帰しないことをコードで担保。
- **手順:**
  1. `pnpm test:unit` を実行
  2. `app/components/note/list/__tests__/listSelectors.test.ts` の新規ケースが PASS することを確認
- **期待結果:** 各プリセット（今日／今週／今月／過去30日／過去90日／今年）が基準日に対し正しい `from`/`to`（`YYYY-MM-DD`）を返す。月またぎ・年またぎの境界も正しい。
- **確認ポイント:** ローカル日付計算で UTC ずれによる1日のずれが起きないこと。

### 2. 期間フィルター（チップ＋ポップオーバー）

- **目的:** むき出し date input が消え、チップ＋ポップオーバーで期間指定でき、URL と同期することを確認。
- **手順:**
  1. `pnpm dev` で `/` を開く
  2. 「期間」ghost トリガーチップを押し、ポップオーバーが開くことを確認
  3. プリセット「今月」を押す → from/to が自動セットされ、一覧が絞り込まれ、URL に `?from=...&to=...` が反映されることを確認
  4. 日付入力を手で変更 → プリセット選択が外れ、即時に一覧・URL が更新されることを確認
  5. チップが `期間: {from}–{to} ×` の dark 表示になることを確認。`×` で個別解除できることを確認
  6. ポップオーバー内「クリア」で範囲が解除されることを確認
- **期待結果:** ポップオーバー操作で期間が即時反映され、URL・一覧・チップ表示が一致する。
- **確認ポイント:** `from` のみ／`to` のみの片側指定でも破綻しないこと。

### 3. 公開状態フィルター（チップ＋ポップオーバー単一選択）

- **目的:** `<select>` が消え、状態色スウォッチ付きの単一選択ポップオーバーで公開状態を絞り込めることを確認。
- **手順:**
  1. 「公開状態」ghost トリガーチップを押す → すべて／非公開／限定公開／公開 の選択肢が状態色スウォッチ付きで表示
  2. 「公開」を選択 → 即座に `visibility=public` が反映されポップオーバーが閉じる。チップが `公開状態: 公開 ×` 表示になる
  3. 再度開いて「すべて」を選択 → `visibility` が解除（URL から消える）されることを確認
  4. `×` でチップから直接解除できることを確認
- **期待結果:** 単一選択で即時反映＆クローズ。状態色（公開=緑／限定公開=橙／非公開・すべて=グレー）が正しい。
- **確認ポイント:** 選択中の項目に選択表示（チェック等）が出ること。

### 4. チップ語彙の一貫性とすべてクリア

- **目的:** タグ／期間／公開状態／ディレクトリ／内部リンク参照が同じ pill チップ＋× 語彙で並び、すべてクリアで一括解除できることを確認。
- **手順:**
  1. 複数フィルター（タグ＋期間＋公開状態＋ディレクトリ＋内部リンク参照）を適用
  2. すべてが統一された見た目のチップで並ぶことを確認
  3. 「すべてクリア」で全フィルターが解除され、URL がクリーンになることを確認（`display` / `q` は維持）
- **期待結果:** 全チップの見た目が統一され、一括解除が効く。
- **確認ポイント:** すべてクリアが `display` / `q` を残すこと（既存挙動）。

### 5. キーボード操作・a11y

- **目的:** ポップオーバーがキーボードで操作でき、`<select>` 廃止後も同等以上の a11y を担保することを確認。
- **手順:**
  1. Tab でトリガーチップへフォーカス → Enter/Space で開く
  2. ポップオーバー内を矢印キー等で操作、Enter で選択
  3. `Escape` で閉じ、フォーカスがトリガーチップへ戻ることを確認
  4. ポップオーバー外をクリックで閉じることを確認
  5. スクリーンリーダー観点で `aria-haspopup` / `aria-expanded` / ラベルが付与されていることを DevTools で確認
- **期待結果:** マウスなしで全フィルターを操作でき、フォーカス復帰が正しい。
- **確認ポイント:** `aria-busy`（読み込み中）・`aria-pressed`（タグトグル）が維持されていること。

### 6. モバイル幅

- **目的:** 狭幅でチップが折り返し、ポップオーバーが画面端で溢れないことを確認。
- **手順:**
  1. DevTools レスポンシブで幅 375px にする
  2. チップ群が自然に折り返すことを確認
  3. 各ポップオーバーを開き、画面外に溢れず操作できることを確認
  4. タップターゲットが十分な大きさ（44px 目安）であることを確認
- **期待結果:** むき出し input/select が無くなり縦の圧迫が減る。狭幅でも破綻しない。

## エッジケース・異常系

### 1. ポップオーバーの多重表示

- **目的:** 期間と公開状態のポップオーバーが意図せず同時表示にならないことを確認。
- **手順:**
  1. 「期間」を開いた状態で「公開状態」を押す
- **期待結果:** 一方を開くともう一方は閉じる（または少なくとも重なって操作不能にならない）。

### 2. フィルター追加時のページリセット

- **目的:** 2ページ目以降を見ている状態でフィルターを追加してもページが破綻しないことを確認。
- **手順:**
  1. `?page=2` の状態で期間・公開状態フィルターを適用
- **期待結果:** ページがスキーマ既定にリセットされ、`?page=N` が URL から消える（既存 handlePick と同様）。

## 既存機能への影響確認

- タグトグル・「もっと見る」折りたたみ（#354）が引き続き動作すること。

- `useOptimistic` の即時反映・`aria-busy` のローディング表示が維持されること。
