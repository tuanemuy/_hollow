# 動作確認計画 — Issue #601: 公開検索(P32)スニペットの FTS5 `<mark>` ハイライト描画

**Issue:** #601
**作成日:** 2026-06-26

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm dev
```

Cloudflare runtime (Vite) のローカル開発サーバーが起動する。公開検索画面は `/search` で確認できる。

### シードデータ

公開ノートが少なくとも1件必要。検索語が本文に含まれるノートを用意し、その語で検索することでスニペットにハイライトが付く状態を作る（FTS インデックスは outbox/consumer 経由で更新されるため、ノート作成後に検索ヒットするまで反映を待つ）。

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. スニペットのハイライトが要素として描画される

- **対応する受け入れ基準:** AC-1, AC-4
- **目的:** スニペット中の検索語が生タグではなく背景色付きの `<mark>` として表示されることを確認する。
- **手順:**
  1. `pnpm dev` で起動し `/search` を開く。
  2. 公開ノート本文に含まれる単語で検索する。
  3. 結果カードのスニペットを確認する。
- **期待結果:** 検索語に accent 系の背景色が付いてハイライトされる。`<mark>` `</mark>` という生文字列は表示されない。
- **確認ポイント:** ハイライトの背景色・文字色が P32 モック (`spec/design/pages/P32-public-search.html`) の `mark` スタイルと一致しているか。

### 2. マーカーを含まないスニペットも正しく出る

- **対応する受け入れ基準:** AC-3
- **目的:** ハイライト対象が無い／少ないスニペットでも従来どおりテキストが崩れず表示される。
- **手順:**
  1. 検索語がタイトルにのみ一致し本文スニペットにマーカーが付きにくいケースなどで検索する。
- **期待結果:** スニペットが通常テキストとして正しく表示される。

## エッジケース・異常系

### 1. ユーザー本文に HTML 風の文字列が含まれる

- **目的:** 本文に `<`, `>`, `<script>` 等が含まれてもエスケープされ、HTML インジェクションが起きないことを確認する（XSS 防止）。
- **手順:**
  1. 本文に `<b>test</b>` や `<script>` を含む公開ノートを作成し、その語で検索する。
- **期待結果:** タグはエスケープされたテキストとして表示され、実 DOM 要素やスクリプトとして解釈されない。ハイライト（`<mark>`）部分のみ要素化される。

## 既存機能への影響確認

- **検索結果の一覧表示全般:** スニペット描画の差し替えにより、件数表示・ページネーション・フィルタ・ソートなど他の検索 UI に影響が出ていないこと。
- **ユニットテスト:** `pnpm typecheck && pnpm test` がパスすること（`highlightSnippet` の新規テスト含む）。
