# 動作確認計画 — Issue #642: 公開検索(P32)にソート選択肢（新着順など）を追加する

**作成日:** 2026-06-13

## 確認環境

このIssueの変更（公開検索画面 `/search` のソートトグルと並び順）を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm db:migrate    # ローカル D1 にマイグレーション適用（初回・未適用時のみ。本Issueに新規マイグレーションはない）
pnpm dev           # vite dev (workerd) on http://localhost:3000
```

確認 URL: `http://localhost:3000/search?q=<キーワード>`

### デプロイ方法

なし（検証環境のみで確認できる）。

### シードデータ

- 公開（public）ノートが複数件、**異なる `updated_at`・複数ユーザー・複数タグ**であること（並び替えの差分とファセット確認に必要）。
- 検索インデックス（`search_documents`）にノートが反映されていること。
- 同一キーワードに対して bm25 関連度順と更新日時順が異なる並びになるデータが望ましい（例: 古いノートほどキーワード出現頻度が高い）。シードの整備は manual-test スキルに委ねる。

## 確認項目

### 1. ソートトグルで並びが切り替わる

- **対応する受け入れ基準:** AC-2
- **目的:** 関連度順 ⇄ 新着順の切替で結果の並びが実際に変わる。
- **手順:**
  1. `/search?q=<複数件ヒットするキーワード>` を開き、結果の並び（関連度順）を控える。
  2. ツールバーのソートボタン（「関連度順」+ 下矢印）をクリックする。
  3. 表示が「新着順」に変わり、結果の並びを確認する。
  4. もう一度クリックして「関連度順」に戻す。
- **期待結果:** 新着順では結果カードの更新日時（カード右列に表示）が降順に並ぶ。関連度順に戻すと元の並びに戻る。
- **確認ポイント:** 新着順の並びがカードに表示されている `updatedAt` と一致すること（`published_at` ではない）。

### 2. ソート状態が URL に保持される

- **対応する受け入れ基準:** AC-3, AC-7
- **目的:** `sort` パラメータの URL 保持と省略時のデフォルト。
- **手順:**
  1. ソートを新着順に切り替え、アドレスバーを確認する。
  2. その URL でリロードする。
  3. URL をコピーして新しいタブで開く。
  4. 関連度順に戻し、アドレスバーを確認する。
- **期待結果:** 新着順で URL に `sort=newest` が付き、リロード・別タブでも新着順が維持される。関連度順に戻すと `sort` が URL から消える（`sort=relevance` を付けない）。
- **確認ポイント:** `sort` なしの既存 URL が従来どおり関連度順で表示される（後方互換）。

### 3. ソート切替時に1ページ目へ戻る（cursor リセット）

- **対応する受け入れ基準:** AC-5
- **目的:** オフセットカーソルが並び替え後の順序に不正に適用されない。
- **手順:**
  1. 結果が複数ページになるキーワードで検索し、「次のページ」で2ページ目以降へ進む（URL に `cursor` が付く）。
  2. その状態でソートトグルをクリックする。
- **期待結果:** URL から `cursor` が消え、新しい並びの1ページ目が表示される。
- **確認ポイント:** `q` / ユーザー / タグ / 期間など他のパラメータは維持されること。

### 4. 新着順でのページネーション連続性

- **対応する受け入れ基準:** AC-2, AC-3
- **目的:** 新着順のままページ送りしても並び・状態が壊れない。
- **手順:**
  1. `sort=newest` で複数ページになる検索を行う。
  2. 「次のページ」リンクで2ページ目へ進む。
- **期待結果:** 2ページ目の URL に `sort=newest` が維持され、1ページ目末尾より古い（または同時刻で `note_id` 順の）結果が重複・欠落なく続く。

### 5. LIKE フォールバック経路でも新着順が効く

- **対応する受け入れ基準:** AC-6
- **目的:** 全トークンが 3 codepoint 未満で LIKE 経路になる場合も新着順が機能する。
- **手順:**
  1. 短いクエリ（例: CJK 1〜2文字）で検索し、LIKE 経路でヒットさせる。
  2. ソートを新着順に切り替える。
- **期待結果:** 新着順で `updated_at` 降順に並ぶ。関連度順に戻すと従来どおりの安定順（`note_id` 昇順）に戻る。

### 6. ファセット変更で sort が維持される

- **対応する受け入れ基準:** AC-3
- **目的:** `SearchFilterDrawer` の `...prev` スプレッドに依存した `sort` 維持の回帰確認（レビュー arch-risk S-002）。
- **手順:**
  1. `sort=newest` の状態で「絞り込み」ドロワーを開く。
  2. ユーザー / タグ / 期間のいずれかのファセットを変更する。
- **期待結果:** URL に `sort=newest` が残り、表示も新着順のまま絞り込まれる。
- **確認ポイント:** キーワード再送（検索フォームから再検索）でも `sort` が維持されること（hidden input 経由）。

### 7. ソートボタンの見た目がモックと整合

- **対応する受け入れ基準:** AC-4
- **目的:** `.sort-btn`（pill、下矢印付き、hover で surface）との見た目の一致。
- **手順:**
  1. ブラウザで `spec/design/pages/P32-public-search.html` を直接開き、ソートボタンの見た目を確認する。
  2. `/search?q=...` のソートボタンと比較する（高さ 36px / pill / 13px テキスト / 下矢印 / hover で背景 surface 化）。
  3. ウィンドウ幅を sm 未満に縮め、ボタン高さが 44px になることを確認する。
- **期待結果:** 実装とモックの見た目が一致する。ホバーで背景・文字色が変化し、クリック可能であることが視覚的に伝わる。
- **確認ポイント:** モック側も `.sort-label` から `.sort-btn`（下矢印付き）へ戻っていること。

### 8. spec の更新

- **対応する受け入れ基準:** AC-1
- **目的:** `spec/pages/index.md` P32 にソート選択肢が定義されている。
- **手順:**
  1. `spec/pages/index.md` の P32 を読む。
  2. `spec/domains/search.md` / `spec/usecases/search.md` の `sort` 記述を確認する。
- **期待結果:** P32 にソート選択肢（関連度順 / 新着順、`sort` パラメータ、省略時関連度順、切替時 cursor リセット、period × newest の時間軸差）が記載され、domains に `SearchSort` とカウント系非影響、usecases に入力DTOの `sort` が記載されている。

## エッジケース・異常系

### 1. 不正な sort 値の URL

- **目的:** `validateSearch` の `.catch(undefined)` により不正値がデフォルトに落ちる。
- **手順:** `/search?q=...&sort=oldest` のような不正値を手入力で開く。
- **期待結果:** エラーにならず関連度順で表示される（500 やクラッシュなし）。

### 2. 旧 sort の cursor を含む手組み URL

- **目的:** 並び替え後の順序にオフセットが適用されてもエラーにならない。
- **手順:** 関連度順2ページ目の URL に手で `&sort=newest` を追記して開く。
- **期待結果:** エラーにならず、新着順のオフセット位置の結果が表示される（内容は直感に反してもよいが整合的）。

### 3. 検索結果ゼロ・1件

- **目的:** ソートトグルが結果数に関わらず壊れない。
- **手順:** ヒットしないキーワード、および1件だけヒットするキーワードでトグルを操作する。
- **期待結果:** 空状態・1件表示が従来どおりで、トグル操作でもエラーにならない。

## 既存機能への影響確認

- **自分のノート検索（P30 系 `/notes/search`）**: ソートUIは追加されず、並びが従来どおり（デフォルト relevance）であること。
- **ユーザー公開ページ検索（`/u/{username}` 内検索）**: 同上、並び・表示に変化がないこと。
- **ファセットカウント（期間ファセットの件数表示）**: `sort=newest` でもドロワー内の件数が relevance 時と同一であること（カウントはソート非依存）。
- **関連度順の既存挙動**: `sort` なし URL の検索結果の並びが変更前と同一であること（既存 integration テストが回帰ガード。ブラウザでは代表キーワード1つでスポット確認）。
