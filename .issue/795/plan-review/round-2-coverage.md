## カバレッジ維持確認（修正による新たな漏れ・矛盾なし）

- **AC 8 項目**: AC-1〜AC-8 すべて表に残存、由来・対応ステップ列も維持。修正で削除・改変なし。
- **Scope (mock first) 3 項目**: Step 1 / Step 2 / Step 3-5+ADR-001 へのマッピング維持。
- **Design questions 3 点**: 共有 vs 軽量（ADR-001）/ single vs multi（スコープ）/ toolbar 配線（スコープ）すべて維持。
- **状態機械の一貫性**: `selected` 削除後、AC-2（L18）・設計 item 3（L82）・Step 1（L92）・Step 5（L128-133）すべてで「独立した確認待ち状態を設けない／選択即アップロード」が統一されており、`done` への遷移（idle→uploading→done / uploading→error）も整合。新たな状態矛盾は発生していない。
- **ADR ↔ plan の整合**: ADR-001 L19/L23 の「2 consumer + editor = 3 箇所」表現が plan.md と一致。ADR-002 の Consequences L48 に「UX 上限は別途設けず server cap を SSOT」が追記され、見送り提案（S-001 arch-risk）と整合。

#### 問題点（要修正）

問題点ゼロ。1周目の P-001 / P-002 はいずれも実コード照合の上で正しく修正され、修正による新たな矛盾・カバレッジ漏れは検出されなかった。

#### 改善提案（検討推奨）

- **[S-001]** スコープ「含まれないもの」L32 は `DROPZONE` 文字列のみを共有プリミティブへ移設し「挙動・見た目は不変」とするが、`UploadDialog.tsx:58` と `UploadForm.tsx:30` の 2 定義が「完全一致」である前提に立っている（plan も「同一インライン」と明記）。実装時に万一 2 定義間で 1 文字でも差分があれば「完全不変移設」が破れる。Step 3 / リスク欄に「移設前に両定義の文字列 diff を取り完全一致を確認してから単一化する」という前提検証の一文を足すと、移設の安全性がより担保される（計画自体は grep で 2 箇所を確認済みなので軽微）。

#### 良い点

- 1周目の 2 つの問題点を、単に文言修正するだけでなく **実コードを grep して行番号・定義箇所を事実ベースで訂正**し、レビュー履歴（L182-194）に修正・取込・見送りを分類して記録している。トレーサビリティが高い。
- P-002 修正で `UploadDialog.tsx` を共有化スコープへ追加した際、調査結果・スコープ・Step 3・リスク欄・ADR-001 の **5 箇所すべてを横断的に同期**しており、片側だけ直して新たな不整合を残す典型的失敗を避けている。
- P-001 修正で「single-file / toolbar はスコープ判断であって ADR ではない」という線引きを plan 全体で一貫させ、ADR の責務（dropzone 抽象化粒度の決定）を肥大化させていない。ADR と plan スコープの責務分離が明確。
- 修正後も AC 8 項目・Scope 3 項目・Design questions 3 点のカバレッジが完全に維持され、スコープクリープ・スコープ縮小のいずれも発生していない。
