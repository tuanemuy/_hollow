# 動作確認計画 — Issue #289: DirectoryActionsMenu の menuitem 内キーボードナビゲーション（roving tabindex）

**Issue:** #289
**作成日:** 2026-05-29

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm db:migrate   # ローカル D1 にマイグレーション適用（未適用の場合のみ）
pnpm dev          # 開発サーバー起動
```

ディレクトリツリーは認証済みユーザーのサイドバーに表示される。シードデータ（ユーザー + 子を持つディレクトリ階層）の準備は manual-test に委ねる。

### デプロイ方法

なし（検証環境のみで確認できる。フロントエンドのコンポーネント変更のみ）。

## 確認項目

### 1. 上下矢印での menuitem 移動

- **目的:** メニュー内を ArrowDown / ArrowUp でフォーカス移動できる。
- **手順:**
  1. サイドバーのディレクトリ行にホバー（またはモバイル幅）して `︙` ボタンにフォーカスし、Enter/Space で開く
  2. メニューが開くと先頭項目「子ディレクトリを作成」にフォーカスが当たっていることを確認
  3. ArrowDown を押す → 「リネーム」にフォーカス移動
  4. さらに ArrowDown → 「移動」→「削除」と移動
  5. ArrowUp で逆方向に移動
- **期待結果:** フォーカスリング（`focus:bg-surface`）が押下ごとに次/前の項目へ移る。
- **確認ポイント:** 矢印キーでページや背後のツリーがスクロール/移動しない（preventDefault / stopPropagation が効いている）。

### 2. ラップ（端での折り返し）

- **目的:** 末尾→先頭、先頭→末尾へラップする。
- **手順:**
  1. メニューを開き「削除」（末尾）まで ArrowDown で移動
  2. さらに ArrowDown → 先頭「子ディレクトリを作成」へラップ
  3. 先頭で ArrowUp → 末尾「削除」へラップ
- **期待結果:** 端で押すと反対端へフォーカスが回る。

### 3. Home / End

- **目的:** Home で先頭、End で末尾へジャンプ。
- **手順:**
  1. メニューを開き、中間項目（例: 「移動」）へ移動
  2. Home を押す → 「子ディレクトリを作成」へ
  3. End を押す → 「削除」へ
- **期待結果:** 端へ即ジャンプする。

### 4. roving tabindex（Tab 挙動）

- **目的:** フォーカス中の項目のみ tab 順に乗る。
- **手順:**
  1. メニューを開く（先頭にフォーカス）
  2. 矢印で「移動」へフォーカスを移す
  3. Tab を押す
- **期待結果:** メニューがクローズし、フォーカスがメニュー外（次のタブ可能要素）へ移動する。メニュー内の他項目を Tab で巡回しない。

### 5. 選択の実行とフォーカス復帰

- **目的:** キーボードで項目を選べる／Escape でトリガーへ戻る。
- **手順:**
  1. メニューを開き、矢印で「リネーム」へ移動して Enter
  2. リネーム操作が起動することを確認
  3. 別途メニューを開いて Escape を押す
- **期待結果:** Enter で当該操作が実行される。Escape でメニューが閉じ、フォーカスが `︙` トリガーへ戻る。

## エッジケース・異常系

### 1. マウスとキーボードの混在

- **目的:** マウスホバー後に矢印キーを使っても破綻しない。
- **手順:**
  1. メニューを開き、マウスで「移動」にホバー
  2. ArrowDown を押す
- **期待結果:** クラッシュせず、フォーカス制御に従ってメニュー内移動が続く（マウス操作中もメニューは閉じない）。

## 既存機能への影響確認

- ツリーの treeitem 自体の ArrowUp/Down（兄弟ノード移動）が、メニューを閉じた状態では従来どおり機能すること。
- メニューを開いている間はツリーの矢印移動が発火しないこと（二重発火しない）。
- マウスクリックでの 4 操作（作成/リネーム/移動/削除）が従来どおり動くこと。
