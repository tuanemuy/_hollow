## 前提データ

言語クラス付きのコードブロックを含むノートが必要。次のいずれかで用意する：

- 既存ノートで HTML モードに切替え、本文に以下を入力して保存する：
  ```html
  <p>サンプル段落</p>
  <pre><code class="language-typescript">function hello(name: string): string {
    const greeting = "Hello, " + name; // greet
    return greeting;
  }</code></pre>
  <p>末尾の段落</p>
  ```
- 言語クラス無しの `<pre><code>plain code</code></pre>`、および `<pre>code text</pre>`（`<code>` ラップ無し）のノートも各 1 件用意し、フォールバックと両構造をカバーする。

## 確認項目

### 1. 読み取り専用ビューのシンタックスハイライト

- **目的:** 読み取り専用ビューで `<pre><code class="language-X">` に色が付くことを確認（要件2）
- **手順:**
  1. 前提データの TypeScript コードブロックを含むノートの詳細画面（読み取り専用）を開く
  2. キーワード（`function`/`const`/`return`）・文字列（`"Hello, "`）・コメント（`// greet`）・関数名・数値の表示色を確認する
- **期待結果:**
  - トークン種別ごとに `--code-keyword` / `--code-string` / `--code-comment` / `--code-function` / `--code-number` に対応する色が付く
  - コードブロックの背景・角丸・モノスペース体裁（既存スタイル）は維持される
- **確認ポイント:** 公開ノート（PublicNoteDetail）・履歴版（NoteRevisionDetail）・法的文書（LegalDocument）でも同様に色が付くこと

### 2. 言語クラス無し / 未対応言語のフォールバック

- **目的:** 言語が解決できないコードブロックは plain（装飾なし）で正しく表示されることを確認
- **手順:**
  1. 言語クラス無しの `<pre><code>plain code</code></pre>` を含むノートを読み取り専用で開く
- **期待結果:** 色は付かず、既存どおりのモノスペース表示になる（エラーやレイアウト崩れが起きない）
- **確認ポイント:** これは仕様どおりの正しい挙動（バグではない）

### 3. inline 編集ビューでのハイライトと「focus 中プレーン」

- **目的:** inline 編集ビューでハイライトが当たり、フォーカス時にプレーン化、blur で再ハイライトされることを確認（要件2 / ADR-002）
- **手順:**
  1. TypeScript コードブロックを含むノートを「編集」（inline モード）で開く
  2. コードブロック以外の領域を見て、コードブロックにハイライトが当たっていることを確認
  3. コードブロック内をクリックしてフォーカスを入れる
  4. 文字を編集し、コードブロック外をクリック（または `Esc`）して blur する
- **期待結果:**
  - フォーカスが入るとそのコードブロックはプレーン（装飾なし）になり、編集中にキャレットが飛ばない
  - blur すると再ハイライトされ、キャレット編集位置が崩れていない
  - 他のコードブロック（フォーカスしていないもの）はハイライトされたまま
- **確認ポイント:** ハイライト span が編集の邪魔をせず、巻き戻り（ロールバック）が起きないこと

### 4. `<pre>` 内の Tab インデント / Shift+Tab デデント / Esc 脱出

- **目的:** ADR-004 の Tab インデント・エスケープ手段を確認（要件1）
- **手順:**
  1. コードブロック内の行頭にキャレットを置き、`Tab` を押す
  2. 同じ行で `Shift+Tab` を押す
  3. コードブロック内で `Esc` を押す
  4. コードブロック**外**の段落で `Tab` を押す
- **期待結果:**
  - `<pre>` 内 `Tab`: スペース2が挿入される（コードブロックの外へフォーカスが逃げない、巻き戻らない）
  - `<pre>` 内 `Shift+Tab`: 行頭のスペースが最大2除去される
  - `<pre>` 内 `Esc`: 編集領域からフォーカスが外れる（blur）。直後に再ハイライトが走る
  - `<pre>` 外 `Tab`: 従来どおりフォーカス移動が抑止される（新規ブロックへ逃げない）
- **確認ポイント:** `Esc` でフォーカストラップから抜けられること（キーボード操作だけで編集領域を離脱できる）

### 5. 保存後の HTML に span が漏れないこと（最重要）

- **目的:** ハイライト span が保存 HTML（`contentHtml`）に漏れないことを確認（最重要不変条件 / ADR-001・002）
- **手順:**
  1. 確認項目3・4の編集後に保存する
  2. 再度「編集」→ モード切替で「HTML を編集」に切替え、生 HTML を確認する
  3. 読み取り専用ビューに戻る
- **期待結果:**
  - 保存 HTML は clean な `<pre><code class="language-X">text</code></pre>`（または `<pre>text</pre>`）で、`<span class="shiki-token-*">` や `contenteditable` を含まない
  - 読み取り専用ビューでは（クライアント側で）改めてハイライトが当たる
- **確認ポイント:** DB に装飾 span が保存されないこと

## エッジケース・異常系

### 1. IME（日本語入力）でのコードブロック編集

- **目的:** 変換中にハイライトが走って入力が壊れないこと、確定後にロールバックされないことを確認
- **手順:**
  1. コードブロック内で日本語をかな漢字変換して入力・確定する（コメント行など）
  2. 改行を含む入力も試す
- **期待結果:** 変換確定後もテキストが正しく残り、コードブロックが消えたり巻き戻ったりしない。変換中に再ハイライトでプリエディット文字列が壊れない

### 2. JS 無効時のプログレッシブ・エンハンスメント

- **目的:** ハイライトが表示専用派生であり、JS 無効でもコードが読めることを確認
- **手順:**
  1. ブラウザの JS を無効化して読み取り専用ビューを開く
- **期待結果:** 色は付かないが、コードブロックの内容は plain で正しく読める（コンテンツが消えない）

### 3. shiki のロード失敗時の best-effort 挙動

- **目的:** ハイライターのロード／トークン化に失敗してもエディタ・読み取りが機能継続することを確認
- **手順:**
  1. （任意）ネットワーク絞り等で shiki チャンクのロードを遅延／失敗させる
- **期待結果:** ハイライトは当たらないが、編集・保存・読み取りはすべて plain で正常に動く（例外でクラッシュしない）

## 既存機能への影響確認

- **`<pre>` を含まないノートの inline 編集**: 段落・見出し・リスト・引用・テーブルの編集が従来どおり動くこと（Enter で新規ブロックが生成されない、構造保持が効く）。
- **`<pre>` 内の Enter（#285）**: 改行入力が従来どおり動くこと（リテラル `\n` 挿入、外へ離脱しない）。
- **ペースト**: コードブロック内外でのペーストが従来どおりプレーンテキスト挿入で、構造が変わらないこと。
- **disabled 状態**: 編集ロック取得失敗などで disabled のとき、`<pre>` も編集不可になり、ハイライト表示自体は維持されること。
