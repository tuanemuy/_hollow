# TC-004: Tab インデント / Shift+Tab デデント / Esc 脱出

| 項目 | 内容 |
| --- | --- |
| 結果 | PASS |
| 手順 | コードブロック内行頭で Tab → スペース挿入確認 / Shift+Tab → デデント確認 / Esc → blur 確認 |
| 期待 | Tab でスペース2挿入・フォーカス維持・巻き戻らない、Shift+Tab で行頭スペース除去、Esc で離脱 |

## 観察した挙動

### Tab インデント
- TS ブロック 2 行目（`  const message...`、行頭スペース 2）にキャレットを置き `Tab` 押下。
- 行頭スペースが 2 → 4 に増加（**スペース 2 挿入**）。
- ブロック数 2 維持、行数 4 維持、新規ブロックへの離脱なし、巻き戻り（ロールバック）なし。

### Shift+Tab デデント
- 同行（スペース 4）で `Shift+Tab` 押下 → 行頭スペースが 4 → 2 に減少（**2 除去**）。ブロック数 2 維持。

### Esc 脱出
- TS ブロックにフォーカス（plain, `activeElement=PRE`）して `Escape` 押下。
- keydown は document に到達（target=PRE, capture phase）し、ハンドラの `blur()` が実行され `focusout`（`doc-focusout:PRE` / `pre-focusout`）が発火。
- 残存セレクションを除去すると `activeElement=BODY` を維持し、TS ブロックが 10 span に**再ハイライト**された。
- 実装の Esc→blur→focusout→再ハイライト経路は正しく機能。

## ソースコード照合

`app/components/note/editor/InlineEditor.tsx` の `onKeyDown`（L600-645）:
- Tab: `<pre>` 内は `insertTextAtCaret(host, "  ")`、Shift+Tab は `dedentAtCaret`、`<pre>` 外は preventDefault のみ（フォーカス移動抑止）。
- Esc: `<pre>` 内なら `activeElement.blur()`（focus trap 脱出）。
- `onFocusOut`（L737-743）が `pre.blur()` の focusout を受けて `highlightPre` で再ハイライト。

## Esc の検証注記

- プログラム的フォーカス + 残存 Selection の状態では、blur 直後にブラウザがセレクション位置へ focus を戻すアーティファクトが発生（active が PRE に戻り plain のまま見える）。
- これは `.focus()` + Selection API 駆動の副作用であり、`focusout` が確かに発火していること（イベントログで確認）、セレクション除去後に正しく BODY へ抜け再ハイライトされることから、実装は正常と判断。
