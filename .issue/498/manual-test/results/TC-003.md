# TC-003: inline 編集ビューのハイライト / focus 中プレーン / blur 再ハイライト

| 項目 | 内容 |
| --- | --- |
| 結果 | PASS |
| 手順 | 編集画面（inline=「ビジュアル」）で span 確認 → コードブロックにフォーカス → plain 化確認 → 編集 → コードブロック外クリックで blur → 再ハイライト確認 |
| 期待 | focus でプレーン化、編集可能、blur で再ハイライト。巻き戻り（コードブロック消失）が起きない |

## 観察した挙動

- 編集画面は inline（タブ `ビジュアル / FrontMatter / HTML`、`ビジュアル` が既定選択）で開く。
- 初期状態（未フォーカス）: TS ブロック `pre[0]` に 10 span のハイライトあり。`pre[0]` は `contenteditable=true`。
- TS コードブロックへ caret を置きフォーカス: `pre[0]` の span が 0 に（plain 化）。`activeElement === PRE`。
- 文字編集（`X` を末尾に挿入）: コンテンツに反映、ブロック消失なし、2 ブロック維持。
- コードブロック外（タイトル input）を**実クリック**で blur: TS ブロックが再び 10 span にハイライト、focus はタイトルに維持。

## focus-stealing に関する注記

- プログラム的 `.focus()` + Selection API で caret を置いたまま blur すると、残存セレクションにブラウザが focus を戻すループが見られた（active が PRE に戻る）。これは**操作手法のアーティファクト**であり実装バグではない。
- 実クリックによる blur では正しく `activeElement=INPUT` を維持しつつ再ハイライトされた（10 span）。実利用シナリオの挙動は正常。
- 他ブロックの「focus 中もハイライト維持」は、本ノートのハイライト対象が 1 ブロックのみ（no-lang は元来 plain）のため直接検証できず。テストデータ上の制約。
