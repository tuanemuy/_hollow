# TC-07 絞り込みの即時反映

幅1280。実装は `useOptimistic` + `useTransition`（FilterBar.tsx）、結果リストは TanStack Router の `isLoading` を `data-pending` + `opacity-60` で表示（NoteListViews.tsx）。

| 操作 | 期待 | 実際 | 判定 |
|---|---|---|---|
| タグ chip クリック直後の active 反映 | サーバ往復を待たず即座に active | クリック直後（次ペイント）に chip data-active=true / aria-pressed=true / bg=濃色。サーバ確定前に反映 | PASS |
| 結果リストの pending 表示 | aria-busy / 半透明 → 確定後更新 | クリックと同時(t=0ms) に結果コンテナ data-pending=true / aria-busy=true、opacity 1→0.6 へ transition。サーバ確定(約50-60ms,ローカルD1)で data-pending 解除し実データ更新 | PASS |
| 連続でタグを切り替え | 取りこぼしなく全て反映 | 逐次クリック（再レンダー挟む）で3タグ accumulate：全 data-active=true、URL=`["issue259","preview-form","test"]`。別tickでの高速2連打も両方反映（URL両方） | PASS |
| クリアボタン / URL 整合 | optimistic と URL/loader 確定値が一致 | クリアで全解除（TC-04で確認）。フィルタ操作後 URL searchParams と表示 chip の active 状態が一致 | PASS |
| pending 中の操作可否 | disabled で固まらない | コントロールは `disabled` にならず（実装コメント「Controls stay enabled」）、pending 中も操作可能 | PASS |

## 判定: PASS

フィルタ選択は即時反映（optimistic）、結果は pending(opacity-60) → 確定。URL と表示が最終的に一致。

## 観察メモ（実装バグではない）

`button.click()` を**同一 JS tick で3つ同期連射**した場合のみ、URL ナビゲーションのコールバック（`router.navigate` の `search` 関数）が同じ stale な `optimistic.tagNames`（空）をクロージャでキャプチャするため、各 nav が上書きし合い最後のタグ1件のみが URL に残る挙動を観測した。ただしこれは React の再レンダーを挟まない非現実的な同期連射に固有のもので、`useOptimistic` の reducer 自体は最新 base に対して reduce されるため UI 上の optimistic 表示は正しい。実ユーザーのタップ（tick が分かれる）や逐次操作では全タグが正しく accumulate し URL にも反映されることを確認済み（上表「連続でタグを切り替え」行）。よって実装上の問題ではないと判断。
