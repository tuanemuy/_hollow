# 動作確認計画 — Issue #728: 認証状態の遷移（ログイン/ログアウト等）でランディングページが一瞬表示される

**Issue:** #728
**作成日:** 2026-06-14

---

## 確認環境

このIssueの変更はフロントエンドのルーター制御（AppShell キャッシュ破棄と遷移順序）のみ。検証は開発サーバーで、認証状態を実際に遷移させて目視で行う。チラつきは 1 フレームの瞬間表示なので、**ブラウザのネットワークスロットリング（Slow 3G 等）や DevTools の遅延を使うと観測しやすい**。

### 検証環境の起動

```bash
pnpm dev
```

（初回やスキーマが古い場合は `pnpm db:migrate` でローカル D1 にマイグレーションを適用。ログイン用の管理者ユーザーは `pnpm seed:dev-admin` でシードする。）

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. `_app` 配下の各パスからログアウトしてもランディングが挟まらない

- **対応する受け入れ基準:** AC-1
- **目的:** `clearCache → navigate({to:"/login"})` により、ログアウト時に未認証ホーム/ランディングが 1 フレームも描画されないこと。
- **手順:**
  1. シードした管理者でログインする。
  2. `/`（ホーム）でサイドバー下部のユーザーメニューを開き「ログアウト」を押す。`/login` に着地するまでの遷移を注視する（必要ならネットワークを Slow 3G に絞って観測）。
  3. 同様に `/notes`、`/settings` の各ページからもログアウトを試す（再ログインして繰り返す）。
- **期待結果:** いずれのパスからログアウトしても、`/login` 着地までの間にランディング（未認証トップ）や未認証ホームが一瞬たりとも描画されない。
- **確認ポイント:** 遷移中に背景がランディングに切り替わる白〜ヒーロー領域のフラッシュが出ないこと。ログアウト自体は正常に完了し `/login` に着地すること。

### 2. ログイン成功後の `/` 遷移でランディングが挟まらない

- **対応する受け入れ基準:** AC-2
- **目的:** ログイン成功 → `/`（認証済みホーム）への遷移過程でランディングが描画されないこと。
- **手順:**
  1. 未認証状態で `/login` を開く。
  2. シードした管理者の認証情報でログインする。`/` に着地するまでの遷移を注視する。
- **期待結果:** `/` 着地までの間にランディング（未認証トップ）が一瞬も描画されず、認証済みホームが表示される。URL に `?page=...&limit=...` 等の余計な search が付かない（`HOME_SEARCH` 維持）。

### 3. パスワードリセット確認完了後の `/` 遷移でランディングが挟まらない

- **対応する受け入れ基準:** AC-3
- **目的:** パスワードリセット確認 action がセッションを確立し `/`（認証済みホーム）へ遷移する過程でランディングが描画されないこと。
- **手順:**
  1. パスワードリセットを要求し、リセット確認画面（`PasswordResetConfirmForm`）に到達する有効なトークン付き URL を開く。
  2. 新しいパスワードを入力して確認を完了する。`/` に着地するまでの遷移を注視する。
- **期待結果:** リセット完了後、`/` 着地までの間にランディングが描画されず、認証済みホームが表示される。
- **確認ポイント:** リセット確認 action がセッション Cookie を確立して認証済みで `/` に着地する前提（この前提が崩れる場合は別の不具合）。

## エッジケース・異常系

### 1. 退会（AccountDeleteForm）からのランディング遷移が従来通り（回帰確認）

- **目的:** AccountDeleteForm を共通ヘルパー `clearAppShellCache` に寄せても、退会 → `/`（ランディング）遷移のチラつき無し挙動が維持されること。
- **手順:** 設定画面からアカウント削除を実行し、`/`（未認証ランディング）へ遷移する流れを注視する。
- **期待結果:** 従来同様、認証済み UI が残らずスムーズにランディングへ遷移する（退会は未認証 `/` 行きなのでランディング表示自体は正しい着地点）。

### 2. invalidate-only フローの成功画面が従来通り表示される（副作用無し回帰確認）

- **目的:** 本 Issue で変更しない invalidate-only フォーム（SignUpForm / VerifyEmail / EmailChangeConfirm 等）の成功画面が、意図しない `/` リダイレクト等を起こさず従来通り出ること。
- **手順:** サインアップ（`/signup`）を完了し成功画面（メール確認案内）が出ることを確認する。可能ならメール確認（VerifyEmail）・メール変更確認（EmailChangeConfirm）の成功画面も確認する。
- **期待結果:** いずれも成功画面が表示され続け、`/` への意図しない遷移が起きない。

## 既存機能への影響確認

- **ユニットテスト:** `pnpm test:unit` で `routerInvalidate` のヘルパーテスト（`clearAppShellCache` の filter が `/_app` 厳密一致のみ通すこと）、`UserMenu.test.tsx`（clearCache → navigate の順序）、`AccountDeleteForm` の既存テストが通ること。
- **エディター系ルートの freeze 挙動:** `routerInvalidate` / `appShellInvalidate` の既存挙動（エディタールート除外・`_app` 専用 invalidate）が変わっていないこと。
- **ログイン/ログアウトの基本動作:** チラつき以外の認証フロー（成功・失敗・エラー表示）が従来通り動くこと。
