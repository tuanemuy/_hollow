# 動作確認計画 — Issue #355: P13 アップロードモーダル: LLM 提案精度の向上と登録 UX 改善

**Issue:** #355
**作成日:** 2026-05-30

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm db:migrate   # ローカル D1 にマイグレーション適用（初回 / 未適用時のみ）
pnpm dev          # vite dev (Cloudflare 構成) でローカルサーバー起動
```

アップロード（取り込み）は P13 モーダル（ヘッダーの「アップロード」CTA → `UploadDialog` / `IngestionPreviewForm`）から行う。

### LLM 接続の前提

タイトル / ディレクトリ / タグの提案品質（確認項目 2〜4）は Anthropic への接続が成立している必要がある。`P41 管理: LLM 設定画面` の接続テストが成功している状態で確認する。接続不可の環境では、本文プレビュー削除（確認項目1）と登録インタラクション（確認項目5）の UI 系のみ検証可能。

### デプロイ方法

なし（検証環境のみで確認できる。staging/production 反映は通常の `pnpm deploy:staging` フローに従う）。

## 確認項目

### 1. モーダル内の本文プレビューが削除されている

- **目的:** 読み取り専用本文 HTML プレビューがフォームから消えていることを確認（要件1）
- **手順:**
  1. アップロード CTA から P13 を開き、サンプルファイル（`sample.html` 等）を取り込む
  2. 処理完了後のプレビュー（編集）フォームを確認する
- **期待結果:** フォームにはタイトル / ディレクトリ / タグ / FrontMatter の編集 UI のみが表示され、本文の HTML プレビュー領域が存在しない
- **確認ポイント:** 取り込み自体は成功し、登録後のノート詳細では本文が正しくレンダリングされる（プレビュー削除はフォーム表示のみで本文データには影響しない）

### 2. タイトル提案が本文内容ベースになっている

- **目的:** ファイル名がそのままタイトルにならず、本文内容から意味のあるタイトルが生成されることを確認（要件2）
- **手順:**
  1. ファイル名と内容が乖離したサンプル（例: `doc1.txt` に「四半期売上レポート」的な本文）を取り込む
  2. プレビューフォームのタイトル提案を確認する
- **期待結果:** タイトルがファイル名（`doc1`）ではなく本文内容を反映した簡潔なタイトルになっている
- **確認ポイント:** 非構造化ファイル（plain/office/pdf/image/audio）で LLM 提案タイトルが使われること。空応答時のみファイル名フォールバックになる

### 3. ディレクトリ提案が既存ツリーを考慮する

- **目的:** 既存ディレクトリツリーを文脈に、既存の適切な配置先が提案されること（要件3）
- **手順:**
  1. 事前に既存ディレクトリを数件作っておく（例: `技術`, `日記`, `仕事/レポート`）
  2. 既存ディレクトリの内容に合致するサンプルを取り込む
  3. プレビューフォームのディレクトリ提案を確認する
- **期待結果:** 内容に合致する既存ディレクトリが選択済み（id 解決）で提示される。該当が無い内容では、root 直下の単一の新規ディレクトリ名が提案される
- **確認ポイント:** 既存マッチ時は新規作成ではなく既存ディレクトリが選ばれること。新規提案はスラッシュを含まない単一名であること（深いネスト新規作成は本Issueスコープ外）

### 4. タグ提案が意味的な集合になっている

- **目的:** 文章中の単語の機械抽出ではなく、内容を考慮した粗めの意味的タグになること（要件4）
- **手順:**
  1. ある程度の長さの本文を持つサンプルを取り込む
  2. プレビューフォームのタグ提案を確認する
- **期待結果:** タグが細かすぎず（概ね 3〜5 件程度）、抽象度の揃った意味のある集合になっている
- **確認ポイント:** 本文中の名詞を機械的に並べたような細かいタグになっていないこと

### 5. 登録時のインタラクションが追加されている

- **目的:** pending / 成功 / 失敗のフィードバックと該当ノートへの導線を確認（要件5）
- **手順:**
  1. プレビューフォームで「登録（保存）」を押す
  2. pending 中の表示 → 成功後の表示を順に確認する
- **期待結果:**
  - 押下中は登録ボタンが pending 表示（ラベル変化 / スピナー等）になり二重送信が防がれる
  - 成功後はモーダル内に成功演出と「ノートを開く」導線・「閉じる」が表示される
  - 「ノートを開く」でノート詳細へ遷移できる
- **確認ポイント:** 成功 view ではモーダルを閉じられる（pending 扱いにならない）。motion 設定に応じて演出が抑制される（motion-safe）

## エッジケース・異常系

### 1. 既存ディレクトリが0件のとき

- **目的:** ツリー空でも取り込みが従来どおり動くことを確認
- **手順:** ディレクトリ未作成のユーザーでサンプルを取り込む
- **期待結果:** 既存マッチが無いため新規ディレクトリ名が提案され、登録まで完走する（エラーにならない）

### 2. 登録失敗時のフィードバック

- **目的:** コミット失敗時に既存の inline エラー（`role="alert"`）が表示されることを確認
- **手順:** （再現可能なら）コミットがエラーになる状況を作り「登録」を押す
- **期待結果:** フォーム内に inline でエラーが表示され、フォーム状態が保持される（成功 view には遷移しない）

## 既存機能への影響確認

- 取り込みパイプライン全体（HTML/Markdown/Office/PDF/画像/音声の各分岐）が従来どおり完走すること
- 登録後のノート詳細で本文が正しくレンダリングされること（本文プレビュー削除の影響が無いこと）
- `findTree` の追加クエリで取り込み処理が遅延・失敗しないこと（DB 障害時は空ツリーで継続）
