# TC-001: サインアップ → 検証メールリンクが `/verify-email?token=...` を指し、検証フローが動く

- **結果**: PASS
- **実行日時**: 2026-05-21
- **対象 Issue**: #65
- **テストソース**: `.issue/65/testing.md`
- **環境**:
  - 開発サーバー: http://localhost:3000
  - APP_URL (Cloudflare 環境変数): http://localhost:8787
  - dev のメール送信は `ConsoleEmailSender` (リンクをログ出力)

## 抽出した検証リンク URL

サーバーログ `/tmp/manual-test-65-server.log` から抽出:

```
email.verification {
  to: 'test-user-65@example.com',
  link: 'http://localhost:8787/verify-email?token=4-000CrEAAjrvIE97NrNCDQ8FCduQnaEEHFxIotZEPI',
  locale: 'en'
}
```

- **パス部分**: `/verify-email?token=...` (修正後の期待パス)
- **修正前の誤りパス**: `/auth/verify` ではないことを確認 (PASS)
- **ホスト**: `localhost:8787` は `APP_URL` の値に由来。dev サーバー実体は 3000 のため、ブラウザ検証では `http://localhost:3000/verify-email?token=...` に置き換えてアクセス（パス・クエリ仕様の検証目的は満たす）。
