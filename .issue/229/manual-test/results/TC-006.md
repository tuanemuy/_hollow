# TC-006 (エッジ2): キューが空の場合の表示

**結果: PASS**
**実行日時:** 2026-05-27
**セッション:** verify-tc-006

## シナリオ

ジョブを一切持たないユーザー (`tc-rename-a@example.com` /
id=`01938f01-0000-7000-8000-000000000011`) でログインし、`/upload` を
開いたときに取り込みキューが「空状態」UI として正常に描画されること
（500・TypeError・エラーオーバーレイ等が発生していないこと、また
アップロードフォームが正常に描画されていること）を確認する。
これにより、Issue #229 のデフォルト除外条件追加が空ケースの UI を
壊していないことを担保する。

## 取り込みキュー領域に表示された要素

- 見出し: `取り込みキュー` (h2)
- 空状態の見出し: `まだジョブがありません` (h2)
- 補助テキスト: `ファイルをアップロードすると、ここに進行状況が表示されます。`

ジョブカード（タイトル・MIME・サイズ・ステータス・「ノートとして保存／
再生成／破棄」ボタン）は1件も描画されていない。

- 見出し `アップロード` (h1)
- 説明文: `ファイルから新規ノートを作成します。HTML / Markdown / Office / PDF / 画像 / 音声に対応しています。`
- ドロップゾーン: `ファイルをドラッグ&ドロップ またはクリックして選択` ／ `複数選択にも対応`
- 共通ヘッダー: `Hollow` / 検索 / 新規作成 / アップロード / ユーザーメニュー（`T` アバター）
- サイドバー: ライブラリ・ディレクトリ・管理（タグ／ゴミ箱／アップロード）すべて描画

## 確認結果（期待値との照合）

- 期待: 取り込みキューが空状態として表示される → **満たす**（`まだジョブがありません` 表示）
- 期待: エラーオーバーレイ・500・TypeError が出ていない → **満たす**（DOM 上に error overlay 無し／本文に TypeError／500／Internal Server Error の文字列無し）
- 期待: アップロードフォーム等の他のUI要素は正常に描画されている → **満たす**（ドロップゾーン・ヘッダー・サイドバー全て描画）

## 実行上のメモ

- `tc-rename-a@example.com` は baseline seed に `ingestion_jobs` を持た
  ないユーザーとして用意されており、別途データを破棄せず空ケースを
  再現できた。
- ユーザーメニューのアバターは `T`（`tc-rename-a` の頭文字）として
  描画されており、正しいユーザーで認証されていることを示している。

## 結論

ジョブが1件も存在しないユーザーでも `/upload` ページは空状態 UI として
正常に描画され、アップロードフォームや共通ナビゲーションを含む周辺
UI にも影響は無い。Issue #229 のデフォルト除外条件は空ケースの表示
パスを破壊していないことが確認できた。**PASS**
