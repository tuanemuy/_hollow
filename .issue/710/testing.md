# 動作確認計画 — Issue #710: ノート一覧: ディレクトリのフィルター表示をチップからパンくず（現在地ナビ）に変更する

**Issue:** #710
**作成日:** 2026-06-13

---

## 確認環境

このIssueの変更（ノート一覧 `/` の `FilterBar` のディレクトリ表示をチップからパンくずへ変更）を確認するために必要な手順のみ記載。変更は presentation 層（`app/components/note/`）に閉じており、DB スキーマ変更はない。

### 検証環境の起動

ライブのソース変更を反映する開発サーバーを起動する。

```bash
pnpm db:migrate       # ローカル D1 にマイグレーション適用（初回・未適用時のみ）
pnpm seed:dev-admin   # 開発用 admin アカウントを投入（ログイン用、初回のみ）
pnpm dev              # 開発サーバー起動（vite dev / Cloudflare runtime ローカル）
```

起動後、`pnpm dev` の出力に表示される URL にブラウザでアクセスし、admin でログインしてノート一覧（`/`）を開く。

（`pnpm start` はビルド済み dist を配信するため、ソース変更の確認には `pnpm dev` を使う。）

**シードデータ前提:** パンくず（階層パス）を確認するには、ネストした複数階層のディレクトリツリーが必要。最低でも 3 階層（例: `Documents › Research › Notes`）になるようディレクトリを作成し、末端ディレクトリ配下にノートを 1 件以上置いておく。タグ／期間フィルタとの共存確認のため、タグ付きノートも数件用意する。

### デプロイ方法

なし（フロントエンドの UI 表示変更でローカル検証環境（`pnpm dev`）のみで確認できる）。ステージング確認が必要なら `pnpm deploy:staging`。

## 確認項目

### 1. ディレクトリを開くとパンくず（チップではない）が階層パスで表示される

- **対応する受け入れ基準:** AC-1, AC-4
- **目的:** ディレクトリを開いた一覧で、末端名だけのチップではなく、ルートからの階層パス全体がパンくず（`nav`）として表示されること
- **手順:**
  1. ノート一覧（`/`）を開く
  2. ディレクトリツリーから 3 階層目（例: `Documents › Research › Notes` の `Notes`）を開く
  3. `FilterBar` のディレクトリ表示部を確認する
- **期待結果:** 「`Documents › Research › Notes`」のように、ルートから現在地までの全階層がパンくず（`ChevronRight` 区切り）で表示される。`filterChip`（角丸の塗りチップ + `data-active`）ではない
- **確認ポイント:** 中間階層（`Documents` / `Research`）が省略されず全部見えること。末端名だけのチップになっていないこと

### 2. 各セグメント（中間階層）がリンクで、クリックでその階層に移動できる

- **対応する受け入れ基準:** AC-2
- **目的:** パンくずの各セグメントがリンクで、クリックでその階層に絞り込みジャンプできること
- **手順:**
  1. 3 階層目（`Notes`）を開いた状態でパンくずを表示する
  2. 中間セグメント `Research` をクリックする
  3. 続けて `Documents` をクリックする
- **期待結果:** `Research` クリックで一覧が `Research` ディレクトリで絞り込まれ、パンくずが「`Documents › Research`」になる。`Documents` クリックで「`Documents`」のみになる。各リンクは `/`（ホーム）にその `directoryId` を付けて遷移する
- **確認ポイント:** リンク遷移先 URL に当該セグメントの `directoryId` が乗ること。途中階層がクリック可能（リンク）であること

### 3. 末尾の × でディレクトリフィルタが解除され、パンくずが消える

- **対応する受け入れ基準:** AC-3, AC-4
- **目的:** パンくず末尾の `×`（`clearDirectory`）でディレクトリ絞り込みが解除されること
- **手順:**
  1. 任意のディレクトリを開いてパンくずを表示する
  2. パンくず末尾の `×` をクリックする
- **期待結果:** ディレクトリ絞り込みが解除され、一覧が全件（ディレクトリ非絞り込み）に戻る。パンくずが非表示になる
- **確認ポイント:** 解除直後にパンくずが消える（空 `nav` が残らない）こと

### 4. タグチップとパンくずが見た目で明確に区別される

- **対応する受け入れ基準:** AC-1
- **目的:** タグの絞り込みチップ（チップ語彙）と、ディレクトリのパンくず（ナビゲーション語彙）が見た目で混同されないこと
- **手順:**
  1. タグ付きノートが見える状態でタグを選択し、同時にディレクトリも開く
  2. タグチップとディレクトリパンくずを並べて見る
- **期待結果:** タグは塗り／枠のチップ（`filterChip`）、ディレクトリは `ChevronRight` 区切りの控えめなテキストナビ（`text-sm text-ink-tertiary` 系）として表示され、形が明確に異なる
- **確認ポイント:** ディレクトリ表示が「絞り込みチップ」ではなく「現在地ナビ」に見えること

### 5. root セグメントの扱い

- **対応する受け入れ基準:** AC-6
- **目的:** root（空名）セグメントがパンくずに混入せず、リンク化もされないこと
- **手順:**
  1. ルート直下のディレクトリ（例: `Documents`）を開く
  2. パンくずを確認する
- **期待結果:** 「`Documents`」のみが表示される。先頭に空名の root セグメントや空リンクが出ない
- **確認ポイント:** root の `directoryId` がリンクに乗らないこと。空名のセグメント（クリック領域だけのリンク）が描画されないこと

### 6. ディレクトリ未選択時はパンくずが表示されない

- **対応する受け入れ基準:** AC-4
- **目的:** ディレクトリを絞り込んでいないときパンくずが出ないこと
- **手順:**
  1. ノート一覧（`/`）をディレクトリ非絞り込み状態で開く
- **期待結果:** ディレクトリのパンくず行が一切表示されない（タグ・期間・公開状態のチップ列のみ）
- **確認ポイント:** 空のパンくず行や `×` だけの要素が残らないこと

### 7. パンくずがタグチップ群とは別行に配置される

- **対応する受け入れ基準:** AC-7
- **目的:** パンくずが折り返しチップ群（タグ・期間・公開状態・内部リンク参照）と同じ行に混ざらず、別行に置かれること
- **手順:**
  1. タグを複数選択し、期間・公開状態フィルタも設定した上でディレクトリを開く
  2. `FilterBar` 全体のレイアウトを確認する
- **期待結果:** チップ列（タグ・期間・公開状態など）の行と、ディレクトリパンくずの行が別行に分かれている
- **確認ポイント:** パンくずがチップ列の中に混ざってチップと並ばないこと

## エッジケース・異常系

### 1. 深い階層・長いディレクトリ名での折り返し

- **目的:** 深い階層や長いディレクトリ名でパンくずが折り返してレイアウトが崩れないこと
- **手順:**
  1. 5 階層以上の深いディレクトリツリー、または長い名前（30 文字以上）のディレクトリを作成し、その末端を開く
  2. 約 375px（モバイル幅）とデスクトップ幅の両方でパンくずを確認する
- **期待結果:** パンくずが折り返して表示され、横スクロールやはみ出し・要素の重なりが起きない。チップ列（`max-sm` で横スクロール）とパンくずの折り返しが干渉しない

### 2. ディレクトリ削除直後など解決失敗時のフォールバック

- **目的:** `directoryId` はあるがツリーに存在しない（削除直後・解決失敗）場合に、空 `nav` を出さず従来同様のフォールバック表示になること
- **手順:**
  1. あるディレクトリを開いた一覧の URL（`directoryId` 付き）を控える
  2. 別タブ等でそのディレクトリを削除する
  3. 控えた URL を開き直す（または再読込する）
- **期待結果:** パンくず（`nav`）ではなく、従来の汎用フォールバックチップ（ラベル「ディレクトリ」+ `×`）が表示される。`×` で解除できる。空のパンくず（`nav`）は描画されない

## 既存機能への影響確認

- タグフィルタの選択／解除（楽観的更新）が従来どおり動くこと（AC-8）
- 期間フィルタ（`DatePopover`）の設定／解除が従来どおり動くこと（AC-8）
- 公開状態フィルタの設定／解除が従来どおり動くこと（AC-8）
- 内部リンク参照チップの選択／解除が従来どおり動くこと（AC-8）
- 「すべてクリア」（`clearAll`）でディレクトリを含む全フィルタが一括解除されること（AC-8）
