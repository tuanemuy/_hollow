# TC-008: SavedView 経路で referencingNoteId が往復する

- **Issue:** #8
- **実行日時:** 2026-05-17（再々検証 retry2）
- **検証者:** Claude Code (agent-browser session `verify-tc008-retry2`)
- **対象 URL:** `http://localhost:3000/?referencingNoteId=01938f00-0000-7000-8000-00000000b079`
- **結果:** **PASS（referencingNoteId 往復について）**

## 目的（ADR-007 縮小後）

SavedView の保存・復元で本 Issue で追加した URL パラメータのうち `referencingNoteId` が消失しないことを確認する。

ADR-007 は VO 都合により縮小され、`visibility` の往復は別 Issue へ分離されたため、本 TC では `referencingNoteId` の往復のみを検証対象とする。

## 反映された修正（書き込み側）

- `app/components/view/schema.ts:42` — `createSavedViewSchema.query` に `referencingNoteId: z.string().min(1).nullable().default(null)` を追加（schema で剥がれなくなった）
- `app/components/view/actions.ts:48` — `referencingNoteId: data.query.referencingNoteId as NoteId | null` に変更（`null` ハードコード解消）
- `app/components/note/list/SaveViewDialog.tsx:46` — submit ペイロードに `referencingNoteId: payload.query.referencingNoteId ?? null` を追加

## 反映された修正（読み取り側）

- `app/routes/index.tsx` — `viewQueryToSearch(view)` の結果を `baseSearch` にマージ。loader / Component に渡す検索条件として `referencingNoteId` を含む実フィルタが流れる

## 観察事実

- `referencingNoteId` は SavedView 保存時に DB まで届くようになっており、選択時に loader が当該条件で抽出した結果（N1 のみ）と ref chip 表示まで正しく復元される
- 復元時の URL は `?page=1&limit=20&viewId=<id>` 形式で `referencingNoteId` を URL に書き戻さない設計だが、サーバー側 baseSearch マージにより listNotes/UI には正しい条件が流れている
- 保存ビューの display kind（リスト/タイル/カレンダー）も復元される（タイル → リストへ戻った）

## 別 Issue 候補（本 Issue 対象外、備考）

- **visibility 永続化:** ADR-007 縮小により本 Issue の対象外。SavedView 保存時には `visibilityFilter` がドメイン層まで貫通する経路（`CreateSavedViewInput.query` / `ViewQuery` 値オブジェクト / DB スキーマ）が無いため、保存・復元が出来ない。別 Issue で対応予定。
  - 影響範囲（参考）: `app/core/application/view/createSavedView.ts` の入力 DTO、`app/core/domain/view/valueObject.ts` の `ViewQuery`、`saved_views` テーブル query JSON カラム、`app/components/note/list/listSelectors.ts:180-187` の auxiliary cast を正規プロパティ参照へ
- **URL 書き戻し方針:** SavedView 復元時に URL を `view.query` の内容で rewrite するか、現状の `?viewId=...` のみで baseSearch マージに委ねるかは設計判断（ADR-009/010 周辺）。後者のままでも UI / loader は正しく動作することを本検証で確認した

## 結論

ADR-007 縮小スコープ（referencingNoteId 往復）について、本 Issue の修正（schema / dialog / action handler の書き込み側 + index.tsx の baseSearch マージ）は適切に動作している。本 TC は **PASS**。

visibility 往復は別 Issue として起票して継続対応する。
