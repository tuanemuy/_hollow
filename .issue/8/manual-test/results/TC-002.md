# TC-002: `?visibility=private` で行が無いノートも含まれる

- **Issue:** #8
- **実行日時:** 2026-05-17
- **検証者:** Claude Code (agent-browser session `verify-tc-issue8-a`)
- **対象 URL:** `http://localhost:3000/?visibility=private`
- **結果:** **PASS**

## 目的

`publication_states` 行が存在しないノートも `visibility=private` フィルタの対象になることを確認する。ADR-003 の `wantsPrivate` 分岐ロジックが、欠損行と明示的 `visibility='private'` 行の和集合を返すことの検証。

## 事前準備

シードでは全 10 ノートに `publication_states` 行が入っているため、N10「今日のタスク」の行を削除して「行なし private」状態を作る:

```bash
pnpm wrangler d1 execute tanstack-start-template-d1 --local --command \
  "DELETE FROM publication_states WHERE note_id='01938f00-0000-7000-8000-00000000b07a';"
```

実行後の状態:
- N10「今日のタスク」: `publication_states` 行なし → 期待は `private` 扱い
- N1, N2, N3, N5, N6, N7, N8: `publication_states` 行あり / `visibility='private'`
- N4: 行あり / `unlisted`（フィルタ対象外）
- N9: 行あり / `public`（フィルタ対象外）

## 手順

1. 上記 DELETE を実行して N10 を「行なし」に
2. シードユーザーでログイン済みの状態で `http://localhost:3000/?visibility=private` にアクセス
3. 表示されたノート一覧と件数を確認

## 期待結果

- 表示されるノートは 8 件: N1, N2, N3, N5, N6, N7, N8 (行あり private 7 件) + N10 (行なし private 1 件)
- N4 (unlisted) と N9 (public) は表示されない
- 全カードの badge が「非公開」

## 実際の結果

表示された 8 件:

1. 今日のタスク（N10、`publication_states` 行なし） — badge: 非公開
2. Weekly planning ノート（N1） — badge: 非公開
3. ブレインストーミング（N2） — badge: 非公開
4. Project A キックオフ（N3） — badge: 非公開
5. Project B レビュー記録（N5） — badge: 非公開
6. 5 月定例ミーティング（N6） — badge: 非公開
7. Reading list（N7） — badge: 非公開
8. Q1 ふりかえり（N8） — badge: 非公開

N4「Project A デザインメモ」（unlisted）と N9「公開デザインガイド」（public）は一覧に出現しない。
公開状態 select の現在値: 「非公開」。

URL: `http://localhost:3000/?visibility=private&page=1&limit=20`
件数表示: `10 件のノート`（ADR-009 既知挙動）

## 結論

`publication_states` 行が存在しない N10 が `visibility=private` の結果集合に含まれた。ADR-003 の wantsPrivate 分岐ロジック（行欠損 + 行あり private の和集合）が正しく動作している。
