#### Round 1 指摘の反映確認

- **[P-001 ラベル SSOT] 反映済み（解消）。** Round 1 はモック `P12-editor.html:985` の `場所` と計画記述の混在を指摘し「『場所』に統一 or 差分許容として記録」を求めた。計画は後者寄りに「**現行実装の『ディレクトリ』を SSOT として維持**」する判断を採り、AC-4 / 調査結果 / 設計（UI）/ ステップ6b / ADR-003 を「ディレクトリ」に統一、未選択プレースホルダも「ディレクトリを選択」に統一済み。`場所` は決定ログ（plan.md:211, adr.md:60）の説明文脈にのみ残り、生きたラベルとしては消えている。Issue 本文も英字 `DIRECTORY`（uppercase 体裁）と記述しており、日本語文字列 `場所` を要件として強制していないため、この判断は要件と矛盾しない。混在による取り違えリスクは解消。
- **[S-001 AC-6 と ADR 紐づけ] 反映済み。** AC-6（plan.md:22）が ADR-001（タグのチップ化）/ ADR-002（`TagsInput` 新設）/ ADR-003（ディレクトリ完全移行・combobox+listbox）/ ADR-004（本文枠線撤去・padding/focus 温存）の4件を明示列挙する形に更新され、adr.md の4 ADR と一致。検証が機械的に可能。
- **[S-002 新規作成導線の独立検証] 反映済み。** AC-4（plan.md:20）に「**インライン新規ディレクトリ作成導線が機能する（`pendingDirectoryName` 契約を維持し、新規作成→保存で実体化される）ことを独立に検証する**」が太字で切り出され、テスト方針（plan.md:201, 203）の「新規作成→保存で実体化」と対応。
- **[S-003 draft 確定ルールの AC-2 昇格] 反映済み。** AC-2（plan.md:18）に「**入力途中（Enter 未押下）の `tagDraft` が非空のまま submit / autosave した場合も、当該タグが確定されて `tagNames` に含まれる**（submit と autosave が同一の純粋ヘルパー `resolveTagNames(state)` を通る）」が昇格。ADR-001（adr.md:23）・依存関係（plan.md:62）・リスク（plan.md:183）・テスト方針（plan.md:198）と lockstep 設計が一貫。

#### 問題点（要修正）

問題点ゼロ。

4 受け入れ条件（タグ/タイトル/ディレクトリ/本文枠線）+ ADR 記録 + 品質ゲートが AC-1〜AC-7 に漏れなく落ち、各 AC が検証可能な具体性（`leading-[1.12]`・`border-hairline`/`rounded-md` 除去・`mb-5`・combobox/listbox a11y・`pendingDirectoryName` 実体化）で書かれている。スコープ外（#688 最大幅・#692 フォーカス表現・Ingestion `fieldset`）の除外も plan.md スコープ節と各 ADR で一貫しており、スコープ外混入なし。Round 1 の4指摘はすべて反映済み。確定済みユーザー判断（タグチップ化・ディレクトリ完全移行）は AC-1 / AC-4・ADR-001 / ADR-003 に正しく載っており、却下された差分許容案の蒸し返しもなし。

#### 改善提案（検討推奨）

- **[S-001]** AC-6 の「対応ステップ」列が `—` のまま。
  - 理由: Round 1 S-001 で ADR-001〜004 との内容紐づけは達成されたが、AC↔ステップの追跡列（他 AC は「2,3,4」等で生成元ステップを指す）だけが空欄。ADR は plan.md「設計判断」節（173-178）と adr.md で生成・記録されるので、AC-6 の対応ステップを「設計判断節 / adr.md」または品質ゲート相当の位置づけと明記すると、AC↔生成物の3列マッピングの一貫性が完成する。なお AC-7（品質ゲート）も対応ステップ「全ステップ後」と書けているため、AC-6 だけが空のままなのは軽微な体裁の非対称。必須ではない（内容追跡は S-001 反映で既に取れている）。

#### 良い点

- Round 1 の P-001 を「モック文字列への機械的追従」ではなく「ユーザー向け文言の不用意な変更を避ける」という SSOT 原則で解決し、判断根拠（モックの `DIRECTORY` は uppercase 体裁であり日本語表記を変える根拠にしない）を adr.md / plan.md 双方に明文化した。要件解釈として妥当かつ追跡可能。
- AC-2 と AC-4 がそれぞれ「保存契約の非破壊（draft 確定 lockstep）」「新規作成導線の実体化」という最も退行しやすい核心を独立検証文として持ち、reducer 純粋関数テスト・`resolveTagNames` 単体テスト・`directoryTreeSelect.ts` 純粋関数テストと対応している。重点視点（データ表現変更時の保存契約破壊）が AC レベルで直接ガードされている。
- ディレクトリ完全移行が `DirectoryPicker` props 契約・`variant="fieldset"`（Ingestion）を不変に保ち影響を `row` に閉じ込める設計（ADR-003 / ステップ6c）で、Ingestion 非回帰が AC-4 末尾・テスト方針（plan.md:202）でカバーされている。スコープ境界が堅い。
- a11y モデル（combobox + `aria-activedescendant` 仮想フォーカス + popup listbox、`useRovingMenu` 不使用）を計画段階で確定し、可視 option フラット列を純粋関数（ステップ6）に切り出して vitest 検証可能にしている。最難点の不確実性を実装前に解消する筋の良い分割。
