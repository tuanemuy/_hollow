## 失敗詳細（Step 4）

- **失敗ステップ**: Step 4
- **期待**: 「already-new-key（既に新鍵）」スキップの成功メッセージ
- **実際**: 403 `kind=forbidden, code=FORBIDDEN_CROSS_ORIGIN, "Cross-origin request rejected"` → UI「権限がありません」
- **原因分類**: 環境問題（実装バグではない）。headless Chrome（agent-browser）からの TanStack Start server-function POST に Origin ヘッダが付かず、フレームワークの同一オリジン/CSRF ガードに弾かれる。`rebuildSearchIndex` を含む全 server function 共通のプレゼンテーション層ミドルウェアの挙動で、本 Issue の変更とは無関係。

## 機能面で確認できたこと（PASS）

- 再暗号化セクション・ボタンが正しく実装・表示される。
- ボタンクリックで server function `reencryptApiKeyFn` が正しく発火する。
- 403 をクラッシュ/500/サイレント失敗させず、UI にエラーとして健全にレンダリングする。console ランタイムエラーなし。

## 未検証の点（integration テストで担保）

- 再暗号化の実処理（新鍵 decrypt → already-new-key スキップ判定 / 旧鍵フォールバック → 新鍵 re-encrypt）は、オリジンガードに阻まれブラウザでは実行に至らず。これは `reencryptApiKey.integration.test.ts`（6 ケース: round-trip / 冪等 / env skip / KeyUnavailable / 非 admin Forbidden / OCC ConflictError）と `decryptWithFallback.test.ts` で担保済み。

## テストデータ
