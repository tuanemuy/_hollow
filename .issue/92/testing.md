## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。

### 自動テスト（主たる検証手段）

LIKE フォールバックは adapter の振る舞いなので、integration test が一次検証になる。

```bash
pnpm typecheck
pnpm test:integration
```

（adapter テストだけ流すなら `pnpm test:integration -- searchIndex` のようにファイル指定でもよい。）

### 検証環境の起動（ブラウザ確認用）

`/search` は公開ルート（`PublicSearch`、認証不要）。ローカル D1 にマイグレーションを適用してから dev サーバーを起動する。

```bash
pnpm db:migrate     # = wrangler d1 migrations apply hollow-local-d1 --local
pnpm dev            # = vite dev --config vite.config.cloudflare.ts
```

ブラウザ確認用のシードは、公開（public）ノートに短いキーワードを含む本文を投入する必要がある。シード投入は agent-browser でサインアップ → ノート作成 → 公開設定、または `pnpm db:execute:local --file <seed.sql>` でローカル D1 に直接投入する（`search_documents` は note の FK 制約があるため users → directories → notes → search_documents の順、または通常のノート作成フローで indexer を経由させる）。

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. ASCII 短キーワードがヒットする（救済の確認）

- **目的:** `AI` のような 2 codepoint のキーワードで、本文に `AI` を含む公開ノートがヒットする（従来は 0 件）。
- **手順:**
  1. 本文に `AI` を含む公開ノートを 1 件用意する。
  2. `/search?q=AI` を開く。
- **期待結果:** 当該ノートが検索結果に表示される。
- **確認ポイント:** スニペットは body 先頭の固定長抜粋になり `<mark>` ハイライトは付かない（LIKE 経路の仕様）。表示が崩れていないこと。

### 2. CJK 1 文字がヒットする

- **目的:** `本` のような 1 codepoint の CJK でヒットする。
- **手順:** 本文に `本` を含む公開ノートを用意し `/search?q=本` を開く。
- **期待結果:** 当該ノートが表示される。

### 3. 3 codepoint 以上は従来どおり MATCH 経路（回帰なし）

- **目的:** `デザイン` 等の通常クエリが従来どおり trigram MATCH でヒットし、ハイライト付きスニペットが出る。
- **手順:** 本文に `デザイン` を含む公開ノートを用意し `/search?q=デザイン` を開く。
- **期待結果:** ヒットし、スニペットに `<mark>` ハイライトが付く（MATCH 経路の挙動が変わっていない）。

### 4. 混在キーワードは MATCH 経路（短トークン無視の維持）

- **目的:** `AI デザイン` は trigram で拾える `デザイン` のみで MATCH し、`AI` は無視される（現状維持）。
- **手順:** 本文に `デザイン` を含むが `AI` を含まない公開ノートを用意し `/search?q=AI+デザイン` を開く。
- **期待結果:** 当該ノートがヒットする（`AI` 無視）。

## エッジケース・異常系

### 1. ヒットしない短キーワード

- **目的:** どのノートにも含まれない短キーワードで 0 件になる。
- **手順:** `/search?q=zz`（どこにも無い 2 codepoint）を開く。
- **期待結果:** 0 件メッセージが表示され、エラーにならない。

### 2. LIKE ワイルドカードのエスケープ

- **目的:** `%` や `_` をリテラルとして扱い、ワイルドカード暴発しない。
- **手順:** 本文に `50%` を含むノートと含まないノートを用意し `/search?q=%25`（URL エンコードした `%`）を開く。
- **期待結果:** `50%` を含むノートだけがヒットし、全件ヒットにならない。

### 3. ページネーション（複数ヒット）

- **目的:** LIKE 経路でも cursor ページングが動く。
- **手順:** 短キーワードで複数ヒットする状態にし、結果末尾の「次へ」を辿る。
- **期待結果:** 2 ページ目が重複なく表示され、note_id 昇順で安定している。

## 既存機能への影響確認

- 通常の 3 codepoint 以上の検索（MATCH 経路）が変わっていないこと（確認項目 3）。
- visibility フィルタ: 非公開ノートが公開検索（`/search`）に短キーワードでも漏れないこと。
- ユーザー絞り込み（`/search?q=AI&username=...`）が短キーワードでも効くこと。
