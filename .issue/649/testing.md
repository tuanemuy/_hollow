# 動作確認計画 — Issue #649: #626 確定デザインの実装反映 — P10 ツールバー（segmented 降格・CTA ヘッダー集約）と P30 系 segmented の追従

**Issue:** #649
**作成日:** 2026-06-12

---

## 確認環境

このIssueはフロントエンド（P10 ホーム上部の UI）と P30 系デザインモック（静的 HTML）の変更のみ。検証は開発サーバーとモック HTML のブラウザ表示で行う。

### 検証環境の起動

```bash
pnpm dev
```

（`vite dev --config vite.config.cloudflare.ts`。Cloudflare ランタイムをターゲットにしたローカル開発サーバー。）

自動チェック:

```bash
pnpm typecheck && pnpm lint:fix && pnpm format
pnpm test:unit
```

P30 系モックはブラウザでファイルを直接開いて確認する（`spec/design/pages/P30-user-public-top.html` / `spec/design/pages/mobile/P30-user-public-top.html`）。

モバイル確認の共通手順: Chrome DevTools（F12）→ デバイスツールバー（Cmd+Shift+M）→ プリセット「iPhone SE」（375×667）を選択。タッチターゲット確認時は DevTools の Elements で対象ボタンを選択し、擬似要素込みの当たり判定サイズが 44px 相当であることと、実タップ（クリック）で隣接要素が誤爆しないことを見る。

### デプロイ方法

なし（検証環境のみで確認できる。デプロイ手順は本Issueの範囲外）。

## 確認項目

### 1. ツールバーから CTA が消えヘッダーのみになっている

- **対応する受け入れ基準:** AC-1
- **目的:** 新規作成 / アップロード CTA がツールバーから削除され、ヘッダー集約（#628）と重複しないこと。
- **手順:**
  1. ホーム `/` を開く。
  2. ノート一覧上部のツールバー領域を確認する。
  3. ヘッダー右側を確認する。
- **期待結果:** ツールバーに「新規作成」「アップロード」ボタンが存在しない。ヘッダーに CTA が従来どおり存在し、新規作成・アップロードが機能する。
- **確認ポイント:** デスクトップ幅・モバイル幅（iPhone SE）の両方で CTA がツールバーに出ないこと。

### 2. 見出し = ビュー切り替えトリガー（ViewSwitcher）

- **対応する受け入れ基準:** AC-2
- **目的:** 保存ビュー `<select>` が廃止され、ページ見出しクリックでビュー一覧ドロップダウンが開き、遷移挙動が従来規約どおりであること。
- **手順:**
  1. 事前に保存ビューを 1 つ以上作成しておく（フィルタを適用 → ビュー保存アイコン → 名前を付けて保存）。
  2. ホーム `/` を開き、ページ見出しが「すべてのノート」であることを確認する。
  3. 見出しをクリックする。
  4. ドロップダウンから保存ビューを選択する。
  5. 見出しがそのビュー名に変わったことを確認し、再度見出しから「すべてのノート」を選択する。
- **期待結果:**
  - 見出しクリックで「すべてのノート + 各保存ビュー」の一覧が開く。
  - 保存ビュー選択時は URL が `viewId` を含む形へ遷移し（`display` パラメータは落ちて #219 のリダイレクト正規化が働く）、フィルタが適用される。
  - 「すべてのノート」選択時は viewId が外れ、表示モード（display）のみ保持される。
- **確認ポイント:** 旧 `<select>` がどこにも残っていない。表示モードをタイルにした状態で「すべてのノート」を選んでも display が維持される。

### 3. 見出しトリガーの a11y とモバイルタッチ床

- **対応する受け入れ基準:** AC-3
- **目的:** 見出しトリガーの aria 契約とモバイル 44px min-height。
- **手順:**
  1. ホームで DevTools Elements から見出しトリガーボタンを検査する。
  2. `aria-haspopup` / `aria-expanded` / `aria-label` / `title` を確認する。開閉して `aria-expanded` の変化を見る。
  3. デバイスツールバーで iPhone SE に切り替え、Computed パネルで min-height を確認する。
  4. キーボードのみで操作: Tab で見出しにフォーカス → Enter で開く → 矢印キーで項目移動 → Enter で選択 → 再度開いて Esc で閉じる。
- **期待結果:** `aria-haspopup="listbox"`、開閉に応じた `aria-expanded`、`aria-label="すべてのノート — ビューを切り替え"`（{可視見出し} — ビューを切り替え 形式、`.issue/649/adr.md` ADR-005） + `title` 併記。モバイルで min-height 44px。listbox 項目は `role="option"` + `aria-selected` で矢印キー移動・Enter 選択・Esc クローズが効く。
- **確認ポイント:** フォーカス時に focus-visible リングが見える。

### 4. 検索時の見出し表示（ADR-005）

- **対応する受け入れ基準:** AC-2, AC-3
- **目的:** 検索中は見出しが「「q」の検索結果」となり、トリガー機能は維持されること。
- **手順:**
  1. 検索ボックスで任意のキーワード（例: `test`）を検索する。
  2. 見出しテキストと `aria-label` を DevTools で確認する。
  3. 見出しから任意のビューを選択する。
- **期待結果:** 見出しは「「test」の検索結果」。`aria-label` は「「test」の検索結果 — ビューを切り替え」（可視見出しが先頭、`.issue/649/adr.md` ADR-005）。ビュー選択で q を含まない状態へ遷移する。

### 5. 選択 / ビュー保存のアイコンのみ化

- **対応する受け入れ基準:** AC-4
- **目的:** 「選択」「ビューとして保存」がアイコンのみで、a11y 属性とサイズ規約を満たすこと。
- **手順:**
  1. ホームのツールバー右群を確認する。
  2. DevTools で各ボタンの `aria-label` / `title`、デスクトップでの実寸（36px 角）を確認する。
  3. 「選択」を押して選択モードを ON/OFF し、`aria-pressed` の変化を確認する。
  4. iPhone SE に切り替えてボタンの当たり判定（44px 床）とタップ動作を確認する。
  5. 「ビューとして保存」を押し、SaveViewDialog が従来どおり開いて保存できることを確認する。
- **期待結果:** 両ボタンとも可視テキストなし・`aria-label` と `title` あり。デスクトップ 36px 角、モバイル 44px タッチ床。選択モードと保存ダイアログの挙動は不変。
- **確認ポイント:** フィルタ未適用などビュー保存が無効の条件のとき、`aria-disabled="true"`（native `disabled` ではない）+ `aria-describedby` で sr-only の理由提示があり、title 文言が従来どおり（`.issue/649/adr.md` ADR-010）。

### 6. 表示モード segmented の確定表現

- **対応する受け入れ基準:** AC-5
- **目的:** segmented がツールバー右端・アイコンのみ・ink 濃度差 active であること。
- **手順:**
  1. ホームのツールバー右端の segmented（リスト / タイル / カレンダー）を確認する。
  2. DevTools で各ボタンの寸法（デスクトップ 32×28px）、アイコンサイズ（13px）、`role="tablist"` / `role="tab"` / `aria-selected` / `aria-label` / `title` を確認する。
  3. 各モードをクリックして切り替え、active の見た目を確認する。
  4. iPhone SE で寸法（36×32px）と 44px 相当の当たり判定を確認する。
- **期待結果:** 可視ラベルなし。active は白カード・shadow ではなく ink 濃度差（非アクティブが薄く、アクティブが濃い）。切り替えで URL の display パラメータが従来どおり更新される（replace）。
- **確認ポイント:** segmented の 44px 当たり判定が隣接ボタンのクリックを奪わない（境界付近をタップして意図したモードに切り替わる）。

### 7. 件数と操作群の 1 行統合（meta-row）

- **対応する受け入れ基準:** AC-6
- **目的:** 「N 件のノート」と右群（選択 / ビュー保存 / segmented）が 1 行に統合されていること。
- **手順:**
  1. デスクトップ幅でホームを開き、見出し直下の行を確認する。
  2. ブラウザ幅を徐々に狭める（〜375px まで）。
- **期待結果:** 左 = 件数、右 = 操作群の 1 行。狭幅では flex-wrap で折り返し、要素が潰れたりはみ出したりしない。
- **確認ポイント:** ノート一覧側に件数表示が重複して残っていない。

### 8. FilterBar のクリア ×

- **対応する受け入れ基準:** AC-7
- **目的:** 「すべてクリア」pill が円形 × に置き換わり、表示条件・動作が正しいこと。
- **手順:**
  1. フィルタ未適用のホームで、クリア × が表示されないことを確認する。
  2. タグや種別など任意のフィルタを適用する。
  3. チップ列末尾の円形 × を DevTools で検査する（デスクトップ 28px、`aria-label="フィルタをすべてクリア"`、`title`）。hover して surface 背景 + ink 文字色になることを確認する。
  4. × をクリックし、全フィルタが解除されることを確認する。
  5. iPhone SE で再度フィルタを適用し、× が 32px・44px 相当の当たり判定でタップできること、チップ横スクロール行で × が潰れない（shrink しない）ことを確認する。
- **期待結果:** 旧「すべてクリア」pill は存在しない。× はチップ列末尾に置かれ、クリックで全フィルタ解除。
- **確認ポイント:** フォーカス時の focus-visible リング。

### 9. ToolbarSkeleton の新レイアウト

- **対応する受け入れ基準:** AC-10
- **目的:** 読み込み中スケルトンが新レイアウト（見出しバー + meta-row）であること。
- **手順:**
  1. DevTools の Network タブでスロットリング「Slow 3G」を有効にする。
  2. ホームをハードリロードする。
- **期待結果:** 見出しバー + meta-row（左 = 件数ライン、右 = アイコンボタン ×2 + segmented プレースホルダ）のスケルトンが表示され、解決後に実 UI へ置換。旧 CTA / select のプレースホルダは出ない。
- **確認ポイント:** ノート一覧スケルトン側に件数バーが残っておらず、件数プレースホルダが二重表示にならない。読み込みアナウンス（`role="status"`）が重複していない（Elements で `role="status"` を検索して確認）。

### 10. P30 系モックの segmented 追従

- **対応する受け入れ基準:** AC-12
- **目的:** P30 モックの表示モード segmented が P10 確定表現と同一であること。
- **手順:**
  1. `spec/design/pages/P30-user-public-top.html` と `spec/design/pages/mobile/P30-user-public-top.html` をブラウザで直接開く。
  2. segmented の見た目（アイコンのみ・固定寸法・ink 濃度差・白カード/shadow なし）とマークアップ（`role="tablist"` / `role="tab"` / `aria-selected` / `aria-label`、デスクトップは `title`）を確認する。
  3. P10 確定モック `spec/design/pages/P10-home.html` の segmented と並べて比較する。
- **期待結果:** P30 の segmented が P10 と同表現。位置（ツールバー左・ソートとの並び）は P30 既存のまま。

## エッジケース・異常系

### 1. 保存ビュー 0 件時の見出しトリガー

- **手順:** 保存ビューをすべて削除した状態でホームを開き、見出しをクリックする。
- **期待結果:** 見出しテキスト「すべてのノート」は表示される。トリガーを表示する実装なら「すべてのノート」1 項目の listbox が開き、選択してもエラーにならない。いずれの実装でも見出しテキストと a11y 契約は崩れない。

### 2. 存在しない viewId を URL に直接指定

- **手順:** URL に削除済み / 不正な `viewId` を付けてホームを開く。
- **期待結果:** 見出しはフォールバックの「すべてのノート」で、画面がクラッシュしない。

### 3. 長いビュー名の見出し折り返し

- **手順:** 長い名前（30 文字以上、空白なしの英数字含む）の保存ビューを作成して適用し、iPhone SE 幅で表示する。
- **期待結果:** 見出しが `overflow-wrap: anywhere` で折り返し、レイアウトがはみ出さない。chevron は縦中央に揃う。

### 4. 一覧クエリ失敗時の境界巻き込み（ADR-002 トレードオフ）

- **手順:** 一時的にノート一覧のローダーへ throw を仕込む（またはオフライン化して再読み込み）。
- **期待結果:** 見出し + meta-row 境界がセクションエラー表示に落ちるのは想定どおり。URL 変更（resetKey）や再読み込みで回復できる。

### 5. 検索 + 保存ビュー同時適用

- **手順:** 保存ビュー適用中に検索を実行する。
- **期待結果:** 見出しは検索文言が優先（「「q」の検索結果」）。検索解除でビュー名表示に戻る。

## 既存機能への影響確認

- 表示モード切り替え（リスト / タイル / カレンダー）の URL 反映・履歴 replace 挙動が従来どおり（#219 契約）。
- 選択モード（一括操作）の機能が従来どおり動作する（`aria-pressed` の ON/OFF と選択 UI）。
- SaveViewDialog によるビュー保存フローが従来どおり（名前入力 → 保存 → サイドバーに反映）。
- ヘッダー CTA（#628）からの新規作成 / アップロードが従来どおり機能する。
- FilterBar のチップ個別解除・内部リンク参照トリガー・「+ タグ」以外の既存チップ挙動が不変。
- 既存 Popover 利用箇所（dialog / menu 系: 各種メニュー・ダイアログトリガー）の開閉・キーボード操作が不変（`PopupRole` 拡張の波及確認）。
- P15 / P16 / P18 等の非表示モード用途の `.segmented` モックが変わっていないこと（`git diff` で対象外ファイルに差分がないことを確認）。
- `pnpm test:unit` が全件グリーン（DisplayModeSwitch / NoteListToolbar / FilterBar / listSelectors / ViewSwitcher）。
