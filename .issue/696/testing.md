# 動作確認計画 — Issue #696: ノート編集画面に WYSIWYG モードを追加（切り替え時に装飾消失の警告ダイアログ）

**Issue:** #696
**作成日:** 2026-06-13

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm db:migrate   # ローカル D1 にマイグレーション適用（初回・未適用時のみ）
pnpm dev          # http://localhost:3000
```

確認には以下のシードが必要:

- ノートが複数件（編集画面 `/notes/$noteId/edit` を開くため）。なければノート作成画面（`/notes/new`）から作成する。
- **WYSIWYG 非対応タグを含むノート**を1件用意する。新規作成画面の「HTML」タブで `<section><p>テキスト</p></section>` や `<table>...</table>` のような非対応タグを含む HTML を直接入力して保存しておくと、編集画面で警告ダイアログの確認ができる（対応タグ一覧は `app/components/note/editor/wysiwygUnsupportedTags.ts` の `WYSIWYG_SUPPORTED_TAGS` を参照）。
- **対応タグのみのノート**も1件（`<p>` / `<strong>` / `<a>` など）用意し、警告無しで切り替わることを確認する。

開発用管理者アカウントが必要な場合は `pnpm seed:dev-admin` で投入できる。

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. 編集画面に WYSIWYG タブが表示・切り替え可能（AC-1）

- **対応する受け入れ基準:** AC-1
- **目的:** 編集画面のモード切り替えに「WYSIWYG」タブが追加され、押すと WYSIWYG モードに切り替わること
- **手順:**
  1. 対応タグのみのノートの編集画面（`/notes/$noteId/edit`）を開く
  2. モード切り替えタブに「ビジュアル」「WYSIWYG」「FrontMatter」「HTML」が並んでいることを確認（既定は「ビジュアル」= inline）
  3. 「WYSIWYG」タブを押す
- **期待結果:** TipTap ベースの WYSIWYG エディタペインに切り替わり、内容が編集できる
- **確認ポイント:** タブの並び順が `[ビジュアル, WYSIWYG, FrontMatter, HTML]` であること

### 2. 非対応タグを含む場合の警告ダイアログ（AC-2 / AC-5）

- **対応する受け入れ基準:** AC-2, AC-5
- **目的:** 現在のコンテンツに非対応タグが含まれる場合、切り替え前に警告ダイアログが表示され、失われる要素が確認できること
- **手順:**
  1. 非対応タグ（例: `<section>`）を含むノートの編集画面を開く
  2. 「WYSIWYG」タブを押す
- **期待結果:** `role="alertdialog"` の確認ダイアログが表示され、「次の要素は WYSIWYG モードでは保持されません」等の文言とともに失われる要素（例: `<section>`）が一覧表示される。この時点ではまだ WYSIWYG ペインに切り替わっていない
- **確認ポイント:** ダイアログを閉じる/同意するまでモードが切り替わらないこと。失われるタグ名が `<code>` で構造的に提示されること

### 3. 非対応タグが無い場合は警告無しで切り替え（AC-3）

- **対応する受け入れ基準:** AC-3
- **目的:** 非対応タグが無い場合はダイアログ無しでそのまま WYSIWYG へ切り替わること
- **手順:**
  1. 対応タグのみのノートの編集画面を開く
  2. 「WYSIWYG」タブを押す
- **期待結果:** ダイアログは表示されず、即座に WYSIWYG ペインに切り替わる

### 4. キャンセル時はモード・コンテンツ維持（AC-4）

- **対応する受け入れ基準:** AC-4
- **目的:** 警告ダイアログでキャンセルした場合、元のモード・コンテンツが維持され装飾が破壊されないこと
- **手順:**
  1. 非対応タグを含むノートの編集画面を開く
  2. 「WYSIWYG」タブを押して警告ダイアログを表示する
  3. キャンセル（閉じる）を押す
- **期待結果:** 元のモード（ビジュアル/inline）のまま、非対応タグを含むコンテンツがそのまま保持される。WYSIWYG に切り替わらず、装飾が消えない

### 5. 同意して切り替えると二重同意を求められない（AC-7）

- **対応する受け入れ基準:** AC-7
- **目的:** 装飾消失警告で同意した後、WYSIWYG ペイン内の既存「非対応タグ警告バナー」で再度同意を求められないこと
- **手順:**
  1. 非対応タグを含むノートの編集画面を開く
  2. 「WYSIWYG」タブを押して警告ダイアログを表示し、同意（切り替える）を押す
- **期待結果:** WYSIWYG ペインに切り替わる。ペイン内バナーは「同意済み」の控えめ表示で、改めて同意ボタンを求めてこない（autosave も停止しない）

### 6. 新規作成画面の挙動が不変（AC-6）

- **対応する受け入れ基準:** AC-6
- **目的:** 新規作成画面のタブ構成・切り替え挙動が変わっていないこと
- **手順:**
  1. ノート作成画面（`/notes/new`）を開く
  2. モード切り替えタブの構成と既定モードを確認
- **期待結果:** タブ構成 `[WYSIWYG, FrontMatter, HTML]`・既定 WYSIWYG のまま。本 Issue の変更による差異が無い

## エッジケース・異常系

### 1. 未保存変更あり + 非対応タグありの順序（AC-7）

- **目的:** 未保存変更がある状態で WYSIWYG に切り替えたとき、未保存確認と装飾消失警告が適切な順序で出て、装飾喪失について二重同意を求められないこと
- **手順:**
  1. 非対応タグを含むノートの編集画面を開き、本文を少し編集して未保存状態にする
  2. 「WYSIWYG」タブを押す
- **期待結果:** まず未保存確認（`window.confirm`）が出て、それを通過すると装飾消失の `ConfirmDialog` が出る。装飾喪失について同じ内容を 2 回同意させられることはない

### 2. HTML タブで生入力直後に WYSIWYG へ切替

- **目的:** HTML タブで非対応タグを直接入力した直後に WYSIWYG へ切り替えても警告が機能すること
- **手順:**
  1. 編集画面で「HTML」タブを開き、`<section>` を含む HTML を入力する
  2. 「WYSIWYG」タブを押す
- **期待結果:** コミット済みの HTML に対して判定され、非対応タグがあれば警告ダイアログが表示される

## 既存機能への影響確認

- **inline（ビジュアル）モード**: 既存の編集挙動が変わっていないこと。非対応タグを含むノートを inline で開いても従来どおり構造が保全されること。
- **HTML / FrontMatter モード**: タブ切り替えに装飾消失ダイアログが挟まらず従来どおり動くこと（ダイアログは WYSIWYG への切り替え時のみ）。
- **自動保存**: WYSIWYG に切り替えても自動保存（saveDraft / abortInFlight）が破壊されないこと。切り替え自体は contentHtml を変更しない。
