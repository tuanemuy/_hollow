# 動作確認計画 — Issue #571: P21 プロフィール拡充（アバターアップロード + リセット/最終保存/次回変更日）

**Issue:** #571
**作成日:** 2026-06-07

---

## 確認環境

本 Issue は P21 プロフィール画面（`/settings/profile`）に、アバターアップロード配線・action-row のリセット/最終保存タイムスタンプ・ユーザー名の次回変更可能日表示を追加する変更。backend は `UserDTO` への2フィールド露出（`lastSavedAt` / `lastUsernameChangedAt`）と domain 定数 export のみで、新規 migration は無い。実機確認はローカル開発サーバで行う。

### 検証環境の起動

```
pnpm dev
```

`vite dev`（Cloudflare ランタイム）でローカルサーバが起動する。表示された URL をブラウザで開き、**ログイン済みユーザー**で `/settings/profile` を確認する。確認には少なくとも以下を持つユーザーが望ましい:

- avatar 未設定のユーザー（イニシャル fallback 確認用）
- 過去にプロフィールを保存したことがあるユーザー（`updatedAt` がセットされ「最終保存」表示の確認用）
- ユーザー名を最近変更したユーザー（`lastUsernameChangedAt` がセットされ「次に変更できる日付」表示の確認用）と、変更したことがないユーザー（`null` → 非表示確認用）

### デプロイ方法

なし（検証環境のみで確認できる。ステージング反映が必要な場合は `pnpm deploy:staging`）。

## 確認項目

### 1. アバター表示（未設定時のイニシャル fallback）

- **目的:** avatar 未設定ユーザーで、avatar-large 枠にイニシャルが表示される。
- **手順:**
  1. avatar 未設定ユーザーで `/settings/profile` を開く。
  2. プロフィールフォーム上部の avatar-large（80px 円）にイニシャル（表示名 or ユーザー名の頭文字）が表示されることを確認。
- **期待結果:** イニシャルが円形枠に表示され、画像 `<img>` は出ない。
- **確認ポイント:** モック `.avatar-large`（80px 円）の寸法・色とトークン経由で一致しているか。

### 2. アバターのアップロード → プレビュー → 保存

- **目的:** PNG/JPEG をアップロードしてプレビューが出て、保存後に再読込しても avatar が残る。
- **手順:**
  1. `/settings/profile` でアバターの「アップロード」ボタンから PNG または JPEG を選択。
  2. presign → PUT → finalize 後、avatar-large 枠にアップロードした画像のプレビューが表示されることを確認。
  3. プロフィールフォームの「保存」を押す。
  4. ページを再読込し、avatar 画像が引き続き表示されることを確認。
- **期待結果:** アップロード直後にプレビュー、保存後の再読込でも `/media/<id>` 経由で画像が表示される。
- **確認ポイント:** プレビューは保存前でも owner 閲覧許可で表示される。保存前は「保存が必要」と分かる見せ方になっているか。

### 3. アバターの削除 → 保存

- **目的:** avatar を削除して保存するとイニシャル fallback に戻る。
- **手順:**
  1. avatar 設定済みユーザーで `/settings/profile` を開く。
  2. アバターの「削除」ボタンを押し、プレビューがイニシャル fallback に戻ることを確認。
  3. 「保存」を押し、再読込後も avatar が消えてイニシャル表示のままであることを確認。
- **期待結果:** 削除 → 保存で avatar がクリアされ、旧 avatar の ref-count が減算される（再読込でイニシャル表示）。
- **確認ポイント:** 削除はフォーム保存時に確定する（即時 API ではない）。

### 4. リセットで未保存変更が破棄される

- **目的:** action-row の「リセット」で、表示名・自己紹介・avatar の未保存変更が初期状態に戻る。
- **手順:**
  1. `/settings/profile` で表示名・自己紹介を編集し、avatar もアップロードする（保存はしない）。
  2. 「リセット」ボタンを押す。
- **期待結果:** 表示名・自己紹介が元の値に戻り、bio 文字数カウンタも初期値に戻り、avatar プレビューも元（保存済み or イニシャル）に戻る。
- **確認ポイント:** リセットは frontend 完結で、サーバへの送信は発生しない。

### 5. 「最終保存」タイムスタンプ表示

- **目的:** action-row に「最終保存: {日時}」が実値で表示される。
- **手順:**
  1. プロフィールを保存したことがあるユーザーで `/settings/profile` を開く。
  2. action-row 右側（spacer の後）に「最終保存: {日時}」が表示されることを確認。
  3. 表示名などを変更して保存し、再読込後にタイムスタンプが更新されていることを確認。
- **期待結果:** `user.updatedAt`（= `lastSavedAt`）が `ja-JP` 形式で表示され、保存のたびに更新される。
- **確認ポイント:** ダミー値ではなく実値。モック action-row の spacer 配置と一致するか。

### 6. ユーザー名「次に変更できる日付」表示

- **目的:** `lastUsernameChangedAt` がセットされ、かつクールダウン（30日）内のとき「次に変更できる日付」が表示される。
- **手順:**
  1. ユーザー名を変更したばかりのユーザー（`lastUsernameChangedAt` が30日以内）で `/settings/profile` を開く。
  2. ユーザー名フォームのヘルプに「ユーザー名は30日に1回まで変更できます。」に加え「次に変更できるのは {日付} 以降です」が表示されることを確認。
- **期待結果:** `lastUsernameChangedAt + 30日` が `ja-JP` 形式で表示される。
- **確認ポイント:** 算出値が虚偽でない（実 `lastUsernameChangedAt` ベース）。

## エッジケース・異常系

### 1. 非対応形式・サイズ超過のアップロード（hard reject）

- **目的:** PNG/JPEG 以外、または 5MB 超のファイルが client で弾かれる。
- **手順:**
  1. アバターアップロードで GIF / SVG 等の非対応形式を選択 → 明示エラーで弾かれることを確認。
  2. 5MB を超える画像を選択 → 明示エラーで弾かれることを確認。
- **期待結果:** 非対応形式・サイズ超過はアップロードされず、ヘルプ文言（PNG/JPEG・5MB まで）と挙動が一致する。

### 2. `lastUsernameChangedAt` が null / クールダウン経過済み

- **目的:** 実値が取れない/経過済みのとき「次に変更できる日付」を出さない（虚偽表示回避）。
- **手順:**
  1. ユーザー名を一度も変更していないユーザー（`lastUsernameChangedAt = null`）で `/settings/profile` を開く → 「次に変更できる日付」が出ないことを確認。
  2. 30日以上前に変更したユーザーで開く → 同様に出ないことを確認。
- **期待結果:** どちらも「次に変更できる日付」行が非表示。静的なレート制限ヘルプ（30日に1回）のみ表示。

## 既存機能への影響確認

- **`UserDTO` 消費箇所**: `UserMenu`・admin・auth など `toUserDTO` を消費する画面が、フィールド追加で壊れていないこと（`pnpm typecheck` で型整合を担保）。
- **ProfileForm の既存機能**: 表示名・自己紹介の保存、bio 文字数カウンタ、ユーザー名変更・公開 URL プレビュー（#543 実装分）が従来どおり動くこと。
- **media フロー**: ノート本文画像の presign/finalize/`/media/<id>` 表示が回帰していないこと。
