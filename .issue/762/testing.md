# 動作確認計画 — Issue #762: HTML 編集モードで本文を整形表示し保存時に minify する

**Issue:** #762
**作成日:** 2026-06-21

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。整形/minify のラウンドトリップ等価性は主にユニットテストで担保し、ブラウザ確認は表示・保存・モード往復の実挙動を見る。

### 検証環境の起動

```bash
pnpm dev
```

ユニットテスト（整形/minify・reducer の派生状態）:

```bash
pnpm test:unit
```

### デプロイ方法

なし（検証環境のみで確認できる）。ステージング反映が必要な場合は `pnpm deploy:staging`。

## 確認項目

### 1. HTML 編集タブで minified な本文が整形表示される

- **対応する受け入れ基準:** AC-1
- **目的:** 保存済みの詰まった（改行・インデントなしの）`contentHtml` が、HTML タブに入った時点でインデント・改行付きで `<textarea>` に表示される
- **手順:**
  1. `pnpm dev` で起動しログイン
  2. ある程度ネスト構造のある本文（見出し・リスト・段落・リンクを含む）を持つ既存ノートを開く
  3. エディタのモードを HTML タブに切り替える
- **期待結果:** `<textarea>` 内の HTML がブロック要素ごとに改行・インデントされ、構造が目で追える形になっている
- **確認ポイント:** 初期表示は必ず `setMode("html")` 遷移時の整形で行われる（初回マウントが html で始まることは無い）。整形が表示限定であり、保存実体には影響しないことを後続項目で確認

### 2. 手動保存で整形済み HTML が minify されて永続化される

- **対応する受け入れ基準:** AC-2, AC-9
- **目的:** HTML タブで整形表示された本文を手動保存したとき、永続化される `contentHtml` がコンパクト（minify 済み）であること
- **手順:**
  1. 項目1の状態（HTML タブで整形表示）から、本文を一部編集する
  2. 手動保存を実行する
  3. ページをリロードして再度同じノートを開き、HTML タブに入る前のソース（または DB/レスポンス上の `contentHtml`）を確認する
- **期待結果:** 保存された `contentHtml` は改行・インデントの無い minified 表現で、編集内容が反映されている。HTML タブに再度入ると改めて整形表示される
- **確認ポイント:** 整形済みの改行・インデントがそのまま保存されていないこと（表示限定の不変条件）。手動保存も自動保存と同じスナップショットルール（`snapshotForSubmit`）を通っていること

### 3. 自動保存でも minify 済み HTML が永続化される

- **対応する受け入れ基準:** AC-3
- **目的:** HTML タブ編集中の自動保存経路でも minify 済みが飛ぶこと
- **手順:**
  1. HTML タブで本文を編集し、保存操作をせずに自動保存が走るのを待つ
  2. 自動保存後の `contentHtml`（DB/レスポンス上）を確認する
- **期待結果:** 自動保存された `contentHtml` も minified 表現になっている
- **確認ポイント:** HTML タブ編集が自動保存に確実に乗る（`snapshot` の依存に `htmlDraft`/`mode` が含まれ、編集が取りこぼされない）

### 4. ホワイトスペース有意要素・インライン語間スペース・内部リンクが保持される

- **対応する受け入れ基準:** AC-4, AC-5, AC-6
- **目的:** 整形/minify のラウンドトリップで `<pre>`/`<code>`/`<textarea>` 内のホワイトスペース、`<a>foo</a> <a>bar</a>` の語間スペース、`[[...]]` プレースホルダが破壊されないこと
- **手順:**
  1. `<pre>`/`<code>` ブロック、インライン要素の連続、内部リンク `[[...]]` を含む本文を用意する
  2. HTML タブに入って整形表示 → 保存 → リロード → 再度整形表示、を往復する
- **期待結果:** `<pre>`/`<code>` 内のインデント・改行が元のまま、インライン要素間のスペースが消えていない、`[[...]]` が保持され内部リンクとして機能する
- **確認ポイント:** ユニットテスト（`htmlFormat.test.ts`）で `minifyHtml(formatHtml(m)) === m` を機械検証済みであることと、実画面の見た目が一致すること

### 5. HTML ⇄ WYSIWYG ⇄ inline のモード往復で本文が破壊されない

- **対応する受け入れ基準:** AC-7
- **目的:** モードを行き来しても本文が壊れないこと（整形済み HTML が他モードに漏れない）
- **手順:**
  1. ノートを開き inline → HTML → inline、WYSIWYG → HTML → WYSIWYG など複数経路で往復する
  2. 各往復の途中で HTML タブ側を一度編集してから他モードへ戻る
- **期待結果:** どの経路・編集を挟んでも本文の意味内容が保持され、整形由来の余分な改行/インデントが WYSIWYG/inline に混入しない
- **確認ポイント:** html から離脱する際に `htmlDraft` の minify 確定が先に走り、その確定後の `contentHtml` で decoration-loss 検出が動くこと（編集を挟んだ往復で破壊が起きないか重点確認）

## エッジケース・異常系

### 1. 不正/未完成な HTML を編集中でも入力が失われない

- **対応する受け入れ基準:** AC-8
- **目的:** 閉じタグ欠落などの壊れた HTML 断片を編集中でも、整形失敗で入力が消えず編集を継続できること
- **手順:**
  1. HTML タブで閉じタグの無い断片（例: `<div><p>未完成`）を入力する
  2. そのまま編集を続ける／他モードに切り替えてみる
- **期待結果:** 整形に失敗しても入力された文字列はそのまま保持され、編集を継続できる（フォールバックで素の文字列を表示）
- **確認ポイント:** エラーで `<textarea>` が空になったりクラッシュしたりしないこと

## 既存機能への影響確認

- **WYSIWYG / inline モードの編集・保存**: HTML タブを一切使わないフローで、本文の表示・保存挙動が従来どおりであること
- **MediaUploader の HTML モード挿入**: HTML タブでメディアを挿入したとき、挿入先が `htmlDraft`（整形表示側）に正しく反映され、保存で minify されること。inline/wysiwyg 側の挿入経路は不変であること
- **サーバ側サニタイズ**: `saveNote.ts` / `createNote.ts` / `htmlSanitizer.ts` に diff が無く、最終防衛線として従来どおり機能していること（AC-9 は当該ファイルの差分ゼロで担保）
