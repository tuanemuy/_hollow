## 確認項目

### 1. ヘッダーの「アップロード」ボタンでモーダルが開く

- **目的:** ヘッダーからの主動線が `/upload` ページ遷移ではなくモーダルになっていることを確認
- **手順:**
  1. ログイン済み状態でホーム（`/`）にアクセス
  2. ヘッダー右上の「アップロード」ボタンをクリック
  3. URL とモーダルの状態を確認
- **期待結果:**
  - URL が `/` のまま、hash が `#upload` になる（例: `http://localhost:3000/#upload`）
  - 画面遷移は起こらず、現在のページ（ホーム）が背景に残る
  - 画面中央にアップロード用モーダルが開く（タイトル「アップロード」、ドラッグ&ドロップ領域、フッターに「取り込みキューを見る」リンク）
- **確認ポイント:** ヘッダー / サイドバー / ノート一覧自体は背景にそのまま残っている（コンテキスト保持）

### 2. サイドバーの「アップロード」項目でモーダルが開く

- **目的:** サイドバーからの動線もモーダル化されていることを確認
- **手順:**
  1. ホーム画面でサイドバーの「管理 > アップロード」をクリック
- **期待結果:**
  - ページ遷移せず、URL hash が `#upload` になり、モーダルが開く
- **確認ポイント:** Header からの起動と完全に同じモーダルが開く

### 3. ノート一覧ツールバーの「アップロード」ボタンでモーダルが開く

- **目的:** ノート一覧画面からの追加動線もモーダル化されていることを確認
- **手順:**
  1. ホーム画面（ノート一覧）の右上ツールバーから「アップロード」をクリック
- **期待結果:**
  - ページ遷移せず、URL hash が `#upload` になり、モーダルが開く
- **確認ポイント:** ノート一覧の絞り込みやスクロール位置がそのまま保持される

### 4. ファイルアップロード → 元画面のリストに即反映

- **目的:** アップロード後、元の画面のコンテキストが保たれたまま結果が反映されることを確認
- **手順:**
  1. ホーム画面でモーダルを開く
  2. ドラッグ&ドロップまたはクリックで小さなテキスト / Markdown ファイルを 1 つアップロード
  3. アップロード処理完了後、モーダルを閉じる（Esc または × ボタン or backdrop クリック）
- **期待結果:**
  - アップロード中は「アップロード中...」表示
  - 完了後、モーダルを閉じると元の画面（ホーム）に戻り、新しい取り込みジョブが（ジョブが previewing 状態になれば）反映されている
  - hash が消えて URL が元の `/` だけになる
- **確認ポイント:** ローダーの再実行で背景画面が更新されている

### 5. URL hash 直リンクでモーダルが開く（共有・リロード復元）

- **目的:** モーダル開閉状態が URL に反映され、リロード / 共有で復元できることを確認
- **手順:**
  1. ホーム画面で `http://localhost:3000/#upload` を直接 URL バーに入力して移動
  2. ブラウザのリロードを実行
- **期待結果:**
  - hash 付き URL での初回ロード時、ホーム画面がレンダーされた直後にモーダルが開く
  - リロード後もモーダルが開いた状態が維持される

### 6. Esc / × / backdrop でモーダルが閉じる + 履歴ポリシー

- **目的:** モーダルの閉じる経路が複数用意されていることと、閉じた後の URL 状態と履歴の整合を確認
- **手順:**
  1. モーダルを開く（hash = `#upload`）
  2. Esc キーを押す → URL を確認、ブラウザ「戻る」で挙動を確認
  3. 再度モーダルを開く
  4. × ボタンをクリック → URL を確認
  5. 再度モーダルを開く
  6. モーダル外（backdrop）をクリック → URL を確認
  7. モーダルを開いた状態でブラウザ「戻る」ボタンを押す
- **期待結果:**
  - いずれのクローズ経路でもモーダルが閉じ、URL から `#upload` が消える（末尾の `#` も残らない）
  - クローズ操作は `replace: true` で履歴に新エントリを積まない（クローズ後にブラウザ「戻る」で「モーダルを開く前の元ページ」に戻る、ではなく、その手前の履歴に遡る）
  - 手順7: モーダルを開く操作は履歴に積むため、「戻る」でモーダルが閉じて元ページに戻る

### 7. `/upload` 直リンクページが引き続き使える（フォールバック）+ モーダル抑止

- **目的:** 既存ブックマーク・直リンクが壊れていないことと、`/upload` ページではモーダルが二重表示されないことを確認
- **手順:**
  1. `http://localhost:3000/upload` に直接アクセス
  2. その状態でヘッダーの「アップロード」ボタンをクリック
- **期待結果:**
  - 手順1: 従来通り `/upload` ページがレンダーされ、アップロードフォーム + 取り込みキュー一覧が表示される
  - 手順2: URL hash は `#upload` になるが、`/upload` ページでは `UploadDialogMount` がモーダル open を抑止するため、モーダルは開かない（ページ本体の UploadForm を使ってもらう想定）
- **確認ポイント:** フォールバックページとモーダルが同時表示されない（同じ UploadForm が二重に出ない）

### 8. モーダルフッターの「取り込みキューを見る」リンク

- **目的:** モーダルから `/upload` ページへの誘導動線が機能することを確認
- **手順:**
  1. ホーム画面でモーダルを開く
  2. モーダル内フッターの「取り込みキューを見る」リンクをクリック
- **期待結果:** `/upload` ページに遷移し、モーダルは閉じる（hash も消える）

## エッジケース・異常系

### 1. 複数ファイル同時アップロード

- **目的:** 複数ファイル選択時の挙動が `/upload` ページと同じく動作することを確認
- **手順:**
  1. モーダルを開いて、複数の小さなファイル（2-3 個）を一度に選択
- **期待結果:** 順次アップロードされ、エラーがなければ完了。モーダルを閉じれば元画面に反映される

### 2. アップロード失敗時のエラー表示

- **目的:** モーダル内でエラーがちゃんと表示されることを確認
- **手順:**
  1. （可能なら）非対応形式 or 巨大ファイルなどをアップロード
- **期待結果:** モーダル内に既存 `UploadForm` のエラー表示が出る。閉じるボタンは押せる

### 3. IME 変換中の Esc キー

- **目的:** モーダル内のテキスト入力（あれば）で IME 変換 cancel 時に閉じてしまわないことを確認
- **手順:** 既存 `Dialog` の挙動と同等であればスキップ可
