# 実装計画 — Issue #608: ヘッダー/フッターのロゴ(BrandLockup)の左・下が途切れて表示される

**Issue:** #608
**作成日:** 2026-06-09
**複雑度:** 小規模

---

## 目的

`BrandLockup`（ヘッダー・フッターのロゴ）で、左端のマーク（Vesica の2つの重なる円）の左側・上下が stroke ごと `viewBox` 外にはみ出してクリップされ、途切れて表示される不具合を解消する。あわせて、ロゴがモック想定よりも約3割大きく描画されている点を、モック（glyph ≈15px）相当のサイズに揃える。

## スコープ

### 含まれるもの

- `BrandLockup` の `viewBox` を、マークの stroke 込み実描画範囲を含むように拡張し、途切れを解消する。
- `BrandLockup` のデフォルト `height` を `20` → `16` に下げ、文字高さをモック相当（≈15.7px）に揃える。
- 上記に伴う JSDoc コメントの更新（なぜ `viewBox` 原点が負か = stroke はみ出し吸収、という WHY を明記）。

### 含まれないもの

- ソースアセット `spec/design/icons/hollow-lockup.svg` の再エクスポート（途切れはコンポーネント側の合成＝マーク + stroke の問題であり、ワードマーク単体ソースは無関係。ADR-001 の再生成方針は今回の原因に該当しない）。
- `BrandMark`（マーク単体）側の調整（`viewBox="0 0 24 24"` で別系統、途切れていない）。
- 各使用箇所（App/Auth/Public/Landing ヘッダー・フッター）のレイアウト変更（`<BrandLockup />` は全箇所 height 明示なしで呼ばれており、デフォルト変更で一律に追従する）。

## 実装ステップ

### 1. viewBox の拡張で途切れを解消

- **対象ファイル:** `app/components/common/BrandLogo.tsx`（L116）
- **変更内容:** `viewBox: "0 0 473.84 84.48"` → `viewBox: "-5 -1 480 86"`
- **理由:** マークの変換は `x' = -14.57 + 5.83·x`、`y' = -27.72 + 5.83·y`、stroke 半幅 ≈ 4.37。実描画端は左 x'≈-4.37 / 上 y'≈-0.03 / 下 y'≈84.51 で現 `viewBox`（0..473.84, 0..84.48）からはみ出している。新 `viewBox` は x: -5..475、y: -1..85 をカバーし、左・上・下のはみ出し（stroke 半幅 + 余白）を吸収する。右端はワードマーク端 473.84 < 475 で収まる。

### 2. デフォルト height の調整でモックサイズに揃える

- **対象ファイル:** `app/components/common/BrandLogo.tsx`（L108）
- **変更内容:** `height = 20` → `height = 16`
- **理由:** 新 `viewBox` 高さ 86 でワードマーク glyph（84.48 単位）を `height` px で描画すると glyph_px = height × 84.48/86。`height=16` で ≈15.7px となり、モックの仮テキスト glyph ≈15px にほぼ一致する（Issue コメントの目安「15〜16px」の中心、ユーザー確認済み）。

### 3. JSDoc の更新

- **対象ファイル:** `app/components/common/BrandLogo.tsx`（`BrandLockup` の JSDoc / 必要なら `LOCKUP_CHILDREN` 付近）
- **変更内容:** `viewBox` が負の原点・上下左右マージンを持つ理由（マークの stroke 半幅が外側にはみ出すのを吸収するため。ワードマーク基準の `0 0 473.84 84.48` ではクリップされる）を WHY コメントとして記す。アスペクト比の記述（≈5.6:1）は 480/86≈5.58 で実質維持。
- **理由:** CLAUDE.md のコメント方針（WHY が非自明なものだけ残す）に沿い、将来の再発防止のため「なぜ余白付き viewBox なのか」を明示する。

## 設計判断

- **(1) viewBox 拡張を採用**（Issue 修正方針案の最小案）。transform 調整案（案2）はマーク位置・ワードマークとの間隔の再調整が必要で副作用が大きい。ソース再エクスポート案（案3）は原因（コンポーネント合成時の stroke はみ出し）に対して過剰。
- **(2) サイズは height=16**（ユーザー確認済み）。モック glyph ≈15px に対し ≈15.7px。height=15（glyph ≈14.7px）より見た目バランス優先。

## リスクと注意点

- `viewBox` のアスペクト比が 473.84/84.48≈5.61 → 480/86≈5.58 にわずかに変化し、同一 height での描画幅が微増する。height も 20→16 に下がるため、最終的な描画幅は現状より縮む（width は aspect 比から自動算出、明示 width なし）。各ヘッダー・フッターのレイアウト崩れがないか目視で確認する。
- 右端マージンが 475-473.84≈1.16 と狭い。ワードマークはこれ以上右に伸びないため問題ないが、将来ワードマークを変更する場合は再確認が必要。
- 全使用箇所（App/Auth/Public/Landing ヘッダー、Public/Landing フッター、admin route 3箇所）が同一デフォルトを共有するため、1箇所の修正で全箇所に反映される＝全箇所を確認対象にする。

## テスト方針

- `pnpm typecheck && pnpm lint:fix && pnpm format` で静的検証。
- `pnpm dev` でローカル起動し、各ヘッダー・フッターのロゴを目視確認：
  - マークの左端・上端・下端が欠けずに完全表示されること。
  - ロゴサイズがモック（glyph ≈15px）相当に縮んでいること。
  - レイアウト崩れ（折り返し・はみ出し・縦位置ズレ）がないこと。
