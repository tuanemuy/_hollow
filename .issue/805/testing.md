## 確認項目

このIssueは「表示が1文字も変わらない」ことが絶対制約。確認は「集約後も既存の表示と一致するか」に集中する。

### 1. formatBytes の回帰テスト（自動）

- **対応する受け入れ基準:** AC-1 / AC-2 / AC-3
- **目的:** 共有化した `formatBytes` の出力が、集約前の各コピーの出力と1文字も変わらないこと
- **手順:**
  1. `pnpm test:unit` を実行
  2. `app/components/common/__tests__/byteSize.test.ts` の `formatBytes` ケースが全て PASS することを確認
- **期待結果:** 境界値（0、null→"—"(U+2014)、B/KB/MB/GB/TB の各単位境界、`scaled >= 100` の桁切替、`i === 0` の桁）が集約前の出力どおり
- **確認ポイント:** 期待値がコピー元ロジックの実出力（`toFixed` の IEEE754 丸め込み）を verbatim にロックしていること。null が en-dash やハイフンでなく EM DASH(U+2014) であること

### 2. 管理ダッシュボードのストレージ表示

- **対応する受け入れ基準:** AC-1
- **目的:** admin/Dashboard の合計ストレージ・R2・DO のバイト表示が集約後も変わらないこと
- **手順:**
  1. 管理者アカウントでログインし、管理ダッシュボードを開く
  2. ストレージ表示（合計 / R2 / DO）のラベルを確認
- **期待結果:** 集約前と同じ単位・桁で表示される（例: 値に応じて `12 MB` / `1.2 GB` のように自動選択、100 以上は 0 桁、B 単位は 0 桁）
- **確認ポイント:** データが 0 のときの `0 B`、未取得（null）のときの `—`

### 3. 管理メトリクス画面の上限値表示

- **対応する受け入れ基準:** AC-1
- **目的:** admin/Metrics の各上限値（1日あたり最大アップロード、最大取り込み、1ノート最大サイズ、最大エクスポート成果物）とストレージ表示が変わらないこと
- **手順:**
  1. 管理者アカウントで管理メトリクス画面を開く
  2. 上限値カード群とストレージ表示を確認
- **期待結果:** 集約前と同じ表示
- **確認ポイント:** Dashboard と同じ整形ポリシー（単位自動選択・桁切替）

### 4. アカウント削除フォームの影響サイズ表示

- **対応する受け入れ基準:** AC-1
- **目的:** identity/AccountDeleteForm のメディア合計サイズ表示が変わらないこと
- **手順:**
  1. メディアを持つユーザーでログインし、アカウント削除フォームを開く
  2. 「{件数} 件 / {サイズ}」の影響サイズ表示を確認
- **期待結果:** 集約前と同じ単位・桁
- **確認ポイント:** ここは元々 `number`（null なし）で呼ばれる。共有 `formatBytes(number | null)` に渡しても値が非 null のため出力が変わらないこと

## エッジケース・異常系

### 1. ゼロ・null 値の表示

- **目的:** 0 バイト・値未取得（null）時の表示がコピー元と一致するか
- **手順:**
  1. ストレージ 0 のデータ、またはメトリクス未取得状態を再現（可能な範囲で）
  2. 該当画面を確認
- **期待結果:** 0 は `0 B`、null は `—`(U+2014)

## 既存機能への影響確認

- **export/ExportJobDetail（MB 2桁）・ingestion/IngestionJobRow（KB 固定）:** 本Issueでは共有化せず現状維持のため、変更が入らない。エクスポート成果物サイズ・取り込みファイルサイズの表示が従来どおりであることを念のため確認する（ADR-001 参照）。
- **既存の `formatMegabytes` 利用箇所（アップロード上限系 UI）:** `formatBytes` 追加時に `formatMegabytes` の JSDoc 相互参照を整合修正するのみで実装は不変。表示に影響しないこと。
