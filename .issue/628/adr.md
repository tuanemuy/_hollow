# ADR — Issue #628: ヘッダー（グローバル）UIのデザインモック見直し

## ADR-001: モバイルの主要導線をヘッダーへ集約し、下部固定CTA（フッター）を廃止する（#588 ADR-001 を Supersede）

### Status
Accepted（#588 ADR-001 を Superseded by #628）

### Context
#588 ADR-001 では「モバイル（< lg）ではグローバルヘッダーの新規作成/アップロードCTAを `max-lg:hidden` で隠し、`note/list/BottomCtaBar.tsx` の下部固定CTAバー（`BottomActionBar` フレーム）へ退避する」と決めた（Status: Proposed）。

しかし運用観点で次の問題が判明した:
- モバイルでも中心的な導線は「検索」と「アップロード」であり、これらはヘッダー上で常時到達できるべき。アバターのみのヘッダーは主要導線を隠していた。
- 画面下部を占有する固定フッターは、限られたモバイル画面の縦方向を圧迫する。

### Decision
- モバイルでも **検索 + アップロード + 新規作成** をヘッダーに常時表示する（CTAの見せ方は ADR-003）。
- 下部固定CTAバー（フッター）を **廃止** する。実装上の `BottomCtaBar` / `BottomActionBar` と、それ専用の定数 `BOTTOM_ACTION_BAR` / `CTA_BAR_PRIMARY` / `CTA_BAR_UPLOAD` を削除する（消費箇所が一意で連鎖削除が安全）。
- 一括操作バー `BulkActionBar` は別物として存続。cta-bar(z-40) との排他前提が消えるため、`max-sm:not-data-[selected]:hidden` の CSS は維持しつつ理由付けを「未選択時に空バーを出さない」へ更新し、z-45 は他に z-45 利用がなければ z-40 へ戻す。
- #588 ADR-001 は本 ADR で **Superseded**。`.issue/588/adr.md` は履歴として書き換えず残す。

### Consequences
- 良い点: モバイルの主要導線がヘッダーで一貫して到達可能になり、画面下部のデッドスペースが消える。dead constant を残さない方針にも合致。
- トレードオフ: ヘッダーは全認証ページに波及するグローバルコンポーネントのため検証範囲が広い。ヘッダー右に2CTAを置くスペースは、ユーザーメニュー（アバター）をサイドバーへ移すことで確保する（ADR-003）。

## ADR-002: 検索の「中央に来ない」問題は構造変更で解決しない（既存レイアウトを維持）

### Status
Accepted（当初案の grid `1fr auto 1fr` 物理中央化を取り下げ）

### Context
Issue 課題1 は「検索が `grid-cols-[auto_1fr_auto]` の中央列で左右非対称のためビューポート中央からズレる」というもの。当初案では grid を `1fr auto 1fr` に対称化して検索を物理中央に固定することを検討した。

しかしユーザー確認の結果、**検索のズレは実装側の問題であり、モックのレイアウト方針（中央列で `max-w-[460px]` + `mx-auto`、focus で glow するピル）はそのままで良い**との判断。物理中央化のための grid 構造変更は行わない。

### Decision
- 検索ボックスは **既存モック通り**: `grid-cols-[auto_1fr_auto]` の中央 `1fr` 列に `max-w-[460px] w-full mx-auto`、focus で `--shadow-focus`（4px リング = glow）。CSS・マークアップを既存から変えない。
- 物理中央化（grid `1fr auto 1fr` / 絶対配置）は **採らない**。
- ヘッダー右からユーザーメニュー（アバター）を外す（ADR-003）ことで右側要素が軽くなり、結果として検索の体感的な中央寄せは改善する（構造変更なしの副次効果）。

### Consequences
- 良い点: 既存の見た目（glow）を完全に維持。構造変更による全認証ページの回帰リスクがない。最小変更。
- トレードオフ: 数学的な物理中央ではないが、ユーザー判断によりそれは要件ではない。

## ADR-003: CTA序列（アップロード主役・案2-B）とユーザーメニューのサイドバー移設

### Status
Accepted

### Context
Issue 課題2/3。「新規作成」が `pillBtnPrimary` で最も目立つが、本来の主役は「アップロード」。視覚的優先度と操作重要度が逆転していた。モバイルでも検索+アップロード（+新規作成）をヘッダーに置きたいが、ヘッダー右にアバター（UserMenu）+ 2CTA を並べるとスペースが足りない。

### Decision
- **CTA序列は案2-B（密度差）**: アップロード = `pillBtnPrimary`（accent 塗り・アイコン+ラベル・並び先頭）、新規作成 = 枠なしテキストボタン（`pillBtn` の text バリアント）に格下げ。spec §7.2「primary=アイコン+ラベル / secondary=テキストのみ」に準拠。
- **モバイルは両ボタンをアイコンのみ**で表示（デスクトップの序列を縮約）: アップロード = accent アイコン、新規作成 = surface アイコン（`+`）。ラベルは出さない（省スペース）。
- **ユーザーメニュー（アバター/UserMenu）をヘッダーから外し、サイドバー最下部へ移設**する。サイドバー下部にユーザー行（アバター + 表示名 + メール + caret）を固定し、クリックで従来の `<Menu>` ドロップダウン（設定 / ログアウト）を開く。デスクトップは常時表示、モバイルはハンバーガーのドロワー内に出る。これによりヘッダー右に2CTAを置く幅が空く。
- **ボタン高さは検索 input に揃えて小さく**: デスクトップ 36px（input と同じ）、モバイル 36px（input と同じ）。アイコンのみボタンは同サイズの正方形。

### Consequences
- 良い点: アップロードが主役という序列が明確化。モバイルでも両CTA+検索がヘッダーで完結。ヘッダーが軽くなり検索の体感中央寄せも改善。
- トレードオフ: ユーザーメニューがヘッダー右上から消えるため、設定/ログアウトはサイドバー経由（モバイルはハンバーガー一段深く）になる。これは主要導線（検索・アップロード・新規作成）をヘッダーに優先する判断。
- 影響範囲: `Header.tsx`（UserMenu 撤去・CTA 入替）、`Sidebar.tsx`（ユーザー行追加・下部固定）、`UserMenu.tsx`（サイドバー文脈で再利用できるよう trigger/配置を調整）、`AppShell`/`Sidebar` のレイアウト（下部アンカー）。

## ADR-004: 44px タップターゲット床の撤廃は「グローバルヘッダーの操作行」に限定する

### Status
Accepted（当初「全面撤廃」案から、実装の波及範囲を踏まえてヘッダー局所に縮小）

### Context
プロジェクトは index.md §7.1 と各モバイルモックのグローバル CSS（`@media (max-width:639px){ button,.pill-btn,.icon-btn{min-height:44px} }`）、および実装側の共有プリミティブ（`pillBtn` の `max-sm:min-h-[44px]`、`ICON_BTN`/`MENU_BTN`/`pillBtnIcon`、`FIELD_INPUT`、`NoteCheckbox`、各画面の `[&>button]:max-sm:min-h-[44px]!` 等）で「モバイルのインタラクティブ要素は最小 44px」を担保してきた（#536/#588 系）。

本 Issue でヘッダーの検索 input（36px）にボタンを揃える（ADR-003）と、この床と衝突する。当初は「全面撤廃」を検討したが、実装上の床は **15 ファイル・全ボタンの基底プリミティブ・入力欄・ダイアログ・エディタ・管理画面等** に織り込まれており、全面撤廃は #628（ヘッダー再設計）の枠を大きく超える巨大 diff・広範な a11y 回帰になる。ユーザー判断により、**撤廃はグローバルヘッダーの操作行に限定**する。

### Decision
- 床の撤廃対象は **グローバルヘッダー（`Header`）の操作行のみ**: 検索 input・アップロード/新規作成 CTA・メニューボタン。これらはヘッダー文脈で 36px（desktop/mobile 共通、検索 input = h-9）に揃える。
- 実装は共有 `pillBtn` 基底の `max-sm:min-h-[44px]` は**変えない**（他画面のボタンに影響させない）。ヘッダーの CTA には床を打ち消す**ヘッダー局所の上書き**（`max-sm:min-h-9!`（床を打ち消し36pxに揃える））を当てる。`ICON_BTN`/`MENU_BTN` のヘッダー用途分は床を外す（用途がヘッダー/レイアウト専用かを確認の上）。
- それ以外の 44px 床（ダイアログ・フォーム・一括操作・カード行アクション・エディタ・管理画面・タグ・公開・認証等）は **そのまま維持**。
- index.md §7.1 は「一般のモバイル操作対象は快適なタップサイズ（≈44px）を保つ。ただしグローバルヘッダーの密なコントロール行は検索 input に揃えて 36px とする例外」と明記する（全面撤廃ではなく例外の文書化）。
- 各モックの**グローバル 44px ルールは復活**させ（非ヘッダーのボタンは 44px 維持）、ヘッダーの `.pill-btn`/`.menu-btn` は局所上書きで 36px にする。

### Consequences
- 良い点: ヘッダーの密な操作行（検索 + CTA）が 36px で揃いつつ、アプリ全体のモバイル a11y（44px 床）は維持。#628 の diff がヘッダー＋関連に収まりレビュー可能。
- トレードオフ: ヘッダーのタップ対象が 36px と若干小さくなるが、ヘッダーは画面上部で誤タップしにくく、対象（検索/CTA）も明確。例外を文書化して意図を残す。

> 注: アプリ全体の 44px 床の見直し（全面撤廃の是非）が将来必要なら、専用 Issue で別途検討する（本 Issue スコープ外）。
