# 動作確認計画 — Issue #658: P10 FilterBar に「+ タグ」ゴーストチップ（タグピッカー導線）を実装する

**作成日:** 2026-06-13

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載（プロジェクト全体のセットアップは省略）。

### 検証環境の起動

```bash
pnpm db:migrate          # ローカル D1 にマイグレーション適用（未適用の場合のみ）
pnpm seed:dev-admin      # 認証済み dev-admin ユーザー + セッションを投入
pnpm dev                 # http://localhost:3000（vite dev / Cloudflare ランタイム）
```

自動チェック（実装ステップ7の品質ゲート）:

```bash
pnpm typecheck && pnpm lint:fix && pnpm format && pnpm test:unit
```

### シードデータ

タグ付きノートが必要。`seed:dev-admin` はユーザー/セッションのみ投入するため、ホーム（P10）のエディタからタグ（`#tag` 形式）付きノートを作成して以下を満たすこと:

- タグ 3 件以上（ピッカーの一覧・複数選択確認用）
- VISIBLE_TAG_LIMIT（12件）を超える 13 種類以上のタグ（既知の制限の確認項目 6 とエッジケース 2 に必要）
- タグが 1 件もないユーザー状態も必要（AC-9。新規ユーザーを作るか、ノートを全削除した状態で確認）

### デプロイ方法

なし（純フロントエンド変更。ローカル開発サーバーで確認できる）。

## 確認項目

### 1. 「+ タグ」チップの表示位置とスタイル

- **対応する受け入れ基準:** AC-1, AC-2
- **目的:** ゴーストチップがモック確定の並び順・見た目で表示されること。
- **手順:**
  1. タグ付きノートが複数ある状態でホーム `/` を開く。
  2. FilterBar のチップ列を観察する。
- **期待結果:** タグチップ群（「もっと見る (+N)」トグル含む）の直後・期間ゴーストチップの前に「+ タグ」チップが表示される。
- **確認ポイント:** 破線枠・透明背景（既存の期間/公開状態ゴーストチップと同スタイル、h-7）。先頭アイコンが `+`（11px 相当）で、他チップの `▾` と描き分けられている。`spec/design/pages/P10-home.html` の `.filter-chip-ghost` と見比べて差異がないこと。

### 2. トリガーの a11y 属性と title

- **対応する受け入れ基準:** AC-3
- **目的:** ADR-008 の a11y 契約を満たすこと。
- **手順:**
  1. devtools で「+ タグ」ボタン要素を検査する。
  2. デスクトップでチップにマウスホバーする。
- **期待結果:** `aria-haspopup="listbox"`・`aria-label="タグで絞り込み"`・`title="タグで絞り込み"` が付与され、ホバーでツールチップが出る。
- **確認ポイント:** モバイル幅でも `title` が付いていること（ADR-004 の意図的逸脱）。当たり判定が 44px 確保されている（チップ周辺のわずかな外側クリックでも反応）。

### 3. タグピッカーパネルの表示内容

- **対応する受け入れ基準:** AC-4
- **目的:** 全タグが件数付き listbox として表示されること。
- **手順:**
  1. 「+ タグ」をクリックする。
  2. devtools でパネルの role 構造を検査する。
- **期待結果:** `role="listbox"` + `aria-multiselectable="true"` のパネルが開き、全タグ（「もっと見る」に畳まれている分も含む）が `#name` + 件数バッジの `role="option"` で並ぶ。
- **確認ポイント:** 適用中のタグは `aria-selected="true"` + 選択表示（✓）、未適用は `aria-selected="false"`。タグが多い場合はパネルが `max-h` 内でスクロールする。

### 4. オプション選択による絞り込み（マルチセレクト）

- **対応する受け入れ基準:** AC-5
- **目的:** トグル選択が既存タグチップと同じ楽観的反映で一覧に効き、パネルが閉じないこと。
- **手順:**
  1. ピッカーで未選択タグをクリックする。
  2. 続けて別のタグをクリックし、最初のタグを再クリックして解除する。
- **期待結果:** クリックの都度ノート一覧が即座に絞り込まれ（URL の `tagNames` も更新）、パネルは開いたまま。再クリックで解除される。
- **確認ポイント:** バー上の対応タグチップの選択状態（`aria-pressed`）とピッカー内の `aria-selected` が一致する。連打してもトグルが取りこぼされない。

### 5. キーボード操作

- **対応する受け入れ基準:** AC-6
- **目的:** ロービングフォーカスとフォーカス復帰が機能すること。
- **手順:**
  1. Tab で「+ タグ」チップにフォーカスし Enter で開く。
  2. 矢印キー（↓/↑）でオプション間を移動し、Enter / Space で選択をトグルする。
  3. 任意のオプションをマウスでクリックした直後に ↓ を押す。
  4. Escape で閉じる。別途、開いた状態でパネル外をクリックする。
- **期待結果:** 矢印で 1 件ずつフォーカス移動、Enter/Space でトグル（閉じない）、Escape / 外側クリックで閉じてトリガーにフォーカスが戻る。手順 3 ではクリックしたオプションの次へ移動する（先頭へ飛ばない — activeIndex 同期の確認）。
- **確認ポイント:** focus-visible のアウトラインが見える。

### 6. モバイル幅でのボトムシート表示

- **対応する受け入れ基準:** AC-7
- **目的:** < sm でパネルが画面下部の全幅シートになること。
- **手順:**
  1. devtools のデバイスエミュレーション（例: 375px 幅）でホームを開く。
  2. 「+ タグ」をタップする。
  3. シート内をスクロールする（タグが多い状態）。
- **期待結果:** パネルが画面下部に全幅シートとして表示される（既存の期間/公開状態ポップオーバーと同挙動）。
- **確認ポイント:** シート内のスクロール操作（スクロールバー上の mousedown 含む）でシートが閉じない。各オプションのタップ当たり判定が十分。

### 7. フィルタポップオーバーの相互排他

- **対応する受け入れ基準:** AC-8
- **目的:** 「+ タグ」と期間 / 公開状態が同時に開かないこと。
- **手順:**
  1. 期間ポップオーバーを開いた状態で「+ タグ」をクリックする。
  2. 逆に、タグピッカーを開いた状態で公開状態チップをクリックする。
- **期待結果:** 先に開いていたポップオーバーが閉じ、新しい方だけが開く。

### 8. タグ 0 件時の非表示

- **対応する受け入れ基準:** AC-9
- **目的:** 追加できるタグがないとき導線を出さないこと。
- **手順:** タグ付きノートが 1 件もないユーザーでホームを開く。
- **期待結果:** 「+ タグ」チップが表示されない（期間・公開状態のゴーストチップは従来どおり表示）。

### 9. 手動テスト手順書の追記

- **対応する受け入れ基準:** AC-11
- **目的:** ドキュメント追従の確認。
- **手順:** `spec/manual-tests/browse.md` を開く。
- **期待結果:** 「+ タグ」導線の手順（デスクトップ/モバイル/キーボード）と VISIBLE_TAG_LIMIT 超タグの既知の制限が追記されている。

## エッジケース・異常系

### 1. 楽観反映中の連続トグル

- **目的:** transition pending 中の操作がドロップされないこと。
- **手順:** devtools でネットワークスロットリング（Slow 3G）を有効にし、ピッカー内で複数タグを素早く連続クリックする。
- **期待結果:** すべてのトグルが最終的に URL / 一覧 / `aria-selected` に反映され、UI が中間状態で固まらない。

### 2. VISIBLE_TAG_LIMIT 超タグの選択（既知の制限）

- **目的:** 13 件目以降のタグをピッカーで選択した際の挙動が、計画どおりの「既知の制限」に収まっていること。
- **手順:**
  1. 13 種類以上のタグがある状態で、ピッカーから「もっと見る」に畳まれているタグを選択する。
  2. バーのチップ列を観察する。
- **期待結果:** 一覧は正しく絞り込まれるが、対応チップはバーに現れない（既存表示の維持）。「もっと見る」展開・ピッカー再オープン・クリア × のいずれかで解除できる。

### 3. ピッカーを開いたままのフィルタクリア

- **目的:** 選択状態の外部変更とピッカー表示の整合。
- **手順:** タグを複数選択した状態でピッカーを閉じ、クリア × でフィルタを全解除した後、再度ピッカーを開く。
- **期待結果:** 全オプションが `aria-selected="false"` に戻っている。

## 既存機能への影響確認

- 既存タグチップのクリックトグル（`aria-pressed`）と「もっと見る (+N)」展開が従来どおり動くこと（ADR-002: 併存）。
- 期間 / 公開状態ポップオーバーの開閉・キーボード操作・モバイルシート挙動に変化がないこと。
- ViewSwitcher（同じ `Popover` listbox モードの既存利用箇所）が従来どおり動くこと — `Popover` への `multiselectable` prop 追加で `aria-multiselectable` 属性が付いていないことを devtools で確認。
- 内部リンク参照の `NotePickerDialog` が従来どおり開けること（相互排他の対象外 = 既存挙動の踏襲）。
- 既存ユニットテスト（`FilterBar.test.tsx` / `Popover.test.tsx`）が `pnpm test:unit` で通ること。
