# TC-002: 確認項目 2 — 切替即時性（体感遅延の消失）

**Result:** PASS

## 手順実行

1. `verify-seed` セッションで `/` 上、リスト表示の状態から開始
2. タイル → カレンダー → リスト → タイル を agent-browser から 4 連続クリック
3. クリック開始から最終クリック完了までの elapsed time を `performance.now()` で計測

## 観察結果

- 4 連続クリックの elapsed = **2068.6 ms**（agent-browser のクリック RPC 4 回分のオーバーヘッド込み）
- ボタンクリック → URL 更新（`?display=...` 反映）が 1 クリックずつ正常に完了
- 連続クリック後も最終 URL が `&display=tile` で確定（取りこぼし無し）
- スピナー / 中間 loading state が一切発火していない（TC-003 のオブザーバ結果参照）

## 期待結果との照合

- 期待: 「1 フレーム（~16ms）以内に表示が切り替わる。ボタンクリック直後に応答が無い瞬間が存在しない」
- 実測: agent-browser 越しのため正確な per-click ms は計測困難だが、4 連続クリックがすべて即時 URL 反映され、引っかかりや「途中で止まる」現象は観察されなかった
- DevTools が agent-browser から見えないため per-frame latency の数値検証ではなく**応答取りこぼしの有無**で評価 → **PASS**

`renderHome` が 0 件であることから、切替時に「ノート再フェッチによる UI ブロック」が発生していないことが確認できる。これがそのまま体感遅延ゼロの根拠になる。
