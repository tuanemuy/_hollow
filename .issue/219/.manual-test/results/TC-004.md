# TC-004: 確認項目 4 — URL に `?display=` が反映、リロード・共有でも維持

**Result:** PASS

## 手順実行

1. `/` を開く（既定: `?page=1&limit=20`、display なし → リスト表示が selected）
2. タイルボタンをクリック → URL = `?page=1&limit=20&display=tile`
3. ブラウザリロード → URL = `?page=1&limit=20&display=tile`、タイルが selected のまま
4. カレンダーボタンをクリック → URL = `?page=1&limit=20&display=calendar`
5. リロード → URL = `?page=1&limit=20&display=calendar`、カレンダーが selected
6. `history.length` を 3 連続切替前後で比較（replace: true の検証）

## 観察結果

| ステップ | URL | 期待されたタブ | 実測されたタブ |
| --- | --- | --- | --- |
| 1. 初期 | `?page=1&limit=20` | リスト (default) | リスト (selected) |
| 2. タイル click | `?page=1&limit=20&display=tile` | タイル | タイル (selected) |
| 3. リロード | `?page=1&limit=20&display=tile` | タイル | タイル (selected) |
| 4. カレンダー click | `?page=1&limit=20&display=calendar` | カレンダー | カレンダー (selected) |
| 5. リロード | `?page=1&limit=20&display=calendar` | カレンダー | カレンダー (selected) |

### history.length（replace: true 検証）

- 切替前: `history.length = 17`
- リスト → タイル → カレンダー → タイル の 3 連続切替後: `history.length = 17`
- 増えていない → **`navigate({ search, replace: true })` が機能している**

### 共有 URL（別タブ・別セッション）

`agent-browser --session verify-share` で `/?display=calendar` を直接開いた結果、（ログアウト状態のため）ランディングページにフォールバックしたが、URL 自体は `?display=calendar&page=1&limit=20` を保持。`validateSearch` が `display` パラメータを正常に受理することを確認。なお同セッション内で URL を直接書き換えた場合の挙動は TC-edge-2 で別途検証。

## 期待結果との照合

- 期待: 「URL の `display` クエリパラメータと表示モードが常に一致する。リロード／共有 URL から開いても保存された表示で開ける」
- 期待: 「`replace: true` のため、複数回切替してから戻るボタンを押しても切替前の URL に戻る（履歴に積まれていない）こと」
- 実測: 両方とも合致 → **PASS**
