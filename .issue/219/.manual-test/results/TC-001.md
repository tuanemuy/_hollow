# TC-001: 確認項目 1 — `_serverFn` リクエストが display 切替で発火しないこと

**Result:** PASS

## 手順実行

1. `/` を `verify-seed` セッションで開く（ログイン済み + ノート 5 件）
2. ブラウザ内 `window.fetch` / `XMLHttpRequest.prototype.open` を hook して `__capturedRequests` に発火 URL を記録（DevTools Network 相当）
3. リスト → タイル → カレンダー → リストの順に DisplayModeSwitch のタブをクリック

## 観察結果

各クリックでキャプチャされたリクエスト（base64 デコード後）：

| 操作 | URL 変化 | 発火 serverFn |
| --- | --- | --- |
| 初期 → タイル | `?page=1&limit=20` → `?page=1&limit=20&display=tile` | `loadAppContext` (root) のみ |
| タイル → カレンダー | `&display=tile` → `&display=calendar` | `loadAppContext` (root) のみ |
| カレンダー → リスト | `&display=calendar` → `&display=list` | `loadAppContext` (root) のみ |
| リスト → タイル | `&display=list` → `&display=tile` | `loadAppContext` (root) のみ |

`renderHome_createServerFn_handler`（ホーム index の loader）は **どの切替でも 0 件**。発火しているのは `__root.tsx` の `loadAppContext` のみで、これは `staleTime: import.meta.env.DEV ? 0 : Number.POSITIVE_INFINITY` の DEV モードで発生する root 層の context reload（Issue #219 のスコープ外）。

## 期待結果との照合

- 期待: 「display 切替ボタン押下のたびに `_serverFn` / `renderHome` 系のリクエストが発火しない（0 件）」
- 実測: `renderHome` 0 件 → **PASS**
- 補足: `loadAppContext` は DEV 限定で発生し、本番 (`staleTime: Infinity`) では 0 件になる。これは本 Issue の対象ではない既存挙動。
