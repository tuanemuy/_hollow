# TC-005: 確認項目 5 — SavedView 復元との整合性

**Result:** PASS

## 手順実行

1. `/?display=tile&q=Test` を開く（タイル表示 + 検索フィルタ）
2. `ビューとして保存` ボタン押下 → ダイアログ表示 → 名前「タイル View」入力 → 保存
3. リロード後、サイドバーの「保存ビュー」 select に「タイル View」が現れることを確認
4. URL を `?display=list` に変えて開く（リスト表示）
5. select から「タイル View」を選択 → URL = `?display=tile&viewId=<id>` に変化、タイル表示
6. その状態で `リスト` タブをクリック → URL = `?display=list&viewId=<id>`、リスト表示
7. リロード → URL = `?display=list&viewId=<id>` のまま、リスト表示で開く
8. select を一旦「保存ビューを選択」に戻し、再度「タイル View」を選び直す → URL が `?display=tile&viewId=<id>` に正規化される

## 観察結果

| ステップ | URL | タブ | 注記 |
| --- | --- | --- | --- |
| 1. 検索状態 | `?display=tile&q=Test&page=1&limit=20` | タイル | 保存ボタンが有効化 |
| 2. SaveDialog 保存 | (変化なし) | タイル | 保存完了 → ダイアログ自動クローズ |
| 3. リロード | (変化なし) | タイル | サイドバー select に「タイル View」追加 |
| 4. `?display=list` 開く | `?display=list&page=1&limit=20` | リスト | viewId なしの状態 |
| 5. select から「タイル View」適用 | `?display=tile&viewId=<id>&page=1&limit=20` | タイル | redirect 1 回で `display=tile` に正規化 |
| 6. リスト click | `?display=list&viewId=<id>&page=1&limit=20` | リスト | viewId 保持、display は手動上書き |
| 7. リロード | 同上 | リスト | 手動上書きが永続 |
| 8. 再選択 | `?display=tile&viewId=<id>&page=1&limit=20` | タイル | SavedView の displayMode で正規化 |

### redirect ループ検証

ステップ 5（SavedView 適用直後）の `__capturedRequests` を観測。`renderHome` が **0 件**、`_serverFn` 自体 0 件。redirect ループは発生していない。
(なお `loadAppContext` は遷移ごとに DEV モードで 1 回発火するが本 Issue 対象外。)

## 期待結果との照合

- 期待 1: SavedView 適用時、URL の `display` が SavedView の `displayMode` で確定 → **満たす**（ステップ 5, 8）
- 期待 2: SavedView 適用後にユーザーが手動で display を変えると、その手動切替が以降の URL に反映 → **満たす**（ステップ 6, 7）
- 期待 3: 再度 SavedView を選び直すと SavedView の display で正規化 → **満たす**（ステップ 8）
