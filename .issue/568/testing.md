# 動作確認計画 — Issue #568: 領域5（P30/P31/P32）モックの未追従機能

**Issue:** #568
**作成日:** 2026-06-08

---

## 確認環境

このIssueはバックエンド（公開 usecase / 新ポートメソッド / 集計）の新設を伴う公開面の機能追従。実機確認はローカル開発サーバで行う。

### 検証環境の起動

```
pnpm dev
```

`vite dev`（Cloudflare ランタイム）でローカルサーバが起動する（`http://localhost:3000`）。表示された URL をブラウザで開いて確認する。

確認には少なくとも以下のシードデータが必要:

- **公開ノートを複数持つユーザー**（P30 公開トップ / P31 公開ノート / P32 公開検索の確認用）。タグ違い・公開日違いのノートが複数あると chip 絞り込み・ソート・期間ファセットを確認できる。
- **公開ノート間の内部リンク**（P31 公開バックリンクの確認用）。公開ノート A が公開ノート B を参照し、かつ非公開ノート C も B を参照する状態にすると「公開参照元のみ表示」を確認できる。
- **同一著者の公開ノートが 5 件以上**（P31 関連ノートの「4 枚 + 当該ノート除外」確認用）。

D1 ローカルにシードが無い場合はマイグレーション適用 → シード投入を行う:

```
pnpm db:migrate
pnpm seed:dev-admin
```

`seed:dev-admin` は dev 用管理ユーザーを作る。公開ノート・タグ・内部リンクなど確認用データが不足する場合は、UI からノート作成 → 公開設定 → 本文に `[[...]]` 内部リンク記法でリンク → タグ付与で用意するか、`pnpm db:execute:local --file <SQLファイル>` で補う。

### デプロイ方法

なし（検証環境のみで確認できる。ステージング反映が必要な場合は DB マイグレーションを伴うため `pnpm db:apply:staging` → `pnpm deploy:staging`）。

## 確認項目

### 1. P31 公開バックリンク（公開参照元のみ）

- **目的:** 公開ノートの「バックリンク」セクションに、その公開ノートを参照している**公開ノートだけ**が並ぶか（モック `P31-public-note.html:689-701`）。
- **手順:**
  1. 公開ノート B（被参照）を開く（`/notes/public/$noteId`）。
  2. B を参照する公開ノート A と非公開ノート C を事前に用意しておく。
  3. B の本文下のバックリンクセクションを確認する。
- **期待結果:** A（公開）はバックリンクに表示され、C（非公開）は表示されない。リンク押下で A の公開ページへ遷移する。バックリンクが 0 件ならセクションごと非表示。
- **確認ポイント:** フォルダ名（ディレクトリセグメント）が露出していないこと（ADR-006）。リテラル px の新規混入なし。

### 2. P31 関連ノート（同じ著者の他の公開ノート）

- **目的:** 「関連ノート」セクションに著者の他の公開ノートが当該ノートを除いて数件並ぶか（モック `P31-public-note.html:703-723`）。
- **手順:**
  1. 同一著者の公開ノートが 5 件以上ある状態で、そのうち 1 件を開く。
  2. 本文下の関連ノートグリッドを確認する。
- **期待結果:** 表示中のノートは含まれず、著者の他の公開ノートが最大 4 枚並ぶ。各カードに公開日とタグが出る。著者の公開ノートが当該のみなら非表示。
- **確認ポイント:** 当該ノートが混ざらないこと。非公開ノートが混ざらないこと。

### 3. P32 検索フィルタードロワー（combobox + 期間 + active-chip + 件数）

- **目的:** フィルターボタンでドロワーが開き、ユーザー/タグ combobox サジェスト・期間 radio・件数が機能し、active-chip に反映されるか（モック `P32-public-search.html:873-1116`）。
- **手順:**
  1. `/search?q=<語>` を開く。
  2. filter-bar の「フィルター」ボタンを押してドロワーを開く。
  3. タグ combobox に文字を入力し、サジェスト候補から 1 つ選ぶ。
  4. ユーザー combobox でも同様にサジェスト→選択する。
  5. 期間 radio（過去 7 日 / 30 日 / 1 年 / すべて）を選ぶ。
  6. ドロワー footer の「N 件を表示」を押す。
- **期待結果:** combobox に公開横断のサジェスト候補が出る。選択するとドロワー上部 or filter-bar に active-chip（×付き）が増える。期間選択で結果が絞られる。footer の件数が現在条件のヒット件数を反映する。active-chip の×で当該条件が解除され URL からパラメタが消える。
- **確認ポイント:** ドロワーは `role="dialog"`/`aria-modal`、Esc・backdrop クリックで閉じる。サジェストは公開ノートを持つユーザー/公開ノートに紐づくタグのみ（列挙対策）。リテラル px の新規混入なし。

### 4. P30 公開トップ chip・表示モード・ソート

- **目的:** フィルター chip でタグ絞り込み、segmented で表示モード切替、sort で並び替えができるか（モック `P30-user-public-top.html:556-592`）。
- **手順:**
  1. 公開ノートを複数持つユーザーの公開トップ（`/u/$username`）を開く。
  2. タグ chip を押してタグ絞り込みする（選択 chip の×で解除）。
  3. segmented（リスト / タイル / カレンダー）を切り替える。
  4. sort ボタン（公開日順）を押す。
- **期待結果:** chip でタグ絞り込みされ一覧が変わる（URL の `tags` 反映）。segmented で list/tile/calendar のレイアウトが切り替わる（`display` は URL 駆動だがサーバ再取得は走らない）。sort で並び順が変わる。
- **確認ポイント:** chip/segmented/sort がすべて実際に動く（飾りでない）。表示モード切替時に余計な再ストリームが走らない。read-only ビューに編集 affordance（チェックボックス等）が出ない。

## エッジケース・異常系

### 1. 公開ノートが 0 件のユーザー公開トップ

- **目的:** chip/segmented/sort が空状態で破綻しないか。
- **手順:** 公開ノートを持たないユーザーの `/u/$username` を開く。
- **期待結果:** 既存の空状態表示が維持され、フィルター UI がエラーにならない。

### 2. P32 サジェスト候補が無いプレフィックス

- **目的:** ヒットしない文字列を combobox に入れたとき listbox が破綻しないか。
- **手順:** 公開ノートに存在しないタグ名/ユーザー名のプレフィックスを入力する。
- **期待結果:** 候補なし（空 listbox）で、選択不能でもクラッシュしない。

### 3. P31 非公開ノートのバックリンク/関連を直接開く

- **目的:** 非公開ノートの公開ページにアクセスした際に NotFound になるか（公開ゲート）。
- **手順:** 非公開ノートの `/notes/public/$noteId` を開く。
- **期待結果:** 既存どおり NotFound（バックリンク/関連 usecase も公開ゲートで弾く）。

## 既存機能への影響確認

- **P30 公開トップの既存表示**: プロフィール hero・ヘッダー検索・ノート一覧の基本表示が従来どおり（`listUserPublicNotes` リファクタの回帰: total/ページングが正しい）。
- **P31 公開ノート詳細の既存表示**: breadcrumb / author-mini / doc-title / meta / 本文が従来どおり（2 セクション追加が既存を壊さない）。
- **P32 検索本体**: キーワード検索・結果リスト・件数表示・スニペット 2 行 clamp（#544）が従来どおり動作する。
- **認証側のノート一覧**: 表示モード/フィルタの認証側実装（`/_app/`）に手を入れていないこと（公開用は別実装）。
