## 詳細

### EC-001: 名前重複（兄弟）

**手順:**
1. サイドバー → `FooRenamed` の「︙」→「子ディレクトリを作成」→ 名前 `Sib` 入力 → 「作成」クリック
   → ツリーに `Sib` が `FooRenamed/Sib` として表示された（前提条件作成完了）
2. もう一度 `FooRenamed` の「︙」→「子ディレクトリを作成」→ 名前 `Sib` 入力 → 「作成」クリック

**期待:**
- 「同名のディレクトリが既に存在します」相当の日本語エラーがダイアログ内に表示される
- ダイアログは閉じない

**実際:**
- ダイアログは **閉じなかった**（OK）
- 入力値 `Sib` は保持された（OK）
- ただしエラー表示は `role=alert` 内に「エラーが発生しました」のみ。具体的な「同名のディレクトリが既に存在します」相当の文言は表示されなかった

**判定:** **partial**
- ダイアログ非クローズ・再試行可能性は要件を満たすが、エラーメッセージが汎用的で、ユーザーが原因を判別できない
- 仕様の「日本語で表示」とは合致するが、エラー種別ごとの文言にローカライズされていない点が要改善

**証跡:** `screenshots/tc-edge/step-02.png`（入力時）/ `step-03.png`（エラー表示時）

### EC-002: 禁止文字 `a/b`

**手順:**
1. サイドバー → `Baz` の「︙」→「子ディレクトリを作成」→ 名前 `a/b` 入力 → 「作成」クリック

**期待:**
- 「使用できない文字が含まれています」相当のバリデーションエラーが日本語で表示される

**実際:**
- ダイアログは **閉じなかった**（OK）
- `role=alert` 内に「エラーが発生しました」のみ表示。NameForbiddenCharacter に対応する具体的な日本語文言は表示されなかった

**判定:** **partial**
- バリデーション自体は機能している（作成は阻止された）が、ユーザーへのフィードバックが「何が悪かったか」を伝えない

**証跡:** `screenshots/tc-edge/step-04.png`（入力時）/ `step-05.png`（エラー表示時）

### EC-004: 循環移動の UI 防止

**手順:**
1. EC-001 で作成済の `FooRenamed/Sib` を前提とする
2. サイドバー → `FooRenamed` の「︙」→「移動」をクリック
3. MoveDirectoryDialog の「移動先」select の選択肢を確認

**期待:**
- select に `FooRenamed`（自身）と `Sib`（子孫）が含まれない

**実際（select の選択肢 6 件）:**
- `— 選択してください —`（プレースホルダ）
- `（ルート）`
- ` //Bar`
- ` //Bar/Child1Renamed`
- ` //Baz`
- ` //TestRoot`

→ `FooRenamed` 自身と子の `Sib` は **含まれていない**。

**判定:** **pass**

**証跡:** `screenshots/tc-edge/step-06.png`

## 所見・推奨

1. **エラーメッセージのローカライズが汎用文言止まり**（EC-001 / EC-002）
   現状、CreateDirectoryDialog 内で発生するサーバーエラーはすべて「エラーが発生しました」に丸められている。
   仕様としては「重複は『同名のディレクトリが既に存在します』」「禁止文字は『使用できない文字が含まれています』」のような種別別文言が期待されている。`*ErrorCode` → 日本語メッセージへのマッピングが Create 系ダイアログでは行われていない可能性が高い。
2. **循環移動の UI 防止は適切に機能している**（EC-004）。Move 用 select の組み立てで自身と子孫を確実に除外できている。
3. **ルートディレクトリの非描画は仕様通り**（EC-005）。すべての treeitem が level≥1。
