## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm dev
```

`vite dev --config vite.config.cloudflare.ts` がローカル開発サーバーを起動する。`http://localhost:3000/`（`vite.config.cloudflare.ts` で port 固定）にログイン済みユーザーでアクセスして検証する。マイグレーション未適用なら事前に `pnpm db:migrate` を実行する。

### デプロイ方法

ステージング・本番への反映は本 Issue の検証では不要（ブラウザ検証は `pnpm dev` で完結）。必要になった場合のコマンドは `pnpm deploy:staging:all`（package.json scripts 参照）。

## 確認項目

### 1. サイドバーからのディレクトリ作成（ルート直下）

- **目的:** サイドバーの「+ ディレクトリを新規作成」ボタンからルート直下にディレクトリを作成できる
- **手順:**
  1. ホーム画面（`/`）を開く
  2. サイドバー「ディレクトリ」セクション見出しの隣にある「+」アイコンボタンをクリック
  3. `CreateDirectoryDialog` が開く
  4. 名前 `TestRoot` を入力して「作成」をクリック
- **期待結果:**
  - ダイアログが閉じる
  - サイドバーのディレクトリツリーに `TestRoot` が即時表示される（router.invalidate により再フェッチ）
- **確認ポイント:** 名前未入力時は作成ボタンが無効化される。重複名や禁止文字（`/` `\` `<` 等）入力時はサーバー側のエラーが日本語で表示される

### 2. サイドバーからの子ディレクトリ作成

- **目的:** ツリー項目の「︙」メニューから子ディレクトリを作成できる
- **手順:**
  1. 確認項目 1 で作成した `TestRoot` の右側「︙」ボタンをクリック
  2. ポップオーバーが開き、「子ディレクトリを作成」「リネーム」「移動」「削除」の 4 項目が表示される
  3. 「子ディレクトリを作成」をクリック
  4. `CreateDirectoryDialog` が開き、親が `TestRoot` であることが分かる UI（例: 親名表示）
  5. 名前 `Child1` を入力して「作成」をクリック
- **期待結果:** `TestRoot` の配下に `Child1` が表示される（インデントで階層が分かる）
- **確認ポイント:** `aria-expanded` 属性が正しく付き、親が「展開」状態になっている

### 3. インライン・リネーム（メニュー経由）

- **目的:** 「︙」メニューの「リネーム」で対象 node がインライン input に変わる
- **手順:**
  1. `Child1` の「︙」→「リネーム」をクリック
  2. node の表示が `<input>` に切り替わり、`Child1` が初期値として表示・フォーカス
  3. テキストを `Child1Renamed` に書き換え Enter キー押下
- **期待結果:** input が消えて新しい名前 `Child1Renamed` が表示される
- **確認ポイント:** 既存 ID は維持され、サイドバーや既存ノートのディレクトリリンクが壊れない

### 4. インライン・リネーム（F2 キー経由）

- **目的:** ツリー項目にフォーカスして F2 で同じ動作
- **手順:**
  1. `Child1Renamed` のリンクに Tab キーでフォーカス
  2. F2 キー押下 → input に切り替わる
  3. `Esc` でキャンセル
- **期待結果:** input が消えて元の名前のまま戻る
- **確認ポイント:** Esc でリネームが破棄され、サーバー呼び出しが発生しない

### 5. ディレクトリ移動

- **目的:** `MoveDirectoryDialog` で別ディレクトリの配下に移動できる
- **手順:**
  1. 別のディレクトリ `TestRoot2` を作成（確認項目 1 と同様）
  2. `Child1Renamed` の「︙」→「移動」をクリック
  3. `MoveDirectoryDialog` が開く
  4. select に「（ルート）」と既存ディレクトリ（自身を除く）が並ぶ
  5. `TestRoot2` を選択して「移動」をクリック
- **期待結果:** `Child1Renamed` が `TestRoot2` の配下に移動。Move dialog 閉じる
- **確認ポイント:**
  - select に「自分自身」「自分の子孫」が含まれない（循環防止 UI）
  - サーバー側 `assertNotCyclicMove` までヒットせず UI で防げている

### 6. ディレクトリ削除（確認文言の検証）

- **目的:** 削除確認ダイアログに子ノートの扱いが明示されている
- **準備:** `TestRoot` の中にノートを 1 件作成（`/notes/new` → ディレクトリ `TestRoot` を選択 → 保存）
- **手順:**
  1. `TestRoot` の「︙」→「削除」をクリック
  2. `DeleteDirectoryDialog`（ConfirmDialog ベース）が開く
- **期待結果:**
  - ダイアログのタイトルに削除対象名 `TestRoot` が表示
  - description に「配下のノートはゴミ箱へ移動し、配下のディレクトリも再帰的に削除されます」と明示
  - 「削除」ボタンが destructive スタイル（赤系）で表示
- **確認ポイント:** 「キャンセル」を押すと何も起きずダイアログが閉じる

### 7. ディレクトリ削除の実行と SavedView broken marker

- **目的:** 削除実行で配下ノートがトラッシュされ、関連 SavedView に broken marker が付く
- **準備:** 確認項目 6 で作ったノートを参照する SavedView を作成（ホーム → ディレクトリフィルタ `TestRoot` → 「ビューとして保存」）
- **手順:**
  1. 確認項目 6 の続きで「削除」をクリック
  2. ダイアログが閉じ、`TestRoot` がサイドバーから消える
  3. `/trash` を開いて配下ノートが「ゴミ箱内」に存在することを確認
  4. `/views` でその SavedView を開いて broken marker（`directory: ...`）が付いていることを確認
- **期待結果:**
  - サイドバーから `TestRoot` 消滅
  - `/trash` にノートが入る
  - SavedView に broken marker（note 経由の indirect fan-out）が反映される
- **確認ポイント:** UI 上のリグレッションが既存 P17（ゴミ箱）、P20（ビュー）でないか

### 8. DirectoryPicker（NoteEditor 内）からのリネーム

- **目的:** Issue 提案 2「ノート編集中の DirectoryPicker からリネーム実行可能」
- **手順:**
  1. 任意のノートを編集（`/notes/$id`）
  2. ディレクトリ select で既存ディレクトリを選択
  3. select の右に「リネーム」「削除」ボタンが表示される
  4. 「リネーム」をクリック → `RenameDirectoryDialog` が開く
  5. 新しい名前を入れて「リネーム」をクリック
- **期待結果:**
  - ダイアログが閉じる
  - DirectoryPicker の select 表示に新しい名前が反映される（router.invalidate 経由）
  - エディタ画面のままで、選択中の ID は維持
- **確認ポイント:** ノート保存時にディレクトリ参照が壊れていない

### 9. DirectoryPicker からの削除

- **目的:** Issue 提案 2「ノート編集中の DirectoryPicker から削除実行可能」
- **手順:**
  1. 確認項目 8 の続きで「削除」をクリック
  2. `DeleteDirectoryDialog` が開く
  3. 確認ダイアログで「削除」をクリック
- **期待結果:**
  - ダイアログが閉じる
  - DirectoryPicker の select 値が空（未選択）に戻る（`onSelectExisting(null)` 経由）
  - サイドバーからもそのディレクトリが消える
- **確認ポイント:** ノート編集中の他の状態（タイトル、内容、タグ）は影響なし

### 10. キーボードナビゲーション

- **目的:** 必須ショートカット 5 種が動作する
- **手順:**
  1. サイドバーのツリーに Tab でフォーカス
  2. **↓** 押下 → 次の treeitem にフォーカス移動
  3. **↑** 押下 → 前の treeitem に戻る
  4. **←** 押下 → 展開中の親なら畳む、リーフなら親へ
  5. **→** 押下 → 折り畳み中の親なら展開、リーフなら次の treeitem
  6. **Enter** → リンク遷移（該当ディレクトリのフィルタ済みホームへ）
  7. **F2** → 当該 node のインライン rename
  8. **Delete** → 削除確認ダイアログ
  9. **Esc** → リネーム中のキャンセル
- **期待結果:** 全ショートカットが期待通り動作
- **確認ポイント:** focus が常に視覚的に分かる（`focus-visible` ring 表示）

### 11. アクションメニューのアクセシビリティ

- **目的:** 「︙」ポップオーバーが ARIA menu pattern に準拠
- **手順:**
  1. 「︙」ボタンに Tab でフォーカス → `aria-label="{name} の操作"` が読み上げられる（スクリーンリーダー）
  2. Enter または Space で展開 → `aria-expanded` が true に
  3. ↓ ↑ で menuitem 間移動
  4. Esc で閉じる
  5. メニュー外クリックでも閉じる
- **期待結果:** 上記すべて動作。フォーカスがトリガーボタンに戻る
- **確認ポイント:** `role="menu"` / `role="menuitem"` / `aria-haspopup` が DOM に存在

## エッジケース・異常系

### 1. 名前重複（兄弟）

- **目的:** 同一親配下に同名（case-insensitive）ディレクトリを作成しようとした場合のエラー表示
- **手順:**
  1. `TestRoot` の配下に `Foo` を作成
  2. 同じ親に `foo` を作成（小文字違い）
- **期待結果:** 「同名のディレクトリが既に存在します」相当のエラーが日本語で表示される
- **確認ポイント:** ダイアログは閉じず、エラーを修正して再試行可能

### 2. 禁止文字

- **目的:** 名前に `/` などの禁止文字を含めた場合のエラー
- **手順:** ディレクトリ作成で名前 `a/b` を入力 → 作成
- **期待結果:** バリデーションエラー表示（サーバー側の `NameForbiddenCharacter` → 日本語化）

### 3. 階層深さ上限

- **目的:** `MAX_DIRECTORY_DEPTH=10` を超える階層作成の拒否
- **手順:** 10 階層の深さまで子ディレクトリを作成し、さらに子作成を試みる
- **期待結果:** 「階層が深すぎます」相当のエラー表示

### 4. 循環移動の UI 防止

- **目的:** 自身/子孫を移動先に選べない
- **手順:**
  1. `A > B > C` の階層を作成
  2. `A` を移動 → MoveDirectoryDialog の select に `A` / `B` / `C` が含まれない
- **期待結果:** select に自分とその子孫が表示されない
- **確認ポイント:** バックエンドの `assertNotCyclicMove` までヒットせず UI で防げている

### 5. ルートの操作

- **目的:** ルートディレクトリ（描画されないはず）の操作が UI 上できない
- **手順:** ツリー描画でルート（name=""）が見えないことを確認
- **期待結果:** ツリーのトップ階層は `tree[0].children` の各要素（level 1）であり、ルート自体は表示されない
- **確認ポイント:** 名前 "" / depth 0 の treeitem が DOM に存在しない

### 6. 空状態

- **目的:** ディレクトリが 1 件もない（root しかない）状態の表示
- **準備:** 新規アカウントを作成（または既存ユーザーで全ディレクトリ削除）
- **手順:** ホーム画面サイドバーを確認
- **期待結果:** 「+ ディレクトリを作成」CTA が表示される
- **確認ポイント:** `tree[0]?.children.length === 0` 判定が機能している

## 既存機能への影響確認

- **ノートエディタの保存フロー** (`/notes/new`, `/notes/$id`):
  - 既存ディレクトリ選択 → 保存 → 正常完了
  - 新規ディレクトリ名入力（既存の `pendingDirectoryName` 経路） → 保存時に作成される
  - 確認: `DirectoryPicker` の props 互換が維持されていることを実機で確認

  - アップロード → preview → ディレクトリ確認の流れで Rename/Delete ボタンが **表示されない** ことを確認

- **ホーム画面のディレクトリフィルタ**:
  - サイドバーのリンクから `directoryId` フィルタが効く（既存挙動と同じ）
- **MoveNoteDialog**:
  - 影響なし。既存パターン維持
- **タグ・ゴミ箱・アップロード**:
  - サイドバー下部の管理セクションが従来通り表示・動作
