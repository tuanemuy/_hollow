# TC-01 — P30 公開トップのソット切替 (publishedAt ⇄ updatedAt)

Status: PASS

## Steps
1. Open `http://localhost:3000/u/alice`, wait networkidle.
2. Observe default sort button label + listing order.
3. Click the sort toggle once (publishedAt → updatedAt).
4. Observe URL + listing order.

## Observations
- Default sort button label: `公開日順`. URL has no `sort` param (default is
  dropped to keep the URL clean — implementation drops the default value;
  the effective default IS publishedAt).
- Default order (公開日順 = published_at DESC):
  Apple(pub 2026-06-08), Banana(2026-05-01), Cherry(2026-01-15), Date(2025-04-01). MATCH.
- After one toggle: button label `更新日順`, URL = `?sort=updatedAt`.
- updatedAt order: Cherry(upd 2026-06-08), Date(2026-06-07), Banana(2025-06-01),
  Apple(2025-02-01). MATCH and DISTINCT from the published_at order.
- trashed-note and null-pub-note correctly absent from both orders.

## Verdict
"公開日順" is backed by `publication_states.published_at` (not updatedAt) and the
toggle swaps axes correctly. The sort toggle UI is wired correctly.

Note (not a defect): testing.md expected the default URL to carry
`?sort=publishedAt`, but `nextFilterSearch` intentionally omits the default
value (`sort === 'publishedAt' ? undefined`). The effective default is still
publishedAt; only the URL serialization differs. Design choice, documented in
PublicTopControls.tsx.
