# TC-06 — username prefix サジェスト (case-insensitive, index 経由, LIKE escape)

Status: PASS

## Setup
Public users with a public note: `alice`, `alicia`, `bob`. Decoys: `alfred`
(prefix `al` but NO public note), `axb` (no public note). usernames are
lowercase-only (domain invariant `[a-z0-9-]`, no `_`/`%` possible).

## Steps & observations
1. `/search` → open「フィルター」→ user combobox, type uppercase `AL`:
   suggestions = `@alice`, `@alicia` only.
   - `bob` absent (no `al` prefix); `alfred` absent (matches `al` but owns no
     public note → enumeration guard). Case-insensitive: uppercase query hits
     lowercase rows.
2. Type lowercase `al`: identical suggestions `@alice`, `@alicia` →
   case-insensitivity is symmetric.
3. Type literal `a_` (LIKE special char): suggestions = **NONE** (empty listbox).
   - Decisive: `alice`/`alicia` both own public notes and *would* match an
     unescaped LIKE pattern `a_%` (where `_` = any single char → `al…`). The
     empty result proves the `_` is escaped to a literal, so it only matches
     usernames literally starting with `a_` (none exist). LIKE escaping works.
4. `EXPLAIN QUERY PLAN SELECT ... WHERE username >= 'al' AND username < 'am'` →
   `SEARCH users USING INDEX uniq_users_username (username>? AND username<?)`
   (index range scan, not a SCAN). Confirms the index-backed prefix path.

## Verdict
Username prefix suggest is case-insensitive (query lowercased), index-backed
(range scan on `uniq_users_username`), LIKE-special-char-safe, and gated to
authors with at least one public note. All #605 acceptance points met.
