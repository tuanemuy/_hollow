#### 問題点（要修正）

**問題点ゼロ。**

2周目改善提案の反映を個別に確認した結果:

- **[S-001 反映: 妥当]** 設定変更 usecase の棚卸しが AC-6 に「対象 usecase は実装時に変更系 adminSettings usecase を棚卸しして確定する（`updateSpeechConfig`（音声）/ 各種 `reset*` / `reencryptApiKey` / `updateUserPromptOverride` を含むか・含まないかを明示し、`settingKind` ユニオンの最終形と AC の検証範囲を一致させる）」と明記され、提案文言を上回る具体度で落ちている。ステップ B-6 も「まず実在する変更系 adminSettings usecase を棚卸しして対象を確定する」を冒頭に置き、実在ファイル名を列挙して「emit する/しない で明示的に仕分け」する手順に具体化。レビュー履歴「2周目 [coverage S-001]」に記録あり。**実在ファイルとの突き合わせ確認済み**: plan が列挙する `updateSpeechConfig` / `resetPromptTemplate` / `resetAllPromptTemplates` / `resetDesignTokens` / `reencryptApiKey` / `updateUserPromptOverride` 等は `app/core/application/adminSettings/` にすべて実在する。架空の usecase 列挙は無く、`settingKind` ユニオンの最終形と AC-6 の検証境界が一致する構造になった。「一部 usecase だけ emit して他が漏れる」取りこぼしが構造的に防がれている。

- **[S-002 反映: 妥当]** 「活動空状態 + 導線非表示の共存」ケースが C-1（「活動空状態 + 導線非表示の共存テスト（空状態メッセージと『すべて見る』非表示が両立）」）とテスト方針（「リリース直後の空テーブルで、空状態メッセージ『アクティビティはまだありません』が出つつ『すべて見る』リンクが非表示で、両者が二重表示にならない」）に 1 ケースとして明記。レビュー履歴「2周目 [coverage S-002]」に記録あり。空状態時の UI 整合（空状態メッセージと導線非表示が両立し二重表示にならない）が検証可能になった。

#### 良い点

- **2周目改善提案が提案文言以上の具体度で AC・ステップ・履歴の全層に反映されている。** 特に S-001 は AC-6 本文に棚卸し指示を直接埋め込み、かつ B-6 に実在ファイル名の列挙＋「emit する/しない の仕分け」手順まで落としており、「`settingKind` ユニオンの最終形と AC の検証範囲を一致させる」という検証可能性の核心を満たしている。実在ファイルとの突き合わせでも列挙の正確性を確認済み。

- **3 周を通じて虚偽表示禁止の鉄則が AC / スコープ / ADR の三層で一貫し続けている。** 1周目（LLM scalar 整合・バックアップ縮退）→ 2周目（usecase 棚卸し・空状態共存）→ 3周目で新たな破れが生じておらず、#540〜545・派生元 #545 ADR-001 との整合が維持されている。AC-2（LLM データ源無しなら描かない + scalar 整合）/ AC-3（実データ 0 と取得失敗 null の区別）/ AC-4（縮退余地付きバックアップ）/ AC-8（導線非表示）が相互矛盾なく成立。

- **スコープ境界が収束している。** 5 つのスコープ外項目（D1 nightly backup 新設 / 任意レンジ集計 / 全件一覧ページ / 遡及バックフィル / 既存 scalar metrics 挙動変更）はいずれも Issue 本文「直近 24h hourly のみ」「チャートと活動は別 PR 可」と一致し、`D1UsageMetricsProvider` の scalar `null` 固定で「既存 4 metric-card 不変」を成立させる判断もスコープ膨張回避として的確。スコープ過大の紛れ込みは無い。

- **2周目で確定スコープに格上げされた保持・刈り込み（AC-10 / B-9 / ADR-005・007）が、再設計（`ingestion_burst_log` 自然キー insert）の副作用（無限増大）を正しく塞いでおり、収束後も穴が残っていない。** 検証手段（刈り込みテスト）まで C-1 に落ちている。
