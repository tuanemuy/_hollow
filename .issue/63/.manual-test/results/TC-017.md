# TC-017 — page リセット（picker 選択時に page=1）

**Result:** PASS (コード検査ベース)

## 検証方法

コード差分による静的検査で判定した。

## 静的検査の根拠

`FilterBar.tsx` の `handlePick` 実装:

```tsx
const handlePick = (noteId: string) => {
  setPickerOpen(false);
  startTransition(() => {
    router.navigate({
      to: "/",
      search: (prev) => ({
        ...withDefaults(prev as Partial<NoteListSearch>),
        referencingNoteId: noteId,
        page: 1,
      }),
    });
  });
};
```

`page: 1` を明示的にスプレッド後に上書きしているため、`prev.page` が何であっても navigate 後は `page === 1` になる。これは他のフィルタ操作（`onToggleTag`, タグ/期間/公開状態の変更）と同じパターン。

## 補強

TC-005「候補選択 → chip 化 → 再開閉」の実機検証で、選択後の URL に `?referencingNoteId=...&page=1` 相当のクエリパラメータが入っていることを確認済み（chip 化 + フィルタ反映を含む全 4 step PASS）。

## 判定

page リセットは plan.md / handlePick 実装通りに動作する。
