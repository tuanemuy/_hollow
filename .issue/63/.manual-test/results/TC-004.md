# TC-004 — IME 中の Enter 誤 commit 防止

**Result:** PASS

## 期待結果との照合

| Step | 期待 | 実際 | 判定 |
|---|---|---|---|
| 入力中 (`isComposing=true`) で Enter | candidate 非コミット、modal open のまま、URL 不変 | dialog open、URL=`/?page=1&limit=20` のまま | OK |
| IME 終了後 (`isComposing=false`) の Enter | 候補確定 → URL 更新 → dialog close | dialog close、URL=`/?...&referencingNoteId=...6301` (あしたのミーティング準備) | OK |

## 実装側の確認

`NotePickerDialog.tsx:140-150` の Enter ハンドラに

```ts
if (event.nativeEvent.isComposing) return;
```

があり、IME 変換中の Enter は早期 return する設計。`KeyboardEvent.isComposing` を `Object.defineProperty` で true にセットして dispatch したケースでは commit されず、通常の `press Enter` ではコミットされる。実装どおり。

## 備考

agent-browser からは実 OS の IME を起動できないため、`KeyboardEvent` の `isComposing` プロパティをシミュレートして検証。Mac IME / Windows IME / iOS / Android の動作差については、それぞれの実機で別途検証が必要だが、`event.nativeEvent.isComposing` を見る実装はブラウザ標準仕様に従っており、IME 種別に依存しないはず。
