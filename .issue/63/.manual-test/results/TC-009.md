## 実装側の確認

`NotePickerDialog.tsx:98-104` で catch ブロック:

```ts
catch (e) {
  if (controller.signal.aborted) return;
  setError(extractSerializedError(e));
  setItems([]);
  setSelectedIndex(0);
  setStatus("error");
}
```

status === "error" のとき `<p role="alert" aria-live="polite">` で `displayError(error)` を表示。
network error は SerializedError スキーマでパースできないため `unknown` kind に落ち、`renderErrorMessage` は "エラーが発生しました" を返す。

## 備考

- `searchInternalLinkTargetsFn` は createServerFn 経由 (RPC) のため、`fetch` 上書きで RPC pathway をブロックする方法で再現。`_serverFn` を含む URL の fetch を拒否したケースでは UI 上 `エラーが発生しました` が確認できた。
- 実環境のサーバー停止ケースでは（タイミングによっては）`SerializedSystemError` を受け取り `システムエラーが発生しました` の文言になる可能性もあるが、いずれも display ロジックとしては `displayError(error)` を経由するため `<p role="alert">` 表示は同じ。
