# TC-012 — モバイル / 仮想キーボード UX

**Result:** PASS (仮想キーボード挙動は実機未検証、ビューポート寸法のみ確認)

## 期待結果との照合

| ビューポート | dialog 寸法 (w×h) | 入力フィールド位置 | overlay 破綻 | 判定 |
|---|---|---|---|---|
| 375×667 (iPhone SE) | 343×224 (16px の外側余白) | y=288 (画面上 1/3) | なし | OK |
| 414×896 (iPhone XR) | 382×226 (16px の外側余白) | 内部に収まる | なし | OK |
| 768×1024 (iPad) | 480×230 | 画面中央 | なし | OK |

`Dialog.tsx` の backdrop は `fixed inset-0 z-[100] flex items-center justify-center p-4` で、
panel は `dialog` クラス (実装側で `max-w-[480px]` 程度) のため、375 / 414 / iPad 全画面サイズで
画面内に収まり破綻しない。

## 備考

- **仮想キーボードによる入力欄重なり**は実機 (iOS Safari / Android Chrome) でないと再現できない。
  Headless Chrome では `visualViewport` が変化しないため、本テストでは検証不可。
- **仮想キーボードの確定 (Enter / Done) で誤 commit しないか** は IME ベースなので TC-4 と同じ実装 (`event.nativeEvent.isComposing`) でカバー。
- **候補リストのスクロール**: max-h-[320px] / overflow-y-auto が設定されているので、20 件以下までスクロール可能。最大 limit=20 の制約あり。
