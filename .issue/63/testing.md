# 動作確認計画 — Issue #63: FilterBar に内部リンク参照フィルタの note picker UI を追加

**Issue:** #63
**作成日:** 2026-05-20

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載（プロジェクト全体のセットアップは省略）。

### 検証環境の起動

```bash

pnpm db:apply:local

# 開発サーバー起動（Vite + Cloudflare 開発モード）
pnpm dev
```

ブラウザで dev サーバーが表示する URL（既定 `http://localhost:5173`）を開く。

### デプロイ方法

```bash

pnpm deploy:staging:dry

pnpm deploy:staging
```

## 前提

- 自分のノートが少なくとも 5 件以上存在し、タイトルにバリエーション（先頭文字違い）があること。0 件 / エラーパスの検証用にタイトル先頭が珍しい文字（例: `Zzz`）で始まらないノートも用意する。
- 認証済みでホーム画面（P10 ノート一覧）に遷移できること。

## 確認項目

### 1. picker トリガーの初期表示

- **目的:** `referencingNoteId` 未指定状態で「ノートを選ぶ…」トリガーが表示される
- **手順:**
  1. ホーム `/` を開く（`?referencingNoteId=...` を含まない URL）
  2. FilterBar の「内部リンク参照」セクションを確認
- **期待結果:** 「内部リンク参照」ラベルと、その隣に「ノートを選ぶ…」ボタン（pill 風スタイル）が表示される
- **確認ポイント:** chip は表示されない / 他のフィルタセクション（タグ・期間・公開状態）と垂直/水平の整列が崩れない

### 2. picker を開いて入力 → 候補表示

- **目的:** debounce 後にタイトル前方一致でノートが listbox 表示される
- **手順:**
  1. 「ノートを選ぶ…」をクリック → モーダル Dialog が開く
  2. 入力フィールドに `フォーカスが初期に当たっている` ことを確認
  3. ノートタイトル先頭の文字（例: `あ`）を 1 文字入力
  4. 100ms 程度待つ
- **期待結果:** loading 表示 (`検索中…`) → 結果リスト（最大 20 件）が表示される。リスト上部または近接位置に「{n} 件」のメタ表示。
- **確認ポイント:** 連続入力中は単一の fetch リクエストに集約される（Network タブで確認） / tag 種別の候補は表示されない（note のみ）

### 3. キーボード操作

- **目的:** マウスを使わずに候補選択できる
- **手順:**
  1. 候補が複数件表示された状態で入力欄に focus
  2. ↓ キーを押下 → 次の候補がハイライト（`aria-selected="true"`）
  3. ↑ キーを押下 → 前の候補に戻る
  4. ↓ を連打して末尾まで進めた状態でさらに ↓ → 先頭に wrap-around
  5. 任意の候補がハイライトされている状態で Enter
- **期待結果:** ハイライトに合わせて URL が `?referencingNoteId=<選択ノートID>&page=1` に navigate、modal が閉じる、chip にタイトルが表示される
- **確認ポイント:** focus が `aria-activedescendant` で input 上に保持されたまま選択操作が完結

### 4. IME 中の Enter 誤 commit 防止

- **目的:** 日本語 IME 確定中の Enter で候補が誤選択されないこと
- **手順:**
  1. 「あ」（変換確定前）を入力 → 候補が表示される
  2. 別の文字「い」を追加（変換確定前の Enter で変換決定する操作）
  3. Enter キーで IME 確定
- **期待結果:** IME 確定の Enter では candidate がコミットされず、modal が開いたまま。続けて Enter（IME 非変換状態）を押すと初めて候補が選択される
- **確認ポイント:** Mac IME / Windows IME / iOS / Android IME すべてで挙動が同じ

### 5. 候補選択 → chip 化 → 再開閉

- **目的:** picker で選択したノートが chip として表示され、× で picker トリガーに戻る
- **手順:**
  1. picker から候補を 1 件選択
  2. URL が `?referencingNoteId=<id>&page=1` に変わる
  3. FilterBar の「内部リンク参照」セクションに chip（タイトル付き）が表示される
  4. ノート一覧が当該 noteId を参照するノートだけに絞り込まれる
  5. chip の × ボタンをクリック
  6. URL から `referencingNoteId` が削除される
  7. picker トリガーが再表示される
  8. もう一度 picker を開いて別ノートを選択 → chip が更新される
- **期待結果:** すべて期待通り動く。chip のタイトルは選択ノートのタイトル
- **確認ポイント:** 選択直後にモーダルが「カチカチ点滅」しないこと（close と navigate が同期）

### 6. ブラウザ戻る・進む

- **目的:** picker による navigate が履歴に乗ること
- **手順:**
  1. picker でノート A を選択 → chip A 表示
  2. picker（chip を×して再表示）でノート B を選択 → chip B 表示
  3. ブラウザの戻るボタン
- **期待結果:** chip A に戻る → さらに戻ると未指定状態（picker トリガー）に戻る
- **確認ポイント:** 一覧の絞り込み結果も連動

## エッジケース・異常系

### 1. 空クエリで開いた状態

- **目的:** クエリ未入力で fetch されない
- **手順:**
  1. picker を開いて入力フィールドが空のまま放置
- **期待結果:** hint 文言「タイトルの先頭一致でノートを検索できます」のみ表示、Network タブで `searchInternalLinkTargets` リクエストが発生しない、listbox 要素も DOM に出ない（`aria-expanded="false"`）

### 2. 0 件ヒット

- **目的:** ヒットしない検索クエリの空状態文言
- **手順:**
  1. picker を開いて存在しない文字列（例: `Zzzzz`）を入力
  2. 100ms 待つ
- **期待結果:** `該当するノートが見つかりません。タイトルの先頭の文字を変えて検索してください` の文言が表示される（listbox は描画しない、`aria-live="polite"` で SR 読み上げ）

### 3. ネットワークエラー / サーバーエラー

- **目的:** fetch エラー時の表示
- **手順:**
  1. DevTools で Network を Offline にする（または server を停止）
  2. picker を開いて 1 文字入力
- **期待結果:** エラー文言が `displayError` 形式で表示される
- **確認ポイント:** modal が閉じない / リトライ（再入力）すると正常な検索が再開する

### 4. Esc / キャンセルボタンで close

- **目的:** Dialog プリミティブの close 経路
- **手順:**
  1. picker open 状態で Esc キー押下
  2. 再度 open してフッターのキャンセルボタンをクリック
- **期待結果:** 全パターンで modal が閉じ、focus が picker トリガーボタンに戻る
- **確認ポイント:** body の scroll lock が解除される（modal close 後にページがスクロール可能）
- **注:** 共通 `Dialog` プリミティブは背景（overlay）クリック・× アイコンボタンによる close を意図的に提供していない（既存仕様）。各コンシューマがキャンセルボタンを配置する設計。

### 5. IME 確定中の Esc

- **目的:** IME 確定 Esc で modal が誤って閉じないこと（Dialog 既存対応）
- **手順:**
  1. picker open 状態で日本語入力中（変換候補出現中）に Esc キー押下
- **期待結果:** IME の変換キャンセルが優先され、modal は閉じない
- **確認ポイント:** IME 終了後の Esc では正しく modal が閉じる

### 6. モバイル / 仮想キーボード UX

- **目的:** モバイル幅・タブレットで操作が破綻しない
- **手順:**
  1. DevTools のレスポンシブモード（375px / 414px / iPad）で表示
  2. picker トリガーが折り返し表示でも操作可能か
  3. picker open 後に仮想キーボードが入力欄を隠さないか
  4. 候補リストを上下スクロールで全件確認できるか
  5. 仮想キーボードの確定（Enter / Done）で候補がコミットされるか（IME 経由の Enter は誤 commit しないこと）
- **期待結果:** 全画面サイズで modal の overlay とコンテンツが破綻しない / 入力フィールドが仮想キーボードに隠れない

### 7. スクリーンリーダー（VoiceOver / NVDA）

- **目的:** SR で適切に読み上げられる
- **手順:**
  1. SR 起動状態で picker トリガーに focus
  2. picker open
  3. 入力 → 候補表示
  4. ↓↑ で候補移動
- **期待結果:**
  - トリガーボタン: 「ノートを選ぶ…、ボタン、ダイアログを開く」
  - Dialog open 時: dialog の aria-label がアナウンスされる
  - 入力フィールド: combobox role、aria-expanded、aria-controls、aria-autocomplete=list が SR に伝わる
  - 候補リスト: listbox role、各 option の aria-selected
  - 件数 / loading / 0 件: `aria-live="polite"` でアナウンス

## 既存機能への影響確認

- **chip 表示・解除 (Issue #32)**: 未変更動作の確認
  - P11 詳細画面の「このノートを参照しているノート一覧を見る」リンクで navigate
  - chip の × で `referencingNoteId` が解除される
  - URL 直叩き `/?referencingNoteId=<id>` で chip にタイトルが表示される
- **他のフィルタ操作との干渉**: タグフィルタ / 期間フィルタ / 公開状態フィルタを切り替えても picker トリガーは影響を受けない
- **SavedView**: SavedView を `referencingNoteId` 付きで保存・復元できる（Issue #11 範囲、未変更）
- **クリアボタン**: picker 単独表示状態（未指定）でクリアボタンが出ないことを確認（`hasAnyFilter` 不変条件）
- **ページネーション**: 別ページ（`page=2` など）で picker を起動して選択すると、`page=1` にリセットされてフィルタが効く
