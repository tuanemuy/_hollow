# 動作確認計画 — Issue #487: 設定画面のナビゲーション挙動

**Issue:** #487
**作成日:** 2026-06-05

---

## 確認環境

このIssueの変更（設定ルートの index 追加・サブページの `staleTime` 見直し）を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm dev
```

`vite dev`（Cloudflare 設定）で開発サーバーが起動する。起動時に TanStack Router の vite plugin が `app/routeTree.gen.ts` を再生成し、新規 `app/routes/_app/settings/index.tsx` がルートツリーに取り込まれる。

> 注意: 開発サーバーは `import.meta.env.DEV === true` のため、本Issueの `staleTime` は `0`（本番の `Infinity` ではない）で動く。よってブラウザ検証では「本番のキャッシュによる体感速度」は再現しない。検証は機能面（リダイレクト・本文非空白・編集反映）に絞る。

### デプロイ方法

なし（検証環境のみで機能確認できる）。

## 確認項目

### 1. `/settings` 直アクセスでプロフィールへリダイレクト

- **目的:** index ルート追加により、`/settings` 直アクセス時の空白本文が解消されること
- **手順:**
  1. ログイン済みの状態で `/settings` に直接アクセスする
  2. URL とページ本文を確認する
- **期待結果:** `/settings/profile` へリダイレクトされ、プロフィール設定フォームが表示される。本文が空白にならない。
- **確認ポイント:** 共通 chrome（Header / 設定サブナビ）が表示され、main 領域にプロフィールフォームが描画されているか

### 2. サブナビ各項目への遷移で本文が表示される

- **目的:** サブページ間の遷移で本文が空白にならず正しい内容が出ること（既存挙動の退行が無いこと）
- **手順:**
  1. `/settings/profile` を起点に、設定サブナビの「セキュリティ」「プロンプト」「アカウント削除」を順にクリックする
  2. 各ページの本文を確認する
- **期待結果:** 各サブページの本文（セキュリティ設定 / プロンプト設定 / アカウント削除フォーム）が正しく表示される。空白にならない。
- **確認ポイント:** アクティブなナビ項目のハイライト（`data-active`）が遷移に追従するか

### 3. プロフィール編集の反映（invalidate 経路の確認）

- **目的:** `staleTime` 変更後も、編集→保存後に最新値が表示されること（mutation 後 invalidate が leaf を再実行する前提の確認）
- **手順:**
  1. `/settings/profile` で表示名（displayName）を変更して保存する
  2. 別のサブページ（例: セキュリティ）へ遷移してから再度プロフィールへ戻る
  3. 表示名のプリフィル値を確認する
- **期待結果:** 保存した最新の表示名がフォームに反映されている。古い値が残らない。
- **確認ポイント:** 保存直後にフォームが更新され、再訪時も最新値が維持されているか

## エッジケース・異常系

### 1. 未ログインで `/settings` にアクセス

- **目的:** 認証ガード（`_app` loader）が index リダイレクトより先に効くこと
- **手順:**
  1. ログアウト状態で `/settings` にアクセスする
- **期待結果:** `_app` の認証ガードによりトップ（`/`）へリダイレクトされる。設定画面は表示されない。

## 既存機能への影響確認

- `/settings/profile` `/settings/security` `/settings/prompts` `/settings/account-delete` の各サブページ直アクセスが従来どおり動作すること（`staleTime` 変更の退行確認）
- プロンプト設定の保存・クリア、セキュリティ（パスワード変更等）の保存後に最新状態が表示されること
