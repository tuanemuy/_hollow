## 主要な確認結果

- **虚偽表示禁止の遵守**: 影響リストの件数（ノート 3 / メディア 1・121 KB / 公開 約1 / リンク 1）が DB 実測値と一致。ノート・メディアは「アクセスできなくなります」系の非断定表現、公開停止（410 Gone）・リンク失効・export キャンセルは断定表現、saved view / custom prompt は個別件数を出さず包括表現。ADR-003 の方針に忠実。
- **多段確認 UI**: step-num 付き 3 ステップ（同意 checkbox / DELETE input / username + password）がモック構造に準拠。
- **有効化ゲート**: 同意 && 確認語が厳密に `DELETE` && username 一致 && password 入力ありを満たして初めて有効化。`Delete` / ` DELETE `（空白）では有効化されない。
- **パスワード再検証**: 誤パスワードで `"Current password is incorrect"` をフォーム内表示・画面非遷移・未削除。正パスワードで削除成功。
- **即時ログアウト**: 削除後ホーム `/` へ遷移し、保護ルート `/settings/profile` 再訪で未認証として `/`（未認証ランディング）へリダイレクト。observable なログアウトを確認。

## 補足（仕様メモ・起票不要）

- AC-7 のテキストは「ログイン画面等へリダイレクト」だが、本プロジェクトの auth-guard は保護ルートをホーム `/`（未認証ランディング）へ遷移させる既存挙動。`/login` ではないが未認証であることが UI 上明示され保護ルートに到達できないため、即時ログアウトの observability は満たす。
- メディア容量表示は KiB ベースの丸め（123456 / 1024 ≈ 120.56 → 121 KB）。仕様上問題なし。
- `click @ref` の React onClick 偽陽性は今回発生せず（両破壊ケースで POST 正常発火）。
