# 動作確認計画 — Issue #825: P12 モバイルエディタの残 UX 改善（ツールバー圧縮・ネイティブダイアログのカスタム UI 化）

**Issue:** #825
**作成日:** 2026-07-10

## 確認環境

このIssueはフロントエンド（`app/components/note/editor/` 配下）のみの変更。確認に必要な手順のみ記載する。

### 検証環境の起動

コンポーネントのスタイル/UI 変更なので HMR が効く vite dev を使う。

```bash
pnpm db:migrate   # ローカル D1 にマイグレーション適用（未適用なら。初回のみ）
pnpm dev          # vite dev（workerd / @cloudflare/vite-plugin）。http://localhost:3000
```

`pnpm dev` はポート 3000 固定（使用中なら自動で番号が上がる）。実ポートは起動ログで確認する。

### シードデータ（必須）

note editor 画面（`/notes/new` / `/notes/$noteId/edit`）は `_app` 配下の認証必須ルート。決定論的な管理者ユーザーとセッションを投入する。

```bash
pnpm seed:dev-admin
```

出力トークンを CDP 経由でセッション cookie に注入する（cookie 名 `__Host-session` は Secure 必須で `document.cookie` 注入不可）。

```bash
agent-browser cookies set "__Host-session" "<token>" \
  --url http://localhost:3000 --path / --secure --sameSite Lax
```

注入後 `/notes/new` を開くと editor が表示される。新規作成パス（`/notes/new`）はノート投入不要で最短。既存リンク付きノートでのリンク編集を確認する場合のみ、所有ノートを 1 件 SQL（`pnpm db:execute:local <SQLファイル>`）で投入して `/notes/$noteId/edit` を使う。

### 確認幅

DevTools のレスポンシブモードで **≤390px（例: iPhone 12 相当 390px、および 375px）** を基準にモバイル確認する。デスクトップ回帰確認は `sm`（640px）以上、代表として 768px / 1280px を見る。

### デプロイ方法

なし（検証環境のみで確認できる。ステージング/本番への反映は不要）。

## 確認項目

### 1. ツールバー圧縮とオーバーフローメニュー（AC-1 / AC-3）

- **対応する受け入れ基準:** AC-1, AC-3
- **目的:** モバイル 390px で主要書式ボタン + `⋯` が横スクロールなしに一目で収まり、低頻度書式が `⋯` オーバーフローメニューから到達できること。
- **手順:**
  1. モバイル幅（390px）で `/notes/new` を開き、WYSIWYG モードにする。
  2. ツールバーに主要ボタン（Bold/Italic/UL/OL/Link/Image）+ `⋯` が横スクロールなしで並んでいるか確認する。
  3. `⋯` をタップしてオーバーフローメニューを開き、低頻度書式（Strike/H2/H3/Quote/Code）が並ぶか確認する。
  4. メニューがツールバー上に見切れずに表示されるか（レール外配置でクリップされない）確認する。
  5. メニューから各書式を適用できるか確認する。
  6. 適用中の書式が、メニューを開いた時点でチェック等で判別できるか確認する。
- **期待結果:** 主要 6 個 + `⋯` が横スクロールなしに収まる。`⋯` メニューが見切れず開き、低頻度書式に到達・適用できる。適用中状態がメニュー再オープン時に反映される。
- **確認ポイント:** メニューが横スクロールレールにクリップされないこと（AC-1 の要）。WAI-ARIA Menu 準拠 — roving tabindex、Esc/外側クリックで閉じる、閉じたら `⋯` トリガーへフォーカス復帰。390px に収まらない場合は主要ボタンをさらに `⋯` 送りにして横スクロールを残さない（AC-1 収束条件）。

### 2. スクロール時のツールバー追従（AC-1 / AC-2 の回帰）

- **対応する受け入れ基準:** AC-1, AC-2（sticky 移設の回帰確認）
- **目的:** レール外配置に伴う sticky 移設後も、ツールバーがヘッダー直下に追従すること。
- **手順:**
  1. モバイル幅で本文に長文（数十行）を入力し、下方向へ大きくスクロールする。
  2. ツールバー（主要ボタン + `⋯`）がヘッダー直下に固定追従したままか確認する。
- **期待結果:** スクロールしてもツールバーが流れて消えず、ヘッダー直下に留まる（sticky を外側ラッパーへ移設した効果）。
- **確認ポイント:** 追従が 1 行に閉じ込められて即消える回帰が起きていないこと。

### 3. 未保存確認ダイアログ（AC-4 / AC-5）

- **対応する受け入れ基準:** AC-4, AC-5
- **目的:** モード切替時の未保存確認が `window.confirm` ではなくアプリ内ダイアログ（モバイルはボトムシート）で表示され、装飾ロス確認と二重プロンプトにならないこと。
- **手順:**
  1. モバイル幅で `/notes/new` を開き、本文を編集して dirty 状態にする。
  2. モード（WYSIWYG ⇄ HTML）を切り替える。
  3. 未保存確認ダイアログがボトムシートで表示されるか確認する。
  4. 「切り替える」を選び、モードが切り替わるか確認する。
  5. 別途、内容を編集し直してからキャンセルを選び、現在のモード・内容が保持されるか確認する。
  6. WYSIWYG 非対応タグを含む HTML を入力した状態で WYSIWYG へ切り替え、「未保存確認 → 装飾ロス確認」の順に 1 回ずつ表示されるか確認する（二重プロンプトなし）。
- **期待結果:** ネイティブ confirm が出ず、アプリ内ボトムシートで確認できる。確認で切替が進み、キャンセルで現状維持。装飾ロス確認は未保存確認の後に続けて 1 回だけ表示。
- **確認ポイント:** 未保存ダイアログと装飾ダイアログが同時に開かないこと。not-dirty のときは未保存ダイアログが出ないこと。フォーカストラップ・Esc が機能すること。

### 4. リンク挿入ダイアログ（AC-6 / AC-7）

- **対応する受け入れ基準:** AC-6, AC-7
- **目的:** リンク挿入/更新が `window.prompt` ではなくアプリ内ダイアログで行え、非対応スキームのエラーが `window.alert` ではなくインライン `role="alert"` で表示されること。
- **手順:**
  1. モバイル幅で WYSIWYG モードにし、本文の一部を選択してリンクボタンをタップする。
  2. リンクダイアログがボトムシートで開き、URL を入力して挿入できるか確認する。
  3. 選択したテキストにリンクが付与されるか確認する（arch-risk S-004）。
  4. 選択なしでリンクボタンを押した場合の挙動が現行と同一か確認する。
  5. 既存リンク上でリンクボタンを押し、「解除」ボタンでリンクを外せるか確認する。
  6. 非対応スキーム（例: `javascript:alert(1)`）を入力して送信し、ダイアログ内にインラインエラー（`role="alert"`）が出てダイアログが開いたまま再入力できるか確認する。
- **期待結果:** ネイティブ prompt/alert が出ず、アプリ内ボトムシートで URL 入力・挿入・解除・エラー表示ができる。
- **確認ポイント:** 非対応スキーム時にダイアログが閉じず再入力できること。選択テキストへのリンク付与が意図どおり効くこと。フォーカストラップ・初期フォーカスが URL 入力に当たること。

## エッジケース・異常系

### 1. リンクダイアログ送信の親フォーム波及

- **目的:** リンクダイアログの submit が親フォーム（NoteEditor）の submit を誤発火させないこと。
- **手順:**
  1. リンクダイアログで URL を入力して挿入ボタンを押す。
  2. ノート全体の保存が誤って走らないか確認する。
- **期待結果:** リンク挿入のみが実行され、ノート保存 submit は発火しない（`stopPropagation`）。

### 2. オーバーフローメニューの dismiss

- **目的:** オーバーフローメニューの外側クリック/Esc が正しく閉じ、フォーカスが復帰すること。
- **手順:**
  1. `⋯` メニューを開き、Esc・外側タップでそれぞれ閉じる。
- **期待結果:** どちらでも閉じ、`⋯` トリガーへフォーカスが戻る。

## 既存機能への影響確認

- **デスクトップレイアウト（`sm` 以上）**: ツールバーの全ボタンが現状の DOM 並び順（Bold/Italic/Strike/H2/H3/UL/OL/Quote/Code/Link/Image）のままインライン表示され、`⋯` オーバーフロー機構は一切描画されない（空ラッパーによる余白増もなし）。レールは shrink-to-fit・左寄せ pill のまま全幅化しない。DOM/見た目/操作が現行と 1px 単位で一致（回帰なし）。768px / 1280px で確認する。
- **デスクトップのダイアログ**: 未保存確認・リンク入力が中央モーダルとして表示され、操作できること（レイアウト崩れなし）。
