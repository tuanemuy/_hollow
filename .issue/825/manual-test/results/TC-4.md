# TC-4: リンク挿入ダイアログ（AC-6/AC-7）モバイル

**結果**: PASS

環境: 390x844, http://localhost:3000/notes/new, WYSIWYG モード

## 実行ログ

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|----------|------------|------|
| 1 | 本文に「リンクテスト本文」を入力し Cmd+A で全選択 | テキスト選択 | 本文入力・全選択完了 | PASS |
| 2 | ツールバー「リンク」ボタンをクリック | リンクダイアログが開く | `dialog "リンクを挿入"` が開く | PASS |
| 3 | ダイアログ種別・URL 入力欄の確認 | ネイティブ prompt ではなくアプリ内ダイアログ、URL 入力欄あり | アプリ内 `dialog`（heading「リンクを挿入」、`textbox "リンク URL"`、ボタン「キャンセル」「挿入」）。ネイティブ prompt ではない | PASS |
| 4 | `https://example.com` を入力し「挿入」 | ダイアログが閉じ、選択テキストにリンク付与 | ダイアログが閉じ、本文が `link "リンクテスト本文"` に変化（選択テキストへリンク付与＝arch-risk S-004 OK）。URL は /notes/new のまま | PASS |
| 5a | 既存リンク上でリンクボタン再押下 | 編集用ダイアログ／「解除」ボタン表示 | `dialog "リンクを編集"`、URL が `https://example.com` プレフィル、ボタン「キャンセル」「解除」「更新」。「解除」ボタンあり | PASS |
| 5b | URL を `javascript:alert(1)` に置換して「更新」 | インラインエラー(role="alert")表示＋ダイアログ開いたまま、ネイティブ alert なし | `alert` ロールで「対応していない URL スキームです (http / https / mailto / 相対 URL のみ)」を表示。ダイアログは開いたまま、URL 値も保持され再入力可能。ネイティブ alert は出ない | PASS |
| 6 | エラー後「キャンセル」 | ダイアログが閉じ、既存リンクは維持 | ダイアログが閉じ、本文リンク（https://example.com）は不正更新されず保持 | PASS |

## 補足

- 既存リンク選択時はダイアログタイトルが「リンクを編集」に切り替わり、URL がプレフィルされ「解除」「更新」ボタンが出る（新規時は「リンクを挿入」＋「挿入」）。
- 非対応スキーム時にダイアログが閉じず、role="alert" のインラインエラーで再入力できることを確認（AC-7）。
- 初期フォーカス: URL 入力欄へ直接 type/fill が通ったことから URL 入力にフォーカスが当たっている挙動と整合。
