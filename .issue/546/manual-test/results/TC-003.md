## BLOCKED の理由

- TC-003 実行に着手した時点で、`http://localhost:3000` の開発サーバーが停止していた（接続拒否）。
  TC-001 / TC-002 は同サーバーで完了・証跡取得済み。サーバーは TC 実行の途中（TC-001 のサーバー関数 POST 前後で
  ブラウザが断続的に `about:blank` へ遷移した事象あり）で落ちた可能性が高い。
- サーバーは私が起動したものではない（外部起動）ため、別構成で勝手に起動し直すことは避け、環境依存の BLOCKED として記録する。
  サーバーを再起動すれば TC-003 は実行可能と見込まれる。

## コード調査による期待挙動（参考・未検証）

ライブ検証はできなかったが、実装上 Setup Token エラーは**案D アラートで表示される設計**であることを確認した。

- `app/routes/setup.tsx`：`/setup` は `setupTokenVerifier.isEnabled()` が true のときのみ `AdminSignUpForm` を表示し、
  false のときは `notFound()`（404「このページは利用できません。」）を投げる。
  ＝ Setup Token 未設定なら **そもそもフォームが出ない**（404）。フォーム到達には Setup Token 設定が有効な環境が必要。
- `app/components/auth/AdminSignUpForm/index.tsx`：
  - `isSetupTokenError`（`error.kind === "unauthorized"` かつ `code === "invalid_setup_token" | "setup_token_disabled"`）のとき、
    専用の案D アラートを描画：
    ```
    <div className={`${ALERT} ${ALERT_ERROR}`} role="alert">
      <span className={ALERT_ICON}><AlertCircle size=20 /></span>
      <p className={ALERT_TITLE}>
        {code === "setup_token_disabled" ? "Setup Token が設定されていません。" : "Setup Token が正しくありません。"}
      </p>
      <p className={ALERT_BODY}>値を確認してもう一度入力してください。</p>
    </div>
    ```
  - `ALERT` = `bg-bg shadow-xs ... border border-[color-mix(...alert-accent 30%...)]`（白地+ヘアライン枠）、
    `ALERT_ERROR` でアクセントを `--color-error` に設定 ＝ **案D の体裁（白地+error枠+アイコン+title+body, `role="alert"`）を満たす実装**。

→ 実装ベースでは案D アラート要件を満たすが、サーバー停止により実画面での観測は未達。判定は委ねる（FAIL ではなく環境依存 BLOCKED）。

## 補足（TC-001 で観測したサーバー安定性の懸念）

TC-001 のサインアップ送信時、ブラウザが繰り返し `about:blank` に遷移する事象が発生した。最終的に開発サーバーが
接続拒否状態（ダウン）になったことと合わせ、ローカル開発サーバーの安定性に懸念がある可能性を申し送る。
