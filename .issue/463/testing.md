# 動作確認計画 — Issue #463: 設定画面のスタイリング実装＋UserMenu の設定ボタンが開いた瞬間グレーになる挙動を修正

## 確認環境

このIssueの変更（`/settings` 配下のスタイリングと UserMenu のハイライト挙動修正）を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm db:migrate        # ローカル D1 にマイグレーション適用（未適用なら）
pnpm seed:dev-admin    # ローカル dev 用の認証シード（ログイン可能なユーザーを用意）
pnpm dev               # Vite dev サーバー（Cloudflare ランタイム）
```

シードしたユーザーでログイン後、ヘッダーのアバター（UserMenu）と `/settings` 配下の各画面を開いて確認する。

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. 設定レイアウトのスタイリング

- **目的:** `/settings` のレイアウト（タイトル・戻りリンク・サブナビ・コンテンツ領域）が他の出荷済み画面（admin / auth / public）と視覚的に馴染んでスタイルされていること。
- **手順:**
  1. ログイン後 `/settings/profile` を開く
  2. ページ上部の「設定」見出し・サブタイトル・戻りリンクの体裁を確認する
  3. サブナビ（プロフィール / セキュリティ / プロンプト / アカウント削除）の並びと余白を確認する
- **期待結果:** 素の HTML（無スタイル）ではなく、デザイントークンに沿った余白・タイポグラフィ・配色で表示される。
- **確認ポイント:** 戻りリンク・見出し階層が破綻していないこと。

### 2. サブナビのアクティブ状態

- **目的:** 現在表示中の設定ページに対応するサブナビ項目がアクティブ表示されること。
- **手順:**
  1. `/settings/profile` → `/settings/security` → `/settings/prompts` → `/settings/account-delete` と順に遷移する
  2. 各ページで対応するサブナビ項目のアクティブ表示を確認する
- **期待結果:** 表示中ページのナビ項目だけがアクティブ配色になる（desktop=`bg-surface` 系、mobile 横スクロール時=ダークピル系）。
- **確認ポイント:** `aria-current` が付いている項目とアクティブ配色が一致すること。

### 3. 各設定フォームのスタイリング

- **目的:** ProfileForm / SecurityForm / PromptsForm / AccountDeleteForm の section・field・input・textarea・ボタン・区切り線が規約準拠でスタイルされていること。
- **手順:**
  1. `/settings/profile`：表示名・ユーザー名・自己紹介の入力欄、保存ボタンの体裁を確認
  2. `/settings/security`：メール・パスワード変更欄、他端末ログアウトのチェックボックス行、現在のメール表示を確認
  3. `/settings/prompts`：各プロンプトカード・デフォルト表示（details/summary/pre）・保存/復帰ボタンを確認
  4. `/settings/account-delete`：説明・危険操作ボタン（既存 pill ボタン）の体裁を確認
- **期待結果:** 各フォームの見出し（section-title）、入力欄、ボタンが整い、他フォーム間で視覚的トーンが揃う。
- **確認ポイント:** 各 Page の大見出し（h1）が視覚的に重複表示されず、セクション見出しのみが見えること（h1 は sr-only で残る）。

### 4. UserMenu をマウスで開いたときのハイライト

- **目的:** ヘッダーのアバターをマウスでクリックしてポップアップを開いた瞬間、先頭「設定」項目がグレー背景にならないこと（本 Issue の主目的）。
- **手順:**
  1. 任意の画面でヘッダー右上のアバターを**マウスでクリック**してメニューを開く
  2. 何もホバー／操作していない状態の先頭「設定」項目の背景を確認する
- **期待結果:** 開いた直後、先頭「設定」項目はグレー（`bg-surface`）でハイライトされず素の状態。マウスでホバーしたときだけグレーになる。

### 5. UserMenu のキーボード操作ハイライト

- **目的:** キーボードで開閉・移動したときは従来どおりフォーカスハイライトが見えること（a11y 後退がないこと）。
- **手順:**
  1. ヘッダーのアバターボタンに Tab でフォーカスし、Enter / Space でメニューを開く
  2. 矢印キー（↓/↑）で「設定」「ログアウト」間を移動する
  3. Escape で閉じてフォーカスがアバターボタンへ戻ることを確認する
- **期待結果:** キーボード操作時は移動先の項目に背景ハイライトが出る。とくに danger 項目「ログアウト」に矢印移動した際もハイライト（`bg-error-surface` 系）が出る。Escape クローズとフォーカス復帰が壊れていない。
- **確認ポイント:** マウス開時はハイライト無し・キーボード移動時はハイライト有り、という出し分けが成立していること。

## エッジケース・異常系

### 1. 設定画面のエラー表示

- **目的:** `errorComponent`（route.tsx）が表示される状況でも体裁が崩れないこと。
- **手順:**
  1. （可能なら）設定読み込みでエラーになる状況を再現する、または `errorComponent` の見た目をコード上で確認する
- **期待結果:** `role="alert"` を保ったまま、無スタイルではなくレイアウトに馴染んだエラー表示になる。

### 2. レスポンシブ表示

- **目的:** サブナビのレイアウトがブレークポイントで正しく切り替わること。
- **手順:**
  1. ウィンドウ幅を `lg` 以上 → `sm` 以下と変化させ、`/settings/profile` のサブナビ表示を確認する
- **期待結果:** desktop では縦並び（active=`bg-surface`）、mobile では横スクロール（active=ダークピル）に切り替わり、横はみ出しや崩れがない。
