## 確認環境

このIssueの変更を確認するために必要な手順のみ記載（プロジェクト全体のセットアップは省略）。

### 検証環境の起動

UI の見た目変更のみで DB 影響は無し。検証は開発サーバーで完結する。

```bash
pnpm dev   # http://localhost:3000 で起動
```

ヘッダー検索アイコンの描画確認のみは未ログイン時 `/login` でも可能だが、認証後画面（ノート一覧・詳細・取り込み・トラッシュ・管理）の確認にはログインユーザーが必要。ローカルにテスト用ユーザーが無ければ `/signup` から作成し、シードノートを数件作成しておく（実装後に確認するため、手動で 2〜3 件のノートと 1 件以上の取り込みジョブ・1 件以上のゴミ箱行を用意する）。

### デプロイ方法

UI の見た目変更のみなので検証環境（`pnpm dev`）で確認できる。本Issueでステージング・本番デプロイは必須ではない。任意で確認するなら:

```bash
pnpm deploy:staging:dry   # ステージング向けビルド・ドライラン（実デプロイ無し）
```

## 確認項目

### 1. ヘッダー検索アイコン（#217 同時解消の確認）

- **目的:** `Header.tsx` の `mask-image` 撤去 → lucide `<Search />` への置換で、検索アイコンが正しく虫眼鏡として描画されること（#217「豆腐」現象が解消すること）
- **手順:**
  1. ログイン後の任意の画面（例: `/`）を開く
  2. ヘッダー中央の検索ボックスを目視確認
  3. DevTools で当該 `<svg>` の `stroke` が `currentColor` 由来であることを確認
- **期待結果:** 虫眼鏡アイコン（円 + ハンドル）が `text-ink-tertiary` 相当の色で描画される。豆腐（黒塗り四角・空白）にならない
- **確認ポイント:** input の左 padding と視覚バランス（アイコン右端と placeholder テキスト左端の余白が 11px 程度）

### 2. 公開ページの検索アイコン

- **目的:** `PublicLayout.tsx` の `SearchIcon` ハンドコード削除 → lucide `<Search />` への置換でも描画が正常であること
- **手順:**
  1. 未ログイン状態で `/u/{適当なユーザー名}` または `/search` 系の公開ページを開く
  2. ヘッダー検索ボックス・ユーザーページ内検索ボックスを目視確認
- **期待結果:** 公開ヘッダーの検索アイコンと、ユーザーページ内 `USER_SEARCH_INPUT` の検索アイコンが lucide スタイルで描画される
- **確認ポイント:** Header.tsx と公開側で視覚バランスが揃っている（右ギャップ 11px）

### 3. ヘッダー / ノート一覧ツールバーのアクションボタン

- **目的:** 「新規作成」「アップロード」「ビューとして保存」にアイコンが付与されていること
- **手順:**
  1. ログイン後 `/`（ノート一覧）を開く
  2. ヘッダーの「新規作成」ボタン、`UploadButton` の「アップロード」ボタンを確認
  3. ノート一覧ツールバーの「ビューとして保存」「新規作成」「アップロード」を確認
- **期待結果:** 各ボタンに `Plus`/`Upload`/`Bookmark` のアイコンが テキストの左に表示される（gap-1.5 維持）
- **確認ポイント:** ボタンの高さ・横余白が変わらず、アイコンとテキストの中央揃えが乱れない

### 4. ノート一覧 一括操作（`BulkActionBar`）

- **目的:** 「移動」「公開設定」「エクスポート」「ゴミ箱へ」「選択解除」にアイコンが付く
- **手順:**
  1. ノート一覧で複数行を選択（チェックボックス等）
  2. 表示される `BulkActionBar` の各アクションを確認
- **期待結果:** `FolderInput` / `Globe` / `Download` / `Trash2` / `X` のアイコンが各ボタンに付く。`data-danger` 色は維持される
- **確認ポイント:** 「ゴミ箱へ」の `pillBtnDanger` 色とアイコンの `currentColor` が連動して赤系で描画される

### 5. 取り込みキューのアクション（`IngestionJobRow`）

- **目的:** 「ノートとして保存」「再生成」「破棄」「ノートを開く」にアイコンが付く
- **手順:**
  1. ジョブが存在する状態で `/upload`（取り込みキュー）を開く
  2. 各行のアクションボタンを確認
- **期待結果:** `Check` / `RefreshCw` / `Trash2` / `ArrowRight` のアイコンがそれぞれのボタンに付く
- **確認ポイント:** ジョブステータスによってボタン表示の出し分けが従前通りであること

### 6. ノート詳細アクション（`NoteActions`, `UrlCopyButton`）

- **目的:** 「編集」「公開設定」「移動」「URL コピー」「複製」「エクスポート」「履歴」「削除」にアイコンが付く
- **手順:**
  1. 任意のノート詳細ページを開く（`/notes/{id}`）
  2. アクションメニュー / バーを開いて各ボタンを確認
- **期待結果:** `Pencil` / `Globe` / `FolderInput` / `Link2` / `Copy` / `Download` / `History` / `Trash2` が対応するボタンに表示
- **確認ポイント:** URL コピーボタンのフィードバック（`aria-live` status）は従前通り動く（本 Issue ではコピー成功時のアイコン切替は行わない）

### 7. トラッシュ行アクション（`TrashRowActions`）

- **目的:** 「復元」「完全削除」にアイコンが付く
- **手順:**
  1. `/trash` を開く（ゴミ箱に項目を入れた状態）
  2. 各行のアクションを確認
- **期待結果:** `RotateCcw`（復元）/ `Trash2`（完全削除）のアイコン付与

### 8. 確認ダイアログのアイキャッチ

- **目的:** `ConfirmDialog` のタイトル左に `<AlertTriangle size={20} />` がアイキャッチとして表示され、`aria-hidden` で accessible name に混入しないこと
- **手順:**
  1. 「削除」「完全削除」など `ConfirmDialog` を呼び出す任意のアクションをトリガー
  2. ダイアログ表示時のタイトルレイアウトを確認
  3. DevTools の Accessibility ツリー（または スクリーンリーダー）でダイアログのアクセシブルネームを確認
- **期待結果:** タイトルテキスト左にアイコンが表示される。alertdialog のアクセシブルネーム = タイトル文字列のみで「AlertTriangle」「警告」のようなアイコン由来テキストが含まれない
- **確認ポイント:** タイトル行が `flex items-center gap-2` で縦中央揃え、ダイアログの幅・縁取りに影響しない

### 9. 空状態のアイキャッチ

- **目的:** アップロードキュー空 / トラッシュ空 / タグ空の各画面で 24px アイコンが上部に表示されること
- **手順:**
  1. `/upload` でジョブが空の状態を確認（ジョブを全て処理・破棄するか、新規ユーザーで開く）
  2. `/trash` でゴミ箱が空の状態を確認
  3. `/tags` でタグが 0 件の状態を確認
- **期待結果:** `Inbox` / `Trash2` / `Hash` の 24px アイコンが空状態テキストの上に表示される。`aria-hidden` 属性を持ち、スクリーンリーダーでは読み上げられない
- **確認ポイント:** 中央揃え（`mx-auto mb-3`）、色 `text-ink-tertiary`、テキストとの余白

### 10. 管理画面セクションヘッダ

- **目的:** `app/components/admin/Jobs/index.tsx` のセクション見出し（4 箇所）の左に 16px アイコンが追加されていること
- **手順:**
  1. 管理者権限ユーザーでログインし、`/admin` 配下の Jobs ページを開く
  2. 各セクション（「未完了ジョブ」「最近の失敗」など）のヘッダを確認
- **期待結果:** セクション見出しテキストの左にアイコンが表示される（例: `Clock` / `AlertCircle` 等、見出しに対応するもの）
- **確認ポイント:** ヘッダの右側コンテンツ（カウント等）レイアウトを乱さない

### 11. デザインガイドラインの追記内容（`spec/design/index.md` §7）

- **目的:** ガイドラインに「使う場面 / 使わない場面 / a11y 契約 / サイズの選び方 / 配色 / 使用ライブラリ」が追記されていること
- **手順:**
  1. `spec/design/index.md` §7 を直接読む
- **期待結果:** 上記 6 項目が §7 内に記載されている。`Icon` ラッパー経由を強制する旨、`import * as` の barrel import 禁止が明記されている

## エッジケース・異常系

### 1. 検索アイコンの色トーン

- **目的:** ダーク/ライト両モードで検索アイコンが見えること
- **手順:** OS のテーマ切替で light/dark を切り替えて再描画
- **期待結果:** `currentColor` 経由で `text-ink-tertiary` トークンに従い視認できる色になる

### 2. 取り込みキュー / ゴミ箱が満杯時のアクション連打

- **目的:** アイコン追加でクリック領域・disabled 状態が壊れていないこと
- **手順:** 連続クリック・disabled 状態（`isPending`）を発火させる
- **期待結果:** `aria-disabled` / `disabled` の見た目（`opacity-55`）が従来通り適用される

### 3. アイコンを含むボタンのキーボード操作

- **目的:** Tab フォーカスとフォーカスリングが従来通りであること
- **手順:** キーボードのみでヘッダー → ツールバー → 一覧 → 詳細を遷移
- **期待結果:** フォーカスリング・タブ順序に変化なし

## 既存機能への影響確認

- **既存テストの影響** — `pnpm test:unit` でユニットテストが緑であること。`getByText` でボタン名指しのテストが壊れていないか（事前 grep で洗い出した範囲内）
- **既存スタイル** — `pillBtn` / `pillBtnDanger` / `pillBtnPrimary` の `gap-1.5` が維持され、アイコン追加でレイアウト崩れがないこと
- **バンドルサイズ** — 個別 import になっているか（生成された JS で `lucide-react` 全部が含まれていないか軽くチェック）。`pnpm build` のサイズログを目視確認
