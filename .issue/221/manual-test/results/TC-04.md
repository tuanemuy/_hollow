## 検出した実装バグ（要起票候補）

0 バイトのファイル（`empty.md`）をアップロードすると：
1. `byteSize` の VO 検証は通過する（`validateByteSize` は `raw >= 0` を許容、`app/core/domain/ingestion/valueObject.ts:258-267`）
2. `uploadFile` ユースケース内で DB INSERT 時に SQLite の CHECK 制約 ないし NOT NULL / UNIQUE 制約に違反し、`CONSTRAINT_VIOLATION` (kind=conflict) で返る
3. `errorDisplay.ts:72-83` の `renderConflictMessage` には `CONSTRAINT_VIOLATION` の case が無いため default の「他の操作と競合しました。もう一度お試しください」にフォールバック

結果として、ユーザには「リトライすれば解消する」と誤読される文言が表示されるが、実際は同じファイルを再投入しても永続的に失敗する。

## 推奨対応（別 Issue で対処すべき）

- A) `uploadFile` で `byteSize === 0` を業務エラーとして弾く（`IngestionErrorCode.InvalidByteSize` または専用 code を throw）→ 既存の `ingestion_invalid_byte_size` の日本語マッピングに乗る
- B) `errorDisplay.ts` の `renderConflictMessage` に `CONSTRAINT_VIOLATION` ケースを追加して、「ファイルが正しく読み取れませんでした」相当の文言にマップ

仕様 (`spec/pages/index.md` / `.issue/221/plan.md`) は 0 byte ファイルを業務エラーとしてマップする想定であるため、A) のほうが妥当。
