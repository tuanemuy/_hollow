# ADR — Issue #626: P10 ヘッダー〜ツールバーのデザインモック見直し（表示切り替えの視覚的優先度）

## ADR-001: 表示モード segmented をツールバー右端へ移動し、アイコンのみ + ink 濃度差 active に変更する（#620 の白カード active 表現を表示モード系に限り Supersede）

### Status
Accepted（比較ドラフト `spec/design/pages/drafts/P10-toolbar-options.html` の案1-B を採用）

### Context
表示モード（リスト / タイル / カレンダー）は「一度決めたらほぼ変えない」設定だが、現行モックではツールバー左端先頭・アイコン+ラベル・白カード + shadow の active（#620 で P30 / モバイルと統一した表現）と、ツールバー内で最も視覚的に強い。利用頻度と視覚的優先度が逆転している。

比較した3案:
- 案1-A: アイコンのみ化 + 縮小（位置・白カード active は維持）— 最小変更だが、左端先頭という一等地は変わらず逆転が解消しきらない。
- 案1-B: ツールバー右端へ移動 + アイコンのみ + active を ink 濃度差（非アクティブ `--color-ink-tertiary` / アクティブ `--color-ink`）で表現。白カード + shadow 廃止。
- 案1-C: segmented 廃止しドロップダウン化 — 一覧性喪失・2操作化・#620 統一の実質破棄で過剰。

### Decision
- **案1-B を採用**。segmented はツールバー右端（選択 / ビューとして保存の後ろ）へ移動し、各ボタンはアイコンのみ（32×28px、コンテナは surface トラック維持）。active は白カード + shadow をやめ、ink 濃度差で表現する。
- 読み順の一等地（ツールバー左）には保存ビュー select（「何を見るか」）を置き、操作頻度と優先度を一致させる。
- **aria 契約は維持**: `role="tablist"` / `role="tab"` / `aria-selected` に加え、アイコンのみ化に伴い各ボタンに `aria-label`（リスト / タイル / カレンダー）を必須とする（実装側に aria 契約テストあり）。`title` はホバーが存在するデスクトップ（hover 可能環境）でのみ必須とし、タッチ主体のモバイルではツールチップが機能しないため省略可（正モックもデスクトップ = aria-label + title / モバイル = aria-label のみ）。モックコメントにも注記を残す。
- **寸法**: デスクトップは 32×28px。モバイルはタッチターゲット配慮で 36×32px に拡大する（#628 ドラフトで pill-btn を 44px へ拡大したのと同系の判断）。さらに実装時は見た目のアイコン寸法を維持したまま padding 等で当たり判定を 44×44px 相当（Apple HIG 44pt）へ拡大すること。

判断根拠: 位置と装飾の両面で優先度を下げられるのは 1-B のみ。装飾（白カード + shadow）を排した静かな表現は設計原則（余白・低ノイズ）とも整合する。1-A は比較の結果、課題（一等地の占有）の根本解消にならないため不採用。

### #620 との Supersede 関係
- #620 の「表示モード segmented は白カード active で P10 / P30 / mobile P10 を統一」のうち、**active 表現と配置を本 ADR が上書き**する（Superseded by #626、表示モード系のみ）。
- **非表示モード用途の `.segmented`（P15-export / P16-export-jobs / P18-tags / mobile P15 等のフォーマット選択・並び替え軸など）は対象外**。これらは白カード active のまま変更しない。
- segmented control という部品自体の統一（pill-btn タブ群に戻さない）は #620 の決定を維持する。

### 適用範囲（P30 / mobile への追従）
- 表示モード segmented の統一は保つ方針を推奨する。ただし**本 Issue で正モックを書き換えるのは P10 系（`P10-home.html` / `mobile/P10-home.html` / `P10-home-skeleton.html`）のみ**とし、P30 等への波及（同じ ink 濃度差表現への追従）はフォローアップ Issue に委ねる。

### Consequences
- 良い点: ツールバーの視覚的階層が利用頻度と一致。装飾が減り一覧（コンテンツ）が主役になる。
- トレードオフ: 濃度差のみの active は白カードよりコントラストが弱い。`aria-selected` / `aria-label`（デスクトップは加えて `title`）で機械可読性・発見性を補完する。追従が済むまで P30 と表現が一時的に分岐する。

## ADR-002: 新規作成・アップロード CTA はヘッダーに集約し、ツールバーから削除する

### Status
Accepted（比較ドラフトの案2-a を採用）

### Context
新規作成・アップロード CTA がヘッダー（#628 ADR-003 で「アップロード = primary / 新規作成 = text」と確定）とツールバー（新規作成 = primary / アップロード = surface）の両方に存在し、primary の割り当てが逆転する矛盾もあった。

比較した3案:
- 案2-a: ヘッダー集約（ツールバーから CTA 削除）
- 案2-b: 役割分離（ヘッダー = アップロード / ツールバー = 新規作成）— #628 ADR-001 を崩し、デスクトップ / モバイルで構成が分岐するため不成立。参考提示のみ。
- 案2-c: ツールバー集約（ヘッダーから削除）— #628 ADR-001（ユーザーメニューをサイドバーへ移設してまで確保したヘッダー CTA）の全面巻き戻しで不成立。参考提示のみ。

### Decision
- **案2-a を採用**。ツールバーの新規作成 / アップロードボタンを削除し、CTA はヘッダー（アップロード = `pill-btn primary`、新規作成 = `pill-btn text`、#628 ADR-003 のまま）に一本化する。
- これにより「作成系 = ヘッダー（グローバル・常時）」「一覧操作系 = ツールバー（文脈）」と役割が一意になり、primary 序列の逆転矛盾も同時に解消される。
- ヘッダーは sticky で常時表示のため、スクロール位置によらず CTA への到達性は維持される。

判断根拠: #628 ADR-001（ヘッダーに検索 + アップロード + 新規作成を常時表示）/ ADR-003（CTA 序列）と完全整合する唯一の案。モバイル（ツールバーに CTA なし）の既存設計とも一致する。

### Consequences
- 良い点: CTA の重複と序列矛盾が消える。ツールバーが軽くなり ADR-001 の再配置（segmented 右端移動）が自然に収まる。
- 影響範囲（実装フォローアップ）: `NoteListToolbar.tsx` から CTA を撤去、`DisplayModeSwitch.tsx` のアイコンのみ化 + active 表現変更、関連 `styles.ts`。実装反映は本 Issue のスコープ外でフォローアップ Issue を起票する。

## ADR-003: 表示モード前回値の永続化は採用方向とし、実装はフォローアップ Issue とする

### Status
Proposed（方向性のみ確定、実装は本 Issue スコープ外）

### Context
表示モードが「一度決めたらほぼ変えない」設定である以上、訪問のたびにリセットされるのは ADR-001 の前提（低頻度操作）と噛み合わない。永続化（前回選択したモードの記憶）が望ましい。

### Decision
- 「前回値の永続化」は**採用方向（推奨）**とする。
- ただし #219 の loaderDeps 設計（URL パラメータと表示状態の関係）に関わるため、本 Issue では実装しない。フォローアップ Issue で永続化先（URL / ローカル永続）と loaderDeps との整合を設計の上で実装する。

## ADR-004: 保存ビューの切り替えはページ見出しをトリガーにする（ツールバーの select を廃止）

### Status
Accepted（R2 リファイン。比較は `drafts/P10-toolbar-options.html` の「R2 リファイン」セクション）

### Context
ADR-001 でツールバー左の一等地に置いた保存ビュー select に対し、「保存ビューの選択も一等地に置くほど重要ではない。見出しが『すべてのノート』なのだから、その見出し辺りから選択できる形でよいのでは」というフィードバックを受けた。見出しはすでに「いま何を見ているか（= 現在のビュー名）」を語っており、切り替えトリガーと意味が一致する。

### Decision
- ツールバーの保存ビュー select を廃止し、**ページ見出し自体をビュー切り替えのトリガー**にする。見出しには現在のビュー名（既定は「すべてのノート」、保存ビュー適用時はそのビュー名）を表示し、クリック/タップでビュー一覧（すべてのノート / 各保存ビュー）のドロップダウンが開く。
- アフォーダンスは chevron（ink-tertiary）と hover の surface のみ。select の枠・背景という chrome が消え、一等地が純粋にコンテンツの名前になる（quiet/editorial と整合）。
- a11y: トリガーは `aria-haspopup="listbox"` + `aria-expanded`、`aria-label` に現在のビュー名を含める（例: 「ビューを切り替え: 現在 すべてのノート」）。デスクトップは `title` 併記、モバイルは `aria-label` のみ（ADR-001 のデバイス別契約踏襲）。モバイルのトリガーは min-height 44px。
- 正モックは静的なため閉状態のみ。開状態は drafts の参考フレームに提示。

### Consequences
- 良い点: ツールバーから select が消え、「何を見るか」は見出し、「どう操作するか」はツールバー右群と役割が一意になる。
- トレードオフ: 見出しがインタラクティブであることの発見性は chevron 頼み。saved view の発見導線はサイドバー「保存したビュー」が並存するため致命的ではない。

## ADR-005: 「選択」「ビューとして保存」はアイコンのみにする（テキストラベル廃止）

### Status
Accepted（R2 リファイン）

### Context
ghost の二次アクションにテキストラベル（特に「ビューとして保存」が長い）が付くと、ツールバー右群の専有幅と視覚ノイズが大きい。モバイルは既にアイコンのみで成立していた。

### Decision
- デスクトップも「選択」「ビューとして保存」を **アイコンのみの `pill-btn ghost icon`（36px角）** にし、デバイス間で表現（アイコンのみ）を統一する。36px角はデスクトップのみで、モバイルは ADR-001 どおり 44px のタッチ床を維持する（サイズの統一ではない）。
- ADR-001 の契約を踏襲: `aria-label` 必須、`title` はデスクトップ（hover 環境）のみ必須・モバイルは省略。「選択」は latch 状態を持つため `aria-pressed` を維持。

### Consequences
- 良い点: 右群が軽くなり、segmented と並んだときの密度が揃う。
- トレードオフ: 初見の発見性が下がる（title / aria-label で補完）。

## ADR-006: 「すべてクリア」ボタンを廃止し、フィルターチップ列末尾の × に置き換える

### Status
Accepted（R2 リファイン）

### Context
FilterBar 右端の「すべてクリア」pill ボタンは、クリア対象（チップ群）から離れた位置にあり、pill ボタン級の強調も過剰だった。「チップの近くに × があれば足りる」というフィードバック。

### Decision
- 右寄せの「すべてクリア」pill を廃止し、**チップ列の末尾（ゴーストチップの直後）に小さな円形の ×** を置く。デスクトップ 28px（チップと同高）/ モバイル 32px。ink-tertiary、hover で surface + ink。
- フィルタが1つも適用されていないときは表示しない（実装側）。
- a11y: `aria-label="フィルタをすべてクリア"` 必須、デスクトップは `title` 併記。モバイルは見た目 32px のまま実装時に当たり判定を 44×44px 相当へ拡大する（ADR-001 と同方針）。

### Consequences
- 良い点: クリアと対象の距離が最短になり、行の右端の重い要素が消える。
- トレードオフ: × 単体は意味がアイコン頼み（aria-label / title で補完）。一括クリアの存在の発見性は下がるが、低頻度操作のため許容。

## ADR-007: 件数サブタイトルとツールバーを1行に統合する（余白は別要素で埋めない）

### Status
Accepted（R2 リファイン）

### Context
ADR-004 でツールバー左から select が消え、「見出しや件数の横が空いているので活用してもよい」というフィードバックがあった。ただしこのデザインの余白は quiet/editorial の意図的な構成要素でもある。

### Decision
- 空いた領域に新しい要素を**追加しない**。代わりに、件数サブタイトル行とツールバー行を **1行に統合**する（左 = 件数、右 = 選択 / ビュー保存 / segmented）。「埋める」のではなく「行数を減らす」ことで空きを解消し、ヘッダー〜一覧間の縦方向の chrome が1段減る。
- モバイルは同構成で `flex-wrap` を許容（320px では2行に折り返す）。
- スケルトン（`P10-home-skeleton.html`）も同レイアウト（見出し1本 + 件数ライン/アクション群の1行）に追従。

### Consequences
- 良い点: 視覚的階層は「見出し（= ビュー名）→ メタ + 操作 → フィルタ → 一覧」と1段ずつ静かに下がる構成になり、縦の密度も改善。
- トレードオフ: 件数と操作群が同一行になるため、極端に長いビュー名や狭幅では折り返しが発生する（flex-wrap で許容）。
