# 実装計画 — Issue #626: ホーム画面（P10）ヘッダー〜ツールバーのデザインモック見直し — 表示切り替えの視覚的優先度を再考

**Issue:** #626
**作成日:** 2026-06-11
**複雑度:** 中〜大規模

---

## 目的

P10（ホーム画面）ページ上部（ヘッダー〜ツールバー）のデザインモックを、(1) 利用頻度に即した視覚的優先度、(2) 新規作成・アップロード CTA の役割重複解消、の両観点で再設計した複数案を作成・比較し、方向性を確定する。確定案を正モック（デスクトップ / モバイル）へ反映する。

## スコープ

### 含まれるもの

- 比較ドラフトモック（`spec/design/pages/drafts/P10-toolbar-options.html`）の作成
- 課題1（表示切り替えの視覚的優先度）/ 課題2（CTA 重複）それぞれの複数案比較と方向性確定
- 確定内容の ADR 記録（`.issue/626/adr.md`、#620/#628 との Supersede 関係を明記）
- 正モック `spec/design/pages/P10-home.html` / `spec/design/pages/mobile/P10-home.html` への反映
- スケルトンモック `spec/design/pages/P10-home-skeleton.html` のツールバー段（`segmented-ph` 等）を確定レイアウトに追従
- モバイルモックの陳腐化コメント（「下部固定 CTA へ退避」— #628 で廃止済み、L515 と L982 の2箇所）の修正
- 必要最小限の `spec/pages/index.md` P10 文言調整（配置非依存の列挙なので原則変更不要）

### 含まれないもの

- 実装反映（`NoteListToolbar.tsx` / `DisplayModeSwitch.tsx` / `styles.ts`）— フォローアップ Issue を起票
- 表示モード前回値の永続化の実装（#219 の loaderDeps 設計に関わる）— 方向性のみ決めてフォローアップ Issue 候補へ
- P30 等、他画面 segmented の実装変更（モック上の追従方針は ADR で確定する）

## 調査結果

- `spec/design/pages/P10-home.html` — segmented スタイル: L529-552（白カード `#fff` + shadow active、アイコン+ラベル）。ツールバー: L1044-1080（右に新規作成 primary + アップロードのアイコン pill）。ヘッダー: L867-893（アップロード primary + 新規作成 text）。**ヘッダーとツールバーで CTA が重複し、primary の割り当てが逆転している矛盾あり**。
- `spec/design/pages/mobile/P10-home.html` L512-554 — モバイルは CTA 重複なしだが、#628 で廃止済みの「下部固定 CTA へ退避」コメントが残存。
- 前例ワークフロー: #628 が `drafts/P10-header-options.html`（比較）→ `P10-header-refined.html`（確定）→ ADR → 正モック反映、を確立済み。
- #628 ADR-001 で「ヘッダーに検索+アップロード+新規作成を常時表示」が確定済み → 課題2 はヘッダー集約が最も整合的。
- #620 で segmented 表現は P30・モバイルと統一されている → 表現変更時は統一範囲を ADR で確定する必要あり。なお `.segmented` クラス自体は P15-export / P16-export-jobs / P18-tags / mobile/P15 等でも別用途（フォーマット選択・並び替え軸など）で使われており、#620 統一の対象は「表示モード segmented（P10 / P30 / mobile P10）」のみ。ADR では表示モード系と非表示モード系を区別して適用範囲を記載する。
- スケルトンモック `spec/design/pages/P10-home-skeleton.html` がツールバー段（`segmented-ph` width 220px + 右側ボタン群、L685-689）を正モックからミラーしており、レイアウト変更時に追従が必要。
- Issue 本文の行番号（ヘッダー L783-807 等）は起票後のモック変更で古くなっており、本計画の行番号（L867-893 等）が現行ファイルに対して正。

## 実装ステップ

### 1. 比較ドラフト作成

- **対象ファイル:** `spec/design/pages/drafts/P10-toolbar-options.html`（新規）
- **変更内容:** #628 の `P10-header-options.html` と同形式で、課題ごとにセクション分けした比較モックを作成。デスクトップ・モバイル両幅プレビューを含める。
  - 課題1: (A) アイコンのみ化+サイズ縮小（白カード active 維持）、(B) ツールバー右端へ移動+アイコンのみ+active を ink 濃度差で表現（白カード+shadow 廃止）、(C) segmented 廃止しドロップダウン/トグル的な設定位置へ退避
  - 課題2: (a) ヘッダー集約（ツールバーから CTA 削除）を基本線として提示、(b) 役割分離（ヘッダー=グローバル / ツールバー=文脈作成）と (c) ツールバー集約は簡略な参考提示に留める（(b)(c) とも #628 ADR-001/003・`NoteListToolbar.tsx` のモバイル設計と衝突し成立余地が狭いため）
  - 各案に利点/欠点コメント。トークンは `tokens.md` 準拠、新トークン追加なし。
- **理由:** 複数案の比較・方向性確定が Issue のゴール。

### 2. 比較・方向性確定

- **変更内容:** 比較モックをもとに課題1・課題2 の採用案を確定。「前回値の永続化」は採否のみ判断しフォローアップ候補として整理。確定案が比較案から修正を伴う場合は `drafts/P10-toolbar-refined.html` として清書する（#628 の `P10-header-refined.html` 相当）。案をそのまま採用する場合は省略可。
- **理由:** Issue ゴールの「方向性を確定する」に対応。

### 3. ADR 記録

- **対象ファイル:** `.issue/626/adr.md`（新規）
- **変更内容:** 採用案と理由、#620（segmented 統一）・#628（ヘッダー CTA 構成）との Supersede / 整合関係、segmented 表現変更の適用範囲（P10 のみ or 全画面）を記録。
- **理由:** デザイン判断のトレーサビリティ確保（前例踏襲）。

### 4. 正モック反映

- **対象ファイル:** `spec/design/pages/P10-home.html`、`spec/design/pages/mobile/P10-home.html`、`spec/design/pages/P10-home-skeleton.html`、必要に応じて `drafts/P10-toolbar-refined.html`
- **変更内容:** 確定案を反映。`.segmented` スタイル（L529-552）、toolbar マークアップ（L1044-1080）、ヘッダー CTA 序列矛盾（L867-893、正は #628 ADR-003 = アップロード primary / 新規作成 text）を解消。スケルトンモックのツールバー段プレースホルダーを確定レイアウトへ追従。モバイルの陳腐化コメント（L515 / L982 の2箇所）修正。モック内コメントに #626 と決定理由を記載。
- **理由:** 確定した方向性を SSOT であるモックに反映する。

### 5. 仕様・フォローアップ整理

- **対象ファイル:** `spec/pages/index.md`（必要時のみ最小修正）
- **変更内容:** P10 の機能列挙は配置非依存なので原則変更不要。集約で文言調整が必要な場合のみ最小修正。実装反映・永続化はフォローアップ Issue を起票。
- **理由:** Issue 明記のスコープ（モック見直しが主）。

## 設計判断

- #628 のワークフロー（drafts 比較 → 確定 → ADR → 正モック反映）を再利用する。
- 課題2 の基本線はヘッダー集約（#628 ADR-001 と整合）。
- segmented の active 表現変更は #620 の「P30・モバイルと統一」決定の上書きになるため、適用範囲を ADR で明示する。
- ヘッダー / ツールバーの primary 序列矛盾は集約時に必ず解消する。

詳細は `.issue/626/adr.md` を参照。

## リスクと注意点

- segmented 表現の変更が P10 のみだと #620 の統一が崩れる。変更範囲を ADR で確定し、P30・モバイル各モックの segmented 使用箇所を洗うこと。
- アイコンのみ化する場合は `aria-label` / `role="tablist"` 契約をモックコメントに残す（実装側に aria 契約テストあり）。
- 「前回値の永続化」は #219 の loaderDeps 設計に関わるため本 Issue では方向性のみ。
