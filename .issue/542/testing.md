## 確認環境

このIssueはフロントエンドの見た目・体験（ゴミ箱 / タグ管理 / 公開設定）をデザインモックに追従させる変更。実機確認はローカル開発サーバで行う。

### 検証環境の起動

```
pnpm db:apply:local
pnpm dev
```

`pnpm db:apply:local`（= `wrangler d1 migrations apply hollow-local-d1 --local`）でローカル D1 にマイグレーションを適用後、`pnpm dev`（`vite dev`、Cloudflare ランタイム）でローカルサーバを起動する。表示された URL をブラウザで開き、ログイン済みユーザーで確認する。

確認には少なくとも以下のデータを持つユーザーが必要:
- **ゴミ箱（P17）**: ゴミ箱に複数のノート（タイトルあり/長め・抜粋あり・削除日が異なるもの）
- **タグ管理（P18）**: 複数のタグ（件数の異なるもの、統合候補が複数あるもの・候補ゼロのものを含む）、タグ付きノート
- **公開設定（P14）**: 公開/限定公開/非公開のノート、限定公開リンクを発行済み（最終アクセスありのもの・未アクセスのものを含む）

開発用 admin ユーザーは `pnpm seed:dev-admin` で投入できる。追加のシードは `pnpm db:execute:local <SQLファイル>` で流せる（manual-test スキルが seed を準備する）。

### デプロイ方法

なし（検証環境のみで確認できる。ステージング反映が必要な場合は `pnpm deploy:staging`）。

## 確認項目

### 1. P17 ゴミ箱 — 保存期間案内カード

- **目的:** 保存期間案内が独立カード（`role="note"`）として表示されるか。
- **手順:**
  1. ログインしてゴミ箱（`/trash`）を開く。
  2. ページタイトル下のサブタイトルと、その下の案内カードを見る。
- **期待結果:** サブタイトルは「{件数} 件のノートがゴミ箱にあります。」のみ。その下に surface 背景の案内カード（時計アイコン + 太字導入文「保存期間を過ぎた…」+ 補足）が出る。
- **確認ポイント:** モック `P17-trash.html` の `.retention-note` と並べて目視。寸法・色がトークン由来か（リテラル px の浮きがないか）。

### 2. P17 ゴミ箱 — 完全削除の確認ダイアログ（赤アラート）

- **目的:** 完全削除確認に削除対象名の赤アラート + 取消不可文が出るか。
- **手順:**
  1. ゴミ箱で任意ノートの「完全に削除」を押す。
  2. 開いた確認ダイアログを見る。
  3. キャンセル / 完全に削除を試す。
- **期待結果:** ダイアログ内に `ALERT_ERROR`（赤枠 + アイコン + 「削除対象」+ 対象ノート名）が表示され、本文に「この操作は取り消せません。」が太字で出る。見出し横に warning アイコンの二重表示が無い。「完全に削除」で実際に削除される。
- **確認ポイント:** モックの確認ダイアログと突合。対象名が正しく出るか。

### 3. P17 ゴミ箱 — 復元

- **目的:** 復元が従来どおり動くか（回帰確認）。
- **手順:** 任意ノートの「復元」を押す。
- **期待結果:** ノートが元のディレクトリに戻り、一覧から消える。

### 4. P18 タグ管理 — 行アクションの hover/focus 表示と狭幅ケバブ

- **目的:** アクションが hover/focus で出現し、狭幅でケバブに畳まれるか。
- **手順:**
  1. タグ管理（`/tags`）を広いウィンドウ（≥1024px）で開く。
  2. タグ行にマウスを乗せる / キーボードで行内をフォーカスする。
  3. ウィンドウを 1023px 未満に狭める。
  4. さらに 639px 未満に狭める。
- **期待結果:** ≥1024px ではアクション（リネーム/統合/削除）が hover/focus で出現。1023px 未満ではアクション列と件数（`tag-count`）が隠れ、ケバブ（`...`）メニューが出る。ケバブからリネーム/統合/削除が選べ、削除は error 表示。統合は候補ゼロのタグでは項目が出ない。639px 未満でケバブのタップターゲットが 44px 確保される。
- **確認ポイント:** モック `P18-tags.html` の `max-width:1023px` / `max-width:639px` 挙動と突合。

### 5. P18 タグ管理 — ボタンのサイズ/バリアント

- **目的:** リネーム/統合が小型ボタン、削除が ghost-danger か。
- **手順:** 広い画面でタグ行アクションを目視。
- **期待結果:** リネーム/統合は `btn-xs` 密度の小型 surface ボタン。削除は transparent で hover 時のみ error 色（常時赤塗りでない）。

### 6. P18 タグ管理 — inline rename ブロック

- **目的:** 編集時にコンテキスト見出し + accent-surface 背景が出るか。
- **手順:**
  1. 任意タグの「リネーム」を押す。
  2. 編集ブロックを見る。
  3. 名前を変えて保存 / キャンセルを試す。
- **期待結果:** input の上に「#{name} をリネーム（{件数} 件のノートに反映）」の見出しが出る。編集UI領域が accent-surface 背景になる。保存で名前が更新され（楽観反映）、キャンセルで元に戻る。
- **確認ポイント:** モックの `.tag-editing-block` と突合。`useOptimistic` の表示が崩れないか。

### 7. P18 タグ管理 — 統合ダイアログ（回帰確認）

- **目的:** 既存マージダイアログが従来どおり動くか（本Issueでは変更なし）。
- **手順:** タグの「統合」を押し、統合先を選んで実行する。
- **期待結果:** モック `P18-merge-tag-dialog.html` 相当（統合先 select・「対象ノート: N 件」・実行中 progressbar・disabled）が従来どおり機能する。

### 8. P14 公開設定 — ラジオ説明文と公開時URL

- **目的:** ラジオに説明文、public 選択時に公開URLプレビューが出るか。
- **手順:**
  1. 任意ノートの詳細から公開設定モーダルを開く。
  2. 非公開/限定公開/公開の各ラジオを見る。
  3. 「公開」を選択する。
- **期待結果:** 各ラジオに説明文（モック文言）が出る。「公開」選択時に「公開時の URL」見出し + 算出URL（`/u/<username>/<slug>`）が表示される。
- **確認ポイント:** モック `P14-publish-settings.html` と突合（URL のパス形式は実装値でよい）。

### 9. P14 公開設定 — 限定公開リンクの link-card

- **目的:** link-card レイアウト・最終アクセス・コピーが出るか。
- **手順:**
  1. 限定公開リンクを発行済みの状態で公開設定を開く。
  2. 発行済みリンク行を見る。
  3. コピーボタンを押す。
- **期待結果:** head 行に有効チップ + 最終アクセス（`lastAccessedAt` が非 null のときのみ、`ml-auto` で右寄せ）、その下に URL 行 + コピーボタン。コピーで URL がクリップボードに入る。未アクセスのリンクは最終アクセスが出ない。

## エッジケース・異常系

### 1. ゴミ箱が空 / タグが無い

- **目的:** 空状態が崩れないか。
- **手順:** ゴミ箱を空・タグ0件のユーザーで各画面を開く。
- **期待結果:** 既存の空状態表示が出る。retention カードや行アクションの追加で空状態が壊れていない。

### 2. ConfirmDialog の他呼び出しの回帰

- **目的:** `subject` 未指定の確認ダイアログ（discard 系など）が従来の見た目のままか。
- **手順:** タグ削除以外で ConfirmDialog を使う動線（編集破棄など）を開く。
- **期待結果:** `subject` 未指定なので赤アラートが出ず、従来の warning アイコン + プレーン文のまま。

## 既存機能への影響確認

- **ConfirmDialog 共有変更**: trash purge / tag delete / discard 系すべてで挙動・見た目を確認（`subject` 指定の有無で分岐が正しいか）。
