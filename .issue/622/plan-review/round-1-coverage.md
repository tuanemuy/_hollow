## スコープ整合性

「含まれないもの」5 項目はいずれも妥当（#621 既対応、Issue 明記の対象外、Issue 乖離リスト外、`dangerouslySetInnerHTML` 領域、P30/P32 側無変更）。スコープ外の作業（ルート追加、検索ページ改修、新規 CSS）は計画に紛れ込んでいない。ADR-001 の選択肢 2 を退けた理由付けも、Issue の「要判断」という指示の範囲内の決定であり越権はない。

#### 問題点（要修正）

問題点ゼロ。

#### 改善提案（検討推奨）

- **[S-001]** リスク欄の「タグ 0 件時の日付位置（`ml-auto` 付与）は実装時の判断に委ねる」を、計画段階でどちらかに確定しておく
  - 理由: AC-1 は「タグ左・日付右」を検証可能な基準として掲げているが、タグ 0 件時の挙動が未決のままだと、実装者と検証者で AC-1 の解釈（日付が左寄せでも合格か）が割れうる。`justify-between` の単一子は左寄せになるため、「日付は常に右」を意図するなら `ml-auto` を基準に含め、許容するなら AC-1 に「タグ 0 件時は対象外」と一言添えるだけで曖昧さが消える。
- **[S-002]** ADR-001 の Status を実装着手前に `Accepted` へ更新する手順をステップ 5 か計画末尾に明記する
  - 理由: 計画本文は ADR-001 を確定事項として参照している（AC-3 の由来）一方、adr.md は `Proposed` のまま。形式上の不整合が残ると、後続レビューで「方針未確定」と誤読される。

#### 良い点

- 受け入れ基準表が「基準・由来・対応ステップ」の 3 列で、Issue の完了条件 4 項目と微差テーブル 3 行がすべて 1:1 でトレースできる。紐づけの誤りもない。
- Issue 本文（末尾メタもリンク）とモック（末尾メタは span）の食い違いを実ファイル精査で発見し、モックを正とする判断を AC-4 として明文化・ADR に記録している。Issue を鵜呑みにせず一次資料で検証した点が優秀。
- 各 AC が具体的なユーティリティ・px 値・遷移先 URL まで書かれており、DevTools / ユニットテストで機械的に検証可能。テスト方針のブラウザ確認手順も AC-1〜AC-7 を網羅している。
- bottom-meta の font-size（モック 13px リテラル vs `text-sm`）を「Issue の乖離リスト外かつ実質一致」として明示的にスコープ外へ置くなど、暗黙の判断を残していない。
- タグリンクのテスト追加（メタ行は `<a>`、末尾メタは非リンク）が AC-3/AC-4 の回帰防止として正しく計画されている。
