# ADR — Issue #622: ユーザー公開ノート詳細（P31）をデザインモックに一致させる

## ADR-001: メタ行タグのリンク先を著者公開トップ（`/u/$username?tags=[...]`）にする

### Status
Accepted

### Context

モック（`spec/design/pages/P31-public-note.html`）ではメタ行のタグが `<a class="tag" href="#">` でリンクだが、href はプレースホルダで遷移先の指定が無い。実装はリンク先を決める必要がある。選択肢:

1. **著者公開トップのタグフィルタ** `/u/$username?tags=["タグ名"]` — P30 の `validateSearch` に `tags`（AND フィルタ）が既存
2. **グローバル公開検索** `/search?tags=["タグ名"]` — P32 にも `tags` パラメータが既存。ただし `q`（キーワード）を主とする検索ページで、タグのみの遷移は「空キーワード検索」の体験になる
3. **リンク化しない（モック側を span に調整）** — 導線が増えないが、Issue が問題視する「タグから辿る導線が無い」が解消されない

なお末尾メタ（bottom-meta）のタグはモック自体が `<span class="tag">`（687-689行）でリンクではない。Issue 本文は末尾メタもリンクと記載しているがモックと食い違うため、モックを正として末尾メタは span のまま維持する。

### Decision

選択肢 1（著者公開トップのタグフィルタ）を採用する。

- P31 のタグは「この著者がこのノートに付けたタグ」であり、文脈上の自然な問いは「この著者の同タグのノート」。著者スコープの P30 フィルタがそれに直接答える。
- P30 には既にタグフィルタの UI（チップ）と URL スキーマがあり、遷移先でアクティブなタグチップが視覚的に確認できる。ルート追加・スキーマ変更が一切不要。
- `/search?tags=...` はキーワード未入力の検索結果という中途半端な状態に着地する上、著者文脈が失われる（`username` も併せて渡せば絞れるが、それは実質 P30 フィルタの再発明になる）。

### Consequences

- 良い点: 既存ルート・既存スキーマのみで完結し、変更は `<span>` → `<Link>` の置き換えだけ。型安全（`search={{ tags: [t] }}` が P30 の zod スキーマに対応）。
- トレードオフ: 「全ユーザー横断で同タグを探す」導線にはならない。グローバルなタグ探索が必要になったら P32 側にタグ起点の体験を設計した上でリンク先を切り替える余地を残す。
