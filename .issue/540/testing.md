## 確認環境

このIssueはフロントエンドの見た目（SHELL サイドバー / 一覧 / 詳細 / エディタ / 保存ビュー）をデザインモックに追従させる変更。実機確認はローカル開発サーバで行う。

### 検証環境の起動

```
pnpm dev
```

`vite dev`（Cloudflare ランタイム）でローカルサーバが起動する。表示された URL をブラウザで開き、ログイン済みのユーザーで領域1の各画面を確認する。確認には少なくとも以下のデータを持つユーザーが必要:
- 複数のノート（公開/限定公開/非公開が混在、タグ付き、ディレクトリ配下のもの含む）
- 複数のディレクトリ（階層あり）
- 複数の保存ビュー（個人ビュー / 共有ビュー、壊れた条件を持つものを含む）
- 内部リンク（`[[...]]`）とバックリンクを持つノート

### デプロイ方法

なし（検証環境のみで確認できる。ステージング反映が必要な場合は `pnpm deploy:staging`）。

## 確認項目

### 1. SHELL サイドバー — 件数バッジと保存ビュー列挙

- **目的:** A-1 / A-2 の追従が正しく表示されるか。
- **手順:**
  1. ログインしてホーム（`/`）を開く。
  2. 左サイドバー `ライブラリ > すべてのノート` を見る。
  3. `保存したビュー` セクションを見る。
  4. ノート詳細（任意ノート）/ エディタ（`/notes/new`）でも同じサイドバーが出ることを確認。
- **期待結果:** 「すべてのノート」の右端にアクティブノート件数バッジ（`text-ink-tertiary`・小サイズ）が出る。「保存したビュー」セクションに個人ビューが列挙され、クリックで該当ビューが一覧に適用される（`/?viewId=...`）。
- **確認ポイント:** モック `P10-home.html` の `.count` / `保存したビュー` 配置と並べて目視。件数が実データと一致しているか。サイドバー描画で重複 fetch や明らかな遅延がないか。

### 2. P10 一覧 — FilterBar の境界・チップ

- **目的:** B-1 の FilterBar 帯がモック（余白区切り・下線なし・左端揃え）になっているか。
- **手順:**
  1. ホームで FilterBar（タグチップ・期間・公開状態・内部リンク参照・すべてクリア）を見る。
  2. タグチップを ON/OFF、期間/公開状態ポップオーバーを開閉、内部リンク参照を選択。
- **期待結果:** FilterBar に下線（border-bottom）が無く、下マージン（余白）でリストと区切られる。先頭チップの左端が見出し・ツールバーと揃う。note-list 先頭行との二重線が無い。フィルタ操作は従来どおり機能する。
- **確認ポイント:** `P10-home.html` の `.filter-bar`（padding:0 / margin-bottom:--space-5）と一致。チップ件数バッジ・active 反転（ink/white）が維持。

### 3. P11 詳細 — メタ順序とバックリンク

- **目的:** C-1 / C-2 のメタブロック順序・項目が正しいか。
- **手順:**
  1. バックリンクを持つノートの詳細（`/notes/$noteId`）を開く。
  2. 本文の下のセクションを上から確認。
- **期待結果:** 本文下に **プロパティ（作成日 / 更新日 / 公開日 / **場所** / タグ / 元ファイル等）→ バックリンク** の順で表示される。**場所行（ディレクトリパス、`/` 区切り）がメタブロックに 1 箇所だけ表示される**（index.md §2.1 + モック準拠、ADR-002）。公開状態はメタブロックに追加されず、トップの公開設定ピル（#459）にのみ存在する。バックリンクカードは title（+ メタ行があれば）+ snippet。
- **確認ポイント:** 場所行がメタに 1 箇所だけ出ているか（breadcrumb と併存するが右メタレール二重化ではない）。公開状態がメタに二重表示されていないか。順序がモック準拠か。

### 4. P12 エディタ — タイトル document 化と topbar

- **目的:** D-1 / D-2 の追従。
- **手順:**
  1. `/notes/new`（新規）と既存ノートの編集（`/notes/$noteId/edit`）を開く。
  2. タイトル入力、モード切替（HTML / WYSIWYG / インライン / FrontMatter）、保存/キャンセルを操作。
- **期待結果:** タイトルが borderless 大型（text-3xl 相当）の document スタイル入力で、placeholder「無題のノート」相当が出る。モードタブ + autosave 表示 + 主アクションが topbar として整理されている。autosave / 編集ロック / モード切替の挙動は従来どおり（dirty 確認ダイアログ含む）。
- **確認ポイント:** `P12-editor.html` の `.title-input` / `.editor-topbar` と並べて確認。フォーカス枠線・余白の作り込み（#522）やタグ chip 化（対象外）に踏み込んでいないか。状態モデルの回帰がないか。

### 5. P20 保存ビュー — 条件 chip 列挙

- **目的:** E-1 のビューカード条件 chip 列挙。
- **手順:**
  1. `/views` を開く。
  2. 各ビューカードの chip 行を確認。壊れた条件を持つビューも確認。
- **期待結果:** 表示モード chip に加えて、ビューの絞り込み条件（タグ `#name` / 期間 / 公開状態 / ソート / ディレクトリ）が chip で列挙される。壊れた条件は broken chip + バナーで示される。適用/編集/名前変更/複製/既定/削除アクションが従来どおり動く。
- **確認ポイント:** `P20-views.html` の `.view-chips` と並べて確認。chip ラベルが実データと一致。新規 px トークンを足していないか。

## エッジケース・異常系

### 1. 保存ビュー 0 件 / ノート 0 件

- **目的:** 件数バッジ・保存ビュー列挙の空状態。
- **手順:** 保存ビューが無い、あるいはノートが無いユーザーで `/` を開く。
- **期待結果:** 件数バッジが `0` を表示。保存したビューセクションが空でも崩れない（セクション非表示 or 空文言）。一覧の空状態（既存の破線枠 EMPTY_STATE）が出る。

### 2. 壊れた条件を持つ保存ビュー

- **目的:** broken chip / バナーがモック準拠か。
- **手順:** 削除済みタグ/ディレクトリを参照するビューを `/views` で開く。
- **期待結果:** broken chip + 警告バナー + 修復ボタンが出る（ADR-004 に従い `.alert` 案D 化の有無は実装方針どおり）。修復が機能する。

### 3. モバイル幅（drawer）

- **目的:** サイドバー変更が drawer でも崩れないか。
- **手順:** ビューポートを `<1024px` にしてハンバーガーから drawer を開く。
- **期待結果:** 件数バッジ・保存ビュー列挙が drawer 内でも正しく出る。フォーカストラップ・Escape クローズが従来どおり。
