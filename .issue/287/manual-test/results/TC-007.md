## フォローアップ判断材料（重要な観察事項）

td への 1 文字入力で発動した rollback は **セル単体ではなくエディタ全体を「最後の rebuild 時点の snapshot」まで巻き戻した**。

観察された事実経過:

1. TC-004 で通常段落・li 内 p・blockquote 内 p・pre に入力（`追記OK` / `LI追記` / `BQ追記` / `line2`）→ 自動保存成功（「保存しました」表示、＝サーバー側にも保存済み）
2. その後 `<td><br></td>` に `X` を 1 文字入力 → rollback 発動
3. rollback により **エディタ DOM 全体が初回 rebuild 時点（ページロード時）の内容に復元**され、手順 1 の入力済みテキストが DOM から全て消失
4. さらにその後、空段落へ `Y` を入力 → 自動保存が発火し、**巻き戻り後の本文（手順 1 の編集を含まない）で上書き保存**された。最終的な保存内容は「初期本文 + Y」となり、**一度「保存しました」まで到達していた編集（`追記OK` 等）がサイレントに失われた**

評価:

- td セル自体については「従来（#287 以前は decorate 対象外＝そもそも編集不可）からの悪化ではない」— testing.md の許容基準内
- ただし #287 で td が編集可能になったことで、「空セルに 1 文字打つ」というごく自然な操作が snapshot 全体巻き戻し（＝rebuild 以降の全入力の消失、後続 emit による保存済み内容の上書き）の新しいトリガーになった。これは plan.md リスク欄／testing.md エッジケース 2 が懸念していた「snapshot 追従」問題の実害シナリオに該当するため、**フォローアップ Issue 化を推奨**（候補対策: rollback 粒度の局所化、または rebuild 後 snapshot の入力追従、または `<br>` プレースホルダ除去 mutation の許容）
