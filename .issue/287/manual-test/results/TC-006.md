# TC-006: `<img>` をクリック選択して文字入力

**結果**: PASS
**実行時間**: 60
**セッション**: verify-tc-001

## 実行ログ

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| 1 | ビジュアルタブで `<img>` をクリックして選択 | 画像が選択状態になる | クリックでは collapsed キャレットがテキストノードに置かれ選択にならず（テスト画像が 8x8px と極小のため）。Selection API `range.selectNode(img)` で img 選択状態を作成（`selectedIsImg: true, collapsed: false`） | PASS（代替手段） |
| 2 | そのまま文字 `Z` を入力 | 画像は消えず復元される（入力は巻き戻る — 既知のトレードオフ） | `<img>` は復元され存続。`Z` は DOM に残らず巻き戻り。構造は `<p contenteditable="true">before<img src="/media/019f4ff8-...>after</p>` で入力前と完全一致 | PASS |
| 3 | エディタが以降も操作可能か確認 | 操作可能 | 巻き戻り後に段落末尾へ `OK` を入力 → 即時残存（`afterOK`）。Backspace ×2 で正常に削除。以降の編集に支障なし | PASS |

## 観察された実挙動

- ブラウザによる「選択中 img の入力文字への置換」（Element remove を含む mutation）は rollback により完全に復元され、画像参照（`/media/<id>`）は失われない。
- 巻き戻り範囲は入力した 1 文字（`Z`）のみ。TC-005 と異なり選択置換の直前に未 rebuild の入力が無かったため、道連れ消失は観察されず。
- 全 decorate ブロック（P×2 + P[has img]）の状態も入力前と同一で、構造破壊なし。

## 備考

- クリックによる img 選択が成立しなかったのはテスト画像サイズ（8x8px）に起因する操作上の都合であり、「選択された img が入力で置換されそうになる」というテスト対象のシナリオ自体は Selection API で忠実に再現できている。
