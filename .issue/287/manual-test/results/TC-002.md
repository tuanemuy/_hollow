# TC-002: 画像前後へのテキスト入力が rollback されず保存される

**結果**: PASS
**実行時間**: 64
**セッション**: verify-tc-001

## 実行ログ

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| 1 | `<p><img></p>` 先頭（Home）にキャレットを置き `before` を入力 | 文字が巻き戻らず残る | `<p contenteditable="true">before<img ...></p>` — 即時残存、巻き戻りなし | PASS |
| 2 | 画像直後にキャレットを置き `after` を入力 | 文字が巻き戻らず残る | `<p contenteditable="true">before<img ...>after</p>` — 即時残存、巻き戻りなし | PASS |
| 3 | 画像の位置・存在を確認 | 画像が消えたり移動したりしない | `<img src="/media/019f4ff8-...>` は before と after の間に維持、ロード成功（naturalWidth > 0） | PASS |
| 4 | 保存ステータスを観察 | 「保存中... → 保存済み」に遷移（自動保存発火） | 自動保存が発火し「保存しました」表示に到達（実際の文言は「保存しました」。中間状態はポーリング間隔の都合で捕捉できず） | PASS |
| 5 | IME（かな漢字変換）入力での巻き戻りなし確認 | 巻き戻らない | **SKIP** — agent-browser では IME 変換・確定イベントを再現できないため未実施 | SKIP |

## 備考

- 操作上の注記（プロダクトの不具合ではない）: `press End` でのキャレット移動は Chromium の挙動として行末 = テキストノード末尾（img の**手前**）に置かれ、入力が img の前に入った。テストではいったん Backspace で取り消し、Selection API で `setStartAfter(img)` によりキャレットを img 直後に置き直して `after` を入力した。いずれの経路でも rollback は一切発生していない。
- テキストノードへの Backspace 削除（Element remove を含まない mutation）も巻き戻されず正常に動作した。
- IME 確認は agent-browser の制約でスキップ。必要なら人手での確認が別途要る。
