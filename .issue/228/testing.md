
```bash

```

### デプロイ方法

本 Issue の確認はローカル検証環境（`pnpm dev`）で完結する。ステージング反映が必要な場合のみ、マイグレーション適用（`pnpm db:apply:staging`）の後に `pnpm deploy:staging`。

## 確認項目

### 1. カスタムプロンプト入力 UI の表示

- **目的:** アップロードモーダルに「詳細オプション」アコーディオンが表示され、structure / metadata のテキストエリアが畳まれた状態で提供されること。
- **手順:**
  1. ログインして任意の画面からアップロードモーダルを開く
  2. 選択ビュー（ドロップゾーン）に「詳細オプション」などのアコーディオンがあることを確認
  3. アコーディオンを展開し、structure 用・metadata 用の2つのテキストエリアが表示されることを確認
- **期待結果:** 普段は畳まれており、展開すると2つの任意入力欄が現れる。
- **確認ポイント:** 既定で畳まれていて普段使いの邪魔をしないこと。

### 2. カスタムプロンプトの上書きが効く（LLM 経由種別）

- **目的:** 入力したカスタムプロンプトがそのジョブの LLM 処理に反映されること。
- **手順:**
  1. アコーディオンを展開し、structure / metadata のテキストエリアに識別しやすいプロンプト（例: 「すべて箇条書きで構造化して」「タグは必ず3つ提案して」）を入力
  2. **LLM 構造化が走る種別**（Office / PDF / 画像 / 音声 / プレーンテキスト）のファイルを選択してアップロード
  3. previewing まで進むのを待つ
- **期待結果:** 生成されたタイトル・本文・メタデータ提案に、入力したプロンプトの意図が反映されている。
- **確認ポイント:** override 入力時はユーザーデフォルトではなく override の内容が優先されること。

### 3. 空入力時のフォールバック

- **目的:** カスタムプロンプト未入力（または空文字）の場合、従来どおりユーザー設定／システムデフォルトの resolver にフォールバックすること。
- **手順:**
  1. アコーディオンを展開せず（または空のまま）ファイルをアップロード
  2. previewing まで進むのを待つ
- **期待結果:** 従来どおりの結果が得られる（resolver のデフォルトプロンプトで処理）。
- **確認ポイント:** 空入力がエラーにならず自然にフォールバックすること。

### 4. 複数ファイル一括時の全件適用

- **目的:** 複数ファイル選択時、入力した override が一括分の全ファイルに適用されること。
- **手順:**
  1. アコーディオンを展開し override を入力
  2. 複数ファイルを同時に選択してアップロード
  3. キュー画面（`/upload`）で各ジョブの結果を確認
- **期待結果:** 全ファイルのジョブに同じ override が適用された結果になる。
- **確認ポイント:** 一部だけ適用されるなどの取りこぼしがないこと。

### 5. 再生成時の override 保持

- **目的:** previewing → 再生成（regenerate）したとき、同じ override で再実行されること。
- **手順:**
  1. override を入力して LLM 経由種別をアップロードし previewing に到達
  2. プレビュー編集画面で「再生成」を実行
  3. 再度 previewing に戻るのを待つ
- **期待結果:** 初回と同じ override の意図が反映された結果になる（override が消えない）。
- **確認ポイント:** 再生成で override が失われないこと。

## エッジケース・異常系

### 1. 過大なプロンプト入力

- **目的:** 16 KiB を超える巨大なプロンプトを弾けること。
- **手順:**
  1. structure / metadata のテキストエリアに 16 KiB を超える長文を貼り付けてアップロード
- **期待結果:** バリデーションエラーが表示され、ジョブが不正な状態にならない（transport / VO の2点で弾かれる）。

### 2. structure override の種別依存（既知の制約）

- **目的:** html / markdown 種別では structure override が無視され、metadata override のみ効く挙動を確認。
- **手順:**
  1. structure / metadata 両方に override を入力
  2. `.html` または `.md` ファイルをアップロードし previewing に到達
- **期待結果:** タイトル・本文には structure override の効果が出ない（sanitizer / markdown 変換のため）一方、メタデータ提案には metadata override が反映される。
- **確認ポイント:** これは仕様上の既知の制約（plan.md「既知の仕様上の制約」参照）。

## 既存機能への影響確認

- **通常アップロード（override なし）**: 既存のアップロード〜プレビュー〜保存フローが従来どおり動くこと。
- **管理者リトライ / 再生成**: 既存の失敗リトライ・再生成が override 列の追加で壊れていないこと。
- **キュー画面（/upload）**: ジョブ一覧表示が新カラム追加後も正常に動くこと。
