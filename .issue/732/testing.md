# 動作確認計画 — Issue #732: セッション失効の leaf 観測時（useAuthGuardEffect）に未認証 UI が 1 フレーム見える

**Issue:** #732
**作成日:** 2026-06-14

---

## 確認環境

このIssueの変更はフロントエンドのルーター制御（`useAuthGuardEffect` の戻り値拡張と `HomeRoute` のレンダリングガード）のみ。検証は開発サーバーで、認証状態を実際に失効させて目視で行う。ちらつきは 1 フレームの瞬間表示なので、**ブラウザのネットワークスロットリング（Slow 3G 等）や DevTools の遅延を使うと観測しやすい**。

### 検証環境の起動

```bash
pnpm dev
```

（初回やスキーマが古い場合は `pnpm db:migrate` でローカル D1 にマイグレーションを適用。ログイン用の管理者ユーザーは `pnpm seed:dev-admin` でシードする。）

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. セッション失効を leaf で観測したとき未認証 UI が 1 フレームも見えない

- **対応する受け入れ基準:** AC-1 / AC-5
- **目的:** ログイン済み状態で session cookie が失効した後に `/`（`_app/index.tsx`）を再評価したとき、`LandingPage`（未認証 UI）が 1 フレームも描画されず、最終的に `LandingPage` に収束すること。
- **手順:**
  1. シードした管理者でログインし、認証済みの `/`（ホーム）を表示する。
  2. DevTools のネットワークを Slow 3G に絞る（過渡フレームを観測しやすくするため）。
  3. DevTools の Application → Cookies から session cookie を手動削除する（セッション失効を再現）。
  4. SPA 遷移で `_app` 配下の別ルート（例 `/notes`）→ `/` へ戻る、または `/` 上で再評価が走る操作（リンク再クリック等）を行い、leaf が `authenticated: false` を観測する状態を作る。
- **期待結果:** 失効観測の瞬間に未認証ランディング（ヒーロー領域・未認証トップ）が一瞬たりとも描画されず（過渡フレームは無表示＝中立）、AppShell 再評価後に `LandingPage` へ収束する。
- **確認ポイント:** 過渡フレームで未認証ランディングの白〜ヒーロー領域がフラッシュしないこと。最終的に未認証ランディングへ正しく収束すること。前ユーザーの chrome（Header/Sidebar）が一瞬残るのは AppShell 再評価待ちの想定挙動で「未認証 UI の露出」とは別物。

### 2. fresh 未認証訪問者では `LandingPage` が即座に表示される（誤抑制しない）

- **対応する受け入れ基準:** AC-2
- **目的:** 一度もログインしていない（shell キャッシュも null）状態で `/` を初訪問したとき、レンダリングガードが初回描画を誤抑制せず `LandingPage` が即表示されること。
- **手順:**
  1. ログアウト状態（cookie 無し）で、新しいタブ/シークレットウィンドウで `/` を直接開く。
- **期待結果:** `LandingPage`（未認証トップ）が即座に表示される。無表示の過渡フレームや空白が挟まらない。
- **確認ポイント:** 最重要。ガード条件が hook の発火条件とズレると fresh 未認証で `LandingPage` が抑制される。ここで未認証トップが正常に出ることを必ず確認する。

### 3. 認証済みの通常表示が変わらない

- **対応する受け入れ基準:** AC-3
- **目的:** ログイン済みで `/` を表示したとき、HomePage が従来どおり描画され、余計な再評価・抑制・点滅が起きないこと。
- **手順:**
  1. シードした管理者でログインし、`/` を表示する。
  2. `/notes` など別ルートへ遷移して `/` に戻る。
- **期待結果:** HomePage が変わらず表示される。無表示フレームや余計なローディングが挟まらない。

## エッジケース・異常系

### 1. RPC 回数（`staleTime: Infinity` 維持）

- **対応する受け入れ基準:** AC-4(b)
- **目的:** レンダリングガード追加が `_app.loader`（`staleTime: Infinity`）の「初回 1 RPC、以降 0 RPC」を regression させないこと。
- **手順:**
  1. DevTools の Network タブを開く（XHR/fetch でフィルタ）。
  2. fresh 未認証で `/` を初訪問する。
  3. 認証済みでログイン後に `/` ↔ `/notes` を数回往復する。
- **期待結果:** `_app.loader` 相当の server fn 呼び出しが初回 1 回のみで、表示系の SPA 遷移では追加されない（認証状態が変わる失効観測時のみ再評価が走る）。本変更で RPC 回数が増えていないこと。

## 既存機能への影響確認

- **ログイン/ログアウト/退会の遷移（#728/#731）:** `clearAppShellCache → navigate` 系の auth 遷移は本変更の対象外（`appShellInvalidate` の挙動は不変）。ログイン・ログアウトでランディングが挟まらない挙動が引き続き維持されることを確認する。
- **errorComponent retry（#300 ADR-003）:** `appShellInvalidate` を共有するが本変更で挙動は変わらない。`_app` のエラー → 再読み込み動線が従来どおり動くことを確認する。
