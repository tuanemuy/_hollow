## 確認項目

### 1. P23 ユーザー向けカスタムプロンプト画面の文言整合（残課題1）

- **目的:** ユーザー設定のカスタムプロンプト画面（`/settings/prompts`）の文言が「全文プロンプトを上書き」前提から「分析の指示（任意）／システム既定」モデルへ整合され、admin と同一概念で見せられていることを確認する。
- **手順:**
  1. 一般ユーザーでログインし、設定 → カスタムプロンプト画面（`/settings/prompts`、P23）を開く。
  2. セクション冒頭の説明文を見る。
  3. 各プロンプトカードの textarea の**ラベル**と **placeholder** を見る。
  4. textarea を空のまま「保存」を押し、バリデーションメッセージを見る。
- **期待結果:**
  - セクション説明が「各用途のプロンプトを上書きできます。空のまま保存すると…」ではなく「分析の意図を補足できます。空欄のままならシステム既定の動作が適用されます」相当になっている。
  - ラベルが「あなたのプロンプト」ではなく「あなたの分析の指示（任意）」相当になっている。
  - placeholder が defaultPrompt 全文ではなく、意図記入を促す固定文言（所有ニュアンス込み）になっている。
  - 空保存時のメッセージが「プロンプト本文を入力してください」ではなく、分析の指示入力を促し空にする場合は「デフォルトに戻す」へ誘導する文言になっている。
- **確認ポイント:** 「全文上書き／プロンプト本文」というミスリーディングな表現が画面上のどこにも残っていないこと。`<details>デフォルトプロンプト</details>` で既定値の本文は引き続き確認できること。

### 2. P23 の保存 → デフォルトに戻す導線（既存挙動の非回帰）

- **目的:** 文言変更によって既存の保存・クリア導線が壊れていないことを確認する。
- **手順:**
  1. 任意のプロンプトカードの textarea に意図テキストを入力し「保存」を押す。
  2. 「個別オーバーライドが有効」表示に変わることを確認する。
  3. 「デフォルトに戻す」を押す。
- **期待結果:**
  - 保存後に「個別オーバーライドが有効」になり「保存しました」が表示される。
  - 「デフォルトに戻す」で textarea がクリアされ「インスタンスデフォルトを使用中」に戻る。
- **確認ポイント:** 保存・クリアの機能自体は従来どおり動くこと。

### 3. title / directory の operator 意図が LLM に届く（残課題2・方針a）

- **目的:** admin の title / directory カードに書いた意図が ingestion の構造化時に LLM へ実際に渡る（dead-input が解消された）ことを確認する。
- **手順:**
  1. 管理者ユーザーでログインし、プロンプト設定画面（P42、`/admin/prompts`）を開く。
  2. 「タイトル生成プロンプト」カードに識別しやすい意図テキスト（例「タイトルは必ず疑問形で」）を入力して保存する。
  3. 「ディレクトリ提案プロンプト」カードにも識別しやすい意図テキストを入力して保存する。
  4. LLM 構造化を伴う取り込み（テキスト/画像など、html/markdown 直挿しではないソース）を1件実行する。
- **期待結果:**
  - 取り込み結果のタイトル・ディレクトリ提案に、入力した意図の影響が現れる（例: タイトルが疑問形になる）。
  - title / directory 意図を空にした場合は、従来どおりシステム既定のガイダンスのみで動作する。
- **確認ポイント:** title / directory カードへの入力が「書いたのに効かない」状態ではなくなっていること。structure / metadata の既存挙動は不変であること。
- **備考:** LLM 出力は確率的なため厳密一致は期待しない。意図の方向性が反映されるかを定性的に確認する。プロンプト送出内容の厳密な検証は `prompts.test.ts` / runIngestionJob 結合テスト（自動）で担保する。

## エッジケース・異常系

### 1. title / directory 意図が空（未上書き）のとき

- **目的:** 意図が空のときに余計な追記が出ず、システム既定ガイダンスのみで構造化されることを確認する。
- **手順:**
  1. admin で title / directory を未上書き（または「この項目をリセット」）にする。
  2. LLM 構造化を伴う取り込みを実行する。
- **期待結果:** 構造化が従来どおり成功し、タイトル・ディレクトリ提案が生成される（`OPERATOR_INTENT_LABEL` 相当の追記が無い状態と等価）。

## 既存機能への影響確認

- **structure / metadata プロンプト**: 既存の per-upload override 含め挙動不変であること。
- **UploadDialog / アップロード時のプロンプト表示**: title / directory には per-upload override 経路がないため、UI に変化が無いこと。
- **3 LLM プロバイダ（anthropic / openai / gemini）**: 共通ビルダー経由のため、どのプロバイダ選択時も title / directory 意図が反映されること（自動テストで担保、手動は1プロバイダで代表確認可）。
