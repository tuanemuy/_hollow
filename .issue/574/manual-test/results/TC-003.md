## 失敗詳細／原因分析
- 本 TC の前提「ローカルは LLM 未設定（StubLLMProvider）」が**この環境では成立していない**。
- `.dev.vars` に `ADMIN_LLM_PROVIDER` / `ADMIN_LLM_MODEL` / `ADMIN_LLM_API_KEY` がすべて設定済み。
- DI（`app/core/application/di/serverCloudflare.ts` `buildLlmProvider`, L529）は「API キーとモデルが両方あれば実 LLM プロバイダを wire、どちらか欠ければ StubLLMProvider」。本環境は両方そろっているため**実 LLM**（設定プロバイダ）が使われた。
- したがって正直なエラー（`llm_preview_unavailable` → 「現在 AI が利用できないためプレビューできません」）の経路は実行されず、代わりに実プレビューが成功した。
- **分類: 環境（前提不成立）**。実装バグではない。agent-browser 偽陽性でもない（click は発火・probe=1・POST 200 を確認済み）。
- 正直なエラー経路自体はコードで担保されている: StubLLMProvider は `UnsupportedFormat` を throw（`app/core/adapters/stub/llmProvider.ts`）→ `previewPrompt.ts` の `translateLLMError` が `LLMPreviewUnavailable` に変換（L168-176）→ `errorDisplay.ts` が「現在 AI が利用できないためプレビューできません」を表示（L53-54）。ユニットテスト `previewPrompt.test.ts` ケース (f) でも検証済み。
- 厳密検証するには `.dev.vars` の `ADMIN_LLM_API_KEY`（または `ADMIN_LLM_MODEL`）を外して StubLLMProvider に切り替えたサーバで再実行する必要がある。
