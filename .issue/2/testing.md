## 確認項目

### 1. マージ（統合）ボタンが表示される

- **目的:** タグが 2 件以上ある状態で「統合」ボタンが各タグ行に表示されることを確認。
- **手順:**
  1. `/tags` 画面でタグを 2 件以上作成（例: `#alpha`, `#beta`）。
  2. 各行に「リネーム」「統合」「削除」の 3 つのアクションボタンが並んでいることを確認。
- **期待結果:** リネーム / 統合 / 削除が並ぶ。
- **確認ポイント:** ボタンのスタイルが既存の `pill-btn` と一貫していること。

### 2. マージ実行（基本フロー）

- **目的:** マージ操作で source タグが削除され、ノートが target タグを持つよう更新されることを確認。
- **手順:**
  1. ノートを 1 件作成し、本文中に `#alpha #beta` を記載して保存（両タグが作成される、もしくは事前に作成）。
  2. `/tags` で `#alpha` の利用件数が 1 件、`#beta` の利用件数が 1 件であることを確認。
  3. `#alpha` 行の「統合」ボタンをクリック。
  4. ダイアログが開き、`<select>` に「— 選択してください —」と `#beta` が表示されることを確認。
  5. `#beta` を選択 → 「統合」ボタンを押下。
- **期待結果:**
  - ダイアログが閉じる。
  - `#alpha` が一覧から消える。
  - `#beta` の利用件数が 1 件のまま（同じノートに集約されたため重複加算されない）。
  - 元ノートを開くとタグが `#beta` のみになっている。
- **確認ポイント:** マージ実行中は「統合」「キャンセル」ボタンが disabled になっていること（`isPending` 連動）。

### 3. マージ候補に source 自身が含まれない

- **目的:** 自タグへのマージを UI レベルで防止していることを確認。
- **手順:**
  1. `/tags` でタグを 3 件作成（`#a`, `#b`, `#c`）。
  2. `#b` 行の「統合」ボタンをクリック。
  3. ダイアログの `<select>` を開く。
- **期待結果:** 選択肢に `#a` と `#c` のみが表示され、`#b` は含まれない。

### 4. タグが 1 件のみのとき「統合」ボタンが表示されない

- **目的:** マージ先候補ゼロの状態で「統合」ボタンが非表示になることを確認。
- **手順:**
  1. `/tags` 画面でタグが 1 件のみの状態にする（他は削除しておく）。
  2. その行のアクションボタン群を確認。
- **期待結果:** リネーム / 削除のみが表示され、「統合」ボタンは表示されない。

### 5. 削除確認文言にブラックリスト化挙動が明示される

- **目的:** 削除時の `confirm` 文言が更新され、再抽出されなくなる旨が記載されていることを確認。
- **手順:**
  1. `/tags` で任意のタグ行の「削除」ボタンをクリック。
- **期待結果:** ブラウザの confirm ダイアログに次の旨が含まれる:
  - タグ名
  - 参照ノートから除去される旨
  - 「同名タグは今後自動抽出されなくなります」
  - 「再追加するには手動で再作成が必要」

### 6. 削除後のブラックリスト挙動（既存バックエンドの回帰確認）

- **目的:** `deleteTag` usecase で `tagBlacklistRepository.add(...)` が実行され、同名タグが自動抽出されないことを確認。
- **手順:**
  1. `/tags` でタグ `#trial` を作成。
  2. `#trial` を削除。
  3. ノートを 1 件作成し、本文に `#trial` を記載して保存。
  4. `/tags` に戻る。
- **期待結果:** `#trial` が再度タグ一覧に出現していないこと（自動抽出パイプラインがブラックリスト経路で抑止する）。
- **確認ポイント:** バックエンドは無変更だが、本 Issue のスコープ説明として spec の挙動と一致していることを示す。

## エッジケース・異常系

### 1. 楽観ロック衝突

- **目的:** 並行操作で楽観ロック衝突が起きた際にエラーが UI に表示されることを確認。
- **手順:**
  1. ブラウザのタブを 2 つ開き、両方で `/tags` を表示。
  2. タブ A で `#x` の「統合」ボタンを押下しダイアログを開く。
  3. タブ B で `#x` をリネーム or 削除して `router.invalidate()` をトリガー。
  4. タブ A のダイアログで `#y` を選択 → 「統合」を実行。
- **期待結果:** タブ A のダイアログ内に `form-error` でエラーメッセージが表示される（`extractSerializedError` 経由）。アプリ全体がクラッシュしない。

### 2. キャンセル操作

- **目的:** ダイアログのキャンセルで実行されないことを確認。
- **手順:**
  1. 「統合」ボタンでダイアログを開く。
  2. ターゲット未選択のまま「キャンセル」を押す（または ESC 等で閉じる）。
- **期待結果:** ダイアログが閉じ、タグ一覧に変化なし。

## 既存機能への影響確認

- **リネーム**: 「統合」ボタン追加によりレイアウトが崩れていないこと。リネームフローは従来通り動作。
- **削除**: 文言変更のみで挙動は変わらないこと。
- **ノート編集画面**: タグマージ後にノートを開いた際、タグ表示が正しく更新されていること。
- **公開ノート / SavedView**: マージで source タグが消えた後、source を含む保存ビューがあれば「壊れたフィルタ」として扱われる（既存挙動）。本 Issue では追加対応しない。
