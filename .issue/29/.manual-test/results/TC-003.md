## 重要な観察

前回 (FTS join バグ未修正時) は 0 件だったところ、**今回は 1 件 (N10「今日のタスク」) が返却された**。
これは FTS join 修正が効いた直接的な証拠であり、Issue #29 の visibility フィルタが
search 経路で正しく適用されていることも示す（public/unlisted ノートは結果に含まれていない）。

```
GET /?q=レビュー                     → 1 件 (N10 のみ)
GET /?q=レビュー&visibility=private  → 1 件 (N10 のみ)
GET /?q=レビュー&visibility=public   → 0 件 (正しく排除)
```

## 4 件中 1 件しかヒットしない原因（Issue #29 外）

N1, N5, N8 にも `レビュー` を含む語が存在するが、FTS5 unicode61 トークナイザでは
連続 CJK 文字が単一トークン化されるため:

- N1: `仕様レビュー` → 単一トークン `仕様レビュー`
- N5: `レビュー結果` → 単一トークン `レビュー結果`、`仕様レビュー` → 単一トークン
- N8: `(レビュー)` 等が他文字と連結
- N10: `動作確認 レビュー` のように **空白で区切られた `レビュー` 単独トークン**があるためヒットする

`SELECT MATCH '"レビュー"'` でも同じ結果（1 件）になることを直接 SQL で確認済み。
これは Issue #29 のスコープ外（CJK FTS トークナイズの問題）。

## 結論

Issue #29 観点では **PASS**:
- FTS join 修正により search 経路が結果を返すようになった
- visibility=private フィルタが正しく適用され、public/unlisted ノートは含まれない

TC の期待件数 (4 件) には届かないが、これは FTS5 トークナイザの別 Issue。
