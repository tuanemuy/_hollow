# 実装計画 — Issue #510: design: 各画面の UX 最適化（デザインモック改善・#500 後続）

**Issue:** #510
**作成日:** 2026-06-06
**複雑度:** 大規模（7領域 × 36モック + 設計言語 SSOT）

---

## 目的

#500 で「実装に寄せ戻した」36モック（`spec/design/pages/*.html`）と設計言語 SSOT（`spec/design/index.md` / `spec/design/tokens.md`）を対象に、**各画面の UX を良くする**。一貫性・トークン整備は手段であって目的ではない。判断に迷ったら常に「この画面の UX が良くなるか？」に立ち返る。

## スコープ

### 含まれるもの
- 全7領域・36モックの UX 最適化（`spec/design/pages/*.html`）
- 設計言語 SSOT の更新（`index.md` / `tokens.md`）— 各画面の UX を支える範囲で
- 「実装が正かモックが正か」が割れている論点の決着（UX が良くなる方を都度判断）

### 含まれないもの
- アプリ実コード（`app/`）の変更 — 実装追従は別Issueへ引き渡す
- ダークモード・印刷・i18n（index.md §10 スコープ外）
- 新規 px トークンの追加（#461 ADR-001 fluid 思想を維持）

## ユーザー決定方針（厳守）
1. スコープは全7領域を一気に、1本の PR にまとめる（領域単位でコミット分割は可）。
2. 割れている論点は **UX が良くなる方を都度判断**。重い論点（影響範囲大）は計画段階でユーザー確認する。

## 重い論点のユーザー確認事項（決定済み — 上表参照）

1. **横断#2 P11 右メタレール**: 推奨=廃止 + index.md §2.1 改訂。理由=#356 実装が既に移行済み、読書集中に資する。影響=P11 大改修 + SSOT 改訂。代替=§2.1 維持し実装を3カラムへ戻す（#356 ADR を覆す、非推奨）。
2. **横断#3 P12 エディタ**: 推奨=モードタブ骨格 + borderless title + 書式ツールバー折衷。理由=モードタブは共通、執筆体験向上。影響=P12 中改修、実装追従は別Issue。代替=完全フォーム（退化）/完全 WYSIWYG（書き換え大）。
3. **横断#4 P13 取り込みキュー**: 推奨=カード型基調 + 進捗バー/バッジ/保存先取り込み。理由=#221 進捗可視化を低コストで満たす。影響=P13 中改修。代替=7カラムテーブル（モバイル不利・大改修）。
4. **横断#5 P14 公開設定 + 単一/バルク**: 推奨=実装2セクション + inline、正本=単一ノート。理由=実装が分離済み、密度過多回避。影響=P14 中改修。代替=ラジオ内包+フッター（乖離大）。
5. **横断#10 一覧行構成（P13/P17/P18）**: 推奨=admin/取り込み=テーブル、タグ/ゴミ箱=DATA_ROW/2カラム。理由=全テーブル化は bulk/filter 未実装と一体で負荷大。影響=P13/P17/P18 + index.md 手段節。代替=全テーブル統一。

補助確認（中規模）: 横断#1 設定サブナビ（左サイドバー統一推奨）、横断#6 公開側空状態（#284 で付与）、横断#7 admin シェル検索/通知（維持推奨）、横断#9 共有解錠後挙動（P31 遷移=実装に寄せる推奨）、P24 削除確認強度（多段確認に寄せる推奨）。

## テスト方針

静的 HTML モックのためブラウザ目視が中心。
- 各 `spec/design/pages/*.html` をブラウザで開き、レイアウト・状態・トークン適用を目視。
- レスポンシブ: 640/768/1024/1280/1536px で横スクロール非発生・カラム切替・drawer 化・P11 右レール sticky 廃止を確認。
- a11y 目視: フォーカスリング、コントラスト AA 床、icon-only の aria-label、タッチ床 44/24。
- トークン整合: 全 `:root` が tokens.md「最終形」と一致するか、`[Npx]` 任意値が増えてないか grep。
- 状態網羅: 複数ステート（P02/P33/P34/P14）の見本が破綻なく描画されるか。
