# 動作確認計画 — Issue #607: タグ管理(P18) デザイン未追従＋楽観的更新の不統一

**Issue:** #607
**作成日:** 2026-06-09

---

## 確認環境

本Issueはフロントエンドのみの変更（作成フォームの意匠/配置/余白のデザイン追従と、作成 / 統合 / 並び替え / 検索の楽観的更新化）。backend / migration の変更は無い。実機確認はローカル開発サーバで行う。

### 検証環境の起動

```
pnpm db:apply:local
pnpm dev
```

`pnpm db:apply:local`（= `wrangler d1 migrations apply hollow-local-d1 --local`）で既存マイグレーションをローカル D1 に適用（本Issueでの新規追加なし、冪等）後、`pnpm dev`（`vite dev`、Cloudflare ランタイム）でローカルサーバを起動する。表示された URL をブラウザで開き、ログイン済みユーザーで確認する。

確認には少なくとも以下のデータを持つユーザーが必要:
- 複数のタグ（名前が五十音順で散らばるもの・ノート件数が異なるもの・未使用タグ（ノート0件）を含む）。
- タグ付きノート（最終使用ソート確認用に `updatedAt` がばらつくもの）。
- 統合確認用に、別タグへ統合できる候補が2つ以上。

開発用 admin ユーザーは `pnpm seed:dev-admin` で投入できる。追加のシードは `pnpm db:execute:local <SQLファイル>` で流せる（manual-test スキルが seed を準備する）。

### デプロイ方法

なし（検証環境のみで確認できる。ステージング反映が必要な場合は `pnpm deploy:staging`。新規 migration が無いため D1 反映は不要）。

## 確認項目

### 1. 作成フォームのデザイン追従（意匠 / トークン）

- **目的:** 作成フォームがタグページの意匠（surface pill 入力・`.btn-primary` 相当の追加ボタン）に揃い、admin 用素朴レイアウトの浮きが解消されているか。
- **手順:**
  1. `/tags` を開く。
  2. 作成フォームの入力欄・ボタンの見た目を、ツールバーの検索 pill / segmented と並べて比較する。
- **期待結果:** 入力欄・ボタンがツールバーの pill / primary ボタンと同じ密度・surface 言語で統一されている。`flex gap-2 items-end mt-4` の素のレイアウト由来の不揃いが無い。
- **確認ポイント:** focus 時の shadow / border、ボタンの primary 配色が `pillBtnPrimary` と一致すること。

### 2. ページ縦リズム（余白）のデザイン追従

- **目的:** タイトル → stats（件数）→ 作成フォーム → ツールバー → 一覧の縦余白がデザイン仕様（`page-header` `--space-6` / `tag-toolbar` `--space-5`）に沿うか。
- **手順:**
  1. `/tags` を desktop 幅で開き、各要素間の余白を `spec/design/pages/P18-tags.html` をブラウザで並べて目視比較する。
  2. ツールバーと一覧の間に二重余白（旧 `mt-6` ＋ ツールバー `mb-5`）が出ていないか確認する。
- **期待結果:** デザイン HTML と縦リズムが一致。作成フォーム後付けによる崩れが解消。
- **確認ポイント:** 空状態（タグ0件）時の余白も `EMPTY_STATE` の `mt-6` とツールバー margin が二重にならないこと。

### 3. 作成の楽観的更新

- **目的:** 「追加」押下後、サーバー応答を待たずに新規タグが即座に一覧へ現れ、件数（`{n} 件のタグ`）も即時に増えるか。
- **手順:**
  1. `/tags` でタグ名を入力し「追加」を押す。
  2. 押下直後の一覧と件数表示を観察する。
- **期待結果:** 新規行（`0 件のノート` / `未使用`）が即時に追加され、件数が +1 される。サーバー確定後も行が維持される（snap back で確定行に置き換わる）。入力欄は送信後クリアされる。
- **確認ポイント:** 「作成中...」待機表示で新規行が出ないまま固まる旧挙動になっていないこと。連打しても二重追加 / 二重送信にならないこと。

### 4. 統合の楽観的更新

- **目的:** 統合確定で統合元タグが即時に一覧から消えるか。
- **手順:**
  1. あるタグの「統合」を開き、統合先を選んで「統合」を押す。
  2. 押下直後の一覧を観察する。
- **期待結果:** ダイアログが即座に閉じ、統合元タグが即時に一覧から消える。サーバー確定後も消えたまま、統合先の件数が更新される。
- **確認ポイント:** 旧来の「統合中...」全体リロード待ちが無いこと。統合元が即消えるため進捗バナーは出ない（ADR-003）。

### 5. 並び替え（segmented / 方向トグル）の楽観的更新

- **目的:** ソート軸 / 昇順降順の選択状態が即時に切り替わり、pending 中もコントロールが disabled にならないか。
- **手順:**
  1. segmented の各軸（名前 / ノート数 / 作成日時 / 最終使用）を素早く連続でクリックする。
  2. 方向トグルを連続でクリックする。
- **期待結果:** クリック直後に active 表示が切り替わる（URL ローダー再実行を待たない）。pending 中もボタンが押せ、rapid 操作が落ちない。一覧の並び替え結果はサーバー確定後に反映される。
- **確認ポイント:** `disabled` でグレーアウト / 操作不能になる旧挙動が消えていること。最終的な URL（`?sort=...&order=...`）と一覧順が一致すること。

### 6. 検索の楽観的更新

- **目的:** 検索 submit 後、適用済みクエリの状態が即時反映され、入力（IME 含む）が壊れないか。
- **手順:**
  1. 検索フォームに部分文字列（日本語タグ名を含む）を IME で入力し submit する。
  2. 結果と URL（`?q=...`）を確認する。
  3. 空にして submit し、`q` が URL から消えるか確認する。
- **期待結果:** submit で適用状態が即時反映。一覧結果はサーバー確定後に反映。IME 入力中に確定前文字が消える等の破綻が無い。
- **確認ポイント:** 検索入力は submit 型のまま（打鍵ごとに URL が変わらない）こと。

## エッジケース・異常系

### 1. 作成エラー（重複名 / 上限超過）

- **目的:** 作成が失敗したとき、楽観追加した行が巻き戻り、エラーがフォーム直下に出るか。
- **手順:**
  1. 既存タグと同名、または64文字超のタグ名で「追加」を押す。
- **期待結果:** 楽観追加した一時行が snap back で消え、フォーム直下にエラーメッセージが表示される。

### 2. 統合エラー

- **目的:** 統合失敗時、楽観的に消した統合元タグが復帰しエラーが表示されるか。
- **手順:**
  1. 統合をトリガし、サーバー側でエラーになる状況（権限/不整合）を再現できれば実行する。
- **期待結果:** 統合元タグが一覧へ復帰（snap back）し、該当行に `FORM_ERROR` でエラーが出る。

### 3. 不正な URL パラメータ

- **目的:** `?sort=bogus` / 空 `?q=` でルートが壊れずデフォルトに落ちるか（#569 で確立済みの挙動を退行させていないか）。
- **手順:**
  1. `/tags?sort=bogus&order=xxx` を直接開く。
- **期待結果:** デフォルト（name / asc）で表示され、エラーにならない。

## モバイル表示の確認

- **目的:** モバイル幅で作成フォーム・余白がモバイルデザイン仕様（`spec/design/pages/mobile/P18-tags.html`）に沿うか。
- **手順:**
  1. ブラウザを `sm` 未満幅にして `/tags` を開く。
  2. 作成フォーム・ツールバー（縦積み）・一覧（ケバブ表示）の余白とレイアウトを確認する。
- **期待結果:** モバイル HTML と縦リズム・折り返しが一致。作成フォームが破綻しない（`flex-wrap` / 入力欄 `min-w`）。

## 既存機能への影響確認

- リネーム / 削除の楽観的更新が従来どおり即時反映されること（本Issueで投影に `add` を足すため `reduceTags` の回帰確認）。
- ソート / 検索 / 最終使用列（#569 追従分）の結果自体が変わらないこと（楽観化は選択状態の即時反映のみで、loader 確定結果は不変）。
- `/` ホームの `FilterBar`（同じ楽観パターンの先例）に副作用が無いこと（共通スタイル `pillBtn` 等を触る場合のみ確認）。
