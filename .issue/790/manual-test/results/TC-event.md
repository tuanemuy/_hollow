# TC-3: イベント駆動更新（AC-3）

結果: **PASS**

## 概要

`/upload` で新規アップロードを成功させると、ページリロードなしにサイドバー「アップロード」項目の未処理件数が 19 → 20（+1）に増加することを確認した。`notifyIngestionQueueChanged` 経由のイベント駆動更新がサイドバーで機能している。

## 件数の変化

- 更新前: 未処理 **19 件**（サイドバー「アップロード（未処理 19 件）」）
- 更新後（リロードなし）: 未処理 **20 件**（サイドバー「アップロード（未処理 20 件）」）

## アップロード手段の実態

- `/upload` 画面はドラッグ&ドロップ用ラベル（「ファイルをドラッグ&ドロップ またはクリックして選択」）の内部に隠れた `<input type="file" multiple>` を持つ。
- agent-browser の `upload <sel> <files...>` コマンドで `input[type=file]` にファイルを添付でき、技術的な制約なく検証可能だった。
- マイク録音による取り込み手段（「録音を開始」ボタン）も存在するが本テストでは未使用。

## 備考（テスト結果に影響なし）

- メイン領域のアップロードキュー一覧は本テスト中ずっと「アップロードの一覧を読み込めませんでした。」というエラーを表示していた（アップロード実行前から表示）。これは一覧パネル側の読み込みエラーで、サイドバー件数の event 駆動更新とは独立。AC-3 の対象であるサイドバー件数は正しく +1 更新された。
- 件数確認後、確認用スクリーンショット取得（`screenshot`）が exit code 144 で失敗し、その後ページが about:blank（empty page）になった。これは件数確認（19→20）を取得した後の事象であり、テスト結論には影響しない。スクリーンショット保存は失敗。
