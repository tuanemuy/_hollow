# TC-001: 未保存編集 → 公開設定に警告が出る

結果: PASS

## 概要

ノートA (`01950000-0000-7000-8000-000000000202`) のエディタで編集し dirty フラグを立てた状態で、autosave のデバウンス (1500ms) が走る前に同一 session で詳細を開き、公開設定モーダルを開いて `role="status"` の「未保存の変更があります」警告が表示されることを確認した。

## 実行ログ

| ステップ | 操作 | 結果 |
| --- | --- | --- |
| 1 | session `verify-583-tc1` で認証し `/notes/.../202/edit` を open（networkidle 待ち） | 認証成功、「ノートを編集」表示 |
| 2 | タイトル欄 (ref=e25) を click → `type "Y"` で dirty 化 | 入力成功 |
| 3 | 直後（1500ms 以内）に同一 session で `/notes/.../202` を open（networkidle 待ち） | 遷移成功。`sessionStorage` の dirty フラグ = `"1"` を確認 |
| 4 | ツールバー「公開状態: 非公開」ボタン (ref=e28) を click | モーダル「公開設定」が開く |
| 5 | モーダル内 snapshot で警告を確認 | `status` ロール内に「未保存の変更があります」+ 説明文を確認 |

## 確認できた警告内容

```
- dialog "公開設定"
    - status
        - paragraph
            - StaticText "未保存の変更があります"
        - paragraph
            - StaticText "公開には最後に保存した版が使われます。最新版を反映したい場合は先にノートを保存してください。"
```

## 補足

- 初回試行では type と navigate の間に eval/snapshot を挟んだため約 1500ms 経過し、autosave がタイトル変更を永続化（"Test Note 02X" として保存）→ dirty フラグがクリアされ、警告が出なかった。これはテスト手順上のタイミングの問題であり、機能の不具合ではない。
- type と open を eval/snapshot を挟まず連続実行することで autosave デバウンスを回避し、dirty フラグ=`"1"` を維持したまま遷移できることを確認 → 警告が正しく表示された。
