# TC-004 (エッジ): 別ノートの未編集オープンが既存フラグを誤消去しない

結果: PASS

## 概要

ノートA の dirty フラグを立てた状態で、別ノートB のエディタを開いて何も編集しなかった場合に、ノートA の dirty フラグが巻き込み消去されないことを確認した。ノートA の公開設定モーダルに警告が依然として表示される。

## 実行ログ

| ステップ | 操作 | 結果 |
| --- | --- | --- |
| 1 | session `verify-583-tc4` で認証し ノートA `/notes/.../202/edit` を open（networkidle 待ち） | 認証成功 |
| 2 | ノートA のタイトル欄 (ref=e25) を click → `type "W"` で dirty 化 | dirty 化 |
| 3 | 直後（1500ms 以内）に同一 session で ノートB `/notes/.../203/edit` を open（networkidle 待ち）。ノートB は何も編集しない | 遷移成功。ノートA のフラグ = `"1"` を維持 |
| 4 | 同一 session で ノートA `/notes/.../202`（詳細）へ戻る（networkidle 待ち） | 遷移成功。ノートA のフラグ = `"1"` を維持 |
| 5 | ノートA ツールバー「公開状態: 非公開」ボタン (ref=e28) を click | モーダル「公開設定」が開く |
| 6 | モーダル内 snapshot で警告を確認 | `status` 内に「未保存の変更があります」を確認 |

## 補足

- ノートB のエディタ未編集オープン後も、ノートA のキー `hollow3:note:01950000-0000-7000-8000-000000000202:dirty` は `"1"` のまま。ノート単位でキーが分離されており、別ノートのオープンで巻き込み消去されないことを確認。
- ステップ2→3 は type と open を eval/snapshot を挟まず連続実行し、autosave デバウンス (1500ms) を回避した。
