# レビュー round-2 — Issue #583 計画（視点: 要件カバレッジ・スコープ整合性）

対象: `.issue/583/plan.md` / `.issue/583/adr.md`
レビュー観点: (1) Issue 要件が受け入れ基準に漏れなく落ちているか / (2) 各基準が検証可能か / (3) 基準と実装ステップの紐づけ / (4) スコープ外混入 / (5) round-1 指摘の解消

#### 問題点（要修正）

問題点ゼロ。

round-1 で挙げた要修正点（P-001 手動保存後の clear / P-002 AC-3 の検証可能性）はいずれも適切に解消されている。実コードでも裏取り済み。

- **[round-1 P-001 解消確認]** 手動保存パスの取りこぼし。実コード（`NoteEditor.tsx:318-333`）で確認 — `mode === "edit"` 分岐は `saveNote` → `router.navigate` を呼ぶだけで `dirtyKeys` リセットの dispatch を行わない。`dirtyKeys` を `EMPTY_DIRTY` に戻す reducer は `autosaveSuccess` ただ1つ（`editorState.ts:497-503`）。計画はこの事実を ADR-002 / ステップ2(b) / リスク欄に正確に反映し、「手動保存成功分岐で `clearNoteUnsaved(props.noteId)` を明示呼出」する2系統設計に修正済み。AC-3 も「手動保存して detail へ遷移し公開設定を開いても警告が出ない」に拡張されており、主ユースケースの誤検知が塞がれている。
- **[round-1 P-002 解消確認]** AC-3 を実装内部状態（`dirtyKeys` が空に戻る）でなく観測可能な外形（`AutosaveIndicator` が保存済み表示 / 手動保存後 detail で警告なし）で表現するよう書き換え済み。テスト方針の手動確認にも autosave 完了の待ち方（`AutosaveIndicator` が保存済み表示）を明記。ブラックボックス検証可能になった。
- **[round-1 S-001 解消確認]** モック行番号。実ファイル `P14-publish-settings.html:960-973` を確認 — `.safety-check` 実体は `:963`、`role="status"` は `:964`、タイトル「未保存の変更があります」は `:969`、本文は `:970`。計画/ADR の記載（`:963-973`）と完全一致。Issue 本文の `:717-746` が旧版／CSS 側参照である旨も調査結果・リスク欄に注記済み。文言も verbatim 一致。
- **[round-1 S-002 解消確認]** AC-2 に「タグは draft 入力（未確定）のみでは dirty にならず、Enter / 追加で確定したとき立つ」（`editorState.ts:setTagDraft` が dirty を積まない仕様）を明示。`setTagDraft`（`editorState.ts:490-492`）が `dirtyKeys` を触らず `tagDraft` のみ更新することを実コードで確認、記載は正確。テスト方針にも「タグは `setTagDraft` のみでは set されず `addTag`（確定）で set される」を追加済み。

#### 改善提案（検討推奨）

- **[S-001]** AC-4 と AC-6 がどちらも `role="status"` の warning 描画を扱い、対応ステップ（AC-4: 3,4 / AC-6: 4）が一部重複している。検証時に「AC-4 のテストで `role="status"` を確認すれば AC-6 も自動的に満たされる」関係になっており、AC-6 は実質「新規スタイルを足さず既存 `ALERT*` プリミティブで組む」という実装手段の制約。これは受け入れ基準というより実装方針に近い。実害はない（むしろ明示は親切）が、AC-6 を「プリミティブ流用の確認」と位置づけるか、AC-4 に内包させるかを意識しておくと AC 表が引き締まる。修正必須ではない。

#### 良い点

- round-1 の全指摘（要修正2件 + 改善4件）を漏れなく取り込み、レビュー履歴に修正内容を対応番号付きで記録。見送りゼロで、各修正が実コードの行番号で裏付けられている。トレーサビリティが高い。
- ADR-002 が追加され、フラグ駆動を「エッジ追跡（自動 set/clear）」+「手動保存の明示 clear」の2系統に分離した設計判断が、実コードの2つの欠陥（手動保存が `dirtyKeys` を残す / 初回マウント `EMPTY_DIRTY` での誤 clear）から正しく導かれている。立ち下がりエッジ限定により `0→0` を no-op にする設計で、未編集オープン・無編集往復での既存フラグ誤消去も同時に塞いでいる。
- `autosaveError` でフラグが残るのは「実際に未保存だから正しい」と過剰検知でないことを明記し、誤読を防いでいる。dirty 残留リスクの3分類（手動保存=明示 clear で解消 / autosave 失敗=正しく残る / タブ落ち=次セッションで消え安全側）が整理されている。
- スコープ外（ナビゲーションガード useBlocker/beforeunload、案2 の DTO 比較、複数タブ同期）が各々「なぜ外すか」付きで維持されており、round-1 から増減なし。Issue が求めていない作業の混入なし。
- AC-1〜AC-6 が Issue チェックリスト3項目（ADR 化 / dirty 供給実装 / モック追従）を過不足なく分解し、各 AC に由来とステップが紐づく。AC と実装ステップの対応（1→ヘルパ, 2→供給, 3-4→消費・表示）も整合。
- `unsavedFlag.ts` の配置（`note/` 直下）を「editor が書き publication が読む2ドメイン横断」という依存方向から導き、`displayPreference.ts` が `note/list/` にある理由（home-route 専用）との性質差まで踏み込んでいる。スコープ内の判断として妥当。

#### スコープ・カバレッジ総評

round-1 の要修正点（手動保存パスの誤検知）が ADR-002 / ステップ2 / AC-3 の3点で確実に塞がれ、検証可能性（P-002）・モック行番号（S-001）・タグ dirty 契機（S-002）も解消済み。Issue チェックリスト3項目は AC に漏れなく落ち、スコープ外混入もない。計画は要件カバレッジ・スコープ整合性の観点で承認可能。S-001 は AC 表の整理にすぎず、実装着手の障害にならない。
