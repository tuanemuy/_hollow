## 確認項目

### 1. プロフィールヒーローの構造（最重要）

- **目的:** モック `.profile-hero`（`flex flex-direction:column; gap:20px`）＋ `.profile-head`（アバター＋名前/ユーザー名を横並び中央揃え `gap:24px`）＋ bio/統計を全幅で下に積む構造に一致。
- **手順:**
  1. `/u/<username>` を開く。
  2. プロフィール部のアバター・名前・ユーザー名・自己紹介・統計の配置を見る。
- **期待結果:** アバターと「名前＋@ユーザー名」が水平に揃い、自己紹介と統計はページ左端（アバター左端と同じ位置）から全幅で始まる。bio/統計がアバター幅ぶん右にインデントしていない。名前の下マージンは 4px。
- **確認ポイント:** 旧実装（bio/統計がアバター幅ぶん右にずれる、アバターが背の高いテキスト列の中央に浮く）になっていないこと。デスクトップ・モバイル両方で確認（`spec/design/pages/P30-user-public-top.html` / `mobile/P30-user-public-top.html`）。

### 2. ソートのドロップダウン化

- **目的:** ソートが選択式メニューになり、4軸（公開日順 / 更新日順 / 作成日順 / タイトル順）を任意選択できる。
- **手順:**
  1. ツールバー右の「公開日順 ▼」ボタンをクリック。
  2. メニューから別の軸（例: タイトル順）を選ぶ。
  3. キーボード（↑↓ / Enter / Esc）でも操作する。
- **期待結果:** クリックでメニューが開き選択肢が見える。選択するとラベルが更新され、URL に `sort=` が反映、一覧が並び替わる。デフォルト（公開日順）選択時は URL から `sort` が消える。Esc で閉じてフォーカスがトリガーに戻る。
- **確認ポイント:** 旧挙動（クリックで順送りサイクル）になっていないこと。`role="menu"` / `menuitemradio` で選択状態が示されること。

### 3. タグ・ソート・表示モードの楽観的即時反映

- **目的:** 操作がサーバー再フェッチ完了を待たず即座に反映される。
- **手順:**
  1. タグ chip をクリック（選択/解除）。
  2. ソートを変更。
  3. 表示モード（リスト/タイル/カレンダー）を切替。
  4. （可能なら）ネットワークを遅延させて再フェッチ中の挙動を見る。
- **期待結果:** chip の active 状態・ソートラベル・表示レイアウトがクリック直後に即変わる。再フェッチ完了後もサーバー確定値と一致（巻き戻りや二重反映が無い）。表示モード切替は再フェッチを起こさず即時切替（loaderDeps 除外, ADR-004）。
- **確認ポイント:** 操作の反応が鈍くないこと。再フェッチ失敗/キャンセル時に baseline へ戻ること（連打しても操作落ちが無い）。

### 4. 期間フィルター

- **目的:** モック `filter-row` のカレンダーアイコン付き「期間」フィルターが機能し、公開日範囲で一覧が絞られる。
- **手順:**
  1. 「期間」chip をクリックしてポップオーバーを開く。
  2. プリセット（例: 直近1ヶ月など）または範囲指定で期間を選ぶ。
  3. 各ソート軸（公開日順 / 更新日順 / タイトル順）で期間が効くか確認。
  4. 期間をクリア。
- **期待結果:** 選択した期間に**公開日**が収まるノートだけ表示される。URL に `from`/`to` が反映され、リロードしても維持。件数（ページネーション）も絞り込み後の総数に一致。ソート軸を変えても期間が効き続ける。クリアで全件に戻る。
- **確認ポイント:** 更新日ではなく**公開日**で絞られていること（ADR-005）。`items.length <= total` が崩れない（ページ件数と総数が矛盾しない）。

### 5. ノート行の日付（公開日ベース＋相対表現）

- **目的:** メタ行が「YYYY年M月D日 公開」、右列が相対表現（今日 / M月D日）。
- **手順:**
  1. リスト表示で各ノート行のメタ行と右列の日付を見る。
  2. 公開日が今日のノート、数日前・数ヶ月前のノートを見比べる。
  3. タイル表示・カレンダー表示でも日付軸を確認。
- **期待結果:** メタ行は公開日で「YYYY年M月D日 公開」。右列は今日のものは「今日」、それ以外は「M月D日」。タイルのメタも公開日。カレンダーの日次グルーピングも公開日基準（ADR-003）。
- **確認ポイント:** 旧実装（「…更新」＝updatedAt、常に「M月D日」）になっていないこと。「今日」判定がクライアント TZ で正しいこと。

## エッジケース・異常系

### 1. 公開ノートが0件

- **目的:** 空状態の表示。
- **手順:** 公開ノートが無いユーザーの `/u/<username>` を開く。
- **期待結果:** 「公開されているノートはまだありません。」が表示され、レイアウトが崩れない。

### 2. 期間でヒット0件

- **目的:** 絞り込み結果が空のときの表示。
- **手順:** 公開ノートが存在しない期間を指定。
- **期待結果:** 空状態が表示され、ページネーションが破綻しない（total=0）。期間クリアで戻る。

### 3. 存在しない/停止/削除ユーザー

- **目的:** notFound 経路。
- **手順:** 存在しない username の `/u/<username>` を開く。
- **期待結果:** 404（ErrorPage notFound）が表示される（既存挙動を壊さない）。

### 4. 不正な search パラメータ

- **目的:** transport 境界バリデーション。
- **手順:** URL に不正な `from`/`to`（例: `from=abc`）や不正な `sort` を手打ち。
- **期待結果:** `.catch(undefined)` でフィルタが無視され、ルートがエラーにならず通常表示される。

## 既存機能への影響確認

- **管理画面のノート一覧**（`NoteListItemDTO` / `groupNotesByDay` / `NoteOwnerFilters` を共用）: 公開日 projection を専用型に分離し、`groupNotesByDay` のキー抽出を後方互換（既定 updatedAt）にするため、auth 側の一覧・カレンダー・日付・フィルターが従来通り動くこと。
- **P32 公開検索**（#617/#618）: 共有 `Popover` / `useRovingMenu` / `listSelectors` を変更する場合、検索側の挙動に影響が出ないこと。
- **publication アダプター**: `listPublicNoteIdsByOwnerSorted` に範囲条件を足す変更が、範囲未指定時（既存呼び出し）の結果・count を変えないこと。
