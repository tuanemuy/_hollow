## 確認項目

### 1. 管理画面ジョブ監視に新セクションが表示される

- **目的:** `/admin/jobs` に「内部リンクバックフィル」セクションが追加され、実行ボタンが表示されることを確認する。
- **手順:**
  1. admin ロールのユーザーでログインする。
  2. `/admin/jobs`（ジョブ監視）を開く。
  3. 既存の「検索インデックスの再構築」セクション付近に新セクションがあることを確認する。
- **期待結果:** 説明文・実行ボタンが表示される。
- **確認ポイント:** セクションの文言、ボタンラベル。

### 2. バックフィル実行と結果表示

- **目的:** 実行で全 owner の未解決 title リンク行が解決され、結果が表示されることを確認する。
- **手順:**
  1. 事前に `note_internal_links.resolved_note_id IS NULL` の滞留行を仕込む（リンク元ノートと、後から作成したリンク先ノートを用意し、再解決されていない状態を作る）。`pnpm db:execute:local --file <sql>` で直接投入してもよい。
  2. セクションの実行ボタンを押す。
  3. 完了後の結果文言を確認する。
- **期待結果:** 「N 件のリンクを解決しました」等、解決行数（`resolvedRows`）が主表示される。走査回数（`scannedNotes`）は distinct ノート数ではない旨の補足が出る。
- **確認ポイント:** 解決行数が仕込んだ滞留行数と一致するか。`resolved_note_id` が埋まったか（DB を直接確認）。

### 3. 再実行で no-op になる（冪等性）

- **目的:** 解決済みの状態で再実行しても二重解決や件数増加が起きないことを確認する。
- **手順:**
  1. 確認項目2の直後に、もう一度実行ボタンを押す。
- **期待結果:** `resolvedRows` が 0 と表示される（あるいは新たに解決すべき行がない旨）。
- **確認ポイント:** DB の `resolved_note_id` が変化しないこと。

## エッジケース・異常系

### 1. 非 admin / 未ログインでの拒否

- **目的:** admin 以外がバックフィルを起動できないことを確認する。
- **手順:**
  1. ログアウト、または非 admin ユーザーでログインした状態で `/admin/jobs` にアクセスする。
- **期待結果:** 管理画面自体にアクセスできない（admin ガードで拒否）。server function を直接叩いた場合も `ForbiddenError`（admin 専用）になる。

### 2. 実行中のボタン無効化

- **目的:** 多重サブミットが抑止されることを確認する。
- **手順:**
  1. 実行ボタンを押し、処理中の状態を観察する。
- **期待結果:** 処理中はボタンが無効化（`disabled` / pending 表示）され、連打できない。
