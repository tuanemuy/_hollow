## 確認項目

### 1. 共通 Skeleton コンポーネント（アップロードダイアログでの表示）

- **目的:** `ingestion/UploadDialog` のローカル `SkeletonBlock` を共通 `Skeleton` に置換しても従来どおりの見た目で表示されること。
- **手順:**
  1. ノートのインジェスト/アップロードダイアログを開く（ファイルアップロード → 処理待ち / LLM 提案待ちの状態に遷移させる）。
  2. waiting / skeleton 状態を表示させる。
- **期待結果:** `--color-surface` のバーが 3 本（幅 75/50/66% 相当）パルスし、キャプション（「N 件のファイルをアップロード中...」「LLM が…提案中...」等）が従来どおり表示される。レイアウト崩れ無し。
- **確認ポイント:** バーの高さ（12px=`h-3`）・色・パルスが P13a モックおよび置換前と一致。スクリーンリーダー用に `role="status"`/`aria-live="polite"` が1コンテナに集約されている。

### 2. タグ作成の pending 表示（CreateTagForm）

- **目的:** タグ作成の送信ボタンに pending ラベルが出ること。
- **手順:**
  1. タグ管理画面でタグ名を入力し「追加」を押す。
  2. 送信中のボタン状態を観察する（ネットワークが速い場合は devtools で throttling）。
- **期待結果:** 送信中はボタンが「追加中...」＋ disabled ＋ `aria-busy`、入力欄も disabled。完了後に元へ戻り、楽観追加された行が確定行に置き換わる。
- **確認ポイント:** 二重送信できないこと。エラー時はフォーム下にエラーが出て楽観行が消えること。

### 3. ノート保存/作成の視覚フィードバック（NoteEditor）

- **目的:** 保存/作成ボタンの pending 視覚フィードバックが強化されていること。
- **手順:**
  1. `/notes/new` で本文を入力し「作成」を押す。
  2. 既存ノートの編集画面で内容を変更し「保存」を押す。
- **期待結果:** 押下直後にボタンが disabled ＋ `aria-busy` ＋「作成中.../保存中...」。完了後に対象ノートへ navigate。
- **確認ポイント:** 装飾過多でないこと（spec/design 準拠）。`prefers-reduced-motion` 下でアニメーションが止まること。

### 4. DirectoryPicker インライン作成のフィードバック（NoteEditor）

- **目的:** 新規ディレクトリ名を指定した保存時に「ディレクトリ作成中」のフィードバックが出ること。
- **手順:**
  1. ノート編集画面の DirectoryPicker で「新規ディレクトリ名」を入力（既存は選ばない）。
  2. 「保存」/「作成」を押す。
- **期待結果:** ディレクトリ作成 → ノート作成/保存の順に進み、最初の段で「ディレクトリ作成中...」（またはインラインの作成中表示）が出てから「保存中...」に切り替わる。
- **確認ポイント:** 作成失敗時にエラーが表示され、保存処理が中断されること。

### 5. 一括ゴミ箱操作中の対象アイテム dim（BulkActionBar）

- **目的:** 一括ゴミ箱処理の確定まで、選択中アイテムが dim されること。
- **手順:**
  1. ノート一覧で選択モードに入り、複数ノートを選択する。
  2. 一括バーの「ゴミ箱へ」を押し、確認ダイアログで確定する。
- **期待結果:** 処理中（確定まで）、選択中の行が `opacity-60` 相当で dim され、`aria-busy` が付く。完了後に選択が解除されリストが更新される。
- **確認ポイント:** dim は list / tile 両ビューで効くこと。`prefers-reduced-motion` 下で opacity トランジションが即時になること。

### 6. ゴミ箱の復元 pending ラベル（TrashRowActions）

- **目的:** 復元ボタンに pending ラベルが出ること。
- **手順:**
  1. ゴミ箱画面で任意のノートの「復元」を押す。
- **期待結果:** 処理中は「復元中...」＋ disabled ＋ `aria-busy`。完了後にリストから当該行が消える。
- **確認ポイント:** 「完全に削除」側（ConfirmDialog）も従来どおり pending 表示されること。

### 7. docs 規約の追記

- **目的:** `docs/frontend_implementation_example.md` に Pending UX / 楽観的更新 / Suspense フォールバック規約が追記されていること。
- **手順:** ファイルを開いて新節を確認する。
- **期待結果:** 規約1〜5（楽観 or pending 必須・振り分け基準・Suspense+Skeleton 方針・エラー境界+リトライ・共通資産と motion-safe）が記載され、既存節（mutation / useOptimistic）へのクロスリンクがある。

## エッジケース・異常系

### 1. prefers-reduced-motion

- **目的:** モーション低減設定でパルス/スピン/dim トランジションが停止すること。
- **手順:** OS / devtools で `prefers-reduced-motion: reduce` を有効化し、項目1〜6を再確認。
- **期待結果:** パルス・スピン・opacity トランジションが無効化され、静的表示になる。

### 2. ミューテーション失敗時

- **目的:** pending 解除とエラー表示が両立すること。
- **手順:** ネットワークを切る/サーバーエラーを誘発し、タグ作成・ノート保存・一括ゴミ箱・復元を実行。
- **期待結果:** pending が解除され、`role="alert"` のエラーが出る。楽観追加した行はエラー時にロールバックされる。

## 既存機能への影響確認

- `ingestion/UploadDialog` のアップロード/プレビューフロー全体（Skeleton 置換による regression が無いか）。
- `tag` 一覧の作成/リネーム/削除/マージ（CreateTagForm の signature 変更による既存挙動の維持）。
- ノート一覧の選択モード・フィルタ navigation 中の dim（`NoteListViews` の既存 `isLoading` dim と、新規の一括処理 dim が干渉しないこと）。
