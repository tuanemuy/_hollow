# 動作確認計画 — Issue #617: 公開検索画面（P32）がデザインモックと乖離している

**Issue:** #617
**作成日:** 2026-06-10

---

## 確認環境

このIssueの変更（公開検索画面 `/search` の見た目）を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm db:migrate    # ローカル D1 にマイグレーション適用（初回・未適用時のみ）
pnpm dev           # vite dev (workerd) on http://localhost:3000
```

確認 URL: `http://localhost:3000/search`（キーワード入力で結果表示。例: `http://localhost:3000/search?q=<キーワード>`）

### デプロイ方法

なし（検証環境のみで確認できる。本変更はフロントのスタイル／JSX のみ）。

### シードデータ

公開ノートが複数件（複数ユーザー・複数タグ）あると結果カードのレイアウト・タグ表現を確認しやすい。シードの整備は manual-test スキルに委ねる。検索結果が出るよう、公開（public）ノートを最低数件用意すること。

## 確認項目

### 1. ヒーロー検索バーの視覚

- **目的:** 検索バーの背景・枠線・高さ・フォーカス挙動がモック（`spec/design/pages/P32-public-search.html`）と一致する。
- **手順:**
  1. `/search` を開く。
  2. ヒーローの検索バーを見る。
  3. 検索バーをクリック（フォーカス）する。
- **期待結果:** 背景は `surface`（淡グレー）、枠線なし、高さ 56px（PC）。フォーカス時は背景が `surface-hover` に変わり focus リング（shadow-focus）が出る。「検索」送信ボタンが右側に accent 色で表示され、淡グレー背景上でも十分視認できる。
- **確認ポイント:** 旧実装の白背景＋枠線になっていないこと。ボタンが input の縦中央に収まり、上下にはみ出さないこと（ADR-004 継承）。

### 2. ヒーローのレイアウト（中央寄せ・余白）

- **目的:** ヒーロー（見出し・サブテキスト・検索バー）が中央寄せでモックの余白に一致する。
- **手順:**
  1. `/search` を開く。
  2. 見出し「公開ノートを検索」・サブテキスト・検索バーの配置を見る。
- **期待結果:** いずれも中央寄せ（`text-center`）。ヒーロー全体は最大幅 720px・検索フォームは最大幅 640px で中央配置。上部余白 64px・下部 24px（PC）。
- **確認ポイント:** 旧実装の左寄せ（`text-left`）になっていないこと。

### 3. 検索結果カードの要素順・タグ表現

- **目的:** 結果カードの要素順とタグ表現がモックと一致する。
- **手順:**
  1. `/search?q=<ヒットするキーワード>` を開く。
  2. 各結果カードの要素の並びとタグの見た目を見る。
- **期待結果:** カード内は「タイトル → スニペット → メタ行」の順。メタ行は「著者（avatar + @username）→ ドット `·` → タグ（accent 色）」。タグは `#tag1 #tag2` のスペース連結で accent 色の単一表示。ドットは著者とタグ群の間に1個だけ。
- **確認ポイント:** 旧実装の「著者が上部・タグがグレーのプレーン表示」になっていないこと。タグ同士がドット区切りになっていない（スペース連結である）こと。更新日時は表示されない（別Issue 対応のため意図的に非表示）。

### 4. ソート表示

- **目的:** ソートラベルの見た目がモックと整合する。
- **手順:**
  1. キーワードで検索し、フィルターバー右側のソート表示を見る。
- **期待結果:** 「関連度順」が読み取り専用ラベルとして表示される。chevron（下矢印）は付かない（ソートは relevance 固定でトグル不能なため、操作可能を誤示唆しない — ADR-002）。
- **確認ポイント:** 押下できそうな見た目（hover 背景・chevron）になっていないこと。

### 5. モバイル表示

- **目的:** モバイル幅でモック（`spec/design/pages/mobile/P32-public-search.html`）に一致する。
- **手順:**
  1. ブラウザ幅を 390px 程度に絞る（または devtools のモバイル表示）。
  2. `/search` とその検索結果を見る。
- **期待結果:** 検索バー高さ 48px、ヒーロー上余白 36px・下 16px。検索バー・ヒーローは中央寄せ。送信ボタンが input 内に収まる（タップ領域 44px 発火時も上下にはみ出さない）。結果カードは単カラム縦積み。
- **確認ポイント:** 送信ボタンが input 下端をはみ出さないこと（ADR-004 の回帰確認）。

## エッジケース・異常系

### 1. キーワード未入力（空状態）

- **目的:** キーワードが無いときの空状態が従来どおり表示される。
- **手順:**
  1. `/search`（クエリなし）を開く。
- **期待結果:** 「まだ検索していません」の空状態が表示され、レイアウト崩れがない。フィルターバー・ソートは表示されない。

### 2. ヒットなし

- **目的:** 該当ノートが無いときの表示が従来どおり。
- **手順:**
  1. `/search?q=<ヒットしないキーワード>` を開く。
- **期待結果:** 「該当するノートが見つかりませんでした」が表示される。

## 既存機能への影響確認

- **検索フォーム送信:** キーワードを入力して「検索」ボタン／Enter で検索が実行され、結果が出る（送信ボタン維持＝既存挙動の維持）。
- **フィルター（ユーザー/タグ/期間）保持:** フィルター適用後にキーワードを再入力しても hidden input でフィルターが保持される（既存挙動）。
- **ページネーション:** 結果が多いとき「次のページ」が表示され遷移できる。
- **結果カードのリンク:** カードをクリックすると該当ノート詳細（`/notes/public/$noteId`）へ遷移する。
