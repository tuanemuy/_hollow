# 動作確認計画 — Issue #486: 設定画面のレイアウトが他画面と一貫していない（Headerと外枠を共有・Sidebarは設定専用を維持）

**Issue:** #486
**作成日:** 2026-06-05

---

## 確認環境

このIssueの変更（設定画面を `/_app` 配下に寄せ、共通 Header + 外枠を共有しつつ設定専用サブナビを維持）を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm db:migrate        # ローカル D1 にマイグレーション適用（未適用なら）
pnpm seed:dev-admin    # ローカル dev 用の認証シード（ログイン可能なユーザー＋セッションを用意）
pnpm dev               # Vite dev サーバー（Cloudflare ランタイム / http://localhost:3000）
```

シードしたセッションでログイン状態にして確認する。Cookie 名は `__Host-session`（Secure 限定で `document.cookie` から設定不可）なので、`pnpm seed:dev-admin` 実行後に出力されるトークン `dev-admin-session-token` を CDP 経由で注入する（manual-test スキルが実施）。

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. 設定画面で共通 Header が表示される

- **目的:** 設定画面の上部 Header が他の認証後画面（`/_app` 配下）と同じ共通 `Header`（ロゴ・検索・新規作成・アップロード・ユーザーメニュー）になっていること。手書きの「← Home」リンク＋「設定」見出しが消えていること。
- **手順:**
  1. ログイン状態で `/settings/profile` を直接開く
  2. ページ上部の Header を確認する
  3. ヘッダー右のユーザーメニュー（アバター）を開く
- **期待結果:** 共通 Header が表示される。「← Home」リンク・独自の「設定」大見出し・サブタイトルは表示されない。
- **確認ポイント:** ロゴクリックでホームへ戻れる、ユーザーメニューが従来どおり開く。

### 2. 左サイドバーが設定専用サブナビになっている

- **目的:** 設定画面の左サイドバーが設定専用サブナビ（プロフィール / セキュリティ / プロンプト / アカウント削除）であり、ライブラリ Sidebar（すべてのノート / 保存ビュー / ディレクトリツリー / タグ / ゴミ箱 / エクスポート / アップロード）が**出ない**こと。
- **手順:**
  1. `/settings/profile` を開く
  2. 左サイドバーの項目を確認する
- **期待結果:** 設定専用の4項目のみが表示される。ライブラリ/管理ナビは表示されない。
- **確認ポイント:** サイドバーの見た目（余白・配色・nav item の体裁）が共通サイドバートークン（`NAV_ITEM` / `SIDEBAR_SECTION`）で他画面と揃っている。

### 3. サブナビのアクティブ状態

- **目的:** 表示中の設定ページに対応するサブナビ項目だけがアクティブ表示されること。
- **手順:**
  1. `/settings/profile` → `/settings/security` → `/settings/prompts` → `/settings/account-delete` と順に遷移する
  2. 各ページで対応するサブナビ項目のアクティブ表示を確認する
- **期待結果:** 表示中ページのナビ項目だけがアクティブ配色（`bg-surface` 系）になり、`aria-current="page"` が付く。
- **確認ポイント:** SPA 遷移でアクティブ表示が即座に追随する。

### 4. コンテナ幅・padding・sticky が他画面と一致

- **目的:** コンテンツ外枠（コンテナ幅・左右 padding・下 padding・サイドバー sticky オフセット）が他の `/_app` 画面と一致していること。
- **手順:**
  1. `/settings/profile` と `/notes`（または `/tags`）を見比べる
  2. ウィンドウ幅を変えて左右 padding とコンテナ最大幅を確認する
  3. コンテンツを下までスクロールしてサイドバーの sticky 位置を確認する
- **期待結果:** 左右 padding は `px-6` 固定（旧 `lg:px-12` の可変ではない）、下 padding は `pb-20`（旧 `pb-24` ではない）、コンテナ幅・sticky オフセットが他画面と同一。
- **確認ポイント:** Header 直下にサイドバーが `top-[var(--header-height)]` で貼り付く（旧 `+32px` オフセットではない）。

### 5. 他の `/_app` 画面のライブラリ Sidebar が従来どおり

- **目的:** 差し替えが設定セクション限定で、他画面ではライブラリ Sidebar が従来どおり表示されること（`staleTime: Infinity` 固定 chrome を壊していない）。
- **手順:**
  1. `/`（ホーム）を開き、左にライブラリ Sidebar（すべてのノート・ディレクトリツリー・管理）が出ることを確認
  2. ホーム → 設定 → ホーム と往復する
- **期待結果:** ホームではライブラリ Sidebar、設定では設定サブナビが出る。往復しても Header が消えない。
- **確認ポイント:** ホーム → 設定 → ホームの往復で余計なローディング（ディレクトリツリーの再取得など）が体感されない（loader 追加 RPC ゼロ）。

### 6. モバイル幅での drawer 表示

- **目的:** モバイル幅で設定サブナビが共通 drawer（オフキャンバス）として動作すること。
- **手順:**
  1. ウィンドウ幅を `lg` 未満（< 1024px）にする
  2. `/settings/profile` でハンバーガーメニューを開く
  3. drawer 内の設定サブナビ項目をタップする
- **期待結果:** drawer に設定サブナビが縦リストで表示され、項目タップで遷移し drawer が閉じる。Escape やバックドロップクリックでも閉じる。
- **確認ポイント:** focus trap が効く（Tab が drawer 内に閉じる）、`lg` に広げると drawer が閉じて in-flow カラムに戻る。

## エッジケース・異常系

### 1. 未認証で設定画面に直アクセス

- **目的:** 未認証時のリダイレクト挙動が `_app` 配下の規約（`/` へ redirect）に統一されていること。
- **手順:**
  1. セッション Cookie を削除（未認証状態）にする
  2. `/settings/profile` に直接アクセスする
- **期待結果:** `/`（landing）へリダイレクトされる（旧挙動の `/login` ではなく `_app` 規約に統一）。
- **確認ポイント:** 設定画面が無防備に表示されない。

### 2. bare `/settings` への遷移

- **目的:** index ルートのない `/settings` への遷移が現状より悪化しないこと。
- **手順:**
  1. ユーザーメニューの「設定」を選ぶ（`/settings` へ navigate）
- **期待結果:** 共通 chrome + 設定サイドバー + 空のメイン領域が表示される（現状の空 Outlet と同等、クラッシュしない）。
- **確認ポイント:** 空白の改善（profile への redirect）は本Issue 対象外（#487）。ここでは悪化していないことのみ確認。

## 既存機能への影響確認

- 各設定フォーム（ProfileForm / SecurityForm / PromptsForm / AccountDeleteForm）の送信が従来どおり動く（unit test でカバー、ルート移動で server-fn action 登録の side-effect import を維持）。
- `internalRouteHead` による各設定ページの head（title / canonical `/settings/xxx`）が公開 URL 不変で維持される。
- `app/routes/_app/__tests__/` 等の既存テストがルート移動で壊れていない（`pnpm test:unit`）。
