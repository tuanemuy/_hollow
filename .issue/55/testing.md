
ブラウザで起動 URL（既定 `http://localhost:3000` 付近、vite が出力する URL）を開き、サインインしたうえで `/tags`（P18 タグ管理画面）にアクセスして確認する。

## 確認項目

### 1. マージダイアログに「対象ノート: N 件」が事前提示される（noteCount > 0）

- **目的:** 統合ダイアログを開いた時点で、source タグの noteCount が表示されることを確認。
- **手順:**
  1. `/tags` 画面で `#alpha`（ノート 3 件紐付け）と `#beta`（ノート 0 件 or 任意）を用意する。
  2. `#alpha` 行の「統合」ボタンをクリック。
  3. ダイアログで `#beta` を選択。
- **期待結果:** 説明文に「**対象ノート: 3 件**」を含む文言が表示される（例: 「#alpha（**対象ノート: 3 件**）を #beta に統合します。…」）。
- **確認ポイント:** 件数が `tag.noteCount` と一致していること。

### 2. マージダイアログに「対象ノート: 0 件」が表示されない（noteCount === 0）

- **目的:** ノート 0 件タグの統合時、件数表示が冗長にならないことを確認。
- **手順:**
  1. ノート 0 件のタグ `#empty` と任意の `#target` を用意する。
  2. `#empty` 行の「統合」ボタンをクリック → `#target` を選択。
- **期待結果:** 説明文に件数フレーズが含まれず、既存文言「#empty を #target に統合します。…」のみ表示される。

### 3. マージ実行中に indeterminate progressbar が描画される（noteCount > 0）

- **目的:** 統合実行中の進捗 UI が機能することを確認。
- **手順:**
  1. ノート 5 件程度紐付いた `#alpha` を `#beta` に統合する。
  2. 「統合」ボタンを押下した直後を観察。
- **期待結果:**
  - フォーム末尾に「**5 件のノートを更新中…**」のテキストが表示される。
  - 直下に薄い横バー（`animate-pulse` でゆるく明滅する）が表示される。
  - 「統合」「キャンセル」ボタンは disabled。
  - 「統合」ボタンのラベルは「統合中...」に切り替わる。
  - `<form>` 要素に `aria-busy="true"` 属性が付与されている（DevTools で確認）。
  - progressbar の `<div>` に `role="progressbar"` + `aria-busy="true"` + `aria-valuemin="0"` + `aria-valuemax="5"` + `aria-label="5 件のノートを更新中"` が付与されている。
  - `aria-valuenow` 属性は**存在しない**（DevTools の要素検査で確認）。
  - 統合完了で `router.invalidate()` 後にダイアログが閉じ、`#alpha` が一覧から消える。

### 4. マージ実行中に progressbar が描画されない（noteCount === 0）

- **目的:** ノート 0 件タグの統合時に progressbar が一瞬出てチラつかないことを確認。
- **手順:**
  1. ノート 0 件の `#empty` を任意の `#target` に統合する。
- **期待結果:** progressbar 描画なし、即座にダイアログクローズ。`#empty` が一覧から消える。

### 5. 削除確認ダイアログに「対象ノート: N 件」が事前提示される（noteCount > 0）

- **目的:** 削除確認ダイアログを開いた時点で noteCount が表示されることを確認。
- **手順:**
  1. ノート 3 件紐付いた `#delete-me` を作成。
  2. 「削除」ボタンをクリック。
- **期待結果:** ConfirmDialog の description に「参照ノートからも除去され、同名タグは今後自動抽出されなくなります（再追加するには手動で再作成が必要）。**対象ノート: 3 件**。続行しますか？」が表示される。

### 6. 削除確認ダイアログで noteCount === 0 のとき件数表示が省略される

- **目的:** ノート 0 件タグの削除確認で件数表示が冗長にならないことを確認。
- **手順:**
  1. ノート 0 件のタグ `#empty` を作成。
  2. 「削除」ボタンをクリック。
- **期待結果:** description に件数フレーズが含まれず、既存文言「参照ノートからも除去され、…続行しますか？」のみ表示される。

### 7. 削除実行中も削除確認ダイアログが開いたまま progressbar が描画される（noteCount > 0）

- **目的:** 削除中もユーザーがコンテキストを失わないことを確認。
- **手順:**
  1. ノート 5 件紐付いた `#delete-me` で「削除」→ ダイアログ内「削除」ボタンを押下。
- **期待結果:**
  - description が「**5 件のノートを更新中…**」+ progressbar に切り替わる。
  - ダイアログは開いたまま。
  - 「削除」「キャンセル」ボタンは disabled。
  - 削除完了で `router.invalidate()` 後にダイアログが閉じ、`#delete-me` が一覧から消える。
  - progressbar の ARIA 属性は確認項目 3 と同じ要件。

### 8. 削除実行中に progressbar が描画されない（noteCount === 0）

- **目的:** ノート 0 件タグの削除でチラつかないことを確認。
- **手順:**
  1. ノート 0 件の `#empty` を削除実行。
- **期待結果:** description は「**削除中…**」のみ（progressbar なし）。即座にダイアログクローズ。

### 9. リネームには進捗 UI が出ない

- **目的:** ADR-004 のスコープ判断通り、リネームに progressbar が出ないことを確認。
- **手順:**
  1. ノート複数件紐付いたタグの「リネーム」を実行。
  2. インライン編集中・保存中の UI を観察。
- **期待結果:** インライン編集 UI のまま「保存」ボタンが disabled になるのみ。progressbar / 件数フレーズは描画されない。

## エッジケース・異常系

### 1. マージのサーバーエラー時

- **目的:** サーバーエラー時に progressbar が消え、エラーが表示されることを確認。
- **手順:**
  1. ネットワーク切断 or 強制的にエラーを起こす（DevTools Network → Offline）。
  2. 統合を実行。
- **期待結果:**
  - progressbar が消える。
  - `MergeTagDialog` 内に既存の `FORM_ERROR` でエラーメッセージが表示される（ダイアログは開いたまま）。
  - 「統合」「キャンセル」ボタンは再度操作可能になる。

### 2. 削除のサーバーエラー時

- **目的:** 削除のエラーパスでダイアログがクローズし、行内 `FORM_ERROR` が表示されることを確認。
- **手順:**
  1. ネットワーク切断状態で削除を実行。
- **期待結果:**
  - 削除確認ダイアログがクローズする。
  - `TagActions` 行内に既存の `FORM_ERROR` でエラーメッセージが表示される。
  - 該当行のボタン群が再度操作可能になる。

### 3. キャンセルでダイアログがクローズする

- **目的:** pre-flight 段階でキャンセルを押した場合、副作用なくクローズすることを確認。
- **手順:**
  1. 統合ダイアログ / 削除確認ダイアログを開き、「キャンセル」を押す。
- **期待結果:** ダイアログがクローズし、何も実行されない。タグ一覧は不変。

### 4. `prefers-reduced-motion: reduce` 設定時にアニメーションが抑制される

- **目的:** `motion-safe:animate-pulse` の効果を確認。
- **手順:**
  1. OS 設定 or DevTools の Rendering タブで `prefers-reduced-motion: reduce` を有効化。
  2. ノート複数件タグで統合実行。
- **期待結果:** progressbar の `animate-pulse` が停止し、静的なバー表示になる（処理中であることは `aria-label` テキストで判別可能）。

### 5. 支援技術での読み上げ

- **目的:** WAI-ARIA indeterminate progressbar の支援技術対応を確認。
- **手順:**
  1. VoiceOver (macOS) や NVDA (Windows) を有効化。
  2. 統合 / 削除を実行。
- **期待結果:**
  - 「N 件のノートを更新中（処理中）」のような読み上げが行われる（読み上げ文言の正確な形式は支援技術依存）。
  - `aria-label` の文言「N 件のノートを更新中」が読み上げに含まれる。
  - 不確定 progressbar として正しく解釈される（「進捗 0%」のような誤った読み上げが行われない）。

## 既存機能への影響確認

- **`ConfirmDialog` を使う他ドメイン（note / view / ingestion / trash）の挙動が変わっていないこと**:
  - 任意のノート削除、ビュー削除等を実行し、確認ダイアログの挙動が従来通りであることを確認（`ConfirmDialog` は無改修のため理論上影響なしだが念のため）。
- **既存のリネーム機能**:
  - インライン編集 + 保存 → タグ名変更 + ノート本文の `#oldName → #newName` 反映が従来通り動くこと。
- **既存のマージ機能**:
  - マージ後の noteCount 集約、source タグ削除、ノート本文への target タグ反映が従来通り動くこと（usecase 無変更）。
- **既存の削除機能**:
  - 削除後の TagBlacklist 登録、参照ノートからのタグ除去が従来通り動くこと（usecase 無変更）。
