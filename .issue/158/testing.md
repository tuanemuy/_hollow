## 確認項目

### 1. P11 「履歴」ボタンが enabled になっている

- **目的:** Issue 受入条件「P11 操作メニューの『履歴』disabled ボタンを enabled に」を満たすこと
- **手順:**
  1. ログイン
  2. ホーム `/` から任意のノートを開く（P11 = `/notes/$noteId`）
  3. 操作メニューを確認
- **期待結果:** 「履歴」ボタンが他の操作（編集 / 公開設定 / 移動 等）と同じスタイルで表示され、クリック可能
- **確認ポイント:** ホバー時に `title="履歴は今後実装予定です"` が出ないこと。disabled 属性が無いこと

### 2. 「履歴」ボタンから履歴一覧画面に遷移できる

- **目的:** 履歴一覧画面 (P11h) のルート `/notes/$noteId/history` が動くこと
- **手順:**
  1. 上記状態から「履歴」ボタンを押す
- **期待結果:** `/notes/$noteId/history` に遷移し、履歴一覧画面が表示される
- **確認ポイント:**
  - 既存ノートで一度も SaveNote が呼ばれていなければ「履歴がありません」の空状態が表示される
  - 既に SaveNote 後なら表形式 or リストで履歴行が見える（作成日時 + タイトル + 「閲覧」リンク）

### 3. SaveNote のたびに履歴が積み上がる

- **目的:** ADR-002 「SaveNote ごとに revision を 1 件作成」が機能していること
- **手順:**
  1. シード後のノート 1 件を P12 エディタで開く
  2. 本文を編集して「保存」ボタンを押す（自動保存ではなく明示保存）
  3. P11 に戻る → 「履歴」ボタン → 履歴一覧画面
  4. 履歴一覧の件数を記録
  5. ノートを再度開いて再編集 → 保存
  6. 再度履歴一覧を開く
- **期待結果:**
  - ステップ 4 の時点で履歴が 1 件追加されている
  - ステップ 6 の時点で履歴が 2 件になっている
  - 並び順は新しい順 (`created_at DESC`)
- **確認ポイント:** 各履歴行のタイトル / 作成日時が編集時点のものと一致

### 4. 自動保存（SaveNoteDraft）では履歴が積み上がらない

- **目的:** ADR-002 で「SaveNoteDraft は revision を作らない」と決めた仕様の確認
- **手順:**
  1. ノートを P12 で開く
  2. 履歴件数を覚えておく
  3. 本文を編集して、明示保存はせずに数秒〜30 秒程度放置（自動保存が走るのを待つ）
  4. 自動保存ステータスが「保存済み」になったのを確認
  5. ブラウザの DevTools Network タブで `saveNoteDraft` server function 呼び出しを確認
  6. 履歴一覧を開く
- **期待結果:** 履歴件数がステップ 2 と同じ（増えていない）
- **確認ポイント:** 自動保存だけでは履歴に乗らないこと

### 5. 履歴詳細から過去版の本文を閲覧できる

- **目的:** `/notes/$noteId/history/$revisionId` 経由で過去版の本文が表示できること
- **手順:**
  1. 確認項目 3 のステップ後（履歴 2 件ある状態）、一覧から古いほうの履歴行をクリック
- **期待結果:**
  - `/notes/$noteId/history/$revisionId` に遷移
  - 過去版のタイトル + 本文（HTML レンダリング）が見える
  - 「この版に復元」ボタンと「履歴一覧に戻る」リンクが表示される
- **確認ポイント:**
  - 過去版の本文が現在の本文と異なる（編集前の内容になっている）
  - 装飾（見出し・リスト等）が正しくレンダリングされる（`.note-detail-content` の CSS が適用されている）

### 6. 「この版に復元」で過去版を本文に書き戻せる

- **目的:** ADR-005 の復元セマンティクス（現在版を新 revision として残しつつ、過去版を Note 本体に書き戻す）が動くこと
- **手順:**
  1. 確認項目 5 で過去版を開いた状態から「この版に復元」ボタン押下
  2. 確認ダイアログで OK
- **期待結果:**
  - 復元成功後、`/notes/$noteId`（P11）に navigate
  - Note の本文が過去版の内容に書き換わっている
  - エディタ (P12) を開き直すと本文も過去版に戻っている
  - 履歴一覧を再度開くと **件数が 1 件増えている**（復元前の状態が新 revision として残った）
- **確認ポイント:**
  - 直近の履歴行（一番上）が、復元直前の本文と一致する
  - その下が、復元元となった過去版と同じ内容（時系列順）

### 7. trashed ノートでは復元ボタンが disabled

- **目的:** trashed Note の履歴は閲覧可能だが復元は不可能なこと（plan D-2 の挙動）
- **手順:**
  1. 任意のノートを 2 回保存して履歴を作る
  2. P11 でそのノートを「削除」（ゴミ箱に移動）
  3. ゴミ箱画面 (P17) でそのノートを見つけてリンクから戻る or 直接 `/notes/$noteId/history` を URL 入力で開く
  4. 履歴一覧で任意の行を開く
- **期待結果:**
  - 履歴一覧は閲覧可能（行が見える）
  - 過去版詳細画面で「この版に復元」ボタンが disabled
  - disabled の理由として「ゴミ箱に入っているノートは復元できません。先に復元してください」相当のテキストが表示される
- **確認ポイント:** クリックしても何も起きない

### 8. 履歴の上限を超えると最古が削除される

- **目的:** ADR-004 の上限ポリシーが機能すること
- **手順:**
  1. 動作確認のため、上限を一時的に小さくする想定（既定 50 のまま全部消化するのは現実的でないので、可能なら一時的に `instance_settings.limits_json` を直接 SQL で書き換えて `maxNoteRevisionsPerNote: 3` 等にする）
     ```bash
     wrangler d1 execute tanstack-start-template-d1 --local --command "UPDATE instance_settings SET limits_json = json_set(limits_json, '$.maxNoteRevisionsPerNote', 3) WHERE id = 'singleton';"
     ```
  2. 任意のノートを 4 回連続で保存（本文を毎回少し変える）
  3. 履歴一覧を開く
- **期待結果:** 履歴件数が **3 件** に揃っている（4 件目の保存時に最古が自動削除されている）
- **確認ポイント:**
  - 3 件は **最新の 3 件**（直近 3 回分の保存）であること
  - 1 番古い保存内容は履歴から消えている
- **後始末:** 確認後に上限を既定値（50）に戻すか、シードを再投入

### 9. 他人のノートの履歴は見えない

- **目的:** 認可チェック (`ForbiddenError`) が機能すること
- **手順:**
  1. テストユーザー A でノートを作成して履歴を残す
  2. （シードに別ユーザーがあれば）テストユーザー B でログイン
  3. A のノート ID で `/notes/<A's noteId>/history` に直接アクセス
- **期待結果:** Forbidden / 403 系のエラー画面が表示される
- **確認ポイント:** B からは A のノートの履歴一覧・履歴詳細・復元 server action のいずれにもアクセスできない

## エッジケース・異常系

### E1. 復元しようとした過去版が、現時点では存在しないメディアを参照している

- **目的:** ADR-005 で言及した「過去のメディアが削除された場合」のエラーパス
- **手順:**
  1. ノートに画像を貼った状態で保存（履歴行 R1 が残る）
  2. 画像を削除して保存（履歴行 R2 が残る）
  3. メディア管理画面 (P19?) or DB 直叩きで該当 media_assets を物理削除（ref_count が 0 になっていれば自動 pruner で消える）
  4. 過去版 R1（画像を参照する版）を開いて「この版に復元」を押す
- **期待結果:** エラー表示「このメディアは所有していません」相当（`BusinessRuleError('media_not_owned')` の i18n 表示）
- **確認ポイント:** Note 本体が壊れていない（部分復元状態にならない、UoW がロールバックする）

### E2. 復元中に他者が同時編集していて OCC 衝突する

- **目的:** Version OCC が機能すること
- **手順:**
  1. ブラウザ A でノートを開いて履歴詳細にアクセス
  2. ブラウザ B（別アカウント or 同一アカウント別タブ）で同じノートを編集 → 保存
  3. ブラウザ A で「この版に復元」を押す
- **期待結果:** ConflictError 相当のエラー表示が出て復元が失敗。「他のセッションで変更されています。再読込してください」相当のメッセージ
- **確認ポイント:** Note 本体は B の編集内容で保たれる

### E3. 他者の編集ロックがある状態で復元しようとする

- **目的:** ADR-005 の「他者の生きたロックがあれば BusinessRuleError」が動くこと
- **手順:**
  1. ブラウザ B で P12 エディタを開いてロックを取得（編集状態を維持）
  2. ブラウザ A で履歴詳細から「この版に復元」を押す
- **期待結果:** `edit_locked_by_other` 相当のエラー表示
- **確認ポイント:** 復元が失敗し、Note 本体は変更されない

### E4. 履歴 0 件の状態で履歴一覧を開く

- **目的:** 空状態 UI の確認
- **手順:**
  1. 既存ノート（シード由来、SaveNote 未経験）を開く
  2. 「履歴」リンクから一覧を開く
- **期待結果:** 「履歴がありません」相当の空状態が表示される
- **確認ポイント:** 500 エラー等が出ない

### E5. 存在しない revisionId で詳細画面を開く

- **目的:** `NotFoundError('REVISION_NOT_FOUND')` のハンドリング
- **手順:**
  1. `/notes/$noteId/history/00000000-0000-7000-8000-000000000000` を URL 入力
- **期待結果:** 404 系の表示

### E6. クロスノートな revisionId（別ノートの履歴 ID を URL 改竄で渡す）

- **目的:** GetNoteRevision での `noteId` 一致チェック
- **手順:**
  1. ノート A の履歴 ID を取得
  2. `/notes/<B's noteId>/history/<A's revisionId>` を URL 入力
- **期待結果:** 404 系（NotFound / Forbidden 相当）

## 既存機能への影響確認

- **SaveNote** の挙動変更: 既存テスト含めて Note 保存後に `note_revisions` に 1 行 INSERT されることを確認。アウトボックスイベント数 (`note.saved` × 1) は変わらない（revision は内部副作用なのでイベントを発火しない）
- **SaveNoteDraft** の挙動変更: 無し。履歴は積み上がらない
- **DeleteNote (trash) → RestoreNote (untrash) → SaveNote** の経路で履歴が一貫すること
- **PurgeNote** 実行時に `note_revisions` も CASCADE で物理削除されること（手動: SQL で `SELECT COUNT(*) FROM note_revisions WHERE note_id = ?` を purge 前後で確認）
- **MediaService.reconcileRefs**: 復元で `mediaRefs` が変わるため、ref_count の inc/dec が正しく走ること（媒体ページから ref_count を確認 or SQL で確認）
- **Outbox / Search 連携**: 復元時に `note.saved` イベントが発火し、検索インデックスが更新されること（検索画面 P10 で復元後の本文が検索ヒットすること）
