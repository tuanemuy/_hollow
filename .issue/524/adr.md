# ADR — Issue #524

## ADR-001: プロトコル相対 URL をスキーム検査に落とさず直接 reject する

**コンテキスト**

`isSafeUrl` は「スキームが無く `/` 始まり」を相対パスとして許可していた。
`//evil.com` もこの分岐に入り通過していた（open-redirect 余地）。

修正方針として、当初は「相対判定から除外して、下流のスキーム allowlist 検査に
落として弾く」案を検討した。しかし `//evil.com` には `:` が無いため、スキーム検査の
`colonIdx <= 0` 分岐で「スキーム無し＝相対パス」とみなされ `true` に戻ってしまう。

**決定内容**

先頭2文字がスラッシュ系のとき `isSafeUrl` の冒頭で **直接 `return false`** する。
スキーム検査には委ねない。

```ts
if (/^[/\\]{2}/.test(value)) return false;
```

**理由**

- `//host` はスキームを持たないため、明示スキーム検査では捕捉できない（相対扱いに戻る）。
  プロトコル相対と判定した時点で確定的に落とすのが唯一安全な選択。
- `http://` 等の正当な絶対 URL は先頭が英字なのでこの分岐に掛からず、従来どおり
  スキーム allowlist で許可される。

## ADR-002: バックスラッシュ変種（`/\`, `\/`, `\\`）も同時に弾く

**コンテキスト**

Issue 本文の対応案は `value.startsWith("//")` のみだったが、ブラウザは URL の authority
区切りでバックスラッシュをスラッシュに正規化することがある（`/\evil.com` → `//evil.com`）。
`//` だけ塞いでも `/\evil.com` 等で同じ外部ホスト解決が起こりうる。

**決定内容**

先頭2文字が「`/` または `\` のいずれか」を2つ並べた形（`/^[/\\]{2}/`）を不許可とする。
これにより `//`, `/\`, `\/`, `\\` の4パターンを一括で弾く。

**理由**

- 単一の `\` 始まり（`\evil.com`）は同一オリジンの絶対パス（`/evil.com`）に正規化される
  だけで外部遷移にならないため、2文字目もスラッシュ系の場合に限定して弾く。
  正当な絶対パス `/media/abc`（2文字目が非スラッシュ）は誤って弾かれない。
- 保守的に弾いても失われる正当なユースケースは無い（サニタイザ通過後に必要なのは
  同一スキーム下の相対/絶対 URL と明示スキーム URL のみ）。

## ADR-003: エンティティ表記によるバイパス（W-001 / W-002）は本 PR で扱わず別 Issue #531 に分離

### Status
Accepted

### Context

review-001 で、本修正が **HTML エンティティ表記でバイパス可能**であることが判明した（実測確認済み）:

- `&#47;&#47;evil.com` / `&sol;&sol;evil.com` → ブラウザは `//evil.com` に解釈（W-001、#524 の再現）
- `&#106;avascript&#58;alert(1)` → ブラウザは `javascript:alert(1)` に解釈（W-002、**XSS**）

根因は `isSafeUrl` が値をデコードせず生のまま部分文字列照合している点。ultrahtml は属性値の
文字参照を literal 保持し、`renderSync` もそのまま再出力するため、ブラウザが最終的にデコードする
URL を `isSafeUrl` が見逃す。

### Decision

本 PR（#529）のスコープは Issue #524 が定義する **literal `//host`** の修正に留め、エンティティ表記
バイパス（W-001 + W-002）は専用 Issue **#531** に分離する。

### Consequences

- 分離の理由:
  1. **完全修正が軽微でない** — 既存 `decodeEntities` は小さな named テーブル＋数値参照のみ対応で、
     `&sol;` / `&colon;` 等のブラウザがデコードする named entity を網羅しない。包括的デコーダの導入か
     検査方式の再設計（URL 解釈 / 文字参照の保守的拒否）が要る。
  2. **#524 の宣言スコープを越える** — W-002 は open-redirect ではなく XSS。Issue #524 本文は明示的に
     「XSS ではない」「//host」を境界としている。
  3. **独立セキュリティレビューが望ましい** — 本 Issue 自体が #493 から「サニタイザのセキュリティ挙動変更は
     独自レビューが望ましい」として分離された経緯があり、同じ方針を踏襲する。
- リスク: #531 が解消されるまで、エンティティ表記の `//host` / `javascript:` は通過し続ける。
  #531 を高優先のセキュリティ課題として明記済み。
- ADR-001 の「プロトコル相対と判定した時点で確定的に落とすのが唯一安全」は **literal 値に対する記述**
  であり、エンティティ表記値は判定前段でデコードされない限り「プロトコル相対」と判定されない点に注意
  （#531 で対応）。
