# ADR — Issue #524

## ADR-001: プロトコル相対 URL をスキーム検査に落とさず直接 reject する

**コンテキスト**

`isSafeUrl` は「スキームが無く `/` 始まり」を相対パスとして許可していた。
`//evil.com` もこの分岐に入り通過していた（open-redirect 余地）。

修正方針として、当初は「相対判定から除外して、下流のスキーム allowlist 検査に
落として弾く」案を検討した。しかし `//evil.com` には `:` が無いため、スキーム検査の
`colonIdx <= 0` 分岐で「スキーム無し＝相対パス」とみなされ `true` に戻ってしまう。

**決定内容**

先頭2文字がスラッシュ系のとき `isSafeUrl` の冒頭で **直接 `return false`** する。
スキーム検査には委ねない。

```ts
if (/^[/\\]{2}/.test(value)) return false;
```

**理由**

- `//host` はスキームを持たないため、明示スキーム検査では捕捉できない（相対扱いに戻る）。
  プロトコル相対と判定した時点で確定的に落とすのが唯一安全な選択。
- `http://` 等の正当な絶対 URL は先頭が英字なのでこの分岐に掛からず、従来どおり
  スキーム allowlist で許可される。

## ADR-002: バックスラッシュ変種（`/\`, `\/`, `\\`）も同時に弾く

**コンテキスト**

Issue 本文の対応案は `value.startsWith("//")` のみだったが、ブラウザは URL の authority
区切りでバックスラッシュをスラッシュに正規化することがある（`/\evil.com` → `//evil.com`）。
`//` だけ塞いでも `/\evil.com` 等で同じ外部ホスト解決が起こりうる。

**決定内容**

先頭2文字が「`/` または `\` のいずれか」を2つ並べた形（`/^[/\\]{2}/`）を不許可とする。
これにより `//`, `/\`, `\/`, `\\` の4パターンを一括で弾く。

**理由**

- 単一の `\` 始まり（`\evil.com`）は同一オリジンの絶対パス（`/evil.com`）に正規化される
  だけで外部遷移にならないため、2文字目もスラッシュ系の場合に限定して弾く。
  正当な絶対パス `/media/abc`（2文字目が非スラッシュ）は誤って弾かれない。
- 保守的に弾いても失われる正当なユースケースは無い（サニタイザ通過後に必要なのは
  同一スキーム下の相対/絶対 URL と明示スキーム URL のみ）。
