# 動作確認計画 — Issue #616: ランディングページの「公開検索」「エクスポート」リンク修正

**Issue:** #616
**作成日:** 2026-06-10

---

## 確認環境

このIssueはランディングページのリンクのみのフロントエンドDOM変更で、DBアクセスやマイグレーションは伴わない。未認証で到達できるランディングページ（`/`）の表示・遷移を確認すれば足りる。

### 検証環境の起動

```bash
pnpm dev
```

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. Teaser「公開検索を試す」が /search へ遷移する

- **目的:** teaser のリンクが公開検索ルートへ正しく繋がること。
- **手順:**
  1. 未ログイン状態でランディングページ（`/`）を開く。
  2. 「公開ノートを覗いてみる」セクションの「公開検索を試す」ボタンをクリック。
- **期待結果:** `/search` に遷移し、公開検索ページが表示される（ホーム `/` に戻らない）。
- **確認ポイント:** URL が `/search` であること。検索ページの UI が描画されること。

### 2. Footer「公開検索」が /search へ遷移する

- **目的:** フッターのプロダクト列「公開検索」リンクの遷移先。
- **手順:**
  1. ランディングページのフッター「プロダクト」列の「公開検索」をクリック。
- **期待結果:** `/search` に遷移する。

### 3. Footer に「エクスポート」リンクが存在しない

- **目的:** 認証必須機能への不適切な直リンクが削除されていること。
- **手順:**
  1. ランディングページのフッター「プロダクト」列を確認。
- **期待結果:** 列が「機能 / 公開検索」の 2 項目になっており、「エクスポート」リンク・テキストが存在しない。
- **確認ポイント:** レイアウト崩れがないこと。

## エッジケース・異常系

### 1. /search への遷移で検索パラメータが不要

- **目的:** `search={{ q: "", limit: 20 }}` で遷移しても検索ページがエラーにならないこと。
- **手順:**
  1. 上記項目 1・2 の遷移後、コンソールにエラーが出ていないか確認。
- **期待結果:** 空キーワードの公開検索ページが正常表示され、ランタイムエラーが出ない。

## 既存機能への影響確認

- ヘッダーのブランドロックアップ（Hollow ロゴ）クリックで `/` に戻ること（変更していないので従来通り）。
- フッターのインスタンス列・法的事項列のリンク（`/about` `/terms` `/privacy` 等）が従来通り機能すること。
