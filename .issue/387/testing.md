# 動作確認計画 — Issue #387: サイドバーでディレクトリを選択してもノート一覧が変わらない

**Issue:** #387
**作成日:** 2026-05-31

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載（プロジェクト全体のセットアップは省略）。

### 検証環境の起動

ソース変更をライブで確認するため Vite 開発サーバーを使う（`pnpm start` は事前ビルド済み dist を配信するためソース変更が反映されない）。

```bash
pnpm db:migrate   # ローカル D1 にマイグレーション適用（未適用の場合のみ）
pnpm dev          # vite dev でライブソースを配信
```

### デプロイ方法

検証環境（`pnpm dev`）のみで確認可能。ステージング反映が必要な場合は `pnpm deploy:staging`（Phase 2 では実行しない）。

## 確認項目

### 1. サイドバーのディレクトリ選択がノート一覧に反映される（本Issueの核心）

- **目的:** ディレクトリ選択（キーワードなし＝フィルタ経路）で一覧が当該ディレクトリ直下のノートに切り替わる。
- **手順:**
  1. ログインしてホーム（`/`）を開く。複数ディレクトリと、各ディレクトリに異なるノートがあるシード状態にする。
  2. 検索ボックスは空のまま、サイドバーの DirectoryTree であるディレクトリ名をクリック。
  3. URL に `?directoryId=xxx` が付くことを確認。
  4. ノート一覧の表示を確認。
- **期待結果:** 一覧が選択ディレクトリ直下のノートだけに切り替わる（修正前は全ノートのまま変わらない）。
- **確認ポイント:** 別ディレクトリを選び直すと一覧も追従して切り替わること。

### 2. 選択中ディレクトリがフィルターチップで可視化される

- **目的:** 選択中ディレクトリが FilterBar にチップ表示される。
- **手順:**
  1. 項目1でディレクトリを選択した状態にする。
  2. FilterBar を確認。
- **期待結果:** 選択中ディレクトリ名のチップ（解除用 `×` 付き）が表示される。「クリア」ボタンも表示される。
- **確認ポイント:** チップのラベルがディレクトリ名であること（ID 露出や空ラベルでない）。

### 3. チップの `×` で directoryId が解除される

- **目的:** チップ単体解除で directoryId が外れ一覧が全ノートに戻る。
- **手順:**
  1. ディレクトリ選択中の状態でチップの `×` をクリック。
- **期待結果:** チップが即座に消え、URL から `directoryId` が外れ、一覧が全ノートに戻る。
- **確認ポイント:** クリック直後にチップが即時に消える（loader 往復待ちでもたつかない＝optimistic 反映）。

### 4. 「クリア」ボタンで directoryId を含む全フィルタが解除される

- **目的:** clearAll で directoryId も落ちる。
- **手順:**
  1. ディレクトリ選択＋タグや期間など他フィルタも併用した状態にする。
  2. 「クリア」ボタンをクリック。
- **期待結果:** directoryId を含む全フィルタが外れ、`q`（検索文字列）と display は保持される。一覧が全ノートに戻る。

### 5. キーワード検索と併用してもディレクトリ絞り込みが効く

- **目的:** 検索経路（キーワードあり）でも directoryId が効く（既存挙動の非回帰）。
- **手順:**
  1. ディレクトリを選択した状態で検索ボックスにキーワードを入力。
- **期待結果:** 当該ディレクトリ配下＋キーワードに一致するノートが表示される（検索経路はサブツリー一致）。

## エッジケース・異常系

### 1. 削除済み等でツリーに無い directoryId を URL に直接指定

- **目的:** 名前解決できない directoryId でも画面が壊れない。
- **手順:**
  1. URL に存在しない（が形式は正当な）`?directoryId=非実在ID` を直接入力して開く。
- **期待結果:** エラー境界に落ちず、一覧は空（該当なし）で表示。チップは汎用ラベル「ディレクトリ」でフォールバック表示される。

### 2. 子ディレクトリを持つ親ディレクトリを選択（直下のみ仕様の確認）

- **目的:** ADR-001 の「直下equality一致」仕様を確認。
- **手順:**
  1. 親ディレクトリ直下にノートを置かず、子ディレクトリにのみノートを置く。
  2. キーワードなしで親ディレクトリを選択。
- **期待結果:** 子ディレクトリのノートは表示されない（直下のみ）。これは仕様（検索経路のサブツリー一致とは非対称）。

## 既存機能への影響確認

- タグ／期間／公開状態／内部リンク参照フィルタが従来どおり単独・併用で動作すること（directoryId 追加でフィルタ連鎖が壊れていないか）。
- SavedView 復元時、保存済み directoryId が（従来の無視から）フィルタとして効くようになる点を確認（望ましい挙動変化）。
- ページネーション：フィルタ適用後の件数・ページ送りが整合すること。
