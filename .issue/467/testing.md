# 動作確認計画 — Issue #467: WAI-ARIA Menu パターンを共通プリミティブ（Popover/Menu）に抽出する

**Issue:** #467
**作成日:** 2026-06-05

---

## 確認環境

このIssueの変更（4つのメニュー/ポップオーバーを共通プリミティブに載せ替え、ハイライト/disabled 方針を統一）を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm db:migrate        # ローカル D1 にマイグレーション適用（未適用なら）
pnpm seed:dev-admin    # ローカル dev 用の認証シード（ログイン可能なユーザーを用意）
pnpm dev               # Vite dev サーバー（Cloudflare ランタイム）
```

シードしたユーザーでログイン後、対象の4箇所を開いて確認する:
- ヘッダーのアバター（UserMenu）
- ディレクトリツリーの `︙` 操作メニュー（DirectoryActionsMenu、サイドバー）
- ノート詳細の `⋯` overflow メニュー（NoteActionsMenu）
- ノート一覧の絞り込みポップオーバー（FilterBar の公開状態 / 期間）

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. 4メニューの基本開閉とキーボードナビ（roving tabindex）

- **目的:** 共通プリミティブ化後も 4箇所すべてで開閉・矢印キー移動・Home/End・Esc クローズが従来どおり動くこと。
- **手順:**
  1. 各メニュー（UserMenu / DirectoryActionsMenu / NoteActionsMenu / FilterBar の公開状態）をトリガーのクリックで開く
  2. ↓↑ で項目間を移動、Home/End で先頭/末尾へ移動
  3. Esc を押して閉じる
- **期待結果:** 開くと先頭（公開状態ポップオーバーは選択中項目）にフォーカスが乗る。矢印キーでフォーカスが循環移動する。Esc で閉じ、フォーカスがトリガーへ戻る。
- **確認ポイント:** フォーカスが乗った項目だけが `tabindex=0`、他は `tabindex=-1`（roving）。

### 2. メニュー項目ハイライトの統一（focus-visible）

- **目的:** マウスで開いた瞬間に先頭項目がグレー化しないこと（コメント1 / #463 の方針を全メニューに統一）。特に DirectoryActionsMenu の残存バグが解消されていること。
- **手順:**
  1. DirectoryActionsMenu（`︙`）を**マウスクリック**で開く
  2. 続けて NoteActionsMenu（`⋯`）、UserMenu をマウスクリックで開く
  3. 各メニューで一度マウスを離した状態のまま、開いた直後の先頭項目の背景を見る
  4. 次にキーボード（↓キー）で項目を移動する
- **期待結果:** マウスで開いた瞬間は先頭項目がグレー背景にならない。キーボードで移動するとフォーカス項目にグレー背景（danger 項目は赤系背景）が付く。
- **確認ポイント:** マウス開時のグレー化が DirectoryActionsMenu で無くなっていること（修正前は残存していた）。

### 3. danger 項目の表示と活性化

- **目的:** 削除・ログアウト等の danger 項目が赤系で表示され、選択でダイアログ/動作が起動すること。
- **手順:**
  1. DirectoryActionsMenu の「削除」、NoteActionsMenu の「削除」、UserMenu の「ログアウト」を確認
  2. キーボードで danger 項目にフォーカスし Enter / クリックで活性化
- **期待結果:** danger 項目は赤系テキスト、フォーカス時に赤系背景。活性化で削除ダイアログ表示 or ログアウト動作。
- **確認ポイント:** 活性化時にメニューが閉じ、ダイアログを開く場合はダイアログにフォーカスが移る（runAndClose のフォーカス連携）。

### 4. UserMenu のログアウト pending 中の disabled 表現

- **目的:** native disabled → aria-disabled 統一後も、ログアウト処理中にログアウト項目が無効化されつつ roving に残ること。
- **手順:**
  1. UserMenu を開きログアウトをクリック（pending 状態を作る）
  2. pending 中にログアウト項目の見た目・フォーカス可否を確認
- **期待結果:** pending 中のログアウト項目は薄く（opacity）表示・カーソル not-allowed、ただしフォーカスは可能（roving から外れない）。再クリックは no-op。他の項目（設定）は無効化されない。
- **確認ポイント:** pending 中の danger×disabled 項目にマウスを乗せても hover 背景が付かない（`not-aria-disabled:` ガード）。

### 5. NoteActionsMenu の各操作（基準実装の回帰）

- **目的:** アイコン・区切り線・各操作（複製/履歴/削除など）が従来どおり表示・動作すること。
- **手順:**
  1. ノート詳細で `⋯` を開く
  2. 各項目のアイコン、区切り線の位置を確認
  3. 各操作を実行
- **期待結果:** アイコン・区切り線が従来どおり。各操作が正しく起動。
- **確認ポイント:** 移行で DOM 構造（aria-label・項目順）が変わっていないこと。

### 6. FilterBar の公開状態ポップオーバー（menu モード）

- **目的:** 公開状態フィルタ（menuitemradio）が選択中項目に着地し、選択で即座に反映・クローズすること。
- **手順:**
  1. ノート一覧で公開状態フィルタのチップ/ボタンを開く
  2. 開いた直後のフォーカス位置（選択中の項目に乗るか）を確認
  3. 別の選択肢を選ぶ
- **期待結果:** 開くと現在の選択肢（initialIndex）にフォーカスが乗り `aria-checked`/選択中表示（`data-active`）が維持される。選択でフィルタ反映＋クローズ。
- **確認ポイント:** 選択中表示（`data-[active]` の背景・太字）が消えていないこと。マウス開時に先頭がグレー化しないこと。

### 7. FilterBar の期間ポップオーバー（dialog モード）

- **目的:** 期間フォーム（role=dialog）が従来どおり開閉・入力・クリアできること。
- **手順:**
  1. 期間フィルタのトリガーを開く
  2. 日付を入力、外側クリック / Esc で閉じる、クリア操作
- **期待結果:** dialog として開き、フォーム入力・クリアが動く。外側クリック / Esc / focus-out で閉じる。
- **確認ポイント:** dialog モードのフォーム操作中に意図せず閉じないこと。

### 8. shiftX 水平クランプ（折返しツールバー）

- **目的:** FilterBar が折り返してトリガーが右端寄りにあるとき、ポップオーバーがビューポート外に出ず水平クランプされること。
- **手順:**
  1. ウィンドウ幅を狭めて FilterBar のトリガーを右端寄りに配置
  2. 公開状態 / 期間ポップオーバーを開く
- **期待結果:** パネルがビューポート右端で見切れず、内側にずれて（translateX）表示される。
- **確認ポイント:** クランプの挙動が修正前と同等。

## エッジケース・異常系

### 1. DirectoryActionsMenu のツリー操作との干渉

- **目的:** ツリー項目（treeitem）上のメニュートリガーで、クリック/キー操作がツリーのナビと二重発火しないこと。
- **手順:**
  1. ディレクトリツリーで treeitem の `︙` をクリックして開く
  2. メニュー内で矢印キー移動、treeitem への伝播が起きないか確認
- **期待結果:** メニュートリガーのクリックで treeitem の選択/遷移が起きない（stopPropagation+preventDefault）。メニュー内矢印キーが DirectoryTree の Arrow ナビと二重発火しない。
- **確認ポイント:** メニューを閉じた後、treeitem のキーボードナビが正常に戻ること。

### 2. 外側クリック / focus-out クローズ

- **目的:** 各メニュー/ポップオーバーが外側 mousedown・focus-out で閉じること。
- **手順:**
  1. 各メニューを開き、メニュー外の領域をクリック
  2. 開いた状態で Tab して focus がメニュー外へ出る操作
- **期待結果:** 外側 mousedown / focus-out で閉じる。
- **確認ポイント:** トリガー自身のクリックで開閉トグルが正しく動くこと。

## 既存機能への影響確認

- UserMenu / DirectoryActionsMenu / NoteActionsMenu / FilterBar の公開状態・期間ポップオーバーすべてが、移行前と同じ見た目・操作感で動くこと。
- ノート詳細の削除・移動などのダイアログがメニューから正しく開き、フォーカスがダイアログに移ること（runAndClose の連携）。
