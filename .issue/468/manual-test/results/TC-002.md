## 手順からの逸脱（結果は PASS 判定）

- **seed id**: testing.md 手順2の id `'test-468-abandoned'` は UUIDv7 形式でないため、リポジトリの再水和検証（`app/core/application/ports/idGenerator.ts` の `UUID_V7_PATTERN` / `app/core/adapters/d1/repositories/mediaAssetRepository.ts` `toMediaAsset`）で `DATA_INTEGRITY_ERROR` になり sweep 対象にできない。UUIDv7 形式の id に変更して実施した（識別は storage_key の `test-468-abandoned` で担保）。testing.md の seed SQL は要修正。
- **outbox 確認 SQL**: testing.md の `SELECT event_type, status FROM outbox_events ...` は実スキーマに `status` 列がなく `SQLITE_ERROR`。`processed_at` 等の実在列に置き換えて確認した。testing.md の SQL は要修正。

## 補足観察

- 手順2の失敗時、malformed id の行が1件あると sweep ステップ全体が失敗する（per-row ではなく一覧の再水和で throw）。アプリ生成の id は常に UUIDv7 なので実運用では発生しない想定だが、sweep 失敗が独立 try/catch で swallow され tick が完走することはこの失敗で実地確認できた（TC-004 の傍証）。
