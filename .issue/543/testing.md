# 動作確認計画 — Issue #543: 領域4「設定」(P21〜P24) のモック実装追従

**Issue:** #543
**作成日:** 2026-06-07

---

## 確認環境

本 Issue はフロントエンドの設定画面（P21 プロフィール / P22 セキュリティ / P23 プロンプト / P24 アカウント削除）をデザインモックへ追従させる変更。新規 backend は無い。実機確認はローカル開発サーバで行う。

### 検証環境の起動

```
pnpm dev
```

`vite dev`（Cloudflare ランタイム）でローカルサーバが起動する。表示された URL をブラウザで開き、**ログイン済みユーザー**で `/settings`（→ `/settings/profile` 等）の各画面を確認する。確認には少なくとも以下を持つユーザーが望ましい:

- 自己紹介(bio) が入力済みのユーザー（文字数カウンタの初期値確認用）と、空のユーザー
- ユーザー名が設定済みのユーザー（公開 URL プレビュー確認用）

> `APP_URL` env が設定されていれば公開 URL プレビューは `{APP_URL}/u/<username>` 形式、未設定なら相対 `/u/<username>` へフォールバックする。両方の挙動を見るには env の有無を切り替える。

### デプロイ方法

なし（検証環境のみで確認できる。ステージング反映が必要な場合は `pnpm deploy:staging`）。

## 確認項目

### 1. 設定ナビの「すべてのノートに戻る」戻り導線（A）

- **目的:** P21〜P24 全画面の左サイドバー最上部に戻り導線が表示され、クリックでホームに戻れる。
- **手順:**
  1. `/settings/profile` を開く。
  2. 左サイドバー最上部に ArrowLeft アイコン + 「すべてのノートに戻る」が表示されることを確認。
  3. クリックしてホーム（`/`）に遷移することを確認。
  4. `/settings/security`・`/settings/prompts`・`/settings/account-delete` でも同じ戻り導線が出ることを確認。
- **期待結果:** 4 画面すべてで戻り導線が表示され、ホームへ正しく遷移する。
- **確認ポイント:** モック `.sidebar-back`（hover で surface 背景）に近い見た目か。アイコンとラベルの間隔・色（ink-secondary）。

### 2. P21 プロフィール — 自己紹介の文字数カウンタ（B-2）

- **目的:** bio textarea の下に「現在文字数 / 500」が表示され、入力に追従する。
- **手順:**
  1. `/settings/profile` を開く。
  2. 自己紹介 textarea 直下のカウンタが初期値（既存 bio の文字数）/ 500 を表示することを確認。
  3. 文字を入力・削除し、カウンタがリアルタイムに更新されることを確認。
- **期待結果:** カウンタが `N / 500`（**160 ではなく 500**）で表示され、入力に同期する。
- **確認ポイント:** 上限は backend 実値 500。モックの 160 が残っていないこと。右寄せ・小さめ・ink-tertiary 系の見た目。

### 3. P21 プロフィール — ユーザー名 URL prefix・公開URLプレビュー・レート制限ヘルプ（B-3）

- **目的:** ユーザー名 input に公開 URL の prefix が前置され、入力中の値で公開 URL プレビューが出て、30日レート制限ヘルプが表示される。
- **手順:**
  1. `/settings/profile` のユーザー名変更フォームを開く。
  2. input の左に prefix（`{APP_URLのホスト}/u/` 相当）が表示されることを確認。
  3. ユーザー名を入力すると、プレビュー行が `{APP_URL}/u/<入力値>` に更新されることを確認（末尾スラッシュの二重化 `//u/` が起きないこと）。
  4. レート制限ヘルプ「ユーザー名は30日に1回まで変更できます。」が表示されることを確認。
- **期待結果:** prefix・プレビューが実 appUrl ベースで表示される（**hollow.example のダミーは出ない**）。ヘルプは **30日**（90日ではない）。
- **確認ポイント:** 「次に変更できる日付」のような算出値は出していないこと（虚偽表示回避）。`APP_URL` 未設定時は相対 `/u/` フォールバックになること。

### 4. P22 セキュリティ — 新パスワード強度ヘルプ（C-2）

- **目的:** 「新しいパスワード」input の下に実 domain ルールに沿った強度ヘルプが出る。
- **手順:**
  1. `/settings/security` のパスワード変更セクションを開く。
  2. 「新しいパスワード」input 直下に「12文字以上。英字・数字・記号のうち2種以上を含めてください。」相当のヘルプが表示されることを確認。
- **期待結果:** ヘルプ文言が実バリデーション（12文字以上 + 2種以上）と一致する。
- **確認ポイント:** スクリーンリーダー用に input と `aria-describedby` で関連付けられていること。

### 5. P24 アカウント削除 — 「取り消せません」強調（E-1）

- **目的:** section-desc の「取り消せません」が強調表示される。
- **手順:**
  1. `/settings/account-delete` を開く。
  2. 説明文の「取り消せません」が太字（font-medium / ink）で強調されていることを確認。
  3. 既存の削除確認（「続けて削除する」→ ConfirmDialog でユーザー名一致）が従来どおり動くことを確認。
- **期待結果:** 強調が反映され、削除確認フロー（ユーザー名一致）は不変。
- **確認ポイント:** 多段確認（DELETE 語入力・パスワード再入力）や影響リストは**追加されていない**こと（スコープ外）。

### 6. section-desc 文言整合（B-1 / C-1 / D-1）

- **目的:** 各設定画面の見出し直下 desc がモック文言に整合する。
- **手順:** P21（プロフィール）/ P22（パスワード変更・メール変更）/ P23（カスタムプロンプト）の各 section-desc をモック（`spec/design/pages/P2*.html`）と並べて目視比較。
- **期待結果:** desc の有無・文言がモックに寄っている。
- **確認ポイント:** P22 のメール変更が「現在のパスワード」を要求する点、P23 の 5 用途・各カード独立保存は**実装が正のまま**変わっていないこと（ADR-005）。

## エッジケース・異常系

### 1. APP_URL 未設定時のフォールバック

- **目的:** appUrl が空でも公開 URL プレビューが誤誘導にならない。
- **手順:** `APP_URL` env を外して `pnpm dev` を起動し、`/settings/profile` のユーザー名 prefix/プレビューを確認。
- **期待結果:** ホスト prefix を出さず相対 `/u/<username>` で表示される（ダミードメインを出さない）。

### 2. bio を上限（500）まで入力

- **目的:** カウンタと maxLength が上限で破綻しない。
- **手順:** bio に 500 文字付近を入力し、カウンタ表示と入力制御を確認。
- **期待結果:** カウンタが `500 / 500` 付近を正しく表示し、`maxLength` で超過入力が抑止される。

## 既存機能への影響確認

- **設定シェルのドロワー a11y**: モバイル幅でドロワーを開き、戻り導線が focus-trap 内で Tab 到達可能（最上部 = Tab 先頭）・Esc で閉じることを確認。
- **ProfileForm の props 追加（appUrl）**: 表示名・自己紹介の保存、ユーザー名変更の送信が従来どおり動くことを確認（prop 追加でフォーム送信が壊れていないか）。
- **AccountDeleteForm の削除フロー**: ユーザー名一致の確認ダイアログ経由の削除が従来どおり動くこと。
