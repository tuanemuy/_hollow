## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。スキーマ変更はないためマイグレーション追加は不要（既存 DB をそのまま使う）。

### 検証環境の起動

ソース変更を実機で確認するには、ビルド済み dist を配信する `pnpm start` の前に `pnpm build` が必須（`pnpm start` = `wrangler dev` は prebuilt dist を配信するため）。

```bash
pnpm build
pnpm start
```

ローカルの開発サーバー（ライブソース）で確認する場合は以下でもよい:

```bash
pnpm dev
```

DB が未初期化の場合のみローカルマイグレーション適用:

```bash
pnpm db:apply:local
```

なし（検証環境のみで確認できる）。

## 確認項目

### 1. パンくず中間セグメントが各ディレクトリのリンクになる

- **目的:** `directorySegments` 拡張により、葉だけでなく中間セグメントも `?directoryId=...` リンクになることを確認する。
- **前提:** 2段以上のディレクトリ階層（例: `親 / 子`）に属するノートが1件以上ある。
- **手順:**
  1. 上記階層に属するノートの詳細ページ `/notes/$noteId` を開く。
  2. ページ上部のパンくず「すべてのノート › 親 › 子 › <ノートタイトル>」を確認する。
  3. 各ディレクトリセグメント（親 / 子）のリンクをそれぞれクリックする。
- **期待結果:** 各セグメントが個別のリンクで、クリックするとホーム `/` がそのディレクトリの `directoryId` で絞り込まれた状態に遷移する。
- **確認ポイント:** 中間セグメント（親）もリンクになっていること（従来はプレーンテキスト）。表示名がディレクトリ名（slug ではなく name）であること。

### 2. ルート直下ノートはディレクトリセグメントが出ない

- **目的:** root 直下ノートで `directorySegments` が空配列になり、ディレクトリリンクが描画されないことを確認する（ADR-002 の挙動踏襲）。
- **手順:**
  1. どのディレクトリにも入れていない（ルート直下の）ノートの詳細ページを開く。
  2. パンくずを確認する。
- **期待結果:** 「すべてのノート › <ノートタイトル>」のみが表示され、ディレクトリセグメントのリンクは出ない。

### 3. バックリンクカードに抜粋が表示される

- **目的:** `BacklinkDTO.snippet` 拡張により、バックリンクカードに参照元本文の抜粋が表示されることを確認する。
- **前提:** ノート A の本文から `[[ノート B]]` でノート B を参照しているデータがある（B の詳細を開くと A がバックリンクに出る）。
- **手順:**
  1. 参照される側のノート B の詳細ページを開く。
  2. 本文下部の「バックリンク」セクションを確認する。
  3. ノート A のカードを確認する。
- **期待結果:** カードにタイトル（A のタイトル）に加えて、A 本文の抜粋テキストが補助表示される。
- **確認ポイント:** 抜粋がプレーンテキスト（HTML タグが残らない）であること。

## エッジケース・異常系

### 1. 本文が空のバックリンク元

- **目的:** 参照元ノートの本文が実質空（`<p></p>` 等）のとき、snippet が `null` 扱いされ抜粋行が描画されないことを確認する。
- **手順:**
  1. 本文がほぼ空のノートから別ノートを参照するデータを用意する。
  2. 参照される側のノート詳細でバックリンクカードを確認する。
- **期待結果:** カードはタイトルのみ表示され、空の抜粋行や余分な余白が出ない。

### 2. バックリンクなし

- **目的:** バックリンクが0件のとき従来どおり「なし」が表示されることを確認する（既存挙動の非回帰）。
- **手順:** どこからも参照されていないノートの詳細を開き、バックリンクセクションを確認する。
- **期待結果:** 「なし」と表示される。

## 既存機能への影響確認

- **パンくず葉リンクの絞り込み:** 従来「葉ディレクトリのみリンク」だった挙動が「全セグメントリンク」に変わる。葉セグメントのリンク先（ホームの directoryId 絞り込み）が従来と同じ結果になることを確認する。
- **検索インデックス:** `directoryPath`（slug パス）は据え置きのため、検索結果・インデックス再構築に影響がないことを念のため確認する（`directorySegments` は DTO 追加のみ）。
