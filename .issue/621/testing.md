# 動作確認計画 — Issue #621: 公開ページのコンテナ幅が中身依存で可変になる

**作成日:** 2026-06-10

## 確認環境

このIssueは `app/components/public/styles.ts` の `PUBLIC_MAIN` / `NOTE_DETAIL_WRAP` に `w-full` を足すだけの CSS（Tailwind ユーティリティ）変更。DB スキーマ変更・migration・新規環境変数はなし。公開ページ（P30/P31/P32）を閲覧するには公開ノートを持つユーザーのシードデータが必要。

```bash

pnpm dev              # vite dev + workerd 経由でアプリ起動
```

### シードデータ

```bash

```

> 公開ページの確認には「公開ノートを複数持つユーザー」が必要。シードに公開ノートが含まれない場合は、ログイン後にノートを数件作成し公開設定にして用意する（manual-test スキルがシード整備を担当）。

## 確認項目

### 1. P30 ユーザー公開トップのコンテナ幅が一定

- **目的:** `PUBLIC_MAIN` への `w-full` 追加で、コンテナ幅がビューポート依存（max-width 上限・中央寄せ）になり、中身に引っ張られなくなること
- **手順:**
  1. `/u/{username}`（公開ノートを複数持つユーザー）を開く
  2. ブラウザ幅を 500px → 600px → 700px → 900px と変化させる
  3. ノートリスト・プロフィール領域の左右端の位置を観察する
- **期待結果:** コンテナ幅は常に `min(ビューポート - padding, --container-max)` で中央寄せ。最長のノートタイトル・日付の有無で幅が伸び縮みしない
- **確認ポイント:** 600px 付近でリスト全体の幅がガタつかないこと

### 2. P31 ノート詳細のコンテナ幅が一定

- **目的:** `NOTE_DETAIL_WRAP` への `w-full` 追加で、詳細ラッパーが全幅化（max-w-[920px] 上限・中央寄せ）すること
- **手順:**
  1. `/u/{username}/{noteSlug}` を開く
  2. ブラウザ幅を 500px〜1000px の範囲で変化させる
  3. パンくず・タイトル・本文・関連セクションの左右端を観察する
- **期待結果:** ラッパー幅は常に `min(ビューポート - padding, 920px)` で中央寄せ。本文の最長行に依存して幅が変わらない

### 3. P32 公開検索のコンテナ幅が一定

- **目的:** `PUBLIC_MAIN` を使う検索ページも同様に幅が安定すること
- **手順:**
  1. `/search` を開き、キーワード検索してヒットを表示させる
  2. ブラウザ幅を 500px〜900px で変化させる
  3. 検索ヒット行・フィルターバーの左右端を観察する
- **期待結果:** コンテナ幅が中身に依存せず一定。600px 付近でガタつかない

## エッジケース・異常系

### 1. 空状態でも幅が安定

- **目的:** ノート 0 件 / 検索ヒット 0 件でも幅が崩れないこと
- **手順:** 公開ノートのないユーザーの `/u/{username}`、またはヒット 0 件の `/search?q=...` を開く
- **期待結果:** 空状態メッセージが中央寄せコンテナ内に収まり、幅は max-width 上限で一定

## 既存機能への影響確認

- **P33 共有ゲート（`/share/{token}`）/ P34 エラー / terms・about・privacy** — `flex-1` を持つ対照群。`w-full` 追加の影響を受けないため、レイアウトが従来どおり全幅・中央であることを確認する
- **フッター** — `PUBLIC_FOOTER_INNER` は本変更対象外。フッターの中央寄せ・最大幅が従来どおりであることを確認する
