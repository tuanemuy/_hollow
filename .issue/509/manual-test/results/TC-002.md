## 失敗詳細（シードデータの不備 — #509 実装とは無関係）

初回ロードで `SystemError: Stored export_job violates invariants`（`<JobsSection>` でエラーバウンダリ発火、一覧全体が「読み込めませんでした」に）。原因は `.issue/509/manual-test/seed-data.md` のシード SQL がドメイン不変条件に違反していたこと。一覧クエリは全行を `ExportJob.reconstruct` で復元するため、1 行でも不正だと一覧全体が落ちる。

検出した不正（修正済み）:

1. `options_json` のキー名が全 6 行で誤り。`{"includeMedia":..}` / `{"paperSize":"a4"}` と書かれていたが、ドメイン/アダプタは `embedMedia` / `pdfPaperSize` を期待（実コードの既存行は `{"includeFrontMatter":..,"embedMedia":..,"pdfPaperSize":..}`）。
2. pdf 行（...112）の用紙サイズが `"a4"`。`PdfPaperSize` は `"A4" | "Letter"` のみ受理（`assertPdfOptions`/`PdfPaperSize.create` で reject）。
3. failed 行（...113）・cancelled 行（...114）の `completed_at` が null。`reconstructByStatus` は failed/cancelled に `completedAt` 必須。

いずれも検証用テストフィクスチャの不備であり、#509 のスタイリング実装の欠陥ではない。検証続行のため D1 の該当行を正しいスキーマに UPDATE して解消した。
