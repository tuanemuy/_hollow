# 動作確認計画 — Issue #697: ノート編集画面: FrontMatterモードを廃止し、メタデータを下部に常設

**Issue:** #697
**作成日:** 2026-06-13

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm db:migrate   # ローカル D1 にマイグレーション適用（初回・未適用時のみ）
pnpm dev          # http://localhost:3000
```

確認には以下のシードが必要:

- ノートが複数件（編集画面 `/notes/$noteId/edit` を開くため）。なければノート作成画面（`/notes/new`）から作成する。
- **FrontMatter を持つノート**を1件用意すると、下部メタデータ領域に既存キーが表示されることを確認しやすい。新規作成画面の「HTML」タブ等で保存後、下部メタデータ領域からキーを追加して保存しておく。
- 開発用管理者アカウントが必要な場合は `pnpm seed:dev-admin` で投入できる。

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. 編集モードタブから FrontMatter が消えている（AC-1）

- **対応する受け入れ基準:** AC-1
- **目的:** 新規・既存どちらの編集画面でも、編集モードタブに「FrontMatter」が表示されないこと
- **手順:**
  1. 既存ノートの編集画面（`/notes/$noteId/edit`）を開く
  2. モード切り替えタブの並びを確認する
  3. 新規ノート作成画面（`/notes/new`）を開き、モードタブを確認する
- **期待結果:** 編集画面のタブは `[ビジュアル, WYSIWYG, HTML]`、新規画面のタブは `[WYSIWYG, HTML]`。いずれにも「FrontMatter」が無い
- **確認ポイント:** WYSIWYG タブ（#696 由来）は残っていること。FrontMatter だけが消えていること

### 2. メタデータ編集領域が画面下部に常設される（AC-2）

- **対応する受け入れ基準:** AC-2
- **目的:** 本文編集モード（inline/wysiwyg/html）に関わらず、画面下部で FrontMatter の追加・編集・削除ができること
- **手順:**
  1. 既存ノートの編集画面を開く（既定は「ビジュアル」= inline）
  2. 画面を下までスクロールし、本文エディタの下にメタデータ編集領域があることを確認
  3. 「キーを追加」でキーを追加し、値を入力する
  4. 既存キーの値を編集する
  5. キーの「削除」ボタンで削除する
  6. 本文モードを「WYSIWYG」「HTML」に切り替えても、下部のメタデータ領域が常に表示・操作可能であることを確認
- **期待結果:** どの本文モードでも下部メタデータ領域でキーの追加・編集・削除ができる
- **確認ポイント:** 本文モードを切り替えても下部メタデータ領域が消えない／再マウントで入力中の値がリセットされない

### 3. 構造編集 ⇔ 生編集（JSON）トグル（AC-3）

- **対応する受け入れ基準:** AC-3
- **目的:** 下部メタデータ領域内で構造編集と生編集（JSON）を切り替えられること
- **手順:**
  1. 編集画面の下部メタデータ領域で「生編集（JSON）」ボタンを押す
  2. JSON テキストエリアに切り替わり、現在の FrontMatter が JSON で表示されることを確認
  3. JSON を直接編集する
  4. 「構造編集に戻す」ボタンで構造編集に戻す
- **期待結果:** 双方向にトグルでき、片方の編集内容がもう片方に反映される
- **確認ポイント:** 生編集で不正な JSON を入力するとエラーメッセージが表示され、保存ボタンが無効化されること（従来挙動の維持）

### 4. バリデーションと保存時シリアライズの維持（AC-4）

- **対応する受け入れ基準:** AC-4
- **目的:** FrontMatter のバリデーション・保存挙動が従来どおりであること
- **手順:**
  1. 下部メタデータ領域でキー・値を編集する
  2. 「保存」（既存）または「作成」（新規）を押す
  3. 保存後、ノート詳細画面で FrontMatter が反映されていることを確認
  4. 再度編集画面を開き、保存したキー・値が下部領域に表示されることを確認
- **期待結果:** 編集した FrontMatter が保存され、詳細画面・再編集画面に正しく反映される
- **確認ポイント:** キー名の制約・ネスト・配列値の扱い（構造編集では read-only 表示）が従来どおり

### 5. モード切り替えで FrontMatter 編集内容が失われない（AC-5）

- **対応する受け入れ基準:** AC-5
- **目的:** 未保存の FrontMatter 編集がある状態で本文モードを切り替えても内容が保持されること
- **手順:**
  1. 編集画面の下部メタデータ領域でキー・値を編集する（保存はしない）
  2. 本文モードタブを別のモード（例: ビジュアル → HTML）に切り替える
  3. 未保存変更の確認ダイアログが出たら「OK」で進む
  4. 切り替え後、下部メタデータ領域の編集内容を確認する
- **期待結果:** 本文モードを切り替えても、下部メタデータの編集内容が保持されている
- **確認ポイント:** FrontMatter 入力が再マウントされず、入力途中の値も維持されること

## エッジケース・異常系

### 1. 生編集（JSON）で不正な JSON のまま保存しようとする

- **目的:** JSON パースエラー時に保存がブロックされること（本文モードに関わらず）
- **手順:**
  1. 下部メタデータ領域で「生編集（JSON）」に切り替え、壊れた JSON（例: `{ "a": }`）を入力する
  2. 本文モードを切り替えたり保存ボタンを確認する
- **期待結果:** エラーメッセージが表示され、保存ボタンが無効化される。本文モードに関わらず常時このゲートが効く

### 2. WYSIWYG 装飾消失ゲート（#696）が引き続き機能する

- **目的:** FrontMatter 常設化が WYSIWYG 切り替え時の装飾消失警告（#696）を壊していないこと
- **手順:**
  1. 既存ノートの編集画面で、WYSIWYG 非対応タグを含む本文（HTML タブで `<section><p>x</p></section>` 等を入力・保存）を用意する
  2. 「WYSIWYG」タブに切り替える
- **期待結果:** 装飾消失の警告ダイアログ（ConfirmDialog）が従来どおり表示される

## 既存機能への影響確認

- autosave（下書き自動保存）が本文・FrontMatter 編集で従来どおり動作すること
