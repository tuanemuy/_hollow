# TC-002: provider を Deepgram に切り替えると model 欄が nova-3 にリセットされ、placeholder/ヒントが切り替わる（AC-4）

判定: **PASS**

セッション: `verify-tc-002b`
対象: `http://localhost:3000/admin/speech`
実行日: 2026-06-21

## サマリー

speech の env override（`ADMIN_SPEECH_PROVIDER` / `ADMIN_SPEECH_MODEL`）を外した状態で
サーバーを再起動した環境で再検証した。今回は provider select（`combobox "プロバイダ"`）・
model 入力欄（`textbox "既定モデル"`）ともに **enabled（env-lock なし）** で描画され、
`is enabled` で双方 `true` を確認した。

provider を **OpenAI → Deepgram** に切り替えると model 欄が `gpt-4o-transcribe` から
`nova-3` に自動リセットされ、API キー placeholder が `sk-...` → `Token ...`、
model ヒントが「例: gpt-4o-transcribe」→「例: nova-3」に切り替わった。
逆方向 **Deepgram → OpenAI** でも model 欄が `gpt-4o-transcribe` に戻り、
placeholder・ヒントも OpenAI 向けに復帰した。AC-4 を双方向で満たすため **PASS**。

## 注記（前回 BLOCKED の経緯）

前回（セッション `verify-tc-002`）は dev サーバーが `wrangler.toml [vars]` で
`ADMIN_SPEECH_PROVIDER="openai"` / `ADMIN_SPEECH_MODEL="gpt-4o-transcribe"` を設定して
おり、フォームが **env-locked（`disabled`）** で描画されていた。実装
（`app/components/admin/SpeechSettingsForm/index.tsx` L247-249）は env-lock 時に
model リセットを意図的に抑制するため、AC-4 の中核「model リセット」を実環境で観測できず
BLOCKED としていた（実装欠陥ではなくテスト環境の前提不備）。今回 env override を外した
再起動により前提が解消され、AC-4 を完全に検証できた。

## 観測値（必須）

- model 欄の遷移: `gpt-4o-transcribe`（OpenAI 初期） → `nova-3`（Deepgram 切替後） → `gpt-4o-transcribe`（OpenAI 戻し後）。**双方向で正しくリセット**。
- model ヒント: 「例: gpt-4o-transcribe」 → 「例: nova-3」 → 「例: gpt-4o-transcribe」。
- API キー placeholder: `sk-...`（OpenAI） → `Token ...`（Deepgram） → `sk-...`（OpenAI 戻し）。
- provider select / model 入力欄ともに `is enabled` = `true`（env-lock 解除済み）。

## 補足（検証手法メモ）

`get text @e21` は textbox の value を返さなかったため、入力値は
`eval` で `input[name=model].value` を直接読み取って確認した。初回 `input[required]` の
querySelector は API キー欄（今回 Deepgram 切替で required 化され DOM 上で先行）にマッチ
したため、`name` で識別する方法に切り替えて正確に取得した。snapshot の
`textbox "既定モデル" [ref=e21]: nova-3` でも一致を確認済み。
