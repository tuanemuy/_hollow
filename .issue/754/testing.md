# 動作確認計画 — Issue #754: モバイルのノート一覧フィルターが横スクロール依存でUXが悪い（省スペースで見直したい）

**Issue:** #754
**作成日:** 2026-06-18

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載（プロジェクト全体のセットアップは省略）。in-scope の変更は P10 ノート一覧（`/`）のフィルターバーの **モバイル（`max-sm`）UI のみ**。デスクトップ（`sm` 以上）は不変であることの確認も含む。

### 検証環境の起動

```bash
pnpm db:migrate         # ローカル D1 (hollow-local-d1) にマイグレーションを適用
pnpm seed:dev-admin     # 決定的な admin ユーザー + セッション（cookie: dev-admin-session-token）を投入
pnpm dev                # vite dev (workerd) を http://localhost:3000 で起動
```

- ノート一覧（`/`）はログインユーザーのノートを表示する。`seed:dev-admin` のセッションでログイン状態にする。
- フィルターを意味のある状態にするには、複数のタグを持つノートが複数必要（タグフィルターが多数描画されるくらいの本数が望ましい）。内部リンク参照フィルターの確認には、別ノートを参照するノートも欲しい。シードデータは manual-test 実行時にブラウザ操作、または `pnpm db:execute:local --file <sql>` で投入する。

### デプロイ方法

検証環境（ローカル D1 + `pnpm dev`）のみで確認できるため、ステージング/本番へのデプロイは本確認には不要。

## 確認項目

### 1. モバイルでフィルターが横スクロールに依存しない

- **対応する受け入れ基準:** AC-1, AC-2
- **目的:** モバイル幅でフィルターバーが横スクロール（`overflow-x-auto`）に頼らず、すべてのフィルターに到達できる。
- **手順:**
  1. devtools をモバイル幅（375px）にして `/` を表示。
  2. フィルター領域に横スクロールバー／横スクロール可能なオーバーフローが**発生していない**ことを確認。
  3. モバイルの集約トリガー（「絞り込み」ボタン）をタップしてシートを開き、タグ／期間／公開状態／内部リンク参照のすべてのフィルターに横スクロールなしで到達できることを確認。
- **期待結果:** モバイルでフィルター行に横スクロールが存在しない。全フィルターがシート展開で到達可能。
- **確認ポイント:** スクロールバー非表示のまま隠れて横に伸びるフィルターが残っていないか。

### 2. 省スペース（常時占有が現状の横スクロール1行と同等以下）

- **対応する受け入れ基準:** AC-3
- **目的:** フィルターが常時占有する縦スペースが増えていない（ノート本体を圧迫しない）。
- **手順:**
  1. モバイル幅（375px）で `/` を表示。
  2. シートを閉じた状態で、フィルターが常時占有する高さ（「絞り込み」トリガーバー + 必要時のディレクトリ行）を確認。
- **期待結果:** 常時占有はトリガーバー1行（＋ディレクトリ行）に収まり、全フィルターを縦に折り返した状態にはならない。
- **確認ポイント:** dangling ディレクトリのフォールバックチップ行が出るケースでも縦に大きく伸びないか。

### 3. モバイル集約UI（ボトムシート）のアクセシビリティ

- **対応する受け入れ基準:** AC-5
- **目的:** シートがフォーカストラップ・ESC で閉じる・トリガーへのフォーカス復帰を備える。
- **手順:**
  1. モバイル幅で「絞り込み」ボタンをタップしシートを開く。
  2. Tab でフォーカスがシート内をループし、背後のノート一覧に漏れないことを確認。
  3. ESC キー（または ×／背景タップ）でシートが閉じることを確認。
  4. 閉じた後、フォーカスが「絞り込み」トリガーに戻ることを確認。
- **期待結果:** `role="dialog"` + アクセシブル名を持ち、フォーカストラップ・ESC・復帰が機能する。
- **確認ポイント:** 背景スクロールがロックされるか。

### 4. 適用中フィルター件数バッジの発見性

- **対応する受け入れ基準:** AC-6
- **目的:** 適用中フィルターの件数がトリガーに表示され、隠れたフィルターの存在に気づける。
- **手順:**
  1. フィルター未適用の状態で「絞り込み」トリガーに件数バッジが出ない／0 であることを確認。
  2. シートでタグ・期間・公開状態などを適用して閉じる。
  3. トリガーの件数バッジが適用数に応じて更新されることを確認。
- **期待結果:** 件数バッジが適用中フィルター数を反映する。`hasAnyFilter`（全クリア×の表示条件）と件数>0 が一致する。
- **確認ポイント:** ディレクトリ選択時も「クリア×表示 ⇔ 件数>0」が崩れないか。

### 5. シート内フィルター操作の反映（楽観的更新・ナビゲーション）

- **対応する受け入れ基準:** AC-2
- **目的:** シート内のフィルター操作が従来どおりノート一覧に反映される。
- **手順:**
  1. シートを開きタグをトグル → 一覧が絞り込まれることを確認。
  2. 期間プリセット／カスタム日付範囲、公開状態 4択を切り替え、一覧に反映されることを確認。
  3. 内部リンク参照フィルターは、シート内では適用中チップ + 解除のみ（新規選択は別動線）であることを確認し、解除が反映されることを確認。
- **期待結果:** 各操作が URL search パラメータ・一覧に反映される（デスクトップと同じ適用ロジック）。
- **確認ポイント:** シート内クリア後もシートが開いたまま維持されるか。

## エッジケース・異常系

### 1. フィルター大量適用時

- **目的:** 多数のフィルター適用でもモバイルで横スクロールが再発しない。
- **手順:**
  1. モバイル幅でタグを多数 + 期間 + 公開状態 + 内部リンク参照を適用。
  2. シートを閉じてトリガーバーを確認。
- **期待結果:** 常時占有はトリガーバー1行のまま。横スクロールは発生しない。

## 既存機能への影響確認

- **デスクトップ（`sm` 以上）不変（AC-4）:** 幅を 1280px 等にして `/` を表示し、フィルターバーが現状（タグチップ列 + 期間/公開状態/タグの各 Popover + 全クリア×）と同一に描画・動作することを確認。モック `P10-home.html` と差分がないこと。
- **ディレクトリフィルター（AC-7）:** パンくず／dangling フォールバックチップの挙動が退行していないことを、ディレクトリ配下のノート表示・パンくず操作で確認。
- **静的検査（AC-8）:** `pnpm typecheck && pnpm lint && pnpm format:check` が通り、`FilterBar.test.tsx`（更新後）が通ること。
