# Plan Review — Issue #669 / Round 1（要件カバレッジ・スコープ整合性）

レビュー対象: `.issue/669/plan.md` / `.issue/669/adr.md`
視点: Issue本文・コメント合意の要件が受け入れ基準に落ちているか、各基準の検証可能性、基準⇔ステップの紐づけ、スコープ外混入の有無。

## 検証メモ（コード照合済み）

- `NoteEditor.tsx:273` の `routerInvalidate(router)` は edit 経路のみ（new 経路は invalidate なし）— 計画の記述どおり
- `editorActions` の `ml-auto` は実装済み — AC-3 を「検証のみ」とする整理は正確
- モック `.toolbar` は `background: var(--color-bg)` / `box-shadow: var(--shadow-xs)` を持つ — Issue本文（「背景: モックは指定なし」）より計画の AC-1 のほうが正確
- `routerInvalidate.ts` は `_app` 除外を AND 合成で集約済み — ステップ1の拡張方針は既存設計（#293 ADR-010）と同型で整合
- edit ルートは `renderServerComponent` を返す RSC loader（`staleTime: 0`）— 「loader 再実行 = RSC ツリー差し替え = 再マウント」という計画の分析は正しい
- Issue コメント（追加調査）の合意 ①②③ はそれぞれ AC-7 / AC-9 / AC-8 に 1:1 で落ちている

## 問題点（要修正）

- **[P-001]** seed-once 防御（AC-9）の効果範囲について計画内で記述が矛盾している。スコープ節（plan.md:36）は「残る生の `router.invalidate()`（3ルール例外）に対しては AC-9 の防御で編集内容が守られる」と述べ、ステップ2（plan.md:103）も同趣旨だが、調査結果（plan.md:60）と adr.md ADR-003 自身が「フォーカス喪失は loader 再実行で RSC ツリーが差し替わり再マウントされる経路」「seed-once は単独では RSC ツリー差し替えに対して不十分」と認めている。edit ルートは RSC loader（`staleTime: 0`）なので、生の `router.invalidate()`（rule 2 等）でも同じ再マウント経路を通り、「同一インスタンスへの props 更新で再初期化しない」テスト（AC-9）では編集内容は守られない。実際、`DirectoryPicker` はエディター内から `RenameDirectoryDialog` / `DeleteDirectoryDialog`（いずれも rule 2 の生 `router.invalidate()` を呼ぶ — `RenameDirectoryDialog.tsx:71`, `DeleteDirectoryDialog.tsx:41`）を開けるため、編集中にディレクトリをリネーム/削除すると未保存の編集内容が fresh load で失われる経路が修正後も残る。
  理由: AC-9/AC-10 の達成範囲が計画内で過大に記述されており、受け入れ基準の検証時（手動確認）に「rule 2 操作で編集内容が消える」を不合格と読むか仕様内と読むかが判定不能。
  提案: (a) plan.md:36 とステップ2の「生 invalidate への防御」という効果主張を、ADR-003 の認識（seed-once は再マウントには無力、退行防止の pin が目的）に合わせて修正する。(b) rule 2 操作（エディター内ディレクトリリネーム等）による編集内容喪失を「本 Issue のスコープ外の既知の残存経路」として明記するか、AC-10 の検証対象に含めて対策（例: rule 2 ダイアログ側の invalidate もエディタールートを除外する設計の検討）をステップに追加するか、どちらかに倒す。Issue 受け入れ条件は「編集中…フォーカスが外れない」とだけ書かれているため、スコープ境界の明文化が必要。

## 改善提案（検討推奨）

- **[S-001]** AC-1 にモック `.toolbar` の `margin-bottom: var(--space-4)` が含まれていない。現状は form の `gap-4`（= space-4）で偶然等価になるが、ステップ4で「form の `gap` を外して各セクションに `mb-*` を付ける」代替案を採った場合にツールバー下余白が脱落しうる。理由: 基準とステップ4の代替案が干渉する可能性があるため、AC-1 か ステップ3 に「ツールバー下余白 space-4 相当の維持」を一言追加しておくと検証が安定する。
- **[S-002]** AC-10 の検証トリガー列挙（autosave 発火・UploadDialog 完了）に、手動検証手順（ステップ8）の (b)(c) は対応しているが、P-001 で挙げた rule 2 経路（エディター内ディレクトリ操作）の確認項目がない。理由: スコープ判断（P-001 の解決）後、その判断どおりの挙動であることをステップ8の手動検証リストに反映すべき。
