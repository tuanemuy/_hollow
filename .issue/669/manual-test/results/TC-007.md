# TC-007: autosave 発火中の入力継続（AC-10）

**結果: FAIL**

検証日: 2026-06-13 / 環境: agent-browser（headed Chrome, CDP）+ localhost:3000 dev サーバー / ノート: `019e9549-a511-7654-8299-90e50bd33b05` / モード: ビジュアル（= `InlineEditor`、`hasTiptap: false` を確認済み）

## 操作と結果

| # | 操作 | 期待 | 実際 |
|---|------|------|------|
| 1 | 本文ブロック（contenteditable な `<p>`）をクリック → End キーでキャレットを末尾へ | キャレットが本文末尾に置かれる | OK（`document.activeElement` = 編集中の P） |
| 2 | 1〜2秒間隔で1文字ずつ入力を継続（CDP の trusted keypress / `execCommand('insertText')` 両方で試行、合計 30 秒以上） | 入力中にフォーカスが外れない・キャレットが飛ばない | **各キーストロークの約 200〜300ms 後にフォーカスが失われる**。文字自体は挿入される |
| 3 | focusin/focusout リスナー + MutationObserver で計測（trusted keypress 1回） | focusout が発生しない | `keypress(+0ms)` → `focusout(P, +217ms)` → `hostChildList 置換(+218ms)` → 以後 focusin なし。`document.activeElement` は BODY のまま復帰しない |

## 失敗詳細

- 再現条件: ビジュアル（inline）モードで本文に1文字入力するだけで再現する。autosave（1500ms）より早い約 217ms 時点で発生するため、**直接の原因は autosave ではなく InlineEditor の onChange emit（`ONCHANGE_DEBOUNCE_MS = 50ms`）後のホスト DOM 再構築**とみられる。
- 計測事実:
  - 入力した文字は state に届き保持される（内容の喪失はない）。
  - emit 直後に `.note-detail-content` ホストの childList が丸ごと置換され（`replaceChildren` 相当）、contenteditable ノードの同一性が失われる。
  - その結果 focusout が発生し、フォーカス復帰処理は走らない（activeElement = BODY）。キャレットも失われる。
- 推定原因箇所: `app/components/note/editor/InlineEditor.tsx` の値リシンク effect（`value !== lastEmittedHtmlRef.current` 時の DOM 再構築）または rollback 経路。emit した HTML と親から戻る `value` の不一致（self-emit ガードのすり抜け）が疑われる。
- 留意点: 検証は CDP 経由の合成キー入力。ただし trusted KeyboardEvent でも同一の focusout +217ms / DOM 置換を確認しており、実ユーザー操作でも同様に発生する可能性が高い。dev サーバー / agent-browser デーモンの不安定（途中で数回再起動）があったが、本事象はデーモン健全時に単発キー入力で安定再現した。

## 影響

連続入力の途中で（最初のキーの約 0.2 秒後）フォーカスが外れるため、AC-10「入力中にフォーカスが外れない・キャレットが飛ばない」を満たさない。

## 再検証

**結果: PASS**

検証日: 2026-06-13 / 環境: agent-browser（headed Chrome, CDP）+ localhost:3000 dev サーバー / ノート: `019e9549-a511-7654-8299-90e50bd33b05` / モード: ビジュアル（inline）

修正内容（emit round-trip で DOM を再構築しない effect 分離）に対する再検証。

| # | 操作 | 期待 | 実際 |
|---|------|------|------|
| 1 | 本文の contenteditable `<p>` をクリックしてフォーカス、focusin/focusout リスナー + MutationObserver（ホスト childList）を設置 | フォーカスが P に入る | OK（focusin(P) を記録、activeElement = P） |
| 2 | trusted キー入力で1文字（"X"）入力 → 800ms 待機 | focusout が発生しない・childList 置換が起きない | OK。focusout なし、childList ミューテーション 0 件、activeElement は P のまま、テキストに "X" 反映 |
| 3 | 250ms 間隔で10文字（a〜j）連続入力 | キャレットが飛ばず入力が続行できる | OK。focusout 0 件・ミューテーション 0 件、キャレットは末尾（offset 17）で collapsed、全文字が順序通り反映 |
| 4 | 2.5 秒放置（autosave 間隔 1.5s を跨ぐ）→ さらに1文字（"Z"）入力 → 800ms 待機 | autosave 後もフォーカス維持・入力可能 | OK。focusout 0 件・ミューテーション 0 件、activeElement = P、"Z" 反映 |

前回 FAIL の事象（キー入力の約 217ms 後の focusout → ホスト childList 全置換 → activeElement が BODY に落ちる）は再現せず。検証全体を通して focusout イベントは 1 件も発生せず、ホストの childList ミューテーションも 0 件だった。AC-10「入力中にフォーカスが外れない・キャレットが飛ばない」を満たす。

補足: テスト中の編集は autosave により永続化されていたため、検証後に末尾の追記文字（XabcdefghijZ）を削除して保存し、元の本文（「本文テキスト」）へ復元済み。
