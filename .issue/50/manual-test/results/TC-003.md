## 補足

- 本テストケースは `?q=&visibility=` の組み合わせを `/` (home) で検証する想定だが、ローカル dev サーバーのログイン処理が 500 を返す状態のため、ブラウザ経由の `searchOwnNotes` 検証は実施できなかった（Issue #50 とは無関係の dev サーバー側エラー）。
- 代替として、`searchIndex.ts` が実行するのと同等の FTS5 クエリを `wrangler d1 execute --local` 経由で直接実行し、visibility 列のフィルタが trigram 移行後も期待どおり機能することを確認。
- 検証コマンド:
  ```sql
  SELECT visibility, title FROM search_documents
  WHERE rowid IN (
    SELECT rowid FROM search_documents_fts WHERE search_documents_fts MATCH 'デザイン'
  ) AND visibility = '<public|unlisted|private>';
  ```
- 全体の `デザイン` ヒット件数: 2 件（public 1 + unlisted 1）。visibility=private は 0 件（seed の private ノートに「デザイン」キーワードを含むものが無いため）。

## 失敗詳細

なし（DB 層で全 visibility パターンが期待どおり動作）。
