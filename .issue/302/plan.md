# 実装計画 — Issue #302: サイドバー「ディレクトリ」セクションの空状態が冗長 — 見出し+に統一する

**Issue:** #302
**作成日:** 2026-05-30
**複雑度:** 小規模

---

## 目的

サイドバー左ペインの「ディレクトリ」セクションで、ディレクトリが0件のとき「見出し横の +」「`+ ディレクトリを作成` CTA ボタン」という同一アクションが重複している。空状態の CTA ボタンを削除し、ルート直下作成のエントリーポイントを見出し横の `+` に一本化する。

## スコープ

### 含まれるもの
- `app/components/directory/DirectoryTree.tsx` の `children.length === 0` ブロックから `+ ディレクトリを作成` ボタンを削除し、説明テキストだけ残す。
- 空状態の文言を、見出し横の `+` への気付きやすさを補強する形に更新する（Issue「留意点」で実装時判断とされた選択肢を採用）。

### 含まれないもの
- `DirectorySidebarSection.tsx` の変更（見出し横の `+` は常時表示のまま、変更不要）。
- 階層あり状態（≧1件）の表示・挙動の変更。
- 各ノードの操作メニュー（…）の「子ディレクトリを作成」の変更。

## 実装ステップ

### 1. 空状態 CTA ボタンの削除と文言更新

- **対象ファイル:** `app/components/directory/DirectoryTree.tsx`
- **変更内容:** `children.length === 0` の分岐（109-127行）の `<button>`（`+ ディレクトリを作成`）を削除し、`<p>` の説明テキストのみ残す。文言を「まだディレクトリがありません。右上の + から作成できます。」に更新して、見出し横の `+` へのアフォーダンスを補強する。`flex flex-col gap-2` は単一要素になるため不要なクラスを整理する。
- **理由:** (1) と (3) が同一アクションで重複しているため。`+` の縦2連を解消し、初回ユーザーの導線を見出しの `+` に集約する。

### 2. 未使用コードの確認

- **対象ファイル:** `app/components/directory/DirectoryTree.tsx`
- **変更内容:** ボタン削除後、`root` 変数は `children = root?.children ?? []` で引き続き使用されるため残す。`dialog` state / `CreateDirectoryDialog` の `createChild` 描画は各ノードのメニューで使われるため残す。`disabled`/`onClick` で参照していた `root` の空状態用途のみ削除される。typecheck / lint で未使用変数が出ないことを確認する。
- **理由:** 削除に伴う未使用シンボルやデッドコードを残さない。

## 設計判断

- **空状態文言の補強:** Issue「留意点」で、初回ユーザーが見出しの `+` に気付きにくい懸念と、文言でアフォーダンスを補強する選択肢が提示されていた。導線が見出しの `+` 一本になることで発見性が下がるため、文言に「右上の + から作成できます」を加えてカバーする。`aria-label`「ディレクトリを新規作成」は既存のまま維持。

## リスクと注意点

- 空状態でクリックできる導線が見出しの `+` のみになるため、文言での誘導が機能しているかをブラウザ確認で検証する。
- 階層あり → 全削除で空状態に戻る遷移でも、新しい空状態が正しく描画されるか確認する。

## テスト方針

- `pnpm typecheck && pnpm lint:fix && pnpm format` で静的検証。
- ブラウザで空状態・階層あり状態・見出し `+` からの作成ダイアログ起動を確認（testing.md 参照）。
