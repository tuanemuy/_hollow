# 動作確認計画 — Issue #671: 公開検索(P32)フィルターUIの改善

**Issue:** #671
**作成日:** 2026-06-13

## 確認環境

このIssueの変更（公開検索画面 `/search` のフィルター UI: 期間「すべて」のデフォルト化・モバイルのボトムシート化/チップ横スクロール/適用ボタン・チップのレイアウト崩れ修正）を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm db:migrate    # ローカル D1 にマイグレーション適用（初回・未適用時のみ）
pnpm dev           # vite dev (workerd) on http://localhost:3000
```

確認 URL: `http://localhost:3000/search?q=<ヒットするキーワード>`

### デプロイ方法

なし（検証環境のみで確認できる。本変更はフロントのスタイル／JSX のみ）。

### シードデータ

- 公開（public）ノートが複数件、**複数ユーザー・複数タグ**であること（@ユーザーチップ・タグチップの確認に必要）。
- 検索インデックス（`search_documents`）にノートが反映されている必要がある。シードの整備は manual-test スキルに委ねる。検索結果が出るよう、公開ノートを最低数件用意すること。

## 確認項目

### 1. 期間「すべて」がデフォルト扱い（URL / チップ / バッジ）

- **対応する受け入れ基準:** AC-1, AC-3, AC-4
- **目的:** 期間「すべて」を選んでもフィルター状態として扱われない。
- **手順:**
  1. `/search?q=<キーワード>` を開く。
  2. 「フィルター」ボタンを押してドロワーを開き、期間ラジオで「すべて」を選ぶ。
  3. 「適用」する。
  4. アドレスバーの URL、フィルターバー直下のアクティブチップ行、フィルターボタンのバッジを見る。
- **期待結果:** URL に `period=all` が**載らない**（`period` パラメータが消える）。アクティブチップ「すべて」が**表示されない**。フィルターボタンのバッジ（件数）に**数えられない**。
- **確認ポイント:** 期間を一度 `30日` 等にしてから「すべて」に戻したときも、`period` が URL から消えてチップ・バッジが消えること。

### 2. 期間未指定時にラジオ「すべて」が checked

- **対応する受け入れ基準:** AC-2
- **目的:** 期間未指定（URL に `period` なし）のとき、デフォルトとして「すべて」が選択状態になる。
- **手順:**
  1. `/search?q=<キーワード>`（`period` を付けない URL）を開く。
  2. 「フィルター」ボタンでドロワーを開き、期間ラジオを見る。
- **期待結果:** 期間ラジオ「すべて」が `checked`（選択済み）になっている。
- **確認ポイント:** 旧実装のように「どのラジオも未選択」になっていないこと。

### 3. 期間 7d/30d/1y は従来どおり動作（リグレッション）

- **対応する受け入れ基準:** AC-5
- **目的:** 「すべて」以外の期間は従来どおりチップ表示・バッジ加算・URL 反映される。
- **手順:**
  1. ドロワーで期間「過去30日」を選び適用する。
  2. URL・チップ・バッジを確認する。`過去7日` `過去1年` も同様に確認する。
- **期待結果:** URL に `period=30d` 等が載り、アクティブチップ「過去30日」が表示され、バッジに数えられる。再度ドロワーを開くと該当ラジオが checked。

### 4. モバイル: ドロワーがボトムシート

- **対応する受け入れ基準:** AC-6
- **目的:** モバイル幅でドロワーがモック（`spec/design/pages/mobile/P32-public-search.html`）のボトムシートになる。
- **手順:**
  1. ブラウザをモバイル幅（< sm, 例 375px）にする。
  2. `/search?q=<キーワード>` で「フィルター」を押す。
- **期待結果:** ドロワーが画面下端に固定され、上角丸で**下からせり上がる**トランジションで開く。`max-height` でビューポート内に収まる。背景に backdrop（フェード）が出る。閉じると下へスライドして消える。
- **確認ポイント:** PC 幅（>= sm）では従来どおり右からスライドするドロワーのままであること（リグレッションなし）。px 完全一致は求めず、rem ベースの相対サイズで評価する。

### 5. モバイル: footer の適用ボタン/リセットリンクのタップ高

- **対応する受け入れ基準:** AC-7, AC-15
- **目的:** モバイルで footer のボタンがタップしやすいフルサイズになる。
- **手順:**
  1. モバイル幅でドロワーを開き footer を見る。
- **期待結果:** 「適用」ボタンが**フルサイズ**（横いっぱい・高さ 48px 相当）。「すべてリセット」リンクもタップしやすい高さ（44px 相当）。
- **確認ポイント:** footer 下端が safe-area（ホームバー等）にかぶらない余白を持つこと。

### 6. モバイル: アクティブチップ行の横スクロール

- **対応する受け入れ基準:** AC-8, AC-9, AC-14
- **目的:** モバイルでチップ行が折り返さず横スクロールする。
- **手順:**
  1. 期間・タグ・@ユーザーを複数指定してチップを多めに出す（URL 例: `/search?q=<キーワード>&period=30d&tags=<タグ>&user=<ユーザー>`）。
  2. モバイル幅でフィルターバー直下のチップ行を見る。横にスワイプする。
- **期待結果:** チップが**折り返さず**横スクロールする。各チップは縮まず高さ 32px 相当で揃う。remove（×）ボタンがタップしやすい（22px 相当）。「すべて解除」ボタンも同じ高さで潰れずスクロール行内に収まる。スクロールバーは表示されない。

### 7. チップのレイアウト崩れ解消（アバター 16px・上下ずれ）

- **対応する受け入れ基準:** AC-10, AC-11
- **目的:** チップ内アバターのサイズ衝突と、チップ行の描画位置ずれが解消されている。
- **手順:**
  1. @ユーザーを指定して @ユーザーチップを出す（PC 幅・モバイル幅の両方）。
  2. アクティブチップ行とフィルターバー（フィルターボタン・ソートトグル）の位置関係を見る。
- **期待結果:**
  - @ユーザーチップ内アバターが **16px** で描画される（チップ高さいっぱいの 28px に化けない）。ドロワー内の token チップのアバターも 16px で、チップからはみ出さない。
  - アクティブチップ行が**フィルターバーの下の独立した全幅の行**として表示され、フィルターボタンとソートトグルの間に挟まらない。期間・タグ・@ユーザーすべてのチップが上下にずれず、チップ下だけに孤立した境界線が出ない。

## エッジケース・異常系

### 1. チップが 0 件のとき

- **目的:** フィルター未指定でチップ行が空のとき、不要な余白や境界線が出ない。
- **手順:** `/search?q=<キーワード>`（フィルターなし）を開く。
- **期待結果:** アクティブチップ行自体が描画されず（`activeCount > 0` ガード）、フィルターバーの下に余分な隙間・下線が出ない。

## 既存機能への影響確認

- **ソートトグル（#674 / SearchSortToggle）:** 構造再編（チップ行をフィルターバー外へ移す）後も、フィルターバー右側にフィルターボタンとソートトグル（関連度順⇄新着順）が並び、ソート切替が従来どおり動作すること。
- **件数表示:** フィルターバー左の結果件数表示（`resultsCount` / 下限表記）が従来どおり正しく表示されること（Props 経由でサーバー算出値が渡る）。
- **タグ／@ユーザーフィルター:** 期間以外のフィルター（タグ・ユーザー）のチップ表示・バッジ加算・URL 反映が従来どおり動作すること。
