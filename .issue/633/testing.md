# 動作確認計画 — Issue #633: モバイルボタンのサイズ整合性改善

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載（プロジェクト全体のセットアップは省略）。

### 検証環境の起動

```bash
pnpm dev
```

Vite + Cloudflare ローカル開発サーバーが起動する。ブラウザでモバイル幅（390px、320/430px 境界）とデスクトップ幅を切り替えて確認する。

DB がまだ初期化されていない場合のみ、開発用 admin シードを用意:

```bash
pnpm db:apply:local
pnpm seed:dev-admin
```

### モックの確認

`spec/design/pages/*.html` / `spec/design/pages/mobile/*.html` は静的 HTML。ブラウザで直接開く（またはエディタのプレビュー）。ビルド不要。

### デプロイ方法

なし（検証環境のみで確認できる。UI スタイルのみの変更で DB マイグレーション・外部反映は不要）。

## 確認項目

### 1. desktop の input とボタンの整合（4px ずれ解消）

- **目的:** `fieldControl`(input h-10=40px) と隣接する `pillBtn` の下端が揃うことを確認。
- **手順:**
  1. `pnpm dev` で起動し、検索バー・フィルタ行など input とピルボタンが横並びになる画面を desktop 幅で開く（例: ノート一覧、公開設定）。
  2. input とボタンの下端・高さを目視。
- **期待結果:** input とボタンが同じ 40px 高さで下端が揃う。
- **確認ポイント:** 旧 4px ずれがないこと。

### 2. モバイルでのボタンサイズ統一

- **目的:** モバイル幅で `pillBtn` が実高40 + タッチ床44(min-h) で描画され、膨張幅が小さいことを確認。
- **手順:**
  1. ブラウザを 390px 幅にし、ヘッダー・ツールバー・一括操作バー・ダイアログのボタン群を確認。
  2. 320px / 430px 境界でも確認。
- **期待結果:** ボタンが 44px 床を持ちつつ、密度崩壊（急激な膨張）がない。
- **確認ポイント:** 周囲要素とのバランス。

### 3. 小型ボタンの床（opt-in 反転の確認）

- **目的:** デフォルト小型ボタン(`pillBtnSm`)がモバイルで44床を持ち、admin の `pillBtnSmDense` だけが密度を保つことを確認。
- **手順:**
  1. 一般画面の小型ボタン（ディレクトリピル等）をモバイル幅で確認 → 44床。
  2. admin のジョブテーブル・ユーザーテーブル・デザイントークンフォームの行アクションをモバイル幅で確認 → 密度維持（44に膨張しない）。
- **期待結果:** 一般小型ボタンは44床、admin 密度行は密度維持。
- **確認ポイント:** `!important` 撤去後の回帰がないこと（admin 行が意図せず膨張していないか）。

### 4. アイコンボタンの正方形維持

- **目的:** `pillBtnIcon` が `w-10 h-10` で正方形を保ち、モバイルで44×44になることを確認。
- **手順:** アイコンのみのピルボタン（ツールバー等）を desktop / mobile で確認。
- **期待結果:** desktop 40×40 正方形、mobile 44×44。縦長にならない。

### 5. モックと実装の一致

- **目的:** モック HTML が実装の統一方針と一致していることを確認。
- **手順:**
  1. 同一 basename の `pages/{name}.html` と `pages/mobile/{name}.html` をブラウザで開く。
  2. ボタンサイズ・床の適用方針が実装と揃っているか目視。
- **期待結果:** モック内で方針が割れていない（blanket 適用と限定版の混在がない）、実装と一致。

## エッジケース・異常系

### 1. モック横スクロール

- **目的:** モック修正で overflow が発生しないことを確認。
- **手順:** 各モックを 320〜430px で開く。
- **期待結果:** 横スクロールなし（overflow=0）。

### 2. 非対称モックファイル

- **目的:** desktop に対応がない mobile 専用モック（`mobile/P13a-upload-modal.html` 等）も統一方針で破綻しないことを確認。
- **手順:** 非対称ファイルを個別に開いて確認。
- **期待結果:** ボタンサイズが統一方針どおり。

## 既存機能への影響確認

- ボタン高さ変更（h-9→h-10）が全ピルボタンに波及するため、各画面のレイアウト崩れ（ボタンが入る行の高さ・縦位置）がないか確認。
- ダイアログのアクションボタン、ヘッダーのアイコンボタン、認証画面のパスワード表示トグルなど add-on 系が破綻していないか確認。
