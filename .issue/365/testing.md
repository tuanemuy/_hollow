ソース変更（`tagRepository.findByOwner`）を反映したライブサーバーで確認する。`pnpm start` はビルド済み dist を配信するため、ソース変更の確認には `pnpm dev` を使う。

```bash
pnpm db:migrate   # ローカル D1 にマイグレーション適用（初回・スキーマ変更時）

```

## 確認項目

### 1. FilterBar のタグファセットに正しい件数が表示される

- **目的:** タグの利用件数が「0件」固定ではなく、実際に紐づく active ノート数で表示されることを確認する。
- **手順:**
  1. ログインし、ノート一覧画面を開く。
  2. シードデータ準備: 同一タグ（例: `work`）を 2 件の active ノートに付与し、別タグ（例: `idea`）を 1 件の active ノートに付与する。
  3. FilterBar のタグファセットを開く。
- **期待結果:** `work` の件数が `2`、`idea` の件数が `1` と表示される（従来は両方 `0`）。
- **確認ポイント:** 件数表示が `0` 固定でないこと。タグごとに実数が出ていること。

### 2. 件数とフィルタ結果が一致する（active 基準）

- **目的:** 件数セマンティクスが active ノート基準で、フィルタ結果と一致することを確認する。
- **手順:**
  1. 確認項目1の状態から、FilterBar で `work` タグをクリックしてフィルタする。
  2. 表示されたノート件数と、ファセットに出ていた件数を比較する。
- **期待結果:** ファセットの件数（2）とフィルタ結果のノート数（2）が一致する。
- **確認ポイント:** 「N件表示なのにフィルタ結果が違う」というズレが起きないこと。

### 3. タグ管理画面（TagManager）に正しい件数が表示される

- **目的:** タグ管理画面でも利用件数が正しく出ることを確認する。
- **手順:**
  1. タグ管理画面を開く。
  2. 確認項目1で作成した `work` / `idea` の件数を確認する。
- **期待結果:** `work` = 2、`idea` = 1 と表示される。
- **確認ポイント:** FilterBar と TagManager で同じ件数が出ること（同一 `listTags` 経路）。

### 4. noteCount での並び替え

- **目的:** 利用件数での並び替え（`ORDER BY COUNT(...)`）が機能することを確認する。
- **手順:**
  1. 件数の異なるタグを 3 つ以上用意する（例: 2件・1件・0件）。
  2. タグを利用件数の降順/昇順でソートする（UI にソート機能がある画面）。
- **期待結果:** 降順では件数の多いタグが先頭、昇順では少ない（0件）タグが先頭に並ぶ。同数のタグ間でも順序が安定している。
- **確認ポイント:** ソートが件数に基づいて正しく効くこと。

## エッジケース・異常系

### 1. 全ノートが trashed のタグ

- **目的:** active ノートが 0 件のタグが正しく 0 と表示されることを確認する。
- **手順:**
  1. あるタグを付与したノートをすべてゴミ箱（trash）に移動する。
  2. FilterBar / TagManager でそのタグの件数を確認する。
- **期待結果:** 件数が `0` と表示される（trashed は数えない）。

### 2. ノートを trash / restore したときの件数増減

- **目的:** active⇄trashed の遷移で件数が即座に追随することを確認する。
- **手順:**
  1. active ノート 2 件に付いたタグ（件数 2）から、1 件を trash する。
  2. 件数を確認 → 1 件に減ることを確認。
  3. trash したノートを restore する。
  4. 件数を確認 → 2 件に戻ることを確認。
- **期待結果:** trash で減り、restore で増える（都度集計なので即時反映）。

## 既存機能への影響確認

- **タグサジェスト・ノート一覧のタグチップ:** `findByIds`/`searchByNamePrefix` は変更しておらず名前のみ使用するため、表示・挙動が従来通りであること。
- **タグのマージ機能:** `mergeTags` のマージ確認件数・マージ結果が従来通り動くこと（件数表示は read-time 集計に切り替わる）。
- **タグ一覧のページネーション:** `listTags` の `limit+1`/hasMore による「もっと見る」相当の挙動が従来通りであること。
