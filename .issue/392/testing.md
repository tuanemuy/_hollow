## 事前準備（シードデータ）

サブツリー一致を確認できる階層構造を用意する:

- 親ディレクトリ `Parent`（owner のツリー直下）
  - 直下ノート `note-parent`（1 件）
  - 子ディレクトリ `Child`
    - 直下ノート `note-child`（1 件）
    - 孫ディレクトリ `Grandchild`
      - 直下ノート `note-grandchild`（1 件）
- 兄弟ディレクトリ `Sibling`（`Parent` と同階層）
  - 直下ノート `note-sibling`（1 件、サブツリーに**含まれてはいけない**）

UI からディレクトリ作成・ノート作成で用意するか、`pnpm db:execute:local --file <seed.sql>` で投入する。

## 確認項目

### 1. キーワードなしで親ディレクトリ選択 → サブツリー全体が表示される（本 Issue の主目的）

- **目的:** フィルタ経路（キーワードなし）が直下のみでなくサブツリー一致になること。
- **手順:**
  1. ホーム（`/`）を開く。検索キーワードは空のまま。
  2. サイドバーの `DirectoryTree` で `Parent` を選択（URL に `?directoryId=<ParentのID>` が乗る）。
  3. 一覧を確認する。
- **期待結果:** `note-parent` / `note-child` / `note-grandchild` の 3 件が表示される。`note-sibling` は表示されない。一覧の総件数表示（count）も 3。
- **確認ポイント:** 修正前は `note-parent` の 1 件のみだった点が、子・孫まで含む 3 件に変わること。

### 2. キーワードあり/なしで件数が一致する（非対称の解消）

- **目的:** 検索経路（キーワードあり）とフィルタ経路（なし）の表示集合が一致すること。
- **手順:**
  1. `Parent` を選択した状態（項目 1 の続き）で、全ノートにマッチする検索キーワード（例: 共通語）を入力する。
  2. キーワードなしの結果（項目 1）と件数・対象ノートを比較する。
- **期待結果:** キーワードあり/なしで同じサブツリー集合（`Parent` 配下の対象ノート）が対象になる。

### 3. 子・孫ディレクトリ選択時のサブツリー

- **目的:** 起点が中間/末端ディレクトリでも正しくサブツリーを返すこと。
- **手順:**
  1. `Child` を選択 → `note-child` / `note-grandchild` の 2 件。
  2. `Grandchild` を選択 → `note-grandchild` の 1 件のみ。
- **期待結果:** 起点ディレクトリ + その子孫のみが表示される（祖先・兄弟は含まない）。

### 4. ディレクトリ × タグ併用

- **目的:** `directoryIds` と `tagIds` の AND 併用が正しく効くこと。
- **手順:**
  1. `Parent` を選択し、`note-child` だけが持つタグでさらに絞り込む。
- **期待結果:** サブツリー内かつ当該タグを持つノートのみ（`note-child`）が表示される。

## エッジケース・異常系

### 1. 非存在/不正な directoryId

- **目的:** 存在しない・malformed な `directoryId` でエラー境界に落ちず空一覧になること（ADR-002: silent-empty 維持）。
- **手順:**
  1. URL を `/?directoryId=00000000-0000-0000-0000-000000000000`（存在しない有効形式）にして開く。
  2. URL を `/?directoryId=not-a-valid-id`（malformed）にして開く。
- **期待結果:** どちらもエラー画面にならず、空一覧（count 0）が表示される。

### 2. 大量ディレクトリ（host-var 境界）

- **目的:** サブツリーのディレクトリ数が `SAFE_CHUNK_SIZE`（90）を超えても D1 host-var 上限でエラーにならないこと。
- **手順:** （主に integration テストで担保。手動で確認する場合のみ）多数の子ディレクトリを持つ親を用意し選択する。
- **期待結果:** エラーなく該当サブツリーのノートが表示される。

## 既存機能への影響確認

- **検索経路（`searchOwnNotes`）**: 無変更。キーワードありのディレクトリ絞り込みが従来どおりサブツリー一致で動くこと。
- **`findByDirectory`（直下リスト用途、`listNotesInDirectory`）**: サブツリー化の波及を受けず、直下のみのままであること。
- **ディレクトリ未選択時のホーム一覧**: `directoryId` なしで従来どおり全ノートが表示されること。
- **FilterBar の選択中ディレクトリチップ / clearAll**: #387 で追加された UI が引き続き動作し、解除で `directoryId` が外れること。

## 注意

サイドバーのディレクトリ選択は `Link`（URL ナビゲーション）経由でありサーバーファンクションの cross-origin POST ではないため、agent-browser でも通常のページ遷移として検証可能（mutation ボタンの 403 制約は本 Issue の確認には影響しない）。
