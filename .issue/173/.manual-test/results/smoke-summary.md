## 観察事項

- `/` への `GET` は HTTP 307 を返すが、リダイレクト先は `/?page=1&limit=20` (クエリ正規化のみ)。ログイン強制のリダイレクトではなく、ランディングが公開公開ページとして提供される設計を確認。
- `/notes` は未認証でアクセスすると 404 を返す (auth ガードで弾くのではなく非公開リソースとして 404 にする方針)。これは backend 内部最適化の本 Issue (NoteRepository.listWithCount 追加) では触らない経路で、リグレッションなし。
- 認証画面 (login / signup) は静的フォームのみで note 一覧経路には到達せず、本 Issue の最適化対象である `listNotesByOwner` usecase は呼ばれない。シードユーザー不在のためログイン後の note 一覧確認は integration test (T-listWithCount-001..004 を含む 420 件) に委譲。
