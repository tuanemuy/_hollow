## 確認項目

### 1. P10 表示形式切替（リスト / タイル / カレンダー）

- **目的:** 3 種類の表示モードが URL 駆動で切り替わり、リロード後も保持されることを確認
- **手順:**
  1. ログイン後 `/` にアクセス
  2. ツールバーの「リスト」「タイル」「カレンダー」ボタンをそれぞれクリック
  3. URL に `?display=list`/`tile`/`calendar` が反映されることを確認
  4. ブラウザリロードで同じ表示モードが復元されること
  5. カレンダー: 月送り操作で前後月に遷移、`updatedAt` の日付別にノートがプロットされる
- **期待結果:** URL と表示状態が完全同期、リロード後も復元
- **確認ポイント:** カレンダーの tz が `Asia/Tokyo` 期待で日付ずれが起きていないか

### 2. P10 フィルタバー（タグ / 期間）

- **目的:** タグ・日付レンジで一覧が絞り込まれる
- **手順:**
  1. `/` でフィルタバーのタグ chip を複数クリック
  2. 日付 from/to に値を入力
  3. URL に `?tagNames=...&from=...&to=...` が反映されること
  4. 結果一覧が条件にマッチするノートのみ表示されること
  5. 「クリア」ボタンでフィルタリセット
- **期待結果:** タグ・期間で絞り込まれた結果が表示される

### 3. P10 検索（ヘッダー検索ボックス）+ 公開状態フィルタ

- **目的:** `?q=` 付きで検索結果が表示され、公開状態でさらに絞り込める
- **手順:**
  1. ヘッダーの検索ボックスにキーワード入力 → Enter（既存 `<form action="/" method="get">` 経由）
  2. URL が `/?q=キーワード` になり、検索結果が表示されること（`searchOwnNotes` 経路）
  3. 検索結果画面で公開状態フィルタ（`visibility=public/unlisted/private`）を切り替えて該当ノートのみ表示されること
- **期待結果:** `q` 有時は `searchOwnNotes`、公開状態フィルタが効く

### 4. P10 ディレクトリツリーからのフィルタ連動

- **目的:** Sidebar のディレクトリクリックで一覧が絞り込まれる
- **手順:**
  1. Sidebar のディレクトリノードをクリック
  2. URL に `?directoryId=...` が反映され、一覧が該当ディレクトリのノートのみになること
- **期待結果:** Link 遷移だけで連動

### 5. P10 複数選択 + 一括操作

- **目的:** 複数ノート選択時に bulk usecase が動作する
- **手順:**
  1. 一覧で複数のノートのチェックボックスを ON
  2. `BulkActionBar` に「N 件選択中」と件数表示
  3. 「移動」 → `MoveNoteDialog` でディレクトリ選択 → 実行 → 該当ディレクトリへ移動
  4. 「ゴミ箱」 → confirm → 実行 → ゴミ箱へ移動、`failures[]` があれば inline 表示
  5. 「公開設定」 → `BulkVisibilityDialog` で visibility 選択 → 実行 → 反映
  6. 「エクスポート」 → `BulkExportDialog` で format 選択 → 実行 → エクスポートジョブ起動（P15/P16 で進捗確認）
  7. 100 件を超えるノートを選択 → エラー文言「100 件まで」が表示される
- **期待結果:** すべての bulk 操作が成功、上限超過は schema レベルでブロック

### 6. P10 「ビューとして保存」 + 復元

- **目的:** 現在のフィルタ + 表示形式が SavedView に保存され、`viewId` 指定で復元される
- **手順:**
  1. フィルタを適用した状態で「ビューとして保存」ボタンクリック
  2. `SaveViewDialog` で名前入力 → 保存
  3. `/views?kind=personal` に該当ビューが表示されること
  4. SavedView のリンクをクリック → `/?viewId=...` 形式で URL 遷移、フィルタが復元されること
- **期待結果:** 保存 → 復元の往復が動作

### 7. P11 メタ情報パネル + FrontMatter パネル

- **目的:** ノート詳細でメタ情報・FrontMatter が表示される
- **手順:**
  1. `/notes/$noteId` を開く
  2. メタ情報パネルに「作成日 / 更新日 / タグ chip / ディレクトリパス / 公開状態 chip / バックリンク一覧」が表示されること
  3. FrontMatter パネルで既知キー（title/date/tags/description/slug）が優先表示され、その他は `<details>` で折り畳まれていること
- **期待結果:** すべてのメタ情報が UI に出る

### 8. P11 操作メニュー（公開設定 / 移動 / URL コピー / エクスポート / 複製）

- **目的:** 各操作リンク/ボタンが正しい遷移・動作をする
- **手順:**
  1. ノート詳細で「公開設定」 → `/notes/$noteId/publish` へ遷移
  2. 「移動」 → `MoveNoteDialog` → 実行 → 移動成功
  3. 「URL コピー」 → visibility に応じて公開 URL or 内部 URL がクリップボードへ
  4. 「エクスポート」 → `/notes/$noteId/export` へ遷移
  5. 「複製」 → 新規ノート作成 → `/notes/{新noteId}/edit` へ遷移（spec L128「コピーして新規ノートとして開く」）
  6. 「履歴」 → disabled、tooltip 表示
- **期待結果:** すべての操作が動作

### 9. P12 ディレクトリ選択（既存 / 新規）

- **目的:** ノートエディタでディレクトリ選択 + 新規作成が動作
- **手順:**
  1. `/notes/new` または `/notes/$noteId/edit` でエディタ表示
  2. ディレクトリ select から既存ディレクトリを選択 → 保存 → 該当ディレクトリに作成/移動される
  3. 「新規ディレクトリ」入力欄に名前を入れて保存 → `createDirectoryFn` でディレクトリ作成 → そのディレクトリにノート作成
- **期待結果:** どちらの経路でも適切に処理される

### 10. P12 FrontMatter 編集（既知キー UI + 生 JSON）

- **目的:** 既知キーの構造編集と生 JSON 編集が両方動作
- **手順:**
  1. エディタで「FrontMatter」タブを開く
  2. 既知キー UI で title/date/tags/description/slug を編集 → 保存 → 詳細画面で反映確認
  3. 「生 JSON 編集」トグルで `<textarea>` 表示 → JSON 編集 → 保存 → 反映
  4. 不正 JSON を入力 → インラインエラー表示、保存ボタン disabled
- **期待結果:** 構造編集と JSON 編集が往復可能、不正 JSON はブロック

### 11. P12 メディアアップロード

- **目的:** 画像アップロード → エディタ挿入 → 保存 → 詳細画面で正しく表示される
- **手順:**
  1. エディタで `MediaUploader` のファイル選択
  2. アップロード進行状況が「アップロード中」プレースホルダ表示
  3. 完了後 HTML エディタに `<img src="/media/<id>" alt="">` が末尾挿入される
  4. 保存 → 詳細画面で画像が表示される（`/media/<id>` ルート経由で R2 presigned URL へ 302 リダイレクト）
  5. 動画ファイルも同様に確認
  6. ファイルサイズ超過時はエラー表示
- **期待結果:** 画像/動画が正しく挿入・表示される。**`PurgeOrphans` 実行後も画像が削除されないこと**（refCount が正しく更新されている）
- **R2 CORS 注意:** ローカル環境で CORS エラーが出る場合は wrangler.toml の R2 設定確認

### 12. P12 自動保存

- **目的:** タイトル/本文/FrontMatter 編集後 1.5s で自動保存される
- **手順:**
  1. 既存ノートを編集モードで開く
  2. タイトルや本文を変更
  3. `AutosaveIndicator` が `dirty` → `saving` → `saved hh:mm` と遷移すること
  4. リロード後も変更が保持されていること
  5. 新規ノート（`/notes/new`）では autosave が動作しないこと（noteId 未確定）
- **期待結果:** 自動保存が動作、状態表示が正しい

### 13. P12 編集ロック（ベストエフォート）

- **目的:** 他者ロック中の警告が表示される
- **手順:**
  1. ユーザー A でノートを編集モードで開く（ロック取得）
  2. ユーザー B（別ブラウザ）で同じノートを編集モードで開く
  3. ユーザー B 側に `EditLockBanner` で警告表示、ただし編集は許可される
  4. ユーザー A がタブを閉じる → 60s 後にロック失効、ユーザー B のリロードで警告消える
  5. 削除済みノートを開く → Forbidden/NotFound エラー boundary 表示
- **期待結果:** 警告表示、TTL 失効で解除、Forbidden/NotFound は error boundary に流れる

### 14. P12 WYSIWYG モードタブ（disabled）

- **目的:** WYSIWYG タブが将来枠として表示される
- **手順:**
  1. エディタの `EditorModeSwitch` で「WYSIWYG（準備中）」タブが disabled で表示されること
  2. hover で tooltip「WYSIWYG モードは別 Issue で対応予定」が出ること
- **期待結果:** disabled で将来枠を明示

## エッジケース・異常系

### 1. 大量タグ選択時の URL 長

- **目的:** URL 長制限を超えない範囲で動作
- **手順:** タグ 30 個以上を選択 → URL が `tagNames=` で展開される
- **期待結果:** 文字列ベースで短く保たれる、parse 失敗しない

### 2. autosave 失敗時のリトライ

- **目的:** ネットワーク失敗時に exponential backoff（最大3回）後エラー表示
- **手順:** dev tools でネットワーク offline → 編集 → autosave 失敗 → `AutosaveIndicator` が `error` 表示
- **期待結果:** リトライ後失敗で `error` 状態固定、明示保存で復帰可能

### 3. autosave と明示保存の競合

- **目的:** OCC version 衝突時に最新版 fetch → prompt
- **手順:** autosave 中に明示保存ボタンを連打
- **期待結果:** reducer 内でキューイング、衝突時は最新版を読み直す prompt

### 4. bulk 操作で 100 件超過

- **目的:** schema レベルで上限エラー
- **手順:** 一覧で 101 件選択 → bulk 操作実行
- **期待結果:** 「100 件まで」のバリデーションエラー、API 呼び出し前にブロック

### 5. SavedView 復元時に保存時より新しいタグ削除済み

- **目的:** 「壊れた条件」表示
- **手順:** SavedView 保存後、含まれるタグを削除 → SavedView を開く
- **期待結果:** `validateSavedView` 経由で「条件の一部が無効」表示、可能な範囲で表示

## 既存機能への影響確認

- **P10 既存検索ページ (`/search`)**: 公開ノート横断検索が引き続き動作すること
- **P13 アップロードページ (`/upload`)**: ingestion フローが影響を受けないこと
- **P14 公開設定ページ (`/notes/$noteId/publish`)**: 単発 visibility 変更が引き続き動作
- **P15 エクスポートページ (`/notes/$noteId/export`)**: 単発エクスポートが引き続き動作
- **P16 エクスポートジョブ一覧**: bulk export ジョブが一覧に表示されること
- **P19 ディレクトリツリー**: Sidebar のツリー表示が崩れていないこと
- **P21 タグ管理**: タグ作成/削除が引き続き動作
- **P22 ゴミ箱**: bulk trash で送ったノートが一覧に表示
- **P25 SavedViews**: ビューの delete/setDefault/rename が引き続き動作
