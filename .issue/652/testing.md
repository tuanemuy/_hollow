# 動作確認計画 — Issue #652: 共有 Popover が垂直ビューポート処理を持たず、下方向メニューの末尾項目が画面外でマウス選択できない

**Issue:** #652
**作成日:** 2026-06-13

---

## 確認環境

このIssueの変更（共有 `usePopover` への垂直クランプ追加）を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm db:migrate    # ローカル D1 にマイグレーション適用（初回・未適用時のみ）
pnpm dev           # vite dev (workerd) on http://localhost:3000
```

確認 URL:
- 公開ページ（Sort メニュー）: `http://localhost:3000/u/<username>`（公開ノートを持つユーザー名）
- auth 側（FilterBar の各 popover）: ノート一覧ページ（ログイン後）

### ユニットテスト

```bash
pnpm test:unit     # vitest run（Popover.test.tsx を含む）
```

### デプロイ方法

なし（検証環境のみで確認できる）。

### シードデータ

確認には以下が揃った状態が必要:
- 公開ノートを複数件持つユーザー（Sort メニューが意味を持つ件数）。プロフィールヒーローが背高（表示名・bio・アバター）で、短いビューポートだと Sort ボタンが下部寄りに来る状態。
- auth 側はノート複数件＋タグ複数（FilterBar の Visibility / Date / TagPicker を開ける状態）。

シード整備は manual-test スキルに委ねる。**鍵はビューポート高さを意図的に低く（例: 633px）すること** — 高いデスクトップ高さでは再現しない。

## 確認項目

### 1. 公開ページ Sort メニュー末尾項目のマウス選択（最重要）

- **対応する受け入れ基準:** AC-1
- **目的:** 下方向に開く Sort メニューの末尾項目「タイトル順」が、短いビューポートでも画面内に収まり実マウスでクリックできる。
- **手順:**
  1. ビューポート高さを 633px 程度に設定して `/u/<username>` を開く。
  2. プロフィールヒーロー＋ツールバーで Sort ボタンが下部寄りに来る状態で Sort メニューを開く。
  3. 末尾項目「タイトル順」を**実マウスでクリック**する。
- **期待結果:** メニューが閉じずに `?sort=title` へ遷移する（outside-mousedown で誤って閉じない）。垂直クランプにより末尾項目が画面内（rect bottom ≤ innerHeight - 8px）に収まっている。
- **確認ポイント:** クランプ前（修正なし）は末尾項目が画面外で null になりクリックが落ちる。修正後は全 4 項目が画面内に収まること。

### 2. 既存の選択経路の回帰なし

- **対応する受け入れ基準:** AC-2
- **目的:** 通常のデスクトップ高さ・キーボード操作・URL 直接遷移で全ソート軸が従来どおり選択できる。
- **手順:**
  1. 通常高さ（例: 1000px）で Sort メニューを開き、各項目をマウスクリック。
  2. キーボード操作（メニューを開く → ↓ → Enter）で末尾項目を選択。
  3. `?sort=title` 等に URL 直接遷移。
- **期待結果:** いずれも従来どおり成功し、垂直クランプが通常高さでは余計な translateY を加えない（rect が収まっていれば shiftY=0）。

### 3. auth 側 FilterBar の回帰なし

- **対応する受け入れ基準:** AC-5
- **目的:** 共有基盤の修正が auth 側の下方向メニュー（`VisibilityPopover` / `DatePopover` / `TagPickerPopover`）に波及しても回帰しない。むしろ下端問題が同様に解消する。
- **手順:**
  1. ログイン後のノート一覧で、トリガーが下部寄りになる短いビューポートで Visibility / Date / TagPicker を順に開く。
  2. 各 popover の末尾項目をマウスクリックして選択できることを確認。
  3. 通常高さでも各 popover が従来どおり開閉・選択できることを確認。
- **期待結果:** 全 popover で末尾項目がクリック可能。通常高さで回帰なし。

### 4. ユニットテスト

- **対応する受け入れ基準:** AC-3 / AC-4 / AC-2（既存テスト更新）
- **目的:** `computeShiftY` の純粋関数テスト・DOM スタブテスト・狭幅スキップ・既存 `translateX` テスト更新が通る。
- **手順:**
  1. `pnpm test:unit` を実行する。
- **期待結果:** `Popover.test.tsx` の全テスト（新規 `computeShiftY` 群・上端優先ケース・DOM スタブの `translate(` 検証・狭幅スキップ・更新済み `applies a translateX clamp`）が PASS。
- **確認ポイント:** 既存 `applies a translateX clamp` が `translate(` 形式に更新され失敗していないこと。

## エッジケース・異常系

### 1. 狭幅（max-sm）ボトムシートへの非干渉

- **対応する受け入れ基準:** AC-4
- **目的:** `< 640px` 幅では垂直クランプがスキップされ、`max-sm:fixed max-sm:bottom-0` のボトムシートが破綻しない。
- **手順:**
  1. ビューポート幅を 640px 未満にして Sort / Filter を開く。
- **期待結果:** パネルが画面下部に固定表示され、translateY が乗らずレイアウトが崩れない。

### 2. 縦長パネル（パネル高 > ビューポート高）の上端優先

- **目的:** 縦長になりうる `DatePopover` を短いビューポートで開いたとき、上端優先（先頭が見える位置）にクランプされる挙動を確認。
- **手順:**
  1. `DatePopover` を高さの低いビューポートで開く。
- **期待結果:** パネルの先頭が画面内に見える位置に収まる（末尾は内部到達不可のままでもレイアウトは破綻しない）。max-height の一律付与はスコープ外。

## 既存機能への影響確認

- **UserMenu（上方向 `bottom-full`、非 clamp）:** `clampToViewport` を渡していないため垂直クランプ対象外。従来どおり上方向に開閉・選択できることを確認。
- **actions メニュー（非 clamp）:** `clampToViewport` 未指定の actions 系メニューが無影響であることを確認。
- **#619 TC-002 の解消:** `.issue/619/manual-test/report.md` の TC-002（Sort 末尾項目のマウス選択失敗）が解消されることを確認し、Issue 間トレーサビリティを閉じる。
