# 動作確認計画 — Issue #421: AccountDeleteForm のサーバーエラー時もダイアログを閉じず in-dialog 表示する

**Issue:** #421
**作成日:** 2026-06-06

---

## 確認環境

このIssueの変更は `app/components/identity/AccountDeleteForm/index.tsx`（`/settings` のアカウント削除フォーム）のみ。確認には開発サーバーとログイン済みユーザーが必要。

### 検証環境の起動

```bash
pnpm dev
```

`vite dev --config vite.config.cloudflare.ts` が起動する（package.json `dev`）。表示された localhost のポートを以下で使う。

### ログインユーザーの準備

削除フォームはログイン必須。`docs/test.md` の手順に従い、seed 済み管理者でログインする:

```bash
pnpm seed:dev-admin
```

その後ブラウザで signup したユーザー、または seed ユーザーでログインして `/settings` のアカウント削除セクションへ移動する（パスワードは 12 文字以上必須）。

> 注意: 削除を最後まで実行するとアカウントが消えるため、検証では「確認ダイアログの挙動」までを見て、実際の削除完了は最後の 1 回に絞る。

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. validation エラー（ユーザー名不一致）はダイアログを開いたまま入力欄近接に出る（回帰なし）

- **目的:** #98 ADR-003 で守った入力欄近接表示が本変更で壊れていないこと。
- **手順:**
  1. `/settings` の「アカウント削除」で「続けて削除する」を押し、確認ダイアログを開く。
  2. ユーザー名と**異なる**文字列を入力して「アカウントを完全に削除する」を押す。
- **期待結果:** ダイアログは開いたまま、入力欄の直下に「ユーザー名が一致しません」が表示される。入力欄に `aria-invalid` が付く。
- **確認ポイント:** エラーが入力欄から離れた位置（action row 直上の共通エラー領域）に出ていないこと。

### 2. サーバーエラー時もダイアログを閉じず in-dialog にエラーを表示する（本Issueの主眼）

- **目的:** 非 validation エラーで `setConfirmOpen(false)` されず、ダイアログ内にエラーが出ること。
- **手順:**
  1. サーバーエラーを再現する（例: DevTools の Network で `deleteAccountFn` のリクエストをブロック / オフラインにする、またはサーバー側を一時停止する）。
  2. 確認ダイアログでユーザー名を**正しく**入力し「アカウントを完全に削除する」を押す。
- **期待結果:** ダイアログは閉じず開いたまま、description（入力欄・ヒント）の下・action row の上に `role="alert"` のエラー文言（例: 「システムエラーが発生しました」）が表示される。画面外側（セクション本文）にはエラーが出ない。
- **確認ポイント:** モーダルが一瞬でも消えないこと。フォーカスが confirm ボタン（ダイアログ内）に留まること。

### 3. 成功時はダイアログが閉じてホームへ遷移する（回帰なし）

- **目的:** 正常系（実削除）の挙動が変わっていないこと。
- **手順:** 確認ダイアログでユーザー名を正しく入力し削除を実行する（この検証は最後に 1 回だけ）。
- **期待結果:** ダイアログが閉じ、ホーム（`/`）へ遷移する。

## エッジケース・異常系

### 1. cancel でエラーが破棄される

- **目的:** in-dialog にエラーが出た状態でキャンセルしても、エラーが外側へ「移動」再表示されないこと（#98 ADR-005 の不変条件）。
- **手順:**
  1. 確認項目 2 の状態（in-dialog にサーバーエラーが出ている）を作る。
  2. 「キャンセル」を押してダイアログを閉じる。
- **期待結果:** ダイアログが閉じ、セクション本文側にエラーが残らない。
- **確認ポイント:** 閉じた後に外側 summary（旧 `role="alert" aria-live="polite"`）が出ていないこと。

### 2. 再オープン時にエラーが残らない

- **目的:** open トリガーでの error クリアが効いていること。
- **手順:** 確認項目 1 か 2 でエラーを出した後、ダイアログを閉じ、再度「続けて削除する」で開く。
- **期待結果:** 再オープンしたダイアログにエラーが残っていない（入力欄も空）。

## 既存機能への影響確認

- `/settings` の他フォーム（ユーザー名変更・メール変更・プロンプト・デザイントークン等）に影響しないこと（本変更は AccountDeleteForm の index.tsx に閉じる）。
- `ConfirmDialog` を使う他の削除フロー（note / view / ingestion / trash / tag / directory）に影響しないこと（`ConfirmDialog` 本体は無変更）。
