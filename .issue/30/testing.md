# 動作確認計画 — Issue #30: countByOwner にフィルタを反映

**Issue:** #30
**作成日:** 2026-05-18

---

## 確認環境

このIssueの変更は「ノート一覧画面の件数表示」に現れる。

### 検証環境の起動

```bash
pnpm dev
```

`http://localhost:3000` で TanStack Start アプリが起動する。ノート一覧画面（ホーム / `/`）でフィルタを変えて件数表示を確認できる。

### デプロイ方法

`pnpm deploy:staging` でステージング環境にデプロイ可能（必要なら）。本 Issue は DB スキーマ変更を伴わないので migration は不要。

## 確認項目

### 1. visibility フィルタで count が絞り込み後の件数になる

- **目的:** Issue 本文の例（`?visibility=public` で表示 1 件なのに「10 件」と出る）が解消されていること
- **前提:** 同一 owner で public 1 件 / private 9 件などのテストデータを用意する
- **手順:**
  1. ホーム `/` を開き、ノート一覧が表示されることを確認（フィルタなしで 10 件）
  2. URL に `?visibility=public` を付けて再読込
  3. 表示されているノート枚数と画面上の「N 件のノート」(またはページネーション総件数表示) を比較する
- **期待結果:** 表示件数 = `count` 表示 = public ノートの実件数（1 件）
- **確認ポイント:** ページネーション部分（最終ページ番号など）も filter 後の件数で計算されていること

### 2. tagIds フィルタで count が一致する

- **目的:** タグフィルタでも count が絞り込み後の件数になっていること
- **手順:**
  1. 複数タグを持つノートを用意
  2. ホームでタグフィルタ UI から特定タグを選ぶ（URL に `?tag=...` などが反映される）
  3. 表示件数と count 表示を比較
- **期待結果:** 両者が一致

### 3. status='trashed' フィルタで count がゴミ箱内ノート数に一致する

- **目的:** trashed フィルタでも count が絞り込み後の件数になっていること
- **手順:**
  1. アクティブと trashed のノートが混在する状態にする
  2. ゴミ箱 / trashed 一覧画面を開く
  3. 表示件数と count 表示を比較
- **期待結果:** 両者が一致

### 4. フィルタなしの状態で挙動が回帰していない

- **目的:** opts 未指定（フィルタなし）の場合に従来通り owner の全件を返すこと
- **手順:**
  1. ホーム `/` をフィルタなしで開く
  2. 表示件数と count 表示を比較
- **期待結果:** 両者が一致し、これまで通り owner の総ノート数を表示する

## エッジケース・異常系

### 1. count > limit のとき表示件数と count が分離する（正しい挙動）

- **目的:** ページネーション動線で `notes.length === limit` でも `count` は filter 後の総件数を保持すること
- **手順:**
  1. owner に 20 件の public ノートを用意
  2. URL `?visibility=public&limit=10&page=1` で開く
  3. 表示は 10 件、count 表示は 20、ページネーションには 2 ページ以上が出る
- **期待結果:** 表示 10 件 / count 20 件 / ページ 2 まで遷移可能

### 2. visibility=public でマッチ 0 件の owner

- **目的:** 該当ノートがゼロのフィルタで count が 0 になり、空状態 UI が出ること
- **手順:**
  1. 全ノートが private の owner で `?visibility=public` を指定
- **期待結果:** count 0 / 空状態の表示

## 既存機能への影響確認

- **search モード（`?q=...` 経路）への影響なし**: search モードは `searchOwnNotes` を使うため、`countByOwner` を呼ばない。挙動が変わらないことを確認するため `?q=foo` でも問題ないかチェック。
- **エクスポート (`runExportJob`)**: 内部 mock の `countByOwner` のシグネチャ追従のみ。実行時挙動は変えないため正常完了することを確認。
- **ディレクトリ一覧（`findByDirectory`）**: 別経路。影響なし。
