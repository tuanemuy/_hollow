# TC-002: 保存ビュー「作業中のタスク」が UI 上で読み出せる

**結果**: PASS
**実行時間**: 約 15 秒

## 実行ログ
| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| 1 | ホームの「保存ビュー」セレクトを確認 | 「作業中のタスク」がリストにある | `combobox "保存済みビュー"` 内に `option "作業中のタスク"` が存在 (`ref=e29`) | PASS |
| 2 | 「作業中のタスク」を選択 | URL に viewId が反映、500 にならない | URL が `http://localhost:3000/?page=1&limit=20&viewId=01938f00-0000-7000-8000-00000000d071` に変化、`combobox` の選択値が `作業中のタスク` に変化、500 なし | PASS |
| 3 | ノート一覧が描画される | 一覧描画 / エラーなし | 10 件のリストが正常描画。`#work` / `#todo` を持つノート (Weekly planning, Project A キックオフ, Project B レビュー記録, Q1 ふりかえり, 今日のタスク, 5月定例ミーティング 等) が含まれる | PASS |

## 補足
- ビュー選択後のホーム一覧は `viewId` 付きで描画され、500 / decode 失敗は発生しなかった。
- `decodeQueryJson(work,todo の tagIds[2]) → ViewQuery` / `decodeSortJson({by:"updatedAt", direction:"desc"}) → ViewSort` の rehydrate が UI まで通っていることを確認。
- 現行 UI ではビュー適用時のフィルタリング絞り込みが list セクションに反映されない挙動だが、これは Issue #52 (decode/rehydrate) のスコープ外。`viewId` が反映され UI 上で「保存ビューが選択された状態」に遷移できる点をもって本 TC は PASS。
