# TC-002: GET 系 server function は CSRF 保護の影響を受けない

**結果**: PASS

## 前提条件

- 開発サーバー: `http://localhost:3000`
- `config.appUrl`: `http://localhost:8787`（cross-origin 状態）
- 認証: `__Host-session` cookie に `dev-admin-session-token` を CDP 経由で注入してログイン状態を作成。

## 実行ログ

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| 1 | `/upload` を開き `wait --load networkidle` で描画完了を待つ | GET 系 server function（キュー件数バッジ・ジョブ一覧・有効プロンプト等）が呼ばれてページが正常表示。認証エラーや 403 でのリダイレクトが起きない | タイトル「アップロード — hollow」で正常表示。URL も `/upload` のまま（リダイレクトなし） | PASS |
| 2 | snapshot で GET 由来データの描画を確認 | バッジ・ジョブ一覧・サイドバー等が表示される | サイドバーのノート件数バッジ「すべてのノート 31」、ディレクトリツリー（Research/論文メモ・旅行/京都）、ジョブ一覧4件（test-note-2/4/2/3、いずれも「保存済み」、タグ・ノートを開くリンク付き）、ログインユーザー「Dev Admin / dev-admin@example.com」がすべて描画。エラー表示・alert は一切なし | PASS |

## 判定根拠

- cross-origin 状態でもページ表示自体が成立し、GET 系 server function 由来のデータ（件数バッジ・ジョブ一覧・ディレクトリツリー）が正常に取得・描画された。
- 403 リダイレクトやエラー表示は発生していない。
- => `csrfMiddleware` は GET 系 server function には影響していない（TC-2 PASS）。

## 失敗詳細（FAILの場合）

なし。
