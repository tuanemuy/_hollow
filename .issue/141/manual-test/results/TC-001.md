# TC-001: secret 入り baseURL の masking

**結果**: PASS
**実行時間**: 約 30 秒

## 前提条件

- `.dev.vars`: `ADMIN_LLM_API_KEY="sk-test-dummy-xxxxxxxxxxxxxxx"` を一時設定（draft 接続テストは env api key を用いるため必須）
- `wrangler.toml`: `ADMIN_LLM_PROVIDER = ""` / `ADMIN_LLM_MODEL = ""`（UI 側で provider を OpenAI に切替可能にするため一時的に env override を解除）
- admin user `admin@example.com` でログイン
- provider = OpenAI-compatible

## 目的

baseURL に secret を含めた状態で接続テストを実行しても、エラーバナーに secret が露出しないことを確認する（Issue #141 ADR-003: URL query 全体潰し）。

## 観察事項

- エラー本文は `server_error: internal error; reference = <ID>` の形。Cloudflare Workers (miniflare) が無効ホストへの fetch を `TypeError` ではなく HTTP 500 として処理しており、それを sanitizer が `server_error:` カテゴリに正しく分類した結果。
- secret 部分（`fake-secret-xxx`、`?key=...` query）は完全に隠蔽されている。Issue #141 の主目的「secret 漏洩防止」が達成されている。
- UI 入力欄（textbox value）には当然ユーザーが入れた secret 入り URL が残るが、これは sanitize の対象外（ユーザー入力なので）。
