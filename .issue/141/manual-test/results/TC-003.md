# TC-003: fetch TypeError 経路の masking

**結果**: PASS
**実行時間**: 約 30 秒

## 前提条件

- TC-001/002 と同じセットアップ

## 目的

到達不能ホストへの fetch が `TypeError` を投げる経路で URL の query 部分がマスクされ、category prefix `network:` が付くことを確認する（testing.md エッジケース1）。

## 観察事項

- **Step A** で `network:` prefix にならず `server_error:` になった理由: Cloudflare Workers ローカル dev（miniflare）が無効 DNS への fetch を `TypeError: fetch failed` ではなく HTTP 500 として包んで返している。実環境（本物の Workers）では `TypeError` 経路で `network:` prefix になるはずだが、ローカルでの再現は Step B のように TCP 接続自体が拒否されるパターンが必要。
- **Step B** で完全に testing.md 期待通りの結果（`network: Network connection lost.`）が得られたことにより、sanitizer の TypeError → `network:` カテゴリ化が正しく機能していることを確認できた。
- 全 step で **secret 部分（`should-be-hidden` / `should-be-hidden-2` / `?key=...`）は完全に隠蔽**されており、Issue #141 の主目的が達成されている。
