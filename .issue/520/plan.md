# 実装計画 — Issue #520: design: admin/metrics のデザインモック新設（#510 スコープ外・P40 責務整理と一体）

**Issue:** #520
**作成日:** 2026-06-06
**複雑度:** 中〜大規模

---

## 目的

実装には `/admin/metrics`（`MetricsPage`）が存在するが、対応するデザインモックが `spec/design/pages/` に存在しない（`.issue/500/mapping.md` の E-no-mock）。`admin/metrics` のデザインモック `spec/design/pages/P47-admin-metrics.html` を新設し、P40 ダッシュボードとの責務整理「**ダッシュボード=概況 / metrics=詳細**」を SSOT（`spec/design/index.md`・`spec/pages/index.md`）に反映する。

## スコープ

### 含まれるもの

- `spec/design/pages/P47-admin-metrics.html` の新設（P40〜P46 の共通シェル・トークンを踏襲、単一ファイルでブラウザ表示可能）
- 「概況（P40） / 詳細（metrics, P47）」の責務境界を `spec/design/index.md` §2.4 と `spec/pages/index.md` に明記
- 既存 admin モック（P40〜P46）の `admin-nav` に「利用状況」（→ P47）リンクを追加し、実シェル（8項目）と整合
- index.md 内の範囲表記「P40〜P46」を「P40〜P47」へ更新

### 含まれないもの

- 実装コード（`app/components/admin/Metrics/index.tsx` 等 `.tsx`）の変更 — 実装追従は #514 の受け皿
- P40 → P47 の「詳細を見る」導線の新設（実装に存在せず、net-new UI を増やすため見送り。#514 で判断）
- 新規デザイントークンの定義・ドラフト提案（既存プリミティブの組み合わせで完結）
- admin シェルの検索・通知の去就そのものの最終判断（#500 横断#7 / §2.4 が既に「維持」を明文化済み）

## 実装ステップ

### 1. P47-admin-metrics.html を新設

- **対象ファイル:** `spec/design/pages/P47-admin-metrics.html`
- **変更内容:** P40 を雛形に、
  - (a) `:root` 全トークンを `spec/design/tokens.md` §11 からコピー
  - (b) header は検索（admin 検索）+ 通知 + avatar を維持（§2.4）
  - (c) `admin-nav` を**8項目**にし「利用状況」を `active`、他を未 active に（実シェル順＝ユーザーとジョブ監視の間に配置）
  - (d) main を実装構成で再現 — page-title「利用状況」/ subtitle「インスタンス全体の利用量と、設定済みの上限値。」/ metric-card×4（ユーザー数・合計ストレージ〔R2・DO 内訳の metric-sub〕・本日アップロード・LLM 呼び出し24h）/ アラート section（severity 見本）/ インスタンス上限 section（2列テーブル「項目・値」、値は mono 右寄せ、8行）/ 登録ポリシー section（公開中バッジ + `/admin/registration` 注記）
  - 末尾に HTML コメントで実装追従の差分を明記（(i) 実装ヘッダーは検索・通知が未実装〔§2.4 が SSOT として維持、追従は #514〕／(ii) インスタンス上限テーブルは `.table` プリミティブでモバイルカード化するが、実装 `LimitsCard` は `overflow-x-auto` の素テーブルでカード化しない〔追従は #514〕／(iii) P40 概況との責務境界）
- **理由:** Issue の主目的（net-new モック新設、ブラウザ単体表示）。

### 2. 責務境界を index.md に明記

- **対象ファイル:** `spec/design/index.md`
- **変更内容:** §2.4 の admin 項を「P40〜**P47**」に更新し、責務境界の一文を追記（ダッシュボード（P40）=概況〔ステータス・主要指標・直近アクティビティ〕／利用状況（P47）=詳細〔利用量実数・インスタンス上限・登録ポリシーの突き合わせ〕。両者は重複でなく粒度の違いで役割分担）。なお index.md 内の範囲表記「P40〜P46」は **§2.4（line 51）の1箇所のみ**に存在する（レビューで確認済み）。ここを「P40〜P47」へ更新し、`grep` は他に漏れがないことの確認目的に留める。
- **理由:** Issue 目的「責務整理を SSOT に反映」。範囲表記の更新漏れ防止。

### 3. pages 一覧に P47 を登録

- **対象ファイル:** `spec/pages/index.md`
- **変更内容:** P46 エントリ直後に P47（管理: 利用状況画面）を追加（目的: 利用量と設定済み上限の突き合わせ／機能: 利用量4指標・アラート・インスタンス上限一覧・登録ポリシー現況／関連シナリオ: I5）。P40 の関連シナリオに「（概況。詳細は P47）」を補足し I5 の二画面分担を示す。P40 と P47 は利用量4指標を共有するが、これは**粒度違いの意図的な重複**（P40=概況サマリ／P47=実数・上限突き合わせ）である旨を1文添え、spec-sync での二重定義誤検出を防ぐ。
- **理由:** 機能仕様 SSOT に新画面を登録（cross-phase で I5→P40 単独だった対応に P47 を追加）。

### 4. 既存 admin モック7枚の nav に P47 リンク追加

- **対象ファイル:** `spec/design/pages/P40〜P46-admin-*.html`
- **変更内容:** 各 `admin-nav-inner` に `<a href="P47-admin-metrics.html">利用状況</a>` を「ユーザー」と「ジョブ監視」の間に追加。
- **理由:** 実シェル nav は8項目。新画面を足す以上、既存モックの nav も整合させないと画面間で nav が食い違う（§9「共通シェルは画面ごとに同じマークアップ」）。

### 5. 検証

- **対象:** `spec/design/pages/P47-admin-metrics.html`
- **変更内容:** ブラウザで単体表示し、シェル整合・レスポンシブ（モバイルでテーブル→カード化、nav 横スクロール）・トークン適用を目視。ドキュメントのみのため `pnpm lint`/`typecheck` は対象外。

## 設計判断

- **モック番号は P47**（連番の自然な次・命名整合）。
- **検索・通知ヘッダーは「維持」で作る**（§2.4 が SSOT として維持を宣言済み）。横断#7 の最終判断を先取りせず、末尾コメントで「実装は未実装、追従は #514」を残す。
- **責務境界は「概況 vs 詳細＝粒度の違い」** として §2.4 に1文、pages/index.md の P40・P47 双方に相互参照で明記。「metrics 固有=インスタンス上限テーブル＋登録ポリシー」を境界の決め手にする（usecase 上も metrics だけ `loadInstanceSettings` を引く事実と一致）。
- **P40↔P47 の相互導線は追加しない**（実装に存在せず、Issue の「実装に馴染ませる／実装変更スコープ外」原則に反するため）。
- **既存7枚の nav 更新は実施**（実シェルが8項目である以上、P47 だけ8項目で他が7項目だと §9「共通シェル＝同一マークアップ」が崩れる）。

詳細な設計判断は `.issue/520/adr.md` を参照。

## リスクと注意点

- **範囲表記の更新漏れ:** index.md は「P40〜P46」を複数箇所で使う。grep で全置換を確認。
- **トークン乖離:** `:root` は必ず tokens.md §11 からコピー（§9）。簡略トークンは作らない。§11 準拠でコピーすると既存 admin モック（P40 等）の `:root` に無い `--opacity-disabled: 0.55;` が含まれ、P47 だけ兄弟モックより1トークン多くなるが、これは §11 を正とする意図的な差分（既存モックの §11 追従は本 Issue スコープ外）。
- **実装との差分の扱い:** モックを実装にベタ追従させず、§2.4 方針優先＋末尾コメントで差分を明記（既存 admin モックの慣例どおり）。
- **横断#7 への配慮:** 検索・通知を「維持」で描くことは横断#7 の判断を先取りしない。コメントで追従先（#514）とシェル去就の最終判断先（#500 横断#7）を明記。
- **新規トークン/ドラフト禁止:** 既存プリミティブ（`.banner` `.table` `.tag` `.metric-card` `<code>`ピル）の組み合わせで完結。

## テスト方針

- HTML モックのためブラウザ単体表示が主検証。`P47-admin-metrics.html` を直接開き、(1) シェル（header 検索・通知・avatar、admin-nav 8項目で「利用状況」active）、(2) メトリクス4枚グリッド（sm:2列 / lg:4列）、(3) アラート見本の severity 色、(4) インスタンス上限テーブル（mono 右寄せ・モバイルでカード化）、(5) 登録ポリシーバッジを目視。
- レスポンシブ: 320/375/768/1024/1280px で nav 横スクロール・テーブル変換・カードグリッド段組みを確認。
- ドキュメント整合: index.md / pages/index.md の「P40〜P47」表記と P47 エントリ追加を確認。実装コードは不変のため `pnpm typecheck/lint` は対象外。
