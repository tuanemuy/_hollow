## 確認項目

### 1. 共通 admin シェルの整合

- **目的:** P47 が既存 admin モック（P40〜P46）と同一の共通シェルを持つことを確認する。
- **手順:**
  1. `P47-admin-metrics.html` を開く。
  2. header に検索・通知・avatar があることを確認（§2.4：admin ヘッダーに検索・通知を維持）。
  3. `admin-nav` の項目を数え、**8項目**（…ユーザー → **利用状況** → ジョブ監視…）であることを確認。
  4. 「利用状況」が `active` 状態（他項目と視覚的に区別）になっていることを確認。
  5. 比較として P46 を開き、シェルの構造・トークンが一致していることを確認。
- **期待結果:** header・nav・配色・余白が P40〜P46 と揃い、nav は8項目で「利用状況」が active。
- **確認ポイント:** nav 項目順が実シェル（`app/routes/admin/route.tsx`）と一致しているか。

### 2. メトリクスカード（利用量4指標）

- **目的:** 実装 `MetricsPage` の利用量カード4枚が再現されていることを確認する。
- **手順:**
  1. main 上部の page-title が「利用状況」、subtitle が「インスタンス全体の利用量と、設定済みの上限値。」であることを確認。
  2. metric-card が4枚（ユーザー数 / 合計ストレージ〔R2・DO 内訳の metric-sub 付き〕/ 本日アップロード / LLM 呼び出し24h）あることを確認。
- **期待結果:** 4カードが表示され、合計ストレージカードに R2/DO の内訳サブテキストがある。
- **確認ポイント:** P40 概況のチャート（charts）は P47 には**持ち込まない**（責務境界）。

### 3. アラート section

- **目的:** severity（critical / warning / info）の見本が正しい配色で表示されることを確認する。
- **手順:**
  1. アラート section に severity 見本が表示されることを確認。
  2. critical=error-surface、warning=warning-surface、info=accent-surface の配色になっていることを確認。
- **期待結果:** severity ごとに配色が変わる。
- **確認ポイント:** 配色トークンが tokens.md 由来であること。

### 4. インスタンス上限テーブル

- **目的:** 8行の項目/値2列テーブルが密度優先で表示されることを確認する。
- **手順:**
  1. インスタンス上限 section に2列テーブル（項目・値）があることを確認。
  2. 値が mono フォントで右寄せされていることを確認。
- **期待結果:** 8行のテーブルが表示され、値は等幅右寄せ。
- **確認ポイント:** §2.5（admin 一覧はテーブル基調・密度優先）に沿っているか。

### 5. 登録ポリシー section

- **目的:** 公開中/停止中バッジと変更導線の注記が表示されることを確認する。
- **手順:**
  1. 登録ポリシー section に「公開中」バッジ（success 配色）があることを確認。
  2. `/admin/registration` から変更できる旨の注記（`<code>` ピル）があることを確認。
- **期待結果:** バッジと注記が表示される。

- **目的:** 各ブレークポイントでレイアウトが崩れないことを確認する。
- **手順:**

- **期待結果:** いずれの幅でも内容が読め、横はみ出しや重なりがない。
