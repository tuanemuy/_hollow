
## 確認項目

### 1. FilterBar DatePopover の初期フォーカス（キーボード）

- **対応する受け入れ基準:** AC-1 / AC-3 / AC-5
- **目的:** 「期間」ポップオーバーを開くと、フォーカスがトリガーに留まらずパネル内の先頭プリセットボタンへ移ること。
- **手順:**
  1. ノート一覧の FilterBar で「期間」チップに Tab でフォーカスし、Enter または Space で開く（キーボード操作）
  2. 開いた直後にフォーカスがどこにあるかを確認する（Tab を押さずに、そのまま矢印/Tab で次の要素へ動かして着地点を確かめる）
- **期待結果:** open した瞬間、パネル内の先頭プリセットボタン（例: 一番左上のプリセット）へフォーカスが移る。SR は「ダイアログが開いた」直後にパネル内要素を読み上げる。
- **確認ポイント:** フォーカスがトリガー（期間チップ）に留まったままにならないこと。開いた瞬間に date input（日付ピッカー）が暴発しないこと（先頭 focusable はプリセットボタン）。

### 2. FilterBar DatePopover の Escape クローズとフォーカス復帰

- **対応する受け入れ基準:** AC-6
- **目的:** 初期フォーカスを入れても、Escape で閉じたときにフォーカスがトリガーへ正しく戻ること（非モーダル dismiss の非回帰）。
- **手順:**
  1. 「期間」ポップオーバーを開く（フォーカスが先頭プリセットへ移る）
  2. Escape を押す
  3. 「閉じる」ボタンや外側クリックでも閉じてみる
- **期待結果:** Escape でポップオーバーが閉じ、フォーカスが「期間」トリガーへ戻る。外側 mousedown / Tab-out でも従来どおり閉じる。フォーカストラップは無く、Tab でパネル外へ抜けられる（非モーダル維持）。
- **確認ポイント:** 閉じた後にフォーカスが `<body>` へ落ちず、トリガーへ戻ること。

### 3. PublicTopControls DatePopover の初期フォーカス

- **対応する受け入れ基準:** AC-4 / AC-5
- **目的:** 公開側の DatePopover でも同じく先頭プリセットボタンへ初期フォーカスが移ること（同一 UI の一貫性）。
- **手順:**
  1. 公開側のノート一覧ページを開く（ログイン不要）
  2. 期間フィルタの DatePopover をキーボードで開く
  3. 開いた直後のフォーカス位置を確認する
- **期待結果:** 開いた瞬間、パネル内の先頭プリセットボタンへフォーカスが移る。Escape で閉じるとトリガーへ復帰する。
- **確認ポイント:** FilterBar 側と同じ挙動になっていること。

### 4. dialog を開いたまま操作してもフォーカスを奪い戻さない

- **対応する受け入れ基準:** AC-9
- **目的:** ポップオーバーを開いたまま、パネル内で navigation を伴う操作（プリセット選択・日付入力）をしても、初期フォーカスが先頭へ奪い戻されないこと。
- **手順:**
  1. 「期間」ポップオーバーを開く（先頭プリセットへフォーカス）
  2. Tab で日付入力（開始日）まで移動してフォーカスを置く
  3. 日付を入力する、または別のプリセットボタンを選ぶ（これらは popover を閉じない）
  4. 一覧が絞り込み再描画されたあと、フォーカスがどこにあるかを確認する
- **期待結果:** ユーザーが最後に操作していた要素にフォーカスが留まり、再描画で先頭プリセットボタンへ勝手に戻らない。
- **確認ポイント:** 開閉の立ち上がり（閉→開）のときだけ初期フォーカスが発火し、開いたままの再描画では発火しないこと。

## エッジケース・異常系

### 1. マウス操作で開いたときの挙動

- **目的:** マウスクリックで開いた場合も初期フォーカスがパネル内へ移り、その直後にポップオーバーが誤クローズしないこと（`onFocusOut` 誤発火の回避）。
- **手順:**
  1. 「期間」チップをマウスでクリックして開く
- **期待結果:** パネルが開いたまま維持され、先頭プリセットボタンへフォーカスが移る。開いた瞬間に閉じてしまわない。

### 2. モバイル幅（sheet 表示）での初期フォーカス

- **目的:** `sm` 未満のボトムシート表示でも初期フォーカスが先頭プリセットボタンへ移り、ソフトキーボードが暴発しないこと。
- **手順:**
  1. ブラウザ幅を `sm`（640px）未満にする
  2. DatePopover を開く
- **期待結果:** 先頭の focusable（プリセットボタン）へフォーカスが移る。date input へ直接フォーカスが飛んでソフトキーボード/日付ピッカーが勝手に開かないこと。

## 既存機能への影響確認

- **menu / listbox モードの Popover（roving）:** UserMenu / NoteActionsMenu / DirectoryActionsMenu / ViewSwitcher / FilterBar の公開状態・タグの各ポップオーバーを開き、従来どおり先頭（または選択中）項目へ roving フォーカスが乗り、初期フォーカスが二重化しないこと（AC-7）。
- **DirectoryTreeSelect（dialog モードだが自前フォーカス）:** ディレクトリ選択ポップオーバーを開き、従来どおり検索入力（combobox）へフォーカスが移ること。二重フォーカスや挙動変化が無いこと（AC-8）。
- **DatePopover の clear / 閉じる / 外側クリック:** 期間チップの解除（×）、パネル内「クリア」「閉じる」、外側クリックでの dismiss が従来どおり動くこと。
