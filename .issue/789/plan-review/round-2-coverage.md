#### 改善提案（検討推奨）

- **[S-001]** AC-7 の「roving focus」を、Issue 原文の語と plan の実装方式の対応として一言補足すると追跡が完全になる。
  - 理由: Issue 受け入れ条件 7 は「combobox / listbox の ARIA と **roving focus** を満たす」と書くが、plan/ADR-003 は roving tabindex ではなく `aria-activedescendant` 方式（実フォーカスは input 固定）を採る。これは ARIA APG の combobox パターンとして正当な解釈であり、AC-7 の文言（plan L23）でも「実フォーカスは input に留めた activedescendant 方式」と明示しているため**実質的に解消済み**。ただし「Issue が言う roving focus を activedescendant で満たす」という用語のブリッジを ADR-003 の Decision に一文添えると、受け入れ判定者が「roving tabindex を実装していない＝未達」と誤読するリスクが消える。必須ではない（任意）。

#### 良い点

- **1 周目指摘の解消が誠実かつ追跡可能。** plan 末尾「レビュー履歴」に各指摘の修正内容・反映箇所・理由が列挙され、AC 表／設計ステップ／ADR／テストステップへ漏れなく波及している。指摘を表面的に潰さず、根拠（なぜそうするか）まで残している。
- **AC↔ステップのトレーサビリティが完全。** 全 AC の対応ステップが実在ステップ（1〜7）を参照し、最終ゲート（AC-11）まで独立ステップ化されて紐づけの破綻が無い。
- **検証可能性の底上げ。** S-002/S-003 の反映で、従来「主観的」「曖昧」だった AC-2（× アフォーダンス）・AC-6（空 draft 時の挙動）が客観的な合否基準（`aria-label`・コントラスト変化・最小ヒット領域／空白 draft は `null`）に落ち、レビュー時の判定が機械的に行える。
- **スコープ規律の維持。** 「含まれないもの」（サーバ往復・autosave 仕様・reducer 拡張・ドメイン正規化・新規 UC/loader）が引き続き明確で、2 周目時点でもスコープクリープは無い。フロントエンドのみの境界が保たれている。
