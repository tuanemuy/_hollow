# 動作確認計画 — Issue #789: ノート編集画面のタグ入力(tag input)の見た目と入力方法を改善する

**Issue:** #789
**作成日:** 2026-06-28

---

## 確認環境

このIssueはフロントエンドのみの変更（`TagsInput.tsx` の combobox 化 + `tagSuggestModel.ts` 新設 + `styles.ts` 追加・改修 + `NoteEditor`/ルート2本の候補配線）。確認に必要な手順のみ記載する。

### 検証環境の起動

フロントエンドのコンポーネント変更なので、HMR が効く vite dev を使う。

```bash
pnpm db:migrate   # ローカル D1 にマイグレーション適用（未適用なら）
pnpm dev          # vite dev（workerd / @cloudflare/vite-plugin）。http://localhost:3000
```

> ソースを本番相当のビルドで確認したい場合のみ `pnpm build && pnpm start`（wrangler dev、`dist/worker` を配信）。フロントエンド反復には `pnpm dev` の方が適する。

### シードデータ（必須）

note editor 画面（`/notes/new` または `/notes/$noteId/edit`）は `_app` 配下の認証必須ルートなので、ログイン済みユーザーが要る。`docs/test.md` の手順に従い、決定論的な管理者ユーザーとセッションを投入する。

```bash
pnpm seed:dev-admin
```

出力されるトークンを CDP 経由でセッション cookie に注入する（cookie 名 `__Host-session` は Secure 必須で `document.cookie` 注入不可）。

```bash
agent-browser cookies set "__Host-session" "<token>" \
  --url http://localhost:3000 --path / --secure --sameSite Lax
```

**候補表示（autocomplete）の検証には既存タグが必要**。`loadAllTags` が供給源なので、事前にタグ付きノートを数件作っておく。最短ルートは UI 上で `/notes/new` から `react`, `typescript`, `日本語タグ` などをタグに付けて保存し、いくつか既存タグを作る。あるいは SQL で直接投入する場合は `pnpm db:execute:local <SQLファイル>` を使う（tag テーブルにレコードを入れる）。既存タグがゼロだと候補ドロップダウンは出ず、新規作成インジケータのみの確認になる。

### デプロイ方法

なし（検証環境のみで確認できる。本番反映は通常のデプロイフロー `pnpm deploy:staging` / `pnpm deploy:production` に従う）。

## 確認項目

### 1. コンテナ枠とフォーカス可視化

- **対応する受け入れ基準:** AC-1
- **目的:** chip + input が 1 つのコンテナ枠で囲まれ、input フォーカス時にフォーカスリングが出ることを確認する。
- **手順:**
  1. `/notes/new` を開く。
  2. タグ入力フィールドの位置を確認する（枠で囲まれているか）。
  3. タグ入力欄をクリック（フォーカス）する。
- **期待結果:** chip と入力欄が 1 つの枠（border）で囲まれ、フォーカス時に枠の色変化＋フォーカスリング（shadow）が出る。
- **確認ポイント:** input 自身とコンテナで二重のフォーカスリングが出ていないこと（リングはコンテナに一本化されている）。

### 2. 空状態ガイドと chip の × 削除アフォーダンス

- **対応する受け入れ基準:** AC-2
- **目的:** タグ未入力時のガイド表示と、各 chip の明示的な × 削除ボタンを確認する。
- **手順:**
  1. タグ未入力の状態でフィールドを見る（placeholder/ガイド文言）。
  2. タグを 2〜3 個入力する。
  3. 各 chip の × ボタンにマウスを乗せる（hover）/ Tab でフォーカスする。
  4. × ボタンをクリックして chip を削除する。
- **期待結果:** 空のときガイド文言が出る。各 chip に × ボタンがあり、hover/focus でコントラストが変化する。クリックで該当 chip が削除される。
- **確認ポイント:** × ボタンに `aria-label`（例: 「タグ「react」を削除」）が付いていること。

### 3. 既存タグ候補のドロップダウン表示

- **対応する受け入れ基準:** AC-3
- **目的:** `loadAllTags` を供給源に、入力中に既存タグ候補のドロップダウンが出ることを確認する。
- **手順:**
  1. 既存タグ（例: `react`）が登録された状態で `/notes/new` を開く。
  2. タグ入力欄に `re` と入力する。
  3. 候補ドロップダウンを観察する。
  4. 既に chip として確定済みのタグ名で部分一致入力し、候補に出ないこと（除外）を確認する。
- **期待結果:** `re` に部分一致する既存タグ（`react` 等）が候補リストに表示される。確定済みタグは候補から除外される。
- **確認ポイント:** 大文字小文字・全角半角・先頭 `#` の違いがあっても正規化して一致/除外されること。

### 4. ↑↓ + Enter のキーボードナビゲーション

- **対応する受け入れ基準:** AC-4, AC-7
- **目的:** 候補を ↑↓ で移動し Enter で確定できることを確認する。
- **手順:**
  1. 候補が複数出る状態で入力する。
  2. ↓ キーを 1 回押す。
  3. さらに ↓/↑ で候補を移動する。
  4. Enter で確定する。
- **期待結果:** 最初の ↓ で先頭候補（1 件目）がハイライトされる（2 件目に飛ばない）。Enter でハイライト中の候補が chip に追加される。
- **確認ポイント:** 実フォーカスは input に留まったまま（candidate の見た目だけがハイライト）であること。

### 5. 「既存一致」と「新規作成」の区別表示

- **対応する受け入れ基準:** AC-5
- **目的:** 入力中に「既存タグ一致」か「新規タグ作成」かが視覚的に区別できることを確認する。
- **手順:**
  1. 既存タグに一致する文字列を入力する（例: `react`）。
  2. どの既存タグにも一致しない新規文字列を入力する（例: `mynewtag123`）。
- **期待結果:** 既存一致時は候補リストにその名前が出る。新規作成時は「新規作成」を示す行（`＋`/`#` グリフや accent 色）が表示される。
- **確認ポイント:** 新規作成のみの場合（既存候補ゼロ）でもパネルが描画され新規作成行が見えること。

### 6. ↑↓未選択時の Enter は draft を新規確定（候補に奪われない）

- **対応する受け入れ基準:** AC-4, AC-5
- **目的:** 候補がハイライトされていない状態の Enter が、部分一致候補ではなく入力中の draft を新規タグとして確定することを確認する。
- **手順:**
  1. 既存タグ `foobarbaz` がある状態で `foobar` と入力する。
  2. ↑↓ を押さずにそのまま Enter を押す。
- **期待結果:** `foobarbaz` ではなく `foobar` が chip として追加される。
- **確認ポイント:** ↓ で候補を選んでから Enter した場合のみ既存候補が採用されること。

### 7. 入力時バリデーションエラーの即時表示

- **対応する受け入れ基準:** AC-6
- **目的:** 50 文字超・不正文字などのバリデーション違反が入力時に即時フィードバックされ、commit が抑止されることを確認する。
- **手順:**
  1. 51 文字以上の文字列を入力する。
  2. Enter / blur を試す。
  3. 文字数を 50 以下に減らす。
- **期待結果:** 51 文字以上のときエラーメッセージが出て chip 化されず draft が残る。50 以下に減らすとエラーが消え commit できる。
- **確認ポイント:** 空欄/空白のみの draft ではエラーが出ないこと。

## エッジケース・異常系

### 1. IME（日本語入力）変換中の確定キー・矢印キー

- **目的:** IME 変換確定中の Enter/カンマ/矢印キーが commit・候補移動を起こさないことを確認する。
- **手順:**
  1. 日本語入力 ON で「にほんご」と打ち、変換候補が出ている状態にする。
  2. 変換確定の Enter を押す（タグ commit ではなく変換確定であるべき）。
  3. 変換中に ↑↓ を押す（IME の候補移動であるべき）。
  4. 変換確定後にもう一度 Enter でタグを commit する。
- **期待結果:** 変換中の Enter/矢印は IME 操作になり、タグ commit や候補移動を起こさない。確定後の Enter で初めてタグが commit される。

### 2. Escape での候補クローズ

- **目的:** Escape で候補パネルが閉じ、draft が保持されることを確認する。
- **手順:**
  1. 候補が出ている状態で Escape を押す。
  2. 入力欄の draft を確認する。
- **期待結果:** 候補パネルが閉じ、入力中の文字列は残る。再度入力すると候補が再表示される。

### 3. 候補クリックでの確定（blur 暴発しない）

- **目的:** 候補をマウスクリックして確定したとき、blur による draft 誤 commit が起きないことを確認する。
- **手順:**
  1. 候補が出ている状態で候補の 1 つをマウスでクリックする。
- **期待結果:** クリックした候補だけが chip 化され、draft の二重 commit や意図しない別タグの追加が起きない。

### 4. 既存挙動の保持（Enter / カンマ / Backspace / blur）

- **目的:** 既存の入力挙動が壊れていないことを確認する。
- **手順:**
  1. `a,b,c` とカンマ区切りで入力して確定する（3 つの chip になる）。
  2. draft 空の状態で Backspace を押す（末尾 chip が消える）。
  3. 非空 draft のまま入力欄外をクリック（blur）する（valid なら commit される）。
- **期待結果:** カンマ分割・Backspace 末尾削除・blur commit が従来どおり動く。

## 既存機能への影響確認

- **autosave がタグを送らない既存挙動**: タグを追加/削除しても、autosave のネットワークリクエスト（draft 保存）のペイロードに tags が含まれないこと（ブラウザの DevTools Network で確認）。
- **ノート編集画面（`/notes/$noteId/edit`）**: 既存ノートを編集する経路でも新しいタグ入力 UI が同様に動作すること。
- **disabled 状態**: 保存中など TagsInput が disabled のとき、候補が開かず入力・× 操作が不活性になること。
