## 補足

- **TC-003-d の確認方法**: `/notes/new` は新規ノートのため画面上は「自動保存はオフ」で autosave が走らない。そこで既存ノート編集画面 `/notes/01960696-0000-7000-8000-000000000001/edit`（autosave オン）でタイトル編集＋タグ追加（Enter で commit）を行い、`network har` で autosave の `saveNoteDraftFn` POST を捕捉した。2回の autosave いずれも payload の対象キーは `noteId / title / contentHtml / frontMatterJson` のみで、`tagNames` および追加タグ文字列は一切含まれていなかった。
  - ソースでも裏取り済み: `app/components/note/editor/useAutosave.ts:249-260` が autosave 時に渡すのは `{noteId, title, contentHtml, frontMatterJson}` のみ。`app/components/note/schema.ts:126-132` の `saveDraftSchema` は `tagNames` を optional で許容するが、`app/components/note/actions.ts:346` の `saveNoteDraftFn` は `void data.tagNames;`（コメント: tag re-extraction runs in the explicit save path）で明示的に無視している。タグ確定は明示保存パス（`saveNoteFn`/`createNoteFn`）の責務。
- **TC-003-e（disabled）**: 保存中に TagsInput を disabled にする状態をブラウザ操作で安定的に作り出すのが困難なため SKIP。dropzone/TagsInput の disabled 不活性はユニットテスト（PR #795 系の data-disabled 規約テスト等）で担保されている前提。
- agent-browser のセレクタは `@ref` 形式または CSS セレクタを使用（role 名直指定 `combobox` は本 CLI では not found となった）。候補ドロップダウンを開く際は最後の1文字を `press` して input イベントを発火させた。
- 注記（テストデータ副作用）: TC-003-d の確認のため既存ノート `01960696-...-000000000001` のタイトル末尾に編集文字（`X EDIT`）が autosave され、タグ `autosavetag`/`secondtag` が追加された。シードノートに対する想定内の副作用。
