# 残存課題 — Issue #588: モバイルモック(#536)の実装追従 ② 画面別レイアウト

**Issue:** #588
**記録日:** 2026-06-08

実装はモバイルレイアウト追従（overflow=0・縦積み・シート化）を完了。以下は本Issueの制約（レイアウトのみ / リテラルpx新規持ち込み回避 / #563・#568 機能追加禁止 / 無変更で狭幅PASSなら変えない）に基づき、意図的に据え置いた項目。

## 1. export 画面（P15/P16）はモックへのフル視覚追従を見送り

- **内容:** `app/components/export/{ExportForm,ExportJobsList,ExportJobDetail}/` は **className を一切持たない素の HTML**（`<section>`/`<ul>`/`<dl>`）で、デスクトップ用スタイルも存在しない。素のブロックフローで既に「1カラム・縦積み・overflow=0」を満たすため、`max-sm:` 差分の追加は不要だった。
- **理由:** モック（segmented control・job-card・meta グリッド）への完全追従は新規 px/トークンを伴う**視覚フル再実装**で、本Issueの「レイアウトのみ / px新規持ち込み回避」を逸脱する。受け入れ基準（320〜430px で横スクロールなし）は満たしている。
- **影響範囲:** P15/P16 は機能的に動作し横スクロールも発生しないが、モックのビジュアル（カード化・segmented control）には未追従。
- **フォローアップ:** export 画面のデザイン追従（デスクトップ含む視覚実装）が必要なら別Issueとして起票するのが適切。Phase 4 で検討。

## 2. P30 公開トップの profile-hero は構造再現を見送り

- **内容:** モバイルモックは avatar+name を `.profile-head` 行にまとめ bio/stats を全幅にする構造だが、現実装は `grid grid-cols-[auto_1fr]`（avatar | 全テキスト）。
- **理由:** モック構造へ寄せるには DOM 子要素を 2→3 に再構成する必要があり、`max-sm:` だけでは表現不可（JS/DOM分岐が要る）。差分は「bio/stats がアバター幅ぶん右にインデントされる」外観のみで、320px でも横はみ出しなし。「無変更で狭幅PASSなら無理に変えない」方針に従い据え置き。
- **影響範囲:** P30 は overflow=0 を満たすが、bio/stats のインデントがモックと僅かに異なる。

## 3. P32 公開検索 hero の text 配置（既存デスクトップ乖離）

- **内容:** モバイル/デスクトップ両モックとも `text-center` だが現実装は `text-left`（#544 由来の既存乖離）。
- **理由:** center 化はデスクトップにも波及し、本Issueの「縦積み/シート化/横スクロール」マンデート外の配置変更になるため未対応。
- **影響範囲:** 横スクロールには無関係。デスクトップ含む既存の配置方針の問題。

## 4. P18 タグ行はケバブメニュー方式を維持

- **内容:** モバイルモックは `.list-row` を単列化しアクションを下段展開するが、実装は #542 ADR-003 のケバブメニュー（`max-lg` で `⋯`）方式。
- **理由:** 両者とも overflow=0 を満たし、ケバブの方がコンパクト。既存の確立済み方針（#542 ADR-003）を尊重。
- **影響範囲:** なし（受け入れ基準を満たす）。
