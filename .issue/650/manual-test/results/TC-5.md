# TC-5（確認項目5 / AC-5）切替・永続値復元のいずれも loader を再実行しない（#219 維持）

判定: PASS（簡易確認）

> Network タブの直接観測は agent-browser では取りにくいため、タスク指示に従い「切替で一覧データ（並び）が変わらず表示レイアウトだけ切り替わること」「URL 無指定 reload で永続値が復元されること」を簡易確認した。

## 操作ログ

| # | 操作 | 結果 |
| - | --- | --- |
| 1 | ホーム（クエリなし）でリスト表示の先頭5件タイトルを取得 | 検証ノートA改 (コピー) / Test Note 02 / 1週間以内のノート hollow671 / 検証ノートA改 / Test Note 14 |
| 2 | segmented「タイル」(e11) をクリック → 先頭5件を再取得 | 同一の並び（再取得・再ソートなし）。URL は `?display=tile` に in-place 変化 |
| 3 | segmented「カレンダー」(e12) をクリック → 先頭5件を再取得 | 同一の並び。localStorage = `"calendar"` |
| 4 | `http://localhost:3000/`（クエリなし）で再読込 | tablist「カレンダー」[selected]、日付見出し（main h2）= 7 個 → 永続値が復元 |

## 確認ポイント

- 3モード間で一覧データ（先頭5件の並び）が同一。表示レイアウトのみ切替。
- segmented 切替はページ遷移ではなく URL の in-place 反映（即時、1レンダーパス相当）。
- URL 無指定 reload で永続値 calendar が復元される。

## 備考

- 厳密な loader 非再実行（RSC ストリーム/server fn 呼び出しの不発）は Network 観測が必要で、本検証ではデータ不変＋即時切替による間接確認にとどまる。
