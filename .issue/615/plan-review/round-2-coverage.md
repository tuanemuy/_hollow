## サマリ

Round 1 の改善提案（S-001〜S-004）は計画・ADR に適切に反映されている。

- **S-001（4種別 glyph 差異の検証粒度）** → AC-3 を「desktop / mobile / tablet は互いに異なる glyph、unknown は汎用 glyph」に一意化。ステップ8・テストも同表現で揃っている。
- **S-002（geo 抜き meta 行構成）** → AC-4・設計 UI 節・ステップ8 に「2行構成（1行目 IP / 2行目 最終アクセス）、device はタイトルへ集約、`·` 複合行を作らない」を明記。
- **S-003（AC-5 の createdAt 相対化の必須/努力目標の揺れ）** → AC-5 を「updatedAt に使うのが必須、createdAt の相対化は努力目標」に一意化。ステップ8「ログイン日時は維持」との齟齬が解消。
- **S-004（geo 見送りの spec トレーサビリティ）** → ステップ9 に「geo は外部依存のため別 Issue と明記」を追加。AC-7 本文は device/updatedAt 反映中心の表現のままだが、ステップ9 で spec への記録が担保されており、実装漏れにはならない（後述 S-001 で軽微に補強推奨）。

また Round 1 で確認済みの既存コード整合（`resolve` が updatedAt を更新しない / `SessionDTO.updatedAt` projection 済み・UI 未使用 / `SessionIcon` 単一 glyph / `sessionTitle` フォールバック / `getCurrentUser` が `resolve` を呼ぶ唯一の cache() 経路 / meta 行が現状 IP + ログイン日時の2行）を本ラウンドでも再確認し、計画記述と一致することを確認した。

Issue 本文スコープ4項目（device-parser / geo / 最終アクセス時刻 / 相対時刻整形）は AC-1〜AC-7 に漏れなく対応し、geo 見送りも「未実装＝虚偽回避」として AC-6 + ADR-002 に決着している。要件カバレッジ・スコープ整合の観点で残る「要修正」は検出されなかった。

#### 改善提案（検討推奨）

- **[S-001]** AC-7 の文言が「device projection・updatedAt 更新経路を反映」中心で、geo 見送りの spec 記録（ステップ9 で実施予定）が AC レベルの検証項目として独立していない
  - 理由: Round 1 S-004 の趣旨（geo 見送り判断を spec に残すことを基準で担保）はステップ9で取り込まれており実装漏れにはならないが、AC-7 本文に「geo を別 Issue 化した旨を spec に記録する」を一文足すと、虚偽表示禁止の一貫性（AC-6・ADR-002）が spec 反映の受け入れ基準にも結びつき、トレーサビリティが基準レベルで閉じる。軽微。

- **[S-002]** AC-4 が「更新経路が無い場合は『最終アクセス』ラベルを出さない」と条件付き表示を規定しているが、本 Issue では `recordActivity` で更新経路を必ず入れるため、この分岐は実質「常にラベルを出す」になる。一方ステップ8は無条件で2行目「最終アクセス」を出す前提で、両者は実装上は整合するが、`updatedAt` が万一 `createdAt` と同値（一度も活動 touch されていないセッション＝発行直後）の場合に「最終アクセス: たった今/ログイン直後」のように createdAt と重複した相対時刻が出る点が基準・ステップから読み取りにくい
  - 理由: スコープ整合の欠落ではない（updatedAt 更新経路は入るので虚偽ではない）。ただし「ログイン日時」と「最終アクセス」が同一相対時刻になりうる初期状態の見え方を、ステップ8 か リスク欄に一文残すと、検証者が「重複表示はバグか仕様か」で迷わない。実害は小さい。

#### 良い点

- Round 1 の4提案（S-001〜S-004）がすべて計画・ADR に追跡可能な形で反映され、レビュー履歴に修正点・取り込み・見送り理由が明記されている。指摘の取りこぼしは無い。
- Issue スコープ4項目の AC 対応（スコープ1→AC-1/2/3、スコープ2→AC-6、スコープ3→AC-4、スコープ4→AC-5、規約→AC-7）が漏れなく、各項目が「実装する／見送る」で明確に決着。判断保留が無い。
- geo 見送りが Issue の虚偽表示禁止原則と一貫。ADR-002 が「手元データで解決不能な唯一の要素」「不正確な geo は捏造禁止違反」「外部依存が表示リッチ化に不釣り合い」「別 Issue 化」と論証し、UI を #572 の IP 素出し据え置きで揃える。Issue 本文「実データを伴って初めて表示する」と矛盾しない。
- AC-2 / AC-3 の検証粒度が Round 1 反映で一意化され、「desktop と mobile が同一 glyph でも合格」と読めてしまう曖昧さが解消。捏造回避（判別不能は null / 汎用 glyph / 不明な端末）が型・テスト（ステップ3）で検証可能。
- スコープ外の線引きが明示的で、既存 `revoke`/`revokeSession` 温存、専用 last-active 列・イベント駆動の不採用、相対時刻ヘルパーの全画面一括展開の見送りを「含まれないもの」に列挙。スコープクリープが無い。
- 各 AC が「対応ステップ」列でステップに紐づき、AC-1→1、AC-4→4,5,6,8 等の紐づけがステップ内容と一致（紐づけ誤りは検出されず）。

## 既存コードとの整合再確認（事実確認）

- `getCurrentUser`（currentUser.ts L51-62）は `resolve(token)` を呼ぶ唯一の cache() 経路で try/catch を持たない read-only ヘルパー → 計画の注入点・best-effort 化（P-001/P-002）の前提と一致。
- `SecurityForm`（SecurityForm/index.tsx）の `SessionIcon` は全行同一 glyph、`sessionTitle` は UA 素出し→「不明な端末」、meta は「IP（あれば）」+「ログイン日時」の現状2行 → 計画のリッチ化対象・S-002 反映後の2行構成と整合。
- 計画が参照する #572 由来の表示分離（projection / SessionRow 差し替えで段階導入可能）は実コードと一致。
