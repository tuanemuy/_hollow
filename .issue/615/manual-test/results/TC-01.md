# TC-01: device-parser によるデバイスラベル表示（AC-1 / AC-2）

対象: `/settings/security` セッション一覧
シード: 同一ユーザー 5+ アクティブセッション（HeadlessChrome×2 / iPhone Safari / curl / macOS Safari / Windows Chrome）

| # | 操作 | 期待 | 実際 | 判定 |
|---|------|------|------|------|
| 1 | `/login` で `test-615@example.com` ログイン → `/settings/security` を開く | セッション節に複数行表示 | 6 行表示（現行 HeadlessChrome + 旧 HeadlessChrome 残骸 + iPhone/curl/macOS/Windows） | PASS |
| 2 | iPhone(mobile) 行のタイトル確認 | `Safari on iOS`（`{browser} on {os}`） | `Safari on iOS` | PASS |
| 3 | macOS Safari 行のタイトル確認 | `Safari on macOS` | `Safari on macOS` | PASS |
| 4 | Windows Chrome 行のタイトル確認 | `Chrome on Windows` | `Chrome on Windows` | PASS |
| 5 | curl 行（判別不能 UA）のタイトル確認 | ラベル捏造せず UA 素出し（label=null → userAgent → 不明な端末 の優先順） | `curl/8.0.1`（UA 素出し。OS/ブラウザ名を捏造していない） | PASS |
| 6 | HeadlessChrome 行のタイトル確認 | UA 素出し（HeadlessChrome は device-parser でラベル化されない）→ 捏造なし | `Mozilla/5.0 (Macintosh ... HeadlessChrome/149 ... Safari/537.36)` 素出し | PASS |

判定: PASS。`{browser} on {os}` 形式のパースラベルが判別できた行に出る。判別不能/未対応 UA はラベルを合成せず UA を素出しする（虚偽表示なし）。

備考: `getTitle`（`app/components/identity/SecurityForm/index.tsx` L113-122）が `device.label → userAgent → 不明な端末` の順でフォールバックする実装に一致。curl は「不明な端末」ではなく UA 素出し（UA が空でないため）で、これは仕様どおり。
