# TC-10: 既存機能への影響 — 行単位ログアウト・「このセッション」バッジ（#572）

対象: device ラベル/アイコン/最終アクセス追加後も、非現行行の個別ログアウトと現行行の「このセッション」pill が #572 どおり動くか。client に session token が露出しないか。

| # | 操作 | 期待 | 実際 | 判定 |
|---|------|------|------|------|
| 1 | 現行 HeadlessChrome 行に「このセッション」バッジが付くこと | 現行行のみ pill 表示・ログアウトボタンなし | 現行行に `このセッション` 表示、ログアウトボタンなし（非現行 5 行にのみログアウトボタン） | PASS |
| 2 | 非現行行（Chrome on Windows）の「ログアウト」を実行 | その行が一覧から消える | クリック → networkidle 後、`Chrome on Windows` と `198.51.100.42` が一覧から消失。ログアウトボタン数 5→4 | PASS |
| 3 | ログアウト後 DB 確認 | 該当セッション行が失効/削除 | `sessions` から Windows 行（UA LIKE %Windows%）が 0 件に。実失効を確認 | PASS |
| 4 | ログアウト後も現行行・他行が残ること | 現行「このセッション」維持、他行（iPhone/curl/macOS）は残存 | `このセッション` 維持、`Safari on macOS` 等の他行残存 | PASS |
| 5 | client に session token が露出しないこと | HTML/DOM に平文トークンが出ない | `document.body.innerHTML` に seed の平文トークン（`test615-session-` / `_B4YNofN` / `ix5tff4`）が一切なし → opaque sessionId のみ | PASS |

判定: PASS。行単位ログアウトが #572 どおり機能し、対象行が UI と DB の両方から消える。「このセッション」バッジは現行行に正しく付与され、token は client に露出しない。
