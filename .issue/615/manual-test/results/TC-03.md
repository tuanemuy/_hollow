# TC-03: 最終アクセス（updatedAt）相対時刻の表示（AC-4 / AC-5）

対象: `session-meta` 2 行目「最終アクセス: {相対時刻}」が実データ（updated_at）に基づき表示されるか。
シードの now 基準: 注入時刻 約 `2026-06-24T16:35Z`。検証時のサーバ now はこれより僅かに後（現行ログインは `16:38`）。

| # | 操作 | 期待（投入 updated_at） | 実際の表示 | 判定 |
|---|------|------|------|------|
| 1 | 現行 HeadlessChrome 行（updated_at = ログイン直後） | たった今 | `最終アクセス: たった今` | PASS |
| 2 | iPhone Safari 行（updated_at `16:30Z` ≈ 5〜8 分前） | N 分前 | `最終アクセス: 8 分前` | PASS |
| 3 | curl 行（updated_at `14:35Z` ≈ 2 時間前） | N 時間前 | `最終アクセス: 2 時間前` | PASS |
| 4 | macOS Safari 行（updated_at `13:35Z` ≈ 3 時間前） | N 時間前 | `最終アクセス: 3 時間前` | PASS |
| 5 | Windows Chrome 行（updated_at `2026-06-21T16:35Z` ≈ 3 日前） | N 日前 | `最終アクセス: 3 日前` | PASS |

判定: PASS。各行の相対時刻が投入 updated_at と整合（たった今 / N 分前 / N 時間前 / N 日前 の全粒度を確認）。

備考: スロットル付き recordActivity による「活動で更新が進む」動的検証は、スロットル幅（5 分）超の待機が 1 TC=3 分の制約に収まらないため未実施（SKIP）。ただし現行行が `updated_at == created_at`（ログイン直後）で「たった今」を示しており、recordActivity のソースが updated_at である点と初期状態の整合（エッジケース4）は確認できた。スロットル挙動自体は integration test（`identity.integration.test.ts` の `recordActivity (#615)`）でカバー。
