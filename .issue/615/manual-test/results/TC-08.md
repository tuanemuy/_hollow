# TC-08: エッジケース3 — recordActivity 失敗時も認証が落ちない（best-effort）

種別: コードレビュー観点（結合テストで担保される範囲。実機では正常運用で認証エラーが出ないことを確認）。

| # | 操作 | 期待 | 実際 | 判定 |
|---|------|------|------|------|
| 1 | `getCurrentUser` 内の recordActivity 呼び出しが限定 try/catch で握り潰されるか（コード確認） | 失敗時は `logger.warn` に留め、認証は完結 | `app/lib/server/currentUser.ts` L71-75: `try { recordActivity(token) } catch (cause) { container.logger.warn("Failed to record session activity", { cause }) }`。JSDoc L52-58 に best-effort の意図明記 | PASS |
| 2 | 保護ページ表示で 5xx に落ちないこと（実機） | 認証経路（requireCurrentUser/requireAdminUser 含む）が完結 | `/`, `/settings`, `/settings/security` を遷移し全て 200 表示・認証エラーなし | PASS |

判定: PASS。recordActivity は best-effort（限定 try/catch + logger.warn）で実装され、付随書き込み失敗が認証を落とさない設計。実機でも認証エラーは顔を出さない。

備考: recordActivity を強制失敗させる注入は実機では行えないため、握り潰しの実挙動は integration test（`identity.integration.test.ts` の不在トークン no-op 等）とコードで担保。本 TC は静的確認 + 正常系の非破壊確認。
