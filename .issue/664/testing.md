# 動作確認計画 — Issue #664: P10 FilterBar: タグフィルタの連続トグルで lost update

**Issue:** #664
**作成日:** 2026-06-13

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm dev
```

ホーム（P10）にタグ付きノートが 3 件以上（互いに異なるタグを持つ）必要。不足する場合はノート作成画面から `#tag1` `#tag2` `#tag3` のようなタグ付きノートを作成する。

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. タグ 3 連クリックで全件累積（AC-1）

- **対応する受け入れ基準:** AC-1
- **目的:** 連続トグルが lost update せず全タグが URL に反映されること
- **手順:**
  1. `pnpm dev` でホームを開く
  2. FilterBar のタグチップ 3 つを素早く連続クリックする（1 フレーム間隔程度）
- **期待結果:** URL の `?tagNames=[...]` に 3 タグすべてが含まれ、一覧が 3 タグで絞り込まれる
- **確認ポイント:** 2/3 件にロストしないこと。チップ 3 つすべてがアクティブ表示のまま確定すること

### 2. 選択済みタグの解除（AC-2）

- **対応する受け入れ基準:** AC-2
- **目的:** 単発トグルの既存挙動が維持されること
- **手順:**
  1. タグを 1 つ選択した状態で、同じタグチップをクリックする
- **期待結果:** 該当タグだけが `tagNames` から外れ、チップが非アクティブになる

### 3. 全タグ解除で URL クリア（AC-3）

- **対応する受け入れ基準:** AC-3
- **目的:** 最後のタグを外したとき `tagNames` パラメータ自体が消えること
- **手順:**
  1. 選択中のタグをすべて解除する
- **期待結果:** URL から `tagNames` が消え、一覧が全件表示に戻る

## エッジケース・異常系

### 1. 選択・解除の混在連打

- **目的:** 追加と解除が混ざった連続操作でも最終状態が正しいこと
- **手順:**
  1. タグ A を選択済みの状態で、A（解除）→ B（追加）→ C（追加）を素早く連続クリックする
- **期待結果:** `tagNames` が B と C の 2 件になる

## 既存機能への影響確認

- 期間・公開状態・内部リンク参照・ディレクトリの各フィルタ操作、および「フィルタをすべてクリア」が従来どおり動くこと（`run` の共通経路は変更しないため軽く確認）
- ユニットテスト: `pnpm test:unit` が全件パスすること
