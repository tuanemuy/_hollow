## 確認項目

### 1. 再生成後の待機 → プレビュー復帰（既存ジョブ起点の happy path・回帰）

- **目的:** #253 ADR-003 のモーダル内完結（再生成 → waiting → editing 復帰）が引き続き動くこと。
- **手順:**
  1. ファイルをアップロードしてプレビュー編集（`editing`）に到達する。
  2. 「再生成」を押す。
  3. 待機表示（LLM がタイトルとメタデータを提案中…）に切り替わるのを確認。
  4. 推論完了後、再びプレビュー編集画面に戻ることを確認。
- **期待結果:** モーダルを離れずに再生成結果のプレビューが表示される。
- **確認ポイント:** 待機中に最初のドロップゾーン（`select`）へ戻らないこと。

### 2. failed からの再試行 → 待機 → プレビュー復帰（既存ジョブ起点・回帰）

- **目的:** failed view の「再試行」が waiting に再入し、ポーリングが継続すること。
- **手順:**
  1. 取り込みが `failed` になるジョブで `failed` view に到達する（または `/upload` の失敗ジョブから操作）。
  2. 「再試行」を押す。
  3. 待機表示に切り替わり、その後プレビュー編集に戻ることを確認。
- **期待結果:** 再試行後にモーダル内で待機 → 編集に進む。
- **確認ポイント:** ドロップゾーンへ戻らないこと。

### 3. 初回アップロードの待機 → プレビュー（回帰）

- **目的:** 初回アップロード起点の正常系が変わっていないこと。
- **手順:**
  1. ファイルをアップロードする。
  2. 待機表示 → プレビュー編集に進むことを確認。
- **期待結果:** 従来通りプレビュー編集に到達。

## エッジケース・異常系

本 Issue の核心（待機ポーリング中の fatal error 時の遷移出し分け）は、ブラウザ上で fatal error を意図的に再現するのが困難なため、**ユニットテスト（`UploadDialog.test.tsx`）で担保する**:

- 既存ジョブ起点（再生成 / retry）の fatal → `queueGuidance`（ドロップゾーンに戻らず、キュー画面リンク表示）。
- 初回アップロード起点の fatal → `select`（従来通りドロップゾーンへ）。

```bash
pnpm test:unit
```

## 既存機能への影響確認

- 初回アップロードの fatal 時に `select` へ戻る挙動（やり直し導線）が維持されていること。
- `timedOut` view・transient 上限超過時の挙動が壊れていないこと。
