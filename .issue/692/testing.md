## 確認項目

### 1. エディタ本文（ビジュアル / markdown 両モード）の caret-only 化

- **対応する受け入れ基準:** AC-1
- **目的:** 編集領域全体（約 480px）を囲む箱型フォーカスリングが消え、caret + 選択色のみでフォーカスが示されること
- **手順:**
  1. エディタ画面（P12）を開く
  2. ビジュアルエディタ本文をクリック、またはキーボード（Tab）でフォーカスを入れる
  3. markdown / HTML モードがあれば切り替えて同様にフォーカスを入れる
  4. テキストを選択して選択色を確認する
- **期待結果:** 編集領域全体を囲む箱リングが描画されない。caret（accent 色）が見え、テキスト選択時に選択色（accent-surface）が出る
- **確認ポイント:** WysiwygEditor（ProseMirror）と InlineEditor（markdown/HTML）の両方で箱リングが出ないこと。InlineEditor は host にも子孫にもリングが出ないことを両方見る

### 2. タイトル入力の caret-only 化

- **対応する受け入れ基準:** AC-2
- **目的:** タイトル入力にフォーカスしても四角い箱リングが出ず、本文と一貫した caret-only 表現になること
- **手順:**
  1. エディタ画面でタイトル入力に Tab でフォーカスを入れる（キーボード操作で `:focus-visible` を発火させる）
  2. クリックでもフォーカスを入れて比較する
- **期待結果:** タイトル周りに四角い 4px / 2px の箱リングが出ない。caret（accent 色）でフォーカスが分かる
- **確認ポイント:** `focus-visible:shadow-none` の打ち消しがグローバル `:focus-visible`（`@layer base`）に詳細度で勝っていること（リングが残っていたら打ち消し失敗）

### 3. 通常 input のフォーカスリング細線化（各画面チェックリスト）

- **対応する受け入れ基準:** AC-3, AC-4, AC-7
- **目的:** グローバル `--shadow-focus` の細線化（4px→2px）後、各画面の通常 input でリングが視認でき、潰れ・はみ出し・コントラスト不足がないこと
- **手順:** 以下の各 input に Tab でフォーカスを入れ、2px リングの見え方を確認する。確認結果をチェックリストとして記録する:

  | # | 画面 / input | 場所 | 背景 | 確認 |
  |---|---|---|---|---|
  | 3-1 | auth INPUT | `auth/styles.ts:40` | surface→focus 時 bg | リングが 2px で視認できる |
  | 3-2 | auth INPUT（error+focus） | 同上 | 同上 | error 枠（inset）＋ 2px リングが合成され破綻しない |
  | 3-3 | public search | `public/styles.ts:202` | surface | リングが 2px で視認できる |
  | 3-4 | public TOKEN_INPUT | `public/styles.ts:299` | bg / `focus-within` | リングが 2px で視認できる |
  | 3-5 | public form input | `public/styles.ts:346` | white | リングが 2px で視認できる |
  | 3-6 | tag 入力 ×2 | `tag/styles.ts:75,144` | surface | リングが 2px で視認できる |
  | 3-7 | fieldControl | `common/styles.ts:266` | グローバル `:focus-visible` 経由 | リングが 2px で視認できる |

- **期待結果:** 全 input で 2px リングが見え、潰れ・隣接要素へのはみ出し・コントラスト不足がない
- **確認ポイント:** 特に error+focus（3-2）で inset の error 枠と外側リングが両立すること

### 4. WCAG コントラスト（白背景・surface 背景の両方）

- **対応する受け入れ基準:** AC-4
- **目的:** 細線化後のリングが WCAG 2.4.7 / 2.4.11 を満たす（白背景・surface 背景の両方で概ね 3:1 以上）
- **手順:**
  1. 白背景 input（例: public form input）と surface 背景 input（例: public search / tag 入力）でリング色とその隣接背景のコントラストを DevTools / コントラストツールで実測する
- **期待結果:** どちらの背景でもリングのコントラストが 3:1 以上（ADR-002 の計算と整合）
- **確認ポイント:** surface カード内 input ではリングが surface に隣接するため、白背景だけで判断しない

## エッジケース・異常系

### 1. キーボード操作での書く面フォーカスの可視性

- **目的:** マウス/タップではなくキーボード（Tab）で書く面（エディタ本文・タイトル）に入った際、caret + 選択色だけで十分に視認できるか
- **手順:**
  1. ページ最上部から Tab だけでエディタ本文・タイトルまで移動する
- **期待結果:** どこにフォーカスがあるか caret（accent 着色）で判別できる。箱リングが無くても操作位置を見失わない

### 2. auth error+focus の合成リング

- **目的:** error 状態の input にフォーカスしたとき、error 枠（inset）と外側リングが両立し、4px の取り残しが無いこと
- **手順:**
  1. ログイン/登録フォームでバリデーションエラーを発生させ、その input にフォーカスを入れる
- **期待結果:** inset の error 枠（1px）＋ 外側 2px リングが合成表示され、旧 4px の太いリングが残らない

## 既存機能への影響確認

- **全画面の input フォーカス:** グローバル `--shadow-focus` 変更はアプリ全画面の box-shadow 方式 input に波及する。上記チェックリスト（確認項目3）で網羅的に確認する。
- **outline 方式の list/menu 系:** `focus-visible:outline-accent` を使うコンポーネントは `--shadow-focus` 非依存なので非影響（確認不要）。
- **#689（border 撤去）との連動:** 本Issueは `focus-within:*` クラスのみを触り border 系には手を付けないため、#689 とは独立に動作する。
