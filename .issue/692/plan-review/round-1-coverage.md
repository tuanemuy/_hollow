# Plan Review — Issue #692 (Round 1)

**視点:** Issueの要件カバレッジ・スコープ整合性
**対象:** `.issue/692/plan.md`, `.issue/692/adr.md`
**レビュー日:** 2026-06-13

---

## サマリ

Issue #692 の受け入れ条件6項目は、おおむね plan.md の AC 表（AC-1〜AC-9）に正しく落ちている。各 AC は検証可能な形で書かれており、実装ステップとの紐づけも整合する。調査結果は実コードと一致しており（WysiwygEditor:576 / InlineEditor:863 / titleInput / tokens.css:120 / auth INPUT の 4px 直値複製）信頼できる。スコープ境界（#689 の border 撤去を持ち込まない）も明示的に守られている。

ただし1点、**モック同期のカバレッジに重大な漏れ**がある（`--shadow-focus` トークンは P12 だけでなく 105 個のモック HTML と `tokens.md` に複製されている）。AC-5 / ステップ4 が P12 のみを対象にしているため、グローバルトークン値変更後にモック群全体が実装と乖離する。これは plan.md の調査結果でも見落とされている唯一の構造的な穴であり、要修正と判断する。

---

## 問題点（要修正）

- **[P-001]** `--shadow-focus` トークン値の細線化（4px→新値）に対し、モック側の同期対象が `P12-editor.html` 1 ファイルに限定されている。実際には `--shadow-focus: 0 0 0 4px ...` の定義が `spec/design/pages/` 配下の **105 個の HTML** に複製されており（PC版 + `mobile/` 版、各ページ冒頭の `:root` ブロックで直値定義）、さらに `spec/design/tokens.md` の 226 / 535 行にも記載されている。
  - 理由: `spec/design/tokens.md` 冒頭が「値の追加・変更はこのファイルを正としてから各画面に反映する」と明記しており、モックはトークン SSOT を各ページに複製する設計。AC-5（「`--shadow-focus` の値が実装トークンと一致する」）を P12 だけ満たしても、残り 104 ページのモックは旧 4px 値のまま実装と乖離する。Issue 受け入れ条件4「通常の input（`fieldControl` 等）のフォーカスが新トークンで破綻しないか**各画面で**確認」の精神にも反する（モックは各画面の参照基準であり、トークン変更の波及はモック全体に及ぶ）。plan.md の「調査結果」のトークン消費者リスト（47-53 行）はアプリ側の波及は網羅しているが、モック側の複製範囲を P12 のみと誤認している。
  - 提案: 次のいずれかを AC・ステップ・ADR に明記する。(a) 全 105 モック + `tokens.md` の `--shadow-focus` 直値を新値へ一括置換することをステップ4の対象に含める（`:root` 内 caret-only の `.editor`/`.title-input` 上書きは P12 のみで良い）。(b) スコープ管理上それが過大なら、「caret-only の構造的上書きは P12 のみ、トークン直値の全モック同期は別Issue/フォローアップとする」と明示的にスコープ外宣言し、その判断を ADR-003 に追記する。いずれにせよ「P12 のみで AC-5 達成」という現状の暗黙の前提は誤りなので訂正が必要。

## 改善提案（検討推奨）

- **[S-001]** AC-7（各画面の input フォーカス破綻確認）が「目視確認」のみで、対象画面の列挙が plan.md ステップ6に留まっている。受け入れ条件として「確認したことの記録（どの画面を見たか）」が成果物に残らないと、後から検証可能性が落ちる。
  - 理由: AC-4 はコントラスト数値を ADR-002 に残す形で検証可能性を担保しているが、AC-7 は同等の記録方針が無い。グローバルトークン変更の波及確認は本Issueの主要リスク（plan.md「リスクと注意点」でも筆頭級）なので、確認結果を簡潔にチェックリスト化して残すと再現性が上がる。

- **[S-002]** ADR-002 の第一候補 `0 0 0 2px var(--color-accent)`（不透明 accent, 白背景 ~8.9:1）は、現行の半透明 4px リング（~1.6:1）と比べて見た目の性格が大きく変わる（淡いリング → 濃い 2px 実線）。Issue は「雑な細線化はしない」「3:1 を維持」を求めているのでコントラスト面は問題ないが、不透明 accent はデザイントーン（Apple Calm = 淡く控えめ）と衝突する可能性がある。
  - 理由: ADR-002 自身も「強すぎると判断されれば alpha を 0.6〜0.75 に下げる余地を残す」と書いており、実装時にデザイン判断が割れると手戻りになりうる。AC-4 の検証時に「白 / surface 両背景での見た目」を確認する点を ADR-002 の検証手順として明記し、確定値を実装着手前に1つに絞っておくと安全。なお Issue スコープ内の調整なので追加要件ではない。

- **[S-003]** AC-1 は WysiwygEditor / InlineEditor 両方の wrapper を対象にしているが、Issue 本文の論点1は WysiwygEditor のみを明示し InlineEditor には触れていない。plan.md の調査（42 行）と ADR-001 で「InlineEditor も P12 の書く面変種であり caret-only 方針の対象」と判断根拠を残している点は妥当で、スコープ拡大ではなく一貫性担保として正しい（実コードでも `NoteEditor.tsx` が wysiwyg / html / inline の3モードを切り替え、InlineEditor は同一 P12 画面の inline モード本体で、`focus-within:border-accent focus-within:shadow-focus` + 内側 caret-only の構造が WysiwygEditor と同一であることを確認した）。
  - 理由: 問題ではないが、レビュー観点として「InlineEditor を含める判断は妥当」と明記しておく。むしろ InlineEditor を除外する方が「P12 のモード間でフォーカス挙動が不一致」という新たな乖離を生むため、含める判断が正しい。ADR-001 にこの「除外すると逆に不整合になる」根拠を1行足すとより強固。

## 良い点

- Issue の受け入れ条件6項目（caret-only 化 / モック更新 / 細線化+WCAG / input 破綻確認 / ADR 記録 / 静的検査）がすべて AC-1〜AC-9 にマッピングされ、各 AC に「由来」列で出典（論点1/2/3, a11y 注記, AC）が明示されている。トレーサビリティが高い。
- 調査結果が実コードと正確に一致している。WysiwygEditor:576・InlineEditor:863 の `focus-within:border-accent focus-within:shadow-focus` + 内側 `focus-visible:shadow-none` / `caret-accent` / `selection:bg-accent-surface`、titleInput の `rounded-*` 欠落、tokens.css:120 の 4px 値、index.css:176 のグローバル `:focus-visible`、いずれも検証済み。
- **AC-6 が秀逸**。Issue 本文には書かれていない `auth/styles.ts` の `0_0_0_4px_oklch(37.1%_0_0_/_0.28)` 直値複製（`INPUT` の `data-[error]:focus-visible:shadow-[...]`）を調査で発見し、トークン変更に追従しない取り残しとして独立 AC + 専用ステップ5 + ADR-003 に落としている。これは実コードでも確認でき（grep で唯一の 4px 直値複製）、見落とせば error+focus 時だけ太い 4px が残る実害がある。漏れなく拾えている。
- スコープ境界の管理が明確。#689 の border 撤去（`border-hairline` / `rounded-md` / `p-4`）を本Issueに持ち込まず、ADR-004 と「リスクと注意点」で担当クラスを `focus-within:*` のみに限定。`transition-[border-color,box-shadow]` を #689 の領分として「触らない（box-shadow トランジションが無害に残るのは許容）」と判断しているのも、スコープ汚染を避ける正しい線引き。#689 の border 撤去は本計画のどのステップにも混入していないことを確認した。
- 既存の WCAG 未達（現行 4px が ~1.6:1 で 2.4.11 未達）を ADR-002 で正面から分析し、「薄くするだけは退行」と退路を塞いだ上で不透明 accent 案で 3:1 を大幅クリアする数値根拠を提示。Issue の a11y 注記（「雑な細線化はしない」）に忠実。
- `admin/Dashboard/index.tsx:94` の `shadow-[0_0_0_4px_rgba(31,143,58,0.12)]`（success ステータスドットの装飾影）を「focus 無関係・非対象」と正しく除外している。4px という数値が一致するため誤って対象に含めかねない箇所を、文脈を読んで適切に切り分けている。
