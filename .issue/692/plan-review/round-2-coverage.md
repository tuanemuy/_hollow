## サマリ

1周目で唯一の要修正だった **P-001（モック同期の範囲漏れ）は適切に解消された**。AC-5 / ステップ1 / ADR-003 が「トークン定義（tokens.css SSOT）＋ tokens.md（226 / 535 行）＋ 直値複製のある全 105 モック HTML を新値へ一括同期」に具体化され、caret-only の構造的上書き（`.editor` / `.title-input` の `:focus-visible` 打ち消し）は書く面を持つ P12 のみ、と線引きも明示された。1周目の改善提案（S-001 記録チェックリスト、S-002 確定値の絞り込み）も取り込まれている。

本周の主眼である「P-001 対応で AC-5 が全 105 モック同期へ拡張されたことが over-scope でないか」を grep で実態検証した結果、**over-scope ではない**と判断する。根拠は下記「良い点」に詳述するが、要点は (1) 105 モック全部が `--shadow-focus` 4px を **定義かつ消費** しており、トークン値変更がそのまま全ページのフォーカスリング描画に効く（死んだ定義はゼロ）、(2) `spec/design/tokens.md` 冒頭がデザインシステムの SSOT 契約として「値の変更はこのファイルを正としてから各画面に反映する」と明記しており、全モック同期はこの規約の履行であって計画者の創作した追加作業ではない、の2点。Issue AC が P12 を明示するのは「caret-only という構造変更」の対象が P12 だけだからで、トークン値の同期範囲を P12 に限定する趣旨ではない（むしろ Issue AC「各画面で確認」がモック横断の波及を前提にしている）。

要修正は1点。**「105」の内訳に drafts が1件混入しており、計画の記述（"PC版 + mobile版"）と実態がズレている**。over-scope そのものではないが、同期対象に exploratory な draft を機械的に含めるかどうかは明示的にスコープ判断すべき箇所であり、訂正を求める。

## 問題点（要修正）

- **[P-001]** AC-5 / ステップ1 / 調査結果（plan.md:55）/ ADR-003 が同期対象を「`spec/design/pages/**`（PC版 + `mobile/` 版）の 105 ファイル全部」と記述しているが、grep で内訳を確認すると **105 = 55（PC top-level）+ 49（mobile/）+ 1（drafts/P10-header-refined.html）** であり、1件は `drafts/` 配下の探索用ドラフトである。計画の「PC版 + mobile版」という性格付けは drafts の存在を取りこぼしており、数（105）は正しいが内訳の記述が不正確。
  - 理由: `drafts/` は canonical なモック（spec/design/tokens.md が「各画面に反映する」と言う「各画面」）とは性格が異なる探索用の成果物（同ディレクトリの他2件 `P10-header-options.html` / `P10-toolbar-options.html` は `--shadow-focus` を持たず、`P10-header-refined.html` のみ 4px を直値複製・消費している）。トークン SSOT の同期義務が drafts にまで及ぶかは自明でなく、機械的一括置換に含めると「破棄予定のドラフトに本Issueの diff が乗る」over-scope になりうる。逆に「canonical な 104（PC 55 + mobile 49）のみ同期」と決めるなら数も記述も訂正が必要。いずれにせよ現状の「PC + mobile で 105」は内訳が破綻している（PC + mobile は 104）。
  - 提案: 次のいずれかに統一する。(a) drafts は同期対象外とし、AC-5 / ステップ1 / ADR-003 を「canonical な 104 モック（PC 55 + mobile 49）+ tokens.md」に訂正（drafts 除外の理由を ADR-003 に1行）。(b) drafts も含める方針なら「105 = PC 55 + mobile 49 + drafts 1（`P10-header-refined.html`）」と内訳を正確に明記し、drafts を含める根拠（機械置換のコストが極小・乖離を残さない）を ADR-003 に1行残す。数の根拠（grep 内訳）を計画に書いておくと再現性が上がる。

## 改善提案（検討推奨）

- **[S-001]** ステップ1の「一括置換」が機械的（`0 0 0 4px oklch(37.1% 0 0 / 0.28)` → 新値）であることは妥当だが、grep 上、`--shadow-focus` を含む行には2形態ある: (1) 単独行 `--shadow-focus: 0 0 0 4px ...;`（94 ファイル）、(2) 複数トークンを1行に連結した行 `... --shadow-md: ...; --shadow-focus: 0 0 0 4px ...;`（11 ファイル）。後者は他トークンと同一行のため、行単位の置換ツールだと取りこぼしやすい。置換は**値文字列 `0 0 0 4px oklch(37.1% 0 0 / 0.28)` 単位**で行う（行頭・行末に依存しない）と明記しておくと、11 ファイルの連結行も確実に同期できる。
  - 理由: 計画は「機械的」とだけ書いており置換単位が曖昧。値文字列単位なら両形態を漏れなく拾え、AC-5 の「全モック同値化」が確実になる。スコープ追加ではなく実施手順の明確化。

## 良い点

- **1周目 P-001 が過不足なく解消された**。AC-5 が「トークン定義（tokens.css）＋ tokens.md（226 / 535 行）＋ 直値複製のある全モック HTML を新値へ同期。加えて P12 の `.editor` / `.title-input` に caret-only 上書き」と、トークン値同期（全モック）と構造変更（P12 のみ）を明確に分離して記述している。ADR-003 にも同期スコープと P12 限定の線引きが残り、トレーサビリティが高い。
- **全 105 モック同期は over-scope ではないことを実証確認した**。grep で 105 ファイル全部が `--shadow-focus: 0 0 0 4px` を **定義し、かつ `box-shadow: var(--shadow-focus)` で消費** していることを確認（define 105 / consume 105、define-but-not-consume はゼロ）。つまり全ページでトークン値がフォーカスリング描画に実際に効いており、P12 のみ更新すれば残り 104 ページが旧 4px のまま実装と乖離する。Issue AC が P12 を明示するのは「caret-only という構造変更」が書く面を持つ P12 固有だからで、`--shadow-focus` は P12 専用トークンではなくアプリ全画面（`fieldControl` / search / TOKEN_INPUT / tag 入力 / auth 等）に効くグローバルトークンである。よってトークン値の同期は全モックに及ぶのが必要十分で、計画の拡張は要件の正しい解釈。
- **デザインシステムの SSOT 契約に沿っている**。`spec/design/tokens.md` 冒頭（6 行目）が「すべての画面 (`spec/design/pages/*.html`) でこのトークンを参照する。値の追加・変更はこのファイルを正としてから各画面に反映する」と明記しており、全モック同期はこの既存規約の履行。計画者が発明した追加作業ではなく、規約上当然に求められる範囲。CLAUDE.md の Styling 規約（tokens.css が SSOT、tokens.md はミラー）とも整合する。
- **caret-only の構造的上書きを P12 のみに正しく限定**。grep で `.title-input` / `.editor:focus` / contenteditable を持つモックは `P12-editor.html` だけと確認。書く面（document canvas）は P12 固有であり、他104ページに `.editor:focus-visible { box-shadow: none }` 等を撒くのは無意味。計画はこの構造変更を P12 限定とし、トークン値同期（全モック）と切り分けており、過剰にも過少にもなっていない。
- **#689（border 撤去）のスコープ汚染が引き続き無い**。本計画のどのステップにも `border-hairline` / `rounded-md` / `p-4` の撤去は混入しておらず、ADR-004 で担当クラスを `focus-within:*` のみに限定。1周目の判断が維持されている。
- AC-6（auth 直値複製の追従）・S-001（input 確認のチェックリスト記録）・S-002（確定値1案＋フォールバック1案への絞り込み）など、1周目で評価した点・改善提案がそのまま残っており、modify による退行は無い。
