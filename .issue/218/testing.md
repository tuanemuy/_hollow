## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
# DB マイグレーションを local に適用（既存テーブル / カラムには変更なしだが、初回セットアップ向け）
pnpm db:apply:local

# 開発サーバ起動（Cloudflare Workers + D1 + Vite）
pnpm dev
```

ブラウザで `http://localhost:5173`（Vite デフォルト）を開き、admin ロールでログインしてから `/admin/prompts` / `/admin/design` を確認する。

### デプロイ方法

なし（検証環境のみで確認可能）。staging 確認が必要になった場合のみ `pnpm deploy:staging` + `pnpm db:apply:staging` を実行。

## 確認項目

### 1. プロンプト編集画面の表示（未上書き状態）

- **目的:** 既定値（=「LLM プロバイダ既定指示を使用」のヒント文）が見え、上書き中バッジが出ていないことを確認。
- **手順:**
  1. admin ロールで `/admin/prompts` を開く
  2. 5 つの purpose カード（structure / title / directory / metadata / ocr_assist）が並んでいることを確認
  3. 各カードの textarea が空 or placeholder 表示
  4. 「上書き中」バッジが表示されていない
  5. 「既定値: LLM プロバイダの既定指示を使用」のようなヒント文が見える
- **期待結果:** 全カードが「未上書き」状態で表示される
- **確認ポイント:** purpose 名が domain SSOT（5 値）に揃っていること、UI 側 3 値（ingestion_structuring 等）の残骸がないこと

### 2. プロンプト編集 → 上書き状態

- **目的:** テキスト入力 → 保存で「上書き中」バッジが表示される。
- **手順:**
  1. `/admin/prompts` で structure カードに任意のテンプレート文を入力
  2. 「保存」ボタンが enabled になることを確認
  3. 保存
  4. ページが再描画され、structure カードに「上書き中」バッジが出る
- **期待結果:** 入力した文が保存され、バッジ表示される
- **確認ポイント:** リセットボタンが表示／有効化されること

### 3. 項目ごとのリセット

- **目的:** 単一 purpose の上書きを削除し、既定状態に戻せる。
- **手順:**
  1. （確認項目 2 の続き）structure カードの「この項目をリセット」ボタンをクリック
  2. ページが再描画される
- **期待結果:**
  - structure カードの textarea が空に
  - 「上書き中」バッジが消失
  - 「既定: LLM プロバイダ既定指示」ヒント文が再表示
- **確認ポイント:** 他 purpose の上書き状態は影響を受けないこと

### 4. 「全プロンプトをリセット」 — 確認モーダル経由

- **目的:** 全 purpose を一括で既定に戻す操作が、確認モーダル経由で実行できる。
- **手順:**
  1. `/admin/prompts` で title / directory の 2 つに任意の文を入力 → 保存（2 つ上書きありの状態を作る）
  2. 画面下部の「全プロンプトをリセット」ボタンをクリック
  3. ConfirmDialog が表示されることを確認
  4. 「キャンセル」をクリック → モーダルが閉じる、上書き状態は変わらない
  5. 再度「全プロンプトをリセット」 → 「確定」をクリック
- **期待結果:** 全 5 カードが未上書き状態に戻る
- **確認ポイント:**
  - キャンセル時に何も変わらない
  - 確定時に全バッジ消失

### 5. デザイントークン編集画面 — 行追加 → 行削除

- **目的:** 上書き行の追加と「この上書きを削除（既定に戻す）」が正しく動作する。
- **手順:**
  1. admin ロールで `/admin/design` を開く
  2. 「行を追加」して `--color-accent` / `#ff0000` を入力 → 保存
  3. 一覧に新規行が表示されることを確認
  4. その行の「この上書きを削除」ボタンをクリック → 確認
- **期待結果:** 行が一覧から消える（= 既定値に戻る）
- **確認ポイント:**
  - placeholder に key 名のヒントが出る
  - `spec/design/tokens.md` への参照リンク／補助テキストがある

### 6. デザイントークン全リセット — 確認モーダル経由

- **目的:** 全リセットが確認モーダル経由で実行できる。
- **手順:**
  1. `/admin/design` で 2 つ以上の上書きを追加 → 保存
  2. 「初期値リセット」（既存ボタン名）をクリック
  3. ConfirmDialog が表示される
  4. キャンセル → 何も変わらない
  5. 再度クリック → 確定
- **期待結果:** 全行が消える
- **確認ポイント:** モーダルなしでリセットが走らないこと

## エッジケース・異常系

### 1. 非 admin ユーザーのアクセス拒否

- **目的:** admin 権限なしユーザーがリセット操作にアクセスできないこと。
- **手順:**
  1. 非 admin ユーザーで `/admin/prompts` を開く（ルートガードで弾かれる想定）
  2. もし URL 直叩きで到達したら、サーバアクションがエラーを返すか確認
- **期待結果:** ガードまたはエラー応答で操作不可

### 2. ingestion ジョブ — 上書きなし purpose のフォールバック

- **目的:** プロンプトを未上書きにした purpose（特に `structure` / `metadata`）で取り込みが LLM プロバイダ既定指示にフォールバックして動作すること。
- **手順:**
  1. `/admin/prompts` で全プロンプトをリセット（確認項目 4）
  2. ingestion ジョブを実行可能なテスト動線（fixtures / メディア追加など）で取り込みを発火
  3. ジョブログでエラーが出ていないことを確認
- **期待結果:** 取り込みが正常完了（LLM プロバイダ既定指示で動く）
- **確認ポイント:** `promptResolver` の挙動が本 Issue で変わっていないこと

### 3. UserPromptOverride 画面 (P23) の整合性

- **目的:** `getInstancePromptDefaults` の API 互換維持により、P23 画面表示が壊れないこと。
- **手順:**
  1. 一般ユーザーとしてプロンプト編集画面（P23: `/(authenticated)/settings/prompts` 相当）を開く
  2. 「インスタンスデフォルト継承中」表示が壊れていないことを確認
- **期待結果:** 既存挙動どおり
- **確認ポイント:** `defaults` map が 5 purpose 揃って返ること

## 既存機能への影響確認

- `runIngestionJob`（structure / metadata の resolver 呼び出し）が変更後も動作すること（エッジケース 2 で確認）。
- 既存 DB に保存されている「full map + 空文字」プロンプトデータが、Partial 化後に「未上書き」と正しく解釈されること（リハイドレート正規化）。
