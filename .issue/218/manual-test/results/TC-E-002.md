# E-002: ingestion ジョブ — 上書きなし purpose のフォールバック

**結果:** SKIPPED
**実行日時:** 2026-05-28

## スキップ理由

ingestion ジョブを UI から発火するには:
1. メディア upload（PDF/画像）→ 実 LLM API キーが必要（インスタンス設定で provider 設定済が前提）
2. ジョブが Cloudflare Workers Queue を介して relay → consumer まで通る完全なパイプラインの稼働
3. LLM 呼び出しが実行され、結果として「フォールバック挙動」が観測可能になる

ローカル `pnpm dev` 環境で本テストを実施するには、有効な LLM API key と adapter 設定、queue 動作の確認まで含めて環境構築が必要であり、本 Issue #218 のスコープ（プロンプト/トークンの上書き UI）からは大きく外れる。

`promptResolver` の挙動は本 Issue で変更されておらず（`getInstancePromptDefaults` の API 互換維持）、空文字 → プロバイダ既定指示にフォールバックする実装は変更がない。これはユニット/結合テスト（`pnpm test`）でカバーされている。

## 推奨対応

- 本テストは spec/manual-tests に「将来検証」として残し、staging 環境で LLM API が稼働した時点で実施する。
- ローカルでの代替として、`runIngestionJob` の挙動を結合テスト（`app/core/__tests__/`）でカバー継続することで品質を担保する。
