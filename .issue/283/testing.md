# 動作確認計画 — Issue #283: UrlCopyButton: コピー成功時にアイコンを Link2 → Check に切り替える

**Issue:** #283
**作成日:** 2026-05-29

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm db:migrate   # ローカル D1 にマイグレーション適用（未適用の場合）
pnpm dev          # 開発サーバー起動（Cloudflare Workers ランタイム / vite dev）
```

`UrlCopyButton` はノート詳細ページ（`/notes/<id>` または公開共有ページ）に表示される。確認には少なくとも 1 件のノートが必要。シードデータの準備は manual-test スキルに委ねる。

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. コピー成功時に Check アイコンへ切り替わる

- **目的:** コピー成功時に視覚フィードバックとしてアイコンが一時的に `Check` へ変わることを確認する。
- **手順:**
  1. ノート詳細ページを開く
  2. 「URLコピー」ボタンを押す
  3. ボタン内のアイコンを観察する
- **期待結果:** クリック直後にアイコンが `Link2`（鎖）から `Check`（チェック）に切り替わり、約 2 秒後に `Link2` に戻る。同時にボタン横に「URL をコピーしました」が表示される。
- **確認ポイント:** アイコンの切り替えタイミングがステータステキストの表示／消去と同期していること。

### 2. ステータステキストが従来どおり維持される

- **目的:** `aria-live` ステータステキストが変更されていないことを確認する。
- **手順:**
  1. ボタンを押す
  2. ボタン横のステータス領域を確認する
- **期待結果:** 「URL をコピーしました」が表示され、約 2 秒後に消える（従来挙動と同一）。

## エッジケース・異常系

### 1. クリップボード利用不可・コピー失敗時

- **目的:** 失敗時はアイコンが `Check` に変わらないことを確認する。
- **手順:**
  1. クリップボード API が使えない環境、もしくは書き込み失敗を再現する
  2. ボタンを押す
- **期待結果:** アイコンは `Link2` のまま。ステータス領域にエラーメッセージ（「クリップボードを利用できません」「コピーに失敗しました」）が表示される。

## 既存機能への影響確認

- コピー機能自体（`navigator.clipboard.writeText`）の動作に変更がないこと。
- アイコンが装飾扱い（`aria-hidden`）のままで、スクリーンリーダーがアイコンを読み上げないこと。
