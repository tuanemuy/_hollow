## 総評

Issue 本文で合意された要件（ゴール・TC-005 img ケース・TC-007 td ケース・「サイレント消失させない」）は
すべて受け入れ基準に落ちており、**要求漏れはない**。B（snapshot 追従）と C（プレースホルダ `<br>` 許容）で
2 つの故障メカニズム（道連れ消失 / 空セルに打てない）を分離してカバーしている点が明快で、スコープ外の混入も
見当たらない（候補 A の却下は #233 ADR-003 に紐づいて根拠が明示されている）。

問題点（要修正）はゼロ。改善提案を 3 件挙げる。いずれも「基準の検証可能性・トレーサビリティの精度」に関するもので、
方針・スコープの妥当性を覆すものではない。

## 問題点（要修正）

問題点ゼロ。Issue で合意された要件はすべて検証可能な基準に落ちており、スコープ外作業の混入もない。

## 改善提案（検討推奨）

- **[S-001]** 受け入れ基準表の「対応ステップ」列にテスト（ステップ 4）が 1 行も現れない。
  - 理由: 各 AC を「検証可能」たらしめているのはステップ 4 の pin テストなのに、AC→検証テストのトレーサビリティが
    表からは追えず、ステップ 4 の散文に埋もれている。特に AC-7 はステップ 4 のテスト列挙（AC-1/2, AC-3, AC-6,
    AC-4, AC-5）から**抜け落ちており、どのステップにも検証が紐づかない**（S-002 参照）。表を根拠に「全 AC が
    テストされる」ことを保証できない。
  - 提案: 「対応ステップ」列に該当 AC のテスト（ステップ 4）を併記する、あるいは「検証テスト」列を 1 本足して
    AC↔テストの対応を明示する。少なくとも全 AC がステップ 4 のどこかで pin されることを表で追えるようにする。

- **[S-002]** AC-7（`<pre>` ハイライト span 注入中は snapshot を更新しない）に対応する pin テストがステップ 4 に無い。
  - 理由: AC-7 は形式上の受け入れ基準として立っているが、検証手段が計画に存在しない。加えて計画自身が
    「捕捉は `serializeHostContent` 経由なので実害は無いが、無駄なので明示スキップ」（plan.md L71）と述べており、
    ハイライト中に捕捉しても snapshot は `<pre>` 平文化された同一形になる＝挙動差が観測できないため、
    純粋な振る舞いテストを書きにくい no-op ガードでもある。「基準として掲げているのに検証されない」状態が残る。
  - 提案: 次のいずれかで整合を取る。(a) `isHighlightingRef` を立てた状態で allowed バッチを流し、`snapshotRef` が
    span 注入前の clean 形のまま（= span を含まない）であることを直接 assert する pin を足す。(b) AC-7 を正式基準から
    「既存 `<pre>` 不変条件の回帰確認（テスト方針の green 維持で担保）」へ格下げし、由来と検証手段を明記する。
    現状の「基準にあるが検証が無い」宙吊りを解消する。

- **[S-003]** AC-3 後段（サイレント消失＝後続 emit の上書き保存を防ぐ）のステップ 4 テストが、TC-007 の実害メカニズムを
  忠実に再現していない懸念。
  - 理由: ステップ 4 の AC-3 テストは「rollback 後の `onChange` 引数が先行編集を含む」と記述されるが、`rollback()` は
    `onChange` を呼ばない（`:510-533` で確認）。TC-007 の実害は「rollback で DOM が巻き戻った**後の次の入力**で走る
    debounced emit が、巻き戻り後の本文を親へ上書き保存する」こと。テストが「rollback 直後の 1 回の flush で
    先行編集が DOM に残る」だけを見て、**rollback 後にもう一度入力 → emit** の経路まで踏まないと、TC-007 で
    実機観察された「サイレント上書き保存」そのものの回帰を pin できない。
  - 提案: AC-3 テストに「rollback 発動 → その後さらにテキスト入力 → flush で走る emit の引数（`onChange` の値）が
    先行編集を含み、巻き戻り前の古い本文になっていない」ことを assert するステップを明示的に加える。DOM 保持の確認と
    上書き保存回避の確認を別 assert に分けると、AC-3 の 2 つの主張（DOM 消失なし / 上書き保存なし）が一対一で検証される。

## 良い点

- **由来列のトレーサビリティが優秀。** 各 AC が Issue ゴール / TC-005 / TC-007 / #233 ADR-003 のどれ由来かを
  明示しており、要件カバレッジのレビューが容易。TC-005（img）と TC-007（td）を取り違えずに別 AC へ割り当てている。
- **B と C の責務分離が明快。** 道連れ消失（B / AC-1〜3）と「空セルに打てない使い勝手劣化」（C / AC-4）という
  異なる故障を別基準に切り分け、AC-3 は C 非依存の汎用 rollback トリガー（別要素 force-remove）で B を単独検証、
  AC-4 は placeholder `<br>` 経路で C を単独検証している。相互依存を避けた堅い設計。
- **「サイレント消失させない」ゴールが検証可能な形で基準化されている。** AC-3 が「DOM から消えない」だけでなく
  「後続 emit が巻き戻り前の本文で上書き保存しない」まで踏み込んでおり、TC-007 の本質（自動保存によるサイレント上書き）を
  取りこぼしていない（テストの忠実度は S-003 で補強余地）。
- **スコープ境界と却下理由が明確。** 候補 A（逐次逆適用）の却下を #233 ADR-003 の既存判断へ紐づけ、
  IME 空セル初回 1 文字の残存制約を adr.md ADR-002 Consequences に「消失ではなくその文字が残らない」と正確に切り分け。
  スコープ外作業（差分エンジン導入・inline での img/装飾削除の正規サポート）も列挙され、混入は無い。
- **回帰防止の網羅性。** AC-5 が装飾要素 / `<img>` / 他要素残存 `<br>` の 3 パターンを rollback 維持として pin し、
  C の過剰許容（`querySelector("*") === null` guard）の境界を守る設計になっている。
