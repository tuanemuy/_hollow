## 前提データ

編集可能な既存ノートが必要（`inline` モードは既存ノート編集面 `surface === "edit"` にのみ存在する）。ノート詳細 → 「編集」（`/notes/{noteId}/edit`）で開くと、編集モードタブ（「ビジュアル」「WYSIWYG」「HTML」）のうち **「ビジュアル」（= inline モード）がデフォルト選択**で開く。

以下 2 種類のノートを用意する。

### ノートA（`<img>` 入りノート — TC-005 用）

1. `http://localhost:8787` にログイン済み状態でアクセスする
2. 既存ノートが無ければ新規作成（`/notes/new`）し、本文に段落テキストを 1 行入れて保存する
3. 「編集」→「ビジュアル」タブで開き、本文下部の `MediaUploader` ドロップゾーン（「画像・動画をドラッグ&ドロップ またはクリックして選択」）から画像（PNG/JPEG 等）を挿入する。「ノートに挿入しました」表示後、本文末尾に `<p><img src="/media/<id>" alt=""></p>` が追記される
4. HTML モードで img を含む段落を `<p>before<img src="/media/<id>" alt="">after</p>` の形（画像の前後にテキスト `before` / `after`）に整えて保存し、ビジュアルタブへ戻る（TC-005 の初期構造）。※ img の `src` は手順 3 で得た実在の `/media/<id>` を使う（孤児 purge 対象にしないため）

### ノートB（複数ブロック + 空セルノート — TC-007 用）

HTML モードで以下の本文を入れて保存する:

```html
<p>段落A</p>
<p>段落B</p>
<pre><code>const x = 1;</code></pre>
<p><br></p>
<table><tbody><tr><td><br></td></tr></tbody></table>
```

## 確認項目

### 1. TC-005 相当: img 付近のテキスト入力 → img Backspace 削除試行で直前テキストが道連れ消失しない

- **対応する受け入れ基準:** AC-1, AC-2
- **目的:** `<img>` の Backspace 削除試行で rollback が発動しても、直前に入力した未保存テキストが img 復元の道連れで消えないこと（TC-005 の実害解消）
- **手順:**
  1. ノートAをビジュアルタブで開く
  2. img 直後（`after` の末尾）にキャレットを置き、`TAIL` を入力する（自動保存の「保存済み」表示は待たない）
  3. DOM が `<p ...>before<img ...>afterTAIL</p>` になっていることを DevTools で確認する
  4. キャレットを img の直後に置き、`Backspace` で `<img>` の削除を試みる
- **期待結果:**
  - `<img>` は削除されず復元される（構造保持・仕様どおり。img 削除の正規経路は HTML モード）
  - **直前に入力した `TAIL` が DOM に保持される**（`before<img>after` まで巻き戻らない）
  - img 前の `before`、img 後の `after` も保持される
  - 段落・table 等の構造タグは壊れない
- **確認ポイント:** 修正前は最後の rebuild snapshot（`before<img>after`）まで丸ごと巻き戻り `TAIL` が消えた（TC-005.md）。rollback が許可外を含んだ**その 1 バッチ分だけ**を巻き戻し、直前の正当編集を保持していること

### 2. TC-007 相当: 複数ブロック編集後の空セル入力で先行編集が DOM から消えず、上書き保存もされない

- **対応する受け入れ基準:** AC-3
- **目的:** 複数ブロックに入力（各々自動保存到達）した後、空セルへの入力で rollback を踏んでも、(1) 先行編集済みブロックの本文が DOM から消えず、(2) その後の入力で走る emit が「巻き戻り前の本文」でサイレント上書き保存しないこと（TC-007 の実害解消）
- **手順:**
  1. ノートBをビジュアルタブで開く
  2. 段落A末尾に `追記A` を入力 → 自動保存の「保存しました」表示を待つ
  3. 段落B末尾に `追記B` を入力 → 「保存しました」を待つ
  4. `<td><br></td>` の空セルをクリックしてキャレットを置き、`X` を 1 文字入力する（rollback トリガーになりうる）
  5. rollback が発動した場合の DOM を確認する
  6. 続けて別の場所（空段落 `<p><br></p>` など）へ `Y` を入力し、自動保存を発火させる
  7. ノート詳細（読み取りビュー）へ戻り、さらにページ再読み込みして保存内容を確認する
- **期待結果:**
  - 手順 5 で（もし rollback が起きても）**段落Aの `追記A`・段落Bの `追記B` が DOM から消えない**（初回 rebuild 時点まで全体巻き戻りしない）
  - 手順 6〜7 の後続保存でも、保存内容に `追記A` / `追記B` が含まれ、**「初期本文 + Y」に上書きされていない**（サイレント消失なし）
  - table / tbody / tr / セル構造は壊れない
- **確認ポイント:** TC-007.md では td への 1 文字入力がエディタ全体を初回 rebuild snapshot まで巻き戻し、後続 emit が保存済み `追記` 群を含まない本文で上書き保存した。この 2 段の実害（DOM 消失・上書き保存）がいずれも解消されていること。なお `<td>` セルへの `X` 入力自体は AC-4 で定着する想定（確認項目 3 参照）

### 3. 空プレースホルダブロックへの 1 文字入力が定着する（候補C）

- **対応する受け入れ基準:** AC-4
- **目的:** #287 で editable になった空 `<td><br></td>` / `<p><br></p>` へ非 IME で 1 文字入力したとき、ブラウザのプレースホルダ `<br>` remove を伴っても rollback されず入力が残ること
- **手順:**
  1. ノートBをビジュアルタブで開く
  2. `<td><br></td>` の空セルにキャレットを置き、直接入力（非 IME、英数）で `A` を 1 文字入力する
  3. 空段落 `<p><br></p>` にキャレットを置き、`B` を 1 文字入力する
  4. それぞれ入力が残るか確認し、自動保存後に読み取りビュー・再読み込みで永続を確認する
- **期待結果:**
  - `<td>A</td>` として `A` が残る（即座に巻き戻らない）
  - `<p>B</p>` として `B` が残る
  - セル / 段落の構造タグは壊れない、`contenteditable` は保存 HTML に漏れない
- **確認ポイント:** TC-007.md では td への 1 文字目が即座に巻き戻った（プレースホルダ `<br>` remove を含むバッチが保守的 rollback）。要素子が残らないブロックへのテキスト入力バッチが allowed になり定着すること

### 4. デバウンス窓経由のサイレント消失防止（P-001）

- **対応する受け入れ基準:** AC-3′
- **目的:** rollback が復元した「捕捉済みだが未 emit（50ms デバウンス保留中）の正当編集」も含めて、rollback 直後の親 `value`（自動保存/submit が読む値）が復元後 DOM と一致すること
- **手順:**
  1. ノートAをビジュアルタブで開く
  2. img 直後に `TAIL2` を入力し、**入力直後（自動保存の「保存済み」を待たず、間を置かず素早く）**キャレットを img 直後に置いて `Backspace` で img 削除を試みる（最後の打鍵から 50ms 以内に rollback を踏むよう意識的に速く操作する）
  3. rollback 後、追加入力せずにそのまま自動保存の完了（「保存しました」）を待つか、「保存」ボタンを押す
  4. ノート詳細（読み取りビュー）→ 再読み込みで保存内容を確認する
- **期待結果:**
  - img は復元され、`TAIL2` は DOM に残る（確認項目 1 と同様）
  - **追加入力なしでも、保存内容に `TAIL2` が含まれる**（pending デバウンスが早期 return して `TAIL2` を含まない古い値のまま保存される、という消失が起きない）
- **確認ポイント:** rollback 後は親 `value` が必ず復元後 DOM に一致するという不変条件。手動ではタイミング再現が難しいため、自動テスト 4-T3（`pnpm test:unit`）が本経路の主保証。実機では「速い Backspace の直後に追加操作なしで保存させる」ことで近似再現する

### 5. 装飾要素・img・他要素残存ブロックの `<br>` remove は従来どおり rollback（#233 回帰防止）

- **対応する受け入れ基準:** AC-5
- **目的:** 候補C の緩和が構造保持契約を壊していないこと。装飾要素/`<img>` の remove、および**他要素が残るブロック**での `<br>` remove は従来どおり rollback される
- **手順:**
  1. HTML モードで `<p>a<strong>x</strong>b</p>` を含むノートを用意し、ビジュアルで開く。`<strong>` を選択して削除操作（例: 選択して Backspace）を試みる
  2. ノートAで img をクリック選択して文字入力する（ブラウザが img を置換しようとする mutation）
  3. HTML モードで `<p>a<br><img src="/media/<id>" alt=""></p>`（remove 後も要素子 `<img>` が残る構造）を用意し、ビジュアルで `<br>` を削除する操作を試みる
- **期待結果:**
  - 手順 1: `<strong>x</strong>` は復元される（装飾要素 remove は rollback）
  - 手順 2: img は消えず復元される（入力は巻き戻る — 既知トレードオフ）
  - 手順 3: `<br>` を含む改行削除は rollback され、`<img>` が残る構造で復元される（要素子が残るブロックは guard で rollback）
- **確認ポイント:** `<p>a<br>b</p>`（2 テキストラン、要素子なし）は guard を通って行結合が allowed になるのが設計どおり（実害小）。ここで見るのは**要素子が残るブロック**での rollback 維持

### 6. IME 変換が従来どおり動き、合成中の構造ドリフト検出が保たれる（AC-6, 回帰）

- **対応する受け入れ基準:** AC-6
- **目的:** snapshot 追従が IME 経路を壊していないこと。IME 変換入力が定着し、合成中の構造ドリフト検出（compositionend 比較）が引き続き機能する
- **手順:**
  1. ノートAで img 前後の段落に日本語 IME でかな漢字変換入力し、確定する
  2. 通常段落でも IME 入力・確定を数回行い、自動保存を確認する
  3. （既知制約の確認）空 `<td><br></td>` に IME で最初の 1 文字を入力・確定してみる
- **期待結果:**
  - IME 確定テキストが巻き戻らず残り、自動保存される
  - IME 変換途中（未確定）の一時的な下線表示状態が確定で正しく反映される
  - 手順 3: 空セルへの IME 最初の 1 文字は巻き戻りうる（**既知の残存制約** — 候補C は非 IME 経路限定。道連れ消失は起きないが、その 1 文字は残らない場合がある）。ここが悪化していない（他ブロックの本文は消えない）ことを確認する
- **確認ポイント:** IME 合成中の半確定構造を snapshot に折り込まず、compositionend での構造ドリフト検出が無効化されていないこと

### 7. `<pre>` ハイライトが従来どおり動き、rollback 復元後も平文である（AC-7, 回帰）

- **対応する受け入れ基準:** AC-7
- **目的:** snapshot 捕捉が `<pre>` のハイライト span 注入と協調し、`<pre>` の不透明性（serialize 平文化）が維持されること
- **手順:**
  1. ノートBの `<pre><code>const x = 1;</code></pre>` をビジュアルで開き、シンタックスハイライトが表示されることを確認する
  2. `<pre>` 内のコードを編集（文字追加）し、ハイライトが再適用されることと自動保存を確認する
  3. `<pre>` 編集後に別ブロックで rollback をトリガー（例: 確認項目 5 の装飾要素削除）し、`<pre>` の復元状態を確認する
  4. 保存 HTML（HTML タブ）で `<pre>` にハイライト用 `<span>` が含まれないことを確認する
- **期待結果:**
  - ハイライト表示・再適用が従来どおり動く
  - rollback 復元後の `<pre>` は span を含まない平文で復元される
  - 保存 HTML の `<pre>` は平文（`contenteditable` / ハイライト span の漏出なし）
- **確認ポイント:** snapshot は `<pre>` を平文で捕捉（ハイライト churn を基準へ折り込まない）していること

## エッジケース・異常系

### 1. rollback 直後の連続操作でエディタが操作可能なまま

- **手順:** 確認項目 1 / 2 / 5 の各 rollback 発動直後に、続けてテキスト入力・削除・別ブロックへのキャレット移動を行う
- **期待結果:** rollback 後もエディタは正常に操作可能。以降の通常テキスト入力（Element remove を含まないバッチ）は巻き戻らず定着し、自動保存が発火する

### 2. モード切替の往復での本文保持

- **手順:** ビジュアル →（装飾喪失ダイアログが出れば内容確認して続行）WYSIWYG → HTML → ビジュアルと往復する。往復の間に確認項目 1〜3 の編集を挟む
- **期待結果:** img・入力テキスト・空セルへの入力が保たれ、ビジュアルへ戻ると decorate が再適用される。往復で本文がサイレント消失しない

### 3. 編集ロック / disabled 状態

- **手順:** 別タブで同じノートの編集を開くなどして disabled にする
- **期待結果:** 全ブロックから `contenteditable` が外れ編集不可になる。disabled 遷移で本文が失われない

## 既存機能への影響確認

- **自動テスト** — `pnpm test:unit` で `inlineEditor.test.tsx` が green であること。特に本 Issue で追加した 4-T1〜4-T8（AC-1〜AC-7 + AC-3′/P-001）と、#233/#287/#498 の既存 pin テスト（rollback・compositionend 構造ドリフト・`<pre>` 平文化・#287 ゲート）が全て green（回帰なし）であること
