# 動作確認計画 — Issue #688: ノート一覧→詳細→編集でメインコンテンツの幅が変わる

**Issue:** #688
**作成日:** 2026-06-13

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。

### 検証環境の起動

```
pnpm dev
```

`vite dev`（Cloudflare 設定）でローカル開発サーバーが起動する。表示された URL をブラウザで開く。ログイン後、ノートが 1 件以上ある状態で確認する（無ければノートを 1 件作成し、本文を数段落入れて過去版を 1 回以上保存しておく）。

### デプロイ方法

なし（検証環境のみで確認できる。スタイルのみの変更）。

## 確認項目

### 1. 一覧 → 詳細 → 編集でメインコンテンツ外枠幅が揃う

- **対応する受け入れ基準:** AC-1, AC-2, AC-3
- **目的:** 画面遷移でメインコンテンツの外枠幅・タイトル左右端がガタつかないこと。
- **手順:**
  1. ノート一覧を開き、ウィンドウを十分広く（>1300px）にする。
  2. メインコンテンツ（一覧）の左右端の位置を目視（または開発者ツールで幅）確認する。
  3. ノートを 1 件開いて詳細へ遷移する。タイトル/パンくずの左右端位置を確認する。
  4. 詳細から「編集」へ遷移する。タイトル入力の左右端位置を確認する。
- **期待結果:** 一覧・詳細ヘッダー・編集タイトルの左右端がいずれも同じ外枠幅（最大 1280px）で揃い、詳細→編集でタイトル幅が変わらない。
- **確認ポイント:** 従来あった「詳細→編集でタイトルが横に広がる」ジャンプが消えていること。

### 2. 詳細・編集の本文プローズ幅は 760px を維持

- **対応する受け入れ基準:** AC-4
- **目的:** 外枠を広げても本文の読み幅は従来どおり 760px に保たれること。
- **手順:**
  1. ノート詳細で本文（`.note-detail-content`）の幅を開発者ツールで確認する。
  2. 編集画面で本文編集エリアの幅を確認する。
- **期待結果:** どちらも本文の読み幅は約 760px（`--content-max`）で、左寄せの位置が詳細⇄編集で一致する。

### 3. 履歴一覧・過去版詳細は 760px を維持

- **対応する受け入れ基準:** AC-6
- **目的:** 履歴系の読みビューが従来の 760px を保つこと。
- **手順:**
  1. 詳細から「履歴」へ遷移し、コンテンツ幅を確認する。
  2. 履歴から過去版を 1 件開き、コンテンツ幅を確認する。
- **期待結果:** 履歴一覧・過去版詳細ともコンテンツ幅が約 760px のまま。

### 4. 保存ビュー一覧の外枠幅が外枠トークンに揃う

- **対応する受け入れ基準:** AC-1, AC-5
- **目的:** 保存ビュー一覧の外枠幅が `--container-max`(1280px) になり、独自 padding は据え置かれること。
- **手順:**
  1. サイドバー等から保存ビュー一覧を開く。
  2. メインの外枠幅と、広い画面での左右 padding を確認する。
- **期待結果:** 外枠幅は最大 1280px。`lg`/`xl` での手厚い左右 padding は従来どおり効いている。

## エッジケース・異常系

### 1. 狭いビューポート（モバイル幅）でのレイアウト

- **目的:** 拡幅トークン化が狭い画面で悪影響を与えないこと。
- **手順:**
  1. ブラウザ幅を 375px 程度にして一覧・詳細・編集・履歴・保存ビューを順に開く。
- **期待結果:** いずれも横スクロールが出ず、各画面が画面幅に収まる（`max-w` は上限なので狭幅では `w-full` が効く）。

## 既存機能への影響確認

- ノートの閲覧・編集・保存・履歴・過去版復元の各動線が従来どおり動作すること（スタイル以外の挙動は変更していないため、表示崩れがないかの目視確認で足りる）。
- 一覧のカード/行レイアウトが拡幅後も崩れないこと（折返し・余白の破綻がないか）。
