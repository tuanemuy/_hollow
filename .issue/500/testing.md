# 動作確認計画 — Issue #500: デザインモック(spec/design/pages)と現状実装の乖離を解消する

**Issue:** #500
**作成日:** 2026-06-05

---

## 確認環境

このIssueは `spec/design/pages/*.html`（静的モック）と `.issue/500/` 成果物のみを変更し、`app/` のコードは変更しない。確認は「モックを開いて崩れないか」と「モックが現状実装の見た目に一致しているか」の2点。

### 検証環境の起動

**モック（静的HTML）の確認** — 依存不要・単一ファイルで開ける:

```bash
open spec/design/pages/P10-home.html   # 確認したいページを指定
```

**実装の見た目の確認** — ローカルサーバを起動して実画面と突き合わせる:

```bash
pnpm db:migrate      # ローカル D1 にスキーマ適用（初回・スキーマ変更時）
pnpm build           # dist/worker を生成（pnpm start は build 済み成果物を配信）
pnpm start           # wrangler dev で起動
```

認証必須ルート（個人領域・設定・管理者）の確認用に決定論的な管理者ユーザー＋セッションを投入:

```bash
pnpm seed:dev-admin  # dev-admin@example.com / role=admin / email_verified=1（冪等）
```

セッション cookie 名は `__Host-session`（Secure 必須）。スクリプトが出力するトークンを CDP 経由で注入する:

```bash
agent-browser cookies set "__Host-session" "<token>" \
  --url http://localhost:<port> --path / --secure --sameSite Lax
```

一般ユーザー画面はブラウザで新規 signup 後、確認リンクの代わりに次を流す:

```bash
echo "UPDATE users SET email_verified=1 WHERE email='<email>';" | pnpm db:execute:local /dev/stdin
```

なし（検証環境のみで確認できる。本番反映不要）。

## 確認項目

### 1. モックが単一ファイルで崩れず開ける

- **目的:** 書き換え後もモックが index.md §9 の制約（単一ファイルで開ける・正式トークン名参照）を維持していることを確認する。
- **手順:**
  1. 書き換えた各 `spec/design/pages/{Pxx}.html` をブラウザで `open` する。
  2. レイアウト崩れ・トークン未解決（色が出ない等）がないか目視する。
  3. `:root` のトークン定義がそのまま残り、ローカル短縮名に置換されていないか確認する。
- **期待結果:** すべてのモックが単独で正しくレンダリングされる。
- **確認ポイント:** トークン参照（`var(--color-*)` 等）が壊れていないこと。

### 2. モックが現状実装の見た目に一致している（方針1の反映確認）

- **目的:** 「実装が正」で書き換えたモックが、実際の実装画面と一致していることを確認する。
- **手順:**
  1. ローカルサーバを起動し、対象ページを実画面で表示する（認証必須ルートは上記シード+cookie注入）。
  2. 同じページのモックを `open` で並べて表示する。
  3. レイアウト／コンポーネント構成／トークン適用（色・寸法・角丸・余白）／状態バリアントの4観点で突き合わせる。
- **期待結果:** 方針1で書き換えた差分が実装と一致している。px 直値→fluidトークン置換箇所は実効値（例 14px→13px）が実装に揃っている。
- **確認ポイント:** `styles.ts` の値を逆引きしたトークンが、実装の実効的な見た目に対応していること。

### 3. 未実装部分がモックに残置されている（方針2の確認）

- **目的:** モックにあるが実装されていない UI/状態/バリアントが、書き換えられず残っていることを確認する。
- **手順:**
  1. `.issue/500/followups.md` の各項目について、該当モックの当該箇所が残っているか確認する。
- **期待結果:** フォローアップ対象のモック記述が削除されず残っている。

## エッジケース・異常系

- **目的:** 代表ページ(P10)で判定したシェル差分が、他の認証済みページ(P11〜P24)に正しく横展開されているか確認する。
- **手順:**
