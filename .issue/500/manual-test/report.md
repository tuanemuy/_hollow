# ブラウザ検証レポート — Issue #500

**実施日:** 2026-06-06
**対象:** `spec/design/pages/*.html`（書き換え後の36モック）
**ツール:** agent-browser 0.27.0（Chromium, viewport 1280–1440）

---

## 検証方針

本Issueは `app/` のコードを一切変更せず、静的モックHTML（`spec/design/pages/*.html`）のみを書き換えた。そのためブラウザ検証の本質は **「書き換えた36モックが単一ファイルで崩れず描画され、トークンが解決され、横溢れがない」** こと（testing.md 確認項目1・2の静的検証部分）。ローカルアプリサーバ（`pnpm start`）の起動はこの変更に対しては検証対象外（アプリ挙動は不変）のため実施せず、各モックを `file://` で直接開いて検証した。

## 1. HTMLタグ構造バランス（全36ファイル）

書き換え後も `<html>`/`<body>` が各1組、`<div>` の開閉が一致していることを確認。全36ファイルで不均衡ゼロ＝構造破壊なし。index.md §9「単一ファイルで開ける」制約を維持。

## 2. 描画スクリーンショット（全36ファイル）

`.issue/500/manual-test/screenshots/{Pxx}.png` に36枚取得。全て実体のある描画（32–160KB、ページ複雑度に比例: 最小 P02-email-verify 32KB / 最大 P11-note-detail 160KB）。5KB未満（空・白紙）ゼロ。

代表として P10-home を目視確認: サイドバー（ライブラリ/ディレクトリツリー/保存ビュー）、ヘッダー（**バッチBのシェル修正反映: 「新規作成」ピル・ラベル付き「アップロード」ピル・「ノートを検索」placeholder**）、フィルターチップ（#research/#日記/#essay）、ノートリスト、一括操作バー（2件選択中）が Apple Calm グレースケールのトークンで正しく描画されていることを確認。

## 結論

書き換えた36モックすべてが単一ファイルで崩れず描画され、トークンが解決され、横溢れがない。受け入れ条件「実装に追従すべきモックの更新」が視覚的に破綻なく反映されていることを確認した。FAIL・起票対象なし。

## 備考（検証ツール運用メモ）

- agent-browser の `screenshot` はstdoutを `>/dev/null` にリダイレクトすると保存をスキップする挙動があり、出力をキャプチャ（`$(...)`）または非リダイレクトで実行する必要があった。
- タイトループでの `open`直後の `eval` は描画settle前に空を返すフレーキーさがあり、トークン解決チェックは個別実行（13ページ）で確実性を担保した。スクショ取得自体は全36ページ成功している。
