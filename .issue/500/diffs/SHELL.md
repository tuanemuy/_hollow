対応実装:
- Header: `app/components/layout/Header.tsx`（+ `MenuButton.tsx`, `UserMenu.tsx`）
- Sidebar: `app/components/layout/Sidebar.tsx`（+ `directory/DirectorySidebarSection`）

- styles: `app/components/layout/styles.ts`, `common/styles.ts`

## A. モック修正（実装に寄せた＝書き換える）

シェル共通で各ページに反映すべき修正。

- [x] ヘッダー右側の「アップロード」が `icon-btn`（円形 `.icon-btn`）→ 実装は `pill-btn`（`UploadButton`、アイコン+ラベル `アップロード`、`max-sm` でラベル非表示）。観点:component。
  - 旧モック: `<button class="icon-btn" aria-label="アップロード">…</button>`
  - 実装: `pill-btn` にアイコン+「アップロード」ラベル。max-sm でラベル隠す（`span.label`）。
  - 修正: アップロードを `pill-btn`（アイコン+`<span class="label">アップロード</span>`）に置換。
- [x] ヘッダー「新規」ボタンのラベルが「新規」→ 実装は「新規作成」。観点:component。
  - 旧モック: `<span class="label">新規</span>` / 実装: `新規作成`。
  - 修正: ラベルを「新規作成」に。
- [x] 検索プレースホルダが「ノート、タグ、本文を検索」→ 実装は「ノートを検索」。観点:component。
  - 修正: placeholder を「ノートを検索」に。
- [x] ヘッダーの pill / icon-btn / search-input の高さリテラル `36px` は実装の `h-9`（=36px）と一致。アバター `32px`=`w-8 h-8`(32px) 一致。menu-btn `36px`=`w-9 h-9`(36px) 一致。→ 寸法は差分なし（値は維持）。観点:token。
- [x] アバターは実装で `UserMenu`（クリックでメニュー展開、表示名/メール/ロール + 設定/ログアウト）。モックは静的な `div.avatar` のみ。観点:component。
  - 判定: ドロップダウンUIはモック静的HTMLでは展開状態を常時描けないため、**トリガーのアバター見た目（円形グラデーション 32px、イニシャル）はモックのままで一致**。展開メニューの常時描画はモックに足さない（静的モックの制約 §9）。実体差はなし扱い。

## B. 実装フォローアップ（モックを正に残した＝未実装）

シェル領域では「モックにあって実装にないUI」が複数ある。これらはモック側を正のまま残す。

- サイドバー「ライブラリ」セクションの **最近更新 / お気に入り** ナビ項目（モックにあり）→ 実装 `Sidebar.tsx` は「すべてのノート / 保存ビュー」のみ。最近更新・お気に入りは未実装。根拠: 実装にナビ導線が無い。別Issue化候補:Yes。
- サイドバー「ライブラリ」の **すべてのノートの件数バッジ `127`**（`.count`）→ 実装はカウント非表示。根拠: 実装の `NAV_ITEM` にカウント表示なし。別Issue化候補:Yes。
- サイドバー「保存したビュー」セクションに **個別ビュー名（未公開の下書き / 今週のレビュー）をナビ列挙** → 実装は「保存ビュー」1リンクのみ（`/views`）でサイドバー内の個別ビュー列挙は無い。根拠: 実装はビュー一覧ページへ集約。別Issue化候補:Yes。
- サイドバー最下部の **タグ / ゴミ箱 / エクスポート** を無題セクションで並べる構成 → 実装は「管理」セクション見出し付きで **タグ / ゴミ箱 / エクスポートジョブ / アップロード** を並べる。実装の方が項目が多い（アップロード追加）。実装が正なので、この差は A（モックを実装に寄せる）として扱える部分もあるが、サイドバーは directory tree 含め大幅に動的のため、サイドバーマークアップ全体の精緻な書き換えは差分が大きい。**最小限の整合（セクション見出し「管理」化 + エクスポート→エクスポートジョブ + アップロード追加）はモックに反映可だが、本Issueでは directory tree の動的描画差が大きいためサイドバー詳細はフォローアップに寄せる**。別Issue化候補:Yes（サイドバー専用の精緻化Issue）。

## C. 要判断（曖昧）

- ディレクトリツリーのインライン操作メニュー（`.dir-menu`）はモックでは1つが open 状態で常時描画されている。実装 `DirectorySidebarSection` / `DirectoryActionsMenu` は同等機能を持つが、モックの「常時 open」表現は静的説明用。→ open 状態を閉じるべきか（実装は通常閉じている）。論点: 静的モックの「状態を見せるための open」を実装の既定（閉）に合わせて潰すと、ディレクトリ操作メニューの存在自体が見えなくなる。モックの教育的表現として残すか判断。
- サイドバーのパディング: モック base `.sidebar` は `padding: 12px 16px 32px`、`@media(min-width:1024px)` で `padding-top: 20px`。実装 `APP_SIDEBAR` は `px-4 pt-5 pb-8`（=16px / 20px / 32px）。base の上 padding が モック12px・実装20px で食い違う。論点: 実装 `pt-5`(20px) を正にしてモック base を 20px に寄せるか、モックの段階的 padding-top を尊重するか（軽微）。

## 反映方針（P10〜P18 各ページへ）

各ページのシェル部分には、A の以下を最低限反映する（差分が明確で副作用が無いもの）:
1. アップロードボタンを `icon-btn`→`pill-btn`（アイコン+「アップロード」、`span.label`）。
2. 「新規」→「新規作成」。
3. 検索 placeholder →「ノートを検索」。

サイドバーの項目構成差（B 項目）は directory tree の動的性が高く、各ページで同一マークアップを精緻に追従させる費用対効果が低いため、本Issueではフォローアップに集約し、モックのサイドバーマークアップは現状維持とする（教育的プロトタイプとして許容）。
