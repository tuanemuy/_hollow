# 動作確認計画 — Issue #541: 領域2「取り込み・書き出し」(P13/P15/P16) のモック実装追従

**Issue:** #541
**作成日:** 2026-06-07

---

## 確認環境

このIssueは #539 から委譲された純新規 UI 2 件（P13 アップロードのクライアント検証バナー / P15 エクスポートの非同期推奨バナー）の追加。実機確認はローカル開発サーバで行う。

### 検証環境の起動

```
pnpm dev
```

`vite dev`（Cloudflare ランタイム）でローカルサーバが起動する。表示された URL をブラウザで開き、ログイン済みのユーザーで確認する。確認には少なくとも以下が必要:
- アップロード可能なユーザー（`/upload` とヘッダーのアップロードモーダルが使える状態）
- 検証用ファイル: 対応形式（例: `.md` / 画像）/ 未対応形式（例: `archive.zip`）/ 50 MB 超のファイル
- エクスポート対象のノートが 51 件以上あるユーザー（bulk 件数超の確認用）

### デプロイ方法

なし（検証環境のみで確認できる。ステージング反映が必要な場合は `pnpm deploy:staging`）。

## 確認項目

### 1. P13 アップロードページ — 未対応形式バナー

- **目的:** クライアント側で未対応形式を送信前に弾き `.alert-error` が出るか。
- **手順:**
  1. `/upload` を開く。
  2. `archive.zip`（未対応形式）をドロップ / 選択する。
- **期待結果:** `.alert-error`「対応外の形式が含まれています」が表示され、本文にファイル名 `archive.zip` が `<code>`（mono）で出る。「対応形式 (...) のみ取り込めます」の案内が続く。アップロードは開始されない（サーバーへ送信されない）。
- **確認ポイント:** `P13-upload.html` 962-973行と並べて目視。配色は白地 + error セマンティックヘアライン枠 + `shadow-xs`、アイコン `size={20}`。`role="alert"`。リテラル px の混入なし。

### 2. P13 アップロードページ — サイズ超過バナー

- **目的:** 50 MB 超ファイルで `.alert-warning` が出るか。
- **手順:**
  1. `/upload` を開く。
  2. 50 MB を超えるファイルをドロップ / 選択する。
- **期待結果:** `.alert-warning`「サイズ超過のファイル」が表示され、本文にファイル名 + サイズ（例: `large.xlsx (72.4 MB)`）が `<code>` で出る。「上限 50 MB を超えています」の案内が続く。当該ファイルは送信されない。
- **確認ポイント:** warning セマンティック配色。`role="alert"`。対応形式かつサイズ内のファイルを同時に選んだ場合、そのファイルだけは送信される（一部除外）。

### 3. P13 アップロードモーダル — 同検証バナー

- **目的:** ヘッダーのアップロードモーダルでも同じ検証バナーが出るか（ADR-004）。
- **手順:**
  1. ヘッダーの「アップロード」からモーダルを開く。
  2. 未対応形式 / 50 MB 超ファイルをドロップする。
- **期待結果:** ページと同じ `.alert-error` / `.alert-warning` がモーダル内（`SelectView`）に出る。すべて弾かれた場合はアップロード進捗ビューに遷移しない（`select` のまま）。
- **確認ポイント:** モーダルの状態機械（ポーリング/キャンセル）が従来どおり。弾かれたファイルを除いて残りが正常にアップロードできる。

### 4. P15 エクスポート — 非同期ジョブ推奨バナー

- **目的:** bulk で件数超 / メディア埋め込み時に `.alert-info` が出るか。
- **手順:**
  1. `/export`（bulk）を開く。
  2. 対象ノート ID を **1 件以上**入力する（発火条件は「対象 1 件以上」かつ「件数 > 50 または『メディアを埋め込む』ON」。`embedMedia` 既定 ON のため、1 件入力した時点で出る。メディア OFF なら 51 件以上で出る）。
- **期待結果:** `.alert-info`「非同期ジョブを推奨します」が**無彩色グレー**で表示され、`<code>エクスポートジョブ一覧</code>` が mono で出る。バナーは推奨表示のみで送信は阻害しない。
- **確認ポイント:** `P15-export.html` 724-728行と並べて目視。info は青を足さない無彩色（`ALERT_INFO`）。`role="note"`。「メール」文言は完了通知メールが実在する場合のみ残す（未実装なら文言から落ちている）。

### 5. P15 エクスポート — single では非表示

- **目的:** 単一エクスポートで推奨バナーが出ないこと。
- **手順:** `/notes/$noteId/export`（single）を開く。
- **期待結果:** `.alert-info` 推奨バナーは表示されない。

## エッジケース・異常系

### 1. bulk で 0 件 / 50 件以下・メディア OFF

- **目的:** 推奨バナーの非発火条件。
- **手順:** `/export` で ID を空 or 50 件以下にし、「メディアを埋め込む」を OFF にする。
- **期待結果:** `.alert-info` は表示されない（件数 0 / 50 以下 かつ embedMedia OFF）。
- **注意:** 対象 **0 件のときは embedMedia ON でもバナーは出ない**（発火条件に `bulkCount > 0` が含まれる = 選択ゼロなら推奨しない妥当な挙動）。`/export` を開いた初期状態は textarea が空＝0 件なのでバナーは出ず、1 件以上入力すると条件成立で表示される。

### 2. `file.type` が空のファイル

- **目的:** ブラウザが MIME を返さないケースで拡張子フォールバックが効くか。
- **手順:** `file.type` が空になるファイル（拡張子あり: `photo.png` / 拡張子なし: `archive`）を選択。
- **期待結果:** 拡張子で判定できる対応形式（`photo.png`）は通過、拡張子なし / 未対応（`archive`）は `.alert-error` で弾かれる。

### 3. サーバー側エラーとの併存

- **目的:** クライアント検証を通過したファイルがサーバーで失敗した場合の表示。
- **手順:** クライアント検証を通る形式で、サーバーが別理由で失敗する状況を作る。
- **期待結果:** 既存のサーバーエラー `FORM_ERROR` 素テキスト表示が従来どおり出る（多重防御。クライアントバナーと併存して崩れない）。

## 既存機能への影響確認

- **アップロード送信フロー（P13）**: クライアント検証導入で、正常な対応形式ファイルのアップロードが従来どおり完了するか。`UploadForm` / `UploadDialog` の既存挙動（進捗・キャンセル・完了）に回帰がないか。
- **エクスポート送信（P15）**: 推奨バナー追加が `ExportForm` の送信・バリデーションに影響しないか（バナーは表示のみ）。
- **関連ユニットテスト**: `note... ingestion/__tests__`（UploadForm / UploadDialog）、`export` の新規テスト。
