# Round 1 レビュー — 要件カバレッジ・スコープ整合性（Issue #743）

レビュー視点: Issue の要件カバレッジ・スコープ整合性
対象: `.issue/743/plan.md` / `.issue/743/adr.md`
日付: 2026-06-15

## 結論サマリー

対応方針1〜4はすべて受け入れ基準（AC-1〜AC-8）に落ちており、root crumb 採用（対応方針3）とフォールバックチップの扱い（対応方針4）も Issue の意図と整合している。スコープ外の作業（NoteBreadcrumb 改変・共通化・ドメイン層）も明示的に除外されており、スコープ漏れ込みは無い。

要修正の重大な漏れは無い。ただし AC-5 の検証可能性と、対応方針3「ディレクトリのみ解除」と採用方針の差分の表現に、改善余地がある。

---

#### 問題点（要修正）

- **[P-001]** AC-5 が「root crumb で directory **のみ**解除できる」と読める書き方になっているが、ADR-001 の決定はこれと異なる（root crumb は他フィルタも落とす）。
  - 理由: AC 表 AC-5 は「root crumb『すべてのノート』で directory **のみ**解除できる」と明記している。一方 ADR-001 Decision は「directory のみでなく他フィルタ（タグ等）も同時に落とす」「『directory だけ厳密に残す』挙動は採らない」と決定しており、AC-5 の文言と矛盾する。検証可能基準としても、テスト実装者が「root crumb クリックで他フィルタが残ること」を検証してしまうと ADR-001 と逆の挙動を検証することになる。Issue 本文の対応方針3も「ディレクトリのみの解除を残したい場合は… root crumb を足す案も**検討**」という条件付き表現であり、必須要件ではない。
  - 提案: AC-5 を ADR-001 の決定に合わせて書き直す。例: 「root crumb『すべてのノート』(`search={HOME_SEARCH}`) リンクが存在し、クリックで directory を含むフィルタが解除される（祖先リンク `{ ...HOME_SEARCH, directoryId }` と同じく他フィルタも落とす一貫挙動）」。「directory のみ解除」という文言は削除し、ADR-001 の「ピンポイント解除は提供しない」決定と一致させる。

#### 改善提案（検討推奨）

- **[S-001]** AC-4 の「`mb-6` 相当」は検証可能だが、ADR-001 で「`nav` 自身が `mb-6` を持つ」と確定済みなので、AC-4 に「(`DirectoryBreadcrumb` の `nav` が `mb-6` を持つ)」と具体値を明記すると検証点が一意になる。
  - 理由: 現状 AC-4 は「`mb-6` 相当の配置」と曖昧さを残すが、ADR で値は確定している。受け入れ基準とテストの紐づけが一意になる。

- **[S-002]** AC-6 の「対応ステップ: S2 or S3」が未確定のまま。
  - 理由: AC と実装ステップの紐づけは検証可能性の前提。設計本文 (c) では「フォールバックチップは `FilterBar` 側に残す」と確定し、実装ステップ S3 が `FilterBar` の改修を担っているので、AC-6 の対応ステップは S3 に確定できる。「or」を残すと「どのステップで担保されるか」が曖昧になり、ステップ削減時に検証漏れが起きうる。
  - 提案: AC-6 の対応ステップを S3 に確定する。

- **[S-003]** root crumb 追加に伴う新規 aria/語彙のテスト観点が AC に明示されていない。
  - 理由: 計画の S4「テスト方針」では root crumb リンク検証が挙がっているが、AC 表（検証可能基準の SSOT）には root crumb の存在自体が AC-5 に埋め込まれているだけで、独立した検証項目になっていない。root crumb は #710 に無い新規要素なので、AC として「先頭に root crumb『すべてのノート』リンクが存在する」を独立で立てると、実装・テストの取りこぼしを防げる。
  - 提案: AC-5 から root crumb の「存在」確認を切り出し、独立 AC（例 AC-5b）として「先頭に `search={HOME_SEARCH}` の root crumb リンク『すべてのノート』が描画される」を追加する。

- **[S-004]** AC-7（テスト更新）が「全テストがパスする」止まりで、FilterBar からパンくず検証が「消える／移設される」ことの検証可能基準が AC に無い。
  - 理由: 設計上 #710 のパンくず検証（709–827行）の主軸が FilterBar から DirectoryBreadcrumb 単体テストへ移る。AC-7 は「更新されパスする」としか言っておらず、「FilterBar 側で nav が描画されないこと（segments ありでも nav 不在）」という回帰観点が AC に落ちていない。リスク欄では「検証漏れが出ないよう AC 表と対応付けて移す」と注意喚起しているが、肝心の AC 表にその受け皿が無い。
  - 提案: AC-7 を分割し、「(a) DirectoryBreadcrumb 単体テストで祖先リンク/末尾 aria-current/root crumb/× 不在/区切りを検証」「(b) FilterBar テストで segments ありでも `nav[aria-label="現在のディレクトリ"]` が描画されないこと（パンくず移設の回帰）を検証」を別基準にする。

#### 良い点

- 対応方針1〜4と Issue 備考（ADR supersede）が AC-1〜AC-8 に漏れなくマッピングされ、各 AC に「由来」列で対応方針への traceability が付いている。要件→基準の追跡可能性が高い。
- スコープ「含まれないもの」が明確で、揃える先である `NoteBreadcrumb` 不変・`directoryAncestorSegments`/型の不変・ドメイン〜アダプター層不変・`NoteBreadcrumb` との描画共通化（#710 ADR-001 のフォローアップ余地）を明示的に除外している。スコープ外作業の紛れ込みは無い。
- 対応方針4（フォールバックチップ）の扱いが正しい。id 解決不能時のチップは filter 語彙として `FilterBar`（フィルタ行）に残し、location（パンくず）と棲み分ける設計（ADR-002 Decision (B)）は Issue 方針4「× を残す（チップなので語彙的に妥当）」と完全に整合する。出現条件が排他（解決可 vs 不可）で同時表示されない点も明記済み。
- 対応方針3「root crumb を足す案（#710 ADR-001 の代替）」の採用が Issue の意図と整合。Issue は「× 廃止で directory 単独解除導線が失われる」懸念に対し root crumb を代替として提示しており、ADR-001 が選択肢 (A)/(B) を比較したうえで (B)（root crumb）を採用、フルリセットは既存「フィルタをすべてクリア」で別途担保済みと確認している（既存 `clearAll` は FilterBar 内で不変、本変更の影響を受けない）。
- 位置移動（最大の難所）について、既存実装の前例（`SavedViewsList/Page.tsx` が `loadDirectoryTreeFlat({ actorUserId })` を 2 セクションから別リテラルで呼ぶ）と同じパターンであり、新規 `DirectoryLocationSection` での再 await もプロジェクト既存の dedup 前提に沿う。計画はこの dedup 前提の検証をリスク欄で明示的に flag しており、計画段階の扱いとして妥当。
- `DirectoryBreadcrumb` が `onClear` 廃止後に client state を持たない純表示コンポーネントになり `"use client"` 不要、という観察（ADR-003）は正確（現行 `onClear` は `FilterBar` の optimistic `clearDirectory` 由来で、root crumb/祖先は素の `<Link search>`）。

#### 検証メモ（事実確認）

- `clearAll`（フィルタをすべてクリア）は `FilterBar.tsx` 内（418–420行）にあり directory を含めて消す。本変更は touch せず、AC-5 のフルリセット節は既存挙動で担保される（確認済み）。
- 現行 `FilterBar.tsx` 443–464行はパンくず or フォールバックチップを `mb-5` 行で分岐描画。設計 (c) の「パンくずブランチ削除・フォールバックのみ残す」は実在ロジックに対応している（確認済み）。
- `FilterBar.test.tsx` 709–827行が #710 パンくずテスト群。設計の「FilterBar 側はフォールバックのみ検証へ再構成」は実在テストに対応（確認済み）。
- `NoteBreadcrumb.tsx` は末尾 `aria-current="page"` + `text-ink-secondary` 非リンク `<span>`、`nav` 自身が `mb-6`、先頭アイコン無し、`Separator` 内部関数化。ADR-001 が「揃える先」とする記述は正確（確認済み）。
