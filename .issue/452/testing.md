# 動作確認計画 — Issue #452: アップロードしたソースファイルを永続保存し、後から閲覧・ダウンロードできるようにする

**Issue:** #452
**作成日:** 2026-06-04

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。

### マイグレーション適用

`notes.source_file_id` 追加と `media_kind_enum` への `source` 追加を含む新規マイグレーションをローカル D1 に適用する。

```bash
pnpm db:apply:local
```

### 検証環境の起動

```bash
pnpm dev
```

開発サーバー（Cloudflare runtime, vite dev）が起動する。

### デプロイ方法

なし（検証環境のみで確認できる）。ステージングで確認する場合は別途 `pnpm db:apply:staging` → `pnpm deploy:staging:all` だが、本Issueの動作確認には不要。

## 確認項目

### 1. 取り込み確定で元ファイルが永続保存される

- **目的:** commit 時にソースファイルが永続ストレージにコピーされ、MediaAsset(kind='source') として保存され、Note に紐付くこと。
- **手順:**
  1. ログインし、取り込み画面から PDF（または画像）ファイルをアップロードする。
  2. パース・プレビュー生成を待ち、内容を確認して「確定（commit）」する。
  3. 確定後に作成されたノートの詳細画面を開く。
- **期待結果:** ノート詳細画面に「元ファイル」セクションが表示され、アップロードしたファイル名が出る。
- **確認ポイント:** 一時ファイルは削除されるが、永続コピーが残ること（詳細画面で閲覧/DL できることで間接確認）。

### 2. ノート詳細画面から元ファイルを閲覧できる

- **目的:** 元ファイルのプレビュー（inline 表示）ができること。
- **手順:**
  1. 確認項目1で作成したノートの詳細画面を開く。
  2. 「元ファイル」セクションの「閲覧」リンクをクリックする。
- **期待結果:** 新規タブで presigned URL が開き、PDF/画像/音声がブラウザのネイティブビューアで inline 表示される。
- **確認ポイント:** ダウンロードではなくブラウザ内表示になること（Content-Disposition が付かない inline）。

### 3. ノート詳細画面から元ファイルをダウンロードできる

- **目的:** 元ファイルを元のファイル名で保存できること。
- **手順:**
  1. 同じノート詳細画面で「ダウンロード」リンク（`/media/<id>?download=1`）をクリックする。
- **期待結果:** ファイルがダウンロードされ、保存ファイル名が元のアップロード時のファイル名になる。
- **確認ポイント:** inline 表示ではなく attachment ダウンロードになること（Content-Disposition: attachment が効く）。

### 4. 既存ノート（元ファイル無し）で UI が壊れない

- **目的:** sourceFile を持たないノートで詳細画面が正常に表示されること。
- **手順:**
  1. 取り込み経由ではない通常作成のノート（または本変更前から存在するノート）の詳細画面を開く。
- **期待結果:** 「元ファイル」セクションは表示されず、ほかの表示崩れもない。

## エッジケース・異常系

### 1. 元ファイルの閲覧/DL に所有者認可が掛かっている

- **目的:** 他人のノートのソースファイルにアクセスできないこと。
- **手順:**
  1. ユーザー A で取り込み確定し、ソースファイルの `/media/<id>` URL を控える。
  2. ログアウトし、ユーザー B（または未ログイン）で同じ `/media/<id>` および `/media/<id>?download=1` にアクセスする。
- **期待結果:** アクセスが拒否され、メディア取得エラー画面が表示される（presigned URL は発行されない）。

### 2. 取り込み確定でノートを上書き（overwrite）した場合

- **目的:** 上書き時に旧ソースファイルが差し替わり、永続 orphan が残らないこと。
- **手順:**
  1. 既存ノートを上書き対象に指定して別のファイルで取り込み確定する。
  2. 詳細画面で「元ファイル」が新しいファイル名になっていることを確認する。
- **期待結果:** 新しいソースファイルが表示され、閲覧/DL できる。旧ソースは orphan 化され purge worker の回収対象になる（DB 上の旧 MediaAsset が orphan status へ）。

### 3. ノートを完全削除（ゴミ箱から削除）した場合

- **目的:** note purge 時にソースファイルが orphan 化され回収対象になること。
- **手順:**
  1. ソースファイル付きノートをゴミ箱に入れ、ゴミ箱から完全削除する。
- **期待結果:** 例外なく削除でき、対応する source MediaAsset が orphan status になる（重複イベント配信でもエラーにならない）。

## 既存機能への影響確認

- **通常のメディア（画像・avatar）のアップロード/表示/ダウンロード:** `presignDownload` のシグネチャ変更後も既存の画像表示・avatar 表示が壊れないこと（default inline）。
- **取り込みの破棄（discard）/再試行（retry）/再生成（regenerate）:** 永続化対象外。従来どおり一時ファイルのみで、永続コピーが作られないこと。
- **ノートのゴミ箱（trash）/復元（restore）:** trash 中もソースファイルが保持され、restore 後に閲覧/DL できること。
