## 確認環境

このIssueはバックエンド変更を伴わない公開・共有面の UI 追従（P33 共有リンク解錠の STATE3 CTA 追加 / ロックアウト警告の `.alert` 案D 追従 / P32 検索結果スニペットの 2 行 clamp / P32 hero-sub 説明文）。実機確認はローカル開発サーバで行う。

### 検証環境の起動

```
pnpm dev
```

`vite dev`（Cloudflare ランタイム）でローカルサーバが起動する。表示された URL をブラウザで開いて確認する。確認には少なくとも以下が必要:

- 公開ノートを持つユーザー（`/u/$username` / 公開検索 `/search` の確認用）
- パスワード付き共有リンク（STATE1 ゲート確認用）／失効・削除済みの共有リンク（STATE3 CTA 確認用）
- 検索ヒットが本文の長いノート（スニペット 2 行 clamp 確認用）

D1 ローカルにシードが無い場合はマイグレーション適用 → シード投入を行う:

```
pnpm db:migrate
pnpm seed:dev-admin
```

`seed:dev-admin` は dev 用管理ユーザーを作る。公開ノート・共有リンク・失効リンクなど確認用データが不足する場合は、`pnpm db:execute:local --file <SQLファイル>` で補うか、UI からノート作成 → 公開設定 → 共有リンク発行で用意する。

### デプロイ方法

なし（検証環境のみで確認できる。ステージング反映が必要な場合は `pnpm deploy:staging`）。

## 確認項目

### 1. P33 共有リンク — 失効/削除状態の「トップへ戻る」CTA

- **目的:** 失効・削除済みの共有リンクで「トップへ戻る」CTA が表示され、押下でトップへ遷移するか（モック 476行）。
- **手順:**
  1. 失効済み or 削除済みの共有リンク URL（`/share/$token`）を開く。
  2. 「リンクは無効です」系の表示を確認する。
  3. 「トップへ戻る」CTA を押す。
- **期待結果:** `isExpiredOrGone` 分岐でアイコン+タイトル+サブに加え、full-width の primary CTA「トップへ戻る」が表示される。押下でトップ（`/`）へ遷移する。
- **確認ポイント:** `P33-share-link.html` 476行と並べて目視。CTA は `GATE_SUBMIT`（pill / tall / primary）相当で全幅、`data-primary` が効いて accent 配色。アイコンは付けない（モック準拠でテキストのみ）。リテラル px の混入なし。

### 2. P33 共有リンク — ロックアウト警告の `.alert` 案D 追従

- **目的:** 連続パスワード失敗でロックアウトした際、警告が `.alert` 案D（白地 + 警告ヘアライン枠 + `shadow-xs` + アイコン + 本文）で出るか。
- **手順:**
  1. パスワード付き共有リンクを開く（STATE1 ゲート）。
  2. 誤ったパスワードで規定回数連続失敗し、ロックアウト状態にする。
- **期待結果:** ロックアウト警告が `.alert alert-warning`（案D）相当で表示される。塗りつぶし背景ではなく白地 + 警告色のヘアライン枠 + `shadow-xs`。文言は現行の「試行回数の上限に達しました。しばらく時間をおいて再度お試しください。」を温存（「あと N 分」固定値は出さない）。
- **確認ポイント:** `P33-share-link.html` 413-416行と並べて目視。塗りつぶし背景になっていないこと。`role="status"`（polite）になっていること。リテラル px/色の新規混入なし。

### 3. P32 公開検索 — 検索結果スニペットの 2 行 clamp

- **目的:** 検索結果のスニペットが 2 行で省略されるか（モック 509-517行）。
- **手順:**
  1. `/search?q=<本文の長いノートにヒットする語>` を開く。
  2. 検索結果カードのスニペットを確認する。
- **期待結果:** スニペットが最大 2 行で省略表示（line-clamp:2）される。行間はモック準拠の `leading-relaxed`。
- **確認ポイント:** `P32-public-search.html` 509-517行と並べて目視。3 行以上にあふれず 2 行で切れる。トークン/ユーティリティ経由でリテラル px なし。

### 4. P32 公開検索 — hero-sub 説明文

- **目的:** 検索 hero の h1 直下に説明文が常時表示されるか（モック 863行）。
- **手順:**
  1. `/search`（未検索状態）を開く。
  2. hero（h1「公開ノートを検索」直下）を確認する。
- **期待結果:** 「このインスタンス全体の公開ノートから横断検索できます」相当の説明文が hero に常設表示される。空状態側の同趣旨の一文と二重掲出になっていない（空状態は「まだ検索していません」系に役割を絞る）。
- **確認ポイント:** `P32-public-search.html` 863行と並べて目視。`text-sm text-ink-secondary` 相当でトークン経由。

## エッジケース・異常系

### 1. P33 パスワード不一致のインラインエラー回帰

- **目的:** ロックアウト前のパスワード不一致で、従来どおりのインラインエラーが出るか（案D アラートに化けていないこと）。
- **手順:**

- **期待結果:** 従来どおりのインラインエラー表示。ロックアウト案D アラートはロックアウト到達時のみ出る。

- **期待結果:** 省略記号が出ず自然に表示される（2 行未満はそのまま）。
