# 動作確認計画 — Issue #525: 公開ノートのコピーボタンが公開URLではなく限定公開リンク/内部URLをコピーする

**Issue:** #525
**作成日:** 2026-06-06

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載（プロジェクト全体のセットアップは省略）。

### 検証環境の起動

```bash
# dev 管理ユーザーの seed（既に投入済みならスキップ可）
pnpm seed:dev-admin

# dev server 起動
pnpm dev
```

ブラウザで http://localhost:3000 を開いてサインインし、ノート詳細画面 (P11) で確認する。

### デプロイ方法

なし（検証環境のみで確認できる。フロントエンドのみの変更で DB マイグレーション不要）。

## 確認項目

### 1. 公開ノート（限定公開リンク無し）→ 公開 URL をコピー

- **目的:** public ノートで `/u/{username}/{slug}` がコピーされることを確認（旧挙動では `/notes/{id}` 内部 URL）。
- **手順:**
  1. 任意のノートを開き、公開設定で「公開」を選択（共有リンクは発行しない）。
  2. ツールバーの `URLをコピー` ボタンをクリック。
  3. クリップボードの内容を貼り付けて確認。
- **期待結果:** `{appUrl}/u/{自分のusername}/{noteのslug}` がコピーされる。
- **確認ポイント:** `/notes/...` でも `/share/by-id/...` でもないこと。コピーした URL をログアウト状態の別タブで開けて公開ノートが表示されること。

### 2. 公開ノート（限定公開リンク残存）→ 公開 URL をコピー

- **目的:** unlisted → public 遷移で残った共有リンクを優先せず、公開 URL をコピーすることを確認（Issue の不具合①）。
- **手順:**
  1. ノートを「限定公開」にして共有リンクを 1 本発行。
  2. その後「公開」に変更（共有リンクはそのまま残る）。
  3. `URLをコピー` をクリックして貼り付け確認。
- **期待結果:** `/share/by-id/...` ではなく `{appUrl}/u/{username}/{slug}` がコピーされる。

### 3. 限定公開ノート → 共有リンクをコピー（回帰確認）

- **目的:** unlisted では従来どおりアクティブな共有リンクがコピーされることを確認。
- **手順:**
  1. ノートを「限定公開」にして共有リンクを発行。
  2. `URLをコピー` をクリックして貼り付け確認。
- **期待結果:** `{appUrl}/share/by-id/{linkId}` がコピーされる。

### 4. 非公開ノート → 内部 URL をコピー（回帰確認）

- **目的:** private では従来どおり内部 URL がコピーされることを確認。
- **手順:**
  1. ノートを「非公開」にする。
  2. `URLをコピー` をクリックして貼り付け確認。
- **期待結果:** `{location.origin}/notes/{noteId}` がコピーされる。

## エッジケース・異常系

### 1. 限定公開でリンク未発行のまま URLコピー

- **目的:** unlisted でアクティブな共有リンクが無い場合の fallback を確認。
- **手順:**
  1. ノートを「限定公開」にする（共有リンクは発行しない、または全て失効させる）。
  2. `URLをコピー` をクリック。
- **期待結果:** 内部 URL `{location.origin}/notes/{noteId}` がコピーされる（従来挙動を踏襲）。

## 既存機能への影響確認

- 公開設定ダイアログ（PublishSettings）の共有リンク発行・失効・パスワード設定は本変更の対象外。コピーボタンの URL 決定のみが変わることを確認する。
- ゴミ箱（trashed）状態のノートではコピーボタン自体が表示されない（`status === "trashed"` 分岐）ことを確認。
