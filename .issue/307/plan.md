# 実装計画 — Issue #307: ボタン形態ガイドライン (#292) 適用の追加棚卸しとフォローアップ

**Issue:** #307
**作成日:** 2026-05-29
**複雑度:** 小規模（umbrella Issue のフォローアップ分割）

---

## 目的

#292（PR #304 でマージ済）で `spec/design/index.md` §7.1 に追加された「ボタン形態の使い分け」ガイドラインに対し、#292 のスコープ外として明示的に積み残された 7 領域を、性質ごとにグループ化したフォローアップ Issue として起票し、棚卸し責務を果たす。本 Issue 自身は umbrella であり、実装は伴わない。

## スコープ

### 含まれるもの

- 7 領域を 2 つのフォローアップ Issue にグループ化して起票する
- 起票した Issue 番号を本 Issue 末尾コメントに記録し、トレーサビリティを確保する
- 本 Issue (#307) を CLOSED にする（umbrella の役目を終える）

### 含まれないもの

- 各フォローアップ Issue の実装そのもの（個別 Issue で順次対応）
- spec §7.1 の追加変更（ガイドライン自体は #292 で合意済）

## 実装ステップ

### 1. フォローアップ Issue A: domain 別の行アクション・フォーム送信ボタン

- **対象:** `TagActions.tsx` / `AccountDeleteForm/index.tsx` / `UsersTable/index.tsx`
- **理由:** どれも「ドメイン特化の行アクション or フォーム送信ボタン」で性質が近い。同一動線で並び順や形態の整合性が問題になるため、1 つの Issue で並列に判断するのが自然。

### 2. フォローアップ Issue B: 横断的・大規模適用

- **対象:** WysiwygEditor ツールバー / サイドバー / Landing-Auth ハンドコード SVG / `auth/styles.ts` icon-only 監査
- **理由:** いずれも「複数画面・複数コンポーネントを横断する適用」「Icon ラッパー方針との整合」という共通軸を持つ。元 Issue (#307) の提案例の通り 1 つの Issue に集約する。

### 3. 本 Issue へのトレースとクローズ

- 本 Issue にコメントで「Issue A: #XXX / Issue B: #YYY に分割した」旨を記録
- 本 Issue を CLOSED に切り替え

## 設計判断

ユーザー指示で「2 Issue にグループ化（提案セクションの Issue 例の通り）」を選択。grouping は性質ごとの集約と、過剰な細分化を避ける観点から、domain 別 ×3 と 横断的 ×4 の 2 軸で分割する。

## リスクと注意点

- フォローアップ Issue B が広範囲のため、起票後に B 側の plan フェーズで再分割される可能性はある（その判断は B の plan フェーズに委ねる）
- 各フォローアップ Issue は本 Issue #307 と #292 / #231 を参照し、ガイドラインの SSOT (`spec/design/index.md` §7.1) を明示する

- 本 Issue に分割先 Issue 番号がコメントされていること
