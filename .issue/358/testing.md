# 動作確認計画 — Issue #358: アップロード時のカスタムプロンプト入力欄の既定値可視化

**Issue:** #358
**作成日:** 2026-05-31

---

## 確認環境

このIssueの変更を確認するために必要な手順のみ記載。

### 検証環境の起動

```bash
pnpm db:migrate   # ローカル D1 にマイグレーション適用（初回 / 未適用時のみ）
pnpm dev          # vite dev (Cloudflare 構成) でローカルサーバー起動
```

アップロード（取り込み）は P13 モーダル（ヘッダーの「アップロード」CTA → ハッシュ `#upload` → `UploadDialog`）から行う。カスタムプロンプト欄は `SelectView` 内の折りたたみ（details）にある。

### 既定プロンプトの前提

本Issueは「未入力時に適用される既定プロンプト（解決済み値）」を表示する機能。解決優先順位は ユーザー上書き（P23 `PromptsForm`）→ インスタンス既定（P42 管理プロンプト）→ プロバイダ組み込み（空文字フォールバック）。確認では以下の状態を作り分ける:

- **インスタンス既定あり:** 管理者として P42（管理: プロンプト）で `structure` / `metadata` の既定プロンプトを設定する
- **ユーザー上書きあり:** P23（ユーザー設定: プロンプト）で `structure` / `metadata` を上書きする
- **どちらも無し:** 既定も上書きも未設定 → 解決結果は空文字（プロバイダ組み込み）

LLM 接続は本Issueの確認には不要（既定プロンプト文字列の表示のみで、実際の取り込み実行までは必須でない）。

### デプロイ方法

なし（検証環境のみで確認できる。staging/production 反映は通常の `pnpm deploy:staging` フローに従う）。

## 確認項目

### 1. 既定（インスタンス既定）が表示される

- **目的:** ユーザー上書きが無くインスタンス既定がある状態で、未入力時に使われる既定プロンプトが UI に出ることを確認
- **前提:** P42 で `structure` / `metadata` の既定プロンプトを設定、当該ユーザーは P23 で上書きしていない
- **手順:**
  1. アップロード CTA（`#upload`）でモーダルを開く
  2. カスタムプロンプトの折りたたみ（details）を開く
  3. 構造化 / メタデータの各欄を確認する
- **期待結果:** 各欄の placeholder と「既定値を表示」展開に、P42 で設定したインスタンス既定プロンプト本文が表示される。状態は「既定を使用中」。「インスタンス既定」を示す表現になっている
- **確認ポイント:** placeholder は長文でも崩れず、全文は details で確認できること

### 2. ユーザー上書きが既定値として表示される

- **目的:** ユーザーが P23 で上書きしている場合、解決結果（= ユーザー上書き値）が既定値として表示されることを確認
- **前提:** P23 で `structure` を非空文字で上書き
- **手順:**
  1. アップロードモーダルを開きカスタムプロンプト details を展開
  2. 構造化欄の既定値表示を確認
- **期待結果:** 構造化欄の既定値が P23 で設定した上書き値になっており、「ユーザー設定で上書き中」を示す表現が出る（メタデータは上書きしていなければインスタンス既定 or 空文字フォールバック）
- **確認ポイント:** ユーザー上書きとインスタンス既定が異なる値のとき、表示されるのは上書き値（実際に使われる値）であること

### 3. 「既定を使用中 / この回だけ上書き」の状態切替

- **目的:** 入力欄の空 / 非空に応じて状態表示が切り替わることを確認
- **手順:**
  1. カスタムプロンプト欄を開いた直後（未入力）の状態を確認
  2. 構造化欄に任意のテキストを入力する
  3. 入力を全消去して空に戻す
- **期待結果:** 未入力時は「既定を使用中」、テキスト入力時は「この回だけ上書き」、消去で再び「既定を使用中」に戻る
- **確認ポイント:** メタデータ欄も独立して切り替わること

### 4. 送信時の既存挙動（非回帰）

- **目的:** 表示追加が送信ロジックを壊していないことを確認
- **手順:**
  1. 構造化欄を空のまま、メタデータ欄に任意テキストを入れてファイルを取り込む
  2. 取り込み処理を確認する
- **期待結果:** 空欄はサーバー側で既定が解決され、入力欄は上書きとして使われる（従来通り）。表示追加による送信内容の変化が無い
- **確認ポイント:** `readPromptOverride` の挙動（trim 後 非空のみ override）が不変であること

## エッジケース・異常系

### 1. 既定も上書きも無い（空文字フォールバック）

- **目的:** 解決結果が空文字のときに「開いても空で分からない」状態にならないことを確認
- **前提:** P42 インスタンス既定・P23 ユーザー上書きとも未設定
- **手順:**
  1. アップロードモーダルのカスタムプロンプト details を開く
- **期待結果:** 既定値が空でも「LLM プロバイダの既定指示を使用」相当のフォールバック文言が表示され、何が使われるか判別できる
- **確認ポイント:** placeholder/全文が空のまま無言にならないこと

### 2. 既定値の取得に失敗してもアップロードを阻害しない

- **目的:** 既定値 fetch 失敗時のサイレントフォールバックを確認
- **手順:**
  1. （再現できる場合）ネットワークを一時遮断するなどで既定値取得を失敗させた状態で details を開く
- **期待結果:** 既定値表示が出ないだけで、ファイル選択・カスタムプロンプト入力・アップロード送信は通常どおり継続できる
- **確認ポイント:** エラーで操作全体がブロックされないこと

## 既存機能への影響確認

- アップロードの基本フロー（ファイル選択 → 取り込み → プレビュー → 登録）が従来どおり動くこと
- P23（ユーザー設定プロンプト）/ P42（管理プロンプト）画面の表示・編集が変わっていないこと
