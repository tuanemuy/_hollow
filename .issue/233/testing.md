## 確認項目

### 1. 新規ノート作成時のデフォルト = WYSIWYG

- **目的:** Issue 完了条件「新規ノート作成時に `mode: "wysiwyg"`（TipTap）で開く」を確認
- **手順:**
  1. ログイン済み状態で `/notes/new` にアクセス
  2. エディタの上部に表示されているモード切替タブを確認
- **期待結果:**
  - 初期表示のエディタが TipTap WYSIWYG（リッチテキスト編集が可能、`<strong>`/`<em>` などのフォーマットボタンが効く）
  - モード切替タブが「WYSIWYG / FrontMatter / HTML」の 3 つになっており、「ビジュアル（inline）」タブは表示されない
  - 「WYSIWYG」タブがアクティブになっている
- **確認ポイント:** タブの並び・ラベル、初期マウント時に WYSIWYG が選ばれているか

### 2. 既存ノート編集時のデフォルト = inline

- **目的:** Issue 完了条件「既存ノート編集時に `mode: "inline"` で開く」を確認
- **手順:**
  1. 既存のノート（例: テキストのみのノート）を作成・保存
  2. `/notes/$noteId/edit` にアクセス
  3. エディタの上部に表示されているモード切替タブを確認
- **期待結果:**
  - 初期表示のエディタがレンダリング済み HTML を表示しつつ、テキスト部分にカーソルを置いて編集可能（contentEditable）
  - モード切替タブが「ビジュアル（inline）/ FrontMatter / HTML」の 3 つになっており、「WYSIWYG」タブは表示されない
  - 「ビジュアル」タブがアクティブになっている
- **確認ポイント:** タブの並び・ラベル、初期マウント時に inline が選ばれているか

### 3. inline モードでブロック構造が維持される

- **目的:** Issue 完了条件「`inline` モードでブロック構造が変更されない」を確認。仕様 C2-2/C2-3 のキー検証
- **準備:** 以下の HTML を含むノートを作成しておく（テスト用に `mode: "html"` で直接入力可）

```html
<h2>見出し</h2>
<p>段落 <strong>太字</strong> と <em>斜体</em> を含む文。</p>
<table>
  <tr><th>列1</th><th>列2</th></tr>
  <tr><td>セル1</td><td>セル2</td></tr>
</table>
<ul>
  <li>項目A</li>
  <li>項目B</li>
</ul>
<blockquote>引用ブロック</blockquote>
```

- **手順:**
  1. 上記ノートを `/notes/$noteId/edit` で開く（inline モードで自動表示）
  2. `<p>` 内のテキスト「段落」「太字」「斜体」を編集（文字入れ替え・追加）
  3. `<td>` 内のテキストを編集
  4. `<h2>` 見出しテキストを編集
  5. `<blockquote>` のテキストを編集
  6. `<li>` のテキストを編集
  7. 保存後、ページをリロードして同じノートを再度開く
- **期待結果:**
  - 編集中、`<strong>` / `<em>` の装飾が保持される（テキストを置き換えても装飾はそのまま）
  - `<table>` / `<ul>` / `<blockquote>` の構造が崩れない
  - 保存後の HTML 構造がトップレベルタグレベルで元と等価（テキスト内容のみ変化）
- **確認ポイント:**
  - `Enter` を押しても新規 `<p>`/`<li>` が生まれない
  - 装飾要素の境界を跨ぐ削除を試したとき、構造が rollback で復元される

### 4. inline モード初期化失敗時の html モード自動フォールバック

- **目的:** Issue 完了条件「`inline` モード初期化失敗時は `html` モードへ安全にフォールバック」を確認
- **手順:**
  1. （開発者ツールで）意図的に DOMParser が失敗するような不正な `contentHtml`（例: 制御文字を含む文字列）を持つノートを作成
  2. もしくは、`pnpm test:unit -- inlineEditor.test` で `onInitFailed` テストケースがパスすることを確認
  3. ブラウザで該当ノートの `/notes/$noteId/edit` を開く
- **期待結果:**
  - パースに失敗した場合、自動的に `html` モード（テキストエリア表示）に切り替わる
  - ユーザーが手動操作することなく編集を続けられる
- **確認ポイント:** エラーが上に通知されず、UI が壊れていないこと（ホスト要素が空のまま固まっていない）

### 5. モード切替時の未保存変更確認ダイアログ

- **目的:** Issue 完了条件「モード切替（inline ⇄ html、wysiwyg ⇄ html）が動作・未保存変更がある場合は確認ダイアログを出す」を確認
- **手順:**
  1. `/notes/$noteId/edit` で既存ノートを inline モードで開く
  2. テキストを 1 文字編集（dirty 状態にする、autosave が走る前の短時間）
  3. モード切替タブで「HTML」をクリック
  4. ブラウザ標準の `window.confirm` ダイアログが表示されることを確認
  5. 「キャンセル」を選ぶ → モードが切り替わらず inline のまま
  6. もう一度モード切替タブで「HTML」をクリックし、今度は「OK」を選ぶ → HTML モードに切り替わる
  7. 別の既存ノートを開き、何も編集せずに「HTML」をクリック → confirm ダイアログが出ないことを確認
  8. 新規ノート（`/notes/new`）で WYSIWYG → HTML 切替も同様に dirty 検出確認
- **期待結果:**
  - dirty （未保存変更あり）または autosave 進行中・エラー時のみダイアログが表示
  - 「キャンセル」で切替がキャンセル、「OK」で切替実行
- **確認ポイント:**
  - 未保存ゼロ時に確認ダイアログが出ない（不要な確認を出さない）
  - FrontMatter の rename 入力中に切替したとき、blur が先に走り、その後 dirty 再評価で確認される（Issue #230 ADR-003 整合）

### 6. inline → wysiwyg 手動切替時の WYSIWYG 警告

- **目的:** 既存の WYSIWYG 未対応タグ警告（Issue #37 ADR-005）が inline からの切替時にも動くことを確認
- **手順:**
  1. `<table>` を含む既存ノートを `/notes/$noteId/edit` で開く（inline モード）
  2. モード切替タブで「WYSIWYG」をクリック（dirty が無ければ confirm 無しで切替）
- **期待結果:**
  - WYSIWYG モードに切り替わり、`<table>` が flatten される旨の警告バナーが表示される
  - ack（了解）ボタンを押すまで警告が残る
- **確認ポイント:** 既存の Issue #37 機能が回帰していないこと

## エッジケース・異常系

### 1. 空ボディノートを inline で開く

- **目的:** `contentHtml === ""` のときフォールバックせず inline モードを継続することを確認
- **手順:**
  1. 本文が空のノートを作成（タイトルのみ入力して保存、または `html` モードで空文字保存）
  2. `/notes/$noteId/edit` で開く
- **期待結果:**
  - inline モードのまま、空のホスト要素が表示される
  - 編集を開始できる（最初の文字を入力すると `<p>` 等にラップされる挙動はブラウザ依存だが、エディタは表示されている）
- **確認ポイント:** `html` モードにフォールバックしていないこと

### 2. `<pre>` を含むノートを inline で開く

- **目的:** `<pre>` が許可リスト外でも表示が崩れないことを確認（ADR-002 のスコープアウト判断）
- **手順:**
  1. `<pre><code>console.log("hi");</code></pre>` を含むノートを作成
  2. `/notes/$noteId/edit` で開く（inline モード）
  3. `<pre>` 内のテキストにカーソルを置こうとする
- **期待結果:**
  - `<pre>` 部分は表示のみで編集不可（contentEditable=true が付かない）
  - 他の段落・見出しは編集可能
  - コードブロック編集が必要なら「HTML」モードに手動切替できる
- **確認ポイント:** 表示崩れ・JS エラーが発生しないこと

### 3. IME（日本語入力）での編集

- **目的:** IME 連続入力中に構造保持ロールバックが誤発火しないことを確認
- **手順:**
  1. inline モードで `<p>` 内をクリックしてフォーカス
  2. 日本語 IME を有効にして長文を入力（複数の単語、変換確定を含む）
  3. 入力途中で `Enter` を押して IME 確定
- **期待結果:**
  - 入力した文字列がそのまま `<p>` 内に反映される
  - 変換確定後に内容が消えたり構造が崩れたりしない
  - autosave が走り、保存後にリロードしても同じ文字列が残る
- **確認ポイント:** ロールバックが誤発火していないこと

### 4. ペースト時のテキスト化

- **目的:** リッチコンテンツのペーストでもテキストとしてのみ挿入されることを確認
- **手順:**
  1. inline モードで `<p>` 内にカーソルを置く
  2. 他サイトから装飾付きテキスト（例: `<strong>bold</strong> <em>italic</em>`）をコピーしてペースト
- **期待結果:**
  - プレーンテキストとして挿入される（装飾タグは混入しない）
  - 構造の childList 変化が起きない（DOM 上で `<strong>`/`<em>` が新規に出現しない）
- **確認ポイント:** XSS 観点ではなく「構造が変わらない」観点の確認

## 既存機能への影響確認

- **autosave**: inline モードでも autosave が動作すること（debounce 後にサーバー保存）
- **MediaUploader**: inline モードでも画像/メディアの挿入が動作すること（文字列追記経路）。挿入後の HTML が DOM に反映されること
- **WYSIWYG（新規）**: 新規ノート作成時の WYSIWYG が変わらず動作すること（Issue #37/#77/#78/#79/#80 の動作回帰確認）
- **HTML モード**: 既存テキストエリア編集に変化がないこと
- **EditLockBanner**: 編集ロックがかかったノートで inline モードでも編集ロックが効くこと
