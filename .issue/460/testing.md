## 確認項目

### 1. 規範→原則への書き換え（要件①）

- **目的:** §7.1「ボタン形態の使い分け」が、禁止・必須の列挙ではなく「文脈で判断するための指針」として読めること。
- **手順:**
  1. `spec/design/index.md` の §7.1（旧 L127-146 相当）を通読する。
  2. 「混在禁止」「MUST」等の硬い規範語が、必要な a11y 契約（`aria-label` 等）を除いて指針調（向く/避ける/文脈で判断）に置き換わっているか確認する。
  3. §7.1 冒頭 L118「使う場面」の断定トーンも軽く緩んでいるか確認する。
- **期待結果:** 3形態（アイコン+ラベル / テキストのみ / アイコンのみ）が「こういう時はこちらが向く」という trade-off 指針として残っている。
- **確認ポイント:** §1〜§5 の原則筆致と並べて読み、トーンが浮いていないこと。

### 2. a11y タップ領域の二段明文化（要件②）

- **目的:** WCAG の最低ラインと意図を保ちつつ、44 の硬直適用が文脈判断に緩和されていること。
- **手順:**
  1. §3 L56 と §7.1 のタップ領域記述を読む。
  2. 「AA 2.5.8 = 24×24 を床」「AAA 2.5.5 = 44×44 を目標」「意図＝タッチで押し間違えない」が明記されているか確認する。
  3. 適用例（base `pillBtn` の `max-sm:min-h-[44px]` / admin `pillBtnSm` の `data-[sm]:h-7` / `dialogCloseButton` のデスクトップ32px・タッチ44px）が実装と符合しているか確認する。
- **期待結果:** AA 未満を許す書き方になっていない（24 が床）。`aria-label` 等の SR 契約は緩められていない。
- **確認ポイント:** `grep -n "44×44\|24×24\|WCAG\|2.5.5\|2.5.8" spec/design/index.md` で §3・§7.1・§8 の数値・成功基準が矛盾しないこと。

### 3. 例外の原則への畳み込み（要件③）

- **目的:** chip close / admin 小型行アクション / タブ・トグルの例外が、個別条文ではなく「なぜ妥当か」の適用例として再配置されていること。
- **手順:**
  1. §7.1 の該当箇所を読み、例外が原則の適用例として説明されているか確認する。
  2. 実装名が現存するものか確認する: `grep -rn "BTN_SM_CLASS" app/` が**空**であること、`pillBtnSm` が `app/components/common/styles.ts` に存在することを確認する。
- **期待結果:** 廃止済みの `BTN_SM_CLASS` が §7.1 に書かれていない。`pillBtn` + `pillBtnSm` 語彙で書かれている。
- **確認ポイント:** `grep -n "BTN_SM_CLASS" spec/design/index.md` が空であること。

### 4. ADR 参照の整合（要件④）

- **目的:** §7.1 の bare ADR 参照が、出典 issue namespace 付きリンクへ直され、誤読しないこと。
- **手順:**
  1. §7.1 の ADR 参照が `[#292 ADR-002](../../.issue/292/adr.md)` 等の形式（L179 の `#221 ADR-003` と同作法）になっているか確認する。
  2. `.issue/292/adr.md` の ADR-002（DisplayModeSwitch）/ ADR-003（Dialog max-sm:min-44）/ ADR-005（admin 小型行アクション）の決定文と、新 §7.1 の適用例が一対一で対応するか照合する。
- **期待結果:** リンク先 `.issue/292/adr.md` が実在し、参照内容と一致する。`.issue/70/adr.md` と CLAUDE.md styling 節には変更が入っていない。
- **確認ポイント:** `spec/design/index.md` からの相対パス `../../.issue/292/adr.md` が実ファイルに解決すること。
