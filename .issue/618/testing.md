- 検索インデックス（`search_documents`）にノートが反映されている必要がある。シードの整備は manual-test スキルに委ねる。

## 確認項目

### 1. 結果カードの更新日時（PC）

- **目的:** #627 — PC では結果カード右列に更新日時が表示される。
- **手順:**
  1. PC 幅（>= sm）で `/search?q=<ヒットするキーワード>` を開く。
  2. 各結果カードの右端を見る。
- **期待結果:** カードが grid（左: 本文、右: 日付）になり、右列に「M月D日」形式の日付（P30 と同表記）。
- **確認ポイント:** 日付が `search_documents.updated_at` 由来の値であること。P30 `/u/{username}` の日付表記と一貫していること。

### 2. 結果カードの更新日時（モバイル）

- **目的:** #627 — モバイルでは右列が消え、メタ行に日付が折り込まれる。
- **手順:**
  1. ウィンドウ幅を sm 未満に縮める（または devtools のモバイルエミュレーション）。
  2. 結果カードを見る。
- **期待結果:** 単カラムに崩れ、右列日付は非表示。メタ行末尾に「YYYY年M月D日 更新」形式の日付。
- **確認ポイント:** レイアウトが崩れない（タイトル・スニペット・メタ行の順は維持）。

### 3. LIKE フォールバック経路でも日付が入る

- **目的:** #627 完了条件 — FTS / LIKE 両経路で `updatedAt` が入る。
- **手順:**
  1. FTS が効くキーワード（通常の単語）で検索し日付表示を確認。
  2. FTS でヒットしない/フォールバックするクエリ（例: 記号を含むクエリや CJK の部分一致）で検索し日付表示を確認。
- **期待結果:** どちらの経路でも各カードに日付が表示される。

### 4. token input のフォーカスリングが単一（#618 項目2）

- **目的:** ユーザー / タグの token input でフォーカスリングが二重に表示されない。
- **手順:**
  1. `/search?q=...` で「絞り込み」からフィルタードロワーを開く。
  2. ユーザー入力欄を (a) マウスクリック、(b) Tab キーでフォーカスする。
  3. タグ入力欄でも同様に確認。
  4. 文字を入力して suggestion listbox が表示された状態でもリングを確認。
- **期待結果:** フォーカスリングはラッパー（角丸）の1本のみ。内側 input の矩形リングが出ない。
- **確認ポイント:** Chrome / Safari の両方で確認。listbox 表示中も二重にならない。

### 5. 期間ファセットの楽観的更新（#618 項目3）

- **目的:** 期間ラジオのクリックがサーバーラウンドトリップを待たず即時反映される。
- **手順:**
  1. devtools の Network でスロットリング（Slow 3G 等）を有効化。
  2. ドロワーの期間ラジオをクリックする。
- **期待結果:** クリック直後にラジオの `checked` が切り替わる（loader 完了を待たない）。loader 確定後も選択状態が維持される。
- **確認ポイント:** ドロワー外の active chips・「絞り込み」バッジ件数も即時反映されること。

### 6. user / tag token の楽観的更新

- **目的:** ユーザー / タグの追加・削除も即時反映される。
- **手順:**
  1. スロットリング有効のまま、タグを suggestion から追加する。
  2. 追加した token の × で削除する。
  3. ユーザーも同様に確認。
- **期待結果:** token の出現・消滅が即時。chips・バッジも追従。

### 7. 連続操作の整合（連打）

- **目的:** 未確定の先行変更が落ちない（楽観値ベースのハンドラ計算）。
- **手順:**
  1. スロットリング有効のまま、タグを追加した直後（loader 完了前）に期間ラジオを変更する。
  2. タグを素早く2つ連続で追加する。
- **期待結果:** すべての変更が最終的な URL と表示に反映される（先行変更が消えない）。

### 8. ソート表示が非インタラクティブ（#618 項目1 (b)案）

- **目的:** 「関連度順」が選択できそうな見た目になっていない。
- **手順:**
  1. 検索結果画面のツールバーの「関連度順」を見る・ホバーする。
- **期待結果:** ボタン風でなくラベル表示。ホバーで反応しない。下矢印アイコンがない。
- **確認ポイント:** モック `spec/design/pages/P32-public-search.html` も同様にラベル化されていること（ブラウザでモックHTMLを直接開いて確認）。

## エッジケース・異常系

### 1. ナビゲーション失敗時のスナップバック

- **目的:** `router.navigate` が reject した場合に楽観値が baseline に戻る。
- **手順:**
  1. スロットリング有効でフィルター操作中に devtools で offline に切り替える。
- **期待結果:** エラー時は選択表示が URL 確定値（元の状態）へ戻り、UI が不整合のまま固まらない。

### 2. 検索結果ゼロ

- **目的:** ヒットなしでもレイアウトが壊れない。
- **手順:** ヒットしないキーワードで検索。
- **期待結果:** 空状態表示が従来どおり。

## 既存機能への影響確認

- **P30（`/u/{username}`）の日付表示**: フォーマッタ共有化（`formatNoteDate.ts` 抽出）後も P30 の右列・メタ行の日付表記が変わらないこと。
- **owner 検索（アプリ内検索）**: `OwnedSearchHitDTO.updatedAt` は DB 最新行由来のまま（挙動不変）。アプリ内検索結果の日付表示が変わらないこと。
- **他画面の `:focus-visible` リング**: グローバルルールは未変更なので、他の input / ボタンのフォーカスリングに変化がないこと（任意の1〜2画面でスポット確認）。
