このIssueの変更（並び替え軸 segmented の radiogroup 化 / 編集モード tabs の APG Tabs 完成）はフロントエンドのキーボード操作・ARIA 契約の変更。検証は開発サーバーで行う。

なし（検証環境のみで確認できる）。

## 確認項目

### 1. 並び替え軸 segmented が radiogroup として動作する（キーボード）

- **対応する受け入れ基準:** AC-1, AC-2
- **目的:** 並び替え軸コントロールが APG Radio Group としてキーボード操作できることを確認する
- **手順:**
  1. ログイン後 `/tags`（タグ一覧）へ移動する
  2. ツールバーの「並び替え軸」コントロール（`aria-label="並び替え軸"`）の選択中ボタンに Tab でフォーカスする
  3. ArrowRight / ArrowLeft（および ArrowUp / ArrowDown）を押す
  4. Home / End を押す
- **期待結果:**
  - 矢印キーでフォーカスが隣の選択肢へ移動し、**移動と同時にその選択肢が選択される**（automatic activation）。両端で押すと反対端へラップする
  - Home で先頭、End で末尾の選択肢へ移動・選択される
  - 選択中ボタンのみ Tab 順に入る（roving tabindex）
- **確認ポイント:** ブラウザの DevTools で当該コンテナが `role="radiogroup"`（`aria-orientation="horizontal"`）、各ボタンが `role="radio"` + `aria-checked`（選択 true / 他 false）であること。`role="tablist"`/`role="tab"`/`aria-selected` が残っていないこと

### 2. 並び替え軸の sort/order 選択・URL 反映が不変

- **対応する受け入れ基準:** AC-3
- **目的:** ARIA 変更後も既存のソート挙動が壊れていないことを確認する
- **手順:**
  1. `/tags` で並び替え軸の選択肢をマウスクリックで切り替える
  2. キーボード（矢印）でも切り替える
  3. URL とタグ一覧の並び順を確認する
- **期待結果:** 選択に応じて URL のクエリが更新され、一覧が並び替わる。クリック・キーボードどちらでも同じ結果になる
- **確認ポイント:** 切り替え中の `aria-busy` / 楽観的更新の表示が従来どおりであること

### 3. 編集モード tabs が APG Tabs（manual activation）として動作する

- **対応する受け入れ基準:** AC-4, AC-5
- **目的:** 編集モード切替が完全な APG Tabs パターンで、矢印キーは選択を変えずフォーカスのみ移動することを確認する
- **手順:**
  1. `/notes/new`（または既存ノートの `/notes/{id}/edit`）を開く
  2. 編集モードコントロール（`aria-label="編集モード"`）の選択中タブに Tab でフォーカスする
  3. ArrowRight / ArrowLeft / Home / End でフォーカスを動かす（**まだ Enter/Space は押さない**）
  4. 任意のタブで Enter または Space を押す（あるいはクリックする）
  5. Tab でコントロールの外へ出て、もう一度 Tab で戻る
- **期待結果:**
  - 矢印キーはフォーカスのみ移動し、**選択（表示中エディタ）は変わらない**。両端でラップする
  - Enter / Space / クリックで初めてそのモードが選択され、エディタ本文が切り替わる
  - 再 Tab-in は**最後にフォーカスしたタブ**へ戻る（選択中タブに戻るのではない）
- **確認ポイント:** DevTools で各タブが `role="tab"` + `aria-selected` + `aria-controls`、エディタ本文を囲む要素が `role="tabpanel"` + `id` + `aria-labelledby`（アクティブタブを指す）であること。非選択タブが `tabIndex=-1` であること

### 4. 編集モードの確認ゲート（未保存・WYSIWYG 装飾喪失）が不変

- **対応する受け入れ基準:** AC-6
- **目的:** モード切替時の確認ダイアログが従来どおり活性化時のみ発火することを確認する
- **手順:**
  1. ノート本文を編集して未保存状態にする
  2. WYSIWYG → HTML など装飾喪失を伴うモードへ、矢印キーでフォーカスだけ通過させる
  3. その後 Enter/クリックで実際に切り替える
- **期待結果:**
  - 矢印キーでフォーカスが通過する間は確認ダイアログが**出ない**（暴発しない）
  - 実際に活性化したときだけ未保存確認（`window.confirm`）や WYSIWYG 装飾喪失の `ConfirmDialog` が従来どおり表示される
- **確認ポイント:** 矢印移動だけでダイアログが暴発しないこと（manual activation の肝）
