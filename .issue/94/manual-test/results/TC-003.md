# TC-003: 既存の URL パラメータが SavedView より優先される

**結果**: PASS
**実行時間**: 約 90 秒
**セッション**: verify-tc-003

## 目的
home loader の `baseSearch = { ...restored, ...search }` の優先順位（URL → SavedView より優先）が回帰していないことを確認する。SavedView の tag フィルタが適用された上で、URL の `q` がキーワード検索として AND で効くこと。

## 実行ログ

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|----------|-----------|------|
| 1 | ログイン (`test-user-001@example.com`) | `/?page=1&limit=20` に遷移 | `http://localhost:3000/?page=1&limit=20` にリダイレクト | PASS |
| 2 | `?page=1&limit=20&viewId=01938f00-0000-7000-8000-00000000d071&q=Weekly` を直接開く | SavedView (作業中のタスク) の tag フィルタ + `q=Weekly` の AND で 1 件（Weekly planning）表示 | 見出し「「Weekly」の検索結果」、件数表示「1 件のノート」、リストに「Weekly planning ノート（#work #todo, 非公開, 2026年5月15日）」、SavedView セレクトは「作業中のタスク」選択中 | PASS |
| 3 | `?page=1&limit=20&viewId=01938f00-0000-7000-8000-00000000d071&q=存在しないキーワードXYZ` を直接開く | tag + `q` の AND で 0 件 / empty state | 見出し「「存在しないキーワードXYZ」の検索結果」、件数表示「0 件のノート」、empty state「該当するノートがありません」、SavedView セレクトは「作業中のタスク」選択中 | PASS |

## 判定根拠
- Step 2 で SavedView を選択した状態のまま URL の `q=Weekly` が検索キーワードとして適用され、SavedView の tag フィルタとの AND 結果として 1 件のみ表示された。これは URL パラメータと SavedView の両方が同時に効いていることを示す。
- Step 3 で同じ SavedView を選択した状態で `q` をマッチしないキーワードに変えると 0 件になった。SavedView 単独なら tag のみで 1 件出るはずなので、URL の `q` が確かに上書きされず AND として効いていることを意味する。
- 結論: `baseSearch = { ...restored, ...search }` の優先順位（URL が SavedView を上書きする）は維持されており、TC-003 の期待結果を満たす。
