# 動作確認計画 — Issue #818: ノート編集画面（P12）のモバイル表示を最適化する

**Issue:** #818
**作成日:** 2026-07-10

---

## 確認環境

このIssueはフロントエンド（`app/components/note/editor/` 配下と `app/components/layout/styles.ts`）のみの変更。確認に必要な手順のみ記載する。

### 検証環境の起動

コンポーネントのスタイル変更なので HMR が効く vite dev を使う。

```bash
pnpm db:migrate   # ローカル D1 にマイグレーション適用（未適用なら。初回のみ）
pnpm dev          # vite dev（workerd / @cloudflare/vite-plugin）。http://localhost:3000
```

### シードデータ（必須）

note editor 画面（`/notes/new` / `/notes/$noteId/edit`）は `_app` 配下の認証必須ルート。決定論的な管理者ユーザーとセッションを投入する。

```bash
pnpm seed:dev-admin
```

出力トークンを CDP 経由でセッション cookie に注入する（cookie 名 `__Host-session` は Secure 必須で `document.cookie` 注入不可）。

```bash
agent-browser cookies set "__Host-session" "<token>" \
  --url http://localhost:3000 --path / --secure --sameSite Lax
```

注入後 `/notes/new` を開くと editor が表示される。既存ノートの編集画面（`/notes/$noteId/edit`）を使う場合は所有ノートを 1 件 SQL（`pnpm db:execute:local <SQLファイル>`）で投入して `noteId` を指定する。新規作成パス（`/notes/new`）はノート投入不要で最短。

### 確認幅

DevTools のレスポンシブモードで **≤390px（例: iPhone 12 相当 390px、および 375px）** を基準にモバイル確認する。デスクトップ回帰確認は `sm`（640px）以上、代表として 768px / 1280px を見る。

### デプロイ方法

なし（検証環境のみで確認できる。ステージング/本番への反映は不要）。

## 確認項目

### 1. 下部固定 保存 CTA バー（AC-1 / AC-2）

- **対応する受け入れ基準:** AC-1, AC-2
- **目的:** モバイルで保存/キャンセルが下部固定バーに表示され、本文を長くスクロールしても常時到達できること。
- **手順:**
  1. モバイル幅（≤390px）で `/notes/new` を開く。
  2. 保存/キャンセルボタンが画面下部に固定表示されているか確認する。
  3. 本文に長文（数十行）を入力し、下方向へ大きくスクロールする。
  4. スクロール中も保存/キャンセルが画面下部に留まっているか確認する。
  5. フォーム末尾（本文末尾やメタ領域）が固定バーに隠れず、余白が確保されているか確認する。
- **期待結果:** 保存/キャンセルが下部固定バーとして常時見え、本文末尾が隠れない。バーは背景（+ 対応ブラウザでは blur）と下側セーフエリアパディングを持つ。
- **確認ポイント:** バー背景の下端がホームインジケータ域に食い込まず `env(safe-area-inset-bottom)` 分の余白が入ること。保存中は「保存中…」等のラベル/無効化が正しく反映されること。

### 2. 場所/タグのメタ折りたたみ（AC-3）

- **対応する受け入れ基準:** AC-3
- **目的:** モバイルで場所（ディレクトリ）とタグが折りたたみに格納され、summary タップで開閉できること。
- **手順:**
  1. モバイル幅で editor を開く。
  2. 場所/タグが折りたたまれ、要約プレビュー（場所パス・タグ）が summary に表示されているか確認する。
  3. summary をタップして展開し、`DirectoryPicker` と `TagsInput` が現れることを確認する。
  4. 再度タップして畳めることを確認する。
  5. 場所を選び直し・タグを追加/削除し、プレビュー文字列が更新されることを確認する。
- **期待結果:** summary タップで開閉し、プレビューに現在の場所パス＋タグが出る。展開時に場所/タグの編集が可能。
- **確認ポイント:** summary は `aria-expanded` が開閉に追従。`aria-controls` が body の id を指す。展開中にディレクトリ検索ドロップダウン / タグ候補パネルを開いたとき、候補の末尾が下部固定保存バー（z-40）に隠れないこと（z-index 相互作用）。

### 3. コントロールサイズ/タップ床の統一（AC-4）

- **対応する受け入れ基準:** AC-4
- **目的:** タグ削除 ×・ディレクトリツリー行・展開キャレット・ディレクトリ検索入力が周辺コントロールとサイズ統一され、行はタップ床（44px）を満たすこと。
- **手順:**
  1. メタを展開し、タグを複数追加してチップの × を確認・タップする。
  2. 場所（ディレクトリ）ピッカーを開き、ツリー行・展開キャレット・検索入力を確認・操作する。
- **期待結果:** タグ × は他チップ × とヒット領域寸法が揃う（背景箱の有無・色はタグ様式を尊重）。ツリー行/検索入力は標準入力高（`h-10`）ベースでモバイル操作行は 44px タップ床を満たす。展開キャレットは行選択タップを奪わない（縦方向のみ拡大）。
- **確認ポイント:** キャレットタップで開閉、行本体タップで選択、が取り違わないこと。検索入力の高さが他の標準入力と揃うこと。

### 4. 本文の折り返しと横スクロール抑止（AC-5 / AC-6）

- **対応する受け入れ基準:** AC-5, AC-6
- **目的:** 本文の長い無空白文字列が折り返され、ページ全体に横スクロールが出ないこと。
- **手順:**
  1. WYSIWYG モードと HTML モードそれぞれで、本文に長い URL・長い連続英字列を入力する。
     - 例: `https://example.com/very/long/path/segment/that/has/no/spaces?query=aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`
     - 例: `supercalifragilisticexpialidociousAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA`
  2. ≤390px でページ全体の横スクロール（横はみ出し）が発生しないか確認する。
- **期待結果:** WYSIWYG 本文・HTML textarea とも長い文字列がエディタ幅内で折り返され、ページ横スクロールが出ない。
- **確認ポイント:** コードブロック（`pre`）は従来どおり折り返さずコードブロック内で横スクロール（本文全体は横スクロールしない）。`APP_MAIN` の横パディングがモバイルで 16px に縮小されていること。

### 5. 本文 min-h のビューポート相対化（AC-7）

- **対応する受け入れ基準:** AC-7
- **目的:** 本文エディタの最小高がモバイルでビューポート相対（52vh 相当）になり、固定 480px が縦を占有しないこと。
- **手順:**
  1. モバイル幅で本文が空の状態のエディタ高さを確認する。
  2. デスクトップ（`sm` 以上）で本文エディタが従来どおり 480px 相当の高さを保つか確認する。
- **期待結果:** モバイルでは 52vh 相当、`sm` 以上では 480px。source-order に依存せず期待どおり切り替わる。

## エッジケース・異常系

### 1. 折りたたみ中の候補パネル

- **目的:** メタ折りたたみ（DOM 保持のCSS開閉）が場所/タグの内部 state を壊さないこと。
- **手順:**
  1. メタを展開し、タグ候補パネル/ディレクトリ Popover を開いた状態にする。
  2. 一度畳んで再度開き、入力途中の state・選択が保持されているか確認する。
- **期待結果:** 折りたたみ操作で内部 state が失われず、Popover/候補パネルが正しく開閉する。

### 2. 保存中の下部バー状態

- **目的:** 保存処理中に下部固定バーのボタン状態が正しく反映されること。
- **手順:**
  1. 本文を編集し保存を実行する。
  2. 保存中のラベル/無効化・完了後の復帰を確認する。
- **期待結果:** 単一 DOM で状態管理されるため、二重 submit や状態不整合が起きない。

## 既存機能への影響確認

- **デスクトップレイアウト（`sm` 以上）**: 保存/キャンセルがトップバー内の現行位置、場所/タグが常時インライン展開、本文 480px、`APP_MAIN` が `px-6` のまま。DOM/見た目が現行と一致（回帰なし）。
- **`APP_MAIN` の `max-sm:px-4` 波及**: 編集画面以外の `/_app` モバイル画面（例: ノート一覧 P10 等）を開き、本文パディングが 16px に縮小されても意図しない詰まり・横スクロールが出ないことを目視する。
- **既存ユニットテスト**: `app/components/note/editor/__tests__/`（特に `TagsInput.test.tsx` の `aria-label` セレクタ、`DirectoryTreeSelect` 系）が緑であること。
- **必須手順**: `pnpm typecheck && pnpm lint:fix && pnpm format` が通過すること（AC-8）。
