## アーキテクチャ適合性
- ドメイン層は DB / HTTP / フレームワーク非依存（純粋関数 + ポート参照のみ）
- 集約境界は ID 参照で守られている
- ユースケースがビジネスロジックを内包していない（オーケストレーションのみ）
- 公開イベント発火責任は usecase が UoW 経由で行う
- ドメイン間の循環依存なし
- 共通の `app/lib` には `CodedError` 系のみ。各ドメインから依存可能
- **Identity ドメインでは認証 credential / session / 確認トークンを集約化せず plumbing として `CredentialStore` / `SessionService` / `VerificationChallenge` ポートに沈める**。これは「集約は業務的に豊かな振る舞いと不変条件を持つもののみ」という方針に基づく。クロスドメイン不変条件 (「最後の admin 保護」「少なくとも 1 つの credential が残る」) は `IdentityService` / `CredentialPolicyService` ドメインサービスで担保

## 実装可能性の最終確認
- 各エンティティに振る舞いがあり、フィールドだけのものは存在しない
- すべてのポートにメソッドシグネチャ + エラーケースが定義されている
- DTO 共通型が spec/usecases/index.md に集約
- DB スキーマは制約付き SQL ライクに記述、インデックスも明示
- テストケースが正常系 / 異常系 / 境界値 / エッジケースを網羅
