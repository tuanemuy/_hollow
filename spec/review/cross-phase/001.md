## アーキテクチャ適合性
- ドメイン層は DB / HTTP / フレームワーク非依存（純粋関数 + ポート参照のみ）
- 集約境界は ID 参照で守られている
- ユースケースがビジネスロジックを内包していない（オーケストレーションのみ）
- 公開イベント発火責任は usecase が UoW 経由で行う
- ドメイン間の循環依存なし
- 共通の `app/lib` には `CodedError` 系のみ。各ドメインから依存可能

## 実装可能性の最終確認
- 各エンティティに振る舞いがあり、フィールドだけのものは存在しない
- すべてのポートにメソッドシグネチャ + エラーケースが定義されている
- DTO 共通型が spec/usecases/index.md に集約
- DB スキーマは制約付き SQL ライクに記述、インデックスも明示
- テストケースが正常系 / 異常系 / 境界値 / エッジケースを網羅

## 検出された残課題

### 軽微
- [問題1] Identity の `IdentityService.assertNotLastAdmin` は `allAdminCount: number` を引数で受け取るが、usecase 側で `UserRepository.countAdmins()` を呼んで渡すフローが明示されていない。usecases/identity.md の DeleteAccount / DemoteAdmin に「事前に countAdmins して渡す」と注記すべき
- [問題2] Search ドメインの NoteSnapshot に含めるべき情報（directoryPath, tagNames）は Note の SaveNote ユースケースが組み立てる必要があるが、usecases/note.md には明示されていない。「Outbox payload に NoteSnapshot を含める」と明示
- [問題3] Outbox イベントの dispatch ハンドラ（誰がどの event_type を購読するか）の対応表が無い。`spec/database/index.md` または `spec/domains/index.md` に追記すると見通しが良い

## 修正方針

- A: usecases/identity.md の DeleteAccount / DemoteAdmin に countAdmins → assertNotLastAdmin の流れを追記
- B: usecases/note.md の SaveNote / SaveNoteDraft / Restore / Move 等で `Outbox payload: NoteSnapshot{ noteId, ownerId, visibility, title, plainBody, tagNames, directoryPath, frontMatterDate, updatedAt }` を含める旨を追記
- C: spec/domains/index.md にイベント購読者対応表を追加
