# 開発するシステムの初期アイデア

- テキスト管理アプリ
- あらゆるファイルをアップロードすると、HTMLに変換して保存される
    - 対応形式
        - HTML: そのまま
        - Markdown: HTMLに変換
        - Word, Excel, PowerPoint, プレーンテキスト: テキストを抽出してLLMで構造化
        - PDF
            - テキストデータあり: テキストを抽出してLLMで構造化
            - テキストデータなし: OCRまたはLLMで内容を解析して構造化
        - 画像: OCRまたはLLMでテキストを抽出して構造化
        - 音声: 音声認識でテキストを抽出して構造化
        - その他
    - 元のファイルは保存しない
    - アップロード時に限り再生成可能
- 個人契約のLLMを利用したい
    - 管理者のAPIキー
        - シークレットや環境変数で管理
- カスタムプロンプトを設定可能
- タイトルや保存先ディレクトリはLLMが自動で決定
    - 修正可能
- デフォルトのスタイルを当てたいが、装飾されたHTMLには影響しないようにしたい
    - GitHubのMarkdownスタイルをすべてに適用
    - カスタムプロパティでデザイントークンを指定
    - それらを考慮してHTMLを生成してもらう
- テキストデータは中央サーバーに保存
    - Durable Objects（ユーザーごと）
    - DBでないと全文検索できない
- メタデータに対応
    - 中央サーバーに保存
    - 形式
        - FrontMatter
        - ハッシュタグ
            - 内部リンクで十分？
        - 内部リンク
    - 自動抽出するかどうか
    - タスクを抽出・登録してリンクさせたい
        - GitHub形式だとハッシュタグと競合する
        - 内部リンクを活用？
            - この場合タスクも1ファイル
        - `[[TODO]]` や `#TODO` で検索できれば十分かも
- 公開ステータスを持つ
    - 非公開: デフォルト
    - 限定公開
        - 共有リンクを知っている人だけがアクセス可能
        - パスワード保護が可能
    - 公開
        - 中央サーバーに複製され、ユーザー名のネームスペースで誰でもアクセス可能
- エディタで内容を編集可能
    - 種類
        - ビジュアルエディタ
            - レンダリングされたテキストノードを編集
        - HTMLエディタ
            - 新規作成のみ？
    - 画像や動画のアップロードが可能
        - 中央サーバーのR2に保存
        - 保存先のタイプとキーでパスを生成（保存先の切り替え機能を実装しない場合も、将来的に切り替え可能なように設計）
- 新規作成可能
    - WYSIWYGエディタ
- 一覧の表示形式は切り替え可能
    - タイルビュー
    - リストビュー
    - カレンダービュー
- フィルタリング
    - 全文検索
    - タグや内部リンクによるフィルタリング
    - 対象
        - ユーザー画面から: 個人データ
        - 公開ページから: 中央サーバーに複製されたデータ
- フィルタリング・ソート条件や表示スタイルをビューとして登録可能
- エクスポート
    - 個別、一括でエクスポート可能
    - 対応形式
        - HTML
        - Markdown
        - PDF
- セルフホスト可能なOSS
- MVP
    - LLMは管理者がAPIキーで提供する
    - 保存先切り替えはなしで中央サーバーのみ
    - セルフホスト版のみ
    - CLIなし

## スコープ外

- ユーザーごとのAPIキー
    - DBに保存
    - 暗号化必須
- OAuthで他サービスのサブスクリプションを利用する
    - AnthropicやOpenAIのサブスクリプションの使用は許可されていない
    - GitHub Copilotはできるかも
- テキストデータ保存先の切り替え
    - それぞれが独立している
    - 保存先候補
        - GitHubリポジトリ（GitHub Appsを利用）
            - コンフリクトの解決方法を考える必要がある
        - S3互換のオブジェクトストレージ
            - ユーザーが自由に指定可能
            - APIキーを保管するリスクあり
- 画像・動画の保存先切り替え
    - GitHubリポジトリ
    - S3互換のオブジェクトストレージ
    - すべてのファイルとパスを選択された保存先に強制同期することが可能
- クラウドサービスの提供
    - 公開先の中央サーバーとしてクラウドサービスを利用することが可能
    - 料金体系
        - 無料プラン
            - 中央サーバーへの保存容量
                - Durable Objects: 100MB
                - R2: 100MB
            - 1日あたりのアップロード数の制限: 5ファイル
        - プレミアムプラン（月額$5）
            - 中央サーバーへの保存容量
                - Durable Objects: 1GB
                - R2: 1GB
            - 1日あたりのアップロード数の制限: 20ファイル
        - ビジネスプラン（月額$20）
            - 中央サーバーへの保存容量
                - Durable Objects: 10GB
                - R2: 10GB
            - 1日あたりのアップロード数の制限: 50ファイル
- CLIから指定されたエディタで編集
    - エディタ
        - Vim
        - NeoVim
        - Emacs
        - Visual Studio Code
        - nano
- ネイティブアプリの提供
    - サーバーを指定できる
    - 他のアプリの共有オプションに表示されるようにする
