# ページ設計レビュー 001

## 観点別チェック結果

### 必要な画面の網羅
- 全シナリオ A1〜A6 / B1〜B5 / C1〜C6 / D1〜D6 / E1〜E5 / F1〜F5 / G1〜G3 / H1〜H4 / I1〜I5 を画面とその機能でカバーできているか個別に照合した結果、いずれも 1 つ以上の画面が割り当たっている

### 役割分担の明瞭さ
- [問題1] P12 ノートエディタの「ディレクトリ選択」は既存ツリー選択 + 新規ディレクトリ入力（自動作成）に対応する必要があるが、P12 の機能リストで明記されていない。B4 の同等記述と整合させる必要
- [問題2] P14 公開設定モーダル / 画面は、ノート詳細 P11 からのみ開かれるのか、一覧画面 P10 の一括操作からも開かれるのかが書かれていない。P10 の「一括操作」に公開状態変更が含まれている以上、起動経路を明示すべき
- [問題3] P10 のヘッダー検索ボックスと P32 の公開検索の関係が不明瞭。ログインユーザーが自分の個人検索を行う UI と、公開ノート横断検索を行う UI の入口を分けるか、同じヘッダーで切替えるか
- [問題4] P34 エラー画面群が「個人領域のエラー」「公開領域のエラー」のどちらに属するか不明。両領域で再利用される旨を明示すべき

### 機能の具体性
- [問題5] P11 ノート詳細に「コピー（複製）」や「URL コピー」など細かい操作が含まれていない。MVP に必要な操作の最小セットだけならこのまま、追加するならここで決める
- [問題6] P30 ユーザー公開トップに「公開 RSS / sitemap」言及無し。MVP スコープ外なら明示

### ナビゲーション・暗黙レイアウト
- [問題7] グローバルヘッダー（ログイン後）/ サイドバー / フッターについて構造を一切記述していない。各画面が依拠するレイアウト要素をまとめておかないと実装者が迷う

## 修正方針

- A: P12 にディレクトリ選択 = 「既存ツリー / 新規作成入力」を追記
- B: P14 の起動経路を「P10 一括 / P11 個別」と明示
- C: ヘッダー検索を「個人領域は自分のノート横断、公開領域は公開ノート横断」とし、各画面側で出し分ける旨を明記
- D: P34 エラー画面群を「個人 / 公開両領域で共通利用」と明示
- E: P11 に「URL コピー」「複製（新規ノートとして開く）」を追加（MVP の最小として妥当）
- F: P30 / P32 に RSS / sitemap は MVP スコープ外と明記
- G: 「レイアウト・ナビゲーション共通要素」セクションを冒頭に追加し、ヘッダー / サイドバー / フッターの責務を整理
