### DTO完全性
- [問題3] Note 系の DTO（NoteDTO / NoteListItemDTO / BacklinkDTO）の定義が共有されていない。共通型として spec/usecases/index.md にまとめて記述するか、各 usecase ファイル先頭に共通定義セクションを置く
- [問題4] InternalLinkRefDTO の型定義が明示されていない（kind/target/displayText）
- [問題5] ViewQuerySnapshotDTO の構造が ExportJob/Export usecase で示されていない

### アーキテクチャ適合性
- [問題6] `note.md` の SaveNote 内で「TagService.resolveOrCreate を assembleFromInputs が呼ぶ」と書いたが、SaveNote の処理フローでは `NoteService.assembleFromInputs` の戻り値が `tagIds` を含むことを明示する必要
- [問題7] `tag.md` の RenameTag では「本文 HTML 中の `#oldName` を `#newName` に置換」を usecase で行うとあるが、これは正規表現マッチ等のドメインロジックでありユースケース層に置くのは過剰。`TagService.renameInBody(html, oldName, newName): ContentHtml` のようなドメインサービスメソッドに切り出すべき
- [問題8] `media.md` の DownloadMedia で `viaShareLinkId` の妥当性検証は Publication 側で行う。usecase が複数ドメインのリポジトリを直接触っているか確認 → PublicationStateRepository を読むだけなので許容範囲。ただし visibility だけでなく ShareLink を ID で検証する場合は明示

### エラー網羅性
- 各 usecase でドメインから上がるエラーをカバーしているが、共通エラー型（AuthenticationError / AuthorizationError / ValidationError / BusinessRuleError / ResourceNotFoundError / RateLimitError / 各種 driver エラー）の定義箇所が未指定
- [問題9] 共通エラー型を `app/lib` 配下に置く前提が CLAUDE.md にあるが、spec 側でも明示すべき

### 単一責任
- 各 usecase は基本的に単一機能をオーケストレートしているが
- [問題10] `BulkMoveNotes` / `BulkTrashNotes` などのバルク系は「複数の独立操作」を内包する。これは MVP では UX 都合で必要なので、ループで個別 usecase を呼ぶ薄いオーケストレータと明示する

## 修正方針

- A: `note.md` に PurgeTrashOlderThan（バッチ）追加
- B: SignUp に「`registration.open === false` でエラー」を明示済み → OK
- C: spec/usecases/index.md に共通 DTO（NoteDTO, NoteListItemDTO, BacklinkDTO, InternalLinkRefDTO, ViewQuerySnapshotDTO, MediaAssetDTO, etc.）を集約
- D: 上記に InternalLinkRefDTO を含める
- E: 上記に ViewQuerySnapshotDTO を含める
- F: `note.md` SaveNote の処理フロー記述で「`assembleFromInputs` の戻り値 `tagIds/mediaRefs/internalLinkRefs/contentHtml` をそのまま `updateContent` に渡す」と明示
- G: `tag.md` RenameTag を `TagService.renameInBody` をドメインサービスに追加 + usecase で呼ぶ構造に変更
- H: `media.md` DownloadMedia に「`viaShareLinkId` 指定時は事前に ResolveShareLink を通過していること」と明示
- I: spec/usecases/index.md に共通エラー型と `app/lib` 配置方針を記述
- J: バルク系 usecase の冒頭に「単一 usecase をループで呼ぶ薄いオーケストレータ」と明示
