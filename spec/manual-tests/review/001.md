### 2. 手順の具体性

概ね「メールアドレス欄に `test@example.com` と入力」のレベルで具体化されているが、以下を追加で明文化すべき:

- **テストケース間の独立性が前提条件に書かれていない**
  - 例: `organize.md` で TC-D1-05 が `Inbox` をゴミ箱に移動した直後に TC-D2-01 を実行すると、`NoteA` がゴミ箱内にあるため失敗する
  - 修正方針: 各カテゴリーファイルの「前提条件 > 事前準備」に「各テストケースは独立に実行する。テスト開始前にテストデータを初期状態にリセットすること」を明記

- **A6-02 / I0-04 で参照する別ユーザー / env 状態の準備手順が薄い**
  - 修正方針: 当該テストの最初の Step に「事前準備:」行を補強

### 3. 期待結果の検証可能性

「正しく表示される」「適切なエラー」のような曖昧表現は避けられている。「相当」を許容している箇所が多いが、これは UI 文言ゆれを許容する意図であり妥当。

### 4. テストデータ / 前提条件

- 各カテゴリーファイルに「環境 / テストデータ / 事前準備」が記載されている
- ただし `account.md` のテストで使う「2 つめの既存ユーザー（メアド衝突用 `existing-new@example.com` の事前所有者）」が前提条件に明示されていない → 修正対象

### 5. 画面遷移 / ページ設計との整合

`spec/pages/index.md` の P01〜P46 と一致する命名で参照できている。
画面名は「P01 サインアップ画面」等の正式名称で記載されている。

### 6. ユースケースのエラーケース反映

- `I0-05` の `ExternalServiceError(service: 'session')` 系統など、ユースケースレベルのエラーが反映されている
- B1-07 のサイズ上限、F2-05 の総当たりロックなど、ユースケース由来のエラーが正しくテスト化されている

## 修正対応

以下を初回レビューの一巡で実施する:

1. 全 9 カテゴリーファイルの「前提条件 > 事前準備」に、テスト独立性のリセット注意書きを追加
2. `account.md` のテストデータ節に「メアド衝突テスト用の事前所有者」を追加
3. `organize.md` の TC-D2-01 以降で `NoteA` を扱うテストは、D1-05 でゴミ箱に入れる前提を解消するため、D1-05 の対象ディレクトリを `Inbox` ではなく一時作成した `Doomed-Dir` に差し替え

修正後の状態は再レビュー（`002.md`）で評価する。
