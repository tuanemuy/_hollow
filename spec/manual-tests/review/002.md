# レビュー 002（再レビュー）

レビュー実施日: 2026-05-17
対象: `spec/manual-tests/{index,account,ingest,authoring,organize,browse,publish,export,trash,admin}.md`

## チェック結果

### 1. シナリオのカバレッジ

`spec/scenario/` 配下の A1〜I5 のすべてのカテゴリーが対応するマニュアルテストファイルでカバーされている。各シナリオの正常系・異常系がテストケースとして抽出されている（一部、MVP 範囲外と spec で明記されているもの — F4 の通報導線、I4 の招待リンク発行 — を除く）。

### 2. 手順の具体性

入力値・操作対象・遷移先がすべて具体的に書かれている。例:
- 「メールアドレスに `tester+1@example.com` と入力」
- 「ヘッダーのユーザーメニューから『ログアウト』を押す」
- 「`P11 ノート詳細画面` を開き〜」

「事前準備として X を設定する」と明示すべきもの（B1-08 の LLM 失敗、F2-05 の総当たり）は手順内で明記済み。

### 3. 期待結果の検証可能性

「正しく表示される」レベルの曖昧表現はなし。すべて「`画面上部に〜と表示される`」「`一覧から消える`」「`410 が返る`」など目視で確認可能な記述になっている。UI 文言ゆれを許容する「相当」の表記は適切。

### 4. テストデータ / 前提条件

各カテゴリーファイルの「前提条件」セクションに、環境 / テストデータ / 事前準備が明記されている。
全 9 ファイルの事前準備に「各テストケースは独立して実行可能とすること。テスト開始前にテストデータを初期状態へリセットすること」が追加され、テスト間依存の問題が解消されている。
`account.md` にはメアド衝突テスト用の事前所有者 `mailowner` が追加され、A6-02 が独立して実行可能。
`organize.md` には D1-05 用に使い捨ての `Doomed-Dir` / `Doomed-Note` が追加され、`Inbox` / `NoteA` がゴミ箱化されず後続テストに影響しなくなった。

### 5. 画面遷移 / ページ設計との整合

`spec/pages/index.md` の P01〜P46 と完全に整合する命名で参照されている。
画面遷移（P01→P02→P10、P11→P14、P15→P16 など）はページ設計に記載のフローと一致。

### 6. ユースケースのエラーケース反映

各シナリオ由来のエラーケースに加え、ユースケース由来のエラー（`AuthenticationError('setup_token_disabled')` / `ExternalServiceError(service: 'session')` 等）が I0-02 / I0-05 に取り込まれている。

## 判定

レビュー観点すべてに問題なし。マニュアルテストドキュメント群は実行可能な状態。
