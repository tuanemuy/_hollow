# ドメイン設計レビュー 002

ゼロベースで実装可能性 / アーキテクチャ適合性 / トレーサビリティをチェック。

## 観点別チェック結果

### 実装可能性
- [問題1] `note.md` の `Note.create` 静的ファクトリの戻り値型と引数構造が振る舞いセクションにのみ書かれており、`mediaRefs` / `internalLinkRefs` の検証順序（サニタイズ → 抽出 → 整合確認）の責任分担が曖昧。`NoteService.assembleFromInputs` のようなファクトリヘルパを明示するか、`Note.create` の処理順を明記したい
- [問題2] `directory.md` の `DirectoryService.deleteSubtree` の戻り値が `Promise<{ trashedNoteIds; deletedDirectoryIds }>` だが、その値を呼び出し元がどう使うかドメイン設計内で明確にしておきたい（usecase 設計で利用する旨）
- [問題3] `tag.md` の `TagBlacklistEntry` を「エンティティ」と分類しているが ID を持たない。値オブジェクト or 別集約（`ownerId` + `name` 複合 ID）として扱いを統一したい
- [問題4] `ingestion.md` の `IngestionCommitDeps` に `uow` を含めていない（前版にあった）。UoW は usecase 側で渡すべきなのか、サービスが受け取るべきなのかを明示する必要

### アーキテクチャ適合性
- [問題5] `note.md` の `Note.updateContent` で `mediaRefs` を引数として受け取るが、本文 HTML から `NoteService.extractMetadataFromHtml` でも抽出する。両者の整合性チェックがどこで行われるか（updateContent 内か NoteService 側か）が未明示
- [問題6] `view.md` の `BrokenConditionMarker.id` を判別ユニオン化したが、TypeScript の型として正しく書くと `kind: 'tag', id: TagId` の構造体になる。値オブジェクトの定義としてその形を例示すべき
- [問題7] `publication.md` の `PublicationService.changeVisibilityAndCascade` は「`note.publish_changed` イベントを発火する」と書いているが、発火責任はサービス自体ではなく UoW 経由で呼び出し元 usecase が担う設計のはず。文言を「呼び出し元 usecase が UoW.publishEvent を介して発火する旨」を補足

### ビジネスロジック網羅
- [問題8] `media.md` のメディアの URL 生成（`presignDownload`）が `ObjectStorage` ポートにあるが、公開ノートの本文中メディア参照を訪問者が直接読むケースでは「ノートが公開済みでないと配信しない」というアクセスチェックが必要。ドメイン側に `MediaService.assertViewableBy(asset: MediaAsset, viewerOwnerId: UserId | null, noteVisibility: Visibility | null): void` を追加したい
- [問題9] `identity.md` の `Session` に「lastAccessedAt」「rememberMe（長期）」のいずれも記述なし。MVP では `expiresAt` だけで十分なら明示。長期ログイン拡張余地を残すなら `expiresAtExtendable: boolean` を将来用に検討

### トレーサビリティ
- 各シナリオを再度ドメインに割り当てた結果、ドメイン側の振る舞いとシナリオの操作はほぼ一致。1点だけ:
- [問題10] シナリオ C5 「自動保存」「明示保存」の区別がドメインに現れていない。`Note.updateContent` の単一 API で吸収する設計なら明記、別 API が必要なら追加する

## 修正方針

- A: `note.md` の `NoteService` に `assembleFromInputs(input): Promise<{ tagIds; internalLinkRefs; mediaRefs }>` を追加し、`Note.create` / `Note.updateContent` 呼び出し前にここを通す方針を明示
- B: `directory.md` の `deleteSubtree` 戻り値説明に「usecase 層で Outbox イベント発火に利用」と明記
- C: `tag.md` の `TagBlacklistEntry` を「値オブジェクト」に分類し直す
- D: `ingestion.md` の `IngestionCommitDeps` に `uow: UnitOfWorkContext` を明記。トランザクション境界はサービスが受け取り、操作中は同一 UoW で進める
- E: `note.md` の `Note.updateContent` 説明に「`mediaRefs` は呼び出し元（NoteService.assembleFromInputs）が本文 HTML から抽出した結果を渡すこと。Note 自身は受け取った値を信頼する」と明記
- F: `view.md` に `BrokenConditionMarker` の TypeScript 形を例示
- G: `publication.md` の `changeVisibilityAndCascade` 説明を「Outbox イベントは呼び出し元 usecase が UoW 経由で発火する」と修正
- H: `media.md` に `MediaService.assertViewableBy(...)` を追加
- I: `identity.md` の `Session` に「MVP では `expiresAt` 固定。延長 / remember 機能は将来拡張」と注記
- J: `note.md` のユースケース概要に「SaveNoteDraft（自動保存・差分は本文/タイトルのみ）」「SaveNote（明示保存・メタデータ含む全体）」を区別追加
