# ドメイン設計レビュー 003

ゼロベース。各ドメイン成果物をチェックリストに沿って評価。

## 観点別チェック結果

### 実装可能性
- 全エンティティに振る舞いが定義されている（フィールドだけのものは無い）
- 全ポートにメソッドシグネチャとエラーケースが揃っている
- 値オブジェクトにバリデーションルールが定義されている
- 補助型（NoteSnapshot, IngestionDeps, IngestionCommitDeps, BrokenConditionMarker）が定義されている
- 集約ファクトリや orchestrator（NoteService.assembleFromInputs, DirectoryService.deleteSubtree, PublicationService.changeVisibilityAndCascade, MediaService.assertViewableBy など）が責任分担をもって配置されている

### アーキテクチャ適合性
- ドメイン層に DB / HTTP / フレームワーク依存は出ていない
- 集約間参照は ID のみ
- 依存方向は domains/index.md と一致（tag→note を解消、search→note は Outbox 経由）
- 循環依存なし
- ビジネスロジックはエンティティ / ドメインサービスに配置されている
- Outbox イベント発火は呼び出し元 usecase が UoW 経由で行うと明示済み

### ビジネスロジック網羅
- シナリオ A〜I の各操作がドメインの振る舞いとして表現されている
- 編集ロック、自動保存 vs 明示保存、複製、孤児メディア、限定公開リンクの失敗ロック、エクスポート権限、ディレクトリ削除カスケードなどエッジケースをカバー
- 不変条件がエンティティごとに明示されている

### トレーサビリティ
- 全シナリオを各ドメインの「ユースケース概要」セクションに対応付け可能
- ページ設計 P01〜P46 の機能と対応関係を確認できる

## 判定

クリーン。修正不要。Phase 2 へ進む。
