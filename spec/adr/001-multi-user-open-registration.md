# ADR 001: マルチユーザー・オープン登録モデルを採用する

## ステータス

承認済み（2026-05-15）

## コンテキスト

セルフホスト版 MVP において、ユーザー管理のあり方を決める必要があった。
idea.md には「ユーザーごとの Durable Objects」「ユーザー名のネームスペースで公開」という記述があり、マルチユーザー前提と読める一方、「管理者の API キー」のような単一管理者を示唆する記述も混在していた。

## 決定

セルフホスト版 MVP からマルチユーザー対応する。登録方式はオープン登録（誰でもサインアップ可能）とする。

- 各ユーザーは独立した名前空間を持つ
- 認証は Email + Password
- LLM API キーは管理者がインスタンスレベルで設定し、全ユーザーで共有する（idea.md 通り）

## 検討した代替案

### 単一ユーザー（管理者のみ）
- 利点: 認証・権限まわりが最小限。実装が軽い
- 不採用理由: idea.md の「公開ページ」「ユーザー名ネームスペース」が成立せず、機能スコープが大きく削れる

### マルチユーザー（招待制）
- 利点: スパム対策が容易、運用者が利用者を制御できる
- 不採用理由: OSS としてセルフホスト→個人/小グループ用途を想定するため、招待フローはオーバー。必要なら後から登録制限を入れるほうが筋がよい

## 影響

- 認証・ユーザー管理・パスワードリセットなどの基本機能が MVP に必要
- ノートのオーナーシップ・公開可視性をユーザー単位で扱う
- 将来「登録を閉じる」設定を追加できるよう、登録は管理者がスイッチで止められる設計余地を残す
- 初期 admin の登録方式は本 ADR では決めず、[ADR 007](./007-admin-setup-token.md) で別途定義する（Setup Token 方式）
