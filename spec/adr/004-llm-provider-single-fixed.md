# ADR 004: MVP では LLM プロバイダを単一固定とする

## ステータス

承認済み（2026-05-15）

## コンテキスト

idea.md には LLM の利用は明記されているが、プロバイダや差し替え可能性については未定だった。スコープ外項目に「ユーザーごとの API キー」「他サービスのサブスクリプション」が挙げられており、利用者ごとの差し替えは MVP に入らない。

## 決定

MVP では LLM プロバイダを単一固定する。既定プロバイダは Anthropic Claude（最新の Sonnet / Opus）とする。

- 管理者は API キーとモデル名のみを設定する
- API キーは環境変数を優先し、未設定時のみ DB に暗号化保管する
- アプリ内部では `LLMProvider` ポートを定義し、Anthropic 実装のみアダプタとして提供する
- 利用箇所はノート構造化・タイトル生成・ディレクトリ提案・OCR 補助の 4 ユースケース

## 検討した代替案

### MVP で複数プロバイダ切替可能にする
- 利点: 利用者のニーズに即応できる
- 不採用理由: プロバイダ別のレスポンス形式・ストリーミング差異・コスト最適化を一律にカバーするコストが高い。MVP のスコープを膨らませる

### LLM を使わない（ルールベースのみ）
- 利点: 外部依存ゼロ
- 不採用理由: アプリの根幹である「あらゆるファイルを構造化 HTML に変換」が成立しない

## 影響

- `LLMProvider` ポートは差し替え可能な抽象として設計し、将来のプロバイダ追加余地は残す
- 利用回数 / コストの上限はインスタンスごとに管理者が設定可能（管理画面で確認）
- プロバイダ障害時はノート取り込み機能が部分的に停止する。ステータスバナーで明示
