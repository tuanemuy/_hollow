# ADR 003: メタデータは FrontMatter / タグ / 内部リンクの3形式を採用する

## ステータス

承認済み（2026-05-15）

## コンテキスト

idea.md ではメタデータの形式として FrontMatter / ハッシュタグ / 内部リンクの 3 案、加えてタスク抽出が挙げられていた。「ハッシュタグと内部リンクの役割が重なるのでは」「タスク抽出は内部リンクで代替できるのでは」といった重複・統合の余地もあった。

## 決定

MVP では以下の 3 形式を **同時にサポート** する。各形式は役割が異なるためいずれも残す。

- **FrontMatter**: ノート単位で構造化されたメタデータを宣言的に付与する用途（title / aliases / created / updated / publish / tags など）
- **タグ（`#hashtag`）**: 本文・FrontMatter に散在する非階層ラベル。一覧/検索の絞り込みに使う
- **内部リンク（`[[Note Title]]` または `[[note-id]]`）**: ノート間の関連付け。バックリンクを自動算出する

タスク抽出は MVP のスコープ外（`[[TODO]]` / `#TODO` の検索で十分代替可能）。

## 検討した代替案

### タグだけにする
- 利点: シンプル。実装が最小
- 不採用理由: FrontMatter は宣言的な公開設定・別名管理にも使いたい。内部リンクのバックリンク機能はタグでは代替できない

### 内部リンクのみで統一（タグも `[[#tag]]` 表現に寄せる）
- 利点: 概念を 1 つに統一できる
- 不採用理由: 「短いラベル付与」と「明示的なノート参照」を 1 つの構文に押し込むと UI/操作感のトレードオフが大きい。両方残す方が自然

## 影響

- パーサーは FrontMatter / `#tag` / `[[link]]` の 3 つを抽出できる必要がある
- 内部リンクは「タイトル参照」と「ID 参照」の解決ルールを決める必要がある（ID 優先、タイトル変更時のリンク追従の方針）
- バックリンクは保存時または非同期で算出してインデックスする
- 自動抽出はアップロード時 + 編集保存時に実行
