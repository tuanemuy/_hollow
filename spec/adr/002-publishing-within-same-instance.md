# ADR 002: 公開機能は同一インスタンス内で完結させる

## ステータス

承認済み（2026-05-15）

## コンテキスト

idea.md は「公開」時に「中央サーバーに複製され、ユーザー名のネームスペースで誰でもアクセス可能」と記述している。
セルフホスト版 MVP において、この「中央サーバー」を外部に別途持つのか、セルフホストインスタンス自体を中央サーバーとみなすのかを決める必要があった。

## 決定

セルフホスト版 MVP では、公開ノートは同一インスタンス内に公開 URL を生やすことで実現する。外部のクラウド中央サーバーへの複製は行わない。

- 公開ステータスは「非公開 / 限定公開（共有リンク・任意でパスワード） / 公開」の 3 段階
- 「公開」のノートは `/<username>/<note-slug>` のような URL で誰でも閲覧可能
- 「限定公開」のノートは推測困難なトークン付き URL で閲覧可能
- 全文検索の公開対象は同一インスタンス上の公開ノートに限る

## 検討した代替案

### 別の中央クラウドサーバーに複製
- 利点: 「クラウドサービスの提供」プランへの拡張パスを直接持てる
- 不採用理由: MVP がセルフホスト単独動作を主眼にしているため、クラウド依存を持ち込むと配布・運用が複雑化する。idea.md でも「クラウドサービス提供」はスコープ外と明記

### MVP では公開機能を持たない
- 利点: 実装スコープが最小化
- 不採用理由: 「公開ステータス」「外部からの全文検索」「エクスポート共有」がアプリの中核体験を構成しており、削ると魅力が大きく減る

## 影響

- ユーザーが公開設定を切り替えただけで、外部からのアクセス可能性が変わる（複製ではないため即時反映）
- 公開ノート用の閲覧ルーティング・認可・全文検索インデックスは「ユーザー個人空間」と分けて扱う
- 将来クラウド版を作る際は、別途複製/同期の仕組みを別 ADR で議論する
