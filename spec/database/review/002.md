# DB設計レビュー 002

ゼロベースでチェックリスト評価。

## 観点別チェック結果

### エンティティ・値オブジェクトの永続化網羅
- 全ドメインのエンティティに対応テーブルがあり、値オブジェクトは親エンティティ内の JSON カラム or 関連テーブルで永続化される（FrontMatter / ViewQuery / ExportOptions など）

### カラム型・制約とドメインモデルの整合
- 列挙型は CHECK 制約で表現
- ID は TEXT で UUID v7 保持
- アプリ層補助制約セクションで content_html / front_matter_json のサイズ運用方針が明示
- directories の root 一意性は部分 UNIQUE で表現済み
- ref_target の長さ CHECK 追加済み
- share_links.locked_until のインデックス追加済み

### 正規化
- 関連は join テーブル（note_tags / note_media_refs）で正規化
- 派生値（tags.note_count）は usecase で更新する設計と整合

### パフォーマンス
- 主要なクエリパターン（owner_id + status + updated_at DESC、token_hash 検索、FK 検索、stuck 検出、expires_at スキャン）にインデックスがある
- FTS5 で全文検索の重い処理を分離

### データ整合性
- ON DELETE 方針が明示されている
- 補助制約（DB 外）の運用方針も明記

## 判定

クリーン。修正不要。Phase 4 へ進む。
