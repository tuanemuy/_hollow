# C. ノート作成・編集

## C1: 空のノートを新規作成（WYSIWYG）

### 正常系
1. 「新規作成」を選ぶ
2. WYSIWYG エディタが開く（タイトル + 本文 + サイドの FrontMatter / タグ パネル）
3. 任意の保存先ディレクトリを選ぶ（未指定はルート）
4. 文書を書きながら自動保存（ドラフト）が走る
5. 「保存」を押すと正式なノートとして公開状態 = 非公開で作成される

### 異常系
- 通信断中の編集: クライアント内でローカル保存し、復帰後にサーバー同期
- 自動保存失敗: ステータス表示を「保存に失敗」に切り替え、再試行ボタンを表示
- タイトル未入力で保存: 1 行目の見出し or 本文先頭から推定し、それも無い場合は「無題」で保存

## C2: 既存ノートをビジュアル編集

### 正常系
1. ノート詳細画面で「編集」を押す
2. レンダリングされた HTML のテキストノード単位で編集できる（段落・見出し・リスト・引用など、装飾済みの要素はその意匠を保ったままインラインで文字を編集）
3. 編集中は構造を壊さない（タグ削除や入れ替えは別 UI を用意）
4. 編集中、エディタ上部のモード切替で「ビジュアル ⇄ HTML」を切替可能。未保存の変更がある場合は切替前に保存または破棄を選ばせる
5. 保存で確定。差分があった行のみが履歴に乗る（将来拡張、MVP では最新版のみ）

### 異常系
- 編集中にロックを取得できない（他セッションが編集中）: 警告を出し、上書きするか閲覧のみにするかを選ばせる
- 編集対象のノートがゴミ箱に移動した: 編集を一時停止し、復元するか破棄するか選ばせる

## C3: 既存ノートを生 HTML で編集

### 正常系
1. ノート詳細 → 「HTML を編集」を選ぶ
2. テキストエディタ風の画面で HTML を直接編集できる
3. 保存時にサニタイズ（XSS 対策）が実行され、許可されないタグ・属性は除去される
4. プレビュー切替で結果を確認できる

### 異常系
- サニタイズで大幅にタグが除去された: 保存前に「以下が削除されます」と差分を提示
- 不正な HTML（タグ閉じ忘れ等）: 自動補正の結果を見せ、利用者が了承して保存

## C4: 編集中の画像・動画アップロード挿入

### 正常系
1. WYSIWYG / HTML エディタ内で「画像を追加」を選ぶ or ペースト or ドラッグ
2. R2 にアップロード（保存先タイプ + キーでパス生成）
3. アップロード完了後、HTML 内に `<img>` / `<video>` 要素として挿入される
4. 進捗表示中はプレースホルダ、完了後に実画像へ差し替わる

### 異常系
- アップロード失敗: プレースホルダの上に再試行ボタンを表示
- 画像形式 / サイズ超過: 事前に弾く
- アップロード途中で保存: 未完了メディアがあることを伝え、完了待ちか破棄を選ばせる
- 未保存編集中に挿入したメディアを使わずタブを閉じた / ノートを破棄した: 孤児メディアとしてマーキングされ、バックグラウンドジョブで一定期間後（既定 24 時間）に R2 から削除される

## C5: 編集の保存・自動保存・キャンセル

### 正常系
- 自動保存はデバウンス付きで動作（保存ステータスをエディタ上部に表示）
- 「保存」ボタンで明示的に保存。タイトル・本文・メタ情報の変更を一括コミット
- 「キャンセル」で最後に保存した版に戻す（確認ダイアログ付き）

### 異常系
- 自動保存衝突（他クライアントが先に書き込み）: 後勝ち方針だが、検出時に「他の編集が反映されました」を表示し、差分の確認とマージを促す
- ブラウザクラッシュ: 復帰時にローカルドラフトの復元提案を出す

## C6: 同時編集衝突

### 正常系
- 別タブで同一ノートを編集しようとすると警告を出し、`現在の編集を引き継ぐ` or `閲覧のみで開く` を選ばせる
- 別デバイスからの編集が検知された場合は、同じ判断を促す

### 異常系
- 衝突解決を選ばずに編集を進めた結果、後勝ちで上書き: 上書きされた側にあとから通知し、復元手段（直近の自動保存版）を提示
