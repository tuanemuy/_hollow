# シナリオレビュー 001

## 観点別チェック結果

### 網羅性
- [問題1] account.md にメールアドレス変更シナリオが欠落。Email + Password 認証である以上、メアド変更フローは MVP に必要
- [問題2] organize.md にタグ管理画面（タグ一覧・リネーム・統合・削除）の独立シナリオが薄い。D3 末尾に触れているのみで、ユーザー視点の操作フローが分からない
- [問題3] browse.md にディレクトリ階層を直接たどる（ツリー閲覧）シナリオが暗黙化。E1 でサイドバーツリーに言及がない
- [問題4] ingest.md のメタデータ自動抽出（FrontMatter / タグ / 内部リンク）の確認・修正がプレビューで「できる」と一言あるのみで、フローが薄い
- [問題5] publish.md で訪問者（未ログイン）がエクスポート可能かが未定義。公開ノートのエクスポート可否を明示する必要

### フローの自然さ
- [問題6] account.md A1 で「ユーザー名 + 表示名 + メール + パスワード」を一度に入力する設計だが、ユーザー名（URL 識別子）と表示名を初回登録時に揃って入れるのはステップが重い。後で変更前提なら表示名は省略可とする選択肢を残すべき
- [問題7] authoring.md C2/C3 で「ビジュアル編集」「HTML 編集」の切替が同一ノート編集中にスムーズか不明。詳細画面の「編集」ボタンと「HTML を編集」ボタンが別経路だが、編集中に切替できるかが書かれていない

### 異常系の漏れ
- [問題8] authoring.md でメディアの著作権 / 容量上限などの言及はあるが、「未保存メディアを残したままタブを閉じる」ケースの後始末（孤児メディアのクリーンアップ）が無い
- [問題9] publish.md F2 でパスワード保護リンクをユーザー側から「忘れた」場合の管理者導線が無い（オーナーが再設定できるかどうか）
- [問題10] export.md でユーザーが自分のアカウントを削除した直後にエクスポート URL を踏むケースの挙動が未定義

### アーキテクチャ・トレーサビリティ
- [問題11] admin.md I1 で「LLM プロバイダの選択」が暗黙。idea.md と ADR ともプロバイダ選択方針が未定。MVP では単一プロバイダ固定か、複数プロバイダ切替可能かを明確化する必要

## 修正方針

- A: account.md にメール変更シナリオ A6 を追加
- B: organize.md にタグ管理シナリオ D6 を追加
- C: browse.md E1 にディレクトリツリー閲覧の挙動を追記
- D: ingest.md B1 にメタデータ確認・修正フローを追記
- E: publish.md F3 / F4 に訪問者のエクスポート可否を明示
- F: account.md A1 のフローを簡素化（表示名はオプションに）
- G: authoring.md C2/C3 にエディタモード切替の挙動を追記
- H: authoring.md C4 に孤児メディア処理を追記
- I: publish.md F2 にパスワード忘れ時のオーナー側再設定を追記
- J: export.md G3 にアカウント削除後の URL 挙動を追記
- K: admin.md I1 を「単一プロバイダ固定（MVP）」と明示し、必要なら ADR 化を検討
