# B. ノート取り込み

## B1: 単一ファイルをアップロードしてノート化

### 正常系
ステップ 4〜7 はアップロードモーダル内で連続して起こる（同一 UI 内で完結）。

1. ユーザーがホーム or 任意のディレクトリ画面で「アップロード」を選ぶ（モーダルが開く）
2. ファイル選択ダイアログ、またはドラッグ&ドロップで 1 ファイルを指定する
3. システムは形式判定を行い、形式に応じた処理を開始する
   - HTML: そのまま取り込み
   - Markdown: HTML に変換
   - Word / Excel / PowerPoint / プレーンテキスト: テキスト抽出 → LLM で構造化 HTML 生成
   - PDF（テキスト層あり）: テキスト抽出 → LLM で構造化
   - PDF（テキスト層なし）: OCR または LLM で内容解析 → 構造化
   - 画像: OCR or LLM でテキスト抽出 → 構造化
   - 音声: 音声認識でテキスト抽出 → 構造化
4. モーダル内に推論待ちのスケルトン UI が表示される。クライアントは `getIngestionJobFn` を 1.5〜2 秒間隔でポーリングし、`status` が `previewing` になるのを待つ（最大 180 秒）
5. モーダル内のプレビュー編集ビューに切り替わる。タイトル・保存先・抽出されたタグ / FrontMatter / 本文 HTML を確認できる
6. ユーザーは同じモーダル内でタイトル、保存先ディレクトリ、タグ、FrontMatter（raw JSON 編集）を修正できる。本文 HTML は読み取り専用プレビュー（編集は別 Issue で対応予定 — Issue #226 ADR-002）
7. 「登録」を押すとモーダルが閉じてノート詳細画面へ遷移する。元ファイルは保存しない

### 異常系
- 対応外形式: アップロード前に弾き、対応形式の一覧を案内する
- ファイルサイズが上限超過: 上限値とファイルサイズを提示する
- LLM 呼び出し失敗 / タイムアウト: モーダル内に失敗状態を表示し「破棄」「キュー画面で詳細を見る」を提示する。所有者向け再試行は別 Issue で実装予定 — Issue #226 ADR-007
- 180 秒以内に推論が完了しなかった場合: モーダル内に「キュー画面で続きを確認できます」と誘導してモーダルを閉じる。ジョブは pending / processing のままキューに残る
- OCR / 音声認識失敗: 失敗箇所を明示。テキストが空でも、利用者が手動で内容を追記して保存可能
- 取り込みキャンセル: プレビュー画面で「破棄」を選ぶと、データもメディアも保存されない

## B2: 複数ファイルを一括アップロード

### 正常系
複数ファイル選択時はモーダル内でプレビュー編集まで遷移しない（並列推論のポーリング UX が複雑なため — Issue #226 ADR-003）。代わりに全件をキューに積み、キュー画面（P13）で 1 件ずつプレビュー編集する。

1. ユーザーが複数ファイルをドラッグ&ドロップ、または選択
2. モーダル内で全ファイルをシリアルに `uploadFileFn` に投げる（途中失敗してもキュー投入は継続）
3. 投入完了後、モーダル内に「N 件中 K 件をキューに追加、M 件失敗」と集計を表示し「キュー画面を開く」ボタンを提示
4. キュー画面（P13）で各カードの状態（待機 / 処理中 / プレビュー可能 / 失敗）を見ながら順次プレビュー編集する

### 異常系
- 一部失敗・一部成功の混在: モーダルの集計表示に失敗ファイル名を列挙。失敗分は再試行 or 個別キャンセル可（再試行は別 Issue 予定）
- ブラウザを閉じた / 通信断: 進行中のものはサーバー側でジョブとして残り、次回ログイン時に「未完了の取り込みがあります」と通知される
- 同一日のアップロード上限（インスタンスが設定している場合）超過: 残量を表示し、超過分は翌日扱いに送るか破棄するかを利用者が選ぶ

## B3: アップロード直後の再生成

### 正常系
1. アップロード直後のプレビュー画面で「再生成」ボタンを押す
2. LLM 構造化を再実行し、結果が更新される
3. 利用者が満足するまで再生成可能。`保存` を押した時点で確定し、それ以降は再生成不可

### 異常系
- 再生成回数上限（過剰呼び出し防止のため）に達した: 「これ以上の再生成はできません」と表示
- 再生成中の保存操作: 結果待ち状態であることを明示し、完了後に再操作させる

## B4: アップロード直後のタイトル・保存先ディレクトリ修正

### 正常系
モーダル内のプレビュー編集ビューで以下を編集できる。本文 HTML はモーダル内では読み取り専用（編集は Issue #226 ADR-002 に基づき別 Issue で対応）。

1. モーダル内のプレビュー編集ビューでタイトル・ディレクトリ・タグ・FrontMatter（raw JSON 編集）を編集する
2. 保存先ディレクトリは既存ツリーから選択（モーダルの editing 突入時に `getDirectoryTreeFn` で lazy load）、もしくは新規ディレクトリ名を入力（自動作成）
3. 「登録」で確定し、ノート詳細画面へ遷移する

### 異常系
- 入力したディレクトリ名がディレクトリ規約違反（禁止文字など）
- 同名ノートが既存: 「上書き保存」か「別名で保存」かを選ばせる
- FrontMatter JSON が parse 不可 / オブジェクトでない: presentation 層の `errorDisplay.ts` 経由で「FrontMatter の JSON が不正です。形式を確認してください」のようなユーザー向け文言をモーダル内に表示する（内部の `BusinessRuleError("FRONT_MATTER_JSON_INVALID")` は UI には露出させない）
- 入力中に取り込みプレビューがタイムアウトでロストした場合は再アップロードを促す

## B5: アップロード失敗・対応外形式・サイズ超過

### 正常系
- アップロード前のクライアント側で対応形式・サイズチェックを行い、即座にフィードバックを返す
- サーバー側でも同様にチェックし、二重で防御する

### 異常系
- 一覧外の形式: 「対応形式」リンクから対応一覧を確認できる
- 巨大ファイル: アップロード自体を始めない
- LLM プロバイダ障害: ステータスバナーで管理者向け案内を表示し、取り込み待機キューに保留できる
