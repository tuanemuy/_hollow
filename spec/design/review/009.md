# デザインレビュー 009 — Issue #795 media-upload UI モック

## 対象

- `spec/design/pages/P12-editor.html`（desktop、`.media-upload` セクション）
- `spec/design/pages/mobile/P12-editor.html`（mobile）
- 計画: `.issue/795/plan.md`（AC-1〜AC-7 / Step 1）

## 視覚確認

agent-browser (0.28.0) で両 HTML を `file://` で開き、スクリーンショットで確認した。

- **desktop（1280px）**: 8 状態すべてが縦に並記され、editor 本文 → 区切り線 →「メディアを挿入」ラベル → idle dropzone（角丸アイコン + dashed 枠）→ dragging（accent 強調）→ uploading image（グラデのサムネ枠 + determinate バー 62%）→ uploading video（動画アイコン + バー 34%）→ unsupported（赤 alert-error）→ oversized（琥珀 alert-warning）→ done（緑 alert-success）→ error+「再試行」pill、と崩れなく描画。直下の link-suggest / save-row も無傷。
- **mobile（390px）**: 同 8 状態が狭幅でパディングを詰めて描画。dropzone は全幅の大きなタップ床、preview は折り返さず、`再試行` ボタンは 44px に拡張。下部固定 save-bar も健在。
- dropzone / progress は `P13-upload.html` の `.dropzone` `.progress` `.progress-bar` とトークン・寸法レベルでほぼ同一（progress は byte 一致）であることを diff で確認。

## 問題点

なし（要修正のブロッカーは検出されず）。

## 改善提案

- [S-001] uploading preview の `.progress` に `role="progressbar"`＋`aria-valuenow` を付けつつ、隣接の `.media-progress-text` に `aria-live="polite"` を併用している。plan.md のリスク欄（「success/preview の a11y 二重読み上げ」）と AC-6 は「ProgressBar を `decorative`（aria-hidden）にして隣接 live-region で 1 回だけアナウンス」を意図しているため、実装時はバーを decorative にし二重読み上げを避けること。モックは図示目的なので現状可だが、実装が mock を写経して二重アナウンスにならないよう注記。
- [S-002] `.media-thumb` の画像サムネ枠は `linear-gradient(135deg,#c9d3df,#8e99a8)`（`.avatar` と同一のハードコード）でプレースホルダ表現している。既存 avatar パターンの踏襲で新トークン発明ではないが、実装では `URL.createObjectURL` の実画像に置換される旨を前提に据える（mock 限定の filler）。
- [S-003] idle dropzone の input は `<label>` 内包＋`aria-label` の二重命名。実装では label 内の説明文と input の関連付け（`htmlFor`/`useId`）に寄せると冗長命名を避けられる（plan Step 5 の方針どおり）。

## 既存との一貫性

良好。

- **ALERT プリミティブ**: unsupported/oversized/error/done の 4 バナーは既存 `.alert` + `.alert-error/warning/success` + `.alert-icon/content/title/body` と再試行 `.alert button` をそのまま使用。同一ページ内の既存 alert-warning（保存系バナー）と並べても完全に同質。
- **dropzone**: `border:2px dashed var(--color-hairline-strong)` / `bg var(--color-surface-elevated)` / `radius var(--radius-xl)` / icon 56px(desktop)/52px(mobile) + `shadow-xs` と P13 を踏襲。padding のみ in-body 二次要素として 48→32/24px に縮小（妥当）。icon は P13 の `border-radius:50%; background:#fff` を `var(--radius-full)`/`var(--color-bg)` に置換し、むしろトークン準拠度が向上。
- **progress**: P13 と byte 一致。
- **タイポ・余白**: ラベルは既存 `.link-suggest-label` / `.dir-label` と同じ uppercase + tracking。section gap は `var(--space-4)`、`.media-upload .alert { margin-bottom:0 }` で個別 margin を畳み section gap に従わせており余白も整合。
- 異質な新パターンの混入なし。`.media-state-label`（mono ラベル）は「実装は排他表示で出ない」とコメント済みのモック専用スキャフォールドで、出荷見た目には影響しない。

## トークン準拠

準拠。新規 `#795` ブロックの CSS は色・余白・radius・shadow・motion・font をすべて既存 `var(--*)` で記述。新トークンの発明なし（plan Step 2 の「原則 新トークンなし」と一致）。唯一の literal は `.media-thumb` のグラデ（既存 `.avatar` の複製、S-002）と寸法 px（モック全体の記法と同じ）のみ。`.sr-only` / `.alert-body code` の追加ユーティリティもトークン使用。

## AC 充足

- AC-1（dropzone D&D + クリック選択）: ○ — 領域全体が `<label>` + 非表示 `<input type=file accept="image/*,video/*">`、`.dragging`/`[data-dragover]` のホバー強調も描画。
- AC-2（preview = filename+size+画像サムネ/非画像アイコン）: ○ — image はサムネ枠、video はアイコン、filename+size+進捗を同一ブロックに併記。
- AC-3（error/warning バナー区別）: ○ — 非対応形式=`alert-error`（赤・丸 i）/ サイズ超過=`alert-warning`（琥珀・三角）で明確に区別。
- AC-4（progress/success/error 各状態）: ○ — determinate バー＋%、`alert-success` 成功、`alert-error`＋再試行をすべて描画。
- AC-6（a11y）: ○（軽微留意あり）— `role=status`/`role=alert`、`aria-live`、`progressbar`、`aria-label`、mobile 再試行 44px、dropzone の hidden input+label を実装。二重読み上げ回避は S-001 で実装時注記。
- AC-7（desktop/mobile 両方）: ○ — 双方の HTML に同一構成で追加、レイアウト崩れなし。

（AC-5 / AC-8 はフロント実装ステップで mock 対象外）

## 既存レイアウトの非破壊

異常なし。media-upload は `editor-body-panel` 内の `.editor` 本文の直後・link-suggest の直前に挿入され、div ネストも `</div><!-- /media-upload --></div><!-- /editor-body-panel -->` で正しく閉じている。toolbar（sticky）/ link-suggest / save-row（desktop）/ save-bar（mobile 下部固定）はスクショ上いずれも従前どおり描画。

## 結論

収束。要修正のブロッカーなし。8 状態すべてが desktop/mobile で崩れず描画され、既存 ALERT / dropzone / progress / pill プリミティブとトークンに完全準拠。S-001（progressbar の二重読み上げ）/ S-002（サムネ placeholder）/ S-003（input 二重命名）は実装フェーズ（Step 5）で吸収すべき軽微な注記であり、モック自体の修正は不要。
