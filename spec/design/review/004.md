# レビュー 004 — P18-tags.html 改修と視覚レビュー

`spec/design/pages/P18-tags.html` のユーザー指摘 4 点（角丸の連結問題、処理中UIの不統一、リネーム/統合の混在フォーム）への対応と、その後のマルチビューポート視覚レビュー記録。

## 入力（ユーザー指摘）

1. ボーダーとの余白なしの角丸背景が変
2. 編集中のタグの背景とフォームの背景のつなぎ目に角丸がある
3. 処理中のレイアウトやUIが他のページと一貫していない
4. リネームと統合が別アクション → 1つのフォーム → 別の実行ボタン、となっておりおかしい

## 対応サマリー

| # | 指摘 | 対応 |
|---|------|------|
| 1 | 角丸背景の余白なし | `.tag-editing-block` という1つのコンテナで囲み、角丸・ボーダー・シャドウを外側に集約。内側は `padding` を確保しカード化。 |
| 2 | つなぎ目角丸 | 別要素 (`.tag-row.editing` + `.inline-form`) を統合し、`overflow: hidden` の単一コンテナ内で行→モード切替→フォームを連続配置。角丸は外側1か所のみ。 |
| 3 | 処理中UIの不統一 | `.progress-card`（縦長カード・page-header 内右寄せ）を廃止し、P12-editor の `.lock-banner` に倣った全幅の横長 `.process-banner` に刷新（spinner + テキスト + メタ + キャンセル + 下に細プログレスバー）。 |
| 4 | リネーム/統合の混在 | `.mode-switch`（タブ風 segmented）でモード切替を導入。表示中モードの **単一フォーム + 単一実行ボタン + キャンセル** に整理。 |

## Step 1: マルチビューポート視覚確認

`/tmp/design-screenshots/review/P18-{desktop,tablet,mobile}.png`（修正前） と `P18-{desktop,tablet,mobile}-2.png`（修正後）で確認。

### 検出された二次問題（モバイル）

修正版を 375×667 で確認したところ、新規に以下の問題が発生していた:

#### A. process-banner のテキストが縦書き化（重大）

`flex-wrap: wrap` で要素が4列横並びを試みた結果、最も縮みやすい `.process-banner-text` の幅が極端に狭くなり、`#project` 等のインライン `tag-mono` が改行を阻害して各日本語1文字ずつ縦書き状態になっていた。

#### B. メタ表記とキャンセルボタンの重なり（重大）

`.process-banner-meta` と `.process-banner-cancel` が `align-items: center` で重なるレイアウトに陥り、テキストが読めない状態。

#### C. ブラックリストバッジが縦書き化

`.blacklist-tag .badge` に `white-space` 指定が無く、`inline-flex` の子の `.badge` が狭い余白内で1文字ずつ縦並び。

### 対応

**process-banner レイアウトを再構築:**
- HTML を `.process-banner-row > (.process-banner-main + .process-banner-aside) > .process-banner-bar` 構造に変更
- `.process-banner-main`（アイコン + テキスト）と `.process-banner-aside`（メタ + キャンセル）の2ブロックに分割し、モバイルでは縦並び、`@media (min-width: 768px)` で横並び
- `.tag-mono` に `display: inline-block; white-space: nowrap` を付与し、改行で分割されないように
- アイコンに `flex-shrink: 0`、テキストに `min-width: 0; word-break: break-word` を付与

**ブラックリストバッジ:**
- `.blacklist-tag` を `flex; flex-wrap: wrap; min-width: 0` に変更
- `.blacklist-tag .badge` に `white-space: nowrap; flex-shrink: 0` を明示

### 修正後の確認結果

| ビューポート | 結果 |
|--------------|------|
| Desktop 1280×800 | ✅ 全要素整然。process-banner は全幅横長で1行に収まる。編集ブロックの角丸・余白は破綻なし。 |
| Tablet 768×1024 | ✅ process-banner 横長維持。サイドバーは隠れてハンバーガー化。 |
| Mobile 375×667 | ✅ process-banner は縦並びで「一括処理中…」が正常に1行表示。メタ・キャンセルは下段に並列。ブラックリストバッジは横書き。 |

## Step 2: `/critique` — UX・デザイン品質

### AIスロップ判定

**合格**（Apple Calm 方針を実直に守っているため、AI 生成物の指紋に該当しない）。

| 検査項目 | 結果 |
|----------|------|
| AIカラーパレット（ダーク+シアン、紫+青グラデ等） | ❌ 該当なし。Apple System Blue 単色 + ティント済みグレー |
| グラデーションテキスト | ❌ なし |
| ダークモード+グローアクセント | ❌ なし |
| グラスモーフィズム | ❌ なし（header の `backdrop-filter` のみ — Apple 自体の慣習なので OK） |
| ヒーローメトリクスレイアウト | ❌ なし |
| 同一カードグリッド | ❌ なし |
| 「丸角+カラーアイコン+見出し」テンプレ | ❌ なし |
| 汎用フォント（Inter, Roboto） | ❌ SF Pro / Hiragino のチェーン |
| 装飾的シャドウ+丸矩形 | ⚠️ `.tag-editing-block` に `box-shadow: --shadow-sm` あり（後述） |

注: 「Apple クローンに見える」点は否定できないが、これは方針として明示的に選択されたもの（`spec/design/index.md` §1）であり、独自性の不在ではなく**意図された制約**。

### 全体の印象

「処理中UI・編集ブロック・モード切替」の3点改修は機能的には正しい方向。一方で、**Apple Calm の核である "静かな書斎" トーンと、新設された編集ブロックの主張の強さ**が衝突している。編集状態を示すために `accent border + box-shadow + accent surface` の三重で囲っており、これは方針の「線で区切るくらいなら 1 段大きい余白を入れる」「シャドウは原則使わない」と矛盾する。

最大の機会: **編集ブロックを "浮かない、線で囲わない、surface のみで状態を示す" 形に静かに格下げすると、ページ全体の静寂感と整合する。**

### うまくいっていること

1. **モード切替（segmented）の導入** — 「リネーム」「統合」を1つの編集行に詰め込まずに直交させたのは正しい。`/index.md` の§2.2「視覚バランスはセンタリング + 左寄せの組み合わせ」とも整合し、認知負荷も下がった。
2. **process-banner の全幅横長化** — P12-editor `.lock-banner` パターンと響き合い、ページ間の一貫性が大きく改善された。spinner アニメーションも控えめで、読書体験を邪魔しない。
3. **ブラックリストとアクティブタグの並置** — セクション分離で「再抽出ブラックリスト」概念の独立性が伝わる構成。

### 優先事項

#### 1. 編集ブロックが Apple Calm の方針に反して "浮きすぎ"（高）

**何が**: `.tag-editing-block` が `border: 1px solid var(--color-accent)` + `box-shadow: var(--shadow-sm)` + `background: var(--color-accent-surface)` の三重で囲まれている。

**なぜ重要か**:
- `spec/design/index.md` §1 「シャドウは原則使わない。ドロップダウンやモーダルなど『浮く』要素のみ控えめに使う」と矛盾。インライン展開のフォームは「浮く要素」ではない。
- P17-trash 等の隣接画面では shadow をフォーカス用以外には使っていない（`grep` で確認済み）ため、P18 だけが浮いて見える。
- `var(--color-accent)` の濃いブルー 1px ボーダーは、§1 「区切りは限りなく薄いヘアラインを使う」のトーンを破る。
- frontend-design の DON'T「カードの中にカードをネストする」にも該当（accent surface 上に白い `.inline-form` カードを置いている）。

**修正**:
- `box-shadow` を削除。
- `border: 1px solid var(--color-accent)` を廃止し、代わりに**左端のみアクセントバー**（`border-left: 3px solid var(--color-accent)`）で状態を示す。Apple Notes / Mail のインライン編集に近い静かなアフォーダンスになる。
- 内側の `.inline-form` の白カード+ボーダーを廃止し、accent surface 上に直接フォーム要素を置く（入力欄だけが白い surface で浮く）。

**コマンド**: `/quieter`（強度を落とす）または手動修正。

#### 2. 編集ブロックの「編集中」バッジが冗長（中）

**何が**: `.editing-badge` がアクションエリアに「編集中」テキストを置いているが、編集状態は **block の囲み + アクセント + 開いたフォーム** で十分伝わっており、ラベルとしては情報量ゼロ。

**なぜ重要か**: frontend-design の DON'T「同じ情報を繰り返す」「すでに見える情報を繰り返す」に該当。Apple Calm の「言葉数を減らす」志向と矛盾。

**修正**: バッジを削除し、その位置に「**閉じる × アイコン**」または「**キャンセル**」テキストリンクを置く。これにより「いま編集中」というステータスではなく「ここで閉じられる」という**操作のアフォーダンス**に変わる。

#### 3. モバイルで `.row-actions` が常時表示・冗長（中）

**何が**: `@media (max-width: 1023px)` で `.row-actions { opacity: 1 }` のため、タグ10件 × 3アクション = 最大30個のテキストボタンが常時画面内に並ぶ。さらに「削除 **(ブラックリスト化)**」という補足が括弧書きで常時表示。

**なぜ重要か**:
- 認知過負荷。タグ管理画面の主目的は「一覧の俯瞰」と「個別操作」であり、操作トリガはタップ時に展開される方が Apple iOS 系の慣習に合う。
- 「(ブラックリスト化)」補足が全行で繰り返されており、行高を肥大化させる（モバイルで顕著）。

**修正**:
- モバイルでは `.row-actions` を `︙` アイコン（kebab menu）に集約し、タップで action sheet（または bottom sheet）展開。
- 「削除」の挙動説明はホバー/ロングタップ時のツールチップで提示。デフォルトでは「削除」一語のみ。
- もしくは少なくともデフォルトでは「リネーム / 統合 / 削除」の3ラベルのみで `(ブラックリスト化)` を削除し、削除実行時の確認ダイアログでブラックリスト化の説明を行う。

**コマンド**: `/clarify` でマイクロコピー再検討 + `/adapt` でモバイルパターン置換。

#### 4. 削除アクションのマイクロコピー「削除（ブラックリスト化）」が初見で意味不明（中）

**何が**: 「削除」と「ブラックリスト化」が同一アクションであることを括弧書きの hint で示している。

**なぜ重要か**:
- 「削除」と「ブラックリスト化」は概念的に別物（一方は除去、もう一方は永続的拒否リスト追加）。ユーザーは「削除すると同時にブラックリスト入りするの？それともブラックリストに入れる別動作？」と迷う。
- 同じ画面の下部に「ブラックリスト」セクションがあるため、用語の重複でさらに混乱しやすい。

**修正**:
- ボタンラベルを「**削除してブラックリストに追加**」または「**削除して再抽出を防止**」に変更。括弧書きをやめる。
- 削除確認ダイアログで、明示的に「このタグを 38 件のノートから削除し、今後の自動抽出も停止します」と全文で説明。
- もしくは「削除」と「ブラックリスト化」を別アクションとして分離（削除 = タグ除去のみ、🚫 = 再抽出ブロック）。

**コマンド**: `/clarify`（UXコピー改善）。

#### 5. process-banner のテキストが冗長（低〜中）

**何が**: 「**一括処理中** · #project を #Projects に統合中」と、spinner + 「処理中」というラベル + 「統合中」という動詞が三重に「処理中」を伝えている。

**なぜ重要か**: frontend-design DON'T「同じ情報を繰り返す」。Apple Calm の「言葉数を減らす」志向と矛盾。

**修正**: 「**#project を #Projects に統合中**」のみで十分（spinner が「進行中」を視覚的に伝える）。「一括処理中」プレフィックスを削除。

**コマンド**: `/clarify`。

### 軽微な観察事項

- **`tag-mono` の小さな白いパディング**: `padding: 1px 6px; background: rgba(255,255,255,0.7)` でハッシュタグを浮かせているが、accent-surface 上で「もう一段浮いている」印象。Apple Calm 的には背景なしで accent-ink 色のみで充分。
- **ブラックリストの `badge` 「再抽出を防止」**: ラベルが冗長気味。Apple HIG 風には「**再抽出停止**」など短い動詞のほうがリズムが良い。あるいは「自動抽出: オフ」のような状態表記。
- **stats のドット区切り**: モバイルで `47 タグ · うち 3 件ブラックリスト · 562 件のタグ付け` が折り返したとき、`·` が単独で取り残される瞬間がある。`flex-wrap` の制御として、各 stat を `white-space: nowrap` の単位にまとめると改善。
- **section-title 「ブラックリスト」が `text-xl semibold`**: page-title (text-3xl regular) との対比で「ブラックリスト」のほうが weight が強く、視覚階層が逆転して見える瞬間がある。`text-lg medium` 程度に控えめにすると Apple Calm のリズムに合う。
- **編集ブロック内のmode-switch（segmented）と、ページ上部の sort segmented が視覚的に似ている**: 並列のアフォーダンスとして問題ないが、editing-block 内の mode-switch は「状態切替」、上部は「並び替え」と意味が異なる。色や形を変えるよりも、**ラベルで明示** している現状は許容範囲。

### 考慮すべき質問

1. **編集モードの "強い視覚的隔離" は本当に必要か？** Apple Notes / Mail でインライン編集を開いても、ここまで濃いブルーで囲まない。surface のみで十分ではないか？
2. **process-banner は永続表示で良いか？** タスク完了後に自動で消えると、Apple Calm の "静かな書斎" トーンに合う。`role="status"` の意図にも整合する。
3. **リネームと統合は本当に同じ編集モードに置くべきか？** 概念的には「**同じタグの中身を変える**」(リネーム) と「**別タグに吸収させる**」(統合) で操作対象が異なる。**統合は別の操作（タグカードから "...へ統合" メニューを開く）** にすると、リネームはもっと軽量なインラインで完結できる。今の mode-switch は妥協案として機能はしているが、最良かは要検証。
4. **「削除 = ブラックリスト化」というモデル自体が UX として正しいか？** タグを消したいだけのユーザーに「再抽出ブラックリスト」概念を強制している。「削除して保留（戻せる）」と「永久ブラックリスト」を分離する案を検討する価値あり。これは設計レイヤーの議論。

## Step 4: `/audit` — A11y・レスポンシブ・プロダクション品質

### アンチパターン判定

**合格**。AI スロップの指紋（AI パレット、グラデーションテキスト、グローイングアクセント、グラスモーフィズム、ネストカード、ヒーローメトリクス、汎用フォント）に該当なし。`/polish` で残っていた「accent-surface 上の半透明白カード」も解消済み。

### エグゼクティブサマリー

- **致命的: 0 件** / **高: 5 件** / **中: 6 件** / **低: 3 件**
- 最も重大: `(1)` キーボードで row-actions にアクセス不可、`(2)` 検索 input が unlabeled、`(3)` タブレット領域で 44×44 タッチターゲット未達、`(4)` `prefers-reduced-motion` 未対応、`(5)` `progressbar` の ARIA 値属性欠落
- 設計レイヤーでは適切に `aria-label` / `role="status"` / `<label for>` 等が付与されている。実装時に **キーボード可達性とタッチターゲット** の補強が必要

### 高重要度の問題

#### A-H1. キーボードで `.row-actions` にアクセス不可

- **場所**: `app/...` の `.tag-row:hover .row-actions { opacity: 1 }`（CSS 470 行付近）
- **WCAG**: 2.1.1 Keyboard (Level A) — **A 違反**
- **説明**: row-actions は `opacity: 0`、`tag-row:hover` でのみ `opacity: 1`。キーボードユーザーは Tab フォーカスしても表示されないため、リネーム/統合/削除に到達不能。
- **影響**: タブレット領域（768〜1023px）はモバイル kebab 化が効かないため、**キーボード操作者はタグの一切のアクションが実行できない**。
- **推奨**: `.tag-row:hover .row-actions, .tag-row:focus-within .row-actions { opacity: 1 }` で `focus-within` を追加。実装時に動的に検証。

#### A-H2. 検索 input が unlabeled（2 か所）

- **場所**:
  - `.header .search input`（HTML 行 730 付近）
  - `.toolbar .field-search input`（HTML 行 838 付近）
- **WCAG**: 1.3.1 / 3.3.2 / 4.1.2 — **A/AA 違反**
- **説明**: 両者とも `<label>` も `aria-label` も持たず、`placeholder` のみで意味を伝えている。
- **推奨**: `aria-label="ノート、タグ、本文を検索"` / `aria-label="タグを検索"` を `<input>` に直接付与。

#### A-H3. タッチターゲット 44×44 未達（タブレット領域 640〜1023px）

- **場所**: 以下のボタン全般 — `.menu-btn (36)`, `.pill-btn (36)`, `.editing-close (36)`, `.row-kebab (36)`, `.btn-sm (32)`, `.text-action (28)`, `.mode-switch button (~32)`, `.process-banner-cancel (~36)`
- **WCAG**: 2.5.5 Target Size (AAA) / 2.5.8 (AA in 2.2) — タブレット領域で **AA 違反の可能性**
- **説明**: グローバル mobile fix は `@media (max-width: 639px)` 内の `min-height: 44px` のみで、640〜1023px のタブレット領域（タッチ操作主体）で 44 未達のボタンが多数残る。さらに `min-width: 44px` は `.icon-btn` のみで、`.editing-close` / `.row-kebab` は対象外。
- **推奨**: ブレークポイントを `@media (max-width: 1023px) and (pointer: coarse)` に拡張、`min-width: 44px` を `.editing-close, .row-kebab, .menu-btn` にも適用。

#### A-H4. `prefers-reduced-motion` 未対応

- **場所**: `.process-banner-icon { animation: spin 1.4s linear infinite }`（CSS 323 行付近）
- **WCAG**: 2.3.3 Animation from Interactions (AAA) / general motion sensitivity
- **説明**: スピナーが常時無限回転。前庭障害や乗り物酔いが起きやすいユーザーに不快感を与える。
- **推奨**:
  ```css
  @media (prefers-reduced-motion: reduce) {
    .process-banner-icon { animation: none; }
  }
  ```

#### A-H5. `.process-banner-bar` に ARIA 進捗値が欠落

- **場所**: `<div class="process-banner-bar"><span></span></div>`（HTML 行 826 付近）
- **WCAG**: 4.1.2 Name, Role, Value — **A 違反**
- **説明**: ビジュアルでは「87 / 247 ノート」が表示されているが、進捗バー自体には `role="progressbar"` も `aria-valuenow/min/max` もない。スクリーンリーダーは「進捗中」の事実すら認識できない。
- **推奨**:
  ```html
  <div class="process-banner-bar" role="progressbar"
       aria-valuemin="0" aria-valuemax="247" aria-valuenow="87"
       aria-label="統合進捗"><span></span></div>
  ```

### 中重要度の問題

#### A-M1. `role="tablist"` パターンが不完全

- **場所**: `.mode-switch[role="tablist"]` とその子 `[role="tab"]`（HTML 行 873 付近）
- **WCAG**: 4.1.2 / ARIA Authoring Practices
- **説明**: `role="tab"` には `aria-controls` で対応する `role="tabpanel"` ID を参照する必要があるが、現状 `tabpanel` 自体が存在しない。実体は **単一フォームの表示モード切替** で tab パターンと意味が乖離している。
- **推奨**:
  - パターンA（推奨）: `role="radiogroup"` + `role="radio"` + `aria-checked` に変更（「2 つの操作モードのうちひとつを選ぶ」セマンティクス）。
  - パターンB: `role="tablist"` を維持するなら `.inline-form` 全体を `<div role="tabpanel" id="rename-panel">` で囲み、tab 側に `aria-controls="rename-panel"` を付与。

#### A-M2. kebab メニュー button に `aria-haspopup` / `aria-expanded` 欠落

- **場所**: 各 `<button class="row-kebab" aria-label="操作メニュー">`（10 か所）
- **WCAG**: 4.1.2
- **説明**: クリックで menu を展開するボタンであることが ATs に伝わらない。menu 実装時には開閉状態を `aria-expanded` で公開する必要がある。
- **推奨**: `aria-haspopup="menu" aria-expanded="false"` を追加。実装時に開閉状態を切り替える。

#### A-M3. `.nav-item` が `<div>` でキーボード操作不可

- **場所**: サイドバーの全 `<div class="nav-item">`（HTML 行 750-805 付近、10 項目）
- **WCAG**: 2.1.1 Keyboard (A) / 4.1.2
- **説明**: ナビゲーション項目が `div` で、`tabindex` も `role` もなくクリックハンドラ未実装。デザインモック段階としては許容範囲だが、実装時には `<a href>` か `<button>` 化が必須。
- **推奨**: 実装時に router link (`<Link to="/tags">` 等) でラップし、aria-current="page" で現在ページを示す。

#### A-M4. ヘッダーのアバターが `<div>` で操作不可

- **場所**: `<div class="avatar" aria-hidden="true">YK</div>`（HTML 行 738）
- **WCAG**: 2.1.1
- **説明**: プロフィールメニューへの入口となるべきアバターが非対話的な div、かつ `aria-hidden="true"` で SR から完全に隠れている。
- **推奨**: `<button aria-label="アカウントメニュー">YK</button>` 化。`aria-hidden` は外す。

#### A-M5. `.segmented` (利用件数/名前/最終使用) に `aria-pressed` 欠落

- **場所**: `.toolbar .segmented button`（HTML 行 843 付近）
- **WCAG**: 4.1.2
- **説明**: 単独の `<button>` で toggle 挙動を持つが、押下状態 (`.active`) が ATs に伝わらない。
- **推奨**: `aria-pressed="true"` / `"false"` を付与。または `role="radiogroup"` + `role="radio"` でセマンティクスを明示。

#### A-M6. menu-btn に `aria-expanded` 欠落

- **場所**: `<button class="menu-btn" id="menuBtn" aria-label="Menu">`（HTML 行 722）
- **WCAG**: 4.1.2
- **説明**: drawer の開閉状態が伝わらない。`aria-label="Menu"` も日本語サイトなら「メニュー」が望ましい。
- **推奨**: `aria-label="メニュー" aria-expanded="false" aria-controls="sidebar"` を追加。JS で開閉時に値を更新（現状の script に追加）。

### 低重要度の問題

#### A-L1. `--color-ink-tertiary` (#86868b) on `--color-bg` のコントラスト不足

- **計算値**: 3.63:1
- **WCAG**: 1.4.3 Contrast (AA) は normal text に 4.5:1 を要求 — **AA fail**
- **使用箇所**: `.tag-last` (text-sm), `.blacklist-meta` (text-sm), `.tag-name .hash` (text-lg, large text なので 3:1 で OK)
- **判断**: Apple Calm 方針として意図的に弱コントラストを採用しているため**仕様意図と WCAG の衝突**。実装時に `--color-ink-tertiary` を `#6b6b70`（contrast ~4.6:1）程度に微調整するか、tokens.md に「AA 対象外の補助テキストのみに使用」と明記する判断が必要。

#### A-L2. `--color-ink-tertiary` on `--color-accent-surface` のコントラスト境界

- **計算値**: 3.19:1
- **使用箇所**: `.tag-editing-block .tag-name .hash`（text-lg = large text）
- **判断**: large text 扱いで 3:1 をかろうじてクリア。境界線上。`accent-ink` を使う方が安全。

#### A-L3. 装飾アイコンに `aria-hidden="true"` 不在

- **場所**: `.search-icon`、`.tag-name .hash`、各 SVG（kebab 等以外で装飾目的のもの）
- **WCAG**: 4.1.2
- **説明**: 装飾アイコンが SR に余分な情報として読まれる可能性がある（多くの SR は `<svg>` を無視するが、明示が望ましい）。
- **推奨**: 装飾 SVG に `aria-hidden="true" focusable="false"` を一律付与。

## Step 5: UX コピーの語彙統一（ユーザー指示）

`/audit` 指摘の A11y 系は後回しとし、まず「ブラックリスト」周りの命名・操作ラベルを整理する。
ブラックリストという内部用語をユーザー向け語彙の「除外」に統一し、操作動詞は文脈に合わせて短く揃える。

| 場所 | 旧 | 新 |
|------|----|----|
| `.row-actions` の編集動詞 | リネーム | **編集** |
| `.row-actions` の destructive | 削除して再抽出を防止 | **ブラックリスト** |
| `.mode-switch` の編集モード | リネーム | **編集** |
| `.inline-form` の入力ラベル | 新しいタグ名 | **タグ名** |
| `.form-actions` の実行ボタン | リネームを実行 | **保存** |
| `.section-title` | ブラックリスト | **除外されたタグ** |
| `.section-desc` | ここに登録されたタグは、自動抽出時に再追加されません。手動でノートに付与することは可能です。 | これらのタグは自動抽出時に再追加されません。手動でノートに付与することは可能です。 |
| `.blacklist-tag .badge` | 再抽出を防止 | **削除**（セクションタイトル「除外されたタグ」と意味重複のため） |
| `.blacklist-meta` | YYYY/MM/DD にブラックリスト化 · 元 N 件 | YYYY/MM/DD に**除外** · 元 N 件 |
| `.blacklist-row` のボタン | ブラックリストから除外 | **元に戻す** |
| `.stats` の集計 | うち 3 件ブラックリスト | うち 3 件**除外中** |

### 用語モデルの整理

- **動詞「ブラックリスト」**: タグを除外リストに追加するアクション（destructive）。「削除」ではなく「除外」へ追加する操作であることを明示するために、敢えて短く「ブラックリスト」と動詞化（ボタンラベル）。
- **状態「除外中」**: そのタグが現在、自動抽出から除外されている状態。セクションタイトル「除外されたタグ」内では自明のためバッジは表示しない（タイトルとの重複回避）。
- **アクション「元に戻す」**: 除外を解除して通常タグに戻す（undo セマンティクス）。
- セクションタイトルは「除外されたタグ」で「結果として除外状態にあるタグの集合」を示す。

これにより、操作（ブラックリスト）→ 状態（除外中）→ 解除（元に戻す）の用語チェーンが意味的に閉じる。
