# デザインレビュー 005 — Issue #198: エラー UI の設計成果物化

**対象:** `spec/design/pages/P01-signup.html` / `P01b-admin-setup.html` / `P03-login.html`
**日付:** 2026-05-30
**範囲:** 認証系3ページへのエラー状態バリアント追加（HTMLモック）。`app/` の React 実装には触れていない。

各ゲート（critique → clarify → harden → audit → polish）の主要指摘と反映内容を記録する。検証は Google Chrome（headless）でデスクトップ(1440/1100px)・モバイル(375px)のスクリーンショットを目視。

---

## critique（階層・情報設計・感情トーン）

- **指摘 B-001（要修正・反映済み）**: 各エラーバリアントの `<main class="auth-shell">` が成功状態と同じ `min-height: calc(100vh - var(--header-height))` を継承するため、バリアント間に約1画面分の巨大な空白が生じ、「成功状態と並べて視覚的一貫性を確認する」（ADR-001 の確認方法）が著しく損なわれていた。
  - **反映**: バリアント `<main>` に `is-variant` クラスを付与し、`.auth-shell.is-variant { min-height: 0; }` を3ファイルの `<style>` に追加。先頭の成功状態ブロックは `min-height` を維持（リファレンスとして1画面占有のまま）。バリアントは縦に詰まって並ぶようになり、比較しやすくなった。
- **良かった点**: エラー面に `--color-error-surface`（淡いピンク #fbebeb）+ `--color-error` の細いリングを使い、強い赤を多用しない Apple Calm トーンを維持。ケース名のキャプション見出し（`--color-ink-tertiary` + 上ヘアライン）が控えめに各バリアントを区切り、情報設計上のノイズになっていない。

## clarify（マイクロコピー・行動指示）

- **方針**: 文言は現実装と一字一句一致させる制約があるため、文面の改善提案は行わず #201 への申し送りに留める（plan.md ステップ4(b)）。
- **指摘 C-001（申し送り / 非修正）**: P03 unauthorized 汎用の合成文「ログインできませんでした。認証が必要です」は、プレフィックス（form 由来）と本文（errorDisplay 由来）の接合にやや違和感がある。ただし Issue 制約により文言は変えず、ファイル内コメントで「文言変更提案は #201 申し送り」と明記した。
- **反映済み**: validation の field 直下 hint は「何が問題か」を述べる短文（例「メールアドレスの形式が正しくありません。」「8文字以上で入力してください。」）とし、エラー時に静的 hint を上書きする現実装の挙動を再現。conflict「あり版」には列挙攻撃リスクと採否を #201 に委ねる旨の HTML コメントを付与。

## harden（長文・i18n・オーバーフロー・エッジケース）

- **確認 H-001**: 長い日本語エラー文（callout 本文）はカード幅 440/460px 内で自然に折り返し、オーバーフローなし。モバイル375pxでも callout・field hint・キャプション見出しが折り返して破綻しない。
- **確認 H-002**: P01b unauthorized は実装では `invalid_setup_token` / `setup_token_disabled` のどちらか一方のみ表示されるが、モックでは文言提示のため両分岐の `.form-error` を並べた。HTML コメントで「実際には一度に片方のみ」と明記し誤解を防止。
- **i18n**: 本フェーズのスコープ外（index.md §10）。既存の `overflow-wrap: anywhere` グローバル規則がタイトル系に効いており、長語の破綻リスクは低い。

## audit（role / aria / フォーカス / レスポンシブ）

- **確認 A-001**: 誤入力 input すべてに `aria-invalid="true"` を付与（validation / conflict あり版 / setup token 不一致）。
- **確認 A-002**: ブロッキングエラーの summary callout は `role="alert"`（assertive 相当）。P03 の未認証「次の行動案内」callout は `role="status"`（polite）を維持（plan.md リスク項・§フィードバック原則に整合）。
- **確認 A-003**: 装飾 SVG はすべて `aria-hidden="true"`。再送ボタンは実装に合わせ `<button type="button">`。reveal トグルは `aria-label="トークンを表示"`。
- **確認 A-004**: エラー状態でもフォーカスリングが見える。`.field.has-error .input:focus-visible` が `inset 0 0 0 1px var(--color-error)` + `var(--shadow-focus)` を重ねる既存定義を維持。
- **確認 A-005**: モバイル375pxで横スクロールなし。タップ領域は既存のグローバル mobile fix（`min-height: 44px`）が効く。

## polish（アラインメント・スペーシング・一貫性）

- **反映 P-001**: critique B-001 の `is-variant` 修正により縦リズムが整った。各バリアント先頭のキャプション見出しは `margin-top: var(--space-12)` + `padding-top: var(--space-8)` + 上ヘアラインで一定の区切りリズムを持つ。
- **確認 P-002**: 3ファイルで `.form-error`（P01/P03 は P01b 定義をコピー）・`.variant-label`・`.is-variant` の定義を揃え、トークン正式名のみ使用（ローカル短縮名なし、§9 準拠）。エラーアイコンは Lucide 風 1.5px ストローク `currentColor` のインライン SVG で統一。

## トークン

**トークン追加なし。** 既存の `--color-error` / `--color-error-surface` / `--color-surface` / `--color-accent` / `--space-*` / `--radius-*` で全エラーケースを表現できた（ADR-002 通り）。`tokens.css` / `tokens.md` / 各 HTML `:root` の3箇所更新は不要だった。

## ADR への適合

- **ADR-001**（同一ファイル末尾 variant + キャプション区切り）: 準拠。
- **ADR-002**（トークン原則追加しない）: 準拠（追加なし）。
- **ADR-003**（conflict あり版はビジュアル提示・採否 #201）: 準拠。P01/P01b にあり版を用意し HTML コメントで採否を #201 に委ねる旨を明記。
- **ADR-004**（P03 未認証 callout は neutral surface + accent アイコン）: 準拠。`.callout-neutral` を新設し正準配色とした。既存の warning 配色 `.callout` は本体ブロックのリファレンスとして残置。
