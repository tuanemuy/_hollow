Outbox パターンを Cloudflare Queues で実装する

公開 2026年5月3日 · 更新 2026年5月10日 · #cloudflare #ddd #architecture · 公開状態: 公開中

サービス境界をまたぐ整合性問題、いわゆる「DBにレコードは入ったがメッセージブローカへの発行に失敗した」状態を回避する手段として Outbox パターン がよく知られている。本ノートでは Cloudflare D1 + Queues + Workers の組み合わせで、最低限動作する実装を整理する。

背景

2 つの外部リソース（DB と message broker）を 1 つの操作で「両方成功 or 両方失敗」にすることはできない。XA 等の分散トランザクションを避けるなら、原子的に書き込めるのは片方だけ。Outbox は「DB に書く側」だけを真実の源とし、別プロセスがそれを読んで非同期に publish する。

Don't try to commit to two systems atomically. Commit to one, then read from it.

関連: イベント駆動アーキテクチャに関するメモ でも触れた。

実装の構成

1. テーブル設計

D1 にイベントを保管するテーブルを置く。claimed_until をリース管理に使うのがミソ。

CREATE TABLE outbox_events (
  id          TEXT PRIMARY KEY,
  aggregate   TEXT NOT NULL,
  payload     TEXT NOT NULL,           -- JSON
  created_at  INTEGER NOT NULL,
  dispatched_at INTEGER,
  claimed_by  TEXT,
  claimed_until INTEGER                -- リース失効時刻
);
CREATE INDEX idx_pending ON outbox_events (dispatched_at, claimed_until);

2. ユースケースからの書き込み

ドメインイベントは Unit of Work 内で outbox_events に 同じ D1 トランザクション として書き込む。これでビジネスデータとイベントが原子的に永続化される。

  • ユースケースは uow.events.enqueue(event) のみ呼び、Queue を直接触らない。
  • UoW のコミット時点で outbox 行も確定する。
  • 失敗時は両方ロールバックされる。

3. リレーワーカー

Cron Trigger で定期起動する Worker が pending 行を取得し、Queues に publish する。1 行を 2 つのワーカーが処理しないよう リース方式 で claim する。

const claim = await db.run(`
  UPDATE outbox_events
   SET claimed_by = ?, claimed_until = ?
   WHERE id IN (
     SELECT id FROM outbox_events
     WHERE dispatched_at IS NULL
       AND (claimed_until IS NULL OR claimed_until < ?)
     LIMIT 50
   )
`, [workerId, now + LEASE_MS, now]);

リース失効後は別のワーカーが拾えるため、ワーカー死亡時も停滞しない。

4. 配信保証

Queues は at-least-once。コンシューマ側で 冪等性 を必ず確保すること。下の表に主要な性質をまとめる。

性質保証備考
配信at-least-once同じ event が複数回届くことがある
順序保証なしaggregate ごとの順序にも頼らない
retry自動 + DLQ最大試行回数を超えると DLQ へ
冪等性消費側責務event_id をユニーク制約で受ける等

運用上の注意

  • リースの長さは 30s 程度が落ち着く。短すぎると同じ行を奪い合い、長すぎると停滞する。
  • dispatched_at が古い行は別のプルーナワーカーで削除する。outbox は無限に伸びる。
  • DLQ に流れた行は手動再生用の管理 UI を別途用意したほうがよい。

関連するメモ

このパターンは Cloudflare Workers + D1 のパフォーマンス計測 でのレイテンシ前提と相性が良い。Queues と組み合わせるなら 静かなインターフェースについての覚書 とは関係ないけれど、同じ作者の整理として並べておく。
