課題1 — 表示切り替えの視覚的優先度を下げる

表示モードは「一度決めたらほぼ変えない」設定。利用頻度に即して目立ち度を下げる。いずれの案も CTA はツールバーから除いた状態（課題2 = 案a 適用後）で比較する。アイコンのみ化する場合、実装は role="tablist" / role="tab" / aria-selected / 各ボタンの aria-label を維持する（aria 契約テストあり）。

案1-A アイコンのみ+縮小（位置は左・白カード active 維持）

利点: 最小変更。ラベル除去と縮小（32×28px）で専有面積と視覚ノイズが減る。#620 の白カード active 表現を維持するため P30/モバイルとの統一が崩れない。
欠点: 左端先頭という「最初に目が行く位置」は変わらず、優先度の逆転（設定が一等地を占める）が解消しきらない。白カード+shadow は依然リッチで目を引く。

desktop — 案1-A
案1-B ツールバー右端へ移動+アイコンのみ+ink 濃度差 active（白カード+shadow 廃止）

利点: 位置（左端先頭 → 右端の補助領域）と表現（白カード → ink 濃度差: 非アクティブ ink-tertiary / アクティブ ink）の両面で優先度を下げる。読み順の一等地（左）には保存ビュー select = 「何を見るか」が来て、操作頻度と優先度が一致する。装飾が消えて静かな佇まいになる（設計原則の余白・低ノイズと整合）。
欠点: 表現変更が #620 の「白カード active で P30/モバイル統一」を上書きするため、適用範囲（表示モード系のみ）を ADR で確定する必要がある。濃度差のみの active は白カードよりコントラストが弱い（aria-selected と tooltip で補完）。

desktop — 案1-B
案1-C segmented 廃止 → ドロップダウンへ退避

利点: 専有面積が最小。表示モードを完全に「設定」として畳める。
欠点: 現在のモードと選択肢の一覧性が失われ、切り替えが2操作になる。3択しかない列挙にドロップダウンは過剰な間接化。保存ビュー select と同形の select が2つ並ぶと役割（ビュー = 何を見るか / モード = どう見るか）の区別が付きにくい。#620 の segmented 統一を実質破棄することになり影響が最大。

モバイルは select（最大150px）を左、選択 + ビュー保存（アイコンのみ）+ segmented を右に。320px でも1行に収まる。

課題2 — 新規作成・アップロード CTA の重複解消

#628 ADR-001 で「ヘッダーに検索 + アップロード + 新規作成を常時表示（デスクトップ/モバイル共通）」が確定済み。重複の解消はどちらを削るかの問題。

案2-a ヘッダー集約（ツールバーから CTA を削除）— 基本線

利点: #628 ADR-001/003 と完全整合。「作成系 = ヘッダー（グローバル・常時）」「一覧操作系 = ツールバー（文脈）」と役割が一意になり、primary の序列逆転（ヘッダー: アップロード主役 / ツールバー: 新規作成主役）も同時に消える。モバイル実装（ツールバーに CTA なし）とも一致する。ツールバーが軽くなり課題1 の再配置余地が生まれる。
欠点: 一覧を深くスクロールした位置からは CTA がヘッダー（sticky）まで視線移動になる — ただしヘッダーは常時固定表示のため実害は小さい。

desktop — 案2-a（課題1 = 案1-B と組み合わせた確定形）
案2-b（参考） 役割分離: ヘッダー = アップロード / ツールバー = 新規作成

作成手段で配置を分ける案。欠点が支配的: #628 ADR-001（両 CTA をヘッダー常時表示）の決定を崩す。ユーザーから見ると「どちらがどこにあるか」を覚える負担が増え、モバイル（ツールバーに CTA を置く幅がない）とデスクトップで構成が分岐する。簡略参考に留め、モック化は省略。

案2-c（参考） ツールバー集約: ヘッダーから CTA を削除

CTA を一覧文脈に寄せる案。欠点が支配的: #628 ADR-001 の全面巻き戻しになり、ヘッダー再設計（ユーザーメニューのサイドバー移設までして CTA の幅を確保した）一連の決定と衝突する。P10 以外の画面（P11 等）でヘッダー CTA に依存する導線も失われる。簡略参考に留め、モック化は省略。
