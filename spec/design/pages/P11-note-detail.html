静かなインターフェースについての覚書

余白の使い方一つで、画面は驚くほど穏やかになる。最近、Apple のウェブサイトや iCloud の UI を観察しながら、なぜそれらが「静か」に感じられるのかを考えていた。気づいたことを順に書き残しておく。

背景にあるアイデア

静けさは「何もないこと」ではなく、明確な意図のもとで配置された空白から生まれる。ノイズを取り除くというより、要素同士の関係性を見えやすくするための余白だと考えるほうが正しい。

Simplicity is the ultimate sophistication.
— Leonardo da Vinci (Steve Jobs 経由で広まった引用)

関連: A Pattern Language を読みながら でも似たことを書いた。空間のヒエラルキーは、建築でもインターフェースでも同じ原理で働く。

具体的な観察

1. ヘアラインに頼る

濃いボーダーで区画を区切るのではなく、rgba(60,60,67,0.12) のような薄いヘアラインで「ほのめかす」程度に留める。視線がボーダーを越えて自然に流れる。

2. システムフォントへの信頼

カスタムフォントを使わず、OS が用意するシステムフォントスタックを素直に使う。読み手のデバイスに最も最適化された描画になる。

font-family: -apple-system, BlinkMacSystemFont,
  "SF Pro Text", "SF Pro Display",
  "Helvetica Neue", sans-serif;
// Apple 端末では SF が、それ以外でも自然な代替が選ばれる
const applyTheme = (density) => density * 1.5;

3. アクセントは一色だけ

多色を使うとそれぞれが意味を主張し始め、画面が騒がしくなる。アクセントは oklch(37.1% 0 0) ひとつに絞り、それ以外は無彩色のグレースケールで構成する。

実装で気をつけること

細かい指針は次の順序で適用していくと混乱が少ない。

  1. 角丸は 用途で使い分ける。ボタンは完全な丸 (980px)、カードは 12px が落ち着く。
  2. ホバー状態は 背景色の変化 のみ。transform や影で動かさない。
  3. 遷移は 0.15s 前後。長すぎるとモッサリし、短すぎると唐突に見える。
  • 境界線は 1px、色は rgba(60,60,67,0.12) 固定。
  • 影は使わない。必要な箇所のみ 0 1px 2px rgba(0,0,0,0.04) を許容する。

チェックリスト

  • ヘアラインの色値を統一する
  • ダークモードの色彩設計を別途検討
