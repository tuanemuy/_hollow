Q2 戦略メモ — リリース後の優先順位

GA リリース後の最初の四半期 (Q2) で、何にフォーカスし、何を意図的に後回しにするかを整理する。 この四半期のキーフレーズは "磨き込みと定着"。新機能の追加ではなく、 ベータからの上位 5 ユースケースが 「これがないと戻れない」 と感じられる体験になるまで詰めることを優先する。

速さは正義だが、急ぐと丁寧さを失う。Q2 は意図的にペースを落とし、土台を固める。

1. 何にフォーカスするか

以下の 3 領域に絞り、それ以外は明示的に "後回し" 棚に置く。

  • 変換品質 — PDF / Office / 音声 → HTML の忠実度を底上げ。変換パイプライン v2 の優先度を最高に。
  • 検索とリンク — Quick Switcher と [[backlinks]] の表示を、Notion / Obsidian と並べて見劣りしないレベルに。
  • 公開体験 — /u/:slug の OGP・読み込み速度・Markdown 描画 (この文書のスタイル自体！) を仕上げる。

2. やらないこと

"やらないリスト" を明示することで、議論を短くする。以下は Q3 以降に検討する。

  • ✓モバイルアプリ (ネイティブ) の着手 — PWA で十分
  • ✓チーム / マルチユーザー機能 — まず "ひとり用" を磨き切る
  • AI 要約・QA の追加 (既存の検索が安定してから)
  • サードパーティ統合 (Slack / Notion インポート)
  • 料金プランの細分化

3. KPI と目標

定量的な北極星は W1 リテンション 35%。サブ指標は以下。

指標 現在値 Q2 目標 備考
W1 リテンション 22% 35% 変換品質に直結する見込み
1 ユーザー / 週 のノート作成数 3.1 5.0 Inbox 機能の磨き込みで
公開ノート数 140 500 テンプレ整備で立ち上げ補助

4. 技術的な投資

アーキテクチャは現状のまま — TanStack Start + Cloudflare D1 / Queues。 Cloudflare 移行ノート で書いた通り、Workers 一本化のメリットがコストを上回っている。

4.1 リレー / アウトボックス の安定化

現状のリレーワーカーで稀に "claim が漏れて lease 期限切れ" が発生するため、メトリクスを足してから対処する。

// app/worker/cloudflare/relay.ts
export async function claimBatch(env: Env) {
  const claimed = await env.DB.prepare(
    "UPDATE outbox SET claimed_at = ?1, lease_id = ?2 ..."
  ).bind(now, leaseId).run();
  // TODO: metric — claim_attempts / claim_succeeded
  return claimed.results;
}

4.2 変換ジョブのキュー分離

軽い変換 (Markdown / HTML) と重い変換 (PDF / 音声) を別キューに分け、後者のスケールアウトを独立させる。

5. リスクと前提

  1. 変換品質の改善が "感じられる差" を生むかは、ユーザーごとの素材依存。早期に ベータ協力者 5 名 と毎週 30 分のセッションを置く。
  2. Cloudflare の D1 リードレプリカが Q2 中に必要になる可能性 — 上限に達する前に観測する。
  3. "ひとり用" に絞ったポジショニングが、認知獲得の天井を早めに作る懸念。これは Q3 以降の論点として保留。
